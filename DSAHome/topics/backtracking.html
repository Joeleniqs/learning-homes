BACKTRACKING & GREEDY

Backtracking

The choose/explore/un-choose template animated on a decision tree: subsets, permutations, combinations, N-Queens, Sudoku and pruning.

Intermediate → Expert~60 min studyBuilds on: Recursion & the Call StackUpdated 2026-11-03

What backtracking is

Some problems ask you to generate things, such as every subset, every arrangement or every valid board, or to find one arrangement that satisfies a set of constraints. There is no formula for them. You build the answer one decision at a time, and as soon as a partial answer can no longer work, you undo the last decision and try the next option. That is backtracking: a depth-first search over a tree of decisions that is never stored, because it exists only as the recursion.

One shared, mutable partial solution walks a decision tree depth-first: choose (change the state), explore (recurse), un-choose (restore the state exactly), and cut any branch that provably cannot reach an answer.

You already know the machinery from Recursion: the call stack, the "generate all" template, and recursion trees. This page is about everything on top of it: the three tree shapes nearly every problem uses, removing duplicates without a set, pruning, constraint search (N-Queens, Sudoku, grids), and how to tell when a backtracking search should become dynamic programming.

Three questions define any backtracking solution. Answer them before writing code:

  1. What is the state? The partial answer (a list, a board, a string) plus whatever makes the checks fast (a used[] array, column sets, a running sum).
  2. What are the choices at a node, and in which order? This decides the shape of the tree, and the order decides how early you find answers or failures.
  3. When do you stop? The goal test says "record this" and the prune test says "nothing below can work". The prune test is where all the speed comes from.

The template: choose, explore, un-choose

The state is one list, board or string, shared by every call. Going down the tree changes it; coming back up must restore it exactly, so that a sibling branch starts from the same state its parent saw. That is the whole trick: one object of size O(depth) instead of a copy per node.

Here is the template, applied to subsets. Every other algorithm on this page is this skeleton with a different loop and a different prune.

def backtrack_template(nums):
    res, path = [], []                 # path: the ONE shared state

    def dfs(start):
        res.append(path[:])            # goal test: here every node is an answer
        for i in range(start, len(nums)):
            # prune here: `continue` skips one choice, `break` skips the rest
            path.append(nums[i])       # 1. choose  (mutate the state)
            dfs(i + 1)                 # 2. explore (recurse on the smaller problem)
            path.pop()                 # 3. un-choose (restore it exactly)

    dfs(0)
    return res

public static IList<IList<int>> BacktrackTemplate(int[] nums)
{
    var res = new List<IList<int>>();
    var path = new List<int>();               // the ONE shared state

    void Dfs(int start)
    {
        res.Add(new List<int>(path));         // goal test: every node is an answer
        for (int i = start; i < nums.Length; i++)
        {
            // prune here: continue skips one choice, break skips the rest
            path.Add(nums[i]);                // 1. choose
            Dfs(i + 1);                       // 2. explore
            path.RemoveAt(path.Count - 1);    // 3. un-choose
        }
    }

    Dfs(0);
    return res;
}

Why "un-choose" and not "copy"? You could pass path + [x] to every call and never undo anything. That works, but every node then allocates a new list of length up to the depth d, which adds O(d) work per node. With mutation plus undo, a node costs O(1) extra and only the recorded answers pay for a copy. On a board (Sudoku, N-Queens, word search) copying is far worse: O(cells) per node. Undo is the default; immutable state is fine for small strings, where it also removes a class of bugs.

The three families

Almost every "generate all" problem is one of three tree shapes. Learn to recognise the shape and the code writes itself.

Family Question A child may pick Record when Leaves
Subsets which elements are in? any index after the last one picked at every node 2ⁿ
Combinations which k elements? (or which add up to a target?) any index after the last (or the same one, if reuse is allowed) size = k, or remaining sum = 0 C(n, k)
Permutations in which order? any element not used yet length = n n!

The difference between subsets and permutations is one thing: a start index. Moving forward only means [1,2] and [2,1] cannot both appear (order does not matter). A used[] array instead lets any unused element come next (order matters).

Subsets: two tree shapes for the same answer

There are two ways to draw the subset tree, and you should know both. The take/skip tree makes one binary decision per element: it is the tree you memoize later, because the state is just an index. The for-loop start-index tree makes every node an answer: it extends naturally to combinations and to skipping duplicates. Switch between them with the problem selector and watch the shapes differ while the answers stay the same.

Take / skip (binary)

Depth n, 2ⁿ leaves, 2ⁿ⁺¹ − 1 nodes. Answers sit only at the leaves. The state is (i, something), so it is the natural shape to memoize (Target Sum, 0/1 knapsack, Partition Equal Subset Sum).

For-loop from start

Exactly one node per subset, 2ⁿ nodes. Every node is an answer. Prunes are a continue or a break in the loop: this is where "skip duplicates" and "break when too big" live.

def subsets_take_skip(nums):
    res, path = [], []

    def dfs(i):
        if i == len(nums):
            res.append(path[:])
            return
        path.append(nums[i])       # take nums[i]
        dfs(i + 1)
        path.pop()
        dfs(i + 1)                 # skip nums[i]

    dfs(0)
    return res


def subsets_bitmask(nums):         # no recursion: mask bit i = "take nums[i]"
    n = len(nums)
    return [[nums[i] for i in range(n) if mask >> i & 1] for mask in range(1 << n)]

public static IList<IList<int>> SubsetsTakeSkip(int[] nums)
{
    var res = new List<IList<int>>();
    var path = new List<int>();
    void Dfs(int i)
    {
        if (i == nums.Length) { res.Add(new List<int>(path)); return; }
        path.Add(nums[i]);                 // take nums[i]
        Dfs(i + 1);
        path.RemoveAt(path.Count - 1);
        Dfs(i + 1);                        // skip nums[i]
    }
    Dfs(0);
    return res;
}

public static IList<IList<int>> SubsetsBitmask(int[] nums)
{
    int n = nums.Length;
    var res = new List<IList<int>>();
    for (int mask = 0; mask < 1 << n; mask++)
    {
        var s = new List<int>();
        for (int i = 0; i < n; i++) if ((mask >> i & 1) == 1) s.Add(nums[i]);
        res.Add(s);
    }
    return res;
}

The bitmask version is a reminder that "subsets of n ≤ 20 items" is the same thing as "integers from 0 to 2ⁿ − 1". When a later state needs to remember which items are used, that integer becomes a DP index (see Bitmask and digit DP).

Permutations: used[] or swapping

For permutations every level picks one unused element, so the root has n children, the next level n − 1, and so on: n! leaves and about e·n! nodes. Two ways to track "unused":

  • a used[] array (or a bitmask): loop over all indices and skip the used ones. Easy to extend to duplicates.
  • swap in place: keep nums[:k] as the fixed prefix and nums[k:] as the pool; choose by swapping nums[i] into slot k, then swap it back. No extra array, but it scrambles the order of the pool, so the sorted-order trick for duplicates does not work directly.

Pick "permutations: used[]" and "permutations: swap in place" in the visualizer above. In the swap version the edge labels show which two slots were swapped, and the array panel shows the prefix that is already fixed in green.

def permute(nums):
    res, path, used = [], [], [False] * len(nums)

    def dfs():
        if len(path) == len(nums):
            res.append(path[:])
            return
        for i in range(len(nums)):
            if used[i]:
                continue
            used[i] = True; path.append(nums[i])     # choose
            dfs()                                    # explore
            used[i] = False; path.pop()              # un-choose

    dfs()
    return res


def permute_swap(nums):
    res = []

    def dfs(k):                       # nums[:k] is fixed
        if k == len(nums):
            res.append(nums[:])
            return
        for i in range(k, len(nums)):
            nums[k], nums[i] = nums[i], nums[k]      # choose
            dfs(k + 1)
            nums[k], nums[i] = nums[i], nums[k]      # un-choose

    dfs(0)
    return res

public static IList<IList<int>> Permute(int[] nums)
{
    var res = new List<IList<int>>();
    var path = new List<int>();
    var used = new bool[nums.Length];
    void Dfs()
    {
        if (path.Count == nums.Length) { res.Add(new List<int>(path)); return; }
        for (int i = 0; i < nums.Length; i++)
        {
            if (used[i]) continue;
            used[i] = true; path.Add(nums[i]);           // choose
            Dfs();                                       // explore
            used[i] = false; path.RemoveAt(path.Count - 1); // un-choose
        }
    }
    Dfs();
    return res;
}

public static IList<IList<int>> PermuteSwap(int[] nums)
{
    var res = new List<IList<int>>();
    void Dfs(int k)
    {
        if (k == nums.Length) { res.Add(new List<int>(nums)); return; }
        for (int i = k; i < nums.Length; i++)
        {
            (nums[k], nums[i]) = (nums[i], nums[k]);     // choose
            Dfs(k + 1);
            (nums[k], nums[i]) = (nums[i], nums[k]);     // un-choose
        }
    }
    Dfs(0);
    return res;
}

Combinations and Combination Sum I, II, III

A combination is a subset with a stopping rule. Two prunes appear again and again, and both are visible in the visualizer as dashed red stubs:

  • Counting bound (Combinations, C(n, k)): if fewer numbers remain than slots to fill, stop. With x as the next candidate, numbers x..n remain, so you need n − x + 1 ≥ k − len(path). Every larger x leaves fewer numbers, so this is a break, not a continue.
  • Sorted overshoot (Combination Sum): sort the candidates; once cands[i] > remain, every later candidate overshoots too: break.

How far the child may look decides reuse. Recurse with i when an element may be reused (Combination Sum I) and with i + 1 when each may be used once (II and III).

def combine(n, k):
    res, path = [], []

    def dfs(start):
        if len(path) == k:
            res.append(path[:])
            return
        for x in range(start, n + 1):
            if n - x + 1 < k - len(path):
                break                  # too few numbers left to fill the slots
            path.append(x)
            dfs(x + 1)
            path.pop()

    dfs(1)
    return res


def combination_sum(cands, target):    # I: unlimited reuse
    cands.sort()
    res, path = [], []

    def dfs(start, remain):
        if remain == 0:
            res.append(path[:])
            return
        for i in range(start, len(cands)):
            if cands[i] > remain:
                break                  # sorted: everything after is bigger
            path.append(cands[i])
            dfs(i, remain - cands[i])  # i, not i + 1: may reuse cands[i]
            path.pop()

    dfs(0, target)
    return res


def combination_sum3(k, n):            # III: k distinct digits 1..9 adding up to n
    res, path = [], []

    def dfs(start, remain):
        if len(path) == k:
            if remain == 0:
                res.append(path[:])
            return
        for d in range(start, 10):
            if d > remain:
                break
            path.append(d)
            dfs(d + 1, remain - d)
            path.pop()

    dfs(1, n)
    return res

public static IList<IList<int>> Combine(int n, int k)
{
    var res = new List<IList<int>>();
    var path = new List<int>();
    void Dfs(int start)
    {
        if (path.Count == k) { res.Add(new List<int>(path)); return; }
        for (int x = start; x <= n; x++)
        {
            if (n - x + 1 < k - path.Count) break;   // too few numbers left
            path.Add(x);
            Dfs(x + 1);
            path.RemoveAt(path.Count - 1);
        }
    }
    Dfs(1);
    return res;
}

public static IList<IList<int>> CombinationSum(int[] cands, int target)
{
    Array.Sort(cands);
    var res = new List<IList<int>>();
    var path = new List<int>();
    void Dfs(int start, int remain)
    {
        if (remain == 0) { res.Add(new List<int>(path)); return; }
        for (int i = start; i < cands.Length; i++)
        {
            if (cands[i] > remain) break;            // sorted: the rest are bigger
            path.Add(cands[i]);
            Dfs(i, remain - cands[i]);               // i: reuse allowed
            path.RemoveAt(path.Count - 1);
        }
    }
    Dfs(0, target);
    return res;
}

public static IList<IList<int>> CombinationSum3(int k, int n)
{
    var res = new List<IList<int>>();
    var path = new List<int>();
    void Dfs(int start, int remain)
    {
        if (path.Count == k) { if (remain == 0) res.Add(new List<int>(path)); return; }
        for (int d = start; d <= 9; d++)
        {
            if (d > remain) break;
            path.Add(d);
            Dfs(d + 1, remain - d);
            path.RemoveAt(path.Count - 1);
        }
    }
    Dfs(1, n);
    return res;
}

Tip The output size is a lower bound on the running time. "Return all permutations of 10 items" is 3.6 million lists of 10 values each; no pruning can beat that. Pruning helps when most branches do not lead to answers: constraint problems, sums and validity rules.

Duplicates: sort, then skip equal siblings

When the input has repeated values, the plain templates produce repeated answers: subsets of [1,2,2] contain [2] twice, once from each copy of 2. Putting answers in a set afterwards works, but you pay for the whole duplicated search. The right fix removes the duplicate branches before they grow.

The visualizer has a correct mode and a buggy mode for each problem. In the buggy modes the repeated answers turn red as they are recorded; in the correct modes the same branches appear as dashed stubs that are never explored.

For permutations there is no start, so "the same level" needs another definition. Sort, then allow equal values only left to right: copy i may be placed only if copy i − 1 is already in the path. If used[i-1] is False, then copy i − 1 was tried at this very level a moment ago and released, so placing copy i here would rebuild the same subtree.

def subsets_with_dup(nums):
    nums.sort()
    res, path = [], []

    def dfs(start):
        res.append(path[:])
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i - 1]:
                continue                       # equal sibling: same subtree
            path.append(nums[i])
            dfs(i + 1)
            path.pop()

    dfs(0)
    return res


def permute_unique(nums):
    nums.sort()
    res, path, used = [], [], [False] * len(nums)

    def dfs():
        if len(path) == len(nums):
            res.append(path[:])
            return
        for i in range(len(nums)):
            if used[i]:
                continue
            if i > 0 and nums[i] == nums[i - 1] and not used[i - 1]:
                continue                       # use equal values left to right
            used[i] = True; path.append(nums[i])
            dfs()
            used[i] = False; path.pop()

    dfs()
    return res


def combination_sum2(cands, target):         # each candidate at most once
    cands.sort()
    res, path = [], []

    def dfs(start, remain):
        if remain == 0:
            res.append(path[:])
            return
        for i in range(start, len(cands)):
            if i > start and cands[i] == cands[i - 1]:
                continue                       # duplicate at this level
            if cands[i] > remain:
                break                          # sorted: the rest are too big
            path.append(cands[i])
            dfs(i + 1, remain - cands[i])
            path.pop()

    dfs(0, target)
    return res

public static IList<IList<int>> SubsetsWithDup(int[] nums)
{
    Array.Sort(nums);
    var res = new List<IList<int>>();
    var path = new List<int>();
    void Dfs(int start)
    {
        res.Add(new List<int>(path));
        for (int i = start; i < nums.Length; i++)
        {
            if (i > start && nums[i] == nums[i - 1]) continue;   // equal sibling
            path.Add(nums[i]);
            Dfs(i + 1);
            path.RemoveAt(path.Count - 1);
        }
    }
    Dfs(0);
    return res;
}

public static IList<IList<int>> PermuteUnique(int[] nums)
{
    Array.Sort(nums);
    var res = new List<IList<int>>();
    var path = new List<int>();
    var used = new bool[nums.Length];
    void Dfs()
    {
        if (path.Count == nums.Length) { res.Add(new List<int>(path)); return; }
        for (int i = 0; i < nums.Length; i++)
        {
            if (used[i]) continue;
            if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) continue; // left to right
            used[i] = true; path.Add(nums[i]);
            Dfs();
            used[i] = false; path.RemoveAt(path.Count - 1);
        }
    }
    Dfs();
    return res;
}

public static IList<IList<int>> CombinationSum2(int[] cands, int target)
{
    Array.Sort(cands);
    var res = new List<IList<int>>();
    var path = new List<int>();
    void Dfs(int start, int remain)
    {
        if (remain == 0) { res.Add(new List<int>(path)); return; }
        for (int i = start; i < cands.Length; i++)
        {
            if (i > start && cands[i] == cands[i - 1]) continue;  // duplicate at this level
            if (cands[i] > remain) break;                         // the rest are too big
            path.Add(cands[i]);
            Dfs(i + 1, remain - cands[i]);
            path.RemoveAt(path.Count - 1);
        }
    }
    Dfs(0, target);
    return res;
}

Pitfall: i > 0 instead of i > start In the start-index templates, if i > 0 and nums[i] == nums[i-1]: continue also skips the first pick at a deeper level. For [1,2,2] it then never builds [2,2] or [1,2,2]. The comparison must be with the left sibling, which exists only when i > start. In Permutations II, i > 0 is right, because the used[i-1] test supplies the "same level" meaning. Writing used[i-1] instead of not used[i-1] is also correct and also deduplicates, but it prunes much later (deep in the tree instead of at the top), so it is slower.

When the input cannot be sorted, or equal values are not adjacent (Increasing Subsequences, LeetCode 491), use a per-level set: create seen = set() inside the call, and skip a value that is already in it. That is exactly what the Partition-to-K visualizer below does with bucket loads.

Pruning, and what backtracking costs

A backtracking tree with branching factor b and depth d has up to bd leaves. The work is roughly the number of nodes times the work per node. Pruning cuts subtrees, and the earlier the cut, the more it saves: a cut at depth k removes up to bd−k leaves.

Problem b d Tree size With answers copied
Subsets 2 n 2ⁿ⁺¹ nodes O(n · 2ⁿ)
Permutations n, n−1, … n ≈ e · n! nodes O(n · n!)
Combinations C(n,k) ≤ n k O(C(n,k) · k) O(k · C(n,k))
Combination Sum, target T, min value m n T / m O(nT/m) worst case output dependent
N-Queens n n far below n! (pruned) O(n!) bound
Sudoku ≤ 9 blanks 9blanks bound; tiny in practice with MRV
Word Search 3 (4 at the start) L R · C · 3L
Generate Parentheses 2 2n Catalan: about 4ⁿ / n1.5

There are four kinds of prune, and good solutions usually combine several:

  1. Feasibility: the choice breaks a rule now (a queen is attacked, a digit repeats, a letter mismatches). Check it before recursing, not at the leaf.
  2. Bound: the rest cannot possibly finish (too few numbers left, the remaining sum is too big, more octets than digits). This looks ahead without searching.
  3. Symmetry: two branches are interchangeable (equal values, equal bucket loads, rotations of a board). Explore one representative.
  4. Ordering: changes no answers, only when failures happen: most-constrained variable first (MRV in Sudoku), largest item first (bin packing), cheapest check first.

The visualizer below measures this for N-Queens. Each bar is the size of a search space on a log scale, from "any n cells" through "one queen per row" and "one per row and column" down to the nodes the pruned DFS really visits.

The best prune is a better encoding Going from C(64, 8) ≈ 4.4 billion to 8⁸ ≈ 16.8 million to 8! = 40,320 needs no pruning code at all; it comes from choosing what one decision means: "a column for this row" instead of "a cell". Before writing checks, ask what decision makes illegal states impossible to express.

Constraint problems

In a constraint problem the leaves are rare. Most of the tree is dead, so the quality of the feasibility check and the order of decisions decide everything. The pattern is always the same: keep side structures that make "is this choice legal?" O(1), update them on choose, and restore them on un-choose.

N-Queens: one queen per row, three sets

Place n queens on an n × n board so that no two share a row, a column or a diagonal. Encode one queen per row, so a decision is "which column for row r". Rows can then never clash, and three sets answer every other question in O(1):

  • cols: columns already taken;
  • diag: "\" diagonals, where every cell has the same r − c;
  • anti: "/" diagonals, where every cell has the same r + c.

Step through the search. The current row is outlined, cells attacked by the queens placed so far are striped, and when a cell is tried and rejected, the queen that attacks it lights up together with the set entry that caught it. A dead end is a row in which every cell is attacked: the whole row turns red and the search returns to move the queen above.

def solve_n_queens(n):
    res, queen = [], [-1] * n          # queen[r] = column of the queen in row r
    cols, diag, anti = set(), set(), set()

    def dfs(r):
        if r == n:
            res.append(["." * c + "Q" + "." * (n - c - 1) for c in queen])
            return
        for c in range(n):
            if c in cols or r - c in diag or r + c in anti:
                continue                                   # attacked
            queen[r] = c
            cols.add(c); diag.add(r - c); anti.add(r + c)  # choose
            dfs(r + 1)                                     # explore
            cols.remove(c); diag.remove(r - c); anti.remove(r + c)  # un-choose

    dfs(0)
    return res

public static IList<IList<string>> SolveNQueens(int n)
{
    var res = new List<IList<string>>();
    var queen = new int[n];
    bool[] cols = new bool[n], diag = new bool[2 * n - 1], anti = new bool[2 * n - 1];
    void Dfs(int r)
    {
        if (r == n)
        {
            res.Add(queen.Select(c => new string('.', c) + "Q" + new string('.', n - c - 1)).ToList());
            return;
        }
        for (int c = 0; c < n; c++)
        {
            int d = r - c + n - 1, a = r + c;
            if (cols[c] || diag[d] || anti[a]) continue;         // attacked
            queen[r] = c;
            cols[c] = diag[d] = anti[a] = true;                  // choose
            Dfs(r + 1);                                          // explore
            cols[c] = diag[d] = anti[a] = false;                 // un-choose
        }
    }
    Dfs(0);
    return res;
}

The fastest version (N-Queens II, count only) replaces the three sets with three bitmasks and shifts the diagonal masks one bit per row, so the free columns of a row are a single expression: free = ~(cols | diag | anti) & full. It appears in the worked problems below.

Sudoku: fill the most constrained cell first

A Sudoku solver is a backtracking search whose state is the board plus nine-bit masks of the digits used in each row, column and 3 × 3 box. The candidates of a cell are the digits missing from all three masks, so the legality test is a couple of bitwise operations.

The decisive trick is which cell to fill next. Filling cells in reading order wastes effort on cells that have five possibilities while a cell elsewhere has only one. MRV (minimum remaining values) always picks the empty cell with the fewest candidates:

  • a cell with 1 candidate is forced, so the search makes no guess at all;
  • a cell with 0 candidates is a contradiction, found immediately instead of many levels deeper;
  • when a guess is unavoidable, it has the fewest alternatives, so the branching factor is as small as it can be.

Compare the two orders on the same puzzle. The small grey numbers on the MRV pick frames are the candidate counts the heuristic compares; the final frame reports the placements tried under both orders.

def solve_sudoku(board):                      # board: 9x9 lists of '1'..'9' or '.'
    rows, cols, boxes = [0] * 9, [0] * 9, [0] * 9
    empty = []
    for r in range(9):
        for c in range(9):
            if board[r][c] == ".":
                empty.append((r, c))
            else:
                bit = 1 << int(board[r][c])
                rows[r] |= bit; cols[c] |= bit; boxes[r // 3 * 3 + c // 3] |= bit

    def candidates(r, c):                     # bits 1..9 that are still free
        return ~(rows[r] | cols[c] | boxes[r // 3 * 3 + c // 3]) & 0x3FE

    def dfs():
        if not empty:
            return True
        # MRV: move the cell with the fewest candidates to the end, then take it
        k = min(range(len(empty)), key=lambda j: candidates(*empty[j]).bit_count())
        empty[k], empty[-1] = empty[-1], empty[k]
        r, c = empty.pop()
        b = r // 3 * 3 + c // 3
        mask = candidates(r, c)               # 0 candidates: the loop never runs
        while mask:
            bit = mask & -mask                # lowest candidate digit
            mask ^= bit
            rows[r] |= bit; cols[c] |= bit; boxes[b] |= bit
            board[r][c] = str(bit.bit_length() - 1)
            if dfs():
                return True
            rows[r] ^= bit; cols[c] ^= bit; boxes[b] ^= bit
        board[r][c] = "."
        empty.append((r, c))                  # un-choose the cell itself
        return False

    dfs()

public static void SolveSudoku(char[][] board)
{
    int[] rows = new int[9], cols = new int[9], boxes = new int[9];
    var empty = new List<(int r, int c)>();
    for (int r = 0; r < 9; r++)
        for (int c = 0; c < 9; c++)
        {
            if (board[r][c] == '.') { empty.Add((r, c)); continue; }
            int bit = 1 << (board[r][c] - '0');
            rows[r] |= bit; cols[c] |= bit; boxes[r / 3 * 3 + c / 3] |= bit;
        }

    int Candidates(int r, int c) => ~(rows[r] | cols[c] | boxes[r / 3 * 3 + c / 3]) & 0x3FE;

    bool Dfs()
    {
        if (empty.Count == 0) return true;
        int k = 0, best = 10;                                   // MRV
        for (int j = 0; j < empty.Count; j++)
        {
            int cnt = System.Numerics.BitOperations.PopCount((uint)Candidates(empty[j].r, empty[j].c));
            if (cnt < best) { best = cnt; k = j; }
        }
        (empty[k], empty[^1]) = (empty[^1], empty[k]);
        var (r, c) = empty[^1];
        empty.RemoveAt(empty.Count - 1);
        int b = r / 3 * 3 + c / 3, mask = Candidates(r, c);
        while (mask != 0)
        {
            int bit = mask & -mask;
            mask ^= bit;
            rows[r] |= bit; cols[c] |= bit; boxes[b] |= bit;
            board[r][c] = (char)('0' + System.Numerics.BitOperations.TrailingZeroCount(bit));
            if (Dfs()) return true;
            rows[r] ^= bit; cols[c] ^= bit; boxes[b] ^= bit;
        }
        board[r][c] = '.';
        empty.Add((r, c));
        return false;
    }

    Dfs();
}

MRV is a general idea "Branch on the most constrained variable" is the core heuristic of every constraint solver (graph colouring, scheduling, exact cover). Its partner is forward checking: after a choice, update the candidates of affected cells and fail as soon as any of them reaches zero, as MRV does here implicitly. Knuth's Dancing Links (Algorithm X) applies the same rule to exact cover and solves Sudoku, pentomino tilings and N-Queens with one engine.

Word Search: DFS on a grid with mark and un-mark

Here the decision tree is laid out on a grid. A node is "word[k] matched at cell (r, c)"; its children are the four neighbours. The state that must be restored is the visited mark: the cell is overwritten with '#' on the way in, so the path cannot reuse it, and restored on the way out, so that other paths can use it.

Notice the frames that say "already on the path": without the '#' mark, the walk for "ABCB" would go A → B → C → back to the same B and wrongly report success. Notice also that after a failed start the board is exactly as it was. That is the un-choose doing its job.

from collections import Counter

def exist(board, word):
    R, C = len(board), len(board[0])
    have = Counter(ch for row in board for ch in row)
    if any(have[ch] < k for ch, k in Counter(word).items()):
        return False                          # not enough letters at all
    if have[word[0]] > have[word[-1]]:
        word = word[::-1]                     # start from the rarer end

    def dfs(r, c, k):
        if k == len(word):
            return True
        if not (0 <= r < R and 0 <= c < C) or board[r][c] != word[k]:
            return False
        board[r][c] = "#"                     # choose: mark
        found = (dfs(r + 1, c, k + 1) or dfs(r - 1, c, k + 1) or
                 dfs(r, c + 1, k + 1) or dfs(r, c - 1, k + 1))
        board[r][c] = word[k]                 # un-choose: restore
        return found

    return any(dfs(r, c, 0) for r in range(R) for c in range(C))

public static bool Exist(char[][] board, string word)
{
    int R = board.Length, C = board[0].Length;
    var have = new Dictionary<char, int>();
    foreach (var row in board) foreach (var ch in row) have[ch] = have.GetValueOrDefault(ch) + 1;
    foreach (var g in word.GroupBy(ch => ch))
        if (have.GetValueOrDefault(g.Key) < g.Count()) return false;   // not enough letters
    if (have[word[0]] > have[word[^1]])
        word = new string(word.Reverse().ToArray());                   // rarer end first

    bool Dfs(int r, int c, int k)
    {
        if (k == word.Length) return true;
        if (r < 0 || r >= R || c < 0 || c >= C || board[r][c] != word[k]) return false;
        board[r][c] = '#';                                             // mark
        bool found = Dfs(r + 1, c, k + 1) || Dfs(r - 1, c, k + 1)
                  || Dfs(r, c + 1, k + 1) || Dfs(r, c - 1, k + 1);
        board[r][c] = word[k];                                         // restore
        return found;
    }

    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (Dfs(r, c, 0)) return true;
    return false;
}

The two lines before the DFS are cheap prunes that matter on adversarial tests: a letter-count check rejects impossible words in O(R·C), and starting from the rarer end of the word shrinks the number of promising starts (a grid full of A with the word AAAAAAB is the classic killer).

Building strings: parentheses, phone letters, palindromes, IP addresses

Four classic generators, one visualizer. Each shows a different kind of prune:

  • Generate Parentheses: two counters replace a validity check. Add ( while open < n; add ) only while close < open. Every leaf is valid by construction, and the dead stubs show the choices the counters forbid.
  • Letter Combinations: no pruning at all, since every leaf is an answer. It is the plain product tree.
  • Palindrome Partitioning: the choice is where to cut next. Only palindromic pieces may be cut off, which kills most branches at once.
  • Restore IP Addresses: a bound prune (the remaining digits must fit in the remaining octets: between 1 and 3 each) plus a break on a leading zero or a value above 255.
def generate_parenthesis(n):
    res, path = [], []

    def dfs(open_, close):
        if len(path) == 2 * n:
            res.append("".join(path))
            return
        if open_ < n:
            path.append("("); dfs(open_ + 1, close); path.pop()
        if close < open_:
            path.append(")"); dfs(open_, close + 1); path.pop()

    dfs(0, 0)
    return res


def partition(s):                               # palindrome partitioning
    n = len(s)
    pal = [[False] * n for _ in range(n)]       # pal[i][j]: s[i..j] is a palindrome
    for i in range(n - 1, -1, -1):
        for j in range(i, n):
            pal[i][j] = s[i] == s[j] and (j - i < 2 or pal[i + 1][j - 1])
    res, path = [], []

    def dfs(start):
        if start == n:
            res.append(path[:])
            return
        for end in range(start, n):
            if pal[start][end]:
                path.append(s[start:end + 1])
                dfs(end + 1)
                path.pop()

    dfs(0)
    return res


def restore_ip_addresses(s):
    res, path = [], []

    def dfs(start):
        left, parts = len(s) - start, 4 - len(path)
        if left < parts or left > 3 * parts:
            return                              # bound: cannot fill the rest
        if parts == 0:
            res.append(".".join(path))
            return
        for L in (1, 2, 3):
            seg = s[start:start + L]
            if len(seg) < L or (seg[0] == "0" and L > 1) or int(seg) > 255:
                break                           # longer segments are no better
            path.append(seg)
            dfs(start + L)
            path.pop()

    dfs(0)
    return res

public static IList<string> GenerateParenthesis(int n)
{
    var res = new List<string>();
    var path = new System.Text.StringBuilder();
    void Dfs(int open, int close)
    {
        if (path.Length == 2 * n) { res.Add(path.ToString()); return; }
        if (open < n) { path.Append('('); Dfs(open + 1, close); path.Length--; }
        if (close < open) { path.Append(')'); Dfs(open, close + 1); path.Length--; }
    }
    Dfs(0, 0);
    return res;
}

public static IList<IList<string>> Partition(string s)
{
    int n = s.Length;
    var pal = new bool[n, n];
    for (int i = n - 1; i >= 0; i--)
        for (int j = i; j < n; j++)
            pal[i, j] = s[i] == s[j] && (j - i < 2 || pal[i + 1, j - 1]);
    var res = new List<IList<string>>();
    var path = new List<string>();
    void Dfs(int start)
    {
        if (start == n) { res.Add(new List<string>(path)); return; }
        for (int end = start; end < n; end++)
        {
            if (!pal[start, end]) continue;
            path.Add(s.Substring(start, end - start + 1));
            Dfs(end + 1);
            path.RemoveAt(path.Count - 1);
        }
    }
    Dfs(0);
    return res;
}

public static IList<string> RestoreIpAddresses(string s)
{
    var res = new List<string>();
    var path = new List<string>();
    void Dfs(int start)
    {
        int left = s.Length - start, parts = 4 - path.Count;
        if (left < parts || left > 3 * parts) return;      // bound
        if (parts == 0) { res.Add(string.Join(".", path)); return; }
        for (int L = 1; L <= 3 && start + L <= s.Length; L++)
        {
            string seg = s.Substring(start, L);
            if ((seg[0] == '0' && L > 1) || int.Parse(seg) > 255) break;
            path.Add(seg);
            Dfs(start + L);
            path.RemoveAt(path.Count - 1);
        }
    }
    Dfs(0);
    return res;
}

Letter Combinations is the plain product tree: for digit i, loop over its letters, append, recurse, pop. It is included in the visualizer and needs no prune.

Partition to K Equal Sum Subsets: the order of choices matters

Split nums into k groups with equal sums. The target is sum / k; each item goes into some bucket. This is the problem where pruning order matters most, and the visualizer lets you compare two strategies on the same input:

  • Descending order: place the largest items first. Large items have the fewest legal buckets, so contradictions appear near the root, where a cut removes the most.
  • Same-load skip: buckets are interchangeable. If bucket 0 and bucket 2 both hold 5, putting the item in either gives the same subtree. A per-call seen set of loads tries each distinct load once. This also covers the classic "if an empty bucket failed, every other empty bucket fails too".

On the default input the pruned search makes 13 calls; the plain one makes 599. Same answer, a tree 46 times smaller.

def can_partition_k_subsets(nums, k):
    total = sum(nums)
    if total % k:
        return False
    target = total // k
    nums.sort(reverse=True)                  # biggest first: fail near the root
    if nums[0] > target:
        return False
    load = [0] * k

    def dfs(i):
        if i == len(nums):
            return True                      # every item placed, no bucket overflowed
        seen = set()
        for b in range(k):
            if load[b] + nums[i] > target or load[b] in seen:
                continue                     # overflow, or an equivalent bucket
            seen.add(load[b])
            load[b] += nums[i]
            if dfs(i + 1):
                return True
            load[b] -= nums[i]
        return False

    return dfs(0)

public static bool CanPartitionKSubsets(int[] nums, int k)
{
    int total = nums.Sum();
    if (total % k != 0) return false;
    int target = total / k;
    Array.Sort(nums, (a, b) => b.CompareTo(a));      // biggest first
    if (nums[0] > target) return false;
    var load = new int[k];

    bool Dfs(int i)
    {
        if (i == nums.Length) return true;
        var seen = new HashSet<int>();
        for (int b = 0; b < k; b++)
        {
            if (load[b] + nums[i] > target || !seen.Add(load[b])) continue;
            load[b] += nums[i];
            if (Dfs(i + 1)) return true;
            load[b] -= nums[i];
        }
        return false;
    }

    return Dfs(0);
}

Why is i == len(nums) enough to return True, without checking that every bucket is full? Each bucket holds at most target and the total is exactly k · target, so if all items fit, every bucket must be exactly full.

When backtracking becomes DP

Backtracking enumerates paths. If two different paths reach the same state and the question asked about that state has the same answer whichever way you arrived, the second visit is wasted work. That is overlapping subproblems, and the cure is a cache: the backtracking function becomes a memoized recursion, which is top-down dynamic programming.

Target Sum makes it visible: assign + or − to each number so the total equals the target. The state after deciding the first i numbers is just (i, running sum). The paths +1 −1 and −1 +1 both arrive at (2, 0), and from there the rest of the search is identical. In the plain mode repeated states are coloured purple; switch to the memo mode and each of them collapses into one lookup.

The test to apply, every time:

Stay with backtracking

You must list every answer (all subsets, all boards), so the output itself is exponential. Or the state is the whole path (which cells are used on a grid with an arbitrary shape), so no two paths share a state. Or n is small and the pruning is strong.

Add a memo

You only need a count, a yes/no or a best value, and the future depends on a small summary of the past: an index plus a sum, a remainder, a last choice. Cache on that summary.

Switch to bitmask DP

The summary is "which items are used", with n ≤ 20 or so. Encode the used set as an n-bit integer: 2ⁿ states instead of n! orders. See bitmask DP.

Partition to K is the textbook case for the last box. The order in which items fell into buckets does not matter; only which items are used. From the mask you know the sum of the used items, and used_sum % target is the load of the bucket being filled, because buckets are filled one at a time. So the state is the mask alone, and there are at most 2ⁿ of them, each tried with n items: O(n · 2ⁿ) time, against the worst case kⁿ of the bucket search.

from functools import cache

def can_partition_k_subsets_mask(nums, k):
    total, n = sum(nums), len(nums)
    if total % k:
        return False
    target = total // k
    nums.sort()

    @cache
    def ok(mask, used_sum):                   # used_sum is a function of mask
        if mask == (1 << n) - 1:
            return True
        room = target - used_sum % target     # space left in the open bucket
        for i in range(n):
            if mask >> i & 1:
                continue
            if nums[i] > room:
                break                         # sorted: the rest are bigger
            if ok(mask | 1 << i, used_sum + nums[i]):
                return True
        return False

    return ok(0, 0)

public static bool CanPartitionKSubsetsMask(int[] nums, int k)
{
    int total = nums.Sum(), n = nums.Length;
    if (total % k != 0) return false;
    int target = total / k;
    Array.Sort(nums);
    var memo = new sbyte[1 << n];             // 0 unknown, 1 true, -1 false

    bool Ok(int mask, int usedSum)
    {
        if (mask == (1 << n) - 1) return true;
        if (memo[mask] != 0) return memo[mask] == 1;
        int room = target - usedSum % target;
        bool res = false;
        for (int i = 0; i < n && !res; i++)
        {
            if ((mask >> i & 1) == 1) continue;
            if (nums[i] > room) break;
            res = Ok(mask | 1 << i, usedSum + nums[i]);
        }
        memo[mask] = (sbyte)(res ? 1 : -1);
        return res;
    }

    return Ok(0, 0);
}

The same move turns "visit every city once" from n! paths into the Held–Karp DP over (mask, last city), O(n² · 2ⁿ); see Hamiltonian paths in advanced graphs. When even 2ⁿ is too much, the problem is usually NP-hard and the practical tools are exactly the ones on this page: strong pruning, good ordering, and bounds (branch and bound).

Recognize it, and avoid the classic bugs

Recognize backtracking when

  • The problem says all, every, list, generate: all subsets, all permutations, all valid boards.
  • The input is small: n ≤ 10 for permutations, n ≤ 20 for subsets, a 9 × 9 board, a word up to 15 letters.
  • An answer is built from a sequence of choices, and a partial answer can often be rejected early.
  • A puzzle with rules: place, fill, colour or partition so that constraints hold.
  • If it asks for a count or the best value instead, and states repeat, think memo or DP first.

Pitfall: appending the path itself res.append(path) stores a reference to the one list that you keep mutating; at the end every entry is the same empty list. Store a copy: path[:], list(path), or new List<int>(path) in C#.

Pitfall: forgetting to un-choose on every exit An early return True inside the loop is fine when the search stops completely (Sudoku). But a continue or a return placed between the choose and the un-choose leaves the state dirty for the next sibling: a visited mark never cleared, a set entry never removed. Keep choose and un-choose as a visually matched pair around the recursive call, and put checks before the choose.

Pitfall: dfs(i + 1) versus dfs(start + 1) In the start-index template, the child must start after the item just chosen (i + 1), not after the parent's start. dfs(start + 1) produces repeated and out-of-order combinations. In Combination Sum, where an item may be reused, the child starts at i, not i + 1.

Pitfall: checking validity only at the leaf Generating all 2²ⁿ strings of parentheses and testing each at the end is correct and exponentially slower than the counter version. Any rule that can be checked on a prefix should be checked on the prefix.

Worked problems

1 · N-Queens II with bitmasks Hard

Count the solutions for n up to about 14 as fast as possible. Insight: hold the attacked columns and both diagonal directions as bitmasks relative to the current row. Going down one row, a "\" attack moves one column right and a "/" attack one column left, so the masks are shifted by one bit. The free columns are ~(cols | ld | rd) & full, and p & -p peels off the lowest free column.

Solution: bitmask DFS, O(n!) bound, no sets or arrays 
def total_n_queens(n):
    full = (1 << n) - 1

    def dfs(cols, ld, rd):
        if cols == full:
            return 1
        count = 0
        free = ~(cols | ld | rd) & full
        while free:
            p = free & -free                    # lowest free column
            free ^= p
            count += dfs(cols | p, (ld | p) << 1 & full, (rd | p) >> 1)
        return count

    return dfs(0, 0, 0)

public static int TotalNQueens(int n)
{
    int full = (1 << n) - 1;
    int Dfs(int cols, int ld, int rd)
    {
        if (cols == full) return 1;
        int count = 0, free = ~(cols | ld | rd) & full;
        while (free != 0)
        {
            int p = free & -free;
            free ^= p;
            count += Dfs(cols | p, (ld | p) << 1 & full, (rd | p) >> 1);
        }
        return count;
    }
    return Dfs(0, 0, 0);
}

The answers are 1, 0, 0, 2, 10, 4, 40, 92 for n = 1 … 8. A further factor of two comes from symmetry: count only first-row columns in the left half, double, and add the middle column separately when n is odd.

2 · Unique Paths III Hard

On a grid with a start 1, an end 2, empty cells 0 and walls −1, count the walks from start to end that pass over every empty cell exactly once. Insight: it is Word Search with a different success test. Count the cells to cover first; the walk succeeds only if it reaches the end with zero cells remaining. The grid is at most 20 cells, so a plain mark/un-mark DFS is fast (and a (cell, visited-mask) memo is possible if needed).

Solution: grid DFS with a remaining-cell counter 
def unique_paths_iii(grid):
    R, C = len(grid), len(grid[0])
    todo = 0
    for r in range(R):
        for c in range(C):
            if grid[r][c] != -1:
                todo += 1                      # cells the walk must cover
            if grid[r][c] == 1:
                sr, sc = r, c

    def dfs(r, c, left):
        if not (0 <= r < R and 0 <= c < C) or grid[r][c] < 0:
            return 0
        if grid[r][c] == 2:
            return 1 if left == 1 else 0       # the end must be the last cell
        saved, grid[r][c] = grid[r][c], -2     # mark
        ways = (dfs(r + 1, c, left - 1) + dfs(r - 1, c, left - 1) +
                dfs(r, c + 1, left - 1) + dfs(r, c - 1, left - 1))
        grid[r][c] = saved                     # un-mark
        return ways

    return dfs(sr, sc, todo)

public static int UniquePathsIII(int[][] grid)
{
    int R = grid.Length, C = grid[0].Length, todo = 0, sr = 0, sc = 0;
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
        {
            if (grid[r][c] != -1) todo++;
            if (grid[r][c] == 1) { sr = r; sc = c; }
        }

    int Dfs(int r, int c, int left)
    {
        if (r < 0 || r >= R || c < 0 || c >= C || grid[r][c] < 0) return 0;
        if (grid[r][c] == 2) return left == 1 ? 1 : 0;
        int saved = grid[r][c];
        grid[r][c] = -2;                                   // mark
        int ways = Dfs(r + 1, c, left - 1) + Dfs(r - 1, c, left - 1)
                 + Dfs(r, c + 1, left - 1) + Dfs(r, c - 1, left - 1);
        grid[r][c] = saved;                                // un-mark
        return ways;
    }

    return Dfs(sr, sc, todo);
}

Time O(3cells) in the worst case, space O(cells) for the recursion. A cheap extra prune: if the end cell is surrounded by marked cells before left reaches 1, stop.

3 · Expression Add Operators Hard

Insert +, − or * between the digits of num so that the expression equals target; list all such expressions. Insight: multiplication binds tighter, so you cannot just keep a running value. Also keep the last operand. When you append * x, undo the last operand and replace it: value − last + last · x, and the new last operand is last · x. Operands may have several digits but no leading zero.

Solution: carry (value, last operand), O(4ⁿ) 
def add_operators(num, target):
    res, n = [], len(num)

    def dfs(i, expr, value, last):
        if i == n:
            if value == target:
                res.append(expr)
            return
        for j in range(i, n):
            if j > i and num[i] == "0":
                break                           # no multi-digit number with a leading 0
            s = num[i:j + 1]
            x = int(s)
            if i == 0:
                dfs(j + 1, s, x, x)
            else:
                dfs(j + 1, expr + "+" + s, value + x, x)
                dfs(j + 1, expr + "-" + s, value - x, -x)
                dfs(j + 1, expr + "*" + s, value - last + last * x, last * x)

    dfs(0, "", 0, 0)
    return res

public static IList<string> AddOperators(string num, int target)
{
    var res = new List<string>();
    int n = num.Length;
    void Dfs(int i, string expr, long value, long last)
    {
        if (i == n) { if (value == target) res.Add(expr); return; }
        for (int j = i; j < n; j++)
        {
            if (j > i && num[i] == '0') break;
            string s = num.Substring(i, j - i + 1);
            long x = long.Parse(s);
            if (i == 0) { Dfs(j + 1, s, x, x); continue; }
            Dfs(j + 1, expr + "+" + s, value + x, x);
            Dfs(j + 1, expr + "-" + s, value - x, -x);
            Dfs(j + 1, expr + "*" + s, value - last + last * x, last * x);
        }
    }
    Dfs(0, "", 0, 0);
    return res;
}

For "105", target 5: 1*0+5 and 10-5. Each of the n − 1 gaps gets one of four options (nothing, +, −, ×), so there are O(4ⁿ) leaves, each producing a string of length O(n). Use long in C#: a 10-digit operand overflows int.

4 · Word Search II Hard

Find every word from a list that can be traced in the grid. Running Word Search once per word repeats the same walks. Insight: put the words in a trie and walk the grid once, moving down the trie alongside the grid path. A path is pruned the moment its prefix leaves the trie. Two finishing touches make it fast: clear a word at its trie node once found (no duplicates), and delete leaf nodes on the way back so that exhausted branches vanish.

Solution: grid DFS guided by a trie 
def find_words(board, words):
    root = {}
    for w in words:
        node = root
        for ch in w:
            node = node.setdefault(ch, {})
        node["$"] = w                          # word ends here
    R, C, res = len(board), len(board[0]), []

    def dfs(r, c, parent):
        ch = board[r][c]
        node = parent[ch]
        if "$" in node:
            res.append(node.pop("$"))          # report once
        board[r][c] = "#"
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < R and 0 <= nc < C and board[nr][nc] in node:
                dfs(nr, nc, node)
        board[r][c] = ch
        if not node:
            parent.pop(ch)                     # prune the exhausted branch

    for r in range(R):
        for c in range(C):
            if board[r][c] in root:
                dfs(r, c, root)
    return res

public sealed class TrieNode
{
    public readonly Dictionary<char, TrieNode> Next = new();
    public string? Word;
}

public static IList<string> FindWords(char[][] board, string[] words)
{
    var root = new TrieNode();
    foreach (var w in words)
    {
        var node = root;
        foreach (var ch in w)
        {
            if (!node.Next.TryGetValue(ch, out var nx)) node.Next[ch] = nx = new TrieNode();
            node = nx;
        }
        node.Word = w;
    }
    int R = board.Length, C = board[0].Length;
    var res = new List<string>();
    int[] dr = { 1, -1, 0, 0 }, dc = { 0, 0, 1, -1 };

    void Dfs(int r, int c, TrieNode parent)
    {
        char ch = board[r][c];
        var node = parent.Next[ch];
        if (node.Word != null) { res.Add(node.Word); node.Word = null; }
        board[r][c] = '#';
        for (int d = 0; d < 4; d++)
        {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr >= 0 && nr < R && nc >= 0 && nc < C && node.Next.ContainsKey(board[nr][nc]))
                Dfs(nr, nc, node);
        }
        board[r][c] = ch;
        if (node.Next.Count == 0 && node.Word == null) parent.Next.Remove(ch);
    }

    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (root.Next.ContainsKey(board[r][c])) Dfs(r, c, root);
    return res;
}

Time O(R · C · 3L) for the longest word length L, but in practice far less because the trie prunes shared prefixes together. Space O(total letters in the words).

5 · Remove Invalid Parentheses Hard

Remove the minimum number of parentheses to make the string valid; return all distinct results. Insight: compute the minimum first, which is a bound for the search. One scan gives rm_open and rm_close: the unmatched ) and the unmatched (. Then backtrack over positions, deleting only while those budgets allow, keeping open − close ≥ 0 on the prefix, and skipping a deletion when the previous character is the same parenthesis that was kept (the duplicate rule again: deleting either of two adjacent equal characters gives the same string).

Solution: budgeted deletions with a prefix-balance prune 
def remove_invalid_parentheses(s):
    rm_open = rm_close = 0
    for ch in s:
        if ch == "(":
            rm_open += 1
        elif ch == ")":
            if rm_open:
                rm_open -= 1
            else:
                rm_close += 1
    res, path = set(), []

    def dfs(i, bal, ro, rc):
        if ro < 0 or rc < 0 or bal < 0:
            return                              # over budget, or ')' unmatched
        if i == len(s):
            if bal == 0 and ro == 0 and rc == 0:
                res.add("".join(path))
            return
        ch = s[i]
        if ch == "(":
            dfs(i + 1, bal, ro - 1, rc)         # delete it
        elif ch == ")":
            dfs(i + 1, bal, ro, rc - 1)
        path.append(ch)                          # keep it
        dfs(i + 1, bal + (ch == "(") - (ch == ")"), ro, rc)
        path.pop()

    dfs(0, 0, rm_open, rm_close)
    return list(res)

public static IList<string> RemoveInvalidParentheses(string s)
{
    int rmOpen = 0, rmClose = 0;
    foreach (char ch in s)
    {
        if (ch == '(') rmOpen++;
        else if (ch == ')') { if (rmOpen > 0) rmOpen--; else rmClose++; }
    }
    var res = new HashSet<string>();
    var path = new System.Text.StringBuilder();

    void Dfs(int i, int bal, int ro, int rc)
    {
        if (ro < 0 || rc < 0 || bal < 0) return;
        if (i == s.Length)
        {
            if (bal == 0 && ro == 0 && rc == 0) res.Add(path.ToString());
            return;
        }
        char ch = s[i];
        if (ch == '(') Dfs(i + 1, bal, ro - 1, rc);
        else if (ch == ')') Dfs(i + 1, bal, ro, rc - 1);
        path.Append(ch);
        Dfs(i + 1, bal + (ch == '(' ? 1 : 0) - (ch == ')' ? 1 : 0), ro, rc);
        path.Length--;
    }

    Dfs(0, 0, rmOpen, rmClose);
    return res.ToList();
}

The set removes duplicates simply; the "skip equal neighbours" rule removes them earlier, but is easy to get wrong. Time O(2ⁿ · n) in the worst case. The alternative is BFS by number of deletions, stopping at the first level with a valid string: simpler to write, but it generates many more strings.

Self-check

Why does Subsets II use i > start but Permutations II uses i > 0?

In the start-index tree, the siblings at one level are exactly the indices start … n−1, so the left sibling exists only when i > start. A permutation level loops over all indices, and "the same level" is detected through used[i−1] being False (copy i−1 was tried here and released), so i > 0 is just a bounds check.

Your Combination Sum returns [2,2,3], [2,3,2] and [3,2,2]. What is wrong?

The loop starts at 0 at every level, so it generates orderings (permutations), not combinations. Pass the start index and loop from start; recurse with i (reuse allowed) so that values never decrease along a path.

In Word Search, what goes wrong if you forget to restore the cell?

The # stays on the board. Later starting cells and sibling branches can no longer use that letter, so a word that exists is reported as missing. Marking prevents reuse within one path; restoring makes the cell available to other paths.

Why does MRV help Sudoku so much when it does not change the set of solutions?

It changes the order of decisions. A forced cell (one candidate) becomes a free deduction instead of a level of search, and a cell with zero candidates causes an immediate backtrack instead of being discovered many levels deeper. The tree has the same leaves but far fewer dead internal nodes.

Target Sum asks for the number of ways. Backtracking or DP?

DP. Only a count is needed and the future depends only on (index, running sum), so states repeat: memoize on that pair, or turn it into the subset-sum DP on (total + target) / 2. Backtracking would be O(2ⁿ); the memo is O(n · range of sums).

Partition to K: why place the largest number first?

A large item fits in few buckets, so the choices near the root are few, and a hopeless partial assignment is detected after a handful of placements. Small items first postpones every failure to deep in the tree, where the search has already multiplied many small choices.
