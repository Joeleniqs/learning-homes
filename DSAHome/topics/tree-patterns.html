TREES

Tree Problem Patterns

Return-value recursion (diameter, max path sum), top-down state, LCA, serialization, and binary lifting.

Intermediate → Expert~65 min studyBuilds on: Tree TraversalsUpdated 2026-11-03

Once you can traverse a tree, most tree problems come down to one question: which way does the information flow? Either a node needs something its ancestors know (the largest value above it, its depth, the sum so far), so you pass it down as a parameter. Or it needs something its descendants know (a height, a count, "is this subtree valid?"), so each call returns it up. This page turns that one choice into a toolkit. You will see the two recursion shapes side by side, the "bend vs arm" split behind every longest path anywhere problem, lowest common ancestors by recursion and by binary lifting, path sums with a prefix map that undoes itself, serialization, subtree hashing, an O(log² n) count of a complete tree, and rerooting, which answers a question for every possible root in O(n).

The invariant. Every recursive call on a tree has a contract: what it receives from its parent (state flowing down) and what it returns to its parent (a summary flowing up). Write that contract down in one sentence before you code. When the answer can bend through a node, the return value and the answer are different numbers: return the part the parent can extend, and record the full answer in a global.

Prerequisite: Tree Traversals. This page assumes you know preorder, postorder and level order, the TreeNode class and the level-order array format used in every example. Recursion & the Call Stack explains the "leap of faith" that bottom-up recursion depends on. Path Sum III reuses the prefix-sum map from Prefix Sums. Binary Search Trees has the faster BST-only LCA. Next steps: Interval & Tree DP (house robber III, binary tree cameras: tree recursion that returns several values) and Segment Trees, Fenwick Trees & Sparse Tables (the same doubling idea as binary lifting, applied to arrays).

The two shapes of tree recursion

Look at the arrows. On the left, information flows from the root to the leaves: a call cannot start its own work until its parent has told it something. On the right, information flows from the leaves to the root: a call cannot finish until its children have reported back. That is the whole difference between preorder-style and postorder-style work from Tree Traversals, now with a purpose attached.

Top-down: pass state down

A top-down call is like a hiker carrying a backpack. The parent packs it (the max so far, the depth, the remaining sum), and every child gets its own copy. Because a call's state comes only from its ancestors, one number can summarise the entire path above, and that is what makes these solutions O(n) instead of O(n · h). Step through it and watch the label above each node: it is exactly what the parent handed down.

Now switch the problem to path sum II. The state is a list, the path itself, so it cannot simply be copied into every call for free. The standard trick is backtracking: one shared list, append on the way in and pop on the way out, so every call returns the list exactly as it received it.

def good_nodes(root):
    """A node is good if no ancestor is larger. O(n) time, O(h) stack."""
    def dfs(node, best):                 # best = max value on the path ABOVE node
        if node is None:
            return 0
        good = 1 if node.val >= best else 0
        best = max(best, node.val)       # what the children will see
        return good + dfs(node.left, best) + dfs(node.right, best)
    return dfs(root, float("-inf"))


def path_sum_ii(root, target):
    """All root-to-leaf paths summing to target. O(n * h) because of the copies."""
    res, path = [], []
    def dfs(node, remain):
        if node is None:
            return
        path.append(node.val)            # choose
        remain -= node.val
        if node.left is None and node.right is None and remain == 0:
            res.append(path[:])          # copy: path keeps changing
        dfs(node.left, remain)
        dfs(node.right, remain)
        path.pop()                       # un-choose before returning to the parent
    dfs(root, target)
    return res

public static class TopDown
{
    // A node is good if no ancestor is larger. O(n) time, O(h) stack.
    public static int GoodNodes(TreeNode root) => Good(root, int.MinValue);

    static int Good(TreeNode node, int best)      // best = max value on the path ABOVE node
    {
        if (node is null) return 0;
        int good = node.val >= best ? 1 : 0;
        best = Math.Max(best, node.val);          // what the children will see
        return good + Good(node.left, best) + Good(node.right, best);
    }

    // All root-to-leaf paths summing to target. O(n * h) because of the copies.
    public static IList<IList<int>> PathSumII(TreeNode root, int target)
    {
        var res = new List<IList<int>>();
        var path = new List<int>();
        void Dfs(TreeNode node, int remain)
        {
            if (node is null) return;
            path.Add(node.val);                    // choose
            remain -= node.val;
            if (node.left is null && node.right is null && remain == 0)
                res.Add(new List<int>(path));      // copy: path keeps changing
            Dfs(node.left, remain);
            Dfs(node.right, remain);
            path.RemoveAt(path.Count - 1);         // un-choose before returning
        }
        Dfs(root, target);
        return res;
    }
}

Notice that good_nodes is not purely top-down: best flows down, but the count flows back up as a return value. That is normal. Most real solutions mix the two directions; the skill is knowing which fact travels which way.

Why immutable state needs no undo best, depth and remain are integers. Each call gets its own copy, so a child changing it cannot affect a sibling. Only shared mutable state (a list, a set, a counter map) needs the explicit undo step. In Path Sum III below the shared map gets exactly the same +1 on entry and −1 on exit.

Bottom-up: return information up

A bottom-up call is a manager who cannot answer until the reports from both teams arrive. You write it with a leap of faith: assume the recursive calls on the children already return the right thing, and only decide how to combine them. The base case is the empty tree, None, which must return a value that combines correctly (height 0, size 0, "balanced").

When one number is not enough, encode a second fact in the same return value. "Is it balanced?" needs a height and a yes/no. Returning -1 for "already unbalanced" packs both into one int, and it lets the caller stop early: once the left side fails, the right subtree is never visited (watch the dimmed nodes).

def is_balanced(root):
    """Every node's subtrees differ in height by at most 1. O(n)."""
    def h(node):                          # height, or -1 if unbalanced somewhere below
        if node is None:
            return 0
        l = h(node.left)
        if l == -1:
            return -1                     # short-circuit: skip the right subtree
        r = h(node.right)
        if r == -1 or abs(l - r) > 1:
            return -1
        return 1 + max(l, r)
    return h(root) != -1


def subtree_info(node):
    """Return several facts at once: (size, total, min, max). The empty tree is the identity."""
    if node is None:
        return 0, 0, float("inf"), float("-inf")
    ls, lt, lmin, lmax = subtree_info(node.left)
    rs, rt, rmin, rmax = subtree_info(node.right)
    return (1 + ls + rs, node.val + lt + rt,
            min(node.val, lmin, rmin), max(node.val, lmax, rmax))

public static class BottomUp
{
    // Every node's subtrees differ in height by at most 1. O(n).
    public static bool IsBalanced(TreeNode root) => H(root) != -1;

    static int H(TreeNode node)           // height, or -1 if unbalanced somewhere below
    {
        if (node is null) return 0;
        int l = H(node.left);
        if (l == -1) return -1;           // short-circuit: skip the right subtree
        int r = H(node.right);
        if (r == -1 || Math.Abs(l - r) > 1) return -1;
        return 1 + Math.Max(l, r);
    }

    // Several facts at once. The empty tree returns the identity of each combine.
    public static (int Size, long Total, int Min, int Max) SubtreeInfo(TreeNode node)
    {
        if (node is null) return (0, 0, int.MaxValue, int.MinValue);
        var l = SubtreeInfo(node.left);
        var r = SubtreeInfo(node.right);
        return (1 + l.Size + r.Size, node.val + l.Total + r.Total,
                Math.Min(node.val, Math.Min(l.Min, r.Min)),
                Math.Max(node.val, Math.Max(l.Max, r.Max)));
    }
}

The tuple form is the general tool. "Validate a BST" returns (min, max); "largest BST subtree" returns (is_bst, size, min, max); tree DP returns (best if I take this node, best if I skip it). The base case is always the identity of the combine step: size 0, sum 0, min = +∞, max = −∞. Pick those and the leaves need no special case.

Pitfall: calling height() inside the recursion is_balanced(node) = abs(height(node.left) - height(node.right)) <= 1 and is_balanced(node.left) and ... looks innocent, but it recomputes every height from scratch at every ancestor: O(n²) on a chain of 10⁵ nodes. If a function calls another full traversal on each node, ask whether the inner result can be returned instead.

Global best vs return value: the bend

Diameter is the smallest example. The longest path in a tree has a highest node, where it bends and goes down both sides. So for every node you consider "the longest path that bends here" = left depth + right depth, and keep the maximum. But what you return must be something the parent can use, and a parent can only attach to one arm: a path that went down both sides of the child and then up to the parent would visit the child twice. Watch the two labels: above each node is the bend candidate, below it is the return value. They are rarely equal.

Maximum path sum adds negative numbers, which adds one more decision: an arm with a negative gain is worse than no arm at all, so clip it to 0. The dashed red edges are arms that were dropped. The final purple path is reconstructed from the choices the recursion made.

The same skeleton solves a whole family. Only the meaning of "arm" changes.

def longest_univalue_path(root):
    """Edges on the longest path whose nodes all share one value. O(n)."""
    best = 0
    def arm(node):                        # longest same-value path going DOWN from node
        nonlocal best
        if node is None:
            return 0
        l, r = arm(node.left), arm(node.right)
        left = l + 1 if node.left and node.left.val == node.val else 0
        right = r + 1 if node.right and node.right.val == node.val else 0
        best = max(best, left + right)    # bend here
        return max(left, right)           # one arm continues up
    arm(root)
    return best

public static class UnivaluePath
{
    // Edges on the longest path whose nodes all share one value. O(n).
    public static int LongestUnivaluePath(TreeNode root)
    {
        int best = 0;
        int Arm(TreeNode node)            // longest same-value path going DOWN from node
        {
            if (node is null) return 0;
            int l = Arm(node.left), r = Arm(node.right);
            int left = node.left != null && node.left.val == node.val ? l + 1 : 0;
            int right = node.right != null && node.right.val == node.val ? r + 1 : 0;
            best = Math.Max(best, left + right);   // bend here
            return Math.Max(left, right);          // one arm continues up
        }
        Arm(root);
        return best;
    }
}

Note that arm(node.left) is called even when the child's value differs. The child's own subtree may contain the best path, and only a full traversal finds it. Skipping the call is a common wrong answer.

Lowest common ancestor

The lowest common ancestor (LCA) of p and q is the deepest node that has both in its subtree (a node counts as its own ancestor). In a BST the values tell you which way to go. In a general binary tree you must search, and the elegant way is bottom-up: each call returns what it found in its subtree.

  • None: neither p nor q is below me.
  • p or q: I found one of them (or I am one of them).
  • the LCA itself: both were below me and they met at or under me.

The node where a non-null value arrives from both sides is the split point. Above it, only one side is ever non-null, so the LCA is passed up unchanged to the root.

The early return at p is the subtle part. If q is inside p's subtree, the search never sees q at all, yet the answer is still right: nothing else is non-null, so p travels up alone and is the LCA. Try p = 5, q = 4:

That shortcut silently assumes both nodes exist. If they might not (LeetCode 1644), visit the whole tree, count how many targets you saw, and return the result only if the count is 2. Variants worth knowing:

def lca_maybe_missing(root, p, q):
    """LCA if both p and q (p is not q) are in the tree, else None. O(n): no early exit."""
    found = 0
    def dfs(node):
        nonlocal found
        if node is None:
            return None
        left, right = dfs(node.left), dfs(node.right)   # always search both sides
        if node is p or node is q:
            found += 1
            return node
        if left and right:
            return node
        return left or right
    ans = dfs(root)
    return ans if found == 2 else None


def lca_with_parents(p, q):
    """Nodes have .parent. Two pointers, like intersecting linked lists. O(h), O(1) space."""
    a, b = p, q
    while a is not b:
        a = a.parent if a else q          # after the root, restart at the other node
        b = b.parent if b else p
    return a


def lca_deepest_leaves(root):
    """Smallest subtree containing all deepest leaves. Returns (depth, lca) per call."""
    def dfs(node):
        if node is None:
            return 0, None
        ld, ln = dfs(node.left)
        rd, rn = dfs(node.right)
        if ld > rd:
            return ld + 1, ln
        if rd > ld:
            return rd + 1, rn
        return ld + 1, node               # equally deep on both sides: they meet here
    return dfs(root)[1]

public class PNode
{
    public int val;
    public PNode left, right, parent;
    public PNode(int val) { this.val = val; }
}

public static class LcaVariants
{
    // LCA if both p and q (p != q) are in the tree, else null. O(n): no early exit.
    public static TreeNode LcaMaybeMissing(TreeNode root, TreeNode p, TreeNode q)
    {
        int found = 0;
        TreeNode Dfs(TreeNode node)
        {
            if (node is null) return null;
            TreeNode left = Dfs(node.left), right = Dfs(node.right);   // always search both
            if (node == p || node == q) { found++; return node; }
            if (left != null && right != null) return node;
            return left ?? right;
        }
        var ans = Dfs(root);
        return found == 2 ? ans : null;
    }

    // Nodes have parent pointers. Two pointers, like intersecting linked lists. O(h), O(1) space.
    public static PNode LcaWithParents(PNode p, PNode q)
    {
        PNode a = p, b = q;
        while (a != b)
        {
            a = a is null ? q : a.parent;    // after the root, restart at the other node
            b = b is null ? p : b.parent;
        }
        return a;
    }

    // Smallest subtree containing all deepest leaves. Each call returns (depth, lca).
    public static TreeNode LcaDeepestLeaves(TreeNode root) => Deep(root).Lca;

    static (int Depth, TreeNode Lca) Deep(TreeNode node)
    {
        if (node is null) return (0, null);
        var l = Deep(node.left);
        var r = Deep(node.right);
        if (l.Depth > r.Depth) return (l.Depth + 1, l.Lca);
        if (r.Depth > l.Depth) return (r.Depth + 1, r.Lca);
        return (l.Depth + 1, node);           // equally deep on both sides: they meet here
    }
}

Binary lifting: jump in powers of two

The recursion above costs O(n) per query. With 10⁵ queries on a 10⁵-node tree that is 10¹⁰ steps. Walking up parent by parent from both nodes is O(depth), which is also O(n) on a chain. The fix is to precompute jumps: for every node, its 1st, 2nd, 4th, 8th, … ancestor.

Two operations use the table:

  1. k-th ancestor: write k in binary and take one jump per set bit, O(log n).
  2. LCA(u, v): first lift the deeper node until both are at the same depth. If they are now equal, done. Otherwise try jumps from the largest power down. A jump is safe only if it lands the two nodes on different ancestors: then both are still strictly below the LCA. After all powers are tried, u and v are the two children of the LCA, so the answer is their parent.

Why "jump only if different"? Landing on the same node proves it is a common ancestor, but not that it is the lowest one: you may have overshot. Jumping only while they differ is a binary search on the meeting height, and it never overshoots. Step through the table being built row by row, then the query:

class BinaryLifting:
    """parent[root] == -1. O(n log n) build, O(log n) per query."""

    def __init__(self, parent):
        n = len(parent)
        self.LOG = max(1, (n - 1).bit_length())       # 2**LOG > any depth
        children = [[] for _ in range(n)]
        root = 0
        for v, p in enumerate(parent):
            if p == -1:
                root = v
            else:
                children[p].append(v)
        self.depth = [0] * n
        order = [root]
        for v in order:                               # BFS: parents before children
            for c in children[v]:
                self.depth[c] = self.depth[v] + 1
                order.append(c)
        self.up = [[p if p != -1 else v for v, p in enumerate(parent)]]   # root -> itself
        for _ in range(1, self.LOG):
            prev = self.up[-1]
            self.up.append([prev[prev[v]] for v in range(n)])         # 2^k = 2^(k-1) twice

    def kth_ancestor(self, v, k):
        if k > self.depth[v]:
            return -1
        for j in range(self.LOG):
            if k >> j & 1:
                v = self.up[j][v]
        return v

    def lca(self, u, v):
        if self.depth[u] < self.depth[v]:
            u, v = v, u
        u = self.kth_ancestor(u, self.depth[u] - self.depth[v])
        if u == v:
            return u
        for k in reversed(range(self.LOG)):
            if self.up[k][u] != self.up[k][v]:        # still below the LCA: jump both
                u, v = self.up[k][u], self.up[k][v]
        return self.up[0][u]

    def dist(self, u, v):
        return self.depth[u] + self.depth[v] - 2 * self.depth[self.lca(u, v)]

public class BinaryLifting
{
    readonly int LOG;
    readonly int[][] up;
    readonly int[] depth;

    // parent[root] == -1. O(n log n) build, O(log n) per query.
    public BinaryLifting(int[] parent)
    {
        int n = parent.Length;
        LOG = 1;
        while ((1 << LOG) < n) LOG++;                  // 2^LOG > any depth
        var children = new List<int>[n];
        for (int v = 0; v < n; v++) children[v] = new List<int>();
        int root = 0;
        for (int v = 0; v < n; v++)
            if (parent[v] == -1) root = v; else children[parent[v]].Add(v);
        depth = new int[n];
        var order = new List<int> { root };
        for (int i = 0; i < order.Count; i++)          // BFS: parents before children
            foreach (int c in children[order[i]]) { depth[c] = depth[order[i]] + 1; order.Add(c); }
        up = new int[LOG][];
        up[0] = new int[n];
        for (int v = 0; v < n; v++) up[0][v] = parent[v] == -1 ? v : parent[v];   // root -> itself
        for (int k = 1; k < LOG; k++)
        {
            up[k] = new int[n];
            for (int v = 0; v < n; v++) up[k][v] = up[k - 1][up[k - 1][v]];      // 2^k = 2^(k-1) twice
        }
    }

    public int KthAncestor(int v, int k)
    {
        if (k > depth[v]) return -1;
        for (int j = 0; j < LOG; j++)
            if (((k >> j) & 1) == 1) v = up[j][v];
        return v;
    }

    public int Lca(int u, int v)
    {
        if (depth[u] < depth[v]) (u, v) = (v, u);
        u = KthAncestor(u, depth[u] - depth[v]);
        if (u == v) return u;
        for (int k = LOG - 1; k >= 0; k--)
            if (up[k][u] != up[k][v]) { u = up[k][u]; v = up[k][v]; }   // still below the LCA
        return up[0][u];
    }

    public int Dist(int u, int v) => depth[u] + depth[v] - 2 * depth[Lca(u, v)];
}

This class is the solution to Kth Ancestor of a Tree Node. The table can also carry path aggregates: store mx[k][v] = the largest edge weight on the 2k edges above v, update it with the same doubling rule, and every jump of the LCA query also collects the path maximum. When the aggregate is a count or sum that you can subtract, you do not even need that: keep a prefix value from the root (cnt[v]), and the path u–v is cnt[u] + cnt[v] − 2·cnt[lca]. Worked problem 7 does exactly that.

Other ways to answer many LCA queries. An Euler tour writes down nodes as the DFS enters and returns to them; the LCA of u and v is the shallowest node between their first appearances, a range-minimum query that a sparse table answers in O(1). Tarjan's offline LCA answers all queries in one DFS with union-find. Binary lifting is the most flexible: it also gives k-th ancestors and path aggregates.

Path Sum III is the interesting one. A downward path from a to b is a contiguous piece of the root-to-b path. On a root path, "a contiguous piece sums to target" is exactly subarray sum equals k: prefix(b) − prefix(above a) = target, so at each node look up how many earlier prefixes equal cur − target.

The only new part is the undo. In an array every earlier prefix stays valid forever. In a tree, when the DFS finishes a node and moves to a sibling branch, that node's prefix is no longer above anything the search will visit, so it must leave the map. Serialization: a tree as a string

To store a tree, send it over a network or use it as a dictionary key, you need a string that describes the shape as well as the values. Preorder alone is ambiguous (1,2 could be "2 is the left child" or "2 is the right child"). Preorder with a marker for every empty child is not.

Why does it work? A preorder token stream with null markers has a recursive grammar: a tree is either # or value tree tree. The decoder is that grammar written as a function. It reads one token; if it is # it returns None; otherwise it builds a node and recursively reads exactly one left tree and one right tree. The tokens tell it where each subtree ends.

Encoding Unique? Notes
Preorder + null markers yes the standard answer; postorder + nulls also works (decode from the right end)
Level order + nulls (LeetCode format) yes BFS on both sides; the format in Tree Traversals
Inorder + null markers no # 1 # 2 # is both "1 with right child 2" and "2 with left child 1"

Subtree identity: hashing trees

Subtree of Another Tree asks whether sub appears inside root (same shape, same values, all the way to the leaves). The direct way compares sub against every node: O(m · n). The fast way gives every distinct subtree a small integer id:

  • The empty tree has id 0.
  • A node's id is determined by the triple (id of left, value, id of right). Look the triple up in a dictionary; if it is new, give it the next id.

Two subtrees are identical if and only if they get the same id, by induction from the leaves up. Each node's key is three small numbers, so building all ids is O(n) expected time. That beats serializing every subtree into a string, where the keys themselves add up to O(n²) characters. The same ids find duplicate subtrees: report a node the second time its id is seen.

Ids vs hashes Assigning ids through a dictionary is exact: there are no collisions, because the dictionary compares whole triples. A numeric rolling hash ("Merkle hash") avoids the dictionary but can collide, so production code either uses 64-bit hashes plus a verification step or uses ids like these. Serializing sub and root with separators and running KMP is the third O(m + n) option.

Complete trees: counting in O(log² n)

A complete tree fills every level except possibly the last, and the last level is filled from the left (it is the shape of a heap). Count Complete Tree Nodes wants the count faster than O(n).

Walk the left edge and the right edge of a subtree. If they have the same length h, the last level under it is full, so the subtree is perfect and has 2h − 1 nodes: no need to look inside. If not, count the root and recurse into both children. The key fact: one of the two children is always perfect. The last node of the tree is in either the left or the right half, and the other half is full. So only one path recurses, it is O(log n) long, and each step does an O(log n) spine walk.

Rerooting: an answer for every root

Some problems ask for a value for every node as if it were the root: the sum of distances from each node to all others, the height of the tree rooted at each node, the number of valid orientations if each node were the root. Running a fresh DFS from every node is O(n²). Rerooting does it in two passes:

  1. Pass 1 (postorder), rooted anywhere (say node 0): compute subtree summaries such as size[v] and down[v] = the answer inside v's subtree. Now ans[0] is known.
  2. Pass 2 (preorder): move the root from a node v to its child c across one edge, and compute ans[c] from ans[v] in O(1) by asking what changed?

For the sum of distances, moving the root from v to c brings the size[c] nodes in c's subtree one step closer and pushes the other n − size[c] nodes one step farther, so ans[c] = ans[v] − size[c] + (n − size[c]). The visualizer runs both passes and checks every answer against a BFS from every node.

When the combine step cannot be undone (max instead of sum), you cannot subtract c's contribution from ans[v]. Store the best two child values instead (or prefix and suffix maxima over the children), so that "the best of v excluding c" is available in O(1). Here is the height of the tree for every possible root, which is also how Minimum Height Trees can be solved without leaf trimming:

def heights_for_every_root(n, edges):
    """h[v] = max distance from v to any node. O(n), iterative (safe for deep trees)."""
    adj = [[] for _ in range(n)]
    for a, b in edges:
        adj[a].append(b)
        adj[b].append(a)
    parent, order = [-1] * n, [0]
    seen = [False] * n
    seen[0] = True
    for v in order:                          # BFS order: parents before children
        for c in adj[v]:
            if not seen[c]:
                seen[c] = True
                parent[c] = v
                order.append(c)
    down1, down2 = [0] * n, [0] * n          # best and second-best depth going DOWN
    for v in reversed(order):                # pass 1: children before parents
        p = parent[v]
        if p != -1:
            d = down1[v] + 1
            if d > down1[p]:
                down1[p], down2[p] = d, down1[p]
            elif d > down2[p]:
                down2[p] = d
    up = [0] * n                             # longest path that leaves v through its parent
    for v in order[1:]:                      # pass 2: parents before children
        p = parent[v]
        sibling_best = down2[p] if down1[v] + 1 == down1[p] else down1[p]   # p's best, excluding v
        up[v] = 1 + max(up[p], sibling_best)
    return [max(down1[v], up[v]) for v in range(n)]

public static class Rerooting
{
    // h[v] = max distance from v to any node. O(n), iterative (safe for deep trees).
    public static int[] HeightsForEveryRoot(int n, int[][] edges)
    {
        var adj = new List<int>[n];
        for (int i = 0; i < n; i++) adj[i] = new List<int>();
        foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
        var parent = new int[n];
        Array.Fill(parent, -1);
        var seen = new bool[n];
        var order = new List<int> { 0 };
        seen[0] = true;
        for (int i = 0; i < order.Count; i++)          // BFS order: parents before children
            foreach (int c in adj[order[i]])
                if (!seen[c]) { seen[c] = true; parent[c] = order[i]; order.Add(c); }
        int[] down1 = new int[n], down2 = new int[n];   // best and second-best depth going DOWN
        for (int i = order.Count - 1; i > 0; i--)       // pass 1: children before parents
        {
            int v = order[i], p = parent[v], d = down1[v] + 1;
            if (d > down1[p]) { down2[p] = down1[p]; down1[p] = d; }
            else if (d > down2[p]) down2[p] = d;
        }
        var up = new int[n];                            // longest path leaving v through its parent
        for (int i = 1; i < order.Count; i++)           // pass 2: parents before children
        {
            int v = order[i], p = parent[v];
            int siblingBest = down1[v] + 1 == down1[p] ? down2[p] : down1[p];   // p's best, excluding v
            up[v] = 1 + Math.Max(up[p], siblingBest);
        }
        var h = new int[n];
        for (int v = 0; v < n; v++) h[v] = Math.Max(down1[v], up[v]);
        return h;
    }
}

The down1[v] + 1 == down1[p] test is the "exclude me" trick. If v's branch is p's best branch, the best alternative is p's second best; otherwise p's best is still available. Ties work out, because a tie puts the same value in both down1 and down2. Rerooting is a kind of tree DP; Interval & Tree DP goes further with states such as "this node takes a camera / is covered / needs cover".

def boundary_of_binary_tree(root):
    """Anticlockwise boundary: root, left edge, leaves, right edge reversed. O(n)."""
    if root is None:
        return []
    def is_leaf(n):
        return n.left is None and n.right is None
    res = [root.val]
    node = root.left                          # left edge, top-down, skipping leaves
    while node:
        if not is_leaf(node):
            res.append(node.val)
        node = node.left if node.left else node.right
    def leaves(node):                         # every leaf, left to right
        if node is None:
            return
        if is_leaf(node) and node is not root:
            res.append(node.val)
        leaves(node.left)
        leaves(node.right)
    leaves(root)
    right, node = [], root.right              # right edge, top-down, then reversed
    while node:
        if not is_leaf(node):
            right.append(node.val)
        node = node.right if node.right else node.left
    return res + right[::-1]

public static class Boundary
{
    // Anticlockwise boundary: root, left edge, leaves, right edge reversed. O(n).
    public static IList<int> BoundaryOfBinaryTree(TreeNode root)
    {
        var res = new List<int>();
        if (root is null) return res;
        static bool IsLeaf(TreeNode n) => n.left is null && n.right is null;
        res.Add(root.val);
        for (var node = root.left; node != null; node = node.left ?? node.right)   // left edge
            if (!IsLeaf(node)) res.Add(node.val);
        void Leaves(TreeNode node)                                                 // all leaves
        {
            if (node is null) return;
            if (IsLeaf(node) && node != root) res.Add(node.val);
            Leaves(node.left);
            Leaves(node.right);
        }
        Leaves(root);
        var right = new List<int>();
        for (var node = root.right; node != null; node = node.right ?? node.left)  // right edge
            if (!IsLeaf(node)) right.Add(node.val);
        right.Reverse();
        res.AddRange(right);
        return res;
    }
}

Choosing a pattern

Recognize it when

  • "for every node … its ancestors", "from the root", "good node", "path from the root": top-down parameter.
  • "height", "depth of the subtree", "balanced", "size", "valid": bottom-up return value (tuple if you need several facts).
  • "path between any two nodes", "does not need to pass through the root", "longest/maximum path": bend vs arm with a global best.
  • "lowest common ancestor", "distance between two nodes", "directions from u to v": LCA (recursion once; binary lifting for many queries).
  • "k-th ancestor", "10⁵ queries on a tree", "path max/min/count between u and v": binary lifting, possibly with prefix values from the root.
  • "number of paths … going downwards", "sum equals target": prefix-sum map on the root path with undo.
  • "serialize", "same structure", "duplicate subtrees", "subtree of": serialization with null markers, or canonical ids.
  • "complete binary tree" plus "faster than O(n)": compare spine heights.
  • "for each node, as if it were the root", "sum of distances", "answer for all roots": rerooting.

Pitfalls

Returning the answer instead of the arm return node.val + l + r in max path sum (or return l + r in diameter) lets the parent extend a path that already forks. Fix: two different numbers. Record val + l + r in best; return val + max(l, r).

Initialising the global best to 0 With all-negative values, the max path sum is the largest single node, for example -3. Starting best = 0 returns 0, which is not a path. Fix: start at -inf (or the root's value). Clipping the arms at 0 is right; clipping the answer is not.

Forgetting to undo shared state In Path Sum II, a missing path.pop() leaves stale values that leak into sibling paths. In Path Sum III, a missing seen[cur] -= 1 counts "paths" that start in one branch and end in another. Fix: every mutation on the way down has an exact inverse on the way up, placed after both recursive calls.

Appending the list instead of a copy res.append(path) stores a reference to the one list that keeps changing; at the end every entry is []. Fix: res.append(path[:]) (C#: new List<int>(path)).

Comparing nodes by value LCA, distance-K and duplicate-subtree problems hand you node objects, and values can repeat. node.val == p.val finds the wrong node. Fix: compare identity (node is p in Python, reference == in C#).

Overshooting in binary lifting Jumping "while the ancestors are equal", or jumping from small powers to large ones, lands above the LCA. Fix: after equalising depths, go from the largest k down to 0 and jump only when up[k][u] != up[k][v]; the answer is up[0][u]. Also make the root its own parent, so oversized jumps stay inside the table.

Recursion depth A 10⁵-node chain overflows Python's default limit of 1000 frames. Fix: sys.setrecursionlimit (and a bigger thread stack for very deep trees, see Recursion), or an iterative BFS order like the rerooting code above: process reversed(order) for postorder work and order for preorder work.

Ambiguous serialization Joining values without separators ("12" could be 1, 2 or twelve) or without null markers loses information. Negative numbers break a parser that splits on -. Fix: a delimiter between every token and an explicit marker for every empty child. For subtree matching by string, also add a delimiter before each value so 2 does not match the end of 12.

1. Binary Tree Maximum Path Sum (Hard)

Problem. A path is any sequence of nodes connected by edges, each node used at most once; it need not pass through the root. Return the largest sum of a path. Values may be negative.

Insight. The best path has a highest node, where it bends. For each node compute the best downward gain on each side, clipped at 0, record val + l + r, and return val + max(l, r). The visualizer above shows both numbers per node and reconstructs the winning path.

Solution 
def max_path_sum(root):
    best = float("-inf")                  # not 0: all values may be negative
    def gain(node):                       # best path that starts at node and goes down
        nonlocal best
        if node is None:
            return 0
        l = max(gain(node.left), 0)       # a negative arm is worse than no arm
        r = max(gain(node.right), 0)
        best = max(best, node.val + l + r)    # bend here: a complete path
        return node.val + max(l, r)           # one arm: extendable by the parent
    gain(root)
    return best

public static class MaxPathSumSolution
{
    public static int MaxPathSum(TreeNode root)
    {
        int best = int.MinValue;                   // not 0: all values may be negative
        int Gain(TreeNode node)                    // best path that starts at node and goes down
        {
            if (node is null) return 0;
            int l = Math.Max(Gain(node.left), 0);  // a negative arm is worse than no arm
            int r = Math.Max(Gain(node.right), 0);
            best = Math.Max(best, node.val + l + r);   // bend here: a complete path
            return node.val + Math.Max(l, r);          // one arm: extendable by the parent
        }
        Gain(root);
        return best;
    }
}

Complexity. O(n) time, O(h) stack. Check: [-3] → −3; [-10,9,20,null,null,15,7] → 42 (15 + 20 + 7).

2. Lowest Common Ancestor of a Binary Tree (Medium)

Problem. Given the root and two nodes p and q that are both in the tree, return their lowest common ancestor.

Insight. Each call returns what it found below: None, a target, or the LCA. The first node that receives a non-null value from both sides is the split point. Returning at p or q immediately is safe because both are guaranteed to exist.

Solution 
def lowest_common_ancestor(root, p, q):
    if root is None or root is p or root is q:
        return root                       # nothing here, or found a target
    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)
    if left and right:
        return root                       # one target on each side: split here
    return left or right                  # pass up whatever was found

public static class LcaSolution
{
    public static TreeNode LowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q)
    {
        if (root is null || root == p || root == q) return root;   // nothing here, or a target
        var left = LowestCommonAncestor(root.left, p, q);
        var right = LowestCommonAncestor(root.right, p, q);
        if (left != null && right != null) return root;            // split here
        return left ?? right;                                      // pass up whatever was found
    }
}

3. Path Sum III (Medium)

Problem. Count the downward paths (any start node, any end node below it) whose values sum to target.

Insight. On the current root path this is subarray-sum-equals-k: count earlier prefixes equal to cur − target. Keep a map of prefix counts for the current root path only: add a node's prefix after looking it up, and remove it after both children are done.

Solution 
from collections import defaultdict


def path_sum_iii(root, target):
    seen = defaultdict(int)
    seen[0] = 1                           # empty prefix: paths that start at the root
    def dfs(node, cur):
        if node is None:
            return 0
        cur += node.val
        found = seen[cur - target]        # paths ending at node (look up BEFORE adding cur)
        seen[cur] += 1
        found += dfs(node.left, cur) + dfs(node.right, cur)
        seen[cur] -= 1                    # leaving: no longer above the next branch
        return found
    return dfs(root, 0)

public static class PathSumIII
{
    public static int PathSum(TreeNode root, int target)
    {
        var seen = new Dictionary<long, int> { [0] = 1 };   // empty prefix: paths from the root
        int Dfs(TreeNode node, long cur)
        {
            if (node is null) return 0;
            cur += node.val;
            int found = seen.GetValueOrDefault(cur - target);   // look up BEFORE adding cur
            seen[cur] = seen.GetValueOrDefault(cur) + 1;
            found += Dfs(node.left, cur) + Dfs(node.right, cur);
            seen[cur]--;                                        // leaving this branch
            return found;
        }
        return Dfs(root, 0);
    }
}

Complexity. O(n) expected time, O(h) map entries and stack. Use long in C#: LeetCode includes values near 10⁹ whose sums overflow int. Looking up before inserting cur matters when target == 0: otherwise the empty path at the node would count itself.

4. Serialize and Deserialize Binary Tree (Hard)

Problem. Design serialize(root) -> str and deserialize(str) -> root so that a round trip gives back the same tree.

Insight. Preorder with a # for each empty child. The decoder is the same recursion: read a token; # means None; otherwise create the node and decode its left subtree, then its right subtree. The tokens are consumed in the order they were written.

Solution 
class Codec:
    def serialize(self, root):
        out = []
        def walk(node):                   # preorder: node, left, right
            if node is None:
                out.append("#")
                return
            out.append(str(node.val))
            walk(node.left)
            walk(node.right)
        walk(root)
        return ",".join(out)

    def deserialize(self, data):
        tokens = iter(data.split(","))
        def build():                      # consumes exactly one subtree's tokens
            tok = next(tokens)
            if tok == "#":
                return None
            node = TreeNode(int(tok))
            node.left = build()
            node.right = build()
            return node
        return build()

public class Codec
{
    public string Serialize(TreeNode root)
    {
        var sb = new StringBuilder();
        void Walk(TreeNode node)                   // preorder: node, left, right
        {
            if (sb.Length > 0) sb.Append(',');
            if (node is null) { sb.Append('#'); return; }
            sb.Append(node.val);
            Walk(node.left);
            Walk(node.right);
        }
        Walk(root);
        return sb.ToString();
    }

    public TreeNode Deserialize(string data)
    {
        var tokens = data.Split(',');
        int i = 0;
        TreeNode Build()                           // consumes exactly one subtree's tokens
        {
            string tok = tokens[i++];
            if (tok == "#") return null;
            var node = new TreeNode(int.Parse(tok));
            node.left = Build();
            node.right = Build();
            return node;
        }
        return Build();
    }
}

Complexity. O(n) time and space each way. An empty tree serializes to "#". For very deep trees in Python, either raise the recursion limit or write walk with an explicit stack (push right, then left).

5. Find Duplicate Subtrees and Subtree of Another Tree (Medium)

Problem. (652) Return one root for every subtree shape that occurs at least twice. (572) Decide whether sub occurs as a complete subtree of root.

Insight. Canonical ids: id(node) = ids[(id(left), val, id(right))], with a fresh id for each new triple. Equal ids mean equal subtrees, exactly. For 652 report a node when its id's count reaches 2. For 572 compute the ids of root and sub in the same dictionary and check whether sub's id appears among root's.

Solution 
from collections import defaultdict


def find_duplicate_subtrees(root):
    ids, count, res = {}, defaultdict(int), []
    def uid(node):
        if node is None:
            return 0
        key = (uid(node.left), node.val, uid(node.right))
        i = ids.setdefault(key, len(ids) + 1)   # new shape -> next id
        count[i] += 1
        if count[i] == 2:                       # report each shape exactly once
            res.append(node)
        return i
    uid(root)
    return res


def is_subtree(root, sub):
    ids, in_root = {}, set()
    def uid(node, record):
        if node is None:
            return 0
        key = (uid(node.left, record), node.val, uid(node.right, record))
        i = ids.setdefault(key, len(ids) + 1)
        if record:
            in_root.add(i)
        return i
    uid(root, True)
    return uid(sub, False) in in_root

public static class SubtreeIds
{
    public static IList<TreeNode> FindDuplicateSubtrees(TreeNode root)
    {
        var ids = new Dictionary<(int, int, int), int>();
        var count = new Dictionary<int, int>();
        var res = new List<TreeNode>();
        int Uid(TreeNode node)
        {
            if (node is null) return 0;
            var key = (Uid(node.left), node.val, Uid(node.right));
            if (!ids.TryGetValue(key, out int i)) { i = ids.Count + 1; ids[key] = i; }   // new shape
            count[i] = count.GetValueOrDefault(i) + 1;
            if (count[i] == 2) res.Add(node);        // report each shape exactly once
            return i;
        }
        Uid(root);
        return res;
    }

    public static bool IsSubtree(TreeNode root, TreeNode sub)
    {
        var ids = new Dictionary<(int, int, int), int>();
        var inRoot = new HashSet<int>();
        int Uid(TreeNode node, bool record)
        {
            if (node is null) return 0;
            var key = (Uid(node.left, record), node.val, Uid(node.right, record));
            if (!ids.TryGetValue(key, out int i)) { i = ids.Count + 1; ids[key] = i; }
            if (record) inRoot.Add(i);
            return i;
        }
        Uid(root, true);
        return inRoot.Contains(Uid(sub, false));
    }
}

Complexity. O(n + m) expected time and space. The naive "compare at every node" for 572 is O(n · m) and is fine for its limits (2000 nodes), but the id method also answers 652 and scales.

6. Count Complete Tree Nodes (Easy, with a Medium twist)

Problem. Count the nodes of a complete binary tree in less than O(n).

Insight. Compare the left-spine and right-spine lengths. Equal means perfect: 2h − 1. Otherwise 1 + both children, and one child is always perfect, so only one path recurses.

Solution 
def count_nodes(root):
    if root is None:
        return 0
    lh, node = 0, root
    while node:                           # left spine
        lh += 1
        node = node.left
    rh, node = 0, root
    while node:                           # right spine
        rh += 1
        node = node.right
    if lh == rh:                          # perfect: never look inside
        return (1 << lh) - 1
    return 1 + count_nodes(root.left) + count_nodes(root.right)

public static class CompleteTree
{
    public static int CountNodes(TreeNode root)
    {
        if (root is null) return 0;
        int lh = 0, rh = 0;
        for (var n = root; n != null; n = n.left) lh++;    // left spine
        for (var n = root; n != null; n = n.right) rh++;   // right spine
        if (lh == rh) return (1 << lh) - 1;                // perfect: never look inside
        return 1 + CountNodes(root.left) + CountNodes(root.right);
    }
}

Complexity. O(log² n) time, O(log n) stack. An alternative with the same bound binary-searches the index of the last node on the bottom level, testing each candidate by walking its bits from the root.

7. Minimum Edge Weight Equilibrium Queries in a Tree (Hard)

Problem. A tree has n nodes and weighted edges (weights 1 to 26). For each query (a, b), return the minimum number of edges on the path a–b whose weight must change so that all weights on the path are equal. Up to 10⁴ nodes and 2·10⁴ queries.

Insight. Keep the most common weight and change the rest: answer = path length − max count of one weight. Path length is depth[a] + depth[b] − 2·depth[lca]. Counts per weight are prefix values from the root: cnt[v][w] = edges of weight w on the root–v path, so the path count is cnt[a][w] + cnt[b][w] − 2·cnt[lca][w]. Binary lifting gives the LCA in O(log n).

Solution 
def min_operations_queries(n, edges, queries):
    adj = [[] for _ in range(n)]
    for u, v, w in edges:
        adj[u].append((v, w))
        adj[v].append((u, w))
    LOG = max(1, (n - 1).bit_length())
    parent, depth = [0] * n, [0] * n                 # root 0 is its own parent
    cnt = [[0] * 27 for _ in range(n)]               # cnt[v][w]: weight-w edges on root..v
    order, seen = [0], [False] * n
    seen[0] = True
    for v in order:                                  # BFS, so no recursion limit issues
        for c, w in adj[v]:
            if not seen[c]:
                seen[c] = True
                parent[c], depth[c] = v, depth[v] + 1
                cnt[c] = cnt[v][:]
                cnt[c][w] += 1
                order.append(c)
    up = [parent]
    for _ in range(1, LOG):
        prev = up[-1]
        up.append([prev[prev[v]] for v in range(n)])

    def lca(u, v):
        if depth[u] < depth[v]:
            u, v = v, u
        diff = depth[u] - depth[v]
        for k in range(LOG):
            if diff >> k & 1:
                u = up[k][u]
        if u == v:
            return u
        for k in reversed(range(LOG)):
            if up[k][u] != up[k][v]:
                u, v = up[k][u], up[k][v]
        return up[0][u]

    out = []
    for a, b in queries:
        c = lca(a, b)
        length = depth[a] + depth[b] - 2 * depth[c]
        most = max(cnt[a][w] + cnt[b][w] - 2 * cnt[c][w] for w in range(1, 27))
        out.append(length - most)
    return out

public static class EquilibriumQueries
{
    public static int[] MinOperationsQueries(int n, int[][] edges, int[][] queries)
    {
        var adj = new List<(int To, int W)>[n];
        for (int i = 0; i < n; i++) adj[i] = new List<(int, int)>();
        foreach (var e in edges) { adj[e[0]].Add((e[1], e[2])); adj[e[1]].Add((e[0], e[2])); }
        int LOG = 1;
        while ((1 << LOG) < n) LOG++;
        var up = new int[LOG][];
        up[0] = new int[n];                              // root 0 is its own parent
        var depth = new int[n];
        var cnt = new int[n][];                          // cnt[v][w]: weight-w edges on root..v
        cnt[0] = new int[27];
        var seen = new bool[n];
        var order = new List<int> { 0 };
        seen[0] = true;
        for (int i = 0; i < order.Count; i++)
        {
            int v = order[i];
            foreach (var (c, w) in adj[v])
            {
                if (seen[c]) continue;
                seen[c] = true;
                up[0][c] = v;
                depth[c] = depth[v] + 1;
                cnt[c] = (int[])cnt[v].Clone();
                cnt[c][w]++;
                order.Add(c);
            }
        }
        for (int k = 1; k < LOG; k++)
        {
            up[k] = new int[n];
            for (int v = 0; v < n; v++) up[k][v] = up[k - 1][up[k - 1][v]];
        }
        int Lca(int u, int v)
        {
            if (depth[u] < depth[v]) (u, v) = (v, u);
            int diff = depth[u] - depth[v];
            for (int k = 0; k < LOG; k++)
                if (((diff >> k) & 1) == 1) u = up[k][u];
            if (u == v) return u;
            for (int k = LOG - 1; k >= 0; k--)
                if (up[k][u] != up[k][v]) { u = up[k][u]; v = up[k][v]; }
            return up[0][u];
        }
        var res = new int[queries.Length];
        for (int q = 0; q < queries.Length; q++)
        {
            int a = queries[q][0], b = queries[q][1], c = Lca(a, b);
            int length = depth[a] + depth[b] - 2 * depth[c], most = 0;
            for (int w = 1; w <= 26; w++)
                most = Math.Max(most, cnt[a][w] + cnt[b][w] - 2 * cnt[c][w]);
            res[q] = length - most;
        }
        return res;
    }
}

Complexity. O((n + q) · (log n + 26)) time, O(n · (log n + 26)) space. The pattern generalises: anything you can subtract (counts, sums, xor) is a prefix from the root plus one LCA; anything you cannot (max, min) goes into the lifting table itself.

8. Sum of Distances in Tree (Hard)

Problem. For each node of an undirected tree with n nodes (up to 3·10⁴), return the sum of its distances to all other nodes.

Insight. Rerooting. Pass 1 from root 0 computes size[v] and down[v] = the sum of distances from v to the nodes in its subtree (down[v] = Σ down[c] + size[c]). Then ans[0] = down[0], and moving the root across the edge v → c gives ans[c] = ans[v] − size[c] + (n − size[c]). The visualizer in the rerooting section runs exactly this.

Solution 
def sum_of_distances_in_tree(n, edges):
    adj = [[] for _ in range(n)]
    for a, b in edges:
        adj[a].append(b)
        adj[b].append(a)
    parent, order = [-1] * n, [0]
    seen = [False] * n
    seen[0] = True
    for v in order:                           # BFS order: parents before children
        for c in adj[v]:
            if not seen[c]:
                seen[c] = True
                parent[c] = v
                order.append(c)
    size, down = [1] * n, [0] * n
    for v in reversed(order):                 # pass 1: children before parents
        p = parent[v]
        if p != -1:
            size[p] += size[v]
            down[p] += down[v] + size[v]      # each node in v's subtree: one more edge
    ans = [0] * n
    ans[0] = down[0]
    for v in order[1:]:                       # pass 2: move the root parent -> v
        ans[v] = ans[parent[v]] - size[v] + (n - size[v])
    return ans

public static class SumOfDistances
{
    public static int[] SumOfDistancesInTree(int n, int[][] edges)
    {
        var adj = new List<int>[n];
        for (int i = 0; i < n; i++) adj[i] = new List<int>();
        foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
        var parent = new int[n];
        Array.Fill(parent, -1);
        var seen = new bool[n];
        var order = new List<int> { 0 };
        seen[0] = true;
        for (int i = 0; i < order.Count; i++)          // BFS order: parents before children
            foreach (int c in adj[order[i]])
                if (!seen[c]) { seen[c] = true; parent[c] = order[i]; order.Add(c); }
        var size = new int[n];
        var down = new int[n];
        Array.Fill(size, 1);
        for (int i = order.Count - 1; i > 0; i--)       // pass 1: children before parents
        {
            int v = order[i], p = parent[v];
            size[p] += size[v];
            down[p] += down[v] + size[v];               // each node in v's subtree: one more edge
        }
        var ans = new int[n];
        ans[0] = down[0];
        for (int i = 1; i < order.Count; i++)           // pass 2: move the root parent -> v
        {
            int v = order[i];
            ans[v] = ans[parent[v]] - size[v] + (n - size[v]);
        }
        return ans;
    }
}

Complexity. O(n) time and space. Both passes are iterative over a BFS order, so a 3·10⁴-node path does not overflow the stack. The sums fit in int: at most n²/2 ≈ 4.5·10⁸.

Self-check

In the diameter code, why does the function return 1 + max(l, r) and not l + r?

The return value is used by the parent to build a longer path through itself. A path can enter a node from the parent and leave by only one child; using both children and the parent would make the path fork. l + r is a complete path that bends at this node, so it is recorded in best and never returned.

Max path sum on the tree [2, -1]: what do the bend and the return value equal at each node, and what is the answer?

At -1 (a leaf): bend = −1, returns −1. At 2: the left gain −1 is clipped to 0, so bend = 2 + 0 + 0 = 2 and it returns 2. best = max(−1, 2) = 2. Note best started at −∞ and briefly held −1: with a single node [-1] the answer would be −1, not 0.

The LCA recursion returns at p without searching below it. Why is the answer still right when q is inside p's subtree?

Then no node outside p's subtree is p or q, so every other call returns None. p's value travels up alone, every ancestor passes it through with left or right, and the root returns p, which is the correct LCA (a node is its own ancestor). The shortcut is only wrong when q might not exist, because then "p alone" could mean "q is missing".

In binary lifting, why does the second loop go from the largest k down to 0, and why does it jump only when up[k][u] != up[k][v]?

It is a binary search for the highest pair of different ancestors at the same depth. Landing on equal nodes might mean we jumped past the LCA, so those jumps are refused. Different nodes are certainly below the LCA, so those jumps are safe. Trying large powers first means each power is needed at most once, like writing a number in binary from the top bit. When the loop ends u and v are the LCA's two children, so the answer is up[0][u].

In Path Sum III, what goes wrong if you forget seen[cur] -= 1? Give a tiny example.

Prefixes from a finished branch stay in the map and pair with nodes in a different branch. Tree [0, 1, 1], target 0. The correct answer is 1: the root alone. The left leaf has cur = 1 and adds seen[1] = 1. Without the undo that entry survives, so at the right leaf (cur = 1 again) the lookup seen[cur − 0] = seen[1] finds it and counts a "path" from the left leaf to the right leaf. That path goes up and back down, which is not allowed: the answer becomes 2.

Why is inorder with null markers not a valid serialization, when preorder with null markers is?

Inorder puts the node between its subtrees, so the decoder cannot tell which token is the root. #,1,#,2,# is produced by both "1 with right child 2" and "2 with left child 1". Preorder puts the root first, so the first token is always the root, and the recursion then knows exactly where the left subtree ends.

Why does counting a complete tree recurse down only one path?

The last level is filled left to right, so the last node is in exactly one of the two subtrees of the root. The other subtree has a full bottom level (or the same height minus one with a full bottom), so it is perfect and its spine walks return equal heights immediately. Only the subtree that contains the last node recurses, and the same argument applies there: O(log n) levels, each costing an O(log n) spine walk.

Rerooting for the sum of distances uses subtraction. Why does "height for every root" need the top-two trick instead?

A sum can be undone: remove c's contribution by subtracting it. A maximum cannot: if c's branch was the maximum, max − c means nothing, you need the next largest branch. Keeping the best and second-best child depth (or prefix and suffix maxima over the children) gives "the best of v excluding c" in O(1).
