Intervals & Sweep Line

Merge, insert and intersect intervals, meeting rooms, and event-based sweep lines on a visual timeline.

Intermediate → Advanced~45 min studyBuilds on: Sorting AlgorithmsUpdated 2026-11-03

What it is and when you need it

An interval is a pair [start, end]: a meeting, a booking, a car trip, a building's footprint, a range of IDs. Interval problems ask what happens when many of them sit on the same line. Which ones overlap? How many overlap at the busiest moment? What is the fewest you must delete so that none overlap? What does their union look like? Checking every pair against every other pair is O(n²). Almost every interval problem becomes O(n log n) with one sort followed by one left-to-right pass.

The invariant. Sort first, then sweep a vertical line from left to right. At any moment the sweep only needs a small summary of what is still open behind the line: the end of the last merged block, a count of active intervals, a heap of end times, or the heights of live buildings. Everything to the left that has already closed can never matter again. Sorting by start makes "what is open" easy to maintain. Sorting by end makes greedy choices safe.

There are only two kinds of sweep, and this page builds both from pictures:

  • Interval sweep: walk the intervals themselves in sorted order, comparing each with a running summary. Used by merge, insert, greedy selection and the two-list intersection.
  • Event sweep: split each interval into two events, a start (+1) and an end (−1), sort the events, and keep a running total. Used by meeting rooms, car pooling, calendars, the skyline and area of rectangles. When the coordinates are small integers, the sorted events become a difference array.

You should know Sorting first, especially sorting by a key. Heaps appear in the second half; see Heaps & Priority Queues.

All pairs: O(n²)

Compare every interval with every other one. Correct, easy, and the reference to test against, but it times out at n = 10⁵. It also answers the wrong question for "how many at once?": pairwise overlaps do not tell you that three intervals share one moment.

Paint a timeline: O(n · range)

Mark every unit of time each interval covers. It is fine when times are small integers and intervals are short. It breaks when times go up to 10⁹, or when the endpoints are real numbers.

Sort + sweep: O(n log n)

Only the 2n endpoints can change anything, so sort them once and visit each one once. Between two consecutive endpoints nothing happens, so you never have to look there.

Intuition: draw them on a number line

Every interval question gets easier once you draw the intervals as bars stacked over one shared axis. Every visualizer on this page does exactly that. The first question is always the same: do two intervals overlap?

Think "apart", then negate Two intervals are apart exactly when one ends before the other starts: a.e <= b.s or b.e <= a.s. Negating it with De Morgan's law gives the overlap test a.s < b.e and b.s < a.e. The same idea in one line: the latest start comes before the earliest end, max(a.s, b.s) < min(a.e, b.e). That second form also gives you the overlap itself: [max(starts), min(ends)).

Closed or half-open? Decide once

The single most common interval bug is a < that should have been <=, or the other way round. It comes from mixing two conventions for what an endpoint means.

Convention Overlap test Touching [1,5] and [5,8] Length Typical problems
Half-open [s, e) a.s < b.e and b.s < a.e apart e − s Meeting Rooms, My Calendar, Car Pooling, Non-overlapping Intervals
Closed [s, e] a.s <= b.e and b.s <= a.e overlap e − s + 1 Merge Intervals, Interval List Intersections, Min Arrows, Flight Bookings

Convert closed to half-open for integers For integer coordinates, the closed interval [s, e] is the same set as the half-open [s, e + 1). Converting at input time lets you write every comparison with <, and makes lengths a plain subtraction. Corporate Flight Bookings is easiest this way: the booking [first, last] becomes +seats at first and −seats at last + 1.

Try both conventions below. Put the two intervals end to end (the default [2,6] and [6,9]) and switch the meaning. The latest start lo and the earliest end hi are marked, and the verdict depends only on how lo compares with hi.

def overlaps(a: tuple[int, int], b: tuple[int, int]) -> bool:
    """Half-open [s, e): touching intervals do NOT overlap."""
    return a[0] < b[1] and b[0] < a[1]


def overlaps_closed(a: tuple[int, int], b: tuple[int, int]) -> bool:
    """Closed [s, e]: sharing one endpoint counts as overlap."""
    return a[0] <= b[1] and b[0] <= a[1]


def intersection(a, b):
    """The shared piece of two closed intervals, or None."""
    lo, hi = max(a[0], b[0]), min(a[1], b[1])
    return (lo, hi) if lo <= hi else None

// Half-open [s, e): touching intervals do NOT overlap.
public static bool Overlaps((int S, int E) a, (int S, int E) b)
    => a.S < b.E && b.S < a.E;

// Closed [s, e]: sharing one endpoint counts as overlap.
public static bool OverlapsClosed((int S, int E) a, (int S, int E) b)
    => a.S <= b.E && b.S <= a.E;

// The shared piece of two closed intervals, or null.
public static (int S, int E)? Intersection((int S, int E) a, (int S, int E) b)
{
    int lo = Math.Max(a.S, b.S), hi = Math.Min(a.E, b.E);
    return lo <= hi ? (lo, hi) : null;
}

Merge Intervals: sort by start, compare with the last block only

Given a list of closed intervals, merge every group of overlapping ones and return the disjoint result. This is the most-asked interval problem, and its loop is the skeleton of half the others.

Why does sorting by start make this one pass? Once the list is sorted, the intervals that belong to the same merged block are consecutive. A new interval cannot reach back past the last block, because every earlier block ended before the last block started. So the only question per interval is: does it start before the last block ends?

Step through it. The last end marker is the only state the algorithm keeps. Switch the touching rule to see [6,7] join or not join [2,6]. The final frame checks the result against a brute force that keeps merging any overlapping pair until none is left.

def merge(intervals: list[list[int]]) -> list[list[int]]:
    """LeetCode 56. Closed intervals: [1,4] and [4,5] merge."""
    out: list[list[int]] = []
    for s, e in sorted(intervals):            # by start (then end)
        if out and s <= out[-1][1]:           # overlaps the last block
            out[-1][1] = max(out[-1][1], e)   # max: e may be inside
        else:
            out.append([s, e])                # gap: open a new block
    return out

// LeetCode 56. Closed intervals: [1,4] and [4,5] merge.
public static int[][] Merge(int[][] intervals)
{
    var sorted = intervals.OrderBy(iv => iv[0]).ToArray();
    var outList = new List<int[]>();
    foreach (var iv in sorted)
    {
        if (outList.Count > 0 && iv[0] <= outList[^1][1])
            outList[^1][1] = Math.Max(outList[^1][1], iv[1]);
        else
            outList.Add(new[] { iv[0], iv[1] });
    }
    return outList.ToArray();
}

Complexity: O(n log n) time for the sort plus O(n) for the pass, and O(n) for the output. For half-open intervals (where touching does not merge), change s <= last_end to s < last_end. The rest is identical.

Insert Interval: three runs, no sort

The list is already sorted and disjoint. Insert one new interval and merge where needed. You could append it and call merge (O(n log n)), but the existing order lets you do it in O(n). Read the list in three runs:

  1. Left run: intervals that end before the new one starts (iv.e < s). Copy them unchanged.
  2. Swallowed run: intervals that start no later than the new one ends (iv.s <= e). Each of them overlaps it, so stretch the new interval to cover it: s = min(s, iv.s) and e = max(e, iv.e).
  3. Right run: everything after that. Emit the stretched interval, then copy the rest.

The visualizer colours the three runs as they are discovered. The original new interval stays behind as a faded ghost, and the stretched copy grows each time it swallows a neighbour.

def insert(intervals: list[list[int]], new: list[int]) -> list[list[int]]:
    """LeetCode 57. intervals is sorted and disjoint (closed)."""
    s, e = new
    out, i, n = [], 0, len(intervals)
    while i < n and intervals[i][1] < s:      # 1. ends before new starts
        out.append(intervals[i])
        i += 1
    while i < n and intervals[i][0] <= e:     # 2. overlaps: swallow it
        s = min(s, intervals[i][0])
        e = max(e, intervals[i][1])
        i += 1
    out.append([s, e])
    out.extend(intervals[i:])                 # 3. starts after new ends
    return out

// LeetCode 57. intervals is sorted and disjoint (closed).
public static int[][] Insert(int[][] intervals, int[] newInterval)
{
    int s = newInterval[0], e = newInterval[1], i = 0, n = intervals.Length;
    var res = new List<int[]>();
    while (i < n && intervals[i][1] < s) res.Add(intervals[i++]);
    while (i < n && intervals[i][0] <= e)
    {
        s = Math.Min(s, intervals[i][0]);
        e = Math.Max(e, intervals[i][1]);
        i++;
    }
    res.Add(new[] { s, e });
    while (i < n) res.Add(intervals[i++]);
    return res.ToArray();
}

Complexity: O(n) time. Finding where the left run ends could use binary search, but the copying is O(n) anyway. If you need many inserts, see Data Stream as Disjoint Intervals under Worked problems, where a sorted structure makes each insert O(log n).

Greedy selection: sort by END

A different family asks you to choose intervals:

  • Non-overlapping Intervals (LC 435): erase as few as possible so the rest do not overlap.
  • Minimum Arrows (LC 452): each balloon is an interval on the x-axis, and one vertical arrow bursts every balloon it touches. How few arrows burst them all?
  • Maximum Length of Pair Chain and Activity Selection: keep as many non-overlapping intervals as possible.

They are the same problem. Keeping the most non-overlapping intervals is the same as erasing the fewest. And the minimum number of arrows equals the maximum number of pairwise-disjoint balloons, because each disjoint balloon needs its own arrow, and one arrow at the end of each kept balloon bursts everything that was skipped. The greedy rule is: sort by end, and keep each interval that starts after the last kept one ends.

The visualizer runs all three modes. In erase mode, kept intervals turn green and erased ones red. In arrows mode, an arrow is fired at the end of the first balloon it has not yet burst. The third mode sorts by start instead, and the final frame shows how much worse that is. The default input has a long [1,11] that starts first and would block everything.

def erase_overlap_intervals(intervals: list[list[int]]) -> int:
    """LeetCode 435. Half-open: [1,2] and [2,3] may both stay."""
    kept, end = 0, float("-inf")
    for s, e in sorted(intervals, key=lambda iv: iv[1]):   # by END
        if s >= end:            # starts after the last kept one ends
            kept += 1
            end = e
    return len(intervals) - kept


def find_min_arrow_shots(points: list[list[int]]) -> int:
    """LeetCode 452. Closed: an arrow at x bursts [s, e] if s <= x <= e."""
    arrows, pos = 0, float("-inf")
    for s, e in sorted(points, key=lambda p: p[1]):
        if s > pos:             # not burst by the last arrow
            arrows += 1
            pos = e             # shoot as far right as possible
    return arrows

// LeetCode 435. Half-open: [1,2] and [2,3] may both stay.
public static int EraseOverlapIntervals(int[][] intervals)
{
    int kept = 0;
    long end = long.MinValue;
    foreach (var iv in intervals.OrderBy(iv => iv[1]))
    {
        if (iv[0] >= end) { kept++; end = iv[1]; }
    }
    return intervals.Length - kept;
}

// LeetCode 452. Closed: an arrow at x bursts [s, e] if s <= x <= e.
public static int FindMinArrowShots(int[][] points)
{
    int arrows = 0;
    long pos = long.MinValue;     // long: inputs reach int.MinValue
    foreach (var p in points.OrderBy(p => p[1]))
    {
        if (p[0] > pos) { arrows++; pos = p[1]; }
    }
    return arrows;
}

Complexity: O(n log n) for the sort, then O(n). The two functions differ only in >= versus >, which is the closed versus half-open choice again. Balloons that touch at one point share an arrow, so they count as overlapping. In LC 452 the coordinates span the whole int range, so p[1] - q[1] comparators overflow. Compare with < or sort by key, as above.

"Sort by start and drop the longer one" also works, but it is easy to get wrong A start-sorted version exists: when two intervals overlap, keep the one with the smaller end (end = min(end, e)). It is the same greedy in disguise. If you forget the min and simply skip the newcomer, you keep the long interval and get the wrong answer, which is exactly what the third mode of the visualizer shows. Sorting by end makes the safe choice automatic.

When intervals have weights, greedy stops working: use DP

If each interval carries a profit and you want the most profitable non-overlapping set (Maximum Profit in Job Scheduling, LC 1235), "earliest end" is no longer safe. A short cheap job can block a long valuable one. Sort by end and use the classic weighted interval scheduling DP. Let best[i] be the best profit using the first i jobs (in end order). For job i, either skip it or take it plus the best you can do among the jobs that end by its start. You find those jobs with binary search over the sorted ends. See DP: Linear & Grid for the general shape.

from bisect import bisect_right


def job_scheduling(start: list[int], end: list[int], profit: list[int]) -> int:
    """LeetCode 1235. Half-open jobs: one may start when another ends."""
    jobs = sorted(zip(end, start, profit))          # by end
    ends = [e for e, _, _ in jobs]
    best = [0] * (len(jobs) + 1)                    # best[i]: first i jobs
    for i, (e, s, p) in enumerate(jobs):
        k = bisect_right(ends, s, 0, i)             # jobs ending <= s
        best[i + 1] = max(best[i], best[k] + p)     # skip vs take
    return best[-1]

// LeetCode 1235. Half-open jobs: one may start when another ends.
public static int JobScheduling(int[] start, int[] end, int[] profit)
{
    var jobs = Enumerable.Range(0, start.Length)
        .Select(i => (S: start[i], E: end[i], P: profit[i]))
        .OrderBy(j => j.E).ToArray();
    var best = new int[jobs.Length + 1];
    for (int i = 0; i < jobs.Length; i++)
    {
        int lo = 0, hi = i;              // count of jobs[0..i) with E <= S
        while (lo < hi)
        {
            int mid = (lo + hi) / 2;
            if (jobs[mid].E <= jobs[i].S) lo = mid + 1; else hi = mid;
        }
        best[i + 1] = Math.Max(best[i], best[lo] + jobs[i].P);
    }
    return best[^1];
}

Complexity: O(n log n). If every profit is 1, this DP computes the same number as the greedy, which is a good way to convince yourself the greedy is right.

Counting overlaps: Meeting Rooms

Meeting Rooms I: can one person attend every meeting? Sort by start and check that each meeting starts no earlier than the previous one ends. Any overlap anywhere shows up between two neighbours in start order, by the same reasoning as merge.

Meeting Rooms II: what is the minimum number of rooms? This is the most important counting question on the page. The minimum number of rooms equals the maximum number of meetings in progress at the same instant. You clearly need at least that many. And that many is always enough, because when a meeting starts, fewer than the peak are running, so some room is free. There are two standard ways to find the peak, and they are worth knowing side by side.

Way 1: event sweep (+1 / −1)

Turn each meeting into two events, (start, +1) and (end, −1). Sort them by time and keep a running count. The peak of the count is the answer. Ties matter: with half-open meetings, a meeting ending at 10 frees its room for one starting at 10, so at equal times the −1 must come first. In Python, sorting the tuples (t, -1) and (t, +1) does this for you, because −1 sorts before +1.

Switch the tie rule in the visualizer to start before end (wrong). The default input has back-to-back meetings at 10 and 15, and the step chart grows a red spike at exactly those instants. The final frame also shows the gaps where the count is 0: that is everyone's free time, which is the whole of Employee Free Time.

Way 2: a min-heap of end times

Process meetings by start time. Each room is represented by the time it becomes free, and those times live in a min-heap, so the room that frees up first is on top. For each meeting: if the top room is free by the start time (heap[0] <= start), reuse it by replacing its end time. Otherwise open a new room. The heap only grows when every room is busy at that instant, so its final size is the peak overlap.

import heapq


def can_attend_meetings(intervals: list[list[int]]) -> bool:
    """Meeting Rooms I. Half-open: back-to-back is fine."""
    iv = sorted(intervals)
    return all(iv[i][0] >= iv[i - 1][1] for i in range(1, len(iv)))


def min_meeting_rooms_sweep(intervals: list[list[int]]) -> int:
    """Meeting Rooms II by events. (t, -1) sorts before (t, +1)."""
    events = [(s, 1) for s, _ in intervals] + [(e, -1) for _, e in intervals]
    cur = best = 0
    for _, delta in sorted(events):
        cur += delta
        best = max(best, cur)
    return best


def min_meeting_rooms_heap(intervals: list[list[int]]) -> int:
    """Meeting Rooms II by heap. heap = end times of rooms in use."""
    heap: list[int] = []
    for s, e in sorted(intervals):
        if heap and heap[0] <= s:
            heapq.heapreplace(heap, e)    # reuse the earliest-free room
        else:
            heapq.heappush(heap, e)       # all busy: open a room
    return len(heap)

// Meeting Rooms I. Half-open: back-to-back is fine.
public static bool CanAttendMeetings(int[][] intervals)
{
    var iv = intervals.OrderBy(x => x[0]).ToArray();
    for (int i = 1; i < iv.Length; i++)
        if (iv[i][0] < iv[i - 1][1]) return false;
    return true;
}

// Meeting Rooms II by events. Ends sort before starts at equal times.
public static int MinMeetingRoomsSweep(int[][] intervals)
{
    var events = new List<(int T, int D)>();
    foreach (var iv in intervals) { events.Add((iv[0], 1)); events.Add((iv[1], -1)); }
    events.Sort();                    // tuples: by T, then -1 before +1
    int cur = 0, best = 0;
    foreach (var (_, d) in events) { cur += d; best = Math.Max(best, cur); }
    return best;
}

// Meeting Rooms II by heap. The heap holds end times of rooms in use.
public static int MinMeetingRoomsHeap(int[][] intervals)
{
    var heap = new PriorityQueue<int, int>();
    foreach (var iv in intervals.OrderBy(x => x[0]))
    {
        if (heap.Count > 0 && heap.Peek() <= iv[0]) heap.Dequeue();
        heap.Enqueue(iv[1], iv[1]);
    }
    return heap.Count;
}

Event sweep

O(n log n) to sort 2n events, then O(1) extra memory. It gives you the whole profile: the peak, where the peak happens, and the free gaps. But it does not say which room each meeting gets.

Min-heap of ends

Also O(n log n). It is an actual assignment: each meeting is placed in a concrete room. You need this as soon as rooms have identities, as in Meeting Rooms III (Worked problems) or "assign tasks to servers".

Two sorted arrays

Sort the starts and the ends separately, then walk them with two pointers: if start[i] < end[j] open a room, else free one. It is the event sweep without building tuples, and the same O(n log n).

Two sorted lists: Interval List Intersections

Each of two lists is sorted and internally disjoint. Return every intersection between an interval of A and an interval of B (closed intervals). With two pointers, i walks A and j walks B:

  1. The current pair intersects in [max(starts), min(ends)] if that is non-empty. Record it.
  2. Then advance whichever interval ends first. It cannot intersect anything else in the other list, because everything later there starts after the current interval of the other list, which already reaches past it.

The other interval stays, because it may still overlap the next interval of the list that moved. Each step advances one pointer, so the total is O(m + n).

def interval_intersection(A: list[list[int]], B: list[list[int]]) -> list[list[int]]:
    """LeetCode 986. Closed intervals; each list sorted and disjoint."""
    i = j = 0
    out: list[list[int]] = []
    while i < len(A) and j < len(B):
        lo = max(A[i][0], B[j][0])
        hi = min(A[i][1], B[j][1])
        if lo <= hi:
            out.append([lo, hi])
        if A[i][1] < B[j][1]:      # A[i] ends first: it is finished
            i += 1
        else:
            j += 1
    return out

// LeetCode 986. Closed intervals; each list sorted and disjoint.
public static int[][] IntervalIntersection(int[][] a, int[][] b)
{
    int i = 0, j = 0;
    var res = new List<int[]>();
    while (i < a.Length && j < b.Length)
    {
        int lo = Math.Max(a[i][0], b[j][0]), hi = Math.Min(a[i][1], b[j][1]);
        if (lo <= hi) res.Add(new[] { lo, hi });
        if (a[i][1] < b[j][1]) i++; else j++;
    }
    return res.ToArray();
}

The same two-pointer walk computes the union of two lists (merge them by start, then run the merge loop) and the difference (cut each A interval wherever B covers it). Employee Free Time is the same idea with k lists.

Difference arrays: many ranges, small coordinates

When the coordinates are small integers (stops 0..1000, flights 1..n, days in a year), you do not need to sort events at all. Store them in an array indexed by time. Each range update [a, b) += c becomes two writes, diff[a] += c and diff[b] -= c. A single running sum afterwards turns diff back into the value at every point. This is the event sweep with counting sort built in, and it is the exact inverse of a prefix sum.

  • Car Pooling (LC 1094): each trip is [passengers, from, to] and riders leave at to, so the range is half-open [from, to). Is the load ever above capacity?
  • Corporate Flight Bookings (LC 1109): each booking [first, last, seats] is closed, so write −seats at last + 1. Return the total for every flight.

Switch the mode in the visualizer between the two conventions and watch the − write move by one cell. The step chart above the arrays is the same load the prefix sum produces, drawn as a profile.

def car_pooling(trips: list[list[int]], capacity: int) -> bool:
    """LeetCode 1094. Riders occupy [from, to)."""
    diff = [0] * (max(t for _, _, t in trips) + 1)
    for p, a, b in trips:
        diff[a] += p
        diff[b] -= p
    load = 0
    for d in diff:
        load += d
        if load > capacity:
            return False
    return True


def corp_flight_bookings(bookings: list[list[int]], n: int) -> list[int]:
    """LeetCode 1109. Flights 1..n; a booking covers [first, last]."""
    diff = [0] * (n + 2)
    for first, last, seats in bookings:
        diff[first] += seats
        diff[last + 1] -= seats         # closed -> half-open
    out, run = [], 0
    for f in range(1, n + 1):
        run += diff[f]
        out.append(run)
    return out

// LeetCode 1094. Riders occupy [from, to).
public static bool CarPooling(int[][] trips, int capacity)
{
    var diff = new int[trips.Max(t => t[2]) + 1];
    foreach (var t in trips) { diff[t[1]] += t[0]; diff[t[2]] -= t[0]; }
    int load = 0;
    foreach (var d in diff)
    {
        load += d;
        if (load > capacity) return false;
    }
    return true;
}

// LeetCode 1109. Flights 1..n; a booking covers [first, last].
public static int[] CorpFlightBookings(int[][] bookings, int n)
{
    var diff = new int[n + 2];
    foreach (var b in bookings) { diff[b[0]] += b[2]; diff[b[1] + 1] -= b[2]; }
    var res = new int[n];
    for (int f = 1, run = 0; f <= n; f++) { run += diff[f]; res[f - 1] = run; }
    return res;
}

Complexity: O(n + R), where R is the coordinate range. When R is huge (10⁹), switch back to sorting the 2n events, or compress the coordinates first (see below). Two-dimensional versions (adding to rectangles in a grid) use a 2-D difference array: four writes per rectangle, then a 2-D prefix sum.

The Skyline Problem: sweep with a max-heap

Buildings are [left, right, height]. Return the key points of the skyline: each point is where the outline's height changes, with the new height. This is the hardest classic sweep, and it combines everything above. The events are building edges. The state behind the sweep line is the set of buildings that are currently standing. The answer at each event is the maximum height in that set.

What makes it hard is that a max-heap cannot delete an arbitrary building when its right edge arrives. The standard fix is lazy deletion. Store each building as (height, right). At each x, first push every building that starts at x, then pop from the top while the top's right <= x, because it has already ended. Buildings that ended but are buried under a taller live one stay in the heap as stale entries. They are harmless until they reach the top, and then they are popped. Finally, if the top height differs from the last height you emitted, emit [x, top].

The visualizer greys out stale heap entries, highlights the building being added, and draws the skyline as it grows. Step to x = 7, where the tallest building ends and the outline drops to the next live one, not to 0.

import heapq


def get_skyline(buildings: list[list[int]]) -> list[list[int]]:
    """LeetCode 218. Sweep critical x values; max-heap with lazy delete."""
    # Start events carry -height (taller first at equal x); ends carry 0.
    events = sorted([(l, -h, r) for l, r, h in buildings] +
                    [(r, 0, 0) for _, r, _ in buildings])
    heap = [(0, float("inf"))]          # (-height, right); ground never ends
    out: list[list[int]] = []
    for x, neg_h, r in events:
        if neg_h:
            heapq.heappush(heap, (neg_h, r))
        while heap[0][1] <= x:          # top has ended: discard (lazy)
            heapq.heappop(heap)
        height = -heap[0][0]
        if not out or out[-1][1] != height:
            out.append([x, height])
    return out

// LeetCode 218. Sweep critical x values; max-heap with lazy delete.
public static IList<IList<int>> GetSkyline(int[][] buildings)
{
    var events = new List<(int X, int NegH, int R)>();
    foreach (var b in buildings) { events.Add((b[0], -b[2], b[1])); events.Add((b[1], 0, 0)); }
    events.Sort();
    // Element (height, right); priority -height makes it a max-heap.
    var heap = new PriorityQueue<(int H, int R), int>();
    heap.Enqueue((0, int.MaxValue), 0);
    var res = new List<IList<int>>();
    foreach (var (x, negH, r) in events)
    {
        if (negH != 0) heap.Enqueue((-negH, r), negH);
        while (heap.Peek().R <= x) heap.Dequeue();
        int h = heap.Peek().H;
        if (res.Count == 0 || res[^1][1] != h) res.Add(new List<int> { x, h });
    }
    return res;
}

Three details carry the whole algorithm:

  • Sort key (x, -h): at the same x, starts come before ends, and taller starts come first. A taller building starting exactly where a shorter one ends therefore produces one key point, not a dip and a rise.
  • Emit only on change: two adjacent buildings of equal height produce no key point between them.
  • The ground sentinel (0, ∞): the heap is never empty, and the outline drops to 0 when nothing is left standing.

Complexity: O(n log n). Each building is pushed once and popped at most once. In C# or Java you can avoid lazy deletion with a SortedDictionary<int, int> (height to count) and delete exactly, at the same complexity.

Online bookings: My Calendar I, II and III

So far you had all the intervals up front, so you could sort. In the My Calendar problems, bookings arrive one at a time and each must be answered immediately:

  • I: accept the booking if it would not create a double booking.
  • II: accept it if it would not create a triple booking.
  • III: accept everything and report the maximum overlap (k) so far.

All three are solved by one structure: a sorted map from time to delta, holding +1 at each start and −1 at each end. That is the event list from Meeting Rooms, kept sorted at all times. To book, add the two deltas, sweep the map with a running sum, and if the sum ever exceeds the limit, roll back the two deltas and refuse.

from bisect import bisect_right, insort


class MyCalendar:
    """I: reject double bookings. Keep disjoint bookings sorted."""

    def __init__(self) -> None:
        self.starts: list[int] = []
        self.ends: list[int] = []

    def book(self, start: int, end: int) -> bool:
        i = bisect_right(self.starts, start)   # bookings before: 0..i-1
        if i > 0 and self.ends[i - 1] > start:
            return False                       # previous one runs into us
        if i < len(self.starts) and self.starts[i] < end:
            return False                       # we run into the next one
        self.starts.insert(i, start)
        self.ends.insert(i, end)
        return True


class KCalendar:
    """II (k=2) and III: sorted delta map + sweep with rollback."""

    def __init__(self, k: int = 10**9) -> None:
        self.k, self.keys, self.delta = k, [], {}

    def _add(self, t: int, d: int) -> None:
        if t not in self.delta:
            insort(self.keys, t)
            self.delta[t] = 0
        self.delta[t] += d

    def book(self, start: int, end: int) -> int:
        """Returns the max overlap, or 0 if the booking was refused."""
        self._add(start, 1)
        self._add(end, -1)
        run = best = 0
        for t in self.keys:
            run += self.delta[t]
            best = max(best, run)
        if best > self.k:                       # refuse: undo the deltas
            self._add(start, -1)
            self._add(end, 1)
            return 0
        return best

// I: reject double bookings. Keep disjoint bookings sorted by start.
public class MyCalendar
{
    private readonly List<(int S, int E)> _iv = new();

    public bool Book(int start, int end)
    {
        int lo = 0, hi = _iv.Count;              // first booking with S > start
        while (lo < hi)
        {
            int mid = (lo + hi) / 2;
            if (_iv[mid].S <= start) lo = mid + 1; else hi = mid;
        }
        if (lo > 0 && _iv[lo - 1].E > start) return false;
        if (lo < _iv.Count && _iv[lo].S < end) return false;
        _iv.Insert(lo, (start, end));
        return true;
    }
}

// II (k = 2) and III: sorted delta map + sweep with rollback.
public class KCalendar
{
    private readonly SortedDictionary<int, int> _delta = new();
    private readonly int _k;
    public KCalendar(int k = int.MaxValue) => _k = k;

    private void Add(int t, int d) => _delta[t] = _delta.GetValueOrDefault(t) + d;

    // Returns the max overlap, or 0 if the booking was refused.
    public int Book(int start, int end)
    {
        Add(start, 1);
        Add(end, -1);
        int run = 0, best = 0;
        foreach (var d in _delta.Values) { run += d; best = Math.Max(best, run); }
        if (best > _k) { Add(start, -1); Add(end, 1); return 0; }
        return best;
    }
}

Complexity: My Calendar I is O(log n) to search plus O(n) for the list insert in Python. In C# with a List it is the same. A balanced tree, such as Java's TreeMap.floorKey, makes it O(log n). The delta-map sweep is O(n) per booking, so O(n²) in total, which is fine for the 1,000 calls these problems allow. For 10⁵ online bookings, use a segment tree with lazy "add on a range" and "max on a range": O(log C) per booking, with dynamic nodes because C can be 10⁹.

Why the delta map handles half-open intervals for free A booking ending at 20 adds −1 at key 20, and one starting at 20 adds +1 at the same key. They cancel inside the map before the sweep reads the key, so back-to-back bookings never look like an overlap. With separate event tuples you had to sort ends first. Here the map merges them.

Coordinate compression and the area of rectangles

Sweeps only care about the order of coordinates, not their values. If a problem has 200 rectangles with coordinates up to 10⁹, there are at most 400 distinct x values and 400 distinct y values. Coordinate compression replaces each coordinate by its rank in the sorted list of distinct values. After that, a difference array or a grid indexed by rank is small, and each cell or segment between two neighbouring ranks remembers its real width.

Rectangle Area II (LC 850) asks for the total area covered by the union of rectangles. Overlaps count once. The visualizer compresses x and y, paints a coverage count into each compressed cell, then sums dx · dy row by row. Summing row by row is a sweep line moving up the y axis. At each height, the covered width is a 1-D union length, which is the merge problem again.

The code turns this into a proper sweep over x. Events are the left edges (+1) and right edges (−1) of the rectangles, and a coverage count is kept per compressed y segment. Between two consecutive events, the covered y length is constant, so it adds covered_y × (x − prev_x) of area.

def rectangle_area(rectangles: list[list[int]]) -> int:
    """LeetCode 850. Sweep x; coverage count per compressed y segment."""
    ys = sorted({y for _, y1, _, y2 in rectangles for y in (y1, y2)})
    rank = {y: i for i, y in enumerate(ys)}
    events = []
    for x1, y1, x2, y2 in rectangles:
        events.append((x1, 1, y1, y2))
        events.append((x2, -1, y1, y2))
    events.sort()
    cover = [0] * (len(ys) - 1)                 # segment j = [ys[j], ys[j+1])
    area, prev_x = 0, events[0][0] if events else 0
    for x, d, y1, y2 in events:
        covered = sum(ys[j + 1] - ys[j] for j, c in enumerate(cover) if c)
        area += covered * (x - prev_x)          # strip [prev_x, x)
        prev_x = x
        for j in range(rank[y1], rank[y2]):
            cover[j] += d
    return area % (10**9 + 7)

// LeetCode 850. Sweep x; coverage count per compressed y segment.
public static int RectangleArea(int[][] rectangles)
{
    var ys = rectangles.SelectMany(r => new[] { r[1], r[3] }).Distinct().OrderBy(y => y).ToArray();
    var rank = new Dictionary<int, int>();
    for (int i = 0; i < ys.Length; i++) rank[ys[i]] = i;
    var events = new List<(int X, int D, int Y1, int Y2)>();
    foreach (var r in rectangles) { events.Add((r[0], 1, r[1], r[3])); events.Add((r[2], -1, r[1], r[3])); }
    events.Sort();
    var cover = new int[Math.Max(0, ys.Length - 1)];
    long area = 0;
    int prevX = events.Count > 0 ? events[0].X : 0;
    foreach (var (x, d, y1, y2) in events)
    {
        long covered = 0;
        for (int j = 0; j < cover.Length; j++) if (cover[j] > 0) covered += ys[j + 1] - ys[j];
        area += covered * (x - prevX);
        prevX = x;
        for (int j = rank[y1]; j < rank[y2]; j++) cover[j] += d;
    }
    return (int)(area % 1_000_000_007);
}

Complexity: O(n²): 2n events, each scanning O(n) y segments. A segment tree over the y segments that stores "covered length" brings it to O(n log n), and that is the industrial version of this algorithm (union of rectangles, VLSI layout checks, map overlays).

Choosing the technique

Recognize it when

  • The input is a list of pairs: [start, end], [from, to], [left, right, height], or bookings and meetings with times.
  • The question says overlap, merge, conflict, free time, at the same time, rooms, platforms, cover, union.
  • The question asks for a maximum or minimum number of intervals to keep, remove, or "shoot": that is the greedy, sorted by end.
  • Many range updates followed by point queries over a small range: a difference array.
  • The answer only changes at endpoints, for example a maximum height, a count, or a covered length. That means an event sweep.
  • Intervals arrive one by one and need immediate answers: a sorted map or a segment tree.

Pitfalls

Mixing closed and half-open The bug: you use s <= last_end in Non-overlapping Intervals and erase [2,3] because it "overlaps" [1,2]. The fix: decide the convention from the problem statement, write it at the top of your code in a comment, and derive every comparison from it. For integers, converting [s, e] to [s, e + 1) removes the question entirely.

Taking e instead of max(last_end, e) when merging The bug: out[-1][1] = e. Sorting by start says nothing about ends, so [1,10] followed by [2,3] shrinks the block to [1,3]. The fix: always max.

Wrong tie order in an event sweep The bug: at equal times you process +1 before −1, and back-to-back meetings count as overlapping, so you report one room too many. The fix: for half-open intervals, sort (time, delta) with −1 first. For closed intervals, where touching does overlap, process +1 first. The rooms-sweep visualizer shows both.

Sorting by start for a greedy selection The bug: you keep the first-starting interval, which might be a giant one that blocks five small ones. The fix: sort by end. Or, if you must sort by start, keep the smaller end whenever two intervals collide.

Comparator overflow The bug: (a, b) => a[1] - b[1] in Java, C# or JavaScript, with coordinates near ±2³¹. The subtraction overflows and the sort silently misorders. LeetCode 452 is built to catch this. The fix: a[1].CompareTo(b[1]), Integer.compare, or a key selector, as in OrderBy.

Mutating the caller's lists The bug: intervals.sort() and then out.append(intervals[i]) without a copy. Later you update out[-1][1] and also change the caller's input. The fix: sort into a new list (sorted(...)) and append copies, [s, e], when you plan to mutate them.

Worked problems

1. Employee Free Time

Each employee has a sorted list of non-overlapping working intervals. Return the finite intervals of positive length when every employee is free. Insight: free time for everyone is the gaps in the union of all working intervals. Merge everything, and each gap between two consecutive merged blocks is an answer. The rooms-sweep visualizer above draws these gaps in green on its last frame: they are the stretches where the busy count is 0.

Solution: O(N log N) time, O(N) space (N = total intervals) 
def employee_free_time(schedule: list[list[list[int]]]) -> list[list[int]]:
    """LeetCode 759. Intervals are closed; gaps must have positive length."""
    work = sorted(iv for emp in schedule for iv in emp)
    free: list[list[int]] = []
    end = work[0][1]
    for s, e in work[1:]:
        if s > end:                    # a gap nobody is working in
            free.append([end, s])
        end = max(end, e)              # merge loop, without storing blocks
    return free

// LeetCode 759. Intervals are closed; gaps must have positive length.
public static List<int[]> EmployeeFreeTime(int[][][] schedule)
{
    var work = schedule.SelectMany(emp => emp).OrderBy(iv => iv[0]).ToArray();
    var free = new List<int[]>();
    int end = work[0][1];
    foreach (var iv in work.Skip(1))
    {
        if (iv[0] > end) free.Add(new[] { end, iv[0] });
        end = Math.Max(end, iv[1]);
    }
    return free;
}

Each employee's list is already sorted, so a k-way merge with a heap of (start, employee, index) produces the same sorted stream in O(N log k) instead of O(N log N). The merge loop on top is unchanged. It is the same trick as Merge k Sorted Lists in Heaps & Priority Queues.

2. Remove Covered Intervals

Interval [a, b) is covered by [c, d) if c <= a and b <= d. Remove every covered interval and return how many remain. Insight: sort by start ascending and, for equal starts, by end descending. Then an interval is covered exactly when some earlier interval reaches at least as far, which you can check against the running maximum end. The tie rule matters: [1,4] must come before [1,2], so that [1,2] sees the bigger end and is counted as covered.

Solution: O(n log n) time, O(1) extra space 
def remove_covered_intervals(intervals: list[list[int]]) -> int:
    """LeetCode 1288."""
    kept, max_end = 0, float("-inf")
    for _, e in sorted(intervals, key=lambda iv: (iv[0], -iv[1])):
        if e > max_end:                # sticks out past everything before
            kept += 1
            max_end = e
    return kept

// LeetCode 1288.
public static int RemoveCoveredIntervals(int[][] intervals)
{
    int kept = 0, maxEnd = int.MinValue;
    foreach (var iv in intervals.OrderBy(iv => iv[0]).ThenByDescending(iv => iv[1]))
    {
        if (iv[1] > maxEnd) { kept++; maxEnd = iv[1]; }
    }
    return kept;
}

Every earlier interval starts no later than the current one, so "covered" reduces to "some earlier end is ≥ mine". Only the largest earlier end matters. Without the descending tie-break, [1,2] would be visited before [1,4] and counted as kept.

3. Maximum Number of Events That Can Be Attended

Event i can be attended on any one day in [start, end], and you can attend one event per day. Maximise the number of events attended. Insight: sweep the days, not the events. On each day, every event that has started is a candidate. Attend the candidate that ends soonest, because it has the fewest remaining options. The others can wait. Keep the candidates' end days in a min-heap. This is the greedy-by-end idea, run online inside a sweep.

Solution: O(n log n) time, O(n) space 
import heapq


def max_events(events: list[list[int]]) -> int:
    """LeetCode 1353. Closed day ranges; one event per day."""
    events = sorted(events)
    heap: list[int] = []              # end days of started events
    i, n, day, attended = 0, len(events), 0, 0
    while i < n or heap:
        if not heap:
            day = max(day, events[i][0])      # jump over idle days
        while i < n and events[i][0] <= day:
            heapq.heappush(heap, events[i][1])
            i += 1
        while heap and heap[0] < day:         # expired: can't attend now
            heapq.heappop(heap)
        if heap:
            heapq.heappop(heap)               # attend the most urgent
            attended += 1
            day += 1
    return attended

// LeetCode 1353. Closed day ranges; one event per day.
public static int MaxEvents(int[][] events)
{
    var ev = events.OrderBy(e => e[0]).ToArray();
    var heap = new PriorityQueue<int, int>();   // end days of started events
    int i = 0, n = ev.Length, day = 0, attended = 0;
    while (i < n || heap.Count > 0)
    {
        if (heap.Count == 0) day = Math.Max(day, ev[i][0]);
        while (i < n && ev[i][0] <= day) { heap.Enqueue(ev[i][1], ev[i][1]); i++; }
        while (heap.Count > 0 && heap.Peek() < day) heap.Dequeue();
        if (heap.Count > 0) { heap.Dequeue(); attended++; day++; }
    }
    return attended;
}

Why the soonest end? Exchange argument: if an optimal plan attends some other candidate today and the most urgent one later (or never), swap them. The urgent one fits today, and the other one has an equal or later deadline, so it fits wherever the urgent one was. The day-jump keeps the loop O(n log n) even when the days go up to 10⁵ or 10⁹.

4. Minimum Interval to Include Each Query

Given closed intervals and a list of query points, return for each query the size (right − left + 1) of the smallest interval that contains it, or −1. Insight: answer the queries offline, in sorted order. Sweep the query points from left to right. Push every interval that has started into a min-heap keyed by size, and lazily discard intervals whose right end is to the left of the current query. Because queries only move right, an interval that has expired stays expired. This is the skyline's lazy-deletion trick with "smallest" in place of "tallest".

Solution: O((n + q) log n) time, O(n + q) space 
import heapq


def min_interval(intervals: list[list[int]], queries: list[int]) -> list[int]:
    """LeetCode 1851."""
    intervals = sorted(intervals)
    heap: list[tuple[int, int]] = []          # (size, right)
    ans: dict[int, int] = {}
    i = 0
    for q in sorted(set(queries)):
        while i < len(intervals) and intervals[i][0] <= q:
            l, r = intervals[i]
            heapq.heappush(heap, (r - l + 1, r))
            i += 1
        while heap and heap[0][1] < q:        # ends before q: gone for good
            heapq.heappop(heap)
        ans[q] = heap[0][0] if heap else -1
    return [ans[q] for q in queries]

// LeetCode 1851.
public static int[] MinInterval(int[][] intervals, int[] queries)
{
    var iv = intervals.OrderBy(x => x[0]).ToArray();
    var order = Enumerable.Range(0, queries.Length).OrderBy(k => queries[k]).ToArray();
    var heap = new PriorityQueue<int, int>();  // element: right, priority: size
    var res = new int[queries.Length];
    int i = 0;
    foreach (int k in order)
    {
        int q = queries[k];
        while (i < iv.Length && iv[i][0] <= q) { heap.Enqueue(iv[i][1], iv[i][1] - iv[i][0] + 1); i++; }
        while (heap.Count > 0 && heap.Peek() < q) heap.Dequeue();
        res[k] = heap.TryPeek(out _, out int size) ? size : -1;
    }
    return res;
}

Interval lengths and the query values are unrelated, so no single sort order handles both. The sweep handles position (which intervals contain q), and the heap handles size (which of those is smallest). Sorting queries offline is the standard escape whenever online answers would need a heavy data structure.

5. Data Stream as Disjoint Intervals

Numbers arrive one at a time (addNum). At any moment getIntervals must return the numbers seen so far as sorted, disjoint closed intervals. Insight: this is Insert Interval for a single point, done online. Keep the intervals in a sorted structure and look only at the two neighbours of the new value: the interval starting at or before v, and the one starting after it. There are four cases:

  • v is already covered: do nothing.
  • v bridges the two neighbours (left.e == v − 1 and right.s == v + 1): fuse them.
  • v extends just one of them.
  • v stands alone: insert [v, v].
Solution: O(log n) per call with a balanced tree (O(n) insert with a Python list) 
from bisect import bisect_right


class SummaryRanges:
    """LeetCode 352. self.iv: sorted, disjoint, non-adjacent [s, e]."""

    def __init__(self) -> None:
        self.iv: list[list[int]] = []

    def addNum(self, v: int) -> None:
        iv = self.iv
        i = bisect_right(iv, [v, float("inf")])    # first with start > v
        if i > 0 and iv[i - 1][1] >= v:
            return                                  # already covered
        joins_left = i > 0 and iv[i - 1][1] == v - 1
        joins_right = i < len(iv) and iv[i][0] == v + 1
        if joins_left and joins_right:
            iv[i - 1][1] = iv[i][1]                 # v bridges the gap
            del iv[i]
        elif joins_left:
            iv[i - 1][1] = v
        elif joins_right:
            iv[i][0] = v
        else:
            iv.insert(i, [v, v])

    def getIntervals(self) -> list[list[int]]:
        return [x[:] for x in self.iv]

// LeetCode 352. A SortedSet ordered by start; sentinels avoid empty checks.
public class SummaryRanges
{
    private readonly SortedSet<(int S, int E)> _set =
        new() { (int.MinValue, int.MinValue), (int.MaxValue, int.MaxValue) };

    public void AddNum(int v)
    {
        var left = _set.GetViewBetween((int.MinValue, int.MinValue), (v, int.MaxValue)).Max;
        var right = _set.GetViewBetween((v, int.MaxValue), (int.MaxValue, int.MaxValue)).Min;
        if (left.E >= v) return;                       // already covered
        bool joinL = left.E == v - 1, joinR = right.S == v + 1;
        if (joinL && joinR)
        {
            _set.Remove(left); _set.Remove(right); _set.Add((left.S, right.E));
        }
        else if (joinL) { _set.Remove(left); _set.Add((left.S, v)); }
        else if (joinR) { _set.Remove(right); _set.Add((v, right.E)); }
        else _set.Add((v, v));
    }

    public int[][] GetIntervals() =>
        _set.Where(x => x.S != int.MinValue && x.S != int.MaxValue)
            .Select(x => new[] { x.S, x.E }).ToArray();
}

The two GetViewBetween calls are a floor and a ceiling lookup, which C#'s SortedSet does not expose directly. Java's TreeMap.floorKey and higherKey do the same job. The (int.MaxValue, int.MaxValue) right sentinel sits after (v, int.MaxValue) only if v is less than int.MaxValue, which LC 352's bounds (0 ≤ v ≤ 10⁴) guarantee. Follow-up: when merges are frequent and the number of disjoint intervals stays small, this is far cheaper than storing every number and re-merging on each getIntervals.

6. Meeting Rooms III

There are n rooms numbered 0..n−1, and meetings [start, end) with distinct starts. Each meeting takes the lowest-numbered free room. If none is free, it waits for the room that frees up first (ties go to the lowest number) and keeps its original duration. Return the room that held the most meetings. Insight: two heaps. One holds free rooms by number. The other holds busy rooms by (free_time, number). Before each meeting, move every room that is free by its start from the busy heap to the free heap. This is the rooms heap from Meeting Rooms II, except that now the rooms have names.

Solution: O(m log m + m log n) time, O(n) space 
import heapq


def most_booked(n: int, meetings: list[list[int]]) -> int:
    """LeetCode 2402."""
    free = list(range(n))                     # already a valid min-heap
    busy: list[tuple[int, int]] = []          # (free_time, room)
    count = [0] * n
    for s, e in sorted(meetings):
        while busy and busy[0][0] <= s:       # rooms that are free by s
            _, r = heapq.heappop(busy)
            heapq.heappush(free, r)
        if free:
            r = heapq.heappop(free)
            heapq.heappush(busy, (e, r))
        else:                                 # wait for the earliest room
            t, r = heapq.heappop(busy)
            heapq.heappush(busy, (t + e - s, r))   # same duration, delayed
        count[r] += 1
    return count.index(max(count))

// LeetCode 2402.
public static int MostBooked(int n, int[][] meetings)
{
    var free = new PriorityQueue<int, int>();
    for (int r = 0; r < n; r++) free.Enqueue(r, r);
    var busy = new PriorityQueue<int, (long T, int R)>();   // room by (free time, room)
    var count = new int[n];
    foreach (var m in meetings.OrderBy(m => m[0]))
    {
        long s = m[0], e = m[1];
        while (busy.TryPeek(out int br, out var p) && p.T <= s) { busy.Dequeue(); free.Enqueue(br, br); }
        int room;
        if (free.Count > 0) { room = free.Dequeue(); busy.Enqueue(room, (e, room)); }
        else
        {
            busy.TryDequeue(out room, out var p);
            busy.Enqueue(room, (p.T + e - s, room));
        }
        count[room]++;
    }
    return Array.IndexOf(count, count.Max());
}

Two traps hide in this problem. First, the delayed end can exceed 2³¹, which is why the C# version uses long. Second, you must move all freed rooms into the free heap before choosing, because "lowest-numbered free room" is not the same as "the room that freed up first".

Self-check

In Merge Intervals, why is it enough to compare each interval with the last merged block only?

The list is sorted by start, so the current interval starts at or after every earlier interval. Every block before the last one ended before the last block started (that is why they are separate blocks), and so it also ends before the current interval starts. Only the last block can still reach the current interval.

Why is the minimum number of meeting rooms equal to the maximum number of meetings running at one instant?

At least: at the peak instant, k meetings are running and each needs its own room. At most: assign rooms greedily in start order. When a meeting starts, fewer than k other meetings are running (or the count would exceed the peak), so one of k rooms is free. The min-heap algorithm is exactly this assignment, which is why its final size equals the peak of the ±1 sweep.

Half-open intervals [1,2], [2,3], [3,4], [1,3]: how many must be erased so the rest do not overlap? Trace the greedy.

Sorted by end: [1,2] (end 2), [2,3] and [1,3] (end 3), [3,4] (end 4). Keep [1,2], so end = 2. [2,3] starts at 2 ≥ 2, so keep it and end = 3. [1,3] starts at 1 < 3, so erase it. [3,4] starts at 3 ≥ 3, so keep it. Three kept, so 1 erased. If you used > instead of >= you would also erase [2,3] and [3,4] and answer 3, which is the closed-interval answer to a half-open question.

In the skyline sweep, why sort start events by (x, −height), and why is lazy deletion from the heap safe?

At the same x, the taller start must be pushed first, so the first height read at that x is already the final one. Otherwise a shorter building starting at the same x would emit a key point that the taller one immediately replaces, giving two key points at one x. Lazy deletion is safe because a stale (already ended) building only affects the answer when it is on top of the heap, and that is exactly when the while top.right <= x loop removes it. Buried stale entries never get read.

In Interval List Intersections, why is it safe to advance the pointer of the interval that ends first?

Say A[i] ends first, at e. The next interval in B starts after B[j] ends (B is disjoint), and B[j] ends at or after e. So every later B interval starts after e, and A[i] cannot intersect any of them. B[j] must stay, because it reaches further and may still overlap A[i+1].

When does "sort by end, keep greedily" give the wrong answer, and what replaces it?

When intervals have weights (profits) and you maximise total weight rather than count. One long interval worth 100 beats three short ones worth 1 each, but the greedy would keep the short ones. Replace it with weighted interval scheduling: sort by end, best[i] = max(best[i−1], best[k] + w_i) where k (found by binary search) counts the jobs that end by job i's start.

Car Pooling writes −c at to, but Corporate Flight Bookings writes −seats at last + 1. Why the difference?

The conventions differ. Car riders get off at to, so they are not in the car there: the range is half-open [from, to), and the load must drop at to. A flight booking [first, last] includes flight last, so the seats must still count there and drop one step later, at last + 1. Both are the same rule: write the minus at the first point that is not covered.
