Sequence & String DP

LIS with patience sorting, LCS, edit distance, palindromic subsequences, regex/wildcard matching and distinct subsequences.

Intermediate → Expert~70 min studyBuilds on: The DP Framework, Binary SearchUpdated 2026-11-03

Where this page fits

The DP Framework gave you the five-step recipe (state, transition, base cases, order, answer). 1D & Grid DP used it on one sequence and on grids, including the Longest Increasing Subsequence (LIS) in O(n²) and in O(n log n) with patience sorting. This page puts two strings side by side, or one string against itself, and asks how they line up.

That covers a large and famous group of problems: longest common subsequence, edit distance, shortest common supersequence, distinct subsequences, interleaving strings, palindromic subsequences and substrings, palindrome partitioning, and the two hardest interview classics, regular expression matching and wildcard matching. They look different on the surface, but they all fill the same kind of table and read it the same way.

Two-sequence DP indexes the table by two prefix lengths: dp[i][j] describes a[:i] against b[:j], and every transition looks at the last letter of one or both prefixes. A diagonal move uses both last letters together, a down move uses a[i−1] alone, and a right move uses b[j−1] alone. Every problem on this page is a choice of which moves are allowed, what each one costs, and how to combine them (max, min, +, or OR).

One picture for the whole page: the alignment grid

Draw the empty prefix and every longer prefix of a down the side, and the same for b across the top. A grid point (i, j) means "I have dealt with the first i letters of a and the first j letters of b". Any way of lining up the two strings, letter by letter, is a path from the top-left (0, 0) to the bottom-right (n, m) that only moves down, right, or diagonally down-right.

Once you see the grid, the five steps almost write themselves:

1 · STATEdp[i][j]

The answer for the prefixes a[:i] and b[:j]: a length, a cost, a count, or true/false.

2 · TRANSITIONLook at the last letters

a[i−1] and b[j−1]: pair them (diagonal), or use one of them alone (down or right).

3 · BASE CASESRow 0 and column 0

One string is empty. The answer there is usually obvious: 0, i, j, 1 way, or "only if the pattern can be empty".

4 · ORDERRow by row, left to right

Every move comes from above, from the left, or from the upper-left, so those cells are ready.

5 · ANSWERdp[n][m]

Both strings used up. Walk the winning arrows back to rebuild the alignment.

Longest common subsequence: the first two-string table

LeetCode 1143 Medium. A subsequence keeps some letters in their original order (gaps allowed): "ace" is a subsequence of "abcde", "aec" is not. Find the length of the longest string that is a subsequence of both a and b.

Brute force lists all 2ⁿ subsequences of a and tests each against b. The DP observation is about the last letters. Compare a[i−1] and b[j−1]:

  • They are equal. Pair them. Some LCS of the two prefixes ends with this shared letter, so the answer is 1 + dp[i−1][j−1].
  • They differ. They cannot both be the last letter of a common subsequence, because a common subsequence ends with one letter that occurs in both. So at least one of them is useless here: drop a[i−1] (dp[i−1][j]) or drop b[j−1] (dp[i][j−1]), and keep the better.

Watch the table fill, then walk it back

Step through LCS of abcbdab and bdcaba (the textbook example; the answer is 4). Matching cells light up with a diagonal arrow. On a mismatch you see both candidate arrows; the winner is green. When the table is full, the walk back starts at the corner: on a match it goes diagonally and emits the letter; otherwise it moves toward the neighbour that holds the same value. Switch the problem to common substring to see what changes when gaps are not allowed, and to supersequence for the shortest string that contains both (worked problem 1).

Why max(up, left) is safe on a mismatch. Look at an optimal common subsequence of a[:i] and b[:j]. Its last letter cannot be matched to both a[i−1] and b[j−1], since they are different letters. So either a[i−1] is unused (the answer is also an answer for a[:i−1], b[:j]) or b[j−1] is unused. Taking the max over both cases cannot miss it. On a match, pairing the two last letters is never worse: any common subsequence that does not use both can be changed into one that does, with the same length or longer.

Template: LCS with reconstruction

def lcs_with_string(a: str, b: str) -> tuple[int, str]:
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]       # dp[i][j] = LCS of a[:i] and b[:j]
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1      # diagonal: both letters join the LCS
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])   # drop a[i-1] or drop b[j-1]
    out, i, j = [], n, m                              # walk back from the corner
    while i > 0 and j > 0:
        if a[i - 1] == b[j - 1]:
            out.append(a[i - 1])
            i, j = i - 1, j - 1
        elif dp[i - 1][j] >= dp[i][j - 1]:
            i -= 1
        else:
            j -= 1
    return dp[n][m], "".join(reversed(out))

public static (int Length, string Lcs) LcsWithString(string a, string b)
{
    int n = a.Length, m = b.Length;
    var dp = new int[n + 1, m + 1];                   // dp[i, j] = LCS of a[..i] and b[..j]
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i, j] = a[i - 1] == b[j - 1]
                ? dp[i - 1, j - 1] + 1                // diagonal: both letters join the LCS
                : Math.Max(dp[i - 1, j], dp[i, j - 1]);   // drop a[i-1] or drop b[j-1]
    var rev = new StringBuilder();
    for (int i = n, j = m; i > 0 && j > 0; )          // walk back from the corner
    {
        if (a[i - 1] == b[j - 1]) { rev.Append(a[i - 1]); i--; j--; }
        else if (dp[i - 1, j] >= dp[i, j - 1]) i--;
        else j--;
    }
    char[] chars = rev.ToString().ToCharArray();
    Array.Reverse(chars);
    return (dp[n, m], new string(chars));
}

Time O(n·m), space O(n·m). The walk back is O(n + m).

One row is enough for the length

Each cell reads up, left and upper-left. With a single array row, at the moment you compute row[j]: row[j] still holds the cell above (not yet overwritten), and row[j−1] already holds the cell to the left (written a moment ago). The upper-left cell was in row[j−1] before that write, so it is gone. Save it in a variable diag just before overwriting. This is the same trick as in 1D & Grid DP, with one extra variable.

def lcs_length_one_row(a: str, b: str) -> int:
    if len(b) > len(a):
        a, b = b, a                                   # let the row run over the shorter string
    row = [0] * (len(b) + 1)
    for ch in a:
        diag = 0                                      # dp[i-1][j-1], saved before it is overwritten
        for j in range(1, len(b) + 1):
            up = row[j]                               # still dp[i-1][j]
            row[j] = diag + 1 if ch == b[j - 1] else max(up, row[j - 1])
            diag = up                                 # becomes the upper-left of column j+1
    return row[-1]

public static int LcsLengthOneRow(string a, string b)
{
    if (b.Length > a.Length) (a, b) = (b, a);         // let the row run over the shorter string
    var row = new int[b.Length + 1];
    foreach (char ch in a)
    {
        int diag = 0;                                 // dp[i-1][j-1], saved before it is overwritten
        for (int j = 1; j <= b.Length; j++)
        {
            int up = row[j];                          // still dp[i-1][j]
            row[j] = ch == b[j - 1] ? diag + 1 : Math.Max(up, row[j - 1]);
            diag = up;                                // becomes the upper-left of column j+1
        }
    }
    return row[b.Length];
}

Time O(n·m), space O(min(n, m)). You lose the ability to walk back. If you need the actual subsequence and small memory, use Hirschberg's divide and conquer (end of this page).

Subsequence vs substring: one line changes

A substring is contiguous. Maximum Length of Repeated Subarray (718) asks for the longest common substring (of two arrays). The state changes meaning: dp[i][j] is the length of the common run that ends exactly at a[i−1] and b[j−1]. A match extends the run diagonally; a mismatch resets it to 0, because a run that ends here must use both letters. The answer is the largest cell anywhere, not the corner. Try it in the visualizer above with the common substring mode: green diagonals appear as streaks, and the table is mostly zeros.

Subsequence (gaps allowed)

  • dp[i][j] = best for the prefixes
  • mismatch: max(up, left)
  • answer: dp[n][m]
  • "abcde" vs "ace" → 3

Substring (contiguous)

  • dp[i][j] = run ending at i−1, j−1
  • mismatch: 0
  • answer: max over all cells
  • "abcde" vs "ace" → 1
def find_length(a: list[int], b: list[int]) -> int:
    best = 0
    row = [0] * (len(b) + 1)                          # row[j] = common run ending at a[i-1], b[j-1]
    for x in a:
        for j in range(len(b), 0, -1):                # backward: row[j-1] is still the previous row
            row[j] = row[j - 1] + 1 if x == b[j - 1] else 0
            best = max(best, row[j])
    return best

public static int FindLength(int[] a, int[] b)
{
    int best = 0;
    var row = new int[b.Length + 1];                  // row[j] = common run ending at a[i-1], b[j-1]
    foreach (int x in a)
        for (int j = b.Length; j >= 1; j--)           // backward: row[j-1] is still the previous row
        {
            row[j] = x == b[j - 1] ? row[j - 1] + 1 : 0;
            best = Math.Max(best, row[j]);
        }
    return best;
}

Time O(n·m), space O(m). Here only the diagonal is read, so a backward inner loop avoids the extra variable: row[j−1] has not been touched yet in this row. This is the same reason the 0/1 knapsack loop runs backward on the Knapsack Family page. For long strings, a suffix automaton or binary search plus rolling hash finds the longest common substring in near-linear time (see String Algorithms).

The LCS family: same table, different story

Many problems are LCS in disguise. Once you spot it, the code is the template above with one changed line.

Problem Why it is LCS Answer
Delete Operation for Two Strings (583) Whatever survives the deletions is a common subsequence; keep the longest n + m − 2·LCS
Minimum ASCII Delete Sum (712) Same, but keep the common subsequence with the largest ASCII sum ascii(a) + ascii(b) − 2·best
Uncrossed Lines (1035) Lines between equal numbers that do not cross pair up elements in the same order: a common subsequence LCS
Shortest Common Supersequence (1092) Write the LCS letters once and every other letter once length n + m − LCS
Longest Palindromic Subsequence (516) A palindrome reads the same backwards, so it is common to s and reverse(s) LCS(s, s[::-1])
Minimum Insertion Steps to Make a String Palindrome (1312) Keep the longest palindromic subsequence and mirror every other letter n − LPS

Minimum ASCII Delete Sum shows the pattern of "LCS with weights": the +1 on the diagonal becomes the weight of the letter.

def minimum_delete_sum(s1: str, s2: str) -> int:
    n, m = len(s1), len(s2)
    keep = [[0] * (m + 1) for _ in range(n + 1)]      # keep[i][j] = largest ASCII sum of a common subsequence
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if s1[i - 1] == s2[j - 1]:
                keep[i][j] = keep[i - 1][j - 1] + ord(s1[i - 1])   # +weight instead of +1
            else:
                keep[i][j] = max(keep[i - 1][j], keep[i][j - 1])
    return sum(map(ord, s1)) + sum(map(ord, s2)) - 2 * keep[n][m]

public static int MinimumDeleteSum(string s1, string s2)
{
    int n = s1.Length, m = s2.Length;
    var keep = new int[n + 1, m + 1];                 // keep[i, j] = largest ASCII sum of a common subsequence
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            keep[i, j] = s1[i - 1] == s2[j - 1]
                ? keep[i - 1, j - 1] + s1[i - 1]      // +weight instead of +1
                : Math.Max(keep[i - 1, j], keep[i, j - 1]);
    return s1.Sum(c => (int)c) + s2.Sum(c => (int)c) - 2 * keep[n, m];
}

Time O(n·m), space O(n·m) (one row works too). Note that "longest common subsequence" and "most valuable common subsequence" can be different strings, which is why you cannot reuse a plain LCS here.

Edit distance: three arrows, three operations

LeetCode 72 Medium. Turn a into b with the fewest single-letter insertions, deletions and replacements. This is the Levenshtein distance, used in spell checkers, diff, and DNA alignment.

State: dp[i][j] = the fewest edits that turn a[:i] into b[:j]. Think about what happens to the last letters:

  • a[i−1] == b[j−1]: they already agree. Leave them alone: dp[i−1][j−1], free.
  • otherwise one edit is paid, and there are exactly three ways to deal with the last letters:
  • replace a[i−1] by b[j−1] (they now agree): 1 + dp[i−1][j−1] (diagonal);
  • delete a[i−1]: 1 + dp[i−1][j] (from above), then turn a[:i−1] into b[:j];
  • insert b[j−1] at the end: 1 + dp[i][j−1] (from the left), then turn a[:i] into b[:j−1].

The base cases are the edges of the grid: turning a[:i] into the empty string takes i deletions (column 0), and building b[:j] from nothing takes j insertions (row 0).

Step through horse → ros. After the fill, the walk back reads the arrows as operations and builds the alignment underneath: one column per edit, green when the letters agree, and coloured by the operation otherwise. The number of non-green columns is always the distance.

Why "equal → take the diagonal" needs no min. When the letters agree you could still delete or insert, but it never helps. Neighbouring cells differ by at most 1 (one extra letter costs at most one extra edit), so dp[i−1][j] + 1 ≥ dp[i−1][j−1] and the same for the left. The free diagonal is always at least as good.

Template: edit distance, full table and one row

def edit_distance(a: str, b: str) -> int:
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]       # dp[i][j] = edits to turn a[:i] into b[:j]
    for i in range(n + 1):
        dp[i][0] = i                                  # delete all i letters
    for j in range(m + 1):
        dp[0][j] = j                                  # insert all j letters
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]           # letters agree: free diagonal
            else:
                dp[i][j] = 1 + min(dp[i - 1][j - 1],  # replace a[i-1] by b[j-1]
                                   dp[i - 1][j],      # delete a[i-1]
                                   dp[i][j - 1])      # insert b[j-1]
    return dp[n][m]


def edit_distance_one_row(a: str, b: str) -> int:
    row = list(range(len(b) + 1))                     # row 0: j insertions
    for i, ch in enumerate(a, 1):
        diag, row[0] = row[0], i                      # save dp[i-1][0], then dp[i][0] = i
        for j in range(1, len(b) + 1):
            up = row[j]                               # still dp[i-1][j]
            row[j] = diag if ch == b[j - 1] else 1 + min(diag, up, row[j - 1])
            diag = up
    return row[-1]

public static int EditDistance(string a, string b)
{
    int n = a.Length, m = b.Length;
    var dp = new int[n + 1, m + 1];                   // dp[i, j] = edits to turn a[..i] into b[..j]
    for (int i = 0; i <= n; i++) dp[i, 0] = i;        // delete all i letters
    for (int j = 0; j <= m; j++) dp[0, j] = j;        // insert all j letters
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i, j] = a[i - 1] == b[j - 1]
                ? dp[i - 1, j - 1]                    // letters agree: free diagonal
                : 1 + Math.Min(dp[i - 1, j - 1],      // replace a[i-1] by b[j-1]
                      Math.Min(dp[i - 1, j],          // delete a[i-1]
                               dp[i, j - 1]));        // insert b[j-1]
    return dp[n, m];
}

public static int EditDistanceOneRow(string a, string b)
{
    var row = new int[b.Length + 1];
    for (int j = 0; j <= b.Length; j++) row[j] = j;   // row 0: j insertions
    for (int i = 1; i <= a.Length; i++)
    {
        int diag = row[0];                            // save dp[i-1][0]
        row[0] = i;
        for (int j = 1; j <= b.Length; j++)
        {
            int up = row[j];                          // still dp[i-1][j]
            row[j] = a[i - 1] == b[j - 1] ? diag : 1 + Math.Min(diag, Math.Min(up, row[j - 1]));
            diag = up;
        }
    }
    return row[b.Length];
}

Time O(n·m). Space O(n·m) for the full table (needed to list the operations), O(m) for one row.

Variants you get by changing the move costs. Only deletions allowed on both sides (583) means no diagonal-replace: 1 + min(up, left), and the answer is n + m − 2·LCS. Different costs for insert, delete and replace (a weighted edit distance) just change the three +1s. Allowing a swap of two adjacent letters (Damerau distance) adds a fourth arrow from dp[i−2][j−2]. If the question is only "is the distance at most 1?" (One Edit Distance), skip the table: walk both strings with two pointers to the first difference and compare the rests.

Counting paths: distinct subsequences

LeetCode 115 Hard. In how many ways can you delete letters from s to leave exactly t? Two ways are different if they keep different positions of s. For s = "babgbag" and t = "bag" the answer is 5.

The grid is the same, but now you count paths instead of finding the best one. dp[i][j] = the number of ways to form t[:j] from s[:i]. Look at the last letter of s:

  • skip s[i−1]: every way of forming t[:j] from s[:i−1] still works: dp[i−1][j];
  • use s[i−1] as the last letter of t[:j], only if s[i−1] == t[j−1]: dp[i−1][j−1] ways.

The two cases never produce the same set of positions (one uses position i−1, the other does not), so you add them instead of taking a max. There is no right move: every letter of t must be matched, never skipped. The base case is column 0: the empty t can be formed in exactly one way (keep nothing), so dp[i][0] = 1.

def num_distinct(s: str, t: str) -> int:
    ways = [1] + [0] * len(t)                         # ways[j] = ways to form t[:j] from s's prefix so far
    for ch in s:
        for j in range(len(t), 0, -1):                # backward: ways[j-1] must still be the previous row
            if ch == t[j - 1]:
                ways[j] += ways[j - 1]                # skip ch (already in ways[j]) + use ch as t[j-1]
    return ways[-1]

public static int NumDistinct(string s, string t)
{
    var ways = new long[t.Length + 1];                // ways[j] = ways to form t[..j] from s's prefix so far
    ways[0] = 1;
    foreach (char ch in s)
        for (int j = t.Length; j >= 1; j--)           // backward: ways[j-1] must still be the previous row
            if (ch == t[j - 1])
                ways[j] += ways[j - 1];               // skip ch (already in ways[j]) + use ch as t[j-1]
    return (int)ways[t.Length];
}

Time O(|s|·|t|), space O(|t|). The one-row version runs backward for the same reason as 0/1 knapsack: each letter of s may be used at most once per way, so ways[j − 1] must still describe the prefix without ch. Run it forward and s = "a", t = "aa" returns 1 instead of 0, because the single a gets used twice.

Pitfall: overflow in the middle. LeetCode promises that the final answer fits in 32 bits, but intermediate cells (ways to form short prefixes of t) can be far larger. In C++ that is undefined behaviour. Fix: in C#, use long. Even if a cell wraps around, the arithmetic is only additions, so the final value is still exact modulo 2⁶⁴, and the true answer is far below that. Problems that ask for the count "modulo 10⁹ + 7" want you to reduce after every addition instead.

Interleaving string: is there a path at all?

LeetCode 97 Medium. Can s3 be formed by merging s1 and s2, keeping the order of the letters inside each? For s1 = "aabcc", s2 = "dbbca": "aadbbcbcac" yes, "aadbbbaccc" no.

A greedy merge fails when the next letter of s1 and the next letter of s2 are both equal to the next letter of s3: you cannot tell which one to take. DP tries both. Here is the key observation that keeps the state small: after using i letters of s1 and j letters of s2, you have produced exactly i + j letters of s3. The position in s3 is not a third dimension; it is implied.

  • dp[i][j] = can s1[:i] and s2[:j] be woven into s3[:i+j]?
  • down (the letter s3[i+j−1] came from s1): dp[i−1][j] and s1[i−1] == s3[i+j−1];
  • right (it came from s2): dp[i][j−1] and s2[j−1] == s3[i+j−1];
  • there is no diagonal: each letter of s3 comes from exactly one string.

A true corner dp[n][m] is a monotone path of true cells, and the path is the weave: each down step takes a letter from s1, each right step takes one from s2.

def is_interleave(s1: str, s2: str, s3: str) -> bool:
    n, m = len(s1), len(s2)
    if n + m != len(s3):
        return False
    ok = [False] * (m + 1)                            # ok[j] = can s1[:i], s2[:j] weave s3[:i+j]
    for i in range(n + 1):
        for j in range(m + 1):
            if i == 0 and j == 0:
                ok[j] = True
                continue
            k = i + j - 1                             # the s3 letter this cell must place
            from_s1 = i > 0 and ok[j] and s1[i - 1] == s3[k]        # ok[j] is still row i-1
            from_s2 = j > 0 and ok[j - 1] and s2[j - 1] == s3[k]    # ok[j-1] is already row i
            ok[j] = from_s1 or from_s2
    return ok[m]

public static bool IsInterleave(string s1, string s2, string s3)
{
    int n = s1.Length, m = s2.Length;
    if (n + m != s3.Length) return false;
    var ok = new bool[m + 1];                         // ok[j] = can s1[..i], s2[..j] weave s3[..(i+j)]
    for (int i = 0; i <= n; i++)
        for (int j = 0; j <= m; j++)
        {
            if (i == 0 && j == 0) { ok[0] = true; continue; }
            int k = i + j - 1;                        // the s3 letter this cell must place
            bool fromS1 = i > 0 && ok[j] && s1[i - 1] == s3[k];         // ok[j] is still row i-1
            bool fromS2 = j > 0 && ok[j - 1] && s2[j - 1] == s3[k];     // ok[j-1] is already row i
            ok[j] = fromS1 || fromS2;
        }
    return ok[m];
}

Time O(n·m), space O(m). The length check comes first: without it, the indices into s3 can run past its end.

One string against itself: palindromes

A palindrome reads the same in both directions. Palindrome problems have one string, not two, but the same "look at the ends" idea applies. The state becomes an interval: dp[i][j] describes the substring s[i..j] (both ends included), and the transition looks at its two end letters s[i] and s[j]. Only i ≤ j makes sense, so only the upper triangle of the table is used.

For the longest palindromic subsequence (516 Medium):

  • ends equal: they can wrap whatever is best inside: 2 + dp[i+1][j−1];
  • ends differ: they cannot both be the outer letters of one palindrome, so drop one: max(dp[i+1][j], dp[i][j−1]);
  • base: one letter is a palindrome of length 1 (dp[i][i] = 1); an empty interval is 0.

Two ways to see the same answer. A palindromic subsequence of s reads the same backwards, so it is a common subsequence of s and reverse(s), and the longest common one is a palindrome too. So LPS(s) = LCS(s, s[::-1]), and you could reuse the LCS template unchanged. The interval table is the more direct view and generalises better: palindrome partitioning, counting palindromic subsequences and Interval & Tree DP all use intervals.

The visualizer fills the interval table length by length. In subsequence mode the walk back reads the palindrome from the outside in. Switch to substring (5, 647) for the boolean table of the next subsection: a cell is a palindrome only if its ends are equal and the inside is a palindrome, so the arrow becomes a strict requirement instead of an option.

def longest_palindrome_subseq(s: str) -> int:
    n = len(s)
    dp = [[0] * n for _ in range(n)]                  # dp[i][j] = LPS inside s[i..j]; 0 below the diagonal
    for i in range(n - 1, -1, -1):                    # i descending: the row below is ready
        dp[i][i] = 1
        for j in range(i + 1, n):                     # j ascending: the cell to the left is ready
            if s[i] == s[j]:
                dp[i][j] = dp[i + 1][j - 1] + 2       # wrap the inside (0 when it is empty)
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j - 1])
    return dp[0][n - 1] if n else 0


def min_insertions(s: str) -> int:                    # LC 1312
    return len(s) - longest_palindrome_subseq(s)      # mirror every letter outside the LPS

public static int LongestPalindromeSubseq(string s)
{
    int n = s.Length;
    if (n == 0) return 0;
    var dp = new int[n, n];                           // dp[i, j] = LPS inside s[i..j]; 0 below the diagonal
    for (int i = n - 1; i >= 0; i--)                  // i descending: the row below is ready
    {
        dp[i, i] = 1;
        for (int j = i + 1; j < n; j++)               // j ascending: the cell to the left is ready
            dp[i, j] = s[i] == s[j]
                ? dp[i + 1, j - 1] + 2                // wrap the inside (0 when it is empty)
                : Math.Max(dp[i + 1, j], dp[i, j - 1]);
    }
    return dp[0, n - 1];
}

public static int MinInsertions(string s) =>          // LC 1312
    s.Length - LongestPalindromeSubseq(s);            // mirror every letter outside the LPS

Time O(n²), space O(n²) (one row works if you only need the length). Minimum insertions to make s a palindrome is n − LPS: keep the longest palindromic subsequence as the core, and every other letter needs a mirror copy inserted on the other side.

Palindromic substrings: a boolean interval table

Longest Palindromic Substring (5) and Palindromic Substrings (647) are both Medium. For contiguous palindromes, pal[i][j] is true when s[i] == s[j] and the inside s[i+1..j−1] is a palindrome (an inside of length 0 or 1 always is). There is no "drop an end" option: a substring cannot skip letters. Count the true cells for 647; keep the longest one for 5.

def palindrome_table(s: str) -> tuple[str, int]:
    n = len(s)
    pal = [[False] * n for _ in range(n)]             # pal[i][j]: is s[i..j] a palindrome?
    best, count = (0, -1), 0
    for i in range(n - 1, -1, -1):
        for j in range(i, n):
            if s[i] == s[j] and (j - i < 2 or pal[i + 1][j - 1]):
                pal[i][j] = True
                count += 1                            # LC 647 counts these cells
                if j - i > best[1] - best[0]:
                    best = (i, j)                     # LC 5 keeps the widest one
    return s[best[0]:best[1] + 1], count

public static (string Longest, int Count) PalindromeTable(string s)
{
    int n = s.Length, count = 0, bestLo = 0, bestHi = -1;
    var pal = new bool[n, n];                         // pal[i, j]: is s[i..j] a palindrome?
    for (int i = n - 1; i >= 0; i--)
        for (int j = i; j < n; j++)
            if (s[i] == s[j] && (j - i < 2 || pal[i + 1, j - 1]))
            {
                pal[i, j] = true;
                count++;                              // LC 647 counts these cells
                if (j - i > bestHi - bestLo) (bestLo, bestHi) = (i, j);   // LC 5 keeps the widest one
            }
    return (s.Substring(bestLo, bestHi - bestLo + 1), count);
}

Time O(n²), space O(n²).

Expand around the centre: the same answers in O(1) memory

The boolean table has a simpler structure than it looks: pal[i][j] depends only on pal[i+1][j−1], its own inside. So every palindrome grows outward from a centre, one letter on each side, and stops growing at the first mismatch. A string of length n has 2n − 1 centres: n letters (odd lengths) and n − 1 gaps between letters (even lengths). Try every centre, expand while the ends match, and count or record what you see. Each successful expansion is one palindromic substring.

def expand_palindromes(s: str) -> tuple[str, int]:
    best, count = (0, -1), 0
    for c in range(2 * len(s) - 1):                   # n letter centres + (n - 1) gap centres
        lo, hi = c // 2, (c + 1) // 2                 # odd length: lo == hi; even: hi == lo + 1
        while lo >= 0 and hi < len(s) and s[lo] == s[hi]:
            count += 1                                # s[lo..hi] is one more palindrome
            if hi - lo > best[1] - best[0]:
                best = (lo, hi)
            lo, hi = lo - 1, hi + 1                   # grow one letter on each side
    return s[best[0]:best[1] + 1], count

public static (string Longest, int Count) ExpandPalindromes(string s)
{
    int count = 0, bestLo = 0, bestHi = -1;
    for (int c = 0; c < 2 * s.Length - 1; c++)        // n letter centres + (n - 1) gap centres
    {
        int lo = c / 2, hi = (c + 1) / 2;             // odd length: lo == hi; even: hi == lo + 1
        while (lo >= 0 && hi < s.Length && s[lo] == s[hi])
        {
            count++;                                  // s[lo..hi] is one more palindrome
            if (hi - lo > bestHi - bestLo) (bestLo, bestHi) = (lo, hi);
            lo--; hi++;                               // grow one letter on each side
        }
    }
    return (s.Substring(bestLo, bestHi - bestLo + 1), count);
}

Time O(n²) in the worst case ("aaaa…", where every expansion succeeds), O(1) extra space, and usually much faster in practice because most expansions stop at once. Manacher's algorithm reuses the expansions of earlier centres (mirror images inside a known palindrome) to get O(n) for both problems. It is animated on the String Algorithms page.

Palindrome Partitioning II: a 1D DP on top of the table

LeetCode 132 Hard. Cut s into pieces that are all palindromes, using as few cuts as possible. "aab" needs 1 cut (aa | b).

This is a prefix DP (like Word Break on 1D & Grid DP) that uses the palindrome table as its dictionary. cuts[i] = the fewest cuts for the prefix s[0..i]. Think about the last piece s[j..i]: it must be a palindrome, and then the rest s[0..j−1] is cut optimally, plus one cut between them. If the whole prefix is a palindrome (j = 0), no cut is needed.

cuts[i] = 0 if s[0..i] is a palindrome, else min(cuts[j−1] + 1) over every j with s[j..i] a palindrome.

The palindrome test pal[j][i] is filled in the same loop: when i grows, every pal[j+1][i−1] it needs was set in an earlier pass. Watch the arcs in the visualizer: each arc is one candidate last piece, and the winner sets the cell.

def min_cut(s: str) -> int:
    n = len(s)
    pal = [[False] * n for _ in range(n)]
    cuts = [0] * n                                    # cuts[i] = fewest cuts for s[0..i]
    for i in range(n):
        cuts[i] = i                                   # worst case: cut before every letter
        for j in range(i + 1):                        # try every last piece s[j..i]
            if s[j] == s[i] and (i - j < 2 or pal[j + 1][i - 1]):
                pal[j][i] = True
                cuts[i] = 0 if j == 0 else min(cuts[i], cuts[j - 1] + 1)
    return cuts[-1]


def min_cut_centres(s: str) -> int:                   # O(n) memory: palindromes from their centres
    n = len(s)
    cuts = list(range(n))
    for c in range(2 * n - 1):                        # centres in order: every piece ending before
        lo, hi = c // 2, (c + 1) // 2                 # s[lo] has a smaller centre, so it is final
        while lo >= 0 and hi < n and s[lo] == s[hi]:
            cuts[hi] = min(cuts[hi], 0 if lo == 0 else cuts[lo - 1] + 1)
            lo, hi = lo - 1, hi + 1
    return cuts[-1]

public static int MinCut(string s)
{
    int n = s.Length;
    var pal = new bool[n, n];
    var cuts = new int[n];                            // cuts[i] = fewest cuts for s[0..i]
    for (int i = 0; i < n; i++)
    {
        cuts[i] = i;                                  // worst case: cut before every letter
        for (int j = 0; j <= i; j++)                  // try every last piece s[j..i]
            if (s[j] == s[i] && (i - j < 2 || pal[j + 1, i - 1]))
            {
                pal[j, i] = true;
                cuts[i] = j == 0 ? 0 : Math.Min(cuts[i], cuts[j - 1] + 1);
            }
    }
    return cuts[n - 1];
}

public static int MinCutCentres(string s)             // O(n) memory: palindromes from their centres
{
    int n = s.Length;
    var cuts = new int[n];
    for (int i = 0; i < n; i++) cuts[i] = i;
    for (int c = 0; c < 2 * n - 1; c++)               // centres in order: every piece ending before
    {
        int lo = c / 2, hi = (c + 1) / 2;             // s[lo] has a smaller centre, so it is final
        while (lo >= 0 && hi < n && s[lo] == s[hi])
        {
            cuts[hi] = Math.Min(cuts[hi], lo == 0 ? 0 : cuts[lo - 1] + 1);

        }
    }
    return cuts[n - 1];
}

Time O(n²) for both. Space O(n²) for the table version, O(n) for the centre version. Why is the centre version safe? A palindrome s[x..lo−1] that ends just before the current piece has centre x + lo − 1 < lo + hi, so it was processed earlier and cuts[lo − 1] is already final when it is read.

Pattern matching: regex and wildcard

These two are the hardest classics in this family, and they become manageable once you see them as the same grid with one special column type. The text s runs down the side and the pattern p across the top. dp[i][j] = does s[:i] match p[:j] completely?

  • Regular Expression Matching (10) Hard: . matches any one letter; x* matches zero or more copies of the letter before it (x or .).
  • Wildcard Matching (44) Hard: ? matches any one letter; * matches any string, including the empty one, on its own.

An ordinary pattern character (a letter, . or ?) is a plain diagonal move: it consumes one letter of s and one character of p, and only if they match. All the difficulty is in the star, and the trick is to give it only two moves:

Star matches nothing more Star eats one more letter
Regex x* (2 pattern chars) dp[i][j−2]: skip x* entirely dp[i−1][j] if s[i−1] matches x: eat a letter, stay on x*
Wildcard * (1 pattern char) dp[i][j−1]: skip the * dp[i−1][j]: eat any letter, stay on *

Staying on the same column is the whole idea. You never have to decide "how many letters does this star take?" up front: each down move takes one more letter and leaves the star available for the next one, and the left move ends the star. So a star is a loop in the grid, not a fan-out of choices.

Step through s = "aab", p = "c*a*b". On star columns you will see both arrows: the arc from two columns back (zero copies) and the arrow from above (one more copy). Switch to wildcard mode: the zero-copies arrow becomes a short left arrow, because a wildcard * is one character, and the one-more-copy arrow no longer checks the letter.

Templates: regex and wildcard

def is_match_regex(s: str, p: str) -> bool:
    n, m = len(s), len(p)
    dp = [[False] * (m + 1) for _ in range(n + 1)]   # dp[i][j]: does s[:i] match p[:j]?
    dp[0][0] = True
    for i in range(n + 1):                           # i = 0 too: 'x*' can match the empty string
        for j in range(1, m + 1):
            if p[j - 1] == '*':
                dp[i][j] = dp[i][j - 2]              # 'x*' used zero times
                if i > 0 and p[j - 2] in (s[i - 1], '.'):
                    dp[i][j] = dp[i][j] or dp[i - 1][j]   # 'x*' eats s[i-1] and stays
            elif i > 0 and p[j - 1] in (s[i - 1], '.'):
                dp[i][j] = dp[i - 1][j - 1]          # one letter or '.': diagonal
    return dp[n][m]


def is_match_wildcard(s: str, p: str) -> bool:
    n, m = len(s), len(p)
    dp = [[False] * (m + 1) for _ in range(n + 1)]   # dp[i][j]: does s[:i] match p[:j]?
    dp[0][0] = True
    for i in range(n + 1):
        for j in range(1, m + 1):
            if p[j - 1] == '*':
                dp[i][j] = dp[i][j - 1] or (i > 0 and dp[i - 1][j])   # match nothing, or eat s[i-1]
            elif i > 0 and p[j - 1] in (s[i - 1], '?'):
                dp[i][j] = dp[i - 1][j - 1]          # one letter or '?': diagonal
    return dp[n][m]

public static bool IsMatchRegex(string s, string p)
{
    int n = s.Length, m = p.Length;
    var dp = new bool[n + 1, m + 1];                  // dp[i, j]: does s[..i] match p[..j]?
    dp[0, 0] = true;
    for (int i = 0; i <= n; i++)                      // i = 0 too: 'x*' can match the empty string
        for (int j = 1; j <= m; j++)
        {
            if (p[j - 1] == '*')
            {
                dp[i, j] = dp[i, j - 2];              // 'x*' used zero times
                if (i > 0 && (p[j - 2] == s[i - 1] || p[j - 2] == '.'))
                    dp[i, j] |= dp[i - 1, j];         // 'x*' eats s[i-1] and stays
            }
            else if (i > 0 && (p[j - 1] == s[i - 1] || p[j - 1] == '.'))
                dp[i, j] = dp[i - 1, j - 1];          // one letter or '.': diagonal
        }

}

public static bool IsMatchWildcard(string s, string p)
{
    int n = s.Length, m = p.Length;
    var dp = new bool[n + 1, m + 1];                  // dp[i, j]: does s[..i] match p[..j]?
    dp[0, 0] = true;
    for (int i = 0; i <= n; i++)
        for (int j = 1; j <= m; j++)
        {
            if (p[j - 1] == '*')
                dp[i, j] = dp[i, j - 1] || (i > 0 && dp[i - 1, j]);   // match nothing, or eat s[i-1]
            else if (i > 0 && (p[j - 1] == s[i - 1] || p[j - 1] == '?'))

        }

Time O(n·m), space O(n·m). Both roll into one row (keep the previous row for the diagonal and the "eat one more" read). LeetCode guarantees that a regex * always has a letter or . before it, so p[j − 2] is safe.

Why regex * looks two columns back. In regex, * is not a pattern on its own: a* is one unit made of two characters. "Zero copies" deletes the whole unit, so it jumps from column j to column j − 2. In wildcard, * is one character, so "zero letters" is one column back. Mixing these two up is the most common bug in problem 10.

Wildcard without a table: greedy with one backtrack point

Wildcard matching has a neat O(1)-memory solution. Walk both strings. When you meet a *, remember where it is and where s was, and first let it match nothing. If you later hit a mismatch, go back to the most recent star and let it eat one more letter. Why only the most recent star? Whatever an earlier star could absorb, the later one can absorb too, because * matches any string. So the earlier choices never need to be revisited.

def is_match_wildcard_greedy(s: str, p: str) -> bool:
    i = j = 0
    star, mark = -1, 0                                # last '*' seen in p, and where s was then
    while i < len(s):
        if j < len(p) and p[j] in (s[i], '?'):
            i, j = i + 1, j + 1
        elif j < len(p) and p[j] == '*':
            star, mark = j, i                         # first try: '*' matches nothing
            j += 1
        elif star != -1:
            mark += 1                                 # mismatch: the last '*' eats one more letter
            i, j = mark, star + 1
        else:
            return False
    while j < len(p) and p[j] == '*':                 # trailing stars match the empty string
        j += 1
    return j == len(p)

public static bool IsMatchWildcardGreedy(string s, string p)
{
    int i = 0, j = 0, star = -1, mark = 0;            // last '*' seen in p, and where s was then
    while (i < s.Length)
    {
        if (j < p.Length && (p[j] == s[i] || p[j] == '?')) { i++; j++; }
        else if (j < p.Length && p[j] == '*') { star = j; mark = i; j++; }   // first try: match nothing
        else if (star != -1) { mark++; i = mark; j = star + 1; }             // the last '*' eats one more
        else return false;
    }
    while (j < p.Length && p[j] == '*') j++;          // trailing stars match the empty string
    return j == p.Length;
}

Worst case O(n·m) (for example s = "aaaa…a", p = "*aaa…ab"), but O(n + m) on typical inputs, and O(1) memory. This greedy does not work for regex, because a* can only absorb as: a later b* cannot cover what an earlier a* should have taken.

When LCS collapses into LIS

Minimum Operations to Make a Subsequence (1713) Hard. target has distinct values; you may insert numbers anywhere in arr. What is the fewest insertions that make target a subsequence of arr?

Keep the longest part of target that already appears in arr in order, and insert the rest: the answer is len(target) − LCS(target, arr). Both arrays can have 10⁵ elements, so the O(n·m) table (10¹⁰ cells) is out. The distinct values save you:

  1. Replace every number in arr by its position in target, and drop numbers that are not in target.
  2. A common subsequence uses target positions in increasing order. So a common subsequence is exactly an increasing subsequence of the rewritten array.
  3. LCS = LIS of the rewritten array, which patience sorting finds in O(m log m). The LIS algorithm itself is taught step by step on 1D & Grid DP; here it is a black box.
from bisect import bisect_left


def min_operations(target: list[int], arr: list[int]) -> int:
    pos = {x: k for k, x in enumerate(target)}        # target values are distinct
    tails = []                                        # tails[L] = smallest end of an increasing run of length L+1
    for x in arr:
        if x in pos:
            k = bisect_left(tails, pos[x])            # strictly increasing: bisect_left
            if k == len(tails):
                tails.append(pos[x])
            else:
                tails[k] = pos[x]
    return len(target) - len(tails)                   # insert every target value that is not kept

public static int MinOperations(int[] target, int[] arr)
{
    var pos = new Dictionary<int, int>();             // target values are distinct
    for (int k = 0; k < target.Length; k++) pos[target[k]] = k;
    var tails = new List<int>();                      // tails[L] = smallest end of an increasing run of length L+1
    foreach (int x in arr)
    {
        if (!pos.TryGetValue(x, out int p)) continue;
        int k = tails.BinarySearch(p);                // values in tails are distinct
        if (k < 0) k = ~k;                            // insertion point = first element >= p
        if (k == tails.Count) tails.Add(p); else tails[k] = p;
    }
    return target.Length - tails.Count;
}

Time O(n + m log m), space O(n). The same reduction works whenever one side has no repeated values, for example LCS of two permutations. With repeated values on both sides, the general tool is Hunt–Szymanski: list the match pairs (i, j), sort them by i ascending and j descending, and run LIS on j. It is fast when there are few matching pairs, and degrades to O(n·m log) when there are many.

Keeping the alignment in linear memory: Hirschberg

The one-row LCS gives the length in O(m) memory, but walking back to the actual subsequence needs the whole table. For two DNA strings of 10⁵ letters, that table has 10¹⁰ cells. Hirschberg's algorithm (1975) gets the subsequence itself in O(n + m) memory and still O(n·m) time:

  1. Split a in the middle: top half a[:mid], bottom half a[mid:].
  2. Run the one-row LCS forward on the top half against b: F[k] = LCS(a[:mid], b[:k]) for every k.
  3. Run it backward on the bottom half (both strings reversed): B[k] = LCS(a[mid:], b[k:]).
  4. The optimal path crosses the middle row at some column k, and its length is F[k] + B[k]. Pick the k with the largest sum.
  5. Recurse on (a[:mid], b[:k]) and (a[mid:], b[k:]), and concatenate.

Each level of the recursion does about half the work of the level above (the subproblems' areas add up to half the parent's area), so the total is n·m·(1 + ½ + ¼ + …) ≤ 2·n·m cell updates.

def lcs_last_row(a: str, b: str) -> list[int]:
    row = [0] * (len(b) + 1)                          # row[k] = LCS(a, b[:k]) in O(len(b)) memory
    for ch in a:
        diag = 0
        for j in range(1, len(b) + 1):
            up = row[j]
            row[j] = diag + 1 if ch == b[j - 1] else max(up, row[j - 1])
            diag = up
    return row


def hirschberg_lcs(a: str, b: str) -> str:
    if not a or not b:
        return ""
    if len(a) == 1:
        return a if a in b else ""
    mid = len(a) // 2
    F = lcs_last_row(a[:mid], b)                      # F[k] = LCS(a[:mid], b[:k])
    B = lcs_last_row(a[mid:][::-1], b[::-1])[::-1]    # B[k] = LCS(a[mid:], b[k:])
    k = max(range(len(b) + 1), key=lambda k: F[k] + B[k])   # where the best path crosses the middle row
    return hirschberg_lcs(a[:mid], b[:k]) + hirschberg_lcs(a[mid:], b[k:])

public static int[] LcsLastRow(string a, string b)
{
    var row = new int[b.Length + 1];                  // row[k] = LCS(a, b[..k]) in O(b.Length) memory
    foreach (char ch in a)
    {
        int diag = 0;
        for (int j = 1; j <= b.Length; j++)
        {
            int up = row[j];
            row[j] = ch == b[j - 1] ? diag + 1 : Math.Max(up, row[j - 1]);
            diag = up;
        }
    }
    return row;
}

public static string Hirschberg(string a, string b)
{
    if (a.Length == 0 || b.Length == 0) return "";
    if (a.Length == 1) return b.Contains(a[0]) ? a : "";
    int mid = a.Length / 2;
    string Rev(string x) { var c = x.ToCharArray(); Array.Reverse(c); return new string(c); }
    int[] F = LcsLastRow(a[..mid], b);                // F[k] = LCS(a[..mid], b[..k])
    int[] B = LcsLastRow(Rev(a[mid..]), Rev(b));      // B[b.Length - k] = LCS(a[mid..], b[k..])
    int best = -1, cut = 0;
    for (int k = 0; k <= b.Length; k++)               // where the best path crosses the middle row
        if (F[k] + B[b.Length - k] > best) { best = F[k] + B[b.Length - k]; cut = k; }
    return Hirschberg(a[..mid], b[..cut]) + Hirschberg(a[mid..], b[cut..]);
}

Time O(n·m), space O(n + m) besides the recursion (depth O(log n)). The same split works for edit distance (pick the column with the smallest F[k] + B[k]), which is how linear-memory sequence aligners work. In interviews, mention it when asked "can you reconstruct with less memory?"; you will rarely need to code it.

Recognize it, cost it, avoid the traps

Recognize a sequence/string DP when:

  • there are two strings or arrays and the question is about lining them up: "common", "subsequence of both", "transform a into b", "delete from both", "merge/interleave", "match the pattern";
  • there is one string and the question is about palindromes inside it (interval table [i..j]) or about cutting it into valid pieces (prefix DP on top of a table);
  • the pattern has *, ? or . (matching DP: star = stay on the same column);
  • the sizes are up to a few thousand each, so n·m cells (about 10⁷) fit. With 10⁵ each, look for a reduction instead: LIS when one side is distinct, binary search plus hashing for substrings, or a greedy (subsequence checks, wildcard).

Pitfall: index of the letter vs index of the prefix. The table has n + 1 rows because row 0 is the empty prefix, so cell (i, j) looks at a[i − 1] and b[j − 1]. Writing a[i] == b[j] inside for i in range(1, n + 1) reads past the end or compares the wrong letters. Fix: say "prefix length i, last letter a[i − 1]" every time, and allocate (n + 1) × (m + 1).

Pitfall: the one-row LCS without a saved diagonal. Writing row[j] = row[j − 1] + 1 on a match uses the left cell (already this row) instead of the upper-left one. lcs("a", "aa") then returns 2: the single a is matched twice. Fix: keep diag (the old row[j]) as in the template, or run the loop backward when only the diagonal is read.

Pitfall: the regex star looks one column back. dp[i][j] = dp[i][j − 1] treats a* as "a once", so s = "", p = "a*" returns false. Fix: zero copies of x* skips both characters: dp[i][j − 2]. (One column back is right for wildcard * only.)

Pitfall: starting the matching loops at i = 1. Row 0 (empty text) is not all false: "a*b*" and "***" match the empty string. If the loop starts at i = 1, those cells stay false and isMatch("", "a*") fails. Fix: run i from 0 and guard the moves that need a letter with i > 0.

Pitfall: filling the palindrome table in the wrong order. With i ascending, pal[0][2] reads pal[1][1] before row 1 has been filled, so "aba" is missed. Fix: fill by length, or with i descending and j ascending, so the inside of every interval is finished first.

Worked problems

1. Shortest Common Supersequence: write the LCS once

LeetCode 1092 Hard. Return the shortest string that has both a and b as subsequences. For "abac" and "cab" one answer is "cabac".

Key insight. Every letter of both strings must appear, but a letter that the two strings share in order can be written once. The most sharing is an LCS, so the length is n + m − LCS. To build the string, walk the LCS table back exactly as before, but write every letter you pass: on a match, write it once and go diagonally; when you step up, write a's letter (it is not in the LCS); when you step left, write b's letter. When one string runs out, copy the rest of the other. In the LCS visualizer above, switch to supersequence (1092): the output builds up during the walk back.

Solution: LCS table, then a writing walk back, O(n·m) 
def shortest_common_supersequence(a: str, b: str) -> str:
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]       # the plain LCS table
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    out, i, j = [], n, m
    while i > 0 and j > 0:
        if a[i - 1] == b[j - 1]:                      # shared letter: write it once
            out.append(a[i - 1])
            i, j = i - 1, j - 1
        elif dp[i - 1][j] >= dp[i][j - 1]:            # a[i-1] is not in the LCS: write it
            out.append(a[i - 1])
            i -= 1
        else:                                         # b[j-1] is not in the LCS: write it
            out.append(b[j - 1])
            j -= 1
    out.extend(reversed(a[:i]))                       # one string ran out: copy what is left
    out.extend(reversed(b[:j]))
    return "".join(reversed(out))

public static string ShortestCommonSupersequence(string a, string b)
{
    int n = a.Length, m = b.Length;
    var dp = new int[n + 1, m + 1];                   // the plain LCS table
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i, j] = a[i - 1] == b[j - 1] ? dp[i - 1, j - 1] + 1 : Math.Max(dp[i - 1, j], dp[i, j - 1]);
    var rev = new StringBuilder();
    int x = n, y = m;
    while (x > 0 && y > 0)
    {
        if (a[x - 1] == b[y - 1]) { rev.Append(a[x - 1]); x--; y--; }   // shared letter: write it once
        else if (dp[x - 1, y] >= dp[x, y - 1]) rev.Append(a[--x]);       // a's letter is not in the LCS
        else rev.Append(b[--y]);                                          // b's letter is not in the LCS
    }
    while (x > 0) rev.Append(a[--x]);                 // one string ran out: copy what is left
    while (y > 0) rev.Append(b[--y]);
    char[] chars = rev.ToString().ToCharArray();
    Array.Reverse(chars);
    return new string(chars);
}

Time O(n·m), space O(n·m). The result has length exactly n + m − LCS, which is optimal: any common supersequence that is shorter would share more than LCS letters in order.

2. Max Dot Product of Two Subsequences: when "empty" is not allowed

LeetCode 1458 Hard. Choose two non-empty subsequences of the same length, one from each array, and maximise their dot product. Numbers can be negative.

Key insight. This is LCS where a "match" is any pair, worth x·y, and you maximise the total. The catch is non-emptiness. With an LCS-style base case of 0, [-1] and [1] would return 0 (choose nothing), but the true answer is −1. So the base cases are −∞ ("no valid choice yet"), and when you pair the last two numbers you either extend the best earlier pairing or start fresh with just this pair: x·y + max(dp[i−1][j−1], 0). The other two moves (drop one number) are the usual up and left.

Solution: LCS shape, −∞ base, "extend or start fresh", O(n·m) 
def max_dot_product(nums1: list[int], nums2: list[int]) -> int:
    n, m = len(nums1), len(nums2)
    NEG = float("-inf")
    dp = [[NEG] * (m + 1) for _ in range(n + 1)]     # dp[i][j] = best NON-EMPTY pairing in the prefixes
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            pair = nums1[i - 1] * nums2[j - 1]
            dp[i][j] = max(pair + max(dp[i - 1][j - 1], 0),   # pair the last two: extend or start fresh
                           dp[i - 1][j],                      # drop nums1[i-1]
                           dp[i][j - 1])                      # drop nums2[j-1]
    return dp[n][m]

public static int MaxDotProduct(int[] nums1, int[] nums2)
{
    int n = nums1.Length, m = nums2.Length;
    var dp = new int[n + 1, m + 1];                   // dp[i, j] = best NON-EMPTY pairing in the prefixes
    for (int i = 0; i <= n; i++) for (int j = 0; j <= m; j++) dp[i, j] = int.MinValue;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
        {
            int pair = nums1[i - 1] * nums2[j - 1];
            int best = pair + Math.Max(dp[i - 1, j - 1], 0);          // pair the last two: extend or start fresh
            best = Math.Max(best, Math.Max(dp[i - 1, j], dp[i, j - 1]));   // drop one number
            dp[i, j] = best;
        }
    return dp[n, m];
}

Time O(n·m), space O(n·m). max(…, 0) also keeps the C# version from adding to int.MinValue. The −∞ base is the general fix for "at least one" constraints; compare the "exactly" pitfall on the Knapsack Family page.

3. Distinct Subsequences II: count each string once, not each position set

LeetCode 940 Hard. Count the distinct non-empty subsequences of s (as strings), modulo 10⁹ + 7. "aba" has 6: a, b, ab, aa, ba, aba.

Key insight. Group the subsequences by their last letter: ends[c] = the number of distinct subsequences that end with c. When you read a new letter c, the subsequences ending with this c are "any distinct subsequence so far, or the empty one, followed by c": total + 1 of them. That set contains every subsequence that ended with c before (each of them is its own prefix plus c). So you replace ends[c], you do not add to it. Replacing is what removes the duplicates.

Read ends[a] ends[b] Total New strings
a 0 + 1 = 1 0 1 a
b 1 1 + 1 = 2 3 b, ab
a 3 + 1 = 4 (replaces 1) 2 6 a (again, not new), aa, ba, aba
Solution: one counter per last letter, O(n·Σ) 
def distinct_subseq_ii(s: str) -> int:
    MOD = 10**9 + 7
    ends = [0] * 26                                   # ends[c] = distinct subsequences ending with letter c
    for ch in s:
        ends[ord(ch) - 97] = (sum(ends) + 1) % MOD    # every subsequence so far (or none) + ch; REPLACE
    return sum(ends) % MOD

public static int DistinctSubseqII(string s)
{
    const long MOD = 1_000_000_007;
    var ends = new long[26];                          // ends[c] = distinct subsequences ending with letter c
    long total = 0;                                   // sum of ends, kept up to date
    foreach (char ch in s)
    {
        int c = ch - 'a';
        long fresh = (total + 1) % MOD;               // every subsequence so far (or none) + ch
        total = ((total - ends[c] + fresh) % MOD + MOD) % MOD;
        ends[c] = fresh;                              // REPLACE, which removes the duplicates
    }
    return (int)total;
}

Time O(n·26) as written in Python, O(n) with the running total in C#. Space O(26). The same "replace by last letter" trick handles counting distinct subsequences in many other settings (for example 1987, Number of Unique Good Subsequences).

4. Number of Ways to Form a Target String Given a Dictionary: counting by columns

LeetCode 1639 Hard. All words have the same length. Build target left to right; each letter must come from some word at column k, and the columns you use must strictly increase. Count the ways modulo 10⁹ + 7.

Key insight. Forget which word a letter comes from: only the column matters for the order rule, and a column offers cnt[k][c] copies of letter c. Now it is Distinct Subsequences with the columns playing the role of s: each column either is skipped, or supplies the next letter of target in cnt[k][target[j−1]] ways. Same table, same backward row, one multiplication.

Solution: distinct-subsequences row over the columns, O(L·(m + W)) 
from collections import Counter


def num_ways_form_target(words: list[str], target: str) -> int:
    MOD = 10**9 + 7
    L, m = len(words[0]), len(target)
    ways = [1] + [0] * m                              # ways[j] = ways to build target[:j] with the columns so far
    for k in range(L):
        cnt = Counter(w[k] for w in words)            # how many words offer each letter in column k
        for j in range(min(m, k + 1), 0, -1):         # backward: one column supplies at most one letter
            ways[j] = (ways[j] + ways[j - 1] * cnt[target[j - 1]]) % MOD
    return ways[m]

public static int NumWaysFormTarget(string[] words, string target)
{
    const long MOD = 1_000_000_007;
    int L = words[0].Length, m = target.Length;
    var ways = new long[m + 1];                       // ways[j] = ways to build target[..j] with the columns so far
    ways[0] = 1;
    var cnt = new long[26];
    for (int k = 0; k < L; k++)
    {
        Array.Clear(cnt);
        foreach (string w in words) cnt[w[k] - 'a']++;   // how many words offer each letter in column k
        for (int j = Math.Min(m, k + 1); j >= 1; j--)    // backward: one column supplies at most one letter
            ways[j] = (ways[j] + ways[j - 1] * cnt[target[j - 1] - 'a']) % MOD;
    }
    return (int)ways[m];
}

Time O(L·(W + m)) for W words of length L, space O(m + 26). Recognising "only the column matters" is what turns a scary three-index problem into a known two-index one.

5. Maximize Palindrome Length From Subsequences: a constraint on the outer pair

LeetCode 1771 Hard. Pick a non-empty subsequence of word1 and a non-empty subsequence of word2, concatenate them, and make the longest palindrome. Return 0 if none exists.

Key insight. Concatenate w = word1 + word2 and run the ordinary LPS interval table. A palindrome uses both words exactly when its outermost pair has its left letter in word1 and its right letter in word2. In the table, the outermost pair is created in a cell where w[i] == w[j]. So record dp[i][j] as a candidate only when i < len(word1) ≤ j.

Solution: LPS on the concatenation, record straddling pairs only, O((n₁ + n₂)²) 
def longest_palindrome_two(word1: str, word2: str) -> int:
    s, n1 = word1 + word2, len(word1)
    n, best = len(s), 0
    dp = [[0] * n for _ in range(n)]                  # ordinary LPS interval table on the concatenation
    for i in range(n - 1, -1, -1):
        dp[i][i] = 1
        for j in range(i + 1, n):
            if s[i] == s[j]:
                dp[i][j] = dp[i + 1][j - 1] + 2
                if i < n1 <= j:                       # this outer pair straddles the border
                    best = max(best, dp[i][j])
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j - 1])
    return best

public static int LongestPalindromeTwo(string word1, string word2)
{
    string s = word1 + word2;
    int n1 = word1.Length, n = s.Length, best = 0;
    var dp = new int[n, n];                           // ordinary LPS interval table on the concatenation
    for (int i = n - 1; i >= 0; i--)
    {
        dp[i, i] = 1;
        for (int j = i + 1; j < n; j++)
        {
            if (s[i] == s[j])
            {
                dp[i, j] = dp[i + 1, j - 1] + 2;
                if (i < n1 && n1 <= j) best = Math.Max(best, dp[i, j]);   // the outer pair straddles
            }
            else dp[i, j] = Math.Max(dp[i + 1, j], dp[i, j - 1]);
        }
    }
    return best;
}

Time O(N²) with N = n₁ + n₂, space O(N²). The pattern is general: solve the unconstrained DP, then read the answer only from the cells where the constraint is decided.

6. Count Different Palindromic Subsequences: inclusion–exclusion on an interval

LeetCode 730 Expert. Count the distinct non-empty palindromic subsequences of s (as strings), modulo 10⁹ + 7.

Key insight. Let dp[i][j] count them inside s[i..j]. If the ends differ, no palindrome uses both ends, so take the two shorter intervals and subtract their overlap (inclusion–exclusion): dp[i+1][j] + dp[i][j−1] − dp[i+1][j−1]. If both ends are the letter c, every palindrome counted inside s[i+1..j−1] stays, and wrapping each one in c…c makes a new one, so the base is 2 · inside. Then fix the small strings "c" and "cc" by looking at copies of c inside:

  • no c inside: "c" and "cc" are both new, so add 2;
  • exactly one c inside: "c" was already counted; only "cc" is new, so add 1;
  • two or more: let lo and hi be the first and last c inside. Everything inside s[lo+1..hi−1], wrapped in c…c, was already counted (wrapped by s[lo] and s[hi]), so subtract dp[lo+1][hi−1].
Solution: interval DP with next/previous occurrence, O(n²) 
def count_palindromic_subsequences(s: str) -> int:
    MOD = 10**9 + 7
    n = len(s)
    nxt, prv, seen = [n] * n, [-1] * n, {}
    for k, ch in enumerate(s):                        # prv[k] = previous index with the same letter
        prv[k] = seen.get(ch, -1)
        seen[ch] = k
    seen = {}
    for k in range(n - 1, -1, -1):                    # nxt[k] = next index with the same letter
        nxt[k] = seen.get(s[k], n)
        seen[s[k]] = k
    dp = [[0] * n for _ in range(n)]                  # dp[i][j] = distinct palindromic subsequences in s[i..j]
    for i in range(n - 1, -1, -1):
        dp[i][i] = 1
        for j in range(i + 1, n):
            inside = dp[i + 1][j - 1]                 # 0 when the inside is empty (below the diagonal)
            if s[i] != s[j]:
                dp[i][j] = dp[i + 1][j] + dp[i][j - 1] - inside
            else:
                lo, hi = nxt[i], prv[j]               # first and last copy of the end letter inside
                if lo > hi:
                    dp[i][j] = 2 * inside + 2         # no copy inside: "c" and "cc" are new
                elif lo == hi:
                    dp[i][j] = 2 * inside + 1         # one copy inside: only "cc" is new
                else:
                    dp[i][j] = 2 * inside - dp[lo + 1][hi - 1]   # "c…c" around s[lo+1..hi-1] counted twice
            dp[i][j] %= MOD
    return dp[0][n - 1]

public static int CountPalindromicSubsequences(string s)
{
    const long MOD = 1_000_000_007;
    int n = s.Length;
    int[] nxt = new int[n], prv = new int[n];
    var seen = new Dictionary<char, int>();
    for (int k = 0; k < n; k++) { prv[k] = seen.TryGetValue(s[k], out int p) ? p : -1; seen[s[k]] = k; }
    seen.Clear();
    for (int k = n - 1; k >= 0; k--) { nxt[k] = seen.TryGetValue(s[k], out int q) ? q : n; seen[s[k]] = k; }
    var dp = new long[n, n];                          // dp[i, j] = distinct palindromic subsequences in s[i..j]
    for (int i = n - 1; i >= 0; i--)
    {
        dp[i, i] = 1;
        for (int j = i + 1; j < n; j++)
        {
            long inside = j - i >= 2 ? dp[i + 1, j - 1] : 0;
            long v;
            if (s[i] != s[j]) v = dp[i + 1, j] + dp[i, j - 1] - inside;
            else
            {
                int lo = nxt[i], hi = prv[j];         // first and last copy of the end letter inside
                if (lo > hi) v = 2 * inside + 2;      // no copy inside: "c" and "cc" are new
                else if (lo == hi) v = 2 * inside + 1;   // one copy inside: only "cc" is new
                else v = 2 * inside - (hi - lo >= 2 ? dp[lo + 1, hi - 1] : 0);
            }
            dp[i, j] = ((v % MOD) + MOD) % MOD;
        }
    }
    return (int)dp[0, n - 1];
}

Time O(n²), space O(n²). If no copy of c lies inside, nxt[i] is j itself and prv[j] is i, so lo > hi covers that case without extra checks. The subtraction can go negative before the modulo, which Python handles and C# fixes with + MOD.

Check yourself

In the LCS table, why may a match always take the diagonal without checking up and left?

If a[i−1] == b[j−1], some optimal common subsequence of the two prefixes ends by pairing these two letters: take any optimal one, and if it does not use both last letters, you can swap its last pair for this one without making it shorter. So diag + 1 is never worse than up or left. You can also see it from the numbers: up = dp[i−1][j] ≤ dp[i−1][j−1] + 1, because adding one letter to b raises an LCS by at most 1.

Edit distance: which arrow is "insert" and which is "delete" when you turn a into b (rows = a, columns = b)?

Moving up from (i−1, j) consumes a letter of a without producing one of b: delete a[i−1]. Moving left from (i, j−1) produces b[j−1] without consuming a: insert it. The diagonal is a free match or a replace. The two names swap if you put b on the rows, and the number does not change.

Why does the one-row Distinct Subsequences loop run backward, like 0/1 knapsack?

Each letter of s may be used at most once in a match. The update ways[j] += ways[j−1] must read the old ways[j−1] (the row above). Going backward, ways[j−1] has not been updated yet in this row. Going forward, the same letter could extend a match it just made: with s = "a" and t = "aa", the forward loop answers 1 instead of 0.

s = "aa", p = "a*". Which cells make dp[2][2] true in the regex table?

dp[0][2] is true (zero copies: two columns left of dp[0][0]). Then dp[1][2] takes the "one more" move from dp[0][2] because s[0] = 'a' matches the a before the star, and dp[2][2] takes it again from dp[1][2]. The star never moves to another column: it stays on column 2 and eats one letter per row.

Longest palindromic subsequence vs longest palindromic substring of "agbcba"?

Subsequence: abcba, length 5 (skip the g). Substring: bcb, length 3 (must be contiguous). The interval tables differ only on a mismatch: the subsequence table takes max(dp[i+1][j], dp[i][j−1]), the substring table says false.

When does LCS run in O(n log n) instead of O(n·m)?

When one side has distinct values (1713). Map every element of the other side to its position in the distinct side and drop the ones that do not appear. A common subsequence is then an increasing sequence of positions, so LCS = LIS of the mapped list, which patience sorting solves in O(n log n). With repeats the general problem has no known strongly subquadratic algorithm.
