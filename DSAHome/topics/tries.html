TREES

Tries

Prefix trees animated insert by insert: autocomplete, word search on boards, and bitwise tries for max XOR.

Intermediate → Advanced~40 min studyBuilds on: Tree TraversalsUpdated 2026-11-03

A trie (say "try", from retrieval) is a tree of strings in which each edge is one character and each node is a prefix. Words with the same start share the same path, so "car", "cart" and "care" are stored as c, a, r plus two short branches. That layout answers the questions a hash set cannot: "does any word start with pre?", "how many words start with pre?", "which stored word is the shortest prefix of this sentence word?", "which stored number has the most bits different from x?". Every one of them is a single walk from the root, costing the length of the query and not the number of stored words. This page builds the trie letter by letter, then shows the patterns that make it a hard-problem tool: DFS over the trie for wildcards and autocomplete, trie-guided backtracking on a grid, binary tries for XOR, reversed tries for streams, suffix tries, and radix compression.

The invariant. The path from the root to a node spells exactly one string, that node's prefix, and every word stored below the node starts with it. So: (1) any prefix question is a walk of O(L) steps for a query of length L; (2) a node needs an explicit end mark because "is a prefix" and "is a word" are different facts; (3) a DFS below a node enumerates exactly the words with that prefix, in sorted order if children are visited a..z.

Prerequisites: Tree Traversals (DFS and BFS on a tree with many children), Hashing (the hash-set baseline we are beating) and Recursion & the Call Stack (wildcard search and Word Search II are recursive). Related: Backtracking for the grid search, Bit Manipulation for the XOR trie, and String Algorithms for KMP, Z and Aho-Corasick, which is a trie with failure links.

Why a trie: shared prefixes

Operation (word length L, n words) Hash set of strings Sorted list + binary search Trie
insert(w) O(L) average (hash the word) O(n) shift O(L)
contains(w) O(L) average O(L log n) O(L)
any word starts with p? O(n·L) scan O(L log n) O(|p|)
count words starting with p O(n·L) scan O(L log n) (two bisects) O(|p|) with pass counts
all words starting with p, sorted O(n·L + k log k) O(L log n + output) O(|p| + output)
shortest stored prefix of s O(L²) (hash every prefix of s) O(L² log n) O(L), stop at first end mark
memory total letters total letters at most total letters nodes, each with a children table

The sorted list is a fair competitor for static data (bisect for p and for p + '{' brackets every word with prefix p). The trie wins when the set changes, when you walk many prefixes of the same string (each extra letter costs O(1) instead of a new lookup), and when the search branches (wildcards, grids, XOR).

Think of it as a decision tree over letters. At the root you ask "what is the first letter?", at depth 1 "what is the second letter?", and so on. A hash set must see the whole word before it can say anything; a trie learns something after every letter, which is exactly what lets search stop early.

Insert, one character at a time

Insert walks the word from the root. For each letter it either reuses an existing child (the prefix is already stored) or creates a new node (a new branch starts here). At the last letter it marks the node as a word end. Two counters on every node make the trie count things for free: pass_count (how many inserted words go through this node) and end_count (how many end exactly here). Step through and watch which letters are reused:

Things to notice in the player:

  • "car" then "cat" creates only one new node: c and a are reused, t branches off a.
  • "cart" and "care" each add one node below r. The summary counts how many letters were saved by sharing.
  • "do" adds no node at all, because "dog" already created d and o. Only end_count at o changes. Without the end mark, a search for "do" could not tell that it was inserted.
  • The root's pass_count is the number of words. A node's pass_count equals the sum of its children's plus its own end_count.

The template

Every problem on this page starts from this class. In Python a dict per node is simplest and handles any alphabet. In C# an array of 26 children is the usual choice for lowercase input (it is faster, and iterating it gives a..z order for free). The walk helper is the heart: all queries are "walk, then look at the node".

class TrieNode:
    __slots__ = ("children", "pass_count", "end_count")

    def __init__(self):
        self.children = {}        # char -> TrieNode
        self.pass_count = 0       # words whose path goes through this node
        self.end_count = 0        # words that end exactly at this node


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        node.pass_count += 1
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
            node.pass_count += 1
        node.end_count += 1

    def walk(self, s):
        """Node for prefix s, or None if no stored word starts with s."""
        node = self.root
        for ch in s:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def search(self, word):
        node = self.walk(word)
        return node is not None and node.end_count > 0

    def starts_with(self, prefix):
        return self.walk(prefix) is not None

    def count_words_equal_to(self, word):
        node = self.walk(word)
        return node.end_count if node else 0

    def count_words_starting_with(self, prefix):
        node = self.walk(prefix)
        return node.pass_count if node else 0

    def erase(self, word):
        """Remove one copy of word (if stored). Branches nobody uses are cut off."""
        if self.count_words_equal_to(word) == 0:
            return False
        node = self.root
        node.pass_count -= 1
        for ch in word:
            child = node.children[ch]
            child.pass_count -= 1
            if child.pass_count == 0:
                del node.children[ch]       # the rest of the path belonged to this word only
                return True
            node = child
        node.end_count -= 1
        return True

public class TrieNode
{
    public TrieNode[] Next = new TrieNode[26];
    public int Pass;   // words through this node
    public int End;    // words ending here
}

public class Trie
{
    private readonly TrieNode root = new TrieNode();

    public void Insert(string word)
    {
        var node = root;
        node.Pass++;
        foreach (char ch in word)
        {
            int c = ch - 'a';
            node.Next[c] ??= new TrieNode();
            node = node.Next[c];
            node.Pass++;
        }
        node.End++;
    }

    private TrieNode Walk(string s)
    {
        var node = root;
        foreach (char ch in s)
        {
            node = node.Next[ch - 'a'];
            if (node == null) return null;
        }
        return node;
    }

    public bool Search(string word) => Walk(word) is { End: > 0 };
    public bool StartsWith(string prefix) => Walk(prefix) != null;
    public int CountWordsEqualTo(string word) => Walk(word)?.End ?? 0;
    public int CountWordsStartingWith(string prefix) => Walk(prefix)?.Pass ?? 0;

    public bool Erase(string word)
    {
        if (CountWordsEqualTo(word) == 0) return false;
        var node = root;
        node.Pass--;
        foreach (char ch in word)
        {
            int c = ch - 'a';
            var child = node.Next[c];
            child.Pass--;
            if (child.Pass == 0) { node.Next[c] = null; return true; }
            node = child;
        }
        node.End--;
        return true;
    }
}

This one class solves LeetCode 208 (Implement Trie) and 1804 (Implement Trie II, with counts and erase). If you only need membership, drop the counters and keep a boolean is_end.

Queries: one walk, four questions

The same walk answers different questions depending on what you read when it stops. Pick a mode in the player below and type a query. Try ca in all four modes, then card in "shortest root", then a word that falls off, like cow:

Question Walk Then read Fell off means
search(w): is w stored? all of w end_count > 0 False
startsWith(p) all of p nothing: surviving is the answer False
countPrefix(p) all of p pass_count 0
shortest stored prefix of s s, one letter at a time stop at the first node with an end mark s has no stored prefix
longest stored prefix of s s until it falls off the last end mark seen (use the last one, if any)

Pitfall: "the walk survived" is not "the word exists". After inserting "apple", walk("app") returns a node, but "app" was never inserted. Always check the end mark for search. The opposite mistake also happens: setting the end mark on every node during insert, which makes every prefix look like a word.

Delete: decrement, and cut the branch nobody uses

Deleting from a trie has one subtle point: you can remove a node only if no other word uses it. With pass counts the rule is simple. Walk the word, decrementing pass_count; the first node whose count drops to 0 is used by nobody else, so detach it from its parent and stop (everything below it goes with it). If you reach the end without that happening, the path is shared, and you only decrement end_count. The player erases "cart" (cuts one leaf), then "car" (only the end mark changes, because "care" still passes through r), then "dog", then "ca" (not stored, nothing changes):

Without counters, the classic recursive delete asks the same question on the way back up: "after removing the word below me, do I still have children or an end mark? If not, my parent can drop me."

def delete(root, word):
    """Recursive delete for a trie with an is_end flag. Returns True if word was present."""
    found = False

    def rec(node, i):
        nonlocal found
        if i == len(word):
            if not node.is_end:
                return False
            node.is_end = False
            found = True
            return not node.children           # prune me if I am now a useless leaf
        child = node.children.get(word[i])
        if child is None:
            return False
        if rec(child, i + 1):
            del node.children[word[i]]
            return not node.children and not node.is_end
        return False

    rec(root, 0)
    return found

public class FlagNode
{
    public Dictionary<char, FlagNode> Children = new();
    public bool IsEnd;
}

public static class TrieDelete
{
    // Returns true if word was present; prunes nodes that no longer lead to a word.
    public static bool Delete(FlagNode root, string word)
    {
        bool found = false;
        bool Rec(FlagNode node, int i)
        {
            if (i == word.Length)
            {
                if (!node.IsEnd) return false;
                node.IsEnd = false;
                found = true;
                return node.Children.Count == 0;
            }
            if (!node.Children.TryGetValue(word[i], out var child)) return false;
            if (Rec(child, i + 1))
            {
                node.Children.Remove(word[i]);
                return node.Children.Count == 0 && !node.IsEnd;
            }
            return false;
        }
        Rec(root, 0);
        return found;
    }
}

In interviews, "lazy delete" is often enough: just clear the end mark (or decrement end_count) and leave the nodes. Searches stay correct, prefix checks may then report prefixes of deleted words, and memory is not reclaimed. Say which one you are doing.

Storing children: array, map, or flat table

All three layouts run the same algorithm. Pick by alphabet and scale:

  • Dict / Dictionary: the default in Python, and for any alphabet that is large, sparse or unknown (Unicode, whole path components such as "/a/b" split on /, digits mixed with letters). Remember that a dict does not iterate in sorted order in general: Python keeps insertion order, so sort the keys when the problem asks for lexicographic output.
  • Array of 26: the default in C#, Java and C++ for lowercase input. Index with ch - 'a', iterate 0..25 for sorted order. Wasteful when most nodes have one child (a dictionary of long, unrelated words).
  • Flat table nxt[node * 26 + c]: one big int array, node ids handed out by a counter. No objects, no pointers, no garbage collector pressure. This is the fastest version and the natural one for binary tries, where each node has exactly two slots.
class ArrayTrie:
    """Flat-table trie for lowercase words. Capacity = total letters + 1 nodes."""

    def __init__(self, capacity):
        self.nxt = [-1] * (26 * capacity)     # nxt[node*26 + c] = child id or -1
        self.end = [0] * capacity
        self.size = 1                          # node 0 is the root

    def insert(self, word):
        node = 0
        for ch in word:
            slot = node * 26 + (ord(ch) - 97)
            if self.nxt[slot] == -1:
                self.nxt[slot] = self.size
                self.size += 1
            node = self.nxt[slot]
        self.end[node] += 1

    def search(self, word):
        node = 0
        for ch in word:
            node = self.nxt[node * 26 + (ord(ch) - 97)]
            if node == -1:
                return False
        return self.end[node] > 0

public class ArrayTrie
{
    private readonly int[] nxt;   // nxt[node*26 + c] = child id, 0 = none (root is never a child)
    private readonly int[] end;
    private int size = 1;

    public ArrayTrie(int capacity)
    {
        nxt = new int[26 * capacity];
        end = new int[capacity];
    }

    public void Insert(string word)
    {
        int node = 0;
        foreach (char ch in word)
        {
            int slot = node * 26 + (ch - 'a');
            if (nxt[slot] == 0) nxt[slot] = size++;
            node = nxt[slot];
        }
        end[node]++;
    }

    public bool Search(string word)
    {
        int node = 0;
        foreach (char ch in word)
        {
            node = nxt[node * 26 + (ch - 'a')];
            if (node == 0) return false;
        }
        return end[node] > 0;
    }
}

The C# version uses 0 for "no child", which is safe because the root (id 0) is never anybody's child; it saves filling the array with -1. Memory check: 10⁵ words of length 10 is at most 10⁶ nodes; an array trie needs 26 × 10⁶ ints = 104 MB, so for big inputs prefer the dictionary version or reduce the alphabet.

Wildcards: DFS over the trie

When the query contains . (any letter), the walk stops being a single path. At a . you must try every child, which turns search into a depth-first search over the trie, with the pattern index as the depth. The pruning is automatic: a branch dies the moment the next fixed letter is missing. Try ..n, .a., d.., ... and ....:

Cost: a pattern of all dots explores every node down to depth L, which is O(min(total nodes, 26^L)). Fixed letters cut the fan-out to 1. That is why LeetCode 211 limits the number of dots: the worst case is a full traversal per query. A useful extra pruning is to bucket words by length (or store max_depth_below per node), so a pattern of length 3 never wanders into long branches.

Autocomplete: walk the prefix, then DFS for the best k

Search Suggestions (LeetCode 1268) asks for the first 3 products, in lexicographic order, that start with each prefix of the typed word. The trie solution reuses the walk: after typing one more letter, move one step from the previous node (do not restart from the root), then DFS the subtree in a..z order and stop after 3 words. Once the walk falls off, every later prefix has no suggestions either.

Two common speed-ups, both used in production autocomplete:

  1. Cache the answer in the node. During insert (with words pre-sorted), append the word to the top list of every node on its path while that list has fewer than k entries. A query is then the walk plus reading node.top, O(L + k), with no DFS. For "top k by frequency" instead of alphabetical, keep the k best in each node and update them on insert.
  2. Skip the trie. Sort the products, and for each prefix binary search for the first word ≥ prefix; the answer is that word and the next two, if they still start with the prefix. Same complexity, much less code. Know both: the trie version extends to "frequency-ranked" and "changing dictionary"; the sorted version is what you write in 5 minutes.

Tries on grids: Word Search II

Searching a grid for many words one at a time repeats the same DFS for every word. Instead, put all words in a trie and run one backtracking DFS from every cell, moving down the trie with every step on the grid. The trie answers "is there any word that continues with this letter?" in O(1), so a path dies as soon as it spells a prefix of nothing. Found words are recorded at end nodes, and the visualizer also shows leaf pruning: once a word is found and its branch has no other words, the branch is removed so no later DFS walks into it.

The three optimisations that make the difference between passing and timing out on LeetCode 212:

  • Store the word itself at its end node (node.word = "oath") instead of rebuilding strings along the path. After reporting it, set node.word = None so it is reported once.
  • Prune found leaves: after returning from a child, if the child has no children and no word left, delete it from the parent. Later starts then fail immediately.
  • Mark visited cells in place (board[r][c] = '#', restore afterwards) instead of a visited set.

Binary tries: maximum XOR

A number is a string over the alphabet {0, 1} if you write its bits from the highest one down. Insert all numbers into such a binary trie and a greedy walk answers "which stored y maximises x XOR y?" in B steps (B = bit width, 31 for non-negative ints). At each bit the walk prefers the child with the opposite bit, because a 1 in that position of the XOR is worth more than all lower bits combined. Each node has at most 2 children, so the flat-table layout is the natural one.

def find_maximum_xor(nums):
    B = max(nums).bit_length() or 1
    nxt = [[0, 0]]                       # node -> [child for bit 0, child for bit 1]; 0 = none
    best = 0
    for x in nums:
        node = 0
        for b in range(B - 1, -1, -1):   # insert x
            bit = (x >> b) & 1
            if not nxt[node][bit]:
                nxt[node][bit] = len(nxt)
                nxt.append([0, 0])
            node = nxt[node][bit]
        node, cur = 0, 0
        for b in range(B - 1, -1, -1):   # query x against everything so far (x itself included)
            bit = (x >> b) & 1
            if nxt[node][bit ^ 1]:
                cur |= 1 << b
                node = nxt[node][bit ^ 1]
            else:
                node = nxt[node][bit]
        best = max(best, cur)
    return best

public static class XorTrie
{
    public static int FindMaximumXor(int[] nums)
    {
        const int B = 31;
        var nxt = new int[(nums.Length * B + 1) * 2];   // nxt[node*2 + bit]; 0 = none
        int size = 1, best = 0;
        foreach (int x in nums)
        {
            int node = 0;
            for (int b = B - 1; b >= 0; b--)
            {
                int bit = (x >> b) & 1;
                if (nxt[node * 2 + bit] == 0) nxt[node * 2 + bit] = size++;
                node = nxt[node * 2 + bit];
            }
            node = 0;
            int cur = 0;
            for (int b = B - 1; b >= 0; b--)
            {
                int bit = (x >> b) & 1;
                int want = nxt[node * 2 + (bit ^ 1)];
                if (want != 0) { cur |= 1 << b; node = want; }
                else node = nxt[node * 2 + bit];
            }
            best = Math.Max(best, cur);
        }
        return best;
    }
}

Why the query never falls off: every inserted number has a full B-bit path, so at each bit at least one child exists (the walk follows an actual stored number). Variants build on the same walk: min XOR prefers the same bit; "max XOR with y ≤ m" (LeetCode 1707) sorts queries by m and inserts numbers offline, or stores the minimum value per node and refuses children whose minimum exceeds m; "count pairs with XOR < k" (LeetCode 1803) stores pass counts and, wherever k has a 1 bit, adds the whole subtree that keeps the XOR bit at 0.

Reversed tries: matching suffixes of a stream

Stream of Characters (LeetCode 1032) asks, after each new letter, whether some word is a suffix of everything typed so far. A forward trie would have to track every possible start position. Instead insert every word reversed and, after each letter, walk the trie backwards through the stream from the newest letter. The walk stops at the first end mark (a match) or when it falls off, and it never needs more than the longest word's length of history.

The general trick: a suffix question on strings is a prefix question on reversed strings. "Short encoding of words" (LeetCode 820) uses the same reversal: a word is free if it is a suffix of another word, which in a reversed trie means it ends at a non-leaf node. For many words and long streams, Aho-Corasick (a forward trie plus failure links, see String Algorithms) answers each letter in amortised O(1).

Suffix tries and two-sided keys

Inserting every suffix of a string turns substring questions into prefix questions. It is O(n²) letters, so it fits problems with n up to a few thousand: counting distinct substrings, checking many patterns against one text, or "longest repeated substring" (deepest node with pass count ≥ 2). Compressed tries: radix trees

A plain trie spends one node per letter even when nothing branches, which wastes memory on long words with unique tails. A radix tree (also called a Patricia trie or compact trie) merges every chain of single-child, non-terminal nodes into one edge labelled with a string. Insert walks edge labels, and when the new word leaves a label in the middle it splits the edge in two. Step through the six Latin words below and watch each split:

You rarely implement a radix tree in an interview, but know the idea: it bounds the node count by 2n − 1 for n words, it is how IP routing tables do longest-prefix match, and it is what suffix trees are (a compressed suffix trie, built in O(n) by Ukkonen's algorithm). If an interviewer pushes on trie memory, "compress single-child chains" and "use a sorted array of children" are the two answers they want to hear.

Recognizing a trie problem

Reach for a trie when you see:

  • "starts with", "prefix", "autocomplete", "suggestions", "dictionary of words" plus many queries.
  • Many words searched in one big structure (grid, text, stream): build the trie of the words, scan once.
  • Replace or match the shortest / longest dictionary prefix of each token.
  • Wildcards (. or ?) in queries against a fixed dictionary.
  • XOR maximised or counted over pairs: binary trie over the bits, highest bit first.
  • Suffix questions: reverse the words. Two-sided questions: glue the sides into one key.
  • Paths like /a/b/c or IP prefixes: a trie whose "letters" are path components or bits.

Probably not a trie: exact membership only (use a hash set), one pattern in one text (KMP or Z), or ordering by value (heap, sorted container).

Pitfalls that cost interviews.

  • Forgetting the end mark, or reading it during startsWith.
  • Python dicts iterate in insertion order, not sorted order: sort children when the output must be lexicographic.
  • Rebuilding strings at every DFS step (O(L²)); store the word at its end node instead.
  • XOR trie with the wrong bit width: if numbers go up to 2³¹ − 1 you need bits 30..0, and all numbers must be inserted with the same width, padded with leading zeros.
  • Allocating 26 child pointers for every node with 10⁶ nodes in a managed language: watch memory.
  • Recursion depth: a DFS over a trie of words with length 10⁴ can overflow Python's default limit.

Worked problems

1. Replace Words (Medium)

LeetCode 648. Given a dictionary of roots and a sentence, replace every word that starts with a root by the shortest such root.

Insight. "Shortest stored prefix of a word" is the trie walk that stops at the first end mark. Store the root string itself at its end node so the answer is ready when you hit it. Each sentence word costs at most its own length, and the walk usually stops after a few letters. The hash-set alternative (try every prefix of the word in increasing length) costs O(L²) per word because every prefix must be sliced and hashed.

Solution: walk each word, stop at the first stored root 
def replace_words(dictionary, sentence):
    root = {}
    for w in dictionary:
        node = root
        for ch in w:
            node = node.setdefault(ch, {})
        node["$"] = w                    # the root word ends here
    out = []
    for word in sentence.split():
        node, rep = root, word
        for ch in word:
            if ch not in node:
                break                    # no root is a prefix of word
            node = node[ch]
            if "$" in node:
                rep = node["$"]          # first end mark = shortest root
                break
        out.append(rep)
    return " ".join(out)

public static class ReplaceWordsSolver
{
    private class Node { public Node[] Next = new Node[26]; public string Word; }

    public static string ReplaceWords(IList<string> dictionary, string sentence)
    {
        var root = new Node();
        foreach (var w in dictionary)
        {
            var node = root;
            foreach (char ch in w) node = node.Next[ch - 'a'] ??= new Node();
            node.Word = w;
        }
        var words = sentence.Split(' ');
        for (int i = 0; i < words.Length; i++)
        {
            var node = root;
            foreach (char ch in words[i])
            {
                node = node.Next[ch - 'a'];
                if (node == null) break;
                if (node.Word != null) { words[i] = node.Word; break; }
            }
        }
        return string.Join(" ", words);
    }
}

Time O(total dictionary letters + total sentence letters); space O(total dictionary letters). In the "shortest root" mode of the query player above, try cats and cards with the default dictionary.

2. Design Add and Search Words Data Structure (Medium)

LeetCode 211. Support addWord(w) and search(pattern) where . matches any one letter.

Insight. Fixed letters follow one edge; a . fans out to every child. The search is a DFS whose depth is the pattern index, exactly what the wildcard player shows with its call stack. Return as soon as one branch succeeds (any in Python short-circuits). The end check is at i == len(word): reaching the end of the pattern is not enough, the node must also be a word end.

Solution: DFS that branches only on dots 
class WordDictionary:
    def __init__(self):
        self.root = {}

    def addWord(self, word):
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
        node["$"] = True

    def search(self, word):
        def dfs(node, i):
            if i == len(word):
                return "$" in node
            ch = word[i]
            if ch == ".":
                return any(dfs(child, i + 1) for key, child in node.items() if key != "$")
            return ch in node and dfs(node[ch], i + 1)

        return dfs(self.root, 0)

public class WordDictionary
{
    private class Node { public Node[] Next = new Node[26]; public bool End; }
    private readonly Node root = new Node();

    public void AddWord(string word)
    {
        var node = root;
        foreach (char ch in word) node = node.Next[ch - 'a'] ??= new Node();
        node.End = true;
    }

    public bool Search(string word) => Dfs(root, word, 0);

    private static bool Dfs(Node node, string word, int i)
    {
        if (i == word.Length) return node.End;
        char ch = word[i];
        if (ch != '.')
        {
            var next = node.Next[ch - 'a'];
            return next != null && Dfs(next, word, i + 1);
        }
        foreach (var child in node.Next)
            if (child != null && Dfs(child, word, i + 1)) return true;
        return false;
    }
}

addWord is O(L). search is O(L) without dots and O(26^d · L) in the worst case with d dots (bounded by the number of trie nodes at those depths). LeetCode allows at most 2 dots per query, so it is fast in practice.

3. Search Suggestions System (Medium)

LeetCode 1268. After each typed letter of searchWord, return up to three products (lexicographically smallest) that start with the typed prefix.

Insight. Insert the products in sorted order and, at every node on a product's path, append the product to the node's top list while it holds fewer than 3. Because insertion is sorted, each top list is automatically the 3 smallest words with that prefix. A query is then one step down per typed letter and a read of top; once the walk falls off, the rest of the answers are empty lists. The bisect version is shown too: it is shorter and equally fast.

Solution: cached top-3 per node (and the sorted-array alternative) 
from bisect import bisect_left


class SuggestNode:
    __slots__ = ("children", "top")

    def __init__(self):
        self.children = {}
        self.top = []


def suggested_products(products, search_word):
    root = SuggestNode()
    for p in sorted(products):
        node = root
        for ch in p:
            node = node.children.setdefault(ch, SuggestNode())
            if len(node.top) < 3:
                node.top.append(p)
    ans, node = [], root
    for ch in search_word:
        node = node.children.get(ch) if node else None
        ans.append(list(node.top) if node else [])
    return ans


def suggested_products_bisect(products, search_word):
    products = sorted(products)
    ans, prefix, lo = [], "", 0
    for ch in search_word:
        prefix += ch
        lo = bisect_left(products, prefix, lo)        # first word >= prefix
        ans.append([p for p in products[lo:lo + 3] if p.startswith(prefix)])
    return ans

public static class SuggestionsSolver
{
    private class Node { public Node[] Next = new Node[26]; public List<string> Top = new(); }

    public static IList<IList<string>> SuggestedProducts(string[] products, string searchWord)
    {
        var sorted = (string[])products.Clone();
        Array.Sort(sorted, StringComparer.Ordinal);
        var root = new Node();
        foreach (var p in sorted)
        {
            var node = root;
            foreach (char ch in p)
            {
                node = node.Next[ch - 'a'] ??= new Node();
                if (node.Top.Count < 3) node.Top.Add(p);
            }
        }
        var ans = new List<IList<string>>();
        var cur = root;
        foreach (char ch in searchWord)
        {
            cur = cur?.Next[ch - 'a'];
            ans.Add(cur == null ? new List<string>() : new List<string>(cur.Top));
        }
        return ans;
    }
}

Building is O(total letters), plus the sort. Each query letter is O(1) steps plus copying 3 strings. Use StringComparer.Ordinal in C#: the default culture-aware comparison does not always match LeetCode's byte order. The lo hint in the bisect version is valid because each longer prefix sorts at or after the previous one.

4. Sum of Prefix Scores of Strings (Hard)

LeetCode 2416. The score of a string p is the number of words that start with p. For each word, return the sum of the scores of all its non-empty prefixes.

Insight. The score of a prefix is exactly its node's pass_count. So insert every word with pass counts, then walk each word again and add the counts along its path. Hashing every prefix would be O(L²) per word; the trie makes it O(L). This is the pass-count player above, read along a whole path instead of at one node.

Solution: pass counts, summed along each word's path 
def sum_prefix_scores(words):
    nxt, cnt = [{}], [0]                 # flat trie: children dict and pass count per node id
    for w in words:
        node = 0
        for ch in w:
            if ch not in nxt[node]:
                nxt[node][ch] = len(nxt)
                nxt.append({})
                cnt.append(0)
            node = nxt[node][ch]
            cnt[node] += 1
    out = []
    for w in words:
        node = total = 0
        for ch in w:
            node = nxt[node][ch]
            total += cnt[node]
        out.append(total)
    return out

public static class PrefixScores
{
    public static int[] SumPrefixScores(string[] words)
    {
        int letters = 1;
        foreach (var w in words) letters += w.Length;
        var nxt = new int[letters * 26];
        var cnt = new int[letters];
        int size = 1;
        foreach (var w in words)
        {
            int node = 0;
            foreach (char ch in w)
            {
                int slot = node * 26 + (ch - 'a');
                if (nxt[slot] == 0) nxt[slot] = size++;
                node = nxt[slot];
                cnt[node]++;
            }
        }
        var res = new int[words.Length];
        for (int i = 0; i < words.Length; i++)
        {
            int node = 0, total = 0;
            foreach (char ch in words[i])
            {
                node = nxt[node * 26 + (ch - 'a')];
                total += cnt[node];
            }
            res[i] = total;
        }
        return res;
    }
}

Two passes over all letters: O(total letters) time and nodes. Sums fit in an int on LeetCode's limits (at most 1000 words of length 1000).

5. Word Search II (Hard)

LeetCode 212. Return every word from a list that can be traced in a letter grid by moving between horizontally or vertically adjacent cells, using each cell at most once per word.

Insight. One backtracking DFS per start cell, guided by a trie of all words, replaces one DFS per word. The DFS carries the trie node for the path so far; a neighbour is explored only if the node has a child for its letter. Store each word at its end node and remove it once reported. After the recursion returns, prune: a node with no children and no word can never produce anything again, so delete it from its parent. The player above shows the trie shrinking as words are found.

Solution: backtracking guided by a trie, with leaf pruning 
def find_words(board, words):
    root = {}
    for w in words:
        node = root
        for ch in w:
            node = node.setdefault(ch, {})
        node["$"] = w
    R, C = len(board), len(board[0])
    found = []

    def dfs(r, c, parent):
        ch = board[r][c]
        node = parent[ch]
        word = node.pop("$", None)       # report each word once
        if word:
            found.append(word)
        board[r][c] = "#"                # mark visited in place
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < R and 0 <= nc < C and board[nr][nc] in node:
                dfs(nr, nc, node)
        board[r][c] = ch                 # restore
        if not node:
            del parent[ch]               # leaf pruning: nothing left below

    for r in range(R):
        for c in range(C):
            if board[r][c] in root:
                dfs(r, c, root)
    return found

public static class WordSearchII
{
    private class Node { public Node[] Next = new Node[26]; public string Word; public int Kids; }

    public static IList<string> FindWords(char[][] board, string[] words)
    {
        var root = new Node();
        foreach (var w in words)
        {
            var node = root;
            foreach (char ch in w)
            {
                int c = ch - 'a';
                if (node.Next[c] == null) { node.Next[c] = new Node(); node.Kids++; }
                node = node.Next[c];
            }
            node.Word = w;
        }
        var found = new List<string>();
        int R = board.Length, C = board[0].Length;
        int[] dr = { 1, -1, 0, 0 }, dc = { 0, 0, 1, -1 };

        void Dfs(int r, int c, Node parent)
        {
            char ch = board[r][c];
            var node = parent.Next[ch - 'a'];
            if (node.Word != null) { found.Add(node.Word); node.Word = null; }
            board[r][c] = '#';
            for (int k = 0; k < 4; k++)
            {
                int nr = r + dr[k], nc = c + dc[k];
                if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
                char nx = board[nr][nc];
                if (nx != '#' && node.Next[nx - 'a'] != null) Dfs(nr, nc, node);
            }
            board[r][c] = ch;
            if (node.Kids == 0 && node.Word == null) { parent.Next[ch - 'a'] = null; parent.Kids--; }
        }

        for (int r = 0; r < R; r++)
            for (int c = 0; c < C; c++)
                if (root.Next[board[r][c] - 'a'] != null) Dfs(r, c, root);
        return found;
    }
}

Worst case O(R · C · 4 · 3^(L−1)) for maximum word length L: each path can turn 3 ways after the first step. The trie bounds the real work by the number of (cell path, trie node) pairs that actually match, and pruning shrinks the trie as words are found, which is what makes boards full of "aaaa…" pass.

6. Maximum XOR With an Element From Array (Hard)

LeetCode 1707. For each query (x, m), return the maximum x XOR y over all y in nums with y ≤ m, or -1 if there is none.

Insight. The XOR walk only works on the numbers that are in the trie, so control which numbers are in it. Answer the queries offline in increasing order of m: sort nums, and before answering a query insert every number ≤ its m. The trie then holds exactly the allowed numbers, and the greedy walk from the binary trie section answers it. This "sort queries, grow the structure" trick works for many data structures, not only tries.

Solution: offline queries sorted by limit, binary trie 
def maximize_xor(nums, queries):
    B = 30                                       # nums and x are below 2^30
    nums = sorted(nums)
    order = sorted(range(len(queries)), key=lambda i: queries[i][1])
    nxt = [[0, 0]]
    ans = [-1] * len(queries)
    j = 0
    for qi in order:
        x, m = queries[qi]
        while j < len(nums) and nums[j] <= m:    # grow the trie up to the limit
            node = 0
            for b in range(B - 1, -1, -1):
                bit = (nums[j] >> b) & 1
                if not nxt[node][bit]:
                    nxt[node][bit] = len(nxt)
                    nxt.append([0, 0])
                node = nxt[node][bit]
            j += 1
        if j == 0:
            continue                             # nothing allowed yet: answer stays -1
        node = cur = 0
        for b in range(B - 1, -1, -1):
            bit = (x >> b) & 1
            if nxt[node][bit ^ 1]:
                cur |= 1 << b
                node = nxt[node][bit ^ 1]
            else:
                node = nxt[node][bit]
        ans[qi] = cur
    return ans

public static class MaxXorWithLimit
{
    public static int[] MaximizeXor(int[] nums, int[][] queries)
    {
        const int B = 30;
        var sorted = (int[])nums.Clone();
        Array.Sort(sorted);
        var order = new int[queries.Length];
        for (int i = 0; i < order.Length; i++) order[i] = i;
        Array.Sort(order, (a, b) => queries[a][1].CompareTo(queries[b][1]));
        var nxt = new int[(sorted.Length * B + 1) * 2];
        int size = 1, j = 0;
        var ans = new int[queries.Length];
        foreach (int qi in order)
        {
            int x = queries[qi][0], m = queries[qi][1];
            for (; j < sorted.Length && sorted[j] <= m; j++)
            {
                int node = 0;
                for (int b = B - 1; b >= 0; b--)
                {
                    int bit = (sorted[j] >> b) & 1;
                    if (nxt[node * 2 + bit] == 0) nxt[node * 2 + bit] = size++;
                    node = nxt[node * 2 + bit];
                }
            }
            if (j == 0) { ans[qi] = -1; continue; }
            int cur = 0, nd = 0;
            for (int b = B - 1; b >= 0; b--)
            {
                int bit = (x >> b) & 1;
                int want = nxt[nd * 2 + (bit ^ 1)];
                if (want != 0) { cur |= 1 << b; nd = want; }
                else nd = nxt[nd * 2 + bit];
            }
            ans[qi] = cur;
        }
        return ans;
    }
}

O((n + q) · B) after sorting. The online alternative stores at each node the minimum number in its subtree; during the walk, a child is usable only if its minimum is ≤ m. Both are accepted; the offline one is easier to get right.

7. Stream of Characters (Hard)

LeetCode 1032. Letters arrive one at a time. After each, report whether any word from a fixed list is a suffix of the letters received so far.

Insight. Words end at the newest letter, so read the stream backwards from the newest letter and match against the words reversed. Build a trie of reversed words; on each query, walk it from the newest letter backwards and stop at the first end mark (true) or when the walk falls off (false). Only the last maxLen letters can matter, so the history can be capped.

Solution: reversed-word trie, backward walk over the stream 
from collections import deque


class StreamChecker:
    def __init__(self, words):
        self.root = {}
        for w in words:
            node = self.root
            for ch in reversed(w):
                node = node.setdefault(ch, {})
            node["$"] = True
        self.max_len = max(map(len, words))
        self.recent = deque()                  # newest letter first

    def query(self, letter):
        self.recent.appendleft(letter)
        if len(self.recent) > self.max_len:
            self.recent.pop()
        node = self.root
        for ch in self.recent:
            node = node.get(ch)
            if node is None:
                return False
            if "$" in node:
                return True
        return False

public class StreamChecker
{
    private class Node { public Node[] Next = new Node[26]; public bool End; }
    private readonly Node root = new Node();
    private readonly List<char> stream = new();
    private readonly int maxLen;

    public StreamChecker(string[] words)
    {
        foreach (var w in words)
        {
            var node = root;
            for (int i = w.Length - 1; i >= 0; i--) node = node.Next[w[i] - 'a'] ??= new Node();
            node.End = true;
            maxLen = Math.Max(maxLen, w.Length);
        }
    }

    public bool Query(char letter)
    {
        stream.Add(letter);
        var node = root;
        for (int i = stream.Count - 1; i >= 0 && i >= stream.Count - maxLen; i--)
        {
            node = node.Next[stream[i] - 'a'];
            if (node == null) return false;
            if (node.End) return true;
        }
        return false;
    }
}

Each query costs O(maxLen) in the worst case, usually much less because the walk falls off early. The C# version keeps the whole stream for simplicity (40 000 queries at most); cap it with a circular buffer in production.

8. Prefix and Suffix Search (Hard)

LeetCode 745. WordFilter(words) then f(pref, suff): the largest index of a word with that prefix and that suffix, or -1.

Insight. Make one key out of both conditions, as in the figure above. For each word w and each split, insert suffix + '{' + w; query with suff + '{' + pref. A word has the prefix and the suffix exactly when that query string is a prefix of one of its keys. Store at each node the largest index that passed through it; since words are inserted in index order, simply overwriting keeps the maximum. '{' is the character right after 'z', so the C# children array only needs 27 slots.

Solution: suffix{word keys in one trie 
class WordFilter:
    def __init__(self, words):
        self.root = {}
        for weight, w in enumerate(words):
            for i in range(len(w) + 1):
                node = self.root
                for ch in w[i:] + "{" + w:
                    node = node.setdefault(ch, {})
                    node["#"] = weight         # later words overwrite: max index
        # '#' never appears as a letter or as the separator, so it is a safe slot name

    def f(self, pref, suff):
        node = self.root
        for ch in suff + "{" + pref:
            node = node.get(ch)
            if node is None:
                return -1
        return node["#"]

public class WordFilter
{
    private class Node { public Node[] Next = new Node[27]; public int Weight; }
    private readonly Node root = new Node();

    public WordFilter(string[] words)
    {
        for (int weight = 0; weight < words.Length; weight++)
        {
            string w = words[weight];
            for (int i = 0; i <= w.Length; i++)
            {
                var node = root;
                foreach (char ch in w.Substring(i) + "{" + w)
                {
                    node = node.Next[ch - 'a'] ??= new Node();
                    node.Weight = weight;
                }
            }
        }
    }

    public int F(string pref, string suff)
    {
        var node = root;
        foreach (char ch in suff + "{" + pref)
        {
            node = node.Next[ch - 'a'];
            if (node == null) return -1;
        }
        return node.Weight;
    }
}

Construction is O(Σ L²) letters (L ≤ 7 on LeetCode, so tiny); each query is O(|pref| + |suff|). The alternative is two tries (prefix and reversed suffix) returning index lists and intersecting them from the largest index down, which uses less memory but makes queries slower.

9. Concatenated Words (Hard)

LeetCode 472. Return every word that is the concatenation of at least two shorter words from the same list.

Insight. This is word break (DP: Linear & Grid) run for every word, with the trie as the dictionary. Process words from shortest to longest, so when checking w the trie holds only shorter words (and a single piece can never be w itself). For the DP, ok[i] means "w[:i] splits into dictionary words"; from every reachable i, walk the trie along w[i:] and mark ok[j + 1] at every end mark. One walk from i finds all words starting there, instead of hashing every substring.

Solution: shortest first, word-break DP with trie walks 
def find_all_concatenated_words(words):
    root = {}

    def insert(w):
        node = root
        for ch in w:
            node = node.setdefault(ch, {})
        node["$"] = True

    def can_form(w):
        n = len(w)
        ok = [False] * (n + 1)
        ok[0] = True
        for i in range(n):
            if not ok[i]:
                continue
            node = root
            for j in range(i, n):
                node = node.get(w[j])
                if node is None:
                    break
                if "$" in node:
                    ok[j + 1] = True       # w[i..j] is a word: w[:j+1] is splittable
        return ok[n]

    out = []
    for w in sorted(words, key=len):
        if not w:
            continue
        if can_form(w):
            out.append(w)
        insert(w)
    return out

public static class ConcatenatedWords
{
    private class Node { public Node[] Next = new Node[26]; public bool End; }

    public static IList<string> FindAllConcatenatedWordsInADict(string[] words)
    {
        var root = new Node();
        var res = new List<string>();
        foreach (var w in words.OrderBy(s => s.Length))
        {
            if (w.Length == 0) continue;
            var ok = new bool[w.Length + 1];
            ok[0] = true;
            for (int i = 0; i < w.Length; i++)
            {
                if (!ok[i]) continue;
                var node = root;
                for (int j = i; j < w.Length; j++)
                {
                    node = node.Next[w[j] - 'a'];
                    if (node == null) break;
                    if (node.End) ok[j + 1] = true;
                }
            }
            if (ok[w.Length]) res.Add(w);
            var t = root;
            foreach (char ch in w) t = t.Next[ch - 'a'] ??= new Node();
            t.End = true;
        }
        return res;
    }
}

O(Σ L²) in the worst case. A concatenated word does not even need to be inserted: anything built with it can be built from its pieces. Skipping that insert is a valid optimisation that keeps the trie smaller.

Self-check

Insert "a", "ab", "abc", "abd", "b". How many nodes are there below the root, and what are the pass counts?

Five nodes: a, ab, abc, abd and b. Pass counts: a = 4 (a, ab, abc, abd), ab = 3, abc = 1, abd = 1, b = 1; the root has 5. End marks on all five, because every node here is also a word. Words that are prefixes of other words never add nodes, only end marks.

After inserting "apple" and then lazily deleting it (only clearing the end mark), what do search("apple") and startsWith("app") return? What would the count-based erase return?

Lazy delete: search("apple") is False (no end mark), but startsWith("app") is still True because the nodes are still there. That is a bug if the problem asks about prefixes of stored words. With the count-based erase, every pass count on the path drops to 0, the branch below the root is cut at "a", and startsWith("app") is False.

Why can the maximum-XOR walk be greedy, with no backtracking?

Bit b is worth 2^b, and all lower bits together are worth at most 2^b − 1. If some stored number gives a 1 at the current highest undecided bit, every number that gives 0 there loses, whatever its lower bits are. So the choice at each bit is forced and the walk is a single path of B steps. The walk never falls off because every number was inserted with the full B bits.

Word Search II: why store the full word at its end node, and why delete it after reporting?

Storing the word avoids building a string along every DFS path (which costs O(L) per step and creates garbage). Removing it after the first report prevents duplicates when the same word can be traced along two paths, without needing a result set. It also makes leaf pruning possible: a node with no word and no children is dead and can be removed so later DFS calls stop earlier.

A dictionary of 10⁵ words is fixed, and you get 10⁵ queries "how many words start with p?". Name a solution without a trie.

Sort the words. Words starting with p form one contiguous block in sorted order: from bisect_left(words, p) up to bisect_left(words, p + '{') (the character after 'z'). Each query is two binary searches, O(|p| log n). The trie is O(|p|) per query and also supports inserts; the sorted array is less code when the data does not change.

In the stream problem, why insert the words reversed instead of keeping a set of "active" forward trie nodes?

The forward approach works: keep the list of trie nodes reached by every suffix of the stream that is still a prefix of some word, advance all of them on each letter, and add the root. But that list can hold up to maxLen nodes, so each letter costs O(maxLen) plus list management. The reversed trie needs no state besides the last maxLen letters and stops at the first match. Aho-Corasick removes the O(maxLen) factor by precomputing where each active state should fall back to.
