ARRAYS & STRINGS

Sliding Window

Fixed and variable windows, the expand/shrink invariant, counting 'at most K' tricks, and monotonic-deque windows.

Beginner → Advanced~55 min studyBuilds on: Two PointersUpdated 2026-11-03

What it is and when you need it

A window is a contiguous stretch a[l..r] of an array or string. An array of length n has n(n+1)/2 of them, so "check every subarray" costs O(n²) windows, and often O(n³) with the check. A sliding window visits them in O(n): both edges move only to the right, and the window's state (a sum, a count map, a deque) is updated by one element at a time instead of being recomputed.

The invariant. Keep a[l..r] valid. Advance r to take one element in. Advance l only to restore validity (or to keep a fixed length). This is correct exactly when validity is monotone: every sub-window of a valid window is valid, so a start that fails for r also fails for every later r.

A sliding window is the "same direction" family of Two Pointers, specialised to contiguous ranges. The two-pointers page proves that discarding is safe in a pair matrix. Here the matrix is a triangle of windows, and the proof is the monotonicity above.

Brute force: O(n²) windows

Enumerate every (l, r) and evaluate it. Even with a running total per l, that is O(n²). It works for any condition, which is its only advantage.

Prefix sums: O(n), any sign

sum(a[l..r]) = P[r+1] − P[l] plus a hashmap answers "sum equals k" even with negative numbers. It only handles sums, and it costs O(n) space. See Prefix Sums.

Sliding window: O(n), O(state)

It handles any condition that is monotone and can be updated incrementally: sums of non-negatives, distinct counts, character quotas, "at most k bad elements", window max and min (with a deque).

Intuition: a staircase through the triangle of windows

Draw every window as a cell (l, r) with l ≤ r. Fix the right end r (a column) and ask which starts l give a valid window. For "no repeated character" the answer is always one contiguous block at the bottom of the column, and the top of that block only ever moves down as r grows. The algorithm just walks along that boundary.

Three facts make this work, and every sliding-window problem must have all three. If any is missing, use the alternatives in When windows do NOT work.

  1. Contiguity. The answer is a subarray or substring, not a subsequence.
  2. Monotone validity. Shrinking a valid window keeps it valid. Equivalently, growing an invalid window keeps it invalid, so l never has to move back.
  3. Incremental state. Adding a[r] and removing a[l] each update the state in O(1) (amortised): a running sum, a count map with a "how many are satisfied" counter, or a monotonic deque.

The two generic templates

Every window problem is one of two loops. In the fixed loop the length is given, so l = r − k + 1 is forced. In the variable loop, l moves only when the invariant demands it. The only thing that changes between "longest" and "shortest" is where you record the answer.

from typing import Callable, Sequence, TypeVar

T = TypeVar("T")


def fixed_window(a: Sequence[T], k: int, add: Callable[[T], None],
                 remove: Callable[[T], None], record: Callable[[int, int], None]) -> None:
    for r in range(len(a)):
        add(a[r])                    # a[r] enters
        if r >= k:
            remove(a[r - k])         # a[r - k] leaves: the window is a[r-k+1 .. r]
        if r >= k - 1:
            record(r - k + 1, r)     # the window is full: evaluate it


def longest_window(a: Sequence[T], add: Callable[[T], None], remove: Callable[[T], None],
                   invalid: Callable[[], bool], record: Callable[[int, int], None]) -> None:
    l = 0
    for r in range(len(a)):
        add(a[r])                    # 1. expand
        while invalid():             # 2. shrink until valid again
            remove(a[l])
            l += 1
        record(l, r)                 # 3. [l..r] is the LONGEST valid window ending at r


def shortest_window(a: Sequence[T], add: Callable[[T], None], remove: Callable[[T], None],
                    valid: Callable[[], bool], record: Callable[[int, int], None]) -> None:
    l = 0
    for r in range(len(a)):
        add(a[r])                    # 1. expand
        while valid():               # 2. while valid ...
            record(l, r)             #    ... record it, then try a shorter one
            remove(a[l])
            l += 1


# Example: the longest substring with at most 2 distinct characters.
def longest_two_distinct(s: str) -> int:
    cnt: dict[str, int] = {}
    best = 0

    def add(c: str) -> None:
        cnt[c] = cnt.get(c, 0) + 1

    def remove(c: str) -> None:
        cnt[c] -= 1
        if cnt[c] == 0:
            del cnt[c]               # keep len(cnt) == number of distinct chars

    def record(l: int, r: int) -> None:
        nonlocal best
        best = max(best, r - l + 1)

    longest_window(s, add, remove, lambda: len(cnt) > 2, record)
    return best

public static void FixedWindow<T>(IReadOnlyList<T> a, int k, Action<T> add, Action<T> remove,
                                  Action<int, int> record)
{
    for (int r = 0; r < a.Count; r++)
    {
        add(a[r]);                              // a[r] enters
        if (r >= k) remove(a[r - k]);           // a[r - k] leaves
        if (r >= k - 1) record(r - k + 1, r);   // the window is full
    }
}

public static void LongestWindow<T>(IReadOnlyList<T> a, Action<T> add, Action<T> remove,
                                    Func<bool> invalid, Action<int, int> record)
{
    int l = 0;
    for (int r = 0; r < a.Count; r++)
    {
        add(a[r]);
        while (invalid()) remove(a[l++]);
        record(l, r);                           // longest valid window ending at r
    }
}

public static void ShortestWindow<T>(IReadOnlyList<T> a, Action<T> add, Action<T> remove,
                                     Func<bool> valid, Action<int, int> record)
{
    int l = 0;
    for (int r = 0; r < a.Count; r++)
    {
        add(a[r]);
        while (valid())
        {
            record(l, r);                       // valid: record, then try shorter
            remove(a[l++]);
        }
    }
}

// Example: the longest substring with at most 2 distinct characters.
public static int LongestTwoDistinct(string s)
{
    var cnt = new Dictionary<char, int>();
    int best = 0;
    LongestWindow(s.ToCharArray(),
        c => cnt[c] = cnt.GetValueOrDefault(c) + 1,
        c => { if (--cnt[c] == 0) cnt.Remove(c); },
        () => cnt.Count > 2,
        (l, r) => best = Math.Max(best, r - l + 1));
    return best;
}

Each element is added once and removed at most once, so all three loops run in O(n) calls to add/remove, plus whatever invalid()/valid() costs. Make that test O(1) by maintaining a counter (such as len(cnt), have == req, or a running sum) rather than rescanning the state.

Fixed-size windows

When the length is fixed at k, consecutive windows overlap in k − 1 elements. Recomputing each window from scratch wastes all of that overlap.

def max_sum_k(a: list[int], k: int) -> int:
    s = sum(a[:k])                   # the first window, paid once
    best = s
    for r in range(k, len(a)):
        s += a[r] - a[r - k]         # one value in, one value out
        best = max(best, s)
    return best

public static long MaxSumK(int[] a, int k)
{
    long s = 0;
    for (int i = 0; i < k; i++) s += a[i];      // the first window, paid once
    long best = s;
    for (int r = k; r < a.Length; r++)
    {
        s += a[r] - a[r - k];                   // one value in, one value out
        best = Math.Max(best, s);
    }
    return best;
}

O(n) time and O(1) space. The same skeleton handles "every window of length |p| that is an anagram of p" (keep 26 counts, see Find All Anagrams), "max distinct-sum window of length k" (a sum and a count map), and "does any window of length k + 1 contain a duplicate" (a set). A fixed window needs no monotonicity, because l is never chosen; it is forced.

Turn "remove k from the ends" into "keep a window of n − k". Maximum Points You Can Obtain from Cards takes k cards from the two ends. Whatever is left is a contiguous window of length n − k. Minimise that window's sum with the fixed template, or equivalently slide a window of length k across the wrap-around point.

Variable windows: expand, shrink, record

Now l is free, and the invariant decides it. Each step has three moves, always in this order:

1 · EXPANDtake a[r]

Update the state with the new element. The window may now break the invariant.

2 · SHRINKwhile broken: drop a[l]

Move l right only as far as needed. Starts left of l are dead for every later r too.

3 · RECORD[l..r] is valid

For "longest", this window is the best one ending at r. Record it after the shrink loop.

Longest valid window

Step through the canonical example: the longest substring without repeating characters. Watch the green invariant panel turn red the moment a duplicate enters, and watch l stop moving when it turns green again. That is the whole algorithm.

def longest_no_repeat(s: str) -> int:
    count: dict[str, int] = {}
    l = best = 0
    for r, ch in enumerate(s):
        count[ch] = count.get(ch, 0) + 1     # 1. expand
        while count[ch] > 1:                 # 2. only ch can be duplicated: shrink
            count[s[l]] -= 1
            l += 1
        best = max(best, r - l + 1)          # 3. record: [l..r] is valid
    return best

public static int LongestNoRepeat(string s)
{
    var count = new Dictionary<char, int>();
    int l = 0, best = 0;
    for (int r = 0; r < s.Length; r++)
    {
        char ch = s[r];
        count[ch] = count.GetValueOrDefault(ch) + 1;    // 1. expand
        while (count[ch] > 1)                           // 2. shrink while broken
        {
            count[s[l]]--;
            l++;
        }
        best = Math.Max(best, r - l + 1);               // 3. record
    }
    return best;
}

O(n) time, O(σ) space for an alphabet of size σ. The shrink test count[ch] > 1 only checks the character that just entered. Before step 1 the window was valid, so the only possible duplicate is ch. Small observations like this keep the validity test O(1).

Shortest valid window

Flip the goal: find the shortest window that satisfies a condition, such as "sum ≥ target" or "contains every character of t". Validity is still monotone, but in the other direction: growing a valid window keeps it valid. So expand until valid, then shrink while still valid, recording at every step. The best window ending at r is the last valid one before the window breaks.

Longest: record after the loop

while invalid: shrink then best = max(best, r − l + 1). The window you record is valid and as long as possible.

Shortest: record inside the loop

while valid: best = min(best, r − l + 1); shrink. Each window you record is valid. Once the loop exits, the window is invalid and must not be recorded.

import math


def min_subarray_len(target: int, nums: list[int]) -> int:
    """Shortest subarray with sum >= target. Requires nums[i] >= 0."""
    l = s = 0
    best = math.inf
    for r, x in enumerate(nums):
        s += x                               # 1. expand
        while s >= target:                   # 2. while valid ...
            best = min(best, r - l + 1)      #    record first
            s -= nums[l]                     #    then try a shorter one
            l += 1
    return 0 if best == math.inf else best

public static int MinSubArrayLen(int target, int[] nums)
{
    int l = 0, best = int.MaxValue;
    long s = 0;
    for (int r = 0; r < nums.Length; r++)
    {
        s += nums[r];
        while (s >= target)
        {
            best = Math.Min(best, r - l + 1);
            s -= nums[l++];
        }
    }
    return best == int.MaxValue ? 0 : best;
}

When validity means "contains a multiset", as in minimum window substring, comparing two count maps on every step would cost O(σ). Instead, keep need[c] (the counts of t) and one integer: have, the number of distinct characters whose quota is met. have changes only when a count crosses its quota, which is an O(1) check on each add or remove. The window is valid exactly when have == req.

Watch two details in the visualizer. First, have goes up only when win[c] reaches need[c] exactly; surplus copies change nothing. Second, have goes down only when win[c] drops below need[c], which is the step that ends the shrink loop. The full solution is worked problem 4.

Counting windows

"How many subarrays satisfy X?" Recording one window per r is not enough here. Every valid window must be counted, and there can be O(n²) of them, so you need to count many windows per step.

At most K: every window that ends at r counts

If [l..r] is the longest valid window ending at r, monotonicity says that every window [i..r] with l ≤ i ≤ r is valid too. That is r − l + 1 windows, all counted with a single addition.

def num_subarray_product_less_than_k(nums: list[int], k: int) -> int:
    """Count subarrays with product < k. nums[i] >= 1."""
    if k <= 1:
        return 0                             # no product of positive integers is < 1
    prod, l, count = 1, 0, 0
    for r, x in enumerate(nums):
        prod *= x
        while prod >= k:
            prod //= nums[l]
            l += 1
        count += r - l + 1                   # all of [l..r], [l+1..r], ..., [r..r]
    return count

public static long NumSubarrayProductLessThanK(int[] nums, int k)
{
    if (k <= 1) return 0;
    long prod = 1, count = 0;
    int l = 0;
    for (int r = 0; r < nums.Length; r++)
    {
        prod *= nums[r];
        while (prod >= k) prod /= nums[l++];
        count += r - l + 1;
    }
    return count;
}

The k <= 1 guard is not optional. Without it, prod >= k stays true even for the empty window. l runs past r, and the code divides by elements outside the window.

Exactly K = atMost(K) − atMost(K − 1)

"Count subarrays with exactly K distinct values" breaks the shrink rule. A window with K distinct values can lose a value and drop to K − 1 (too few), or keep K. No single l describes "all the good starts", because the good starts are a band with two moving edges. Each edge, though, is the left edge of an "at most" window, and "at most" is monotone.

The visualizer runs both "at most" counters together with one shared r. Its bottom row shows the distinct count of every window ending at r, so you can see the bands directly. That row is for illustration only; the algorithm never computes it.

def subarrays_with_k_distinct(nums: list[int], k: int) -> int:
    def at_most(k: int) -> int:
        cnt: dict[int, int] = {}
        l = total = 0
        for r, x in enumerate(nums):
            cnt[x] = cnt.get(x, 0) + 1
            while len(cnt) > k:
                cnt[nums[l]] -= 1
                if cnt[nums[l]] == 0:
                    del cnt[nums[l]]         # len(cnt) must count distinct values
                l += 1
            total += r - l + 1
        return total

    return at_most(k) - at_most(k - 1)

public static long SubarraysWithKDistinct(int[] nums, int k)
{
    long AtMost(int kk)
    {
        var cnt = new Dictionary<int, int>();
        long total = 0;
        int l = 0;
        for (int r = 0; r < nums.Length; r++)
        {
            cnt[nums[r]] = cnt.GetValueOrDefault(nums[r]) + 1;
            while (cnt.Count > kk)
            {
                if (--cnt[nums[l]] == 0) cnt.Remove(nums[l]);
                l++;
            }
            total += r - l + 1;
        }
        return total;
    }
    return AtMost(k) - AtMost(k - 1);
}

The same trick counts subarrays with exactly k odd numbers (Count Number of Nice Subarrays), with sum exactly goal in a binary array (Binary Subarrays With Sum), and in general anything of the form "exactly" where "at most" is monotone. For sums of non-negative numbers, atMost(goal) uses while s > goal. For goal = 0, atMost(−1) must return 0; a guard like if goal < 0: return 0 handles it.

Sliding window maximum: the monotonic deque

A sum can be "un-added", but a maximum cannot be "un-maxed": when the current max leaves the window, which value takes over? A heap answers in O(log k) with lazy deletion. A monotonic deque answers in amortised O(1), because most values can be thrown away for good the moment a bigger value arrives.

from collections import deque


def max_sliding_window(nums: list[int], k: int) -> list[int]:
    dq: deque[int] = deque()                 # indices; nums[dq] strictly decreasing
    out: list[int] = []
    for r, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:      # dominated: older and not bigger
            dq.pop()
        dq.append(r)
        if dq[0] <= r - k:                   # the front left the window
            dq.popleft()
        if r >= k - 1:
            out.append(nums[dq[0]])          # front = max of nums[r-k+1 .. r]
    return out

public static int[] MaxSlidingWindow(int[] nums, int k)
{
    var dq = new LinkedList<int>();                     // indices, values decreasing
    var outp = new int[nums.Length - k + 1];
    for (int r = 0; r < nums.Length; r++)
    {
        while (dq.Count > 0 && nums[dq.Last!.Value] <= nums[r]) dq.RemoveLast();
        dq.AddLast(r);
        if (dq.First!.Value <= r - k) dq.RemoveFirst(); // expired
        if (r >= k - 1) outp[r - k + 1] = nums[dq.First.Value];
    }
    return outp;
}

Each index is pushed once and popped at most once, so the total is O(n) and the extra space is O(k). For the minimum, flip the comparison to >=. To keep both, maintain two deques. That is how Longest Continuous Subarray With Absolute Diff ≤ Limit combines a variable window with "max − min" (worked problem 6). The general structure lives in Monotonic Stack & Queue.

When windows do NOT work

The window's shrink rule is a proof: "the sum is too big, so every window starting at l is too big". With negative numbers the proof is false, because a later negative value can pull the sum back down.

The visualizer runs the naive window on mixed-sign input for "count subarrays with sum = k", compares its count with brute force, and then solves the same input with prefix sums and a hashmap. Press Randomize a few times to see how often the naive window is wrong.

def subarray_sum(nums: list[int], k: int) -> int:
    """Count subarrays with sum == k. Any signs. O(n) time, O(n) space."""
    seen = {0: 1}                            # prefix value -> how many times seen
    p = count = 0
    for x in nums:
        p += x
        count += seen.get(p - k, 0)          # earlier prefixes P[i] with P[r+1] - P[i] == k
        seen[p] = seen.get(p, 0) + 1
    return count

public static int SubarraySum(int[] nums, int k)
{
    var seen = new Dictionary<long, int> { [0] = 1 };
    long p = 0;
    int count = 0;
    foreach (int x in nums)
    {
        p += x;
        count += seen.GetValueOrDefault(p - k);
        seen[p] = seen.GetValueOrDefault(p) + 1;
    }
    return count;
}

The full list of situations where a window is the wrong tool:

  • Negative numbers with a sum condition. For "sum = k", use prefix sums with a hashmap (above). For "shortest subarray with sum ≥ k", use prefix sums with a monotonic deque (worked problem 8). For "maximum subarray sum", use Kadane or prefix minima.
  • Exactly-K conditions. These are not monotone directly. Use atMost(K) − atMost(K − 1), or count with two left edges.
  • Subsequences. The answer is not contiguous, so there is no window. Use DP, or sort and use Two Pointers.
  • Non-invertible state without a deque structure. Examples are the median of each window (use two heaps with lazy deletion, or a sorted list), or the k-th largest. The window still slides, but the state needs a richer structure: O(n log k).
  • Validity that depends on the whole array. For example, "the subarray's sum is the largest of all subarrays" is a global property, not a window property.

Decision chart

Templates at a glance

Kind Move l when Record / count Typical state Time · space
Fixed length k always, once r ≥ k (l = r − k + 1) when r ≥ k − 1 sum, 26 counts + matches O(n) · O(1) or O(σ)
Longest valid while invalid after the loop: max(best, r − l + 1) count map + distinct, sum O(n) · O(σ)
Shortest valid while valid inside the loop, before shrinking sum, need/have O(n) · O(σ)
Count, at most while invalid count += r − l + 1 count map, product O(n) · O(σ)
Count, exactly K two at-most windows atMost(K) − atMost(K − 1) two count maps O(n) · O(σ)
Window max / min expiry from the front a[dq[0]] once r ≥ k − 1 deque of indices O(n) · O(k)
Sum = k with negatives not a window count += seen[P − k] prefix hashmap O(n) · O(n)

Recognize it when

  • The question asks for a contiguous subarray or substring: the longest, the shortest, the count, or every window of length k.
  • The condition is "at most k" of something (distinct values, zeros to flip, replacements, odd numbers), or a sum or product bound with non-negative values.
  • A brute force has an inner loop for j in range(i, n) that you could stop early, and the start i that works never moves backward as j grows.
  • The phrase "exactly K" next to a monotone "at most" condition: subtract two counts.
  • "Maximum / minimum of every window of size k", or "max − min ≤ limit": a monotonic deque.
  • Values can be negative and the condition is a sum: stop, and reach for prefix sums.

Pitfalls

Pitfall: if instead of while when shrinking One step left may not be enough. In "longest without repeats" on "abcdbe", the second b requires dropping both a and the first b. With if, only a is dropped, the invalid window "bcdb" survives, and the code reports 5 for "bcdbe", which contains two bs. The correct answer is 4 ("cdbe"). Always shrink with while. (Longest Repeating Character Replacement is the one deliberate exception; see worked problem 2.)

Pitfall: recording in the wrong place For "shortest", recording after the loop records an invalid window: the loop exits precisely when the window broke. With target 7 and [2, 3, 1, 2, 4, 3], that version reports length 1. For "longest", recording inside a while invalid loop records broken windows. The rule: record only windows you know are valid.

Pitfall: zero counts left in the map len(cnt) is supposed to be the number of distinct values, but cnt[x] -= 1 leaves x: 0 behind. The map then claims [1, 2] has 3 distinct values once a 3 has passed through. Delete keys that reach 0, or keep a separate distinct counter that you update when a count goes 0 → 1 or 1 → 0.

Pitfall: sliding over negative numbers while s > k: shrink is only sound when every value is ≥ 0. On [5, −4, 2] with k = 3 it drops the 5 immediately and never finds [5, −4, 2]. If the constraints allow negatives, switch to prefix sums. Check this before writing any code.

Pitfall: storing values instead of indices in the deque To expire the front you must know whether it is still inside [r − k + 1, r]. With values only, [3, 3, 1] and k = 2 cannot tell which 3 left. Store indices. (The values-only variant works only if you pop with strict <, so duplicates stay in the deque, and expire with if dq[0] == nums[r − k].)

Pitfall: fixed-window off-by-one Record when r >= k − 1 (the window a[r−k+1..r] is full), and remove a[r − k] when r >= k. Recording at r >= k silently skips the first window; with k = len(a), it returns nothing at all.

Worked problems

1. Longest Substring Without Repeating Characters

Insight: the count-map version above shrinks one step at a time. If you store each character's last index instead, l can jump straight past the earlier copy. The check last[ch] >= l matters: an old copy to the left of the window is not a duplicate. Without it, "abba" would move l backwards when the final a arrives.

Solution: O(n) time, O(σ) space 
def length_of_longest_substring(s: str) -> int:
    last: dict[str, int] = {}
    l = best = 0
    for r, ch in enumerate(s):
        if last.get(ch, -1) >= l:            # earlier copy is inside the window
            l = last[ch] + 1                 # jump past it
        last[ch] = r
        best = max(best, r - l + 1)
    return best

public static int LengthOfLongestSubstring(string s)
{
    var last = new Dictionary<char, int>();
    int l = 0, best = 0;
    for (int r = 0; r < s.Length; r++)
    {
        if (last.TryGetValue(s[r], out int p) && p >= l) l = p + 1;
        last[s[r]] = r;
        best = Math.Max(best, r - l + 1);
    }
    return best;
}

2. Longest Repeating Character Replacement

Replace at most k characters to get the longest run of one letter. Insight: a window is valid when length − maxFreq ≤ k, where maxFreq is the count of its most common letter. Recomputing the true maxFreq after each shrink would be correct but is unnecessary. Only a larger maxFreq can produce a longer answer, so the window never needs to shrink: when it is invalid, slide it one step (drop one on the left, as the new one entered on the right). A stale maxFreq only keeps the size where it is, and the size grows only when a genuinely higher frequency appears. At the end, the window size n − l is the answer.

Solution: O(n) time, O(26) space 
def character_replacement(s: str, k: int) -> int:
    count = [0] * 26
    l = max_f = 0
    for r, ch in enumerate(s):
        i = ord(ch) - ord("A")
        count[i] += 1
        max_f = max(max_f, count[i])         # may be stale later: that is fine
        if r - l + 1 - max_f > k:            # `if`, not `while`: slide, never shrink
            count[ord(s[l]) - ord("A")] -= 1
            l += 1
    return len(s) - l                        # the window only ever grew

public static int CharacterReplacement(string s, int k)
{
    var count = new int[26];
    int l = 0, maxF = 0;
    for (int r = 0; r < s.Length; r++)
    {
        maxF = Math.Max(maxF, ++count[s[r] - 'A']);
        if (r - l + 1 - maxF > k)
        {
            count[s[l] - 'A']--;
            l++;
        }
    }
    return s.Length - l;
}

3. Find All Anagrams in a String

Return every start index where a window of s is a permutation of p. Insight: this is a fixed window of length |p|. Comparing two 26-count arrays on each step costs O(26). Keep diff[c] = need[c] − window[c] and an integer bad, the number of letters whose diff is not 0. Each add or remove changes one diff entry, which can change bad by at most one. The window is an anagram exactly when bad == 0. Permutation in String is the same code returning a boolean.

Solution: O(n) time, O(26) space 
def find_anagrams(s: str, p: str) -> list[int]:
    k = len(p)
    diff = [0] * 26                          # need - window, per letter
    for ch in p:
        diff[ord(ch) - 97] += 1
    bad = sum(d != 0 for d in diff)
    out: list[int] = []

    def change(ch: str, delta: int) -> None:
        nonlocal bad
        i = ord(ch) - 97
        if diff[i] == 0:
            bad += 1                         # was balanced, now is not
        diff[i] += delta
        if diff[i] == 0:
            bad -= 1                         # became balanced

    for r, ch in enumerate(s):
        change(ch, -1)                       # enters the window
        if r >= k:
            change(s[r - k], +1)             # leaves the window
        if r >= k - 1 and bad == 0:
            out.append(r - k + 1)
    return out

public static IList<int> FindAnagrams(string s, string p)
{
    int k = p.Length;
    var diff = new int[26];
    foreach (char c in p) diff[c - 'a']++;
    int bad = 0;
    foreach (int d in diff) if (d != 0) bad++;
    var outp = new List<int>();

    void Change(char c, int delta)
    {
        int i = c - 'a';
        if (diff[i] == 0) bad++;
        diff[i] += delta;
        if (diff[i] == 0) bad--;
    }

    for (int r = 0; r < s.Length; r++)
    {
        Change(s[r], -1);
        if (r >= k) Change(s[r - k], +1);
        if (r >= k - 1 && bad == 0) outp.Add(r - k + 1);
    }
    return outp;
}

4. Minimum Window Substring

The shortest substring of s that contains every character of t, duplicates included. Insight: this is a shortest valid window with the need/have counter from the visualizer. Record inside while have == req. Store (length, start) instead of slicing on every improvement, so the loop stays O(1) per step.

Solution: O(|s| + |t|) time, O(σ) space 
from collections import Counter


def min_window(s: str, t: str) -> str:
    need = Counter(t)
    req, have = len(need), 0                 # distinct chars needed / satisfied
    win: dict[str, int] = {}
    best_len, best_l = len(s) + 1, 0
    l = 0
    for r, ch in enumerate(s):
        if ch in need:
            win[ch] = win.get(ch, 0) + 1
            if win[ch] == need[ch]:          # just reached its quota
                have += 1
        while have == req:                   # valid: record, then shrink
            if r - l + 1 < best_len:
                best_len, best_l = r - l + 1, l
            c = s[l]
            if c in need:
                win[c] -= 1
                if win[c] < need[c]:         # just fell below its quota
                    have -= 1
            l += 1
    return "" if best_len > len(s) else s[best_l:best_l + best_len]

public static string MinWindow(string s, string t)
{
    var need = new Dictionary<char, int>();
    foreach (char c in t) need[c] = need.GetValueOrDefault(c) + 1;
    var win = new Dictionary<char, int>();
    int req = need.Count, have = 0, l = 0;
    int bestLen = s.Length + 1, bestL = 0;
    for (int r = 0; r < s.Length; r++)
    {
        char ch = s[r];
        if (need.TryGetValue(ch, out int q))
        {
            win[ch] = win.GetValueOrDefault(ch) + 1;
            if (win[ch] == q) have++;
        }
        while (have == req)
        {
            if (r - l + 1 < bestLen) { bestLen = r - l + 1; bestL = l; }
            char c = s[l++];
            if (need.TryGetValue(c, out int qc) && --win[c] < qc) have--;
        }
    }
    return bestLen > s.Length ? "" : s.Substring(bestL, bestLen);
}

5. Subarrays with K Different Integers

Count subarrays with exactly k distinct values. Insight: the section above computes atMost(k) − atMost(k − 1) in two passes. The same idea fits in one pass with two left edges sharing r. l1 is the left edge of the "at most k" window, and l2 is the left edge of the "at most k − 1" window. The starts in [l1, l2) have exactly k distinct values, so add l2 − l1. This is exactly what the visualizer draws.

Solution: O(n) time, O(n) space 
def subarrays_with_k_distinct_one_pass(nums: list[int], k: int) -> int:
    c1: dict[int, int] = {}                  # window [l1..r]: at most k distinct
    c2: dict[int, int] = {}                  # window [l2..r]: at most k - 1 distinct
    l1 = l2 = total = 0

    def drop(c: dict[int, int], x: int) -> None:
        c[x] -= 1
        if c[x] == 0:
            del c[x]

    for x in nums:
        c1[x] = c1.get(x, 0) + 1
        c2[x] = c2.get(x, 0) + 1
        while len(c1) > k:
            drop(c1, nums[l1])
            l1 += 1
        while len(c2) > k - 1:
            drop(c2, nums[l2])
            l2 += 1
        total += l2 - l1                     # starts with exactly k distinct
    return total

public static long SubarraysWithKDistinctOnePass(int[] nums, int k)
{
    var c1 = new Dictionary<int, int>();
    var c2 = new Dictionary<int, int>();
    int l1 = 0, l2 = 0;
    long total = 0;

    static void Drop(Dictionary<int, int> c, int x)
    {
        if (--c[x] == 0) c.Remove(x);
    }

    foreach (int x in nums)
    {
        c1[x] = c1.GetValueOrDefault(x) + 1;
        c2[x] = c2.GetValueOrDefault(x) + 1;
        while (c1.Count > k) Drop(c1, nums[l1++]);
        while (c2.Count > k - 1) Drop(c2, nums[l2++]);
        total += l2 - l1;
    }
    return total;
}

6. Longest Continuous Subarray With Absolute Diff ≤ Limit

The longest subarray whose max − min ≤ limit. Insight: validity is monotone, because shrinking a window can only lower its max and raise its min. So this is a longest-valid window. The state needs the window's max and min under removals from the left, which is exactly what two monotonic deques provide. When the window is invalid, advance l and expire any deque front that fell out.

Solution: O(n) time, O(n) space 
from collections import deque


def longest_subarray(nums: list[int], limit: int) -> int:
    mx: deque[int] = deque()                 # indices, values decreasing
    mn: deque[int] = deque()                 # indices, values increasing
    l = best = 0
    for r, x in enumerate(nums):
        while mx and nums[mx[-1]] <= x:
            mx.pop()
        mx.append(r)
        while mn and nums[mn[-1]] >= x:
            mn.pop()
        mn.append(r)
        while nums[mx[0]] - nums[mn[0]] > limit:
            l += 1
            if mx[0] < l:
                mx.popleft()
            if mn[0] < l:
                mn.popleft()
        best = max(best, r - l + 1)
    return best

public static int LongestSubarray(int[] nums, int limit)
{
    var mx = new LinkedList<int>();
    var mn = new LinkedList<int>();
    int l = 0, best = 0;
    for (int r = 0; r < nums.Length; r++)
    {
        while (mx.Count > 0 && nums[mx.Last!.Value] <= nums[r]) mx.RemoveLast();
        mx.AddLast(r);
        while (mn.Count > 0 && nums[mn.Last!.Value] >= nums[r]) mn.RemoveLast();
        mn.AddLast(r);
        while (nums[mx.First!.Value] - nums[mn.First!.Value] > limit)
        {
            l++;
            if (mx.First.Value < l) mx.RemoveFirst();
            if (mn.First.Value < l) mn.RemoveFirst();
        }
        best = Math.Max(best, r - l + 1);
    }
    return best;
}

7. Count Subarrays With Fixed Bounds

Count subarrays whose minimum is exactly minK and whose maximum is exactly maxK. Insight: this is a counting window in which the "left edges" are just remembered indices. For each r, a start i works when no out-of-range value lies in [i..r] (so i > bad) and the window contains both a minK and a maxK (so i ≤ min(lastMin, lastMax)). The good starts form a band, and its size is max(0, min(lastMin, lastMax) − bad).

Solution: O(n) time, O(1) space 
def count_subarrays(nums: list[int], min_k: int, max_k: int) -> int:
    bad = last_min = last_max = -1
    total = 0
    for i, x in enumerate(nums):
        if x < min_k or x > max_k:
            bad = i                          # no window may contain this index
        if x == min_k:
            last_min = i
        if x == max_k:
            last_max = i
        total += max(0, min(last_min, last_max) - bad)
    return total

public static long CountSubarrays(int[] nums, int minK, int maxK)
{
    int bad = -1, lastMin = -1, lastMax = -1;
    long total = 0;
    for (int i = 0; i < nums.Length; i++)
    {
        int x = nums[i];
        if (x < minK || x > maxK) bad = i;
        if (x == minK) lastMin = i;
        if (x == maxK) lastMax = i;
        total += Math.Max(0, Math.Min(lastMin, lastMax) - bad);
    }
    return total;
}

8. Shortest Subarray with Sum at Least K

Like Minimum Size Subarray Sum, but the values may be negative, so a plain window fails. Insight: with prefix sums P, you want the largest i < j with P[j] − P[i] ≥ k. Keep a deque of candidate starts with increasing P. A start i is useless when a later i' has P[i'] ≤ P[i], because i' is closer and gives a bigger sum. Pop from the front while the front works: it has found its best j, since any later j would be farther away.

Solution: O(n) time, O(n) space 
from collections import deque


def shortest_subarray(nums: list[int], k: int) -> int:
    n = len(nums)
    P = [0] * (n + 1)
    for i, x in enumerate(nums):
        P[i + 1] = P[i] + x
    dq: deque[int] = deque()                 # start indices, P increasing
    best = n + 1
    for j in range(n + 1):
        while dq and P[j] - P[dq[0]] >= k:   # front start is done: record it
            best = min(best, j - dq.popleft())
        while dq and P[dq[-1]] >= P[j]:      # j dominates older, higher starts
            dq.pop()
        dq.append(j)
    return best if best <= n else -1

public static int ShortestSubarray(int[] nums, int k)
{
    int n = nums.Length;
    var P = new long[n + 1];
    for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
    var dq = new int[n + 1];                            // array deque: [head, tail)
    int head = 0, tail = 0, best = n + 1;
    for (int j = 0; j <= n; j++)
    {
        while (head < tail && P[j] - P[dq[head]] >= k) best = Math.Min(best, j - dq[head++]);
        while (head < tail && P[dq[tail - 1]] >= P[j]) tail--;
        dq[tail++] = j;
    }
    return best <= n ? best : -1;
}

Self-check

Why is the variable window O(n) even though it has a while loop inside a for loop?

Each iteration of the inner loop moves l right by one, and l never moves left and never passes n. So across the whole run the inner loop executes at most n times in total, not n times per r. Together with the n steps of r, the total work is at most 2n steps.

"Longest subarray with sum ≤ S" on an array that may contain negative numbers. Does the window work?

No. Shrinking assumes that once [l..r] is too big, every window [l..r'] with r' > r is too big as well. A later negative value can bring the sum back under S, so the window may already have dropped the start of the best answer. Use prefix sums. (This specific problem takes O(n log n): binary-search a running maximum of the prefix sums for the earliest start that works.)

For "shortest valid window", why do you record inside the shrink loop and not after it?

The loop is while valid, so it exits exactly when the window has become invalid. A window recorded after the loop is the first invalid one. Inside the loop, each window is still valid, and the last one recorded before exiting is the shortest valid window ending at r.

In "subarray product less than k", why does each step add r − l + 1?

After shrinking, [l..r] is the longest valid window ending at r. Every shorter window ending at r, from [l+1..r] to [r..r], has a smaller product, so it is valid too. That is r − l + 1 windows. Each subarray is counted exactly once, at its right end.

Why can't you count "exactly K distinct" with one window, and how does the subtraction fix it?

For a fixed r, the starts with exactly K distinct values form a band with two moving edges: starts too far left have more than K, and starts too far right have fewer. One l can track only one edge. Each edge, however, is the left edge of a monotone "at most" window: atMost(K) includes the band and everything to its right, atMost(K − 1) includes only what is to its right, and the difference is the band.

In the sliding-window-maximum deque, why can a value be popped forever when a bigger value arrives?

The new value is to the right of it, so it stays in the window at least as long. It is also at least as big. Every future window that contains the old value also contains the new one, so the old value can never be the maximum again. Each index enters and leaves the deque once, which gives O(n) in total.

Longest Repeating Character Replacement uses if instead of while and never lowers maxFreq. Why is that not a bug?

The answer only improves when a window of a new record size becomes valid, and that requires a maxFreq larger than any seen before. Until then, the window just slides at its current size, so it is never smaller than the best answer so far. It may be invalid while it slides, but it is never recorded as a new best. n − l is the largest size it ever reached.
