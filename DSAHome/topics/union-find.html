Union-Find (Disjoint Set Union)

Watch forests merge with union by rank and path compression; connectivity, redundant edges, and offline queries.

Intermediate → Advanced~45 min studyBuilds on: Graph Fundamentals: BFS & DFSUpdated 2026-11-03

Why union-find exists

Some problems are only about who is connected to whom. Which computers share a network? Which accounts belong to one person? After this road opens, can city A reach city B? Which edge closes a cycle? You don't need paths, distances or orders. You need two operations, asked thousands of times while edges keep arriving:

  • union(a, b): from now on a and b are in the same group (and so are their whole groups);
  • find(x): which group is x in? Two items are connected exactly when find gives the same answer for both.

Graph Fundamentals already counts components with BFS or DFS, and that is the right tool when the whole graph is given up front and asked about once. Union-find (also called a disjoint-set union, or DSU) wins when edges arrive over time, when the same question is asked after every edge, or when you only care about connectivity and don't want to build an adjacency list at all. Both operations run in effectively constant time, and the whole structure is one integer array.

The union-find invariant. Every set is a tree stored in parent[], and its root (the node with parent[r] == r) is the set's name. Two items are in the same set if and only if find walks them to the same root. union only ever links one root under another, so the invariant survives every operation, and with union by size (or rank) plus path compression, any sequence of m operations on n items costs O(m·α(n)), where α(n) ≤ 4 for any n you will ever meet.

The picture: a forest in one array

Each set is a tree whose arrows point up, from a child to its parent. Nothing points down, so there are no child lists to maintain. Storing the arrow for node i at parent[i] gives the whole forest in a single array.

Three consequences fall straight out of the picture:

  1. Every node starts as its own root. parent = [0, 1, 2, …, n−1] means n singleton sets.
  2. find(x) is a walk upward until a node points at itself. Its cost is the depth of x.
  3. union(a, b) writes one pointer. Find both roots; if they differ, make one root the parent of the other. Every member of the lower set now reaches the new root through its old root, so nothing else needs touching. If the roots are equal, a and b were already connected, and in a graph that means the edge a–b closes a cycle. That single boolean powers half the problems on this page.

Keeping the trees short

The only thing that can make union-find slow is a tall tree, because find costs the depth of the node. Two independent ideas keep trees short, and they combine.

Idea 1: union by size (or by rank)

When linking two roots, put the smaller tree under the larger one. A node's depth only increases when its tree is the smaller side of a union, which means the size of the tree containing it at least doubles. A tree can only double log₂ n times before it holds all n nodes, so no node is ever deeper than log₂ n.

Union by rank is the same idea with a different bookkeeping number. Instead of the exact size, each root keeps a rank, an upper bound on its height. Link the lower-rank root under the higher one; only when the ranks tie does the winner's rank go up by one.

Size or rank? They give identical guarantees. Size is usually more useful in interviews because problems often ask for the size of a group ("largest island after one flip", "number of pairs in the same group", "sum of c·(c−1)/2"), and it is right there in size[find(x)]. Rank fits in a byte, which matters only in very memory-tight settings.

Idea 2: path compression

A find walks the whole path to the root anyway, so it might as well leave the path better than it found it: after locating the root, point every node on the path directly at the root. The cost of this find doubles at most, and every later find on those nodes (and on everything hanging below them) is shorter.

There are three common ways to write it, and they are interchangeable for correctness:

  • Two-pass compression (used in the templates below): walk up to find the root, then walk the path again re-pointing each node. Iterative, so no recursion limit.
  • Recursive compression: parent[x] = find(parent[x]); return parent[x]. The shortest to type, but on a long chain before any compression has happened it recurses n deep. With union by size the depth is at most log₂ n, so recursion is safe if you also balance.
  • Path halving: in one pass, point each visited node at its grandparent: parent[x] = parent[parent[x]]; x = parent[x]. Each find only halves the path, but the amortized bound is the same, and it is a single tiny loop.

Give the visualizer a deliberately tall tree (the default parent array is a chain plus a side branch) and compare the three methods' hop counts. Notice that two-pass compression flattens the whole path at once while halving needs a couple of finds to get there.

How fast is “almost constant”?

With both ideas, a sequence of m finds and unions on n items costs O(m·α(n)), where α is the inverse of the Ackermann function. The Ackermann function grows so absurdly fast that its inverse is at most 4 for every input that fits in the universe. You don't need the proof (it is one of the most famous amortized analyses in computer science); you need the table:

What you use Cost of one find (worst / amortized) n = 10⁶ in practice
Naive links, no compression O(n) worst case, every time a chain: up to 10⁶ hops
Path compression only O(log n) amortized a handful of hops
Union by size or rank only O(log n) worst case ≤ 20 hops
Both O(α(n)) amortized, α(n) ≤ 4 1 or 2 hops

The template

This is the version to memorize. It is iterative (no recursion limit), keeps sizes (more useful than ranks), counts the number of sets, and union returns whether it merged anything, which is the cycle test for free.

class DSU:
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.size = [1] * n
        self.count = n                          # number of disjoint sets

    def find(self, x: int) -> int:
        root = x
        while self.parent[root] != root:        # 1. walk up to the root
            root = self.parent[root]
        while self.parent[x] != root:           # 2. point the whole path at it
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                        # already in one set
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra                     # ra is the bigger tree
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.count -= 1
        return True

    def connected(self, a: int, b: int) -> bool:
        return self.find(a) == self.find(b)

    def set_size(self, x: int) -> int:
        return self.size[self.find(x)]

public class DSU
{
    private readonly int[] parent, size;
    public int Count { get; private set; }            // number of disjoint sets

    public DSU(int n)
    {
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
        Count = n;
    }

    public int Find(int x)
    {
        int root = x;
        while (parent[root] != root) root = parent[root];          // 1. walk up
        while (parent[x] != root) { int next = parent[x]; parent[x] = root; x = next; } // 2. compress
        return root;
    }

    public bool Union(int a, int b)
    {
        int ra = Find(a), rb = Find(b);
        if (ra == rb) return false;                                // already in one set
        if (size[ra] < size[rb]) (ra, rb) = (rb, ra);              // ra is the bigger tree
        parent[rb] = ra;
        size[ra] += size[rb];
        Count--;
        return true;
    }

    public bool Connected(int a, int b) => Find(a) == Find(b);
    public int SetSize(int x) => size[Find(x)];
}

A few lines deserve a second look:

  • self.parent[x], x = root, self.parent[x] is safe in Python because the right-hand side is evaluated first: it saves the old parent, then assigns parent[x] = root and moves x to the saved parent. In C# the explicit next does the same.
  • union swaps so that ra is always the bigger root. Writing the two cases separately is a classic place to update the wrong size.
  • size is only meaningful at roots. size[x] for a non-root is a stale number from before x was linked; always read size[find(x)].

Variant: union by rank with path halving

The other textbook form. Same guarantees, the find is one loop, and rank never decreases even when compression flattens a tree.

class RankDSU:
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.rank = [0] * n                     # upper bound on tree height

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # path halving
            x = self.parent[x]
        return x

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1                  # only equal ranks grow
        return True

public class RankDSU
{
    private readonly int[] parent;
    private readonly byte[] rank;                     // upper bound on tree height (≤ 31)

    public RankDSU(int n)
    {
        parent = new int[n];
        rank = new byte[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    public int Find(int x)
    {
        while (parent[x] != x)
        {
            parent[x] = parent[parent[x]];            // path halving
            x = parent[x];
        }
        return x;
    }

    public bool Union(int a, int b)
    {
        int ra = Find(a), rb = Find(b);
        if (ra == rb) return false;
        if (rank[ra] < rank[rb]) (ra, rb) = (rb, ra);
        parent[rb] = ra;
        if (rank[ra] == rank[rb]) rank[ra]++;         // only equal ranks grow
        return true;
    }
}

Variant: keys that are not 0 … n−1

When the items are strings, coordinates or huge integers, swap the array for a dictionary and create each item the first time find sees it. This skips the "map everything to an index first" step and is the natural shape for Accounts Merge, Most Stones Removed and Similar String Groups. Without sizes the trees are only kept short by compression, which is amortized O(log n), more than fast enough; add a size dictionary if you need group sizes.

class KeyedDSU:
    def __init__(self):
        self.parent = {}

    def find(self, x):
        self.parent.setdefault(x, x)            # first sight: a new singleton
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        self.parent[ra] = rb
        return True


def remove_stones(stones):
    """Most Stones Removed: a stone links its row and its column."""
    dsu = KeyedDSU()
    for r, c in stones:
        dsu.union(("r", r), ("c", c))           # tag rows and columns apart
    groups = {dsu.find(("r", r)) for r, c in stones}
    return len(stones) - len(groups)            # each group keeps one stone

public class KeyedDSU<T> where T : notnull
{
    private readonly Dictionary<T, T> parent = new();

    public T Find(T x)
    {
        if (!parent.ContainsKey(x)) parent[x] = x;              // first sight: a singleton
        T root = x;
        while (!EqualityComparer<T>.Default.Equals(parent[root], root)) root = parent[root];
        while (!EqualityComparer<T>.Default.Equals(parent[x], root))
        {
            T next = parent[x]; parent[x] = root; x = next;
        }
        return root;
    }

    public bool Union(T a, T b)
    {
        T ra = Find(a), rb = Find(b);
        if (EqualityComparer<T>.Default.Equals(ra, rb)) return false;
        parent[ra] = rb;
        return true;
    }
}

public int RemoveStones(int[][] stones)
{
    var dsu = new KeyedDSU<(char, int)>();
    foreach (var s in stones) dsu.Union(('r', s[0]), ('c', s[1]));  // tag rows and columns apart
    var groups = new HashSet<(char, int)>();
    foreach (var s in stones) groups.Add(dsu.Find(('r', s[0])));
    return stones.Length - groups.Count;                            // each group keeps one stone
}

Connectivity as edges arrive

Most union-find problems are this loop: for each edge, union it, and react to the return value. True means two components merged (the component count drops by one). False means both ends were already connected, so the edge is redundant: it closes a cycle, and a spanning tree doesn't need it.

Step through it: each node is coloured by its current component, the small forest on the right is the DSU itself, and an edge turns red when union returns False.

That one loop answers a surprising number of questions:

Question What to read from the loop
How many connected components / provinces / friend circles? dsu.count at the end (start at n, minus one per successful union).
Is this graph a tree? (Graph Valid Tree) Exactly n − 1 edges and no union returned False.
Which edge can be removed to leave a tree? (Redundant Connection) The first edge whose union returns False.
Fewest cable moves to connect every computer? Needs ≥ n − 1 cables; then the answer is count − 1 (each redundant cable can bridge two components).
When did everyone first become connected? Sort events by time; the first moment count == 1.
Largest group / number of pairs in the same group? size[find(x)]; pairs = Σ size·(size − 1)/2 over roots.

Number of Provinces is the loop over an adjacency matrix:

def find_circle_num(is_connected):
    n = len(is_connected)
    dsu = DSU(n)
    for i in range(n):
        for j in range(i + 1, n):               # the matrix is symmetric
            if is_connected[i][j]:
                dsu.union(i, j)
    return dsu.count

public int FindCircleNum(int[][] isConnected)
{
    int n = isConnected.Length;
    var dsu = new DSU(n);
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)               // the matrix is symmetric
            if (isConnected[i][j] == 1) dsu.Union(i, j);
    return dsu.Count;
}

When DSU, when BFS/DFS?

Situation Better tool Why
Whole graph given, one question ("how many components?") Either; BFS/DFS is just as good Both O(V + E).
Edges arrive one at a time; answer after each DSU BFS would recompute from scratch after every edge.
"Which edge closes a cycle?" in an undirected graph DSU union returning False is the test.
Groups defined by a shared key (email, row, letter) DSU No adjacency list needed; union on the key.
Need a path, a distance or a BFS layer BFS/DFS DSU forgets how things are connected.
Edges are deleted Neither directly Reverse time (below), or rebuild.
Directed reachability, strongly connected components DFS (Advanced Graphs) Union is symmetric; it cannot represent "a reaches b but not back".

Grids: cell ids, virtual nodes and online islands

Grid problems are graph problems with implicit edges between neighbouring cells. Give cell (r, c) the id r·C + c and the DSU doesn't know or care that it was a grid. A second trick: add one extra id that stands for a whole region ("the border", "the roof", "the outside water") and union the relevant cells with it; then "is this cell connected to the border?" is connected(cell, V).

The online version is Number of Islands II: land appears one cell at a time and you must report the number of islands after each addition. Running a fresh BFS after every addition costs O(k·R·C). With a DSU, each addition is "+1 island, then −1 for every neighbouring land cell whose union succeeds". The union success check matters: two neighbours may already be the same island (they are when the new cell fills in a corner), and that must not be subtracted twice.

Each land cell below shows the cell id of its root, so you can watch two islands keep different names until a bridging cell arrives, and then share one.

Grouping by shared keys

A large family of problems never mentions a graph: "accounts that share an email are the same person", "stones that share a row or a column", "strings that are similar", "letters declared equivalent". The graph is there anyway: items are nodes and a shared key is an edge. Comparing all pairs is O(n²); a dictionary from key → first item that had it turns each repeated key into one union instead.

Two practical patterns:

  • Union items, keep an owner map (Accounts Merge): owner[email] = i on first sight, union(i, owner[email]) on every later sight. Afterwards, group by find(owner[email]).
  • Make the keys themselves nodes (Most Stones Removed, the keyed template above): union a stone's row with its column, so stones sharing either end up together. Tag the two kinds of key (("r", 3) vs ("c", 3)) so row 3 and column 3 don't collide.

Equalities first, then inequalities

Satisfiability of Equality Equations gives constraints like a==b and b!=c. Equality is transitive, which is exactly what sets capture; inequality is not (a ≠ b and b ≠ c says nothing about a and c), so it cannot be stored in a DSU. The fix is ordering: union every == first, so the sets are final, then check that every != joins two different sets. Checking != while still merging is a bug: a later == can join two variables that an earlier != already "approved".

The same two-pass pattern solves anything shaped like "merge by the transitive relation, then validate the non-transitive one".

Weighted union-find: storing a value relative to the parent

Plain union-find knows whether two items are related. A weighted (or potential) DSU also knows how: each node stores a value relative to its parent, so after find (with compression) it holds its value relative to the root. Comparing two nodes with the same root is then one subtraction (or division, or XOR).

  • Ratios (Evaluate Division): w[x] = x / parent[x]; a query is w[a] / w[b].
  • Differences (relative positions, "is this set of x − y = d statements consistent?"): d[x] = value[x] − value[parent[x]]; a query is d[a] − d[b].
  • Parity (bipartite checks online, "x and y are on different teams"): p[x] = colour[x] XOR colour[parent[x]]; a contradiction is two nodes in one set whose parities disagree with the claim.

The only delicate line is union: the two given nodes are usually not roots, so the weight of the new root-to-root link has to be solved from a little square of relations.

Step through Evaluate Division. Every edge label is the node's ratio to its current parent; watch compression rewrite those ratios so they become ratios to the root.

The general template with differences (swap +/− for *// to get ratios, or for ^ to get parity):

class PotentialDSU:
    """Tracks value[x] - value[root]. union(a, b, d) asserts value[a] - value[b] == d."""

    def __init__(self, n: int):
        self.parent = list(range(n))
        self.diff = [0] * n                     # value[x] - value[parent[x]]

    def find(self, x: int) -> int:
        path = []
        while self.parent[x] != x:
            path.append(x)
            x = self.parent[x]
        acc = 0
        for y in reversed(path):                # nearest the root first
            acc += self.diff[y]                 # acc = value[y] - value[root]
            self.parent[y], self.diff[y] = x, acc
        return x

    def union(self, a: int, b: int, d: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return self.diff[a] - self.diff[b] == d   # consistent with what we know?
        self.parent[ra] = rb
        self.diff[ra] = d + self.diff[b] - self.diff[a]
        return True

    def delta(self, a: int, b: int):
        """value[a] - value[b], or None if a and b are unrelated."""
        if self.find(a) != self.find(b):
            return None
        return self.diff[a] - self.diff[b]

public class PotentialDSU
{
    private readonly int[] parent;
    private readonly long[] diff;                     // value[x] - value[parent[x]]

    public PotentialDSU(int n)
    {
        parent = new int[n];
        diff = new long[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    public int Find(int x)
    {
        var path = new List<int>();
        while (parent[x] != x) { path.Add(x); x = parent[x]; }
        long acc = 0;
        for (int i = path.Count - 1; i >= 0; i--)     // nearest the root first
        {
            int y = path[i];
            acc += diff[y];                           // acc = value[y] - value[root]
            parent[y] = x;
            diff[y] = acc;
        }
        return x;
    }

    // Asserts value[a] - value[b] == d; returns false on a contradiction.
    public bool Union(int a, int b, long d)
    {
        int ra = Find(a), rb = Find(b);
        if (ra == rb) return diff[a] - diff[b] == d;
        parent[ra] = rb;
        diff[ra] = d + diff[b] - diff[a];
        return true;
    }

    public long? Delta(int a, int b) => Find(a) == Find(b) ? diff[a] - diff[b] : null;
}

Why diff[ra] = d + diff[b] − diff[a]: after the two finds, diff[a] = a − ra and diff[b] = b − rb. We want ra − rb = (a − diff[a]) − (b − diff[b]) = d − diff[a] + diff[b]. Draw the square every time you are unsure; it is faster than guessing signs.

Offline queries and running time backwards

A DSU can only add edges. That sounds limiting, but when all the queries are known in advance (offline), you can choose the order in which you answer them, and a good order turns everything into additions.

Threshold queries. Checking Existence of Edge Length Limited Paths asks, for many (p, q, limit), whether p and q are connected using only edges shorter than limit. Each query sees a different graph, but the graphs are nested: a bigger limit only ever adds edges. Sort the edges by weight, sort the query indices by limit, and sweep: before answering a query, union every edge below its limit. Each edge is added once overall, and the answers are written back at the query's original index.

The same sweep solves "number of good paths" (open the nodes in increasing value), "minimum effort / swim in rising water" (open cells or edges in increasing height until start meets end), and Kruskal's algorithm in Minimum Spanning Trees, which is the sweep with the queries replaced by "keep the edge if it merged two sets".

Deletions. Bricks Falling When Hit removes bricks one at a time and asks how many fall each time. Run it backwards: remove all the hit bricks first, build the DSU of what is left (with a virtual "roof" node), then add the hits back in reverse order. The number of bricks that newly join the roof's set when a brick returns is the number that fell when it was removed.

Undo: union-find with rollback

Sometimes you need to undo unions in stack order: backtracking searches, divide-and-conquer over time ("offline dynamic connectivity": each edge lives during an interval of queries, and a segment tree over time adds it on entry and undoes it on exit), or trying an edge and taking it back. Union changes exactly one parent pointer and one size, so remember which root moved and undo is O(1).

The one rule: no path compression. Compression rewrites pointers during find, and those writes are not on the history stack, so rollback would leave the forest in a state that never existed. Union by size alone already bounds every find by O(log n).

class RollbackDSU:
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.size = [1] * n
        self.history = []                       # one entry per union call

    def find(self, x: int) -> int:
        while self.parent[x] != x:              # NO path compression
            x = self.parent[x]
        return x

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            self.history.append(-1)             # record "nothing changed"
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.history.append(rb)
        return True

    def rollback(self) -> None:                 # undo the most recent union call
        rb = self.history.pop()
        if rb == -1:
            return
        ra = self.parent[rb]
        self.size[ra] -= self.size[rb]
        self.parent[rb] = rb

public class RollbackDSU
{
    private readonly int[] parent, size;
    private readonly Stack<int> history = new();      // one entry per Union call

    public RollbackDSU(int n)
    {
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }

    public int Find(int x)
    {
        while (parent[x] != x) x = parent[x];         // NO path compression
        return x;
    }

    public bool Union(int a, int b)
    {
        int ra = Find(a), rb = Find(b);
        if (ra == rb) { history.Push(-1); return false; }   // record "nothing changed"
        if (size[ra] < size[rb]) (ra, rb) = (rb, ra);
        parent[rb] = ra;
        size[ra] += size[rb];
        history.Push(rb);
        return true;
    }

    public void Rollback()                            // undo the most recent Union call
    {
        int rb = history.Pop();
        if (rb == -1) return;
        int ra = parent[rb];
        size[ra] -= size[rb];
        parent[rb] = rb;
    }
}

Pushing -1 for a failed union keeps union and rollback calls paired one-to-one, so callers never have to remember which unions "counted".

Recognize it when

Recognize union-find when

  • The question is about groups, components, or "are these connected?", and paths or distances don't matter.
  • Edges or relations arrive over time and you answer after each one (islands appearing, friends meeting, roads opening).
  • You must find the edge that closes a cycle in an undirected graph, or decide whether edges form a tree.
  • Items are related by a shared key (same email, same row or column, same letter class) and the relation is transitive.
  • Constraints mix a transitive relation (==, "same team") with checks against it (!=), or carry a ratio, difference or parity between items.
  • Queries have a threshold ("using only edges below L", "with values at most v") and can be answered offline in sorted order.
  • Something is removed over time, but all removals are known up front: reverse time and add instead.
  • You are building a minimum spanning tree (Kruskal), or a "minimax" path whose answer is the smallest threshold that connects s and t.

Pitfalls: the actual bug and its fix

  1. Linking the items instead of their roots. parent[a] = b cuts a out of its old tree and leaves the rest of that tree behind, so the sets silently split. Fix: always parent[find(a)] = find(b), and only after checking the roots differ.
  2. Comparing parent[a] == parent[b] to test connectivity. Two nodes in the same set can have different parents (depth 2 vs depth 1). Fix: compare find(a) == find(b).
  3. Reading size[x] for a non-root. It is a stale number from before x was linked. Fix: size[find(x)].
  4. Recursive find without union by size. The first find on a 10⁵-long chain recurses 10⁵ deep: RecursionError in Python, StackOverflowException in C#. Fix: the iterative two-pass find, or balance the unions.
  5. Off-by-one node ids. Redundant Connection numbers nodes 1 … n; DSU(n) then indexes parent[n] out of range. Fix: DSU(n + 1) and ignore 0, or subtract 1 on the way in.
  6. Subtracting islands twice. In Number of Islands II, two neighbours of a new cell may already share a root. Fix: decrement the count only when union returns True, and skip a cell that is already land.
  7. Checking != constraints while still merging. A later == can connect two variables after their != was checked. Fix: union every equality first, then check every inequality.
  8. Weighted union with the wrong formula. Using w[ra] = v (forgetting that a and b are not roots) gives wrong ratios that only show up on deeper trees. Fix: call find on both first, then w[ra] = v · w[b] / w[a] (or d + diff[b] − diff[a]); re-derive from the square.
  9. Path compression in a rollback DSU. Compression writes are not recorded, so rollback restores a forest that never existed. Fix: union by size, no compression.
  10. Answering offline queries in sorted order but returning them sorted. Fix: sort the query indices, and write ans[original_index].
  11. Strict vs non-strict thresholds. "Strictly less than limit" means the edge pointer advances while w < limit, not <=. Fix: read the inequality twice; test a query whose limit equals an edge weight.

Worked problems

1. Redundant Connection Medium

A tree with n nodes (labelled 1 … n) had one extra edge added. Return an edge that can be removed so that the rest is a tree; if there are several, return the one that appears last in the input.

Key insight. Process the edges in order. The first edge whose ends are already connected closes the (only) cycle. Every other cycle edge came earlier, so this is also the cycle edge that appears last, exactly what the problem asks for.

Solution: the first union that fails 
def find_redundant_connection(edges):
    dsu = DSU(len(edges) + 1)                   # nodes are 1..n, and n == len(edges)
    for u, v in edges:
        if not dsu.union(u, v):
            return [u, v]                       # u and v were already connected
    return []

public int[] FindRedundantConnection(int[][] edges)
{
    var dsu = new DSU(edges.Length + 1);              // nodes are 1..n, and n == edges.Length
    foreach (var e in edges)
        if (!dsu.Union(e[0], e[1])) return e;         // e[0] and e[1] were already connected
    return Array.Empty<int>();
}

Complexity: O(n·α(n)) time, O(n) memory. The directed version, Redundant Connection II, adds a twist: a node may have two parents. Find that node's two incoming edges, try skipping the later one, and fall back to the earlier one (or the cycle edge) if a cycle remains.

2. Accounts Merge Medium

Each account is [name, email1, email2, …]. Two accounts belong to the same person if they share any email. Merge them and return each person as [name, sorted emails…].

Key insight. Union accounts through an owner map (email → first account that had it); you never compare accounts pairwise. Then bucket emails by find(owner[email]). Names are not keys: two different Johns stay separate unless they share an email.

Solution: owner map, union, then group 
from collections import defaultdict

def accounts_merge(accounts):
    dsu = DSU(len(accounts))
    owner = {}                                  # email -> first account that had it
    for i, acc in enumerate(accounts):
        for email in acc[1:]:
            if email in owner:
                dsu.union(i, owner[email])      # shared email: same person
            else:
                owner[email] = i
    groups = defaultdict(list)
    for email, i in owner.items():
        groups[dsu.find(i)].append(email)
    return [[accounts[root][0]] + sorted(emails) for root, emails in groups.items()]

public IList<IList<string>> AccountsMerge(IList<IList<string>> accounts)
{
    var dsu = new DSU(accounts.Count);
    var owner = new Dictionary<string, int>();        // email -> first account that had it
    for (int i = 0; i < accounts.Count; i++)
        for (int k = 1; k < accounts[i].Count; k++)
        {
            string email = accounts[i][k];
            if (owner.TryGetValue(email, out int j)) dsu.Union(i, j);   // shared email
            else owner[email] = i;
        }

    var groups = new Dictionary<int, List<string>>();
    foreach (var (email, i) in owner)
    {
        int root = dsu.Find(i);
        if (!groups.TryGetValue(root, out var list)) groups[root] = list = new List<string>();
        list.Add(email);
    }
    var result = new List<IList<string>>();
    foreach (var (root, emails) in groups)
    {
        emails.Sort(StringComparer.Ordinal);
        var row = new List<string> { accounts[root][0] };
        row.AddRange(emails);
        result.Add(row);
    }
    return result;
}

Complexity: O(E log E) for E emails in total (the sorting dominates; the DSU part is O(E·α(n))). Use StringComparer.Ordinal in C#: the default culture-aware sort can order emails differently from the expected answer.

3. Satisfiability of Equality Equations Medium

Each equation is "x==y" or "x!=y" over the letters a–z. Can all of them hold at once?

Key insight. Equality is transitive, inequality is not. Union every == first so the classes are final, then each != must join two different classes.

Solution: two passes over 26 letters 
def equations_possible(equations):
    dsu = DSU(26)
    idx = lambda ch: ord(ch) - ord("a")
    for e in equations:                         # pass 1: every ==
        if e[1] == "=":
            dsu.union(idx(e[0]), idx(e[3]))
    for e in equations:                         # pass 2: every !=
        if e[1] == "!" and dsu.connected(idx(e[0]), idx(e[3])):
            return False
    return True

public bool EquationsPossible(string[] equations)
{
    var dsu = new DSU(26);
    foreach (var e in equations)                      // pass 1: every ==
        if (e[1] == '=') dsu.Union(e[0] - 'a', e[3] - 'a');
    foreach (var e in equations)                      // pass 2: every !=
        if (e[1] == '!' && dsu.Connected(e[0] - 'a', e[3] - 'a')) return false;
    return true;
}

Complexity: O(n·α(26)), effectively O(n). "a!=a" is handled for free: a is connected to itself.

4. Smallest String With Swaps Medium

You may swap the characters at any pair [a, b] in pairs, any number of times. Return the lexicographically smallest string you can reach.

Key insight. Swaps compose: if you can swap (0, 1) and (1, 2), you can realise any permutation of positions 0, 1, 2 (adjacent transpositions generate every permutation). So each connected component of positions is a bag whose letters can be arranged freely. Sort each bag and deal the smallest letters to the leftmost positions of that component.

Solution: components, then sort inside each one 
from collections import defaultdict

def smallest_string_with_swaps(s, pairs):
    dsu = DSU(len(s))
    for a, b in pairs:
        dsu.union(a, b)
    groups = defaultdict(list)
    for i in range(len(s)):                     # indices arrive in increasing order
        groups[dsu.find(i)].append(i)
    out = list(s)
    for idx in groups.values():
        for i, ch in zip(idx, sorted(s[i] for i in idx)):
            out[i] = ch                         # smallest letters to the leftmost slots
    return "".join(out)

public string SmallestStringWithSwaps(string s, IList<IList<int>> pairs)
{
    var dsu = new DSU(s.Length);
    foreach (var p in pairs) dsu.Union(p[0], p[1]);
    var groups = new Dictionary<int, List<int>>();
    for (int i = 0; i < s.Length; i++)                // indices arrive in increasing order
    {
        int r = dsu.Find(i);
        if (!groups.TryGetValue(r, out var list)) groups[r] = list = new List<int>();
        list.Add(i);
    }
    var res = new char[s.Length];
    foreach (var idx in groups.Values)
    {
        var chars = idx.Select(i => s[i]).OrderBy(c => c).ToArray();
        for (int k = 0; k < idx.Count; k++) res[idx[k]] = chars[k];   // smallest to the left
    }
    return new string(res);
}

Complexity: O(n log n + p·α(n)). Lexicographically Smallest Equivalent String is the same idea on 26 letters, with one twist: always make the smaller letter the root, so find(c) is directly the smallest equivalent letter.

5. Evaluate Division Medium

Given equations like a / b = 2.0 and queries like a / c, return each query's value, or -1.0 if it cannot be determined.

Key insight. A weighted DSU on ratios. Each variable stores w[x] = x / parent[x]; after find it holds x / root. Variables with the same root are related, and a / b = w[a] / w[b]. Unknown variables and different roots give −1. (A BFS over a graph of ratios also works, at O(V + E) per query.)

Solution: weighted union-find on ratios 
def calc_equation(equations, values, queries):
    parent, weight = {}, {}                     # weight[x] = x / parent[x]

    def find(x):
        path = []
        while parent[x] != x:
            path.append(x)
            x = parent[x]
        acc = 1.0
        for y in reversed(path):                # nearest the root first
            acc *= weight[y]                    # acc = y / root
            parent[y], weight[y] = x, acc
        return x

    for (a, b), val in zip(equations, values):
        for v in (a, b):
            if v not in parent:
                parent[v], weight[v] = v, 1.0
        ra, rb = find(a), find(b)
        if ra != rb:
            parent[ra] = rb
            weight[ra] = val * weight[b] / weight[a]   # ra / rb
    out = []
    for a, b in queries:
        if a not in parent or b not in parent or find(a) != find(b):
            out.append(-1.0)
        else:
            out.append(weight[a] / weight[b])
    return out

public double[] CalcEquation(IList<IList<string>> equations, double[] values, IList<IList<string>> queries)
{
    var parent = new Dictionary<string, string>();
    var weight = new Dictionary<string, double>();    // weight[x] = x / parent[x]

    string Find(string x)
    {
        var path = new List<string>();
        while (parent[x] != x) { path.Add(x); x = parent[x]; }
        double acc = 1.0;
        for (int i = path.Count - 1; i >= 0; i--)     // nearest the root first
        {
            string y = path[i];
            acc *= weight[y];                         // acc = y / root
            parent[y] = x;
            weight[y] = acc;
        }
        return x;
    }

    for (int i = 0; i < equations.Count; i++)
    {
        string a = equations[i][0], b = equations[i][1];
        foreach (var v in new[] { a, b })
            if (!parent.ContainsKey(v)) { parent[v] = v; weight[v] = 1.0; }
        string ra = Find(a), rb = Find(b);
        if (ra != rb) { parent[ra] = rb; weight[ra] = values[i] * weight[b] / weight[a]; }  // ra / rb
    }
    var res = new double[queries.Count];
    for (int i = 0; i < queries.Count; i++)
    {
        string a = queries[i][0], b = queries[i][1];
        res[i] = parent.ContainsKey(a) && parent.ContainsKey(b) && Find(a) == Find(b)
            ? weight[a] / weight[b]
            : -1.0;
    }
    return res;
}

Complexity: O((E + Q)·α(V)) with hashing. Note x / x for a known x is 1.0, but for an unknown x it is −1.0, and the membership check handles both.

6. Number of Islands II Hard

An m × n grid starts as all water. positions[i] = [r, c] turns that cell into land. Return the number of islands after each addition.

Key insight. Online connectivity: each new land cell is +1 island, then −1 for every land neighbour whose union actually merges two sets. A repeated position changes nothing.

Solution: +1, then −1 per successful union 
def num_islands2(m, n, positions):
    dsu = DSU(m * n)
    land = [False] * (m * n)
    count, out = 0, []
    for r, c in positions:
        cell = r * n + c
        if land[cell]:
            out.append(count)                   # duplicate addition
            continue
        land[cell] = True
        count += 1
        for nr, nc in ((r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)):
            if 0 <= nr < m and 0 <= nc < n and land[nr * n + nc]:
                if dsu.union(cell, nr * n + nc):
                    count -= 1                  # two islands just became one
        out.append(count)
    return out

public IList<int> NumIslands2(int m, int n, int[][] positions)
{
    var dsu = new DSU(m * n);
    var land = new bool[m * n];
    int[] dr = { -1, 1, 0, 0 }, dc = { 0, 0, -1, 1 };
    int count = 0;
    var res = new List<int>();
    foreach (var p in positions)
    {
        int r = p[0], c = p[1], cell = r * n + c;
        if (!land[cell])                              // a duplicate changes nothing
        {
            land[cell] = true;
            count++;
            for (int d = 0; d < 4; d++)
            {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr >= 0 && nr < m && nc >= 0 && nc < n && land[nr * n + nc]
                    && dsu.Union(cell, nr * n + nc))
                    count--;                          // two islands just became one
            }
        }
        res.Add(count);
    }
    return res;
}

Complexity: O(m·n + k·α(m·n)) for k positions. If the grid is huge and sparse, use the keyed DSU with (r, c) keys instead of allocating m·n.

7. Checking Existence of Edge Length Limited Paths Hard

Given an undirected weighted graph and queries [p, q, limit], decide for each query whether some path from p to q uses only edges with weight strictly less than limit.

Key insight. Offline sweep. Sort edges by weight and query indices by limit; before answering a query, union every edge with weight below its limit. The DSU then holds exactly that query's graph.

Solution: sort both, sweep with one pointer 
def distance_limited_paths_exist(n, edge_list, queries):
    edge_list.sort(key=lambda e: e[2])
    order = sorted(range(len(queries)), key=lambda i: queries[i][2])
    dsu = DSU(n)
    ans = [False] * len(queries)
    j = 0
    for i in order:
        p, q, limit = queries[i]
        while j < len(edge_list) and edge_list[j][2] < limit:   # strictly less
            dsu.union(edge_list[j][0], edge_list[j][1])
            j += 1
        ans[i] = dsu.connected(p, q)            # written at the original index
    return ans

public bool[] DistanceLimitedPathsExist(int n, int[][] edgeList, int[][] queries)
{
    Array.Sort(edgeList, (x, y) => x[2].CompareTo(y[2]));
    var order = Enumerable.Range(0, queries.Length).ToArray();
    Array.Sort(order, (x, y) => queries[x][2].CompareTo(queries[y][2]));
    var dsu = new DSU(n);
    var ans = new bool[queries.Length];
    int j = 0;
    foreach (int i in order)
    {
        int limit = queries[i][2];
        while (j < edgeList.Length && edgeList[j][2] < limit)        // strictly less
        {
            dsu.Union(edgeList[j][0], edgeList[j][1]);
            j++;
        }
        ans[i] = dsu.Connected(queries[i][0], queries[i][1]);         // original index
    }
    return ans;
}

Complexity: O(E log E + Q log Q + (E + Q)·α(n)). If the queries arrived online (each answer needed before the next query is shown), you would build the minimum spanning forest once and answer "maximum edge on the tree path ≤ limit" with binary lifting, a natural follow-up to Minimum Spanning Trees.

8. Number of Good Paths Hard

A tree has a value on each node. A good path starts and ends at nodes with the same value, and no node on it has a larger value (a single node counts). Count the good paths.

Key insight. Open the nodes in increasing value. When the nodes with value v are opened, union each with every neighbour whose value is ≤ v (already open). Now any two value-v nodes in the same component are joined by a path whose maximum is v, which is exactly a good path. If a component holds c nodes of value v, it contributes c·(c + 1)/2 paths (pairs plus singles). Earlier components can't contain value-v nodes, so nothing is counted twice.

Solution: increasing-value sweep with a DSU 
from collections import Counter, defaultdict

def number_of_good_paths(vals, edges):
    n = len(vals)
    adj = [[] for _ in range(n)]
    for a, b in edges:
        adj[a].append(b)
        adj[b].append(a)
    by_val = defaultdict(list)
    for i, v in enumerate(vals):
        by_val[v].append(i)
    dsu = DSU(n)
    good = 0
    for v in sorted(by_val):
        for u in by_val[v]:                     # open the nodes with value v
            for w in adj[u]:
                if vals[w] <= v:                # only through nodes already open
                    dsu.union(u, w)
        cnt = Counter(dsu.find(u) for u in by_val[v])
        good += sum(c * (c + 1) // 2 for c in cnt.values())
    return good

public int NumberOfGoodPaths(int[] vals, int[][] edges)
{
    int n = vals.Length;
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
    var nodes = Enumerable.Range(0, n).OrderBy(i => vals[i]).ToArray();
    var dsu = new DSU(n);
    int good = 0;
    for (int s = 0; s < n; )
    {
        int e = s;
        while (e < n && vals[nodes[e]] == vals[nodes[s]]) e++;   // nodes[s..e) share one value
        for (int k = s; k < e; k++)
            foreach (int w in adj[nodes[k]])
                if (vals[w] <= vals[nodes[k]]) dsu.Union(nodes[k], w);   // only open nodes
        var cnt = new Dictionary<int, int>();
        for (int k = s; k < e; k++)
        {
            int r = dsu.Find(nodes[k]);
            cnt[r] = cnt.GetValueOrDefault(r) + 1;
        }
        foreach (int c in cnt.Values) good += c * (c + 1) / 2;
        s = e;
    }
    return good;
}

Complexity: O(n log n) for the sort plus O(n·α(n)) for the unions. This "activate in sorted order and count inside components" pattern is the threshold sweep from the offline section, with nodes instead of edges.

Self-check

Why is parent[a] = b wrong as a union, even when a and b are in different sets?

It moves a (and the subtree hanging below a) into b's set, but a's old root and every other branch of a's old tree stay where they were. The old set is split in two, and nothing reports an error. A union has to merge whole sets, and the only node that represents a whole set is its root: parent[find(a)] = find(b).

You use path compression but naive linking. Is that fast enough for 10⁵ operations?

Yes in practice. Compression alone gives O(log n) amortized per operation, so 10⁵ operations cost a few million steps. What you lose is the worst-case bound on a single find (the first find on a long chain still walks all of it), and a recursive find can overflow the stack on that first walk. Adding union by size costs two lines and gives α(n) amortized, so there is no reason not to.

Path compression changes tree heights. Why doesn't union by rank need to update ranks afterwards?

Rank is only used as an upper bound on height, to decide which root goes underneath. Compression can only lower the true height, so the bound stays valid. The guarantee "a root of rank r has at least 2r nodes" is about sizes, which compression doesn't change. Keeping exact heights would cost work on every find and buy nothing.

Redundant Connection asks for the answer that occurs last in the input. Why is the first failing union that edge?

A tree plus one edge has exactly one cycle, and only cycle edges are valid answers (removing any other edge disconnects the graph). While the edges arrive in order, the cycle cannot close until its last edge arrives, and that is the moment its ends are first already connected. So the first failing union is the cycle edge that appears latest.

Can a DSU find strongly connected components or answer “can a reach b?” in a directed graph?

No. union is symmetric: after union(a, b), a and b are interchangeable. Directed reachability is not symmetric (a → b doesn't give b → a), and SCCs need the structure of cycles, which DSU throws away. Use Tarjan's or Kosaraju's DFS from Advanced Graphs. DSU still helps in a few directed problems (Redundant Connection II), but only for the undirected skeleton.

A problem deletes edges between queries. What are your options with union-find?
  1. If all deletions are known up front and nothing is re-added: reverse time. Start from the final graph and add the deleted edges back in reverse order, recording answers backwards.
  2. If edges come and go arbitrarily but offline: offline dynamic connectivity. Each edge is alive during intervals of time; insert it into a segment tree over time, DFS the tree, union on the way down and rollback on the way up (rollback DSU, no compression), giving O((n + q) log q log n).
  3. If it must be online with deletions, a DSU is the wrong tool (link-cut trees or rebuilding are the options).
In Evaluate Division, why must find be called on both a and b before setting weight[ra]?

The formula weight[ra] = v · weight[b] / weight[a] needs weight[a] = a / ra and weight[b] = b / rb, i.e. ratios to the roots. Before find, weight[a] is only the ratio to a's current parent, which may be several levels below the root. find with compression rewrites both into root ratios, and only then does the square of relations give the correct new link.
