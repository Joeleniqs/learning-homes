Monotonic Stack & Queue

Next greater element, histogram rectangles, stock spans and sliding-window maximum, with the pop-means-answer insight.

Intermediate → Expert~55 min studyBuilds on: Stacks & QueuesUpdated 2026-11-03

What it is and when you need it

Many array questions ask the same thing about every index: "what is the first element after (or before) me that is bigger (or smaller) than me?" The next warmer day, the next taller person, the first cheaper price, the bar that stops a rectangle from growing. The brute force scans outward from every index, which is O(n²) on a sorted input. A monotonic stack answers the question for every index in one O(n) pass.

The invariant. The stack holds exactly the indices that are still waiting for their answer. A new element pops every waiting index it beats, and that pop is the answer for the popped index. Because beaten indices leave immediately, the values left on the stack are always sorted (monotonic). The index left on top after the pops is the new element's answer in the other direction.

Two facts make this work. Order: nothing left on the stack beats anything above it; otherwise it would already have been popped. Cost: each index is pushed once and popped at most once, so the inner while loop runs at most n times in total over the whole scan, not n times per element. A monotonic queue (a deque) adds a second exit at the front, for windows that move: the Sliding Window page introduces it for window maximum, and this page goes deeper.

You should be comfortable with Stacks & Queues first. The whole technique is a while loop around pop().

Brute force: O(n²)

For each i, scan j = i+1, i+2, … until a[j] > a[i]. On a decreasing array every scan runs to the end. It is simple, and it is the reference to test against.

Sort or tree: O(n log n)

"Next greater" is about position, not just value, so sorting destroys the information you need. A balanced tree or a segment tree can answer it, but that is a large hammer for a stack-sized nail.

Monotonic stack: O(n)

One left-to-right pass. Each pop answers one index. It also gives both neighbours (previous and next) in the same pass, which is what histogram and contribution problems need.

Intuition: a line of people waiting for someone taller

Picture the array as people of different heights standing in a line, all looking right. Each person wants to know: who is the first taller person to my right? Walk along the line. Everyone you have passed who has not found their answer is still waiting. When a new person arrives, every waiting person shorter than the newcomer has just found their answer: it is the newcomer. They stop waiting (pop). Taller people keep waiting, and so does the newcomer (push).

Why are the waiting values always decreasing from bottom to top? Suppose a waiting value were smaller than a value pushed after it. Then the later value would have beaten it on arrival and popped it. So the stack can never contain a "beaten" pair. Once you see the waiting room as a staircase going down, two more facts follow.

What a pop tells you When index t is popped by the newcomer i, you learn two things at once. i is the first index to the right of t that beats it: that is next[t]. The index just below t in the stack is the nearest index to the left of t that t did not beat: that is prev[t]. So at the moment of a pop, the popped element knows both of its walls. Largest Rectangle in Histogram and the contribution technique are built entirely on this.

Store indices, not values Push the index i, and read the value as a[i]. Indices give you distances (i − t days until warmer), widths (right − left − 1), and they let you tell equal values apart. Values alone cannot do any of those.

One template, four questions

There are four "nearest" questions: next or previous, greater or smaller. Each also has a strict or non-strict version, which matters as soon as there are duplicates. They are all one loop. Only the comparison in the while changes, and one pass gives you a "next" answer at pop time and a "previous" answer at push time.

def next_and_prev_greater(a: list[int]) -> tuple[list[int], list[int]]:
    """nxt[i] = first j > i with a[j] > a[i]  (else -1)
       prv[i] = last  j < i with a[j] >= a[i] (else -1)"""
    n = len(a)
    nxt, prv = [-1] * n, [-1] * n
    st: list[int] = []                    # indices; a[st] is non-increasing
    for i, x in enumerate(a):
        while st and a[st[-1]] < x:       # x beats the waiting top
            nxt[st.pop()] = i             # pop = answer
        prv[i] = st[-1] if st else -1     # whoever survived is >= x
        st.append(i)                      # i starts waiting
    return nxt, prv

public static (int[] Next, int[] Prev) NextAndPrevGreater(int[] a)
{
    int n = a.Length;
    var nxt = new int[n]; var prv = new int[n];
    Array.Fill(nxt, -1);
    var st = new Stack<int>();             // indices; a[st] is non-increasing
    for (int i = 0; i < n; i++)
    {
        while (st.Count > 0 && a[st.Peek()] < a[i])
            nxt[st.Pop()] = i;             // pop = answer
        prv[i] = st.Count > 0 ? st.Peek() : -1;
        st.Push(i);
    }
    return (nxt, prv);
}

Complexity: O(n) time (each index is pushed once and popped at most once), O(n) space for the stack in the worst case (a decreasing array never pops).

Change the comparison and you get the other questions. The table is worth memorising as one rule: the stack is sorted the opposite way to the question. If you want something greater, the waiting room is decreasing, because anything greater than a waiting value would have popped it.

You want Pop while a[top] … x Stack values (bottom → top) Popped t gets next[t] = i meaning Top after pops gives prev[i] meaning
next greater < non-increasing first j > t with a[j] > a[t] last j < i with a[j] >= a[i]
next greater or equal <= strictly decreasing first j > t with a[j] >= a[t] last j < i with a[j] > a[i]
next smaller > non-decreasing first j > t with a[j] < a[t] last j < i with a[j] <= a[i]
next smaller or equal >= strictly increasing first j > t with a[j] <= a[t] last j < i with a[j] < a[i]

Read the last column carefully: the "previous" answer you get for free always has the opposite strictness to the "next" answer. Popping on ties makes "next" non-strict, and it leaves only strictly larger values below, so "previous" becomes strict. If you need both sides strict (or both non-strict), run a second pass from the right, or fix the ties as in the contribution section.

Step through it. Change the family, the tie rule and the array, and watch the arcs. Solid arcs are "next" answers produced by pops. Dashed arcs are "previous" answers read from the top of the stack at push time.

The mirror view: scan from the right, keep the candidates

You can also scan right to left. Now the stack holds the candidates: values to the right that could still be someone's next greater element. Before reading the answer for a[i], pop every candidate that is <= a[i]. They are hidden behind a[i] for everyone further left, because a[i] is closer and at least as tall. The top of the stack is then the answer.

def next_greater_from_right(a: list[int]) -> list[int]:
    n = len(a)
    nxt = [-1] * n
    st: list[int] = []                    # candidates to the right, decreasing
    for i in range(n - 1, -1, -1):
        while st and a[st[-1]] <= a[i]:   # hidden behind a[i] forever
            st.pop()
        nxt[i] = st[-1] if st else -1
        st.append(i)
    return nxt

public static int[] NextGreaterFromRight(int[] a)
{
    int n = a.Length;
    var nxt = new int[n];
    var st = new Stack<int>();            // candidates to the right, decreasing
    for (int i = n - 1; i >= 0; i--)
    {
        while (st.Count > 0 && a[st.Peek()] <= a[i]) st.Pop();
        nxt[i] = st.Count > 0 ? st.Peek() : -1;
        st.Push(i);
    }
    return nxt;
}

Both directions are O(n) and give the same answers. The left-to-right "waiting room" version is better when the data arrives as a stream, because answers appear the moment they are known. The right-to-left "candidates" version reads more naturally when you need the answer for i at step i, as in 132 Pattern and Number of Visible People in a Queue (worked problems below).

Circular arrays: walk around twice

In a circular array, the element after the last one is the first one, so the next greater element of a[n−1] may be a[0]. Do not copy the array. Iterate i from 0 to 2n − 1 and read a[i % n]. During the second lap, only pop, never push: those indices already had their turn to wait.

def next_greater_circular(a: list[int]) -> list[int]:
    n = len(a)
    res = [-1] * n
    st: list[int] = []
    for i in range(2 * n):
        x = a[i % n]
        while st and a[st[-1]] < x:
            res[st.pop()] = x             # this problem returns values
        if i < n:
            st.append(i)
    return res

public static int[] NextGreaterCircular(int[] a)
{
    int n = a.Length;
    var res = new int[n];
    Array.Fill(res, -1);
    var st = new Stack<int>();
    for (int i = 0; i < 2 * n; i++)
    {
        int x = a[i % n];
        while (st.Count > 0 && a[st.Peek()] < x) res[st.Pop()] = x;
        if (i < n) st.Push(i);
    }
    return res;
}

Why two laps are enough: after the first lap, every index still waiting needs a value to its right or wrapped around to the start. Lap two shows it every index from 0 to n − 1, which covers the whole wrap-around. Only the global maximum (and copies of it) survive both laps. Set the visualizer above to circular to watch the second lap at work: the faded bars are the copy.

Daily temperatures and stock span

These two are the same pop seen from both sides.

Daily Temperatures asks, for each day, how many days until a warmer one. That is "next strictly greater", and the answer is a distance: when t is popped by i, ans[t] = i − t.

def daily_temperatures(temps: list[int]) -> list[int]:
    ans = [0] * len(temps)
    st: list[int] = []
    for i, t in enumerate(temps):
        while st and temps[st[-1]] < t:
            j = st.pop()
            ans[j] = i - j                # days waited
        st.append(i)
    return ans

public static int[] DailyTemperatures(int[] temps)
{
    var ans = new int[temps.Length];
    var st = new Stack<int>();
    for (int i = 0; i < temps.Length; i++)
    {
        while (st.Count > 0 && temps[st.Peek()] < temps[i])
        {
            int j = st.Pop();
            ans[j] = i - j;
        }
        st.Push(i);
    }
    return ans;
}

Online Stock Span looks backwards: for today's price, how many consecutive days (including today) had a price <= today's? That is "distance to the previous strictly greater price", which is the top of the stack after popping. The twist is that the prices arrive one call at a time and you cannot keep indices into an array you never see. So each stack entry stores (price, span). The span is the number of days that entry swallowed when it was pushed. Popping an entry absorbs its whole block of days in O(1).

class StockSpanner:
    def __init__(self) -> None:
        self.st: list[tuple[int, int]] = []   # (price, days it covers)

    def next(self, price: int) -> int:
        span = 1
        while self.st and self.st[-1][0] <= price:
            span += self.st.pop()[1]          # swallow the whole block
        self.st.append((price, span))
        return span

public sealed class StockSpanner
{
    private readonly Stack<(int Price, int Span)> _st = new();

    public int Next(int price)
    {
        int span = 1;
        while (_st.Count > 0 && _st.Peek().Price <= price)
            span += _st.Pop().Span;           // swallow the whole block
        _st.Push((price, span));
        return span;
    }
}

Complexity: O(1) amortised per call. Each price is pushed once and popped at most once over the whole stream. A single call can still pop many entries, for example a new all-time high, so the worst case for one call is O(n).

Compression is the general idea The stock-span stack stores a summary of a dominated block of history: "these 4 days were all ≤ 85". Whenever a monotonic stack needs an aggregate of the region it pops (a count, a sum, a minimum), store that aggregate in the stack entry and merge it on pop. Car Fleet, the running-sum version of Sum of Subarray Minimums and Count Submatrices With All Ones all use this trick.

Largest rectangle in a histogram

This is the problem that makes monotonic stacks famous. You are given bar heights, all of width 1. Find the largest axis-aligned rectangle that fits under the bars.

The key observation: the best rectangle is limited by its shortest bar. So guess which bar is the shortest one. If bar i is the shortest bar of the rectangle, the rectangle should be as wide as possible at height h[i]. It extends left until the first bar that is shorter than h[i] and right until the first bar that is shorter than h[i]. Those two walls are the previous smaller and next smaller elements.

So the answer is max(h[i] × (next_smaller[i] − prev_smaller[i] − 1)) over all i. You could compute both arrays with two passes, but one pass is enough, because of the insight above: at the moment bar t is popped, both of its walls are known.

  • It is popped by i because h[i] < h[t]. So i is the right wall.
  • After the pop, the new top of the stack is the nearest bar to the left that is shorter than h[t] (or equal, see below). That is the left wall. If the stack is empty, the left wall is −1, the left edge.
  • Width = i − new_top − 1. Area = h[t] × width.

Add a sentinel bar of height 0 at the end: it is shorter than every real bar, so it pops everything that is still on the stack and every bar gets measured. Each pop in the visualizer draws the rectangle it measures.

def largest_rectangle_area(heights: list[int]) -> int:
    st: list[int] = []                         # indices, heights increasing
    best = 0
    for i, h in enumerate(heights + [0]):      # sentinel 0 flushes the stack
        while st and heights[st[-1]] >= h:
            top = st.pop()
            left = st[-1] if st else -1        # first shorter bar to the left
            width = i - left - 1               # i is the first shorter to the right
            best = max(best, heights[top] * width)
        st.append(i)
    return best

public static int LargestRectangleArea(int[] heights)
{
    int n = heights.Length, best = 0;
    var st = new Stack<int>();                  // indices, heights increasing
    for (int i = 0; i <= n; i++)
    {
        int h = i == n ? 0 : heights[i];        // sentinel 0 flushes the stack
        while (st.Count > 0 && heights[st.Peek()] >= h)
        {
            int top = st.Pop();
            int left = st.Count > 0 ? st.Peek() : -1;
            best = Math.Max(best, heights[top] * (i - left - 1));
        }
        st.Push(i);
    }
    return best;
}

Complexity: O(n) time, O(n) space.

Ties: >= or >, and why both are correct With >=, an equal bar pops the earlier equal bar. That earlier bar then measures a rectangle that stops too early on the right, so its area is an underestimate. That is harmless, because the last bar of the equal run is popped later by a strictly shorter bar, and its left wall reaches past all the equal bars. It measures the full width. With >, the equal bars stack up, and the first of the run measures the full width when the run is flushed. Either way the maximum is found. Underestimates are fine when you take a maximum. They are not fine when you sum or count, which is why the contribution technique below needs a precise tie rule.

Maximal rectangle: a histogram on every row

Given a 0/1 grid, find the largest rectangle that contains only 1s. Turn each row into the floor of a histogram: h[c] is the number of consecutive 1s in column c ending at this row. Every all-1 rectangle has a bottom row, and on that row it is a rectangle under the histogram. So run Largest Rectangle once per row.

def maximal_rectangle(matrix: list[list[str]]) -> int:
    if not matrix:
        return 0
    h = [0] * len(matrix[0])
    best = 0
    for row in matrix:
        for c, cell in enumerate(row):
            h[c] = h[c] + 1 if cell == "1" else 0   # extend or reset the column
        best = max(best, largest_rectangle_area(h))
    return best

public static int MaximalRectangle(char[][] matrix)
{
    if (matrix.Length == 0) return 0;
    var h = new int[matrix[0].Length];
    int best = 0;
    foreach (var row in matrix)
    {
        for (int c = 0; c < row.Length; c++)
            h[c] = row[c] == '1' ? h[c] + 1 : 0;      // extend or reset the column
        best = Math.Max(best, LargestRectangleArea(h));
    }
    return best;
}

Complexity: O(R·C) time, O(C) space. The related problem Maximal Square is easier with DP (side = 1 + min(up, left, diag), see DP on grids); a square is not a rectangle you can stretch freely, so the histogram view gives nothing extra there.

Trapping rain water: layers versus columns

Water above index i rises to min(highest wall on the left, highest wall on the right). The Two Pointers page computes that level column by column in O(1) extra space. A monotonic stack computes the same water in horizontal layers: it is the histogram idea turned upside down. The stack holds a decreasing staircase of walls. When a taller bar i arrives, it pops a lower floor bottom. If there is still a wall left under it, the region between left and i, above bottom, holds water:

  • width = i − left − 1
  • height = min(h[left], h[i]) − h[bottom]
def trap(height: list[int]) -> int:
    st: list[int] = []                 # indices, heights decreasing
    water = 0
    for i, h in enumerate(height):
        while st and height[st[-1]] < h:
            bottom = st.pop()
            if not st:                 # no left wall: water spills off the edge
                break
            left = st[-1]
            width = i - left - 1
            depth = min(height[left], h) - height[bottom]
            water += width * depth     # one horizontal layer
        st.append(i)
    return water

public static int Trap(int[] height)
{
    var st = new Stack<int>();         // indices, heights decreasing
    int water = 0;
    for (int i = 0; i < height.Length; i++)
    {
        while (st.Count > 0 && height[st.Peek()] < height[i])
        {
            int bottom = st.Pop();
            if (st.Count == 0) break;  // no left wall: water spills off the edge
            int left = st.Peek();
            int width = i - left - 1;
            int depth = Math.Min(height[left], height[i]) - height[bottom];
            water += width * depth;    // one horizontal layer
        }
        st.Push(i);
    }
    return water;
}
Stack (layers) Two pointers (columns) Prefix max arrays
Time O(n) O(n) O(n)
Extra space O(n) O(1) O(n)
Works on a stream (left to right, no look-ahead) yes: water is final when the right wall arrives no: needs the right end no
Generalises to "water between walls" with widths, histogram family "two moving boundaries" anything needing both maxima per index
Best for interviews when they ask for a stack default answer easiest to explain

Equal heights are harmless here: a layer of depth 0 adds nothing. Trapping Rain Water II (a 2D height map) is a different algorithm: a min-heap flood fill from the border (see Heaps & Priority Queues).

The contribution technique: sum of subarray minimums

Problem: return the sum of min(sub) over all n(n+1)/2 contiguous subarrays. Computing each minimum is hopeless at n = 3·10⁴. Turn the sum inside out: instead of asking each subarray for its minimum, ask each element how many subarrays it is the minimum of.

For index j, let left[j] be the nearest index to the left with a smaller value, and right[j] the nearest to the right. Then a[j] is the minimum of exactly the subarrays that start in left[j]+1 … j and end in j … right[j]−1. That is L × R subarrays, with L = j − left[j] and R = right[j] − j:

Contribution. answer = Σ a[j] × (j − left[j]) × (right[j] − j). Both walls come from one monotonic stack pass. This works for any "sum over all subarrays of (min or max)", and with prefix sums for "sum of min × sum".

The tie rule decides who owns a subarray

With duplicates, a subarray can have two positions holding its minimum, and it must be counted exactly once. "Smaller" has to be strict on one side and non-strict on the other:

Try the bad rules in the visualizer. With duplicates in the input, the final frame shows exactly which subarray was counted twice or not at all.

The one-pass stack gives exactly this mixed rule for free. Pop while a[top] >= x: the popped top gets right[top] = i (next smaller or equal), and every surviving top is strictly smaller, so left[i] is the previous strictly smaller index. You can even compute the contribution at pop time, when both walls of the popped element are known, just as in the histogram:

def sum_subarray_mins(arr: list[int]) -> int:
    MOD = 10**9 + 7
    total = 0
    st: list[int] = []                         # indices, values strictly increasing
    for i, x in enumerate(arr + [0]):          # sentinel 0 <= every value flushes all
        while st and arr[st[-1]] >= x:         # right wall: next smaller or equal
            j = st.pop()
            left = st[-1] if st else -1        # left wall: previous strictly smaller
            total += arr[j] * (j - left) * (i - j)
        st.append(i)
    return total % MOD

public static int SumSubarrayMins(int[] arr)
{
    const long Mod = 1_000_000_007;
    int n = arr.Length;
    long total = 0;
    var st = new Stack<int>();                  // indices, values strictly increasing
    for (int i = 0; i <= n; i++)
    {
        int x = i == n ? 0 : arr[i];            // sentinel flushes everything
        while (st.Count > 0 && arr[st.Peek()] >= x)
        {
            int j = st.Pop();
            int left = st.Count > 0 ? st.Peek() : -1;
            total = (total + (long)arr[j] * (j - left) % Mod * (i - j)) % Mod;
        }
        st.Push(i);
    }
    return (int)total;
}

Complexity: O(n) time and space. The sentinel 0 works because the problem guarantees arr[i] ≥ 1. For arbitrary values use float('-inf') (Python) or int.MinValue (C#) and compare carefully. In C#, (long)arr[j] * (j - left) is at most 3·10⁴ · 3·10⁴ ≈ 9·10⁸, and multiplying the reduced value by (i − j) stays below 3·10¹³, which fits in a long.

Variants on the same skeleton:

  • Sum of Subarray Ranges = Σ max − Σ min. Run the contribution twice, once with the comparisons flipped for max (worked problem 3).
  • Maximum Subarray Min-Product: for each j as the minimum, the best subarray is its whole kingdom. The value is a[j] × sum(kingdom), with the sum from prefix sums (worked problem 5).
  • Sum of Total Strength of Wizards: Σ min × sum over all subarrays. Each element's contribution needs the sum of all subarray sums inside its kingdom: a prefix sum of prefix sums (worked problem 8).

Greedy stacks: build the smallest sequence

A different family uses the same stack for a greedy choice. You build an output left to right, and a later, better character can undo earlier choices, as long as the undo is still allowed.

Remove K digits

Remove k digits from num to make the smallest possible number. Greedy rule: if a digit is followed by a smaller digit, deleting it makes the number smaller at the first position that changes, and nothing else you could delete does better. So scan left to right, and while you still have deletions, pop any kept digit that is bigger than the arriving one.

def remove_k_digits(num: str, k: int) -> str:
    st: list[str] = []
    for d in num:
        while k and st and st[-1] > d:     # a bigger digit before a smaller one: delete it
            st.pop()
            k -= 1
        st.append(d)
    if k:
        st = st[:-k]                       # still owe deletions: the tail is non-decreasing
    return "".join(st).lstrip("0") or "0"

public static string RemoveKdigits(string num, int k)
{
    var st = new StringBuilder();          // used as a stack of chars
    foreach (char d in num)
    {
        while (k > 0 && st.Length > 0 && st[^1] > d)
        {
            st.Length--;                   // pop
            k--;
        }
        st.Append(d);
    }
    st.Length -= Math.Min(k, st.Length);   // still owe deletions: drop from the end
    int z = 0;
    while (z < st.Length - 1 && st[z] == '0') z++;
    var s = st.ToString(z, st.Length - z);
    return s.Length == 0 ? "0" : s;
}

Complexity: O(n) time and space. Three edge cases catch most people: leftover k (the digits are already non-decreasing, so remove from the end), leading zeros ("10200", k=1 → "200"), and removing everything ("10", k=2 → "0").

Smallest subsequence of distinct characters

Return the lexicographically smallest subsequence of s that contains every distinct letter exactly once (LeetCode 316 and 1081). Same greedy, two extra rules:

  1. Skip a letter that is already on the stack. It was placed at a position at least as good as this one.
  2. Pop a bigger letter only if it appears again later. Otherwise popping it would lose that letter for good. Precompute last[c], the last index of each letter.
def smallest_subsequence(s: str) -> str:
    last = {c: i for i, c in enumerate(s)}
    st: list[str] = []
    on_stack: set[str] = set()
    for i, c in enumerate(s):
        if c in on_stack:
            continue                                   # rule 1: already placed
        while st and st[-1] > c and last[st[-1]] > i:  # rule 2: it comes back later
            on_stack.remove(st.pop())
        st.append(c)
        on_stack.add(c)
    return "".join(st)

public static string SmallestSubsequence(string s)
{
    var last = new int[26];
    for (int i = 0; i < s.Length; i++) last[s[i] - 'a'] = i;
    var st = new StringBuilder();
    var onStack = new bool[26];
    for (int i = 0; i < s.Length; i++)
    {
        char c = s[i];
        if (onStack[c - 'a']) continue;                // rule 1: already placed
        while (st.Length > 0 && st[^1] > c && last[st[^1] - 'a'] > i)
        {
            onStack[st[^1] - 'a'] = false;             // rule 2: it comes back later
            st.Length--;
        }
        st.Append(c);
        onStack[c - 'a'] = true;
    }
    return st.ToString();
}

Complexity: O(n) time, O(σ) space for an alphabet of size σ. The same "pop if you can still afford to" rule solves Find the Most Competitive Subsequence (pop while len(st) − 1 + (n − i) >= k) and is the building block of Create Maximum Number.

Monotonic queues: a stack with a second exit

A monotonic stack answers "nearest" questions over everything seen so far. Many problems restrict the candidates to a window: the last k indices, or indices whose x-coordinate is within k. Candidates then have two ways to become useless:

  1. Dominated (back): a newer element is at least as good and lives longer. This is exactly the stack rule.
  2. Expired (front): the oldest candidate has fallen outside the window. Since the deque is in index order, the oldest is always at the front.

The Sliding Window page has the visualizer for the basic sliding window maximum: a deque of indices with decreasing values. The front is the window maximum. Pop the back while a[back] <= a[r], and pop the front when it is <= r − k. Two deques (one decreasing, one increasing) give the window max and min at once, which solves Longest Continuous Subarray With Absolute Diff ≤ Limit. The two harder uses below show where the deque really earns its place.

Shortest subarray with sum at least K (negative numbers allowed)

With only non-negative numbers this is a plain sliding window. Negative numbers break the window, because adding an element can make the sum smaller. Use prefix sums instead: sum(i..j−1) = P[j] − P[i], and we want the smallest j − i with P[j] − P[i] ≥ K. Keep a deque of candidate starts i with increasing P[i]:

  • Front pop (answered): while P[j] − P[front] ≥ K, record j − front and pop the front. Any later end j' > j would give that start a longer subarray, so it can never do better. It is done.
  • Back pop (dominated): while P[back] ≥ P[j], pop the back. Start j is later (so shorter subarrays) and has a smaller or equal prefix (so bigger sums) than back. back can never be the better start again.

The visualizer plots the prefix sums. The deque is the set of points that are still candidate starts, and the dashed threshold line is P[j] − K: every candidate on or below it is answered.

from collections import deque

def shortest_subarray(nums: list[int], k: int) -> int:
    P = [0]
    for x in nums:
        P.append(P[-1] + x)
    best = len(nums) + 1
    dq: deque[int] = deque()                 # candidate starts, P increasing
    for j in range(len(P)):
        while dq and P[j] - P[dq[0]] >= k:   # answered: later ends only get longer
            best = min(best, j - dq.popleft())
        while dq and P[dq[-1]] >= P[j]:      # dominated: j is later and lower
            dq.pop()
        dq.append(j)
    return best if best <= len(nums) else -1

public static int ShortestSubarray(int[] nums, int k)
{
    int n = nums.Length;
    var P = new long[n + 1];
    for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
    int best = n + 1;
    var dq = new LinkedList<int>();          // candidate starts, P increasing
    for (int j = 0; j <= n; j++)
    {
        while (dq.Count > 0 && P[j] - P[dq.First!.Value] >= k)
        {
            best = Math.Min(best, j - dq.First.Value);  // answered
            dq.RemoveFirst();
        }
        while (dq.Count > 0 && P[dq.Last!.Value] >= P[j])
            dq.RemoveLast();                  // dominated
        dq.AddLast(j);
    }
    return best <= n ? best : -1;
}

Complexity: O(n) time and space. Note the front pop has a different meaning from the sliding-window maximum: there it means "expired", here it means "answered, and nothing later can beat this answer". Both are the same structural move: the oldest candidate is finished. (A circular buffer of ints, or an int[] with head and tail indices, is faster in C# than LinkedList<int>; the linked list keeps the code short.)

Constrained subsequence sum: a deque inside a DP

Pick a non-empty subsequence with maximum sum such that consecutive picked indices are at most k apart. The DP is natural:

dp[i] = nums[i] + max(0, dp[i−k], …, dp[i−1])

That is O(nk), because every i scans the last k values. But the inner max is a sliding window maximum over dp. Keep a decreasing deque of indices into dp, and the transition is O(1) amortised. The visualizer runs both versions and compares them.

from collections import deque

def constrained_subset_sum(nums: list[int], k: int) -> int:
    dp = [0] * len(nums)
    dq: deque[int] = deque()                 # indices into dp, dp values decreasing
    for i, x in enumerate(nums):
        if dq and dq[0] < i - k:             # expired: too far back to jump from
            dq.popleft()
        dp[i] = x + max(0, dp[dq[0]] if dq else 0)
        while dq and dp[dq[-1]] <= dp[i]:    # dominated: older and not better
            dq.pop()
        dq.append(i)
    return max(dp)

public static int ConstrainedSubsetSum(int[] nums, int k)
{
    int n = nums.Length;
    var dp = new int[n];
    var dq = new LinkedList<int>();          // indices into dp, dp values decreasing
    int best = int.MinValue;
    for (int i = 0; i < n; i++)
    {
        if (dq.Count > 0 && dq.First!.Value < i - k) dq.RemoveFirst();
        dp[i] = nums[i] + Math.Max(0, dq.Count > 0 ? dp[dq.First!.Value] : 0);
        while (dq.Count > 0 && dp[dq.Last!.Value] <= dp[i]) dq.RemoveLast();
        dq.AddLast(i);
        best = Math.Max(best, dp[i]);
    }
    return best;
}

Complexity: O(n) time, O(n) space for dp (O(k) for the deque). One if is enough for the expiry because the window moves by exactly one index per step, so at most one index leaves. This is the general recipe for DP whose transition is a max or min over a sliding range of previous states: Jump Game VI is the same problem with a forced path, and Max Value of Equation (worked problem 7) is the same idea with x-coordinates as the window. See DP framework for how to set up the recurrence in the first place.

Recognize it when

  • Each element needs the nearest element to its left or right that is bigger or smaller: next warmer day, next taller person, first cheaper item, the bar that stops a rectangle.
  • The brute force has an inner loop that scans outward from i until a comparison fails.
  • The answer is a width bounded by a minimum (histograms, rectangles in grids, "min × length", "min × sum").
  • You need the sum, count or max over all subarrays of a min or max: think contribution, where each element owns a range.
  • You build a lexicographically smallest sequence by deleting or choosing characters, and a later smaller character should undo earlier bigger ones.
  • A window (last k items, x within k) asks for a max or min, or a DP takes the max over a sliding range of earlier states.
  • The values can be negative, so a sliding window breaks, but you still need the shortest or longest range: prefix sums plus a monotonic deque.

Pitfalls

Pitfall: the same tie rule on both sides In Sum of Subarray Minimums on [2, 5, 2], using "strictly smaller" on both sides lets both 2s claim the whole array: the sum comes out 2 too big. Using "smaller or equal" on both sides lets neither claim it: 2 too small. Fix: exactly one side strict. The single-pass stack gives you this automatically: pop on >=, read left from the surviving top.

Pitfall: forgetting the sentinel (or the final flush) In Largest Rectangle on [2, 4, 6], nothing is ever popped during the scan, because the heights only increase. Without a final pass the answer comes out 0 instead of 8. Append a 0 (or loop i to n and treat h[n] = 0) so every bar is popped and measured.

Pitfall: pushing during the second lap of a circular array Pushing in lap two adds a second waiting copy of each index, and when the copy is popped it writes res[i % n] again. On [1, 3, 2] with indices as answers, index 0 is answered by index 1 in lap one, then its lap-two copy is popped at i = 4 and overwrites the answer with 4, which is not even a valid index. (With values as answers the rewrite happens to be identical, so the bug hides until you switch to indices or distances.) Only push when i < n.

Pitfall: Remove K Digits leftovers On "12345", k = 2 no digit is ever followed by a smaller one, so the loop deletes nothing and returns "12345". The remaining k deletions must come off the end (the largest digits of a non-decreasing tail), giving "123". Then strip leading zeros, and return "0" for an empty result.

Pitfall: deque front means different things In window maximum, the front leaves when it expires. Check dq[0] <= r − k before reading the answer. In Shortest Subarray ≥ K, the front leaves when it is answered: check P[j] − P[dq[0]] >= k in a while loop and record the length before popping. Mixing them up gives either stale maxima or missed shortest lengths.

Pitfall: overflow Histogram areas fit in an int (10⁵ bars × 10⁴ height = 10⁹). Prefix sums with 10⁵ values of size 10⁵ do not. Contribution products like a[j] × L × R can reach about 10¹⁹ for 10⁵ elements of size 10⁹, so reduce with a modulo after each multiplication. Python hides this. C# does not: use long and % Mod after each multiplication.

Worked problems

1. Next Greater Element I

nums1 is a subset of nums2 (all values distinct). For each value in nums1, return the first greater value to its right in nums2. Insight: answer the question once for every value of nums2 with the template, store the answers in a hashmap keyed by value, then look each query up. Values are distinct, so storing values (not indices) is safe here.

Solution: O(n + m) time, O(n) space 
def next_greater_element(nums1: list[int], nums2: list[int]) -> list[int]:
    nxt: dict[int, int] = {}
    st: list[int] = []                    # values still waiting, decreasing
    for x in nums2:
        while st and st[-1] < x:
            nxt[st.pop()] = x
        st.append(x)
    return [nxt.get(x, -1) for x in nums1]

public static int[] NextGreaterElement(int[] nums1, int[] nums2)
{
    var nxt = new Dictionary<int, int>();
    var st = new Stack<int>();            // values still waiting, decreasing
    foreach (int x in nums2)
    {
        while (st.Count > 0 && st.Peek() < x) nxt[st.Pop()] = x;
        st.Push(x);
    }
    var res = new int[nums1.Length];
    for (int i = 0; i < nums1.Length; i++)
        res[i] = nxt.TryGetValue(nums1[i], out int v) ? v : -1;
    return res;
}

2. 132 Pattern

Is there i < j < k with a[i] < a[k] < a[j]? Insight: scan from the right with a decreasing stack. When a[j] pops smaller values, each popped value is a valid "2" (it sits to the right of a bigger "3"). Keep the largest popped value as third: the bigger the "2", the easier it is to find a "1" below it. Any later (further left) value below third is the "1".

Solution: O(n) time, O(n) space 
def find_132_pattern(nums: list[int]) -> bool:
    st: list[int] = []                    # candidates for "3", decreasing
    third = float("-inf")                 # best "2" seen: popped by a bigger "3"
    for x in reversed(nums):
        if x < third:
            return True                   # x is the "1"
        while st and st[-1] < x:
            third = st.pop()              # popped values only grow
        st.append(x)
    return False

public static bool Find132Pattern(int[] nums)
{
    var st = new Stack<int>();            // candidates for "3", decreasing
    long third = long.MinValue;           // best "2" seen so far
    for (int i = nums.Length - 1; i >= 0; i--)
    {
        if (nums[i] < third) return true; // nums[i] is the "1"
        while (st.Count > 0 && st.Peek() < nums[i]) third = st.Pop();
        st.Push(nums[i]);
    }
    return false;
}

Why is one number enough? Every value still on the stack is >= third: the values that survived the pop are bigger than the value that popped, and any value pushed later that was smaller than third would already have returned True. So a new pop can only raise third, and the largest "2" is always the best one to keep.

3. Sum of Subarray Ranges

Return Σ (max − min) over all subarrays. Insight: split the sum: Σ max − Σ min. Each half is a contribution sum. Sum of maxima of a is minus the sum of minima of −a, so one helper does both. Flushing with i == n instead of a sentinel value works for any values, including negatives.

Solution: O(n) time, O(n) space 
def sum_of_mins(a: list[int]) -> int:
    n, total = len(a), 0
    st: list[int] = []
    for i in range(n + 1):
        while st and (i == n or a[st[-1]] >= a[i]):
            j = st.pop()
            left = st[-1] if st else -1
            total += a[j] * (j - left) * (i - j)
        st.append(i)
    return total

def sub_array_ranges(nums: list[int]) -> int:
    sum_max = -sum_of_mins([-x for x in nums])
    return sum_max - sum_of_mins(nums)

static long SumOfMins(long[] a)
{
    int n = a.Length;
    long total = 0;
    var st = new Stack<int>();
    for (int i = 0; i <= n; i++)
    {
        while (st.Count > 0 && (i == n || a[st.Peek()] >= a[i]))
        {
            int j = st.Pop();
            int left = st.Count > 0 ? st.Peek() : -1;
            total += a[j] * (j - left) * (i - j);
        }
        st.Push(i);
    }
    return total;
}

public static long SubArrayRanges(int[] nums)
{
    var a = Array.ConvertAll(nums, x => (long)x);
    var neg = Array.ConvertAll(nums, x => -(long)x);
    return -SumOfMins(neg) - SumOfMins(a);
}

4. Maximum Width Ramp

Find the largest j − i with i < j and a[i] <= a[j]. Insight: a start i is only worth considering if it is smaller than every start to its left (otherwise an earlier start is both further left and smaller or equal). Those prefix minima form a decreasing stack. Then scan j from the right: the first j that works for the top start is the furthest one it will ever get, so record the width and pop it.

Solution: O(n) time, O(n) space 
def max_width_ramp(nums: list[int]) -> int:
    st: list[int] = []
    for i, x in enumerate(nums):
        if not st or nums[st[-1]] > x:
            st.append(i)                  # a new prefix minimum: candidate start
    best = 0
    for j in range(len(nums) - 1, -1, -1):
        while st and nums[st[-1]] <= nums[j]:
            best = max(best, j - st.pop())  # furthest end this start will get
    return best

public static int MaxWidthRamp(int[] nums)
{
    var st = new Stack<int>();
    for (int i = 0; i < nums.Length; i++)
        if (st.Count == 0 || nums[st.Peek()] > nums[i]) st.Push(i);
    int best = 0;
    for (int j = nums.Length - 1; j >= 0 && st.Count > 0; j--)
        while (st.Count > 0 && nums[st.Peek()] <= nums[j])
            best = Math.Max(best, j - st.Pop());
    return best;
}

This is the one common problem where the stack is built in one pass and consumed in another. A decreasing stack built from the left also works with binary search per j (O(n log n)), but the reverse scan is linear.

5. Maximum Subarray Min-Product

The min-product of a subarray is min × sum. Return the maximum over all subarrays, modulo 10⁹ + 7 (maximise before the modulo). All values are positive. Insight: fix the element that is the minimum. Since everything is positive, a longer subarray has a bigger sum, so take its whole kingdom: from the previous smaller to the next smaller. Prefix sums give the kingdom's sum in O(1).

Solution: O(n) time, O(n) space 
def max_sum_min_product(nums: list[int]) -> int:
    n = len(nums)
    P = [0] * (n + 1)
    for i, x in enumerate(nums):
        P[i + 1] = P[i] + x
    best = 0
    st: list[int] = []
    for i in range(n + 1):
        while st and (i == n or nums[st[-1]] >= nums[i]):
            j = st.pop()
            left = st[-1] if st else -1
            best = max(best, nums[j] * (P[i] - P[left + 1]))   # kingdom left+1 .. i-1
        st.append(i)
    return best % (10**9 + 7)

public static int MaxSumMinProduct(int[] nums)
{
    int n = nums.Length;
    var P = new long[n + 1];
    for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
    long best = 0;
    var st = new Stack<int>();
    for (int i = 0; i <= n; i++)
    {
        while (st.Count > 0 && (i == n || nums[st.Peek()] >= nums[i]))
        {
            int j = st.Pop();
            int left = st.Count > 0 ? st.Peek() : -1;
            best = Math.Max(best, nums[j] * (P[i] - P[left + 1]));
        }
        st.Push(i);
    }
    return (int)(best % 1_000_000_007);
}

The >= tie rule underestimates some kingdoms, exactly as in the histogram, and for the same reason it does not matter: the last copy of an equal run measures the full kingdom.

6. Number of Visible People in a Queue

Heights are distinct. Person i can see person j > i if everyone between them is shorter than both. Count, for each person, how many people they can see. Insight: scan from the right with a decreasing stack of the people still visible from the left. Everyone shorter than i that i pops is someone i sees, and after i arrives they are hidden from everyone further left. If someone is left on the stack, it is the first person taller than i, and i sees them too.

Solution: O(n) time, O(n) space 
def can_see_persons_count(heights: list[int]) -> list[int]:
    ans = [0] * len(heights)
    st: list[int] = []                    # heights visible from the left, decreasing
    for i in range(len(heights) - 1, -1, -1):
        while st and st[-1] < heights[i]:
            st.pop()
            ans[i] += 1                   # i sees them, then hides them
        if st:
            ans[i] += 1                   # the first taller person
        st.append(heights[i])
    return ans

public static int[] CanSeePersonsCount(int[] heights)
{
    var ans = new int[heights.Length];
    var st = new Stack<int>();            // heights visible from the left, decreasing
    for (int i = heights.Length - 1; i >= 0; i--)
    {
        while (st.Count > 0 && st.Peek() < heights[i]) { st.Pop(); ans[i]++; }
        if (st.Count > 0) ans[i]++;
        st.Push(heights[i]);
    }
    return ans;
}

7. Max Value of Equation

Points are sorted by x. Maximise yi + yj + |xi − xj| over pairs i < j with xj − xi <= k. Insight: since xj >= xi, the value is (yj + xj) + (yi − xi). For each j, the first part is fixed, so you need the maximum of yi − xi over earlier points within distance k. That is a sliding window maximum, where the window is defined by x-coordinates. Expire from the front by distance, then drop dominated points from the back.

Solution: O(n) time, O(n) space 
from collections import deque

def find_max_value_of_equation(points: list[list[int]], k: int) -> int:
    dq: deque[int] = deque()              # indices, y − x decreasing
    best = float("-inf")
    for j, (xj, yj) in enumerate(points):
        while dq and xj - points[dq[0]][0] > k:
            dq.popleft()                  # expired: too far to the left
        if dq:
            xi, yi = points[dq[0]]
            best = max(best, yj + xj + yi - xi)
        while dq and points[dq[-1]][1] - points[dq[-1]][0] <= yj - xj:
            dq.pop()                      # dominated: older and not better
        dq.append(j)
    return best

public static int FindMaxValueOfEquation(int[][] points, int k)
{
    var dq = new LinkedList<int>();       // indices, y − x decreasing
    int best = int.MinValue;
    for (int j = 0; j < points.Length; j++)
    {
        int xj = points[j][0], yj = points[j][1];
        while (dq.Count > 0 && xj - points[dq.First!.Value][0] > k) dq.RemoveFirst();
        if (dq.Count > 0)
        {
            var p = points[dq.First!.Value];
            best = Math.Max(best, yj + xj + p[1] - p[0]);
        }
        while (dq.Count > 0 && points[dq.Last!.Value][1] - points[dq.Last.Value][0] <= yj - xj)
            dq.RemoveLast();
        dq.AddLast(j);
    }
    return best;
}

Read the answer before pushing j: the pair needs i < j, so j may not pair with itself.

8. Sum of Total Strength of Wizards

The total strength of a group of consecutive wizards is min × sum. Return the sum over all subarrays, modulo 10⁹ + 7. Insight: contribution again. Wizard j is the minimum of every subarray [s..e] with left < s <= j <= e < right (left: previous strictly smaller, right: next smaller or equal). We need the sum of the sums of those subarrays. With prefix sums P (sum(s..e) = P[e+1] − P[s]) and a prefix sum of prefix sums PP[k] = P[0] + … + P[k−1]:

Σ sums = (j − left) × (PP[right+1] − PP[j+1]) − (right − j) × (PP[j+1] − PP[left+1])

The first term adds every possible P[e+1], once per start; the second subtracts every possible P[s], once per end.

Solution: O(n) time, O(n) space 
def total_strength(strength: list[int]) -> int:
    MOD = 10**9 + 7
    n = len(strength)
    P = [0] * (n + 1)
    for i, x in enumerate(strength):
        P[i + 1] = P[i] + x
    PP = [0] * (n + 2)
    for k in range(n + 1):
        PP[k + 1] = PP[k] + P[k]
    total = 0
    st: list[int] = []
    for i in range(n + 1):
        while st and (i == n or strength[st[-1]] >= strength[i]):
            j = st.pop()
            left, right = (st[-1] if st else -1), i
            plus = (j - left) * (PP[right + 1] - PP[j + 1])
            minus = (right - j) * (PP[j + 1] - PP[left + 1])
            total += strength[j] * (plus - minus)
        st.append(i)
    return total % MOD

public static int TotalStrength(int[] strength)
{
    const long M = 1_000_000_007;
    int n = strength.Length;
    var P = new long[n + 1];
    for (int i = 0; i < n; i++) P[i + 1] = (P[i] + strength[i]) % M;
    var PP = new long[n + 2];
    for (int k = 0; k <= n; k++) PP[k + 1] = (PP[k] + P[k]) % M;
    long total = 0;
    var st = new Stack<int>();
    for (int i = 0; i <= n; i++)
    {
        while (st.Count > 0 && (i == n || strength[st.Peek()] >= strength[i]))
        {
            int j = st.Pop();
            int left = st.Count > 0 ? st.Peek() : -1, right = i;
            long plus = (j - left) * ((PP[right + 1] - PP[j + 1] + M) % M) % M;
            long minus = (right - j) * ((PP[j + 1] - PP[left + 1] + M) % M) % M;
            total = (total + strength[j] * ((plus - minus + M) % M)) % M;
        }
        st.Push(i);
    }
    return (int)total;
}

In C#, reduce every prefix value modulo M and add M before each % on a difference, so nothing goes negative or overflows. Python's big integers let you take the modulo once at the end.

Self-check

The template has a while loop inside a for loop. Why is it O(n) and not O(n²)?

Every iteration of the while loop pops one index, and each index is pushed exactly once, so it can be popped at most once. Over the whole run the while body executes at most n times in total. One call can pop many indices, but then those indices are gone for every later call. This is amortised analysis: total work ≤ n pushes + n pops.

You want "next smaller element". Should the values on the stack be increasing or decreasing from bottom to top, and why?

Increasing (non-decreasing). The stack holds elements that have not yet met a smaller element. If a waiting element sat above a bigger one, the smaller one would have popped the bigger one when it arrived. The rule is always: the stack is sorted the opposite way to the question.

In Largest Rectangle, when bar t is popped by i, why is the left wall the new top of the stack and not t − 1?

Bars between the new top and t were popped earlier, and they were popped because they were taller or equal to some later bar (at most t). So all of them are at least h[t] tall, and the rectangle of height h[t] extends over them. The new top is the first index to the left that was never popped by a bar of height ≤ h[t], which makes it the nearest shorter bar: the real wall.

Compute Sum of Subarray Minimums for [3, 1, 2, 4] with the contribution formula.

Walls (left = previous strictly smaller, right = next smaller or equal): 3 has L = 1, R = 1, so 3 · 1 · 1 = 3. 1 has L = 2, R = 3, so 1 · 2 · 3 = 6. 2 has L = 1, R = 2, so 2 · 1 · 2 = 4. 4 has L = 1, R = 1, so 4. Total 3 + 6 + 4 + 4 = 17. Check by brute force: the 10 subarrays have minimums 3, 1, 1, 1, 1, 1, 1, 2, 2, 4, which also sum to 17.

Why is the greedy in Remove K Digits correct: why delete the first digit that is bigger than its right neighbour?

Compare the numbers left to right. If num[i] > num[i+1] is the first descent, deleting num[i] leaves the prefix before it unchanged and makes position i smaller (it now holds num[i+1]). Deleting any digit before i would put a digit that is ≥ in that position (the prefix is non-decreasing), and deleting any digit after i leaves the bigger num[i] in place. So this deletion gives the smallest possible number with one digit removed, and repeating the argument k times gives the answer. The stack simply finds each next descent in O(1) amortised.

In Shortest Subarray with Sum ≥ K, the front of the deque is popped once it is "answered". Why can it never be needed again?

A start i that already works with end j gives length j − i. Any later end j' > j would give j' − i > j − i, which is longer. Since we are looking for the shortest subarray, start i has already produced its best possible answer, and keeping it can only produce worse ones.

Constrained Subsequence Sum uses dp[i] = x + max(0, window max). What does the max(0, …) mean, and what happens if you leave it out?

It means "start a new subsequence at i" when every reachable earlier dp is negative: it is better to pick nothing before i. Without it, dp[i] would be forced to extend a negative chain, so on [-1, -2, 5] with k = 1 you would get dp = [-1, -3, 2] and answer 2 instead of 5.
