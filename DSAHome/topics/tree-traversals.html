TREES

Tree Traversals

Pre/in/post-order and level-order animated with their stacks and queues, iterative versions, Morris traversal and rebuilding trees.

Beginner → Intermediate~50 min studyBuilds on: Recursion & the Call StackUpdated 2026-11-03

Every tree problem you will meet is a traversal with a little work bolted on. Count nodes, find depth, check a property, rebuild a tree, print it level by level: the question is always the same two choices. In what order do I reach the nodes? And at which moment, relative to a node's children, do I do the work? This page makes both choices visible. You will watch the call stack grow and shrink, push and pop an explicit stack by hand, thread a tree with temporary pointers so it needs no stack at all, sweep it level by level with a queue, and rebuild a tree from two of its traversals.

The invariant. A depth-first traversal walks once around the tree and passes every node three times: before its left subtree, between its subtrees, and after its right subtree. Preorder, inorder and postorder are the same walk, writing the node down at pass 1, 2 or 3. A breadth-first traversal instead uses a queue, and finishes each depth before starting the next.

Prerequisite: Recursion & the Call Stack. Everything here builds on "a function call is a frame on a stack". Trees are also graphs (connected, acyclic, n − 1 edges), so Graph Fundamentals is the general version of the BFS and DFS you see here. Next steps: Binary Search Trees, Tree Problem Patterns (diameter, path sums, LCA, serialization), and Tries.

Trees in one picture

A binary tree is either empty (None / null) or a node with a value and two binary trees: left and right. The "either empty or a node with two subtrees" phrasing is the definition you code against. Every recursive function you write on trees has the shape:

  1. Base case: the empty tree. What is the answer for None? (0 nodes, depth 0, an empty list, True…)
  2. Recursive case: get the answers for node.left and node.right, then combine them with node.val.

Words you will see constantly:

Term Meaning In the picture
root the only node without a parent 1
leaf a node with no children 4, 5, 6
depth of a node edges from the root down to it depth(5) = 2
height of a tree the maximum depth (edges on the longest root-to-leaf path) 2
subtree of v v and all its descendants {2, 4, 5}
full binary tree every node has 0 or 2 children no (3 has one child)
complete binary tree every level full except possibly the last, which fills left to right no (gap under 3)
perfect binary tree every level completely full: 2h+1 − 1 nodes no

Some books count height in nodes rather than edges (so a single node has height 1). LeetCode's "maximum depth" counts nodes. Always check which one a problem means.

TreeNode in Python and C

This is the exact class LeetCode gives you. Every snippet on this page uses it.

from collections import deque
from typing import Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


def build(arr: list) -> Optional[TreeNode]:
    """LeetCode level-order list -> tree. None means 'no child here'."""
    if not arr or arr[0] is None:
        return None
    root = TreeNode(arr[0])
    q, i = deque([root]), 1
    while q and i < len(arr):
        node = q.popleft()                    # the next parent that owns two slots
        if i < len(arr) and arr[i] is not None:
            node.left = TreeNode(arr[i])
            q.append(node.left)
        i += 1
        if i < len(arr) and arr[i] is not None:
            node.right = TreeNode(arr[i])
            q.append(node.right)
        i += 1
    return root


def serialize(root: Optional[TreeNode]) -> list:
    """Tree -> LeetCode level-order list (trailing None values trimmed)."""
    out, q = [], deque([root])
    while q:
        node = q.popleft()
        if node is None:
            out.append(None)
            continue
        out.append(node.val)
        q.append(node.left)
        q.append(node.right)
    while out and out[-1] is None:
        out.pop()
    return out

public class TreeNode
{
    public int val;
    public TreeNode left;
    public TreeNode right;
    public TreeNode(int val = 0, TreeNode left = null, TreeNode right = null)
    {
        this.val = val;
        this.left = left;
        this.right = right;
    }
}

public static class TreeIO
{
    // LeetCode level-order array -> tree. null means "no child here".
    public static TreeNode Build(int?[] a)
    {
        if (a.Length == 0 || a[0] is null) return null;
        var root = new TreeNode(a[0].Value);
        var q = new Queue<TreeNode>();
        q.Enqueue(root);
        int i = 1;
        while (q.Count > 0 && i < a.Length)
        {
            var node = q.Dequeue();               // the next parent that owns two slots
            if (i < a.Length && a[i] is int l) { node.left = new TreeNode(l); q.Enqueue(node.left); }
            i++;
            if (i < a.Length && a[i] is int r) { node.right = new TreeNode(r); q.Enqueue(node.right); }
            i++;
        }
        return root;
    }

    // Tree -> level-order list with trailing nulls trimmed.
    public static List<int?> Serialize(TreeNode root)
    {
        var output = new List<int?>();
        var q = new Queue<TreeNode>();
        q.Enqueue(root);
        while (q.Count > 0)
        {
            var node = q.Dequeue();
            if (node is null) { output.Add(null); continue; }
            output.Add(node.val);
            q.Enqueue(node.left);
            q.Enqueue(node.right);
        }
        while (output.Count > 0 && output[^1] is null) output.RemoveAt(output.Count - 1);
        return output;
    }
}

Conventions worth noticing:

  • Python: test if node is None, not if not node.val. A node whose value is 0 is falsy in the second form. if node: is fine because a TreeNode object is always truthy; only None is falsy.
  • C#: TreeNode is a reference type, so null is the empty tree. Queue<T>, Stack<T> and Dictionary<TreeNode, …> use reference equality on nodes, which is what you want (two different nodes can hold the same value). int?[] with a[i] is int x is the idiomatic way to read the nullable array.
  • Node identity is not node value. Several problems (Distance K, LCA) hand you a node object. Store nodes, not values, in maps and sets unless the problem promises distinct values.

The level-order array format

Every LeetCode tree arrives as a list like [3,9,20,null,null,15,7]. Read it the way BFS would build it: keep a queue of real nodes, and let each one, in order, take the next two entries as its left and right child. A null entry fills a slot with nothing, and because nothing was created, it never claims slots of its own. That is why it is not the heap layout (children of i are 2i+1 and 2i+2): in [1,null,2,3], the 3 is the left child of 2, at index 3, not at index 5. Type your own arrays below and watch the parent queue hand out slots.

Depth-first: three orders, one walk

Recursion performs this walk for free. Calling dfs(node.left) is walking down the left edge; returning from it is walking back up. The three places you can put "record the node" inside the function are the three passes:

Order Record the node Sequence for the tree above Typical use
preorder before both children (node, L, R) 1 2 4 5 3 6 copy/serialize a tree, pass state down (depth, path so far, bounds)
inorder between the children (L, node, R) 4 2 5 1 3 6 BSTs: inorder is sorted order; "k-th smallest", validate BST
postorder after both children (L, R, node) 4 5 2 6 3 1 compute from children's answers: height, size, diameter, delete/free a tree

Step through the recursion below. The call stack on the right is the real Python call stack: one frame per dfs call that has started and not yet returned. A frame's label says where in its body it is waiting. Use "dfs(None) calls: hide" once you have seen that every missing child is a real (cheap) call.

Things to notice in the animation:

  • The stack only ever holds one root-to-node path. That is why recursion uses O(h) memory, where h is the height: log n for a balanced tree, n for a chain.
  • A node turns green (returned) only after its whole subtree has. Postorder is literally "the order in which frames are popped".
  • Inorder emits a node exactly when control comes back up from its left child. For a node with no left child that is immediately after dfs(None) returns.

Recursive templates

def traversals(root: Optional[TreeNode]) -> tuple[list, list, list]:
    pre, ino, post = [], [], []

    def dfs(node: Optional[TreeNode]) -> None:
        if node is None:              # base case: the empty tree
            return
        pre.append(node.val)          # pass 1: before both children
        dfs(node.left)
        ino.append(node.val)          # pass 2: between the children
        dfs(node.right)
        post.append(node.val)         # pass 3: after both children

    dfs(root)
    return pre, ino, post


def max_depth(root: Optional[TreeNode]) -> int:
    """Postorder in disguise: combine the children's answers."""
    if root is None:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))

public static class Recursive
{
    public static (List<int> Pre, List<int> In, List<int> Post) Traversals(TreeNode root)
    {
        var pre = new List<int>();
        var ino = new List<int>();
        var post = new List<int>();
        void Dfs(TreeNode node)
        {
            if (node is null) return;     // base case: the empty tree
            pre.Add(node.val);            // pass 1
            Dfs(node.left);
            ino.Add(node.val);            // pass 2
            Dfs(node.right);
            post.Add(node.val);           // pass 3
        }
        Dfs(root);
        return (pre, ino, post);
    }

    public static int MaxDepth(TreeNode root) =>
        root is null ? 0 : 1 + Math.Max(MaxDepth(root.left), MaxDepth(root.right));
}

Complexity: O(n) time (each node is entered once and does O(1) work), O(h) stack space. There are also n + 1 calls on None (a binary tree with n nodes has n + 1 empty child slots), which only changes the constant.

Two ways to move information

Down (preorder style): pass it as a parameter, for example dfs(node, depth + 1) or dfs(node, lo, hi). Up (postorder style): return it, for example return 1 + max(left, right). Most tree problems need one or both. Tree Problem Patterns builds on exactly this split.

Iterative traversals with an explicit stack

Recursion is a stack you do not see. Replacing it with a stack you manage yourself gives you three things: no recursion-depth limit, the ability to pause and resume (iterators), and control over exactly when a node is "done". The catch is that each order needs a slightly different loop, because the explicit stack must remember which pass a node is waiting for.

Preorder: pop, emit, push right then left

The easiest one. A node is emitted the moment it is popped, so the stack only needs to remember subtrees still to visit. Push the right child first so that the left child ends up on top and is processed first.

Inorder: slide down the left spine

A node can only be emitted once its whole left subtree is done. So keep a pointer cur: push it and move left until you fall off the tree. The top of the stack is now the leftmost unfinished node: pop it, emit it, and continue from its right child. The stack holds exactly the ancestors whose left side you are still inside.

Postorder: the tricky one

A node must wait until both subtrees are done, so it is visited twice while sitting on the stack: once when you come back up from the left, once when you come back from the right. Only the second time may you pop it. How do you tell the two apart? Remember prev, the last node emitted. If the top's right child is prev, you just finished its right side. Watch the "peek" frames: the same node is examined twice before it turns green.

Iterative templates

def preorder_iter(root: Optional[TreeNode]) -> list[int]:
    if root is None:
        return []
    out, stack = [], [root]
    while stack:
        node = stack.pop()
        out.append(node.val)
        if node.right:
            stack.append(node.right)
        if node.left:                    # pushed last, so popped first
            stack.append(node.left)
    return out


def inorder_iter(root: Optional[TreeNode]) -> list[int]:
    out, stack, cur = [], [], root
    while cur or stack:
        while cur:                       # push the whole left spine
            stack.append(cur)
            cur = cur.left
        cur = stack.pop()                # leftmost unfinished node
        out.append(cur.val)
        cur = cur.right                  # then its right subtree
    return out


def postorder_iter(root: Optional[TreeNode]) -> list[int]:
    out, stack, cur, prev = [], [], root, None
    while cur or stack:
        while cur:
            stack.append(cur)
            cur = cur.left
        top = stack[-1]
        if top.right and top.right is not prev:
            cur = top.right              # right side not done yet: go there
        else:
            stack.pop()                  # both sides done
            out.append(top.val)
            prev = top
    return out


def postorder_reversed(root: Optional[TreeNode]) -> list[int]:
    """(root, right, left) preorder, reversed = (left, right, root)."""
    if root is None:
        return []
    out, stack = [], [root]
    while stack:
        node = stack.pop()
        out.append(node.val)
        if node.left:
            stack.append(node.left)
        if node.right:
            stack.append(node.right)
    return out[::-1]

public static class Iterative
{
    public static List<int> Preorder(TreeNode root)
    {
        var output = new List<int>();
        if (root is null) return output;
        var stack = new Stack<TreeNode>();
        stack.Push(root);
        while (stack.Count > 0)
        {
            var node = stack.Pop();
            output.Add(node.val);
            if (node.right is not null) stack.Push(node.right);
            if (node.left is not null) stack.Push(node.left);   // popped first
        }
        return output;
    }

    public static List<int> Inorder(TreeNode root)
    {
        var output = new List<int>();
        var stack = new Stack<TreeNode>();
        var cur = root;
        while (cur is not null || stack.Count > 0)
        {
            while (cur is not null) { stack.Push(cur); cur = cur.left; }
            cur = stack.Pop();
            output.Add(cur.val);
            cur = cur.right;
        }
        return output;
    }

    public static List<int> Postorder(TreeNode root)
    {
        var output = new List<int>();
        var stack = new Stack<TreeNode>();
        TreeNode cur = root, prev = null;
        while (cur is not null || stack.Count > 0)
        {
            while (cur is not null) { stack.Push(cur); cur = cur.left; }
            var top = stack.Peek();
            if (top.right is not null && top.right != prev)
            {
                cur = top.right;                                  // right side not done yet
            }
            else
            {
                stack.Pop();                                      // both sides done
                output.Add(top.val);
                prev = top;
            }
        }
        return output;
    }

    public static List<int> PostorderReversed(TreeNode root)
    {
        var output = new List<int>();
        if (root is null) return output;
        var stack = new Stack<TreeNode>();
        stack.Push(root);
        while (stack.Count > 0)
        {
            var node = stack.Pop();
            output.Add(node.val);
            if (node.left is not null) stack.Push(node.left);
            if (node.right is not null) stack.Push(node.right);
        }
        output.Reverse();
        return output;
    }
}

All four are O(n) time and O(h) extra space (postorder_reversed also stores the whole output before reversing it). Each node is pushed once and popped once; in the prev version each node is peeked at most twice.

One template for all three: the "ready" flag

If you would rather memorise one loop, push pairs (node, ready). A node popped with ready = False is expanded: push its children and itself (marked ready) in the reverse of the order you want them. A node popped with ready = True is emitted. Changing the order means reordering three pushes, which is also how you would write an iterative version of any recursive function: each frame says what is left to do.

def traverse_flags(root: Optional[TreeNode], order: str = "in") -> list[int]:
    out, stack = [], [(root, False)]
    while stack:
        node, ready = stack.pop()
        if node is None:
            continue
        if ready:
            out.append(node.val)
            continue
        # push in REVERSE of the desired order (stack = last in, first out)
        if order == "pre":
            stack += [(node.right, False), (node.left, False), (node, True)]
        elif order == "in":
            stack += [(node.right, False), (node, True), (node.left, False)]
        else:  # post
            stack += [(node, True), (node.right, False), (node.left, False)]
    return out

public static class FlagTraversal
{
    public static List<int> Traverse(TreeNode root, string order = "in")
    {
        var output = new List<int>();
        var stack = new Stack<(TreeNode Node, bool Ready)>();
        stack.Push((root, false));
        while (stack.Count > 0)
        {
            var (node, ready) = stack.Pop();
            if (node is null) continue;
            if (ready) { output.Add(node.val); continue; }
            // push in REVERSE of the desired order
            switch (order)
            {
                case "pre":
                    stack.Push((node.right, false)); stack.Push((node.left, false)); stack.Push((node, true));
                    break;
                case "in":
                    stack.Push((node.right, false)); stack.Push((node, true)); stack.Push((node.left, false));
                    break;
                default: // post
                    stack.Push((node, true)); stack.Push((node.right, false)); stack.Push((node.left, false));
                    break;
            }
        }
        return output;
    }
}

It costs up to twice as many pushes as the specialised loops, which rarely matters. In an interview, write the specialised inorder loop (it is the one that appears in BST problems) and know this one as a fallback.

Morris traversal: O(1) extra space

Both recursion and the explicit stack need O(h) memory to remember how to get back up. Morris traversal (1979) needs none. It notices that the tree already contains n + 1 null pointers doing nothing, and it borrows some of them as temporary "return addresses".

The rule, at the current node cur:

  1. No left child? Nothing comes before cur in its subtree. Emit it and go right. (The right pointer is either a real child or a thread back up: you do not need to know which.)
  2. Has a left child? Find the predecessor: step left once, then right as far as possible, stopping if you reach a pointer back to cur. - Predecessor's right is None: this is the first visit. Point it at cur (build the thread) and go left. - Predecessor's right is cur: you came back up through the thread, so the left subtree is finished. Remove the thread, emit cur, go right.

For preorder, move the emit: a node is emitted on its first visit (when the thread is built, or when it has no left child) instead of its second.

def morris_inorder(root: Optional[TreeNode]) -> list[int]:
    out, cur = [], root
    while cur:
        if cur.left is None:
            out.append(cur.val)
            cur = cur.right                       # real child or thread
        else:
            pred = cur.left
            while pred.right and pred.right is not cur:
                pred = pred.right
            if pred.right is None:                # first visit: build thread
                pred.right = cur
                cur = cur.left
            else:                                 # second visit: remove it
                pred.right = None
                out.append(cur.val)
                cur = cur.right
    return out


def morris_preorder(root: Optional[TreeNode]) -> list[int]:
    out, cur = [], root
    while cur:
        if cur.left is None:
            out.append(cur.val)
            cur = cur.right
        else:
            pred = cur.left
            while pred.right and pred.right is not cur:
                pred = pred.right
            if pred.right is None:
                out.append(cur.val)               # emit on the FIRST visit
                pred.right = cur
                cur = cur.left
            else:
                pred.right = None
                cur = cur.right
    return out

public static class Morris
{
    public static List<int> Inorder(TreeNode root)
    {
        var output = new List<int>();
        var cur = root;
        while (cur is not null)
        {
            if (cur.left is null)
            {
                output.Add(cur.val);
                cur = cur.right;                  // real child or thread
                continue;
            }
            var pred = cur.left;
            while (pred.right is not null && pred.right != cur) pred = pred.right;
            if (pred.right is null) { pred.right = cur; cur = cur.left; }       // build thread
            else { pred.right = null; output.Add(cur.val); cur = cur.right; }   // remove it
        }
        return output;
    }

    public static List<int> Preorder(TreeNode root)
    {
        var output = new List<int>();
        var cur = root;
        while (cur is not null)
        {
            if (cur.left is null)
            {
                output.Add(cur.val);
                cur = cur.right;
                continue;
            }
            var pred = cur.left;
            while (pred.right is not null && pred.right != cur) pred = pred.right;
            if (pred.right is null) { output.Add(cur.val); pred.right = cur; cur = cur.left; }
            else { pred.right = null; cur = cur.right; }
        }
        return output;
    }
}

Why is it O(n) if there is a nested loop? The inner while walks the right spine of a left subtree. Each such spine is walked exactly twice (once to build the thread, once to find and remove it), and every edge belongs to at most one such spine. So the total inner work is at most about 2n steps, plus n outer steps.

Pitfall: leaving early from a Morris loop

Morris temporarily modifies the tree. If you return or break mid-traversal (say, "find the k-th smallest and stop"), any threads still in place stay there: the tree now has cycles and every later traversal loops forever. Either finish the loop, or keep going until the threads you built are removed. It is also unsafe when another thread is reading the same tree. Postorder Morris exists, but it reverses right spines in place; in practice reach for the explicit stack instead.

Breadth-first: level by level

Depth-first goes deep along one path; breadth-first visits nodes in order of depth. A queue does this automatically: children are discovered after their parent and served after everything discovered earlier, so all of depth d leaves the queue before any of depth d + 1.

Almost every level-order problem is this loop with a different "finish the level" step. Pick a variant in the dropdown: the queue never changes, only what you do with each finished level.

def level_order(root: Optional[TreeNode]) -> list[list[int]]:
    if root is None:
        return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):          # freeze this level's size
            node = q.popleft()
            level.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        res.append(level)
    return res


def right_side_view(root: Optional[TreeNode]) -> list[int]:
    return [level[-1] for level in level_order(root)]


def average_of_levels(root: Optional[TreeNode]) -> list[float]:
    return [sum(level) / len(level) for level in level_order(root)]


def level_order_dfs(root: Optional[TreeNode]) -> list[list[int]]:
    """Same output with DFS: carry the depth and append into res[depth]."""
    res = []

    def dfs(node, depth):
        if node is None:
            return
        if depth == len(res):
            res.append([])
        res[depth].append(node.val)      # preorder + left-first = left-to-right
        dfs(node.left, depth + 1)
        dfs(node.right, depth + 1)

    dfs(root, 0)
    return res

public static class Levels
{
    public static List<List<int>> LevelOrder(TreeNode root)
    {
        var res = new List<List<int>>();
        if (root is null) return res;
        var q = new Queue<TreeNode>();
        q.Enqueue(root);
        while (q.Count > 0)
        {
            int size = q.Count;                      // freeze this level's size
            var level = new List<int>(size);
            for (int k = 0; k < size; k++)
            {
                var node = q.Dequeue();
                level.Add(node.val);
                if (node.left is not null) q.Enqueue(node.left);
                if (node.right is not null) q.Enqueue(node.right);
            }
            res.Add(level);
        }
        return res;
    }

    public static List<int> RightSideView(TreeNode root) =>
        LevelOrder(root).Select(level => level[^1]).ToList();

    public static List<double> AverageOfLevels(TreeNode root) =>
        LevelOrder(root).Select(level => level.Average(v => (double)v)).ToList();

    public static List<List<int>> LevelOrderDfs(TreeNode root)
    {
        var res = new List<List<int>>();
        void Dfs(TreeNode node, int depth)
        {
            if (node is null) return;
            if (depth == res.Count) res.Add(new List<int>());
            res[depth].Add(node.val);
            Dfs(node.left, depth + 1);
            Dfs(node.right, depth + 1);
        }
        Dfs(root, 0);
        return res;
    }
}

Complexity: O(n) time. The queue holds at most one level plus part of the next, so space is O(w) where w is the maximum width: up to about n/2 for a perfect tree (the last level), O(1) for a chain. That is the mirror image of DFS, whose space is O(h). Pick BFS when the answer is about depth or levels (minimum depth, nearest leaf, right side view): BFS can stop at the first level that satisfies the question, while DFS must explore everything.

Averages overflow too. In C#, summing a level of int values near int.MaxValue overflows silently in an unchecked context. LeetCode 637 has such tests: sum into a long (or double) as Average(v => (double)v) does above.

Vertical order and column traversal

Give every node a coordinate: the root is (row 0, column 0), a left child is one row down and one column left (c − 1), a right child is one row down and one column right (c + 1). Then "vertical order" means: group nodes by column, columns from left to right, and inside a column top to bottom. The only argument is about ties, when two nodes land on the same (row, column).

Problem Inside one column Tie (same row and column)
Binary Tree Vertical Order Traversal (314) top to bottom left to right, i.e. BFS order: no sort needed
Vertical Order Traversal of a Binary Tree (987) by row by value: sort by (column, row, value)

Must it be BFS? For 314, yes: a DFS would put a deeper node from the left subtree ahead of a shallower node from the right subtree. BFS fills each column top to bottom for free. For 987 the final sort fixes any order, so DFS works too. Try the example: the default tree has 5 and 6 sharing (2, 0). Switch the problem in the dropdown.

from collections import defaultdict


def vertical_order_bfs(root: Optional[TreeNode]) -> list[list[int]]:
    """LC 314: ties keep BFS (left-to-right) order."""
    if root is None:
        return []
    cols = defaultdict(list)
    q = deque([(root, 0)])
    lo = hi = 0
    while q:
        node, c = q.popleft()
        cols[c].append(node.val)
        lo, hi = min(lo, c), max(hi, c)
        if node.left:
            q.append((node.left, c - 1))
        if node.right:
            q.append((node.right, c + 1))
    return [cols[c] for c in range(lo, hi + 1)]   # columns are contiguous: no sort

public static class Vertical
{
    // LC 314: ties keep BFS (left-to-right) order.
    public static List<List<int>> VerticalOrderBfs(TreeNode root)
    {
        var res = new List<List<int>>();
        if (root is null) return res;
        var cols = new Dictionary<int, List<int>>();
        var q = new Queue<(TreeNode Node, int Col)>();
        q.Enqueue((root, 0));
        int lo = 0, hi = 0;
        while (q.Count > 0)
        {
            var (node, c) = q.Dequeue();
            if (!cols.TryGetValue(c, out var list)) cols[c] = list = new List<int>();
            list.Add(node.val);
            lo = Math.Min(lo, c); hi = Math.Max(hi, c);
            if (node.left is not null) q.Enqueue((node.left, c - 1));
            if (node.right is not null) q.Enqueue((node.right, c + 1));
        }
        for (int c = lo; c <= hi; c++) res.Add(cols[c]);
        return res;
    }
}

The columns that appear are always a contiguous range (a path from the root to any column passes through every column in between), so you can track lo and hi and skip sorting the keys. The LC 987 version, with its sort, is worked problem 7 below.

Rebuilding a tree from its traversals

A single traversal does not determine a tree: [1, 2] as a preorder could be 1 with a left child 2 or 1 with a right child 2. Two traversals usually do, if one of them is inorder and the values are distinct.

The recursion: the first unused value of preorder is the root of the current subtree. Look it up in inorder (hash map, O(1)): everything left of it in the current inorder window is the left subtree, everything right of it is the right subtree. Build the left subtree first (preorder lists it next), then the right. You never need to slice arrays: a shared pointer p into preorder plus the window [lo, hi] into inorder is enough.

Postorder + inorder is the mirror image. Postorder ends with the root, so read roots from the back. Reading backwards gives root, right subtree, left subtree, so you must build the right subtree first. Swap those two lines and you get a wrong tree with no error. The visualizer checks itself: try swapping two values in one input.

def build_tree_pre_in(preorder: list[int], inorder: list[int]) -> Optional[TreeNode]:
    pos = {v: i for i, v in enumerate(inorder)}
    nxt = iter(preorder)                          # roots, in the order we need them

    def build(lo: int, hi: int) -> Optional[TreeNode]:   # inorder[lo..hi]
        if lo > hi:
            return None
        root = TreeNode(next(nxt))
        mid = pos[root.val]
        root.left = build(lo, mid - 1)
        root.right = build(mid + 1, hi)
        return root

    return build(0, len(inorder) - 1)


def build_tree_post_in(inorder: list[int], postorder: list[int]) -> Optional[TreeNode]:
    pos = {v: i for i, v in enumerate(inorder)}
    nxt = reversed(postorder)                     # root, right..., left...

    def build(lo: int, hi: int) -> Optional[TreeNode]:
        if lo > hi:
            return None
        root = TreeNode(next(nxt))
        mid = pos[root.val]
        root.right = build(mid + 1, hi)           # right FIRST
        root.left = build(lo, mid - 1)
        return root

    return build(0, len(inorder) - 1)

public static class Rebuild
{
    public static TreeNode BuildTreePreIn(int[] preorder, int[] inorder)
    {
        var pos = new Dictionary<int, int>();
        for (int i = 0; i < inorder.Length; i++) pos[inorder[i]] = i;
        int p = 0;
        TreeNode Build(int lo, int hi)            // inorder[lo..hi]
        {
            if (lo > hi) return null;
            var root = new TreeNode(preorder[p++]);
            int mid = pos[root.val];
            root.left = Build(lo, mid - 1);
            root.right = Build(mid + 1, hi);
            return root;
        }
        return Build(0, inorder.Length - 1);
    }

    public static TreeNode BuildTreePostIn(int[] inorder, int[] postorder)
    {
        var pos = new Dictionary<int, int>();
        for (int i = 0; i < inorder.Length; i++) pos[inorder[i]] = i;
        int p = postorder.Length - 1;
        TreeNode Build(int lo, int hi)
        {
            if (lo > hi) return null;
            var root = new TreeNode(postorder[p--]);
            int mid = pos[root.val];
            root.right = Build(mid + 1, hi);      // right FIRST
            root.left = Build(lo, mid - 1);
            return root;
        }
        return Build(0, inorder.Length - 1);
    }
}

Complexity: O(n) time and O(n) space for the map, plus O(h) recursion. The common slower version calls inorder.index(root) and slices arrays: O(n²) on a skewed tree, both in time and in copied memory.

Preorder + postorder: unique only for full trees

Without inorder there is no way to tell a lone left child from a lone right child. LeetCode 889 therefore asks for any valid tree. The trick: after the root, the next preorder value is the root of the left subtree (choose left when ambiguous). In postorder that value comes last in its subtree, so its position marks where the left subtree ends.

def construct_from_pre_post(preorder: list[int], postorder: list[int]) -> Optional[TreeNode]:
    pos = {v: i for i, v in enumerate(postorder)}
    i = 0

    def build(lo: int, hi: int) -> Optional[TreeNode]:   # postorder[lo..hi]
        nonlocal i
        if lo > hi:
            return None
        root = TreeNode(preorder[i])
        i += 1
        if lo == hi:                              # a leaf
            return root
        m = pos[preorder[i]]                      # left child's subtree ends at m
        root.left = build(lo, m)
        root.right = build(m + 1, hi - 1)         # hi itself is the root
        return root

    return build(0, len(postorder) - 1)

public static class RebuildPrePost
{
    public static TreeNode ConstructFromPrePost(int[] preorder, int[] postorder)
    {
        var pos = new Dictionary<int, int>();
        for (int k = 0; k < postorder.Length; k++) pos[postorder[k]] = k;
        int i = 0;
        TreeNode Build(int lo, int hi)            // postorder[lo..hi]
        {
            if (lo > hi) return null;
            var root = new TreeNode(preorder[i++]);
            if (lo == hi) return root;
            int m = pos[preorder[i]];             // left child's subtree ends at m
            root.left = Build(lo, m);
            root.right = Build(m + 1, hi - 1);
            return root;
        }
        return Build(0, postorder.Length - 1);
    }
}

A tree is a graph: going up as well as down

TreeNode only points down. Questions about distance ("all nodes k edges from this one"), or about walking up from a node, need the parent too. Record parents with any traversal, and the tree becomes an undirected graph you can BFS from any node, exactly as in Graph Fundamentals. A seen set is needed again, because the edge to the parent can lead straight back.

The same trick answers "burn a tree from a node" (minutes until all nodes burn = BFS eccentricity of that node), "closest leaf to a target", and "path between two nodes". For many such questions on a static tree, Tree Problem Patterns shows faster tools: LCA and binary lifting.

N-ary trees

When a node has a children list instead of left/right, preorder and postorder and level order carry over unchanged; inorder has no meaning (there is no single "between"). The only edit to the iterative preorder is to push the children in reverse so that the first child is popped first.

class NaryNode:
    def __init__(self, val=None, children=None):
        self.val = val
        self.children = children or []


def nary_preorder(root: Optional[NaryNode]) -> list:
    out, stack = [], [root] if root else []
    while stack:
        node = stack.pop()
        out.append(node.val)
        stack.extend(reversed(node.children))     # first child ends up on top
    return out

public class NaryNode
{
    public int val;
    public IList<NaryNode> children = new List<NaryNode>();
}

public static class Nary
{
    public static List<int> Preorder(NaryNode root)
    {
        var output = new List<int>();
        if (root is null) return output;
        var stack = new Stack<NaryNode>();
        stack.Push(root);
        while (stack.Count > 0)
        {
            var node = stack.Pop();
            output.Add(node.val);
            for (int i = node.children.Count - 1; i >= 0; i--) stack.Push(node.children[i]);
        }
        return output;
    }
}

Choosing a traversal

Recognize it when

  • "Compute something from the children" (height, size, balanced?, diameter, subtree sums, delete the tree): postorder, usually as a recursive function that returns the answer.
  • "Pass something down" (depth, path so far, allowed value range, prefix): preorder, with a parameter.
  • "In sorted order", "k-th smallest", "validate a BST": inorder (iterative if you need to stop early).
  • "Level", "row", "depth d", "closest", "minimum depth", "from the right/left side": BFS with the frozen len(q) loop.
  • "Column", "vertical", "diagonal": BFS (or DFS) carrying a coordinate, then group.
  • "Given preorder/inorder/postorder, build…": the split-at-the-root recursion with a value → index map.
  • "Distance from a node", "nodes within k", "burn": parent map, then graph BFS.
  • "O(1) extra space" on a tree with no parent pointers: Morris threading (or next pointers if the problem provides them).
Method Time Extra space Modifies tree? Notes
Recursive DFS (any order) O(n) O(h) call stack no simplest; depth limit on skewed trees
Iterative pre/in-order O(n) O(h) no each node pushed and popped once
Iterative postorder (prev) O(n) O(h) no nodes peeked twice
Postorder by reversing O(n) O(n) no must store the full output first
Ready-flag stack O(n) O(h) no ≈ 2× pushes; one loop for all orders
Morris (in/pre) O(n) O(1) temporarily never exit early; not thread-safe
BFS level order O(n) O(w) queue no w ≤ ⌈n/2⌉; stops early at shallow answers
Rebuild from two traversals O(n) O(n) map builds new O(n²) with index() + slicing

h = height (log n balanced, up to n − 1 skewed). w = maximum level width.

Pitfalls

Pitfall: testing the value instead of the node

if not root.left.val: or while node and node.val: treats a node with value 0 as missing. LeetCode loves zeros in tree tests. Always test identity: if node is None, if node.left is not None, or just if node.left: (a node object is truthy, None is not).

Pitfall: BFS that forgets level boundaries

for node in q:              # BUG: iterating a deque while appending to it
    q.append(node.left)     # RuntimeError, or levels blur together

Read size = len(q) once before the inner loop and pop exactly that many. Also check children for None before enqueueing (or skip None after dequeuing); enqueueing None and then reading .val is the C# NullReferenceException classic.

Pitfall: iterative postorder without prev

If you peek the top and "go right if it has a right child", you go back into the right subtree every time you return to that node: an infinite loop. The node is visited twice and you need state (the prev pointer, the ready flag, or a second stack) to know which visit this is.

Pitfall: rebuilding with the wrong subtree first

Preorder + inorder: build left then right. Postorder + inorder (reading the postorder backwards): build right then left. With a shared index into the root list, the wrong order silently consumes the other subtree's roots. Also: inorder.index(v) inside the recursion is O(n) per node, O(n²) total. Build a map once.

Pitfall: recursion depth on real inputs

LeetCode trees with 10⁴–10⁵ nodes may be a single chain. Python stops at about 1000 frames (sys.setrecursionlimit helps, but the C stack can still overflow). C# throws a StackOverflowException that kills the process. When height can be large, use the iterative templates or BFS.

Pitfall: vertical order sorted by the wrong key

Sorting a column by value alone breaks "top to bottom"; sorting by row alone breaks the tie rule. LC 987 needs (column, row, value). And never group by drawing x-position: different layouts give different pixels, while columns are defined by the ±1 rule.

Worked problems

1. Binary Tree Zigzag Level Order Traversal (Medium)

LeetCode 103. Return the level order, but alternate direction: left to right, then right to left, and so on.

Insight. Do not change how the queue is filled; children must still be enqueued left to right or the next level comes out scrambled. Only the output of each level alternates. Either reverse every other level, or build the level in a deque and appendleft on odd levels. The BFS visualizer above defaults to zigzag: watch the res panel flip while the queue stays in order.

Solution: BFS, alternate where each value is written 
def zigzag_level_order(root: Optional[TreeNode]) -> list[list[int]]:
    if root is None:
        return []
    res, q, left_to_right = [], deque([root]), True
    while q:
        level = deque()
        for _ in range(len(q)):
            node = q.popleft()
            if left_to_right:
                level.append(node.val)
            else:
                level.appendleft(node.val)          # write it at the front
            if node.left:
                q.append(node.left)                 # queue order never changes
            if node.right:
                q.append(node.right)
        res.append(list(level))
        left_to_right = not left_to_right
    return res

public static class Zigzag
{
    public static IList<IList<int>> ZigzagLevelOrder(TreeNode root)
    {
        var res = new List<IList<int>>();
        if (root is null) return res;
        var q = new Queue<TreeNode>();
        q.Enqueue(root);
        bool leftToRight = true;
        while (q.Count > 0)
        {
            int size = q.Count;
            var level = new int[size];
            for (int k = 0; k < size; k++)
            {
                var node = q.Dequeue();
                level[leftToRight ? k : size - 1 - k] = node.val;   // write from the other end
                if (node.left is not null) q.Enqueue(node.left);
                if (node.right is not null) q.Enqueue(node.right);
            }
            res.Add(level);
            leftToRight = !leftToRight;
        }
        return res;
    }
}

O(n) time, O(w) space. The C# version knows the level size in advance, so it writes each value straight into its final slot instead of reversing.

2. Maximum Width of Binary Tree (Medium)

LeetCode 662. The width of a level is the distance between its leftmost and rightmost non-null nodes, counting the null positions in between as if the tree were complete. Return the maximum width.

Insight. Number positions like a heap: root 0, children 2i + 1 and 2i + 2. Then width = last − first + 1 on each level. The danger is size: positions double every level, so a chain of depth 3000 needs 3000-bit numbers. Subtract each level's first position before computing children; numbers then stay below the width itself.

Solution: BFS with normalised heap positions 
def width_of_binary_tree(root: Optional[TreeNode]) -> int:
    if root is None:
        return 0
    best, level = 0, [(root, 0)]
    while level:
        first = level[0][1]
        best = max(best, level[-1][1] - first + 1)
        nxt = []
        for node, i in level:
            i -= first                            # normalise: keeps numbers small
            if node.left:
                nxt.append((node.left, 2 * i + 1))
            if node.right:
                nxt.append((node.right, 2 * i + 2))
        level = nxt
    return best

public static class Width
{
    public static int WidthOfBinaryTree(TreeNode root)
    {
        if (root is null) return 0;
        long best = 0;
        var level = new List<(TreeNode Node, long Pos)> { (root, 0) };
        while (level.Count > 0)
        {
            long first = level[0].Pos;
            best = Math.Max(best, level[^1].Pos - first + 1);
            var next = new List<(TreeNode Node, long Pos)>();
            foreach (var (node, pos) in level)
            {
                long i = pos - first;                 // normalise per level
                if (node.left is not null) next.Add((node.left, 2 * i + 1));
                if (node.right is not null) next.Add((node.right, 2 * i + 2));
            }
            level = next;
        }
        return (int)best;
    }
}

O(n) time, O(w) space. Python's integers never overflow, but without normalisation they grow to thousands of bits and every arithmetic operation slows down; in C# long alone is not enough without the normalisation.

3. Construct Binary Tree from Preorder and Inorder Traversal (Medium)

LeetCode 105. Values are distinct; rebuild the tree.

Insight. This is the split recursion from Rebuilding a tree: preorder supplies roots in exactly the order the recursion needs them (root, then the whole left subtree, then the right), and inorder says how many values each side gets. A shared pointer into preorder means you never compute subarray boundaries for it at all.

Solution: shared preorder pointer, inorder window, hash map

build_tree_pre_in / Rebuild.BuildTreePreIn above is the full solution. The visualizer runs it step by step: the yellow window is the inorder range of the current call, the green node is the root just taken from preorder.

O(n) time, O(n) space. Follow-ups worth knowing:

  • Iterative version (no recursion): walk preorder with a stack. Each new value is the left child of the stack top, until the top equals the next inorder value; then pop while they match, and the next value is the right child of the last popped node.
  • Postorder + inorder (LeetCode 106): roots from the back, build right first.
  • Preorder of a BST alone (LeetCode 1008) is enough, because sorting it gives the inorder: see Binary Search Trees.

4. Flatten Binary Tree to Linked List (Medium)

LeetCode 114. Rearrange the tree in place so it becomes a "linked list" along .right pointers in preorder, with every .left set to None. Follow-up: O(1) extra space.

Insight. In preorder, the node after the left subtree's last node is the right child. And the left subtree's last preorder node is its rightmost node: exactly the Morris predecessor. So at each node with a left subtree, splice: hang cur.right on the predecessor, move cur.left to cur.right, clear cur.left, and step right. No threads to undo, because these rewirings are the answer.

Solution: Morris-style splicing, O(1) space 
def flatten(root: Optional[TreeNode]) -> None:
    cur = root
    while cur:
        if cur.left:
            pred = cur.left
            while pred.right:                     # rightmost node of the left subtree
                pred = pred.right
            pred.right = cur.right                # old right subtree goes after it
            cur.right = cur.left                  # left subtree moves to the right
            cur.left = None
        cur = cur.right

public static class Flattener
{
    public static void Flatten(TreeNode root)
    {
        var cur = root;
        while (cur is not null)
        {
            if (cur.left is not null)
            {
                var pred = cur.left;
                while (pred.right is not null) pred = pred.right;   // rightmost of left subtree
                pred.right = cur.right;
                cur.right = cur.left;
                cur.left = null;
            }
            cur = cur.right;
        }
    }
}

O(n) time: each right spine is walked once before it is spliced away. O(1) space. The recursive alternative visits in reverse preorder (right, left, node) keeping a prev pointer: node.right = prev; node.left = None; prev = node. Elegant, but O(h) stack.

5. All Nodes Distance K in Binary Tree (Medium)

LeetCode 863. Given the root, a target node and k, return the values of all nodes exactly k edges from the target.

Insight. Distances go up through parents as well as down. Record each node's parent, then BFS from the target over three neighbours (left, right, parent) for k rounds; the queue then is the answer. The visualizer above runs exactly this on the LeetCode example.

Solution: parent map + ring-by-ring BFS 
def distance_k(root: TreeNode, target: TreeNode, k: int) -> list[int]:
    parent, stack = {root: None}, [root]
    while stack:                                  # any traversal works
        node = stack.pop()
        for child in (node.left, node.right):
            if child:
                parent[child] = node
                stack.append(child)
    q, seen = deque([target]), {target}
    for _ in range(k):
        for _ in range(len(q)):                   # one ring per round
            node = q.popleft()
            for nb in (node.left, node.right, parent[node]):
                if nb and nb not in seen:
                    seen.add(nb)
                    q.append(nb)
    return [node.val for node in q]

public static class DistanceK
{
    public static IList<int> DistanceKNodes(TreeNode root, TreeNode target, int k)
    {
        var parent = new Dictionary<TreeNode, TreeNode> { [root] = null };
        var stack = new Stack<TreeNode>();
        stack.Push(root);
        while (stack.Count > 0)
        {
            var node = stack.Pop();
            foreach (var child in new[] { node.left, node.right })
                if (child is not null) { parent[child] = node; stack.Push(child); }
        }
        var q = new Queue<TreeNode>();
        q.Enqueue(target);
        var seen = new HashSet<TreeNode> { target };
        for (int d = 0; d < k; d++)
        {
            for (int size = q.Count; size > 0; size--)
            {
                var node = q.Dequeue();
                foreach (var nb in new[] { node.left, node.right, parent[node] })
                    if (nb is not null && seen.Add(nb)) q.Enqueue(nb);
            }
        }
        return q.Select(node => node.val).ToList();
    }
}

O(n) time and space. If the queue empties before k rounds, the answer is empty: the loop handles that naturally.

6. Populating Next Right Pointers in Each Node II (Medium)

LeetCode 117. Each node has an extra next pointer. Point every node to its right neighbour on the same level (or None). The tree is not necessarily perfect. Follow-up: O(1) extra space.

Insight. BFS with a queue solves it in O(w) space. For O(1), notice that once a level is linked, it is a queue: walk it with .next. While walking level d, stitch level d + 1 together behind a dummy head with a tail pointer. When level d ends, the dummy's next is the start of level d + 1.

Solution: use the finished level as the queue 
class Node:
    def __init__(self, val=0, left=None, right=None, next=None):
        self.val = val
        self.left = left
        self.right = right
        self.next = next


def connect(root: Optional[Node]) -> Optional[Node]:
    head = root                                   # first node of the current level
    while head:
        dummy = tail = Node(0)                    # builds the next level's list
        node = head
        while node:
            for child in (node.left, node.right):
                if child:
                    tail.next = child
                    tail = child
            node = node.next                      # walk the current level
        head = dummy.next
    return root

public class Node
{
    public int val;
    public Node left, right, next;
    public Node(int val = 0, Node left = null, Node right = null, Node next = null)
    {
        this.val = val; this.left = left; this.right = right; this.next = next;
    }
}

public static class NextPointers
{
    public static Node Connect(Node root)
    {
        var head = root;
        while (head is not null)
        {
            var dummy = new Node(0);
            var tail = dummy;
            for (var node = head; node is not null; node = node.next)
            {
                if (node.left is not null) { tail.next = node.left; tail = tail.next; }
                if (node.right is not null) { tail.next = node.right; tail = tail.next; }
            }
            head = dummy.next;
        }
        return root;
    }
}

O(n) time, O(1) extra space. The dummy node removes the "is this the first child on the level?" special case. For a perfect tree (LeetCode 116) it is even simpler: node.left.next = node.right and node.right.next = node.next.left.

7. Vertical Order Traversal of a Binary Tree (Hard)

LeetCode 987. Columns left to right; within a column, top to bottom; nodes at the same row and column sorted by value.

Insight. Collect (column, row, value) for every node with any traversal, sort the triples, and cut the sorted list wherever the column changes. Sorting by the whole triple encodes all three rules at once. Here is the tie case from the column picture: 6 and 1 share (2, 0). LC 987 lists them by value, 1 before 6; switch to LC 314 and BFS order puts 6 (the left one) first.

Solution: collect (col, row, val), sort, group 
def vertical_traversal(root: Optional[TreeNode]) -> list[list[int]]:
    if not root:
        return []
    entries = []                                  # (col, row, val)
    q = deque([(root, 0, 0)])
    while q:
        node, r, c = q.popleft()
        entries.append((c, r, node.val))
        if node.left:
            q.append((node.left, r + 1, c - 1))
        if node.right:
            q.append((node.right, r + 1, c + 1))
    entries.sort()                                # col, then row, then value
    res, last = [], None
    for c, r, v in entries:
        if c != last:
            res.append([])
            last = c
        res[-1].append(v)
    return res

public static class VerticalTraversal
{
    public static IList<IList<int>> Solve(TreeNode root)
    {
        var res = new List<IList<int>>();
        if (root is null) return res;
        var entries = new List<(int Col, int Row, int Val)>();
        var q = new Queue<(TreeNode Node, int Row, int Col)>();
        q.Enqueue((root, 0, 0));
        while (q.Count > 0)
        {
            var (node, r, c) = q.Dequeue();
            entries.Add((c, r, node.val));
            if (node.left is not null) q.Enqueue((node.left, r + 1, c - 1));
            if (node.right is not null) q.Enqueue((node.right, r + 1, c + 1));
        }
        entries.Sort();                           // tuples compare field by field
        int? last = null;
        foreach (var (c, _, v) in entries)
        {
            if (c != last) { res.Add(new List<int>()); last = c; }
            res[^1].Add(v);
        }
        return res;
    }
}

O(n log n) time for the sort, O(n) space. You can shave the sort to per-column sorts (bucket by column first, columns are contiguous), but the asymptotic cost is the same when one column holds most nodes.

8. Recover a Tree From Preorder Traversal (Hard)

LeetCode 1028. The input is a preorder dump like "1-2--3--4-5--6--7": each node is written as depth dashes followed by its value. If a node has one child, it is the left child. Rebuild the tree.

Insight. This is the iterative preorder in reverse. During a preorder walk the explicit stack holds the path from the root to the current node, and the stack's height is the current depth. So when you read a node of depth d, pop until the stack has exactly d nodes; the top is then its parent. The parent gets it as left if that is still free, otherwise as right.

Solution: stack of the current root-to-node path 
def recover_from_preorder(traversal: str) -> Optional[TreeNode]:
    stack, i, n = [], 0, len(traversal)
    while i < n:
        depth = 0
        while traversal[i] == "-":
            depth += 1
            i += 1
        j = i
        while j < n and traversal[j] != "-":
            j += 1
        node = TreeNode(int(traversal[i:j]))
        i = j
        while len(stack) > depth:                 # climb back to the parent
            stack.pop()
        if stack:
            parent = stack[-1]
            if parent.left is None:
                parent.left = node
            else:
                parent.right = node
        stack.append(node)
    return stack[0] if stack else None

public static class RecoverPreorder
{
    public static TreeNode RecoverFromPreorder(string traversal)
    {
        var stack = new List<TreeNode>();         // index = depth
        int i = 0, n = traversal.Length;
        while (i < n)
        {
            int depth = 0;
            while (traversal[i] == '-') { depth++; i++; }
            int value = 0;
            while (i < n && traversal[i] != '-') value = value * 10 + (traversal[i++] - '0');
            var node = new TreeNode(value);
            stack.RemoveRange(depth, stack.Count - depth);   // climb back to the parent
            if (stack.Count > 0)
            {
                var parent = stack[^1];
                if (parent.left is null) parent.left = node; else parent.right = node;
            }
            stack.Add(node);
        }
        return stack.Count > 0 ? stack[0] : null;
    }
}

O(n) time in the length of the string (each node is pushed and popped once), O(h) space. The bottom of the stack is the root, which is why the answer is stack[0].

Self-check

A node's inorder position is 0. What must be true about it, and where is it in the tree?

Nothing is emitted before it, so it has no left child, and every ancestor it hangs under it from the left. It is the end of the left spine: start at the root and keep going left. In a BST that is the minimum.

Why does iterative preorder push the right child before the left?

A stack is last in, first out. Pushing right then left leaves left on top, so the left subtree is processed completely before the right one is popped. Push them the other way round and you get (root, right, left), which, reversed, is the postorder trick.

Recursive DFS and BFS both take O(n) time. Give a tree where DFS needs far less memory than BFS, and one where it is the other way round.

A perfect tree of n nodes: DFS holds one root-to-leaf path, about log₂ n frames; BFS holds the last level, about n/2 nodes. A chain (linked-list-shaped tree): BFS holds one node at a time, while DFS recursion holds all n frames. DFS space is O(height), BFS space is O(width).

In Morris inorder, how does the algorithm know whether it is visiting a node for the first or second time?

It walks to the node's inorder predecessor (left once, then right while possible). If the predecessor's right pointer is None, no thread exists yet: first visit, so build one and go left. If it points back to the current node, we must have climbed up through that thread: second visit, so the left subtree is done; remove the thread, emit and go right.

Preorder [1, 2, 3] and postorder [3, 2, 1]. How many binary trees match? What extra information would pin it down?

Four. Each of the two nodes with one child (1 and 2) could have it on the left or the right: 2 × 2 = 4 chains. The inorder traversal pins it down: for example [3, 2, 1] means both are left children. (A "the tree is full" promise would also make pre + post unique, but no full tree has these traversals: a full tree never has a node with exactly one child.)

You need the k-th node in inorder and want to stop as soon as you find it. Which inorder implementation should you use, and which must you avoid?

Use the iterative stack version: return the moment the counter reaches k, at O(h + k) cost. Recursion also works with an early-exit flag. Avoid Morris unless you keep looping until all threads are removed: returning early leaves the tree with cycles.
