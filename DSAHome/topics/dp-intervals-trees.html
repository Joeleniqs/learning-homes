Interval & Tree DP

Solve by split point (burst balloons, matrix chain, stone merging) and by subtree (house robber III, tree cameras, rerooting).

Advanced → Expert~60 min studyBuilds on: The DP Framework, Tree Problem PatternsUpdated 2026-11-03

Where this page fits

The DP Framework gave you the five-step recipe (state, transition, base cases, order, answer). 1D & Grid DP, Knapsack DP and Sequence & String DP applied it to things you walk through from left to right: a prefix, a capacity, a pair of prefixes. This page covers the two shapes where "left to right" stops working:

  • Interval DP. The subproblem is a contiguous piece a[i..j], and the piece is solved by choosing where to split it or which element acts last. Matrix chains, bursting balloons, cutting a stick, merging stones, optimal games on a row, strange printers, removing boxes.
  • Tree DP (and its cousin, DP on a DAG). The subproblem is a subtree, solved after all of its children (post-order). Each node hands its parent a small tuple that sums up everything the parent needs to know. House Robber III, Binary Tree Cameras, picking k connected nodes, and rerooting to get an answer for every root in O(n).

Interval DP: dp[i][j] is the answer for the contiguous piece i..j, built from two strictly shorter pieces around a split or "last action" k, so you fill the table by increasing length. Tree DP: dp[v] is a tuple describing v's subtree, built from the children's tuples, so you fill it in post-order. In both, the fill order is a property of the shape (short before long, children before parent), not of the array index.

If you have not read Tree Traversals and Tree Patterns, skim their post-order sections first. Tree DP is post-order traversal, with a richer return value.

Interval DP: the shape

Take a row of things: matrices to multiply, stones to merge, balloons to burst, letters to print. Every problem in this family has the same feature: an operation on the row only ever touches a contiguous block, and once it has been done, the block to its left and the block to its right can be solved separately. So the natural subproblem is "the best I can do with exactly the piece i..j", and the natural transition is "which k splits the piece into two independent smaller pieces?"

1 · STATEdp[i][j]

The best answer (min cost, max score, number of ways…) for the contiguous piece i..j only.

2 · TRANSITIONTry every split / last action k

dp[i][j] = best over k of dp[i][k] ⊕ dp[k+1][j] ⊕ cost(i, k, j). Some problems use (i, k) and (k, j) with k shared.

3 · BASE CASESThe shortest pieces

Length 1 (one matrix, one letter) or the empty piece. Usually 0 or 1.

4 · ORDERBy increasing length

Both pieces are shorter than i..j. Fill diagonal by diagonal, or i from n−1 down to 0 with j going up.

5 · ANSWERdp[0][n−1]

The whole row. O(n²) states × O(n) split points = O(n³) time, O(n²) memory.

The fill order is the diagonal, not the row

This is the part that feels strange the first time. The table is square, but only the upper triangle (i ≤ j) means anything, and you cannot fill it row 0 first: dp[0][5] needs dp[1][5], which is in a later row. What every cell needs is cells that are shorter: some in its own row to the left (dp[i][k], the left piece), and some in its own column below it (dp[k+1][j], the right piece).

Two loop orders both satisfy "everything shorter is ready":

  • By length: for length in 2..n: for i: j = i + length − 1. This walks the diagonals, as in the picture. It is the easiest to reason about.
  • By row from the bottom: for i from n−1 down to 0: for j from i+1 up to n−1. Row i+1 (which holds every right piece dp[k+1][j]) is finished before row i starts, and inside row i the left pieces dp[i][k] with k < j are already done. It produces the same table, and it is often shorter to write.

Memoised recursion (@cache def f(i, j)) needs no order at all, and it is a perfectly good first version in an interview. Write the loops when you need the speed, or when you want to roll rows away.

Watch it: try every split point

The visualizer fills the table by length. For each cell it scans every k: the left piece is outlined in one colour, the right piece in another, and the running best is kept. Switch the problem in the drop-down. Four different-looking problems use the same loops; only the cost of joining changes:

  • matrix chain multiplication: p lists the dimensions; matrix t is p[t] × p[t+1]. Joining costs p[i]·p[k+1]·p[j+1].
  • merge adjacent stones: merging two neighbouring piles costs their total size. Joining costs sum(i..j) whatever k is.
  • cut a stick (1547): written as n; cuts. The DP runs over the sorted cut points with shared endpoints. Joining costs the length of the stick being cut.
  • polygon triangulation (1039): the vertices of a convex polygon. The DP runs over vertices with shared endpoints. Joining costs v[i]·v[k]·v[j], the triangle on edge (i, j).

"Split point" and "last operation" are the same idea. In a matrix chain, k says where the final multiplication happens: (A_i…A_k) × (A_k+1…A_j). In merging stones, k says which two piles are merged last. In a stick, the first cut splits the stick, and in a polygon, the triangle on edge (i, j) splits it. Whenever you are stuck on an interval problem, ask: what is the first or last thing that happens to the whole piece, and what does it leave behind?

Template: split-point interval DP

def matrix_chain(p: list[int]) -> int:
    n = len(p) - 1                          # matrix t has shape p[t] x p[t+1]
    dp = [[0] * n for _ in range(n)]        # dp[i][i] = 0: one matrix, no work
    for length in range(2, n + 1):          # shorter intervals first
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = min(dp[i][k] + dp[k + 1][j] + p[i] * p[k + 1] * p[j + 1]
                           for k in range(i, j))   # k = where the LAST multiply splits
    return dp[0][n - 1]

public int MatrixChain(int[] p) {
    int n = p.Length - 1;                       // matrix t has shape p[t] x p[t+1]
    var dp = new int[n, n];                     // dp[i,i] = 0
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i, j] = int.MaxValue;
            for (int k = i; k < j; k++)         // k = where the LAST multiply splits
                dp[i, j] = Math.Min(dp[i, j], dp[i, k] + dp[k + 1, j] + p[i] * p[k + 1] * p[j + 1]);
        }
    return dp[0, n - 1];
}

Complexity: O(n³) time (n²/2 cells, up to n split points each), O(n²) memory. matrix_chain([30, 35, 15, 5, 10, 20]) is 11875. To print the bracketing, store the winning k in split[i][j] and recurse: "(" + show(i, k) + show(k+1, j) + ")".

Cut a stick: the DP runs over cut points, not centimetres

LeetCode 1547 gives a stick of length n (up to 10⁶) and a list of up to 100 cut positions. Each cut costs the length of the piece being cut, and you choose the order. An interval over centimetres would be far too big. The trick is that only the cut positions matter: sort them and add both ends, pts = [0, c1, c2, …, n]. Then dp[i][j] is the cheapest way to make every cut strictly between pts[i] and pts[j], and the endpoints are shared between the two pieces (dp[i][k] and dp[k][j]), because the cut at pts[k] becomes an end of both.

def min_cost_cut(n: int, cuts: list[int]) -> int:
    pts = [0] + sorted(cuts) + [n]
    m = len(pts)
    dp = [[0] * m for _ in range(m)]        # dp[i][j]: cost to make every cut strictly between pts[i] and pts[j]
    for length in range(2, m):
        for i in range(m - length):
            j = i + length
            dp[i][j] = pts[j] - pts[i] + min(dp[i][k] + dp[k][j] for k in range(i + 1, j))
    return dp[0][m - 1]

public int MinCost(int n, int[] cuts) {
    var pts = new List<int> { 0, n };
    pts.AddRange(cuts);
    pts.Sort();
    int m = pts.Count;
    var dp = new int[m, m];                     // dp[i,j]: cost of every cut strictly between pts[i] and pts[j]
    for (int len = 2; len < m; len++)
        for (int i = 0; i + len < m; i++) {
            int j = i + len, best = int.MaxValue;
            for (int k = i + 1; k < j; k++) best = Math.Min(best, dp[i, k] + dp[k, j]);
            dp[i, j] = pts[j] - pts[i] + best;
        }
    return dp[0, m - 1];
}

Complexity: O(m³) with m = number of cuts + 2. min_cost_cut(7, [1, 3, 4, 5]) is 16. Polygon triangulation (LeetCode 1039) is the same code with pts[j] − pts[i] replaced by v[i]·v[k]·v[j] moved inside the min: the triangle (i, k, j) sits on the edge (i, j), and the two leftover polygons are i..k and k..j.

Shared or not shared? If the element at k belongs to both pieces after the split (a cut point, a polygon vertex, a balloon that is still standing), use dp[i][k] and dp[k][j], with length-1 pieces (j = i + 1) as the empty base case. If k ends the left piece and k + 1 starts the right one (matrices, piles), use dp[i][k] and dp[k+1][j], with length-1 pieces (i = j) as the base. Getting this wrong is the most common off-by-one on this page.

Burst Balloons: think about the last balloon, not the first

LeetCode 312 Hard. Bursting balloon k earns left · nums[k] · right, where left and right are its current neighbours (or 1 past either end). Burst them all; maximise the coins.

The obvious state, "which balloon do I burst first?", does not split. After k is gone, its two neighbours touch, so the left side's coins depend on the right side's balloons. The fix is to turn the question around: which balloon in the piece is burst last? While everything else in (i, j) is being burst, that last balloon k is still standing, so it acts as a wall: the left side (i, k) and the right side (k, j) never see each other. When k finally goes, everything between i and j is gone, so its neighbours are exactly i and j.

So pad the row with a 1 on each side (two walls that are never burst), and let dp[i][j] be the best total for bursting everything strictly between i and j:

dp[i][j] = max over i < k < j of dp[i][k] + v[i]·v[k]·v[j] + dp[k][j]

This is the "shared endpoint" pattern from the stick: the walls i, j and the last balloon k belong to both sides.

def max_coins(nums: list[int]) -> int:
    v = [1] + nums + [1]                    # walls that are never burst
    n = len(v)
    dp = [[0] * n for _ in range(n)]        # dp[i][j]: best for the OPEN interval (i, j)
    for length in range(2, n):
        for i in range(n - length):
            j = i + length
            for k in range(i + 1, j):       # k is the LAST balloon burst between i and j
                dp[i][j] = max(dp[i][j], dp[i][k] + v[i] * v[k] * v[j] + dp[k][j])
    return dp[0][n - 1]

public int MaxCoins(int[] nums) {
    int n = nums.Length + 2;
    var v = new int[n];
    v[0] = v[n - 1] = 1;                        // walls that are never burst
    for (int t = 0; t < nums.Length; t++) v[t + 1] = nums[t];
    var dp = new int[n, n];                     // dp[i,j]: best for the OPEN interval (i, j)
    for (int len = 2; len < n; len++)
        for (int i = 0; i + len < n; i++) {
            int j = i + len;
            for (int k = i + 1; k < j; k++)     // k is the LAST balloon burst between i and j
                dp[i, j] = Math.Max(dp[i, j], dp[i, k] + v[i] * v[k] * v[j] + dp[k, j]);
        }
    return dp[0, n - 1];
}

Complexity: O(n³) time, O(n²) memory. max_coins([3, 1, 5, 8]) is 167: burst 1, then 5, then 3, then 8.

The "last action" trick is the most reusable idea on this page. Whenever doing something to element k changes its neighbours' future (balloons, removing boxes, Zuma), choosing k first couples the two sides, and choosing it last decouples them. The last action freezes k in place as a wall while both sides are solved independently.

Games on a row: store the score difference

Two players take turns removing a number from either end of a row, and both play perfectly. Predict the Winner (486) asks whether player 1 can win. This looks like it needs two tables (my score and your score), plus whose turn it is. The trick that makes it a plain interval DP is to store one number:

dp[i][j] = (the mover's total) − (the other player's total), playing optimally on a[i..j].

Whoever moves takes an end and then becomes the other player on the piece that is left, so their lead on that smaller piece is subtracted:

dp[i][j] = max(a[i] − dp[i+1][j], a[j] − dp[i][j−1])

The minus sign does all the minimax work. There is no turn flag, because the state is "the person about to move", whoever that is. Player 1 wins (or ties) exactly when dp[0][n−1] ≥ 0.

Stone Game VII (1690) changes only the reward: removing an end stone scores the sum of the stones that remain. Use a prefix sum so each reward costs O(1). Switch modes in the visualizer and watch the two candidate moves (take left, take right) in each cell. Each candidate reads one neighbour: the cell below (i+1) or the cell to the left (j−1).

def predict_the_winner(nums: list[int]) -> bool:
    n = len(nums)
    dp = nums[:]                            # dp[j] = dp[i][j] for the row i being built
    for i in range(n - 2, -1, -1):
        for j in range(i + 1, n):           # dp[j] still holds dp[i+1][j]; dp[j-1] is already dp[i][j-1]
            dp[j] = max(nums[i] - dp[j], nums[j] - dp[j - 1])
    return dp[n - 1] >= 0

def stone_game_vii(stones: list[int]) -> int:
    n = len(stones)
    pre = list(accumulate(stones, initial=0))
    dp = [[0] * n for _ in range(n)]        # dp[i][j]: mover's best lead on stones[i..j]
    for i in range(n - 2, -1, -1):
        for j in range(i + 1, n):
            take_left = pre[j + 1] - pre[i + 1] - dp[i + 1][j]
            take_right = pre[j] - pre[i] - dp[i][j - 1]
            dp[i][j] = max(take_left, take_right)
    return dp[0][n - 1]

public bool PredictTheWinner(int[] nums) {
    int n = nums.Length;
    var dp = (int[])nums.Clone();               // dp[j] = dp[i,j] for the row i being built
    for (int i = n - 2; i >= 0; i--)
        for (int j = i + 1; j < n; j++)
            dp[j] = Math.Max(nums[i] - dp[j], nums[j] - dp[j - 1]);
    return dp[n - 1] >= 0;
}

public int StoneGameVII(int[] stones) {
    int n = stones.Length;
    var pre = new int[n + 1];
    for (int t = 0; t < n; t++) pre[t + 1] = pre[t] + stones[t];
    var dp = new int[n, n];                     // dp[i,j]: mover's best lead on stones[i..j]
    for (int i = n - 2; i >= 0; i--)
        for (int j = i + 1; j < n; j++) {
            int takeLeft = pre[j + 1] - pre[i + 1] - dp[i + 1, j];
            int takeRight = pre[j] - pre[i] - dp[i, j - 1];
            dp[i, j] = Math.Max(takeLeft, takeRight);
        }
    return dp[0, n - 1];
}

Complexity: O(n²) time. Predict the Winner rolls the table into one row, O(n) memory, because each cell reads only the row below (dp[j] before it is overwritten) and the cell to its left (dp[j−1], already overwritten with the current row). That is the same trick as the one-row grid DP in 1D & Grid DP. The Python uses from itertools import accumulate.

The rest of the Stone Game family. Stone Game (877) is this exact DP, although with an even number of piles the first player can always win by parity, so return True passes. Stone Game II, III and IV take from one end only, so their state is a suffix (dp[i], plus M in II), not an interval. They belong with 1D & Grid DP, but the "score difference, subtract the opponent's best" trick carries over unchanged.

When [i][j] is not enough: Remove Boxes

LeetCode 546 Expert. Remove a group of t adjacent boxes of one colour and earn t². Maximise the total.

Try dp[i][j] and it breaks: the best way to clear i..j depends on what lies outside it. If three more boxes of the colour boxes[i] are waiting to be glued on from the left, removing boxes[i] early wastes them. The fix is to put that outside information into the state:

dp(l, r, k) = the best score for boxes[l..r] when k extra boxes of colour boxes[l] are already glued to the left of l.

Now there are only two things box l (with its k passengers) can do:

  1. Leave now. Remove the group of k + 1 boxes: (k + 1)² + dp(l + 1, r, 0).
  2. Wait for a partner. Choose a later box m with the same colour. First clear everything strictly between them (dp(l + 1, m − 1, 0)), so that l and its passengers slide over and glue onto m: dp(m, r, k + 1).

The visualizer runs the memoised recursion on a small row. Each frame shows the call stack and the current (l, r, k), and memo hits light up when a state is reused. The state count stays tiny next to the brute force, which tries every order of removals. The code is worked problem 5 below. It costs O(n⁴) time in the worst case (n³ states, O(n) choices of m each) and O(n³) memory, which is fine for n ≤ 100.

The general lesson: if the answer for a piece depends on its surroundings, add the surroundings to the state. Here the surroundings are "how many matching boxes are glued on". Other problems use "the colour of the last thing printed" or "how many open brackets are waiting". Keep the extra dimension as small as possible: a count is fine, a full list never is.

Match the endpoint: Strange Printer and palindrome removal

Some interval problems are not "split anywhere". They are "s[j] (or s[i]) pairs up with an equal element s[k] somewhere inside". The pairing is what saves an operation.

Strange Printer (LeetCode 664): each turn prints a run of one character over any range, overwriting what is there. Print s in the fewest turns. Look at the last character, s[j]. Either it gets its own turn (dp[i][j−1] + 1), or it is printed by the same turn that prints some earlier equal character s[k]. That turn simply stretches from k to j, and whatever lies between them (k+1..j−1) is printed on top of it later, at a cost of dp[k+1][j−1].

Palindrome Removal (LeetCode 1246, the Zuma-style member of the family): one move deletes a palindromic subarray, and the pieces close up. Look at arr[i]. Either it leaves on its own (1 + dp[i+1][j]), or the last palindrome removed inside i+1..k−1 can be wrapped by arr[i] and an equal arr[k] and leave in the same move (dp[i+1][k−1] + dp[k+1][j]). Both problems are worked in full below (problems 2 and 4).

Zuma Game (488) is not this DP. In Zuma you insert balls from a hand and groups of three or more vanish, triggering chain reactions. The hand turns it into a search over (board, hand) states with memoisation, not a clean dp[i][j]. Palindrome Removal and Remove Boxes are the interval-DP members of the "remove a block, the ends close up" family.

Palindrome Partitioning II lives on the strings page. Sequence & String DP builds the interval table isPal[i][j] (by length, from isPal[i+1][j−1]) and then runs a 1D DP on top of it: cuts[j] = min(cuts[i−1] + 1) over every palindrome s[i..j]. That is a common combination: an interval table that answers a question about every piece, used by a linear DP that chooses pieces.

Knuth's optimisation at a glance

The split-point DP costs O(n³) because every cell tries every k. For some cost functions, the best split point is monotone:

opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j]

Widening the piece by one on the right never moves the best split to the left, and widening it on the left never moves it to the right. If that holds, cell (i, j) only has to try k in that window. Summed along one diagonal, the window sizes telescope: Σ (opt[i+1][j] − opt[i][j−1] + 1) is at most about n + n. So each diagonal costs O(n), and the whole table costs O(n²).

When does it hold? A sufficient condition is that the cost satisfies the quadrangle inequality, w(a, c) + w(b, d) ≤ w(a, d) + w(b, c) for a ≤ b ≤ c ≤ d, and is monotone (a piece never costs more than a piece containing it). w(i, j) = sum(i..j), as in "merge adjacent stones" and optimal binary search trees, satisfies both. The matrix-chain cost p[i]·p[k+1]·p[j+1] depends on k, so this test does not apply to it.

The visualizer runs merge-adjacent-stones with Knuth's window. For each cell it shades the k range it actually tries, and the meter compares the total k evaluations against the plain O(n³) loop.

def merge_stones_knuth(a: list[int]) -> int:
    n = len(a)
    pre = list(accumulate(a, initial=0))
    dp = [[0] * n for _ in range(n)]
    opt = [[i] * n for i in range(n)]       # opt[i][i] = i
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = inf
            for k in range(opt[i][j - 1], min(opt[i + 1][j], j - 1) + 1):
                if dp[i][k] + dp[k + 1][j] < dp[i][j]:
                    dp[i][j], opt[i][j] = dp[i][k] + dp[k + 1][j], k
            dp[i][j] += pre[j + 1] - pre[i]
    return dp[0][n - 1]

public long MergeStonesKnuth(int[] a) {
    int n = a.Length;
    var pre = new long[n + 1];
    for (int t = 0; t < n; t++) pre[t + 1] = pre[t] + a[t];
    var dp = new long[n, n];
    var opt = new int[n, n];
    for (int i = 0; i < n; i++) opt[i, i] = i;
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i, j] = long.MaxValue;
            for (int k = opt[i, j - 1]; k <= Math.Min(opt[i + 1, j], j - 1); k++)
                if (dp[i, k] + dp[k + 1, j] < dp[i, j]) { dp[i, j] = dp[i, k] + dp[k + 1, j]; opt[i, j] = k; }
            dp[i, j] += pre[j + 1] - pre[i];
        }
    return dp[0, n - 1];
}

Complexity: O(n²) time, O(n²) memory. inf is float("inf"). In an interview, write the plain O(n³) version first, then mention Knuth as the follow-up. The proof, and the related divide-and-conquer and convex hull tricks, are in Advanced DP.

Tree DP: every node returns a tuple

In a tree, the natural subproblem is "the best answer inside the subtree of v". A subtree is built from its children's subtrees, so you solve the children first. That is post-order traversal, the same recursion as computing a height in Tree Traversals. The new part is what the recursion returns.

A single number is rarely enough, because the parent has a constraint that involves the child itself ("you may not rob a child if you rob me", "I am covered if a child has a camera"). So the child returns one value per situation the parent might need: a small tuple. The parent combines its children's tuples into its own tuple, and the answer comes out of the root's tuple.

1 · STATEdp[v][s]

Best answer inside v's subtree, given that v is in situation s (robbed / not, camera / covered / waiting…).

2 · TRANSITIONCombine the children

For each situation of v, pick for each child the best situation that is compatible with it, and add them up.

3 · BASE CASESnull or leaf

Return the tuple of an empty subtree. Use ∞ for situations that are impossible.

4 · ORDERPost-order

Children before parent. The recursion does it for you; use an explicit order for very deep trees.

5 · ANSWERRead the root's tuple

Usually the best situation at the root, excluding any that need a parent (the root has none).

House Robber III: the (rob, skip) pair

LeetCode 337 Medium. Houses form a binary tree, and you may not rob a house together with its parent. A single number per node ("the best for this subtree") is not enough: the parent cannot tell whether that best already used the child, which would forbid robbing the parent. So return both:

  • rob = the best for the subtree with this node robbed = val + left.skip + right.skip.
  • skip = the best for the subtree without this node = max(left) + max(right). Each child is free to do whichever is better.

Step through it: the pair for each node lights up as the post-order reaches it, and the arrows carry the two numbers to the parent.

def rob(root: TreeNode | None) -> int:
    def go(node):                           # -> (best if node robbed, best if node skipped)
        if not node:
            return (0, 0)
        lr, ls = go(node.left)
        rr, rs = go(node.right)
        return (node.val + ls + rs,         # robbed: children must be skipped
                max(lr, ls) + max(rr, rs))  # skipped: children choose freely
    return max(go(root))

public int Rob(TreeNode? root) {
    (int robbed, int skipped) Go(TreeNode? node) {
        if (node == null) return (0, 0);
        var l = Go(node.left);
        var r = Go(node.right);
        return (node.val + l.skipped + r.skipped,                                   // children must be skipped
                Math.Max(l.robbed, l.skipped) + Math.Max(r.robbed, r.skipped));     // children choose freely
    }
    var (a, b) = Go(root);
    return Math.Max(a, b);
}

Complexity: O(n) time, O(h) stack. Compare it with the linear House Robber, where dp[i] = max(dp[i−1], dp[i−2] + a[i]). The "previous two houses" become "the child's two situations". The plain memoised version (f(node) = max(val + grandchildren, children)) is also O(n), but the tuple is shorter and never touches grandchildren.

Binary Tree Cameras: three situations

LeetCode 968 Hard. A camera watches its node, its parent and its children. Find the fewest cameras that watch every node. Each node can be in exactly one of three situations:

Situation Meaning Value from the children's tuples l, r
cam a camera sits on this node 1 + min(l) + min(r). Each child is happy in any situation, because my camera covers it.
cov no camera here, but a child's camera covers me min(l.cam + min(r.cam, r.cov), min(l.cam, l.cov) + r.cam). At least one child has a camera, and neither child is left waiting.
unc no camera, not covered yet: my parent must place one l.cov + r.cov. My children are covered without me, and neither has a camera (or I would be cov).

The empty subtree returns (cam = ∞, cov = 0, unc = ∞): it cannot hold a camera, it needs nothing, and it never makes its parent wait. At the root, unc is not allowed (nobody is above it), so the answer is min(root.cam, root.cov).

def min_camera_cover(root: TreeNode | None) -> int:
    INF = float("inf")
    def go(node):                           # -> (cam, cov, unc) for this subtree
        if not node:
            return (INF, 0, INF)            # nothing to cover; no camera can sit here
        l, r = go(node.left), go(node.right)
        cam = 1 + min(l) + min(r)                                   # my camera covers both children
        cov = min(l[0] + min(r[0], r[1]), min(l[0], l[1]) + r[0])   # a child's camera covers me
        unc = l[1] + r[1]                                           # wait for my parent's camera
        return (cam, cov, unc)
    cam, cov, _ = go(root)
    return min(cam, cov)                    # the root has no parent to cover it

public int MinCameraCover(TreeNode? root) {
    const int INF = 1_000_000;
    (int cam, int cov, int unc) Go(TreeNode? node) {
        if (node == null) return (INF, 0, INF);         // nothing to cover; no camera can sit here
        var l = Go(node.left);
        var r = Go(node.right);
        int lMin = Math.Min(l.cam, Math.Min(l.cov, l.unc));
        int rMin = Math.Min(r.cam, Math.Min(r.cov, r.unc));
        int cam = 1 + lMin + rMin;                                                 // my camera covers both children
        int cov = Math.Min(l.cam + Math.Min(r.cam, r.cov), Math.Min(l.cam, l.cov) + r.cam); // a child's camera covers me
        int unc = l.cov + r.cov;                                                   // wait for my parent's camera
        return (cam, cov, unc);
    }
    var s = Go(root);
    return Math.Min(s.cam, s.cov);                      // the root has no parent to cover it
}

Complexity: O(n) time, O(h) stack. There is also a well-known greedy (put cameras on the parents of leaves, bottom-up). It is correct, but it is hard to prove under pressure. The 3-state DP is mechanical: list the situations, write each one's compatibility rule, and the code follows.

How to find the situations. Ask: "when the parent decides about itself, what does it need to know about this child?" For the robber, it is "was the child robbed?" (2 states). For cameras, it is "does the child have a camera (which covers me)? and if not, does the child need me to have one?" (3 states). For Maximum Sum BST (worked problem 6), it is "is it a BST, and what are its min, max and sum?". The tuple is exactly the parent's questions.

Return value vs global answer: diameter and max path sum

Some tree problems return one thing to the parent but record a different thing. In Diameter of Binary Tree and Binary Tree Maximum Path Sum, the best path may bend at a node (go down both sides). A bent path cannot be extended by the parent, so it is recorded in a global best, while the function returns only the best straight path going down one side.

Returned to the parent (can be extended)

  • the longest one-sided downward path, 1 + max(left, right)
  • for max path sum: val + max(0, left, right)

Recorded at the node (cannot be extended)

  • the bent path through this node, left + right
  • for max path sum: val + max(0, left) + max(0, right)

Tree Patterns walks through this "bend" pattern step by step. In tree DP language, the return value is the tuple the parent needs, and the global best is a separate answer you collect along the way.

Tree knapsack: choose k connected nodes

Now each node returns a whole array. The problem: a rooted tree has a value on every node. Choose exactly k nodes that include the root and are connected (if you take a node, you take its parent). Maximise the total. It is the shape of "courses with prerequisites and a budget", or "keep k cities and the roads between them".

dp[v][t] = the best total using exactly t nodes from v's subtree, v included. Start with dp[v] = [−∞, val[v]] (only v). Then fold in each child c like a group knapsack: give c some number b of the slots (b = 0 means "take nothing from c") and keep the best total for each new size a + b.

def best_k_connected(parent: list[int], val: list[int], k: int) -> float:
    n = len(val)
    children = [[] for _ in range(n)]
    for v in range(1, n):
        children[parent[v]].append(v)
    NEG = float("-inf")
    def go(v):                              # dp[t]: best sum, t nodes of v's subtree, v included
        dp = [NEG, val[v]]
        for c in children[v]:
            dc = go(c)
            dc[0] = 0                       # taking nothing from c is allowed
            new = [NEG] * min(k + 1, len(dp) + len(dc) - 1)
            for a in range(1, len(dp)):     # loops bounded by sizes: O(n * k) overall
                for b in range(len(dc)):
                    if a + b < len(new):
                        new[a + b] = max(new[a + b], dp[a] + dc[b])
            dp = new
        return dp
    dp = go(0)
    return dp[k] if k < len(dp) else NEG

public long BestKConnected(int[] parent, int[] val, int k) {
    int n = val.Length;
    var children = new List<int>[n];
    for (int v = 0; v < n; v++) children[v] = new List<int>();
    for (int v = 1; v < n; v++) children[parent[v]].Add(v);
    const long NEG = long.MinValue / 4;
    long[] Go(int v) {                                  // dp[t]: best sum, t nodes of v's subtree, v included
        var dp = new long[] { NEG, val[v] };
        foreach (int c in children[v]) {
            var dc = Go(c);
            dc[0] = 0;                                  // taking nothing from c is allowed
            var nw = new long[Math.Min(k + 1, dp.Length + dc.Length - 1)];
            Array.Fill(nw, NEG);
            for (int a = 1; a < dp.Length; a++)
                for (int b = 0; b < dc.Length && a + b < nw.Length; b++)
                    nw[a + b] = Math.Max(nw[a + b], dp[a] + dc[b]);
            dp = nw;
        }
        return dp;
    }
    var res = Go(0);
    return k < res.Length ? res[k] : NEG;
}

Complexity: O(n·k) time. That is not obvious, since it looks like O(n·k²). The key is that the arrays are only as long as the subtree (capped at k + 1). Without the cap, merging two arrays of sizes s1 and s2 costs s1·s2, which is the number of node pairs that meet for the first time at v. Every pair of nodes meets exactly once, at its lowest common ancestor, so the total is O(n²). With the cap at k the same argument gives O(n·k). If you allocate full k + 1 arrays everywhere, you lose this bound.

Mind the −∞ and the 0. dp[c][0] ("take nothing from this child") must be 0, not −∞, or every node would be forced to take something from every child. But dp[v][0] for the node itself must stay −∞, because a non-empty selection inside v's subtree must include v (connectedness). Mixing these up silently gives answers that are too large.

Rerooting: an answer for every root in O(n)

Sum of Distances in Tree (834) Hard wants, for every node, the sum of its distances to all other nodes. Running the tree DP once per root is O(n²). Rerooting does all roots in two passes:

  1. Pass 1, down (post-order): root the tree at 0 and compute subtree facts: size[v] and down[v], the sum of distances from v to the nodes in its subtree: down[p] = Σ (down[c] + size[c]). Each child's nodes are one edge farther from p than from c.
  2. Pass 2, up (pre-order): compute up[v], the same quantity for the nodes outside v's subtree, from the parent's answers: up[v] = up[p] + (down[p] − down[v] − size[v]) + (n − size[v]). Take everything p sees except v's branch, and add 1 for each of the n − size[v] outside nodes, which are one step farther from v than from p.

The answer for v is down[v] + up[v]. The famous one-line form, ans[v] = ans[p] − size[v] + (n − size[v]), is the same algebra: moving the root across one edge brings size[v] nodes one step closer and pushes the other n − size[v] one step farther.

The visualizer shows both passes. In the first, values bubble up from the leaves. In the second, they flow down from the root, and each node becomes "the root" for a moment. The second mode, "farthest node from each root", shows that rerooting works for max as well as sum. That needs the top two child heights, because when you go down into the child that gave the best height, the parent must offer its second best.

def sum_of_distances_in_tree(n: int, edges: list[list[int]]) -> list[int]:
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v); adj[v].append(u)
    parent, order = [-1] * n, [0]
    for v in order:                         # BFS order: every parent before its children
        for c in adj[v]:
            if c != parent[v]:
                parent[c] = v; order.append(c)
    size, down, up = [1] * n, [0] * n, [0] * n
    for v in reversed(order[1:]):           # pass 1, children first: look down
        p = parent[v]
        size[p] += size[v]
        down[p] += down[v] + size[v]
    for v in order[1:]:                     # pass 2, parents first: bring the outside in
        p = parent[v]
        up[v] = up[p] + down[p] - (down[v] + size[v]) + (n - size[v])
    return [down[v] + up[v] for v in range(n)]

def height_from_every_root(n: int, edges: list[list[int]]) -> list[int]:
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v); adj[v].append(u)
    parent, order = [-1] * n, [0]
    for v in order:
        for c in adj[v]:
            if c != parent[v]:
                parent[c] = v; order.append(c)
    down, up = [0] * n, [0] * n
    best1, best2 = [0] * n, [0] * n         # top two values of down[child] + 1
    for v in reversed(order[1:]):
        p, h = parent[v], down[v] + 1
        if h > best1[p]:
            best1[p], best2[p] = h, best1[p]
        elif h > best2[p]:
            best2[p] = h
        down[p] = best1[p]
    for v in order[1:]:
        p = parent[v]
        other = best2[p] if down[v] + 1 == best1[p] else best1[p]   # best route from p avoiding v
        up[v] = 1 + max(up[p], other)
    return [max(down[v], up[v]) for v in range(n)]

public int[] SumOfDistancesInTree(int n, int[][] edges) {
    var adj = new List<int>[n];
    for (int v = 0; v < n; v++) adj[v] = new List<int>();
    foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
    var parent = new int[n];
    Array.Fill(parent, -1);
    var order = new List<int> { 0 };
    for (int t = 0; t < order.Count; t++)               // BFS order: every parent before its children
        foreach (int c in adj[order[t]])
            if (c != parent[order[t]]) { parent[c] = order[t]; order.Add(c); }
    var size = new int[n]; var down = new int[n]; var up = new int[n];
    Array.Fill(size, 1);
    for (int t = n - 1; t >= 1; t--) {                  // pass 1, children first: look down
        int v = order[t], p = parent[v];
        size[p] += size[v];
        down[p] += down[v] + size[v];
    }
    for (int t = 1; t < n; t++) {                       // pass 2, parents first: bring the outside in
        int v = order[t], p = parent[v];
        up[v] = up[p] + down[p] - (down[v] + size[v]) + (n - size[v]);
    }
    var ans = new int[n];
    for (int v = 0; v < n; v++) ans[v] = down[v] + up[v];
    return ans;
}

public int[] HeightFromEveryRoot(int n, int[][] edges) {
    var adj = new List<int>[n];
    for (int v = 0; v < n; v++) adj[v] = new List<int>();
    foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
    var parent = new int[n];
    Array.Fill(parent, -1);
    var order = new List<int> { 0 };
    for (int t = 0; t < order.Count; t++)
        foreach (int c in adj[order[t]])
            if (c != parent[order[t]]) { parent[c] = order[t]; order.Add(c); }
    var down = new int[n]; var up = new int[n];
    var best1 = new int[n]; var best2 = new int[n];     // top two values of down[child] + 1
    for (int t = n - 1; t >= 1; t--) {
        int v = order[t], p = parent[v], h = down[v] + 1;
        if (h > best1[p]) { best2[p] = best1[p]; best1[p] = h; }
        else if (h > best2[p]) best2[p] = h;
        down[p] = best1[p];
    }
    for (int t = 1; t < n; t++) {
        int v = order[t], p = parent[v];
        int other = down[v] + 1 == best1[p] ? best2[p] : best1[p];   // best route from p avoiding v
        up[v] = 1 + Math.Max(up[p], other);
    }
    var ans = new int[n];
    for (int v = 0; v < n; v++) ans[v] = Math.Max(down[v], up[v]);
    return ans;
}

Complexity: O(n) time and memory for both. Both passes are iterative over a BFS order (reversed for pass 1), so a path-shaped tree with 3·10⁴ nodes cannot overflow the recursion stack. height_from_every_root gives each node's eccentricity: the nodes where it is smallest are the centres used by Minimum Height Trees (310).

Rerooting recipe. You need it when the question says "for every node as the root" (or "for each node, over the whole tree") and one root costs O(n).

  1. Solve it for root 0 with a normal tree DP (down).
  2. Write how a node's answer changes when the root moves across one edge p → v. Usually that is "remove v's contribution from p, add p's remaining side to v".
  3. If "remove v's contribution" is not a subtraction (max, min, gcd), keep the top two (or prefix and suffix aggregates over the children) so you can exclude one child in O(1).

DP on a DAG: topological order is the fill order

Every DP is secretly a graph: states are nodes, and "this state reads that state" is an edge. The fill order is any topological order of that graph (The DP Framework draws this explicitly). Interval DP uses "by length", and tree DP uses post-order, both because those are topological orders of their dependency graphs. When the problem hands you a DAG directly, use Kahn's algorithm as the loop:

  • Longest path: best[v] = max(best[u] + 1) over edges u → v. A node is processed only when its in-degree reaches 0, so all of its predecessors are final.
  • Count paths s → t: ways[v] = Σ ways[u], starting from ways[s] = 1.
  • Cycle check for free: if fewer than n nodes are ever popped, the graph has a cycle, and "longest path" is undefined (worked problem 8 relies on this).
def longest_path_dag(n: int, edges: list[list[int]]) -> int:
    adj, indeg = [[] for _ in range(n)], [0] * n
    for u, v in edges:
        adj[u].append(v); indeg[v] += 1
    q = deque(v for v in range(n) if indeg[v] == 0)
    best = [0] * n                          # edges on the longest path ending at v
    while q:
        u = q.popleft()                     # every predecessor of u is already final
        for v in adj[u]:
            best[v] = max(best[v], best[u] + 1)
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return max(best)

def count_paths_dag(n: int, edges: list[list[int]], s: int, t: int) -> int:
    adj, indeg = [[] for _ in range(n)], [0] * n
    for u, v in edges:
        adj[u].append(v); indeg[v] += 1
    q = deque(v for v in range(n) if indeg[v] == 0)
    ways = [0] * n
    ways[s] = 1
    while q:
        u = q.popleft()
        for v in adj[u]:
            ways[v] += ways[u]
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return ways[t]

public int LongestPathDag(int n, int[][] edges) {
    var adj = new List<int>[n];
    for (int v = 0; v < n; v++) adj[v] = new List<int>();
    var indeg = new int[n];
    foreach (var e in edges) { adj[e[0]].Add(e[1]); indeg[e[1]]++; }
    var q = new Queue<int>();
    for (int v = 0; v < n; v++) if (indeg[v] == 0) q.Enqueue(v);
    var best = new int[n];                              // edges on the longest path ending at v
    while (q.Count > 0) {
        int u = q.Dequeue();                            // every predecessor of u is already final
        foreach (int v in adj[u]) {
            best[v] = Math.Max(best[v], best[u] + 1);
            if (--indeg[v] == 0) q.Enqueue(v);
        }
    }
    return best.Max();
}

public long CountPathsDag(int n, int[][] edges, int s, int t) {
    var adj = new List<int>[n];
    for (int v = 0; v < n; v++) adj[v] = new List<int>();
    var indeg = new int[n];
    foreach (var e in edges) { adj[e[0]].Add(e[1]); indeg[e[1]]++; }
    var q = new Queue<int>();
    for (int v = 0; v < n; v++) if (indeg[v] == 0) q.Enqueue(v);
    var ways = new long[n];
    ways[s] = 1;
    while (q.Count > 0) {
        int u = q.Dequeue();
        foreach (int v in adj[u]) {
            ways[v] += ways[u];
            if (--indeg[v] == 0) q.Enqueue(v);
        }
    }
    return ways[t];
}

Complexity: O(V + E) time and memory. The Python uses from collections import deque. Longest path is NP-hard in a general graph, but on a DAG it is this easy, because the order removes every cycle. The same loop works for weighted longest or shortest paths: replace + 1 with + w. The C# best.Max() needs using System.Linq;.

Recognize it, cost it, avoid the traps

Reach for interval DP when:

  • the operation always acts on a contiguous block, and afterwards the left and right sides close up or stay independent (merge, burst, cut, print, remove a palindrome);
  • the input is small (n ≤ 500 for O(n³), n ≤ 100 for O(n⁴)), which is a strong hint on its own;
  • two players take from either end of a row;
  • the statement says "bracket", "parenthesise", "triangulate", or "in any order" about neighbours.

Reach for tree DP when:

  • the input is a tree, and a choice at a node constrains its parent or children (no adjacent picks, coverage, colouring);
  • you need "the best subtree / path / selection" and the brute force enumerates subsets of nodes;
  • "for every node as the root" appears (rerooting);
  • the graph is a DAG (or the state graph is), and you need longest, shortest or count of paths.
Pattern State Transition Time Memory
Split point (matrix chain, merge stones, stick) dp[i][j] every k in i..j O(n³) O(n²)
Last action (burst balloons) dp[i][j], open interval every last k O(n³) O(n²)
End-removal game dp[i][j] = mover's lead 2 choices O(n²) O(n) rolled
Match the endpoint (printer, palindrome removal) dp[i][j] every equal s[k] O(n³) O(n²)
Extra context (remove boxes) dp[l][r][k] every equal m O(n⁴) O(n³)
Knuth-optimised split dp[i][j] + opt[i][j] k in an opt window O(n²) O(n²)
Tree tuple (robber, cameras) dp[v][s], s small combine children O(n·s²) O(h) stack
Tree knapsack dp[v][t], t ≤ k merge child arrays O(n·k) O(n·k)
Rerooting down[v], up[v] two passes O(n) O(n)
DAG paths best[v] / ways[v] over in-edges, topological order O(V + E) O(V)

The traps that cost the most time:

  • Filling row 0 first. dp[0][j] needs row k + 1 > 0. Fill by length, or i from the bottom.
  • Shared vs separate endpoints. dp[i][k] + dp[k][j] (cut points, walls, polygon vertices) vs dp[i][k] + dp[k+1][j] (matrices, piles). Each has a different base case and a different k range.
  • Thinking "first" when you need "last". If removing k changes its neighbours, choose the last one.
  • A state that ignores the surroundings. If the best for i..j depends on what is glued on outside, add that to the state (Remove Boxes).
  • A tree tuple that is missing a situation. If you find yourself checking a grandchild, the child's tuple is too small.
  • Recursion depth. Trees and DAGs with 10⁵ nodes can be paths. Use an explicit BFS order, or raise the recursion limit (Python) and test a path.
  • Rerooting with max. You cannot "subtract" a max: keep the top two.

Worked problems

Each problem is solved in Python and C#. The solutions were checked against a brute force (trying every order, subset or root) on random small inputs. The Python snippets assume from functools import cache, from itertools import accumulate, from collections import deque and inf = float("inf").

1. Minimum Cost Tree From Leaf Values: a split DP in disguise

LeetCode 1130 Medium. Build a binary tree whose in-order leaves are arr. Every internal node's value is (largest leaf on its left) × (largest leaf on its right). Minimise the sum of the internal nodes.

Key insight. The root splits arr into a left block arr[i..k] and a right block arr[k+1..j], and each block is again a tree. That is exactly the matrix-chain bracketing. The cost of joining is max(i..k) · max(k+1..j), so precompute mx[i][j] once.

Solution: split DP with a range-max table, O(n³)

def mct_from_leaf_values(arr: list[int]) -> int:
    n = len(arr)
    mx = [[0] * n for _ in range(n)]        # mx[i][j] = max(arr[i..j])
    for i in range(n):
        mx[i][i] = arr[i]
        for j in range(i + 1, n):
            mx[i][j] = max(mx[i][j - 1], arr[j])
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = min(dp[i][k] + dp[k + 1][j] + mx[i][k] * mx[k + 1][j]
                           for k in range(i, j))
    return dp[0][n - 1]

public int MctFromLeafValues(int[] arr) {
    int n = arr.Length;
    var mx = new int[n, n];                             // mx[i,j] = max(arr[i..j])
    for (int i = 0; i < n; i++) {
        mx[i, i] = arr[i];
        for (int j = i + 1; j < n; j++) mx[i, j] = Math.Max(mx[i, j - 1], arr[j]);
    }
    var dp = new int[n, n];
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i, j] = int.MaxValue;
            for (int k = i; k < j; k++)
                dp[i, j] = Math.Min(dp[i, j], dp[i, k] + dp[k + 1, j] + mx[i, k] * mx[k + 1, j]);
        }
    return dp[0, n - 1];
}

Complexity: O(n³) time, O(n²) memory. For [6, 2, 4] the answer is 32. There is also an O(n) greedy with a decreasing monotonic stack: always pair the smallest leaf with its smaller neighbour. It makes a good follow-up, but the DP is the version you can derive under pressure.

2. Strange Printer: s[j] rides along with an earlier equal letter

LeetCode 664 Hard. The printer prints a run of one character over any range, overwriting. Find the fewest turns that print s.

Key insight. Look at the last character s[j]. Either it costs its own turn (dp[i][j−1] + 1), or the turn that prints some equal s[k] (with i ≤ k < j) is simply stretched to reach j. Then s[k+1..j−1] is printed later on top of it, independently: dp[i][k] + dp[k+1][j−1]. Duplicate neighbours are handled automatically.

Solution: interval DP matching s[j] with an equal s[k], O(n³)

def strange_printer(s: str) -> int:
    n = len(s)
    dp = [[0] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):
        dp[i][i] = 1
        for j in range(i + 1, n):
            dp[i][j] = dp[i][j - 1] + 1                     # s[j] gets its own turn
            for k in range(i, j):
                if s[k] == s[j]:                            # s[j] rides on the turn that prints s[k]
                    inner = dp[k + 1][j - 1] if k + 1 <= j - 1 else 0
                    dp[i][j] = min(dp[i][j], dp[i][k] + inner)
    return dp[0][n - 1]

public int StrangePrinter(string s) {
    int n = s.Length;
    var dp = new int[n, n];
    for (int i = n - 1; i >= 0; i--) {
        dp[i, i] = 1;
        for (int j = i + 1; j < n; j++) {
            dp[i, j] = dp[i, j - 1] + 1;                // s[j] gets its own turn
            for (int k = i; k < j; k++)
                if (s[k] == s[j]) {                     // s[j] rides on the turn that prints s[k]
                    int inner = k + 1 <= j - 1 ? dp[k + 1, j - 1] : 0;
                    dp[i, j] = Math.Min(dp[i, j], dp[i, k] + inner);
                }
        }
    }
    return dp[0, n - 1];
}

Complexity: O(n³) time, O(n²) memory. "aaabbb" takes 2 turns and "aba" takes 2. The brute force used for checking is a BFS over every partially printed string.

3. Minimum Cost to Merge Stones: when a split must leave exactly one pile

LeetCode 1000 Hard. Each move merges exactly K consecutive piles into one, costing their total. Find the minimum cost to end with one pile, or −1 if that is impossible.

Key insight. Each merge removes K − 1 piles, so n piles can become one only if (n − 1) % (K − 1) == 0. Let dp[i][j] be the cheapest way to squeeze i..j into as few piles as possible (that number is fixed by the length). Split so that the left part becomes exactly one pile: its length must be 1, K, 2K − 1, …, so m steps by K − 1. When i..j itself can become one pile, add the final merge, which costs sum(i..j) whatever happened before.

Solution: split with step K − 1, O(n³ / K)

def merge_stones(stones: list[int], K: int) -> int:
    n = len(stones)
    if (n - 1) % (K - 1):
        return -1
    pre = list(accumulate(stones, initial=0))
    dp = [[0] * n for _ in range(n)]        # dp[i][j]: min cost to squeeze i..j into as few piles as possible
    for length in range(K, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = min(dp[i][m] + dp[m + 1][j] for m in range(i, j, K - 1))
            if (j - i) % (K - 1) == 0:      # i..j can now become ONE pile: pay its sum
                dp[i][j] += pre[j + 1] - pre[i]
    return dp[0][n - 1]

public int MergeStones(int[] stones, int K) {
    int n = stones.Length;
    if ((n - 1) % (K - 1) != 0) return -1;
    var pre = new int[n + 1];
    for (int t = 0; t < n; t++) pre[t + 1] = pre[t] + stones[t];
    var dp = new int[n, n];                             // min cost to squeeze i..j into as few piles as possible
    for (int len = K; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i, j] = int.MaxValue;
            for (int m = i; m < j; m += K - 1)
                dp[i, j] = Math.Min(dp[i, j], dp[i, m] + dp[m + 1, j]);
            if ((j - i) % (K - 1) == 0) dp[i, j] += pre[j + 1] - pre[i];   // i..j becomes ONE pile
        }
    return dp[0, n - 1];
}

Complexity: O(n³ / K) time, O(n²) memory. [3, 2, 4, 1] with K = 2 costs 20, and [3, 5, 1, 2, 6] with K = 3 costs 25. Pieces shorter than K cost 0, since they cannot merge at all, and the loops start at length K. With K = 2 this is the "merge adjacent stones" mode of the split visualizer.

4. Palindrome Removal: arr[i] wraps the last palindrome inside

LeetCode 1246 Hard. One move removes a palindromic subarray, and the neighbours close up. Find the fewest moves that empty the array.

Key insight. Follow arr[i]. It leaves either on its own (1 + dp[i+1][j]), or together with its twin when arr[i+1] is equal (1 + dp[i+2][j]), or as the outer layer of some palindrome: if arr[k] == arr[i], clear i+1..k−1 so that its last move removes a palindrome P. Then arr[i] P arr[k] is also a palindrome, and it leaves in that same move, for free. Cost: dp[i+1][k−1] + dp[k+1][j].

Solution: interval DP wrapping with equal ends, O(n³)

def minimum_moves(arr: list[int]) -> int:
    n = len(arr)
    dp = [[0] * (n + 1) for _ in range(n + 1)]   # dp[i][j] for arr[i..j]; empty ranges are 0
    for i in range(n - 1, -1, -1):
        for j in range(i, n):
            best = 1 + dp[i + 1][j]                  # arr[i] removed on its own
            if i + 1 <= j and arr[i] == arr[i + 1]:
                best = min(best, 1 + dp[i + 2][j])   # "x x" removed together
            for k in range(i + 2, j + 1):
                if arr[i] == arr[k]:                 # arr[i], arr[k] wrap the last palindrome removed inside
                    best = min(best, dp[i + 1][k - 1] + dp[k + 1][j])
            dp[i][j] = best
    return dp[0][n - 1]

public int MinimumMoves(int[] arr) {
    int n = arr.Length;
    var dp = new int[n + 1, n + 1];                     // dp[i,j] for arr[i..j]; empty ranges are 0
    for (int i = n - 1; i >= 0; i--)
        for (int j = i; j < n; j++) {
            int best = 1 + dp[i + 1, j];                // arr[i] removed on its own
            if (i + 1 <= j && arr[i] == arr[i + 1])
                best = Math.Min(best, 1 + dp[i + 2, j]);   // "x x" removed together
            for (int k = i + 2; k <= j; k++)
                if (arr[i] == arr[k])                   // arr[i], arr[k] wrap the last palindrome removed inside
                    best = Math.Min(best, dp[i + 1, k - 1] + dp[k + 1, j]);
            dp[i, j] = best;
        }
    return dp[0, n - 1];
}

Complexity: O(n³) time, O(n²) memory. [1, 3, 4, 1, 5] takes 3 moves: remove 4, then 1 3 1, then 5. The table has an extra row and column so that dp[i+2][j] and dp[k+1][j] can point past the end and read 0. Note that wrapping costs no extra move, because the wrapped palindrome was going to be removed anyway.

5. Remove Boxes: carry the glued boxes in the state

LeetCode 546 Expert. Remove t adjacent boxes of the same colour for t² points. Maximise the total.

Key insight. This is the third dimension from the Remove Boxes section above. dp(l, r, k) says k boxes of colour boxes[l] are glued on the left. Two moves: remove the group now, or clear l+1..m−1 to join a later box m of the same colour. Before branching, absorb the run of equal boxes that starts at l into k. That one while loop removes most of the duplicate states.

Solution: memoised dp(l, r, k), O(n⁴) worst case

def remove_boxes(boxes: list[int]) -> int:
    @cache
    def dp(l: int, r: int, k: int) -> int:  # k extra boxes equal to boxes[l] glued on the left
        if l > r:
            return 0
        while l < r and boxes[l + 1] == boxes[l]:
            l += 1; k += 1
        best = (k + 1) ** 2 + dp(l + 1, r, 0)            # remove the group now
        for m in range(l + 1, r + 1):
            if boxes[m] == boxes[l]:                       # clear l+1..m-1, then join boxes[m]
                best = max(best, dp(l + 1, m - 1, 0) + dp(m, r, k + 1))
        return best
    return dp(0, len(boxes) - 1, 0)

public int RemoveBoxes(int[] boxes) {
    int n = boxes.Length;
    var memo = new int[n, n, n];                        // 0 = not computed yet (every real answer is >= 1)
    int Dp(int l, int r, int k) {                       // k extra boxes equal to boxes[l] glued on the left
        if (l > r) return 0;
        while (l < r && boxes[l + 1] == boxes[l]) { l++; k++; }
        if (memo[l, r, k] != 0) return memo[l, r, k];
        int best = (k + 1) * (k + 1) + Dp(l + 1, r, 0);           // remove the group now
        for (int m = l + 1; m <= r; m++)
            if (boxes[m] == boxes[l])                              // clear l+1..m-1, then join boxes[m]
                best = Math.Max(best, Dp(l + 1, m - 1, 0) + Dp(m, r, k + 1));
        return memo[l, r, k] = best;
    }
    return Dp(0, n - 1, 0);
}

Complexity: O(n³) states and O(n) work each, so O(n⁴) worst case, but far less in practice. [1, 3, 2, 2, 2, 3, 4, 3, 1] scores 23. In Python, @cache on a 100³ state space is fine. In C#, the flat int[n, n, n] array beats a dictionary by a wide margin.

6. Maximum Sum BST in Binary Tree: a four-field tuple

LeetCode 1373 Hard. Find the largest sum of keys of any subtree that is a valid BST. The empty BST counts, so the answer is at least 0.

Key insight. To decide whether v's subtree is a BST, the parent's question is "are both children BSTs, and does left.max < v < right.min?". So each child returns (is_bst, min, max, sum). An empty child returns (True, +∞, −∞, 0), so the comparisons pass without special cases. Record each valid sum in a global best.

Solution: post-order tuple, O(n)

def max_sum_bst(root: TreeNode | None) -> int:
    best = 0
    def go(node):                           # -> (is_bst, min, max, sum) of the subtree
        nonlocal best
        if not node:
            return (True, inf, -inf, 0)
        lb, llo, lhi, ls = go(node.left)
        rb, rlo, rhi, rs = go(node.right)
        if lb and rb and lhi < node.val < rlo:
            total = ls + rs + node.val
            best = max(best, total)
            return (True, min(llo, node.val), max(rhi, node.val), total)
        return (False, 0, 0, 0)             # values do not matter once it is not a BST
    go(root)
    return best

public int MaxSumBST(TreeNode? root) {
    int best = 0;
    (bool bst, int lo, int hi, int sum) Go(TreeNode? node) {
        if (node == null) return (true, int.MaxValue, int.MinValue, 0);
        var l = Go(node.left);
        var r = Go(node.right);
        if (l.bst && r.bst && l.hi < node.val && node.val < r.lo) {
            int total = l.sum + r.sum + node.val;
            best = Math.Max(best, total);
            return (true, Math.Min(l.lo, node.val), Math.Max(r.hi, node.val), total);
        }
        return (false, 0, 0, 0);                        // values do not matter once it is not a BST
    }
    Go(root);
    return best;
}

Complexity: O(n) time, O(h) stack. Notice min(llo, node.val): when the left child is empty, llo is +∞, and the subtree's minimum is the node itself. The sum can be negative, which is why best starts at 0 (the empty tree) and not at the root's sum.

7. Count Number of Possible Root Nodes: rerooting a count

LeetCode 2581 Hard. Bob guesses pairs "u is the parent of v". For how many choices of root are at least k guesses correct?

Key insight. Count the correct guesses for root 0 with one traversal. Moving the root from p to its child v flips only the edge p–v: the guess (p, v) stops being true and the guess (v, p) starts being true. Every other parent relation is unchanged. So correct[v] = correct[p] − [(p,v) guessed] + [(v,p) guessed], in O(1) per node.

Solution: rerooting with a hash set of guesses, O(n + g)

def root_count(edges: list[list[int]], guesses: list[list[int]], k: int) -> int:
    n = len(edges) + 1
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v); adj[v].append(u)
    g = {(u, v) for u, v in guesses}
    parent, order = [-1] * n, [0]
    for v in order:
        for c in adj[v]:
            if c != parent[v]:
                parent[c] = v; order.append(c)
    correct = [0] * n
    correct[0] = sum((parent[v], v) in g for v in order[1:])   # one full count for root 0
    for v in order[1:]:                     # move the root across edge (p, v)
        p = parent[v]
        correct[v] = correct[p] - ((p, v) in g) + ((v, p) in g)
    return sum(c >= k for c in correct)

public int RootCount(int[][] edges, int[][] guesses, int k) {
    int n = edges.Length + 1;
    var adj = new List<int>[n];
    for (int v = 0; v < n; v++) adj[v] = new List<int>();
    foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
    var g = new HashSet<long>();
    foreach (var x in guesses) g.Add((long)x[0] * n + x[1]);
    var parent = new int[n];
    Array.Fill(parent, -1);
    var order = new List<int> { 0 };
    for (int t = 0; t < order.Count; t++)
        foreach (int c in adj[order[t]])
            if (c != parent[order[t]]) { parent[c] = order[t]; order.Add(c); }
    var correct = new int[n];
    for (int t = 1; t < n; t++)                         // one full count for root 0
        if (g.Contains((long)parent[order[t]] * n + order[t])) correct[0]++;
    int res = correct[0] >= k ? 1 : 0;
    for (int t = 1; t < n; t++) {                       // move the root across edge (p, v)
        int v = order[t], p = parent[v];
        correct[v] = correct[p] - (g.Contains((long)p * n + v) ? 1 : 0) + (g.Contains((long)v * n + p) ? 1 : 0);
        if (correct[v] >= k) res++;
    }
    return res;
}

Complexity: O(n + g) time and memory. Both passes are iterative over a BFS order. This is the cleanest example of the rerooting rule "write what changes when the root crosses one edge": here only one edge changes direction.

8. Largest Color Value in a Directed Graph: DP over a topological order

LeetCode 1857 Hard. Every node has a colour a–z. A path's colour value is the count of its most frequent colour. Return the largest colour value over all paths, or −1 if the graph has a cycle.

Key insight. Run "longest path on a DAG" 26 times at once: cnt[v][c] = the most nodes of colour c on any path that ends at v. Kahn's algorithm gives the order (every predecessor is final before v is popped), and it also detects the cycle: if some node is never popped, there is one.

Solution: Kahn's order with a 26-wide DP row, O(26 · (V + E))

def largest_path_value(colors: str, edges: list[list[int]]) -> int:
    n = len(colors)
    adj, indeg = [[] for _ in range(n)], [0] * n
    for u, v in edges:
        adj[u].append(v); indeg[v] += 1
    cnt = [[0] * 26 for _ in range(n)]      # cnt[v][c]: most c-coloured nodes on a path ending at v
    q = deque(v for v in range(n) if indeg[v] == 0)
    seen = best = 0
    while q:
        u = q.popleft(); seen += 1
        cnt[u][ord(colors[u]) - 97] += 1
        best = max(best, max(cnt[u]))
        for v in adj[u]:
            for c in range(26):
                cnt[v][c] = max(cnt[v][c], cnt[u][c])
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return best if seen == n else -1        # some node never reached in-degree 0: cycle

public int LargestPathValue(string colors, int[][] edges) {
    int n = colors.Length;
    var adj = new List<int>[n];
    for (int v = 0; v < n; v++) adj[v] = new List<int>();
    var indeg = new int[n];
    foreach (var e in edges) { adj[e[0]].Add(e[1]); indeg[e[1]]++; }
    var cnt = new int[n, 26];                           // most c-coloured nodes on a path ending at v
    var q = new Queue<int>();
    for (int v = 0; v < n; v++) if (indeg[v] == 0) q.Enqueue(v);
    int seen = 0, best = 0;
    while (q.Count > 0) {
        int u = q.Dequeue(); seen++;
        best = Math.Max(best, ++cnt[u, colors[u] - 'a']);
        foreach (int v in adj[u]) {
            for (int c = 0; c < 26; c++) cnt[v, c] = Math.Max(cnt[v, c], cnt[u, c]);
            if (--indeg[v] == 0) q.Enqueue(v);
        }
    }
    return seen == n ? best : -1;                       // a node never reached in-degree 0: cycle
}

Complexity: O(26·(V + E)) time, O(26·V) memory. "abaca" with edges 0→1, 0→2, 2→3, 3→4 gives 3 (path 0→2→3→4 has three as). A self-loop 0→0 gives −1. Taking the max per colour independently is safe, because each colour's best path can be different, and the answer only needs the best over all colours.

Check yourself

1. Why can't you fill the interval table row by row starting at row 0?

dp[0][j] needs the right pieces dp[k+1][j], which sit in later rows (k + 1 > 0). Every cell depends on cells to its left in the same row and below it in the same column. So fill by length (diagonal by diagonal), or run i from n − 1 down to 0 with j going up. Both finish every shorter piece first.

2. In Burst Balloons, what goes wrong if k is the first balloon to burst in (i, j)?

After k bursts, its neighbours k − 1 and k + 1 become adjacent, so later coins on the left depend on balloons on the right. The two sides are no longer independent subproblems. If k is the last to burst, it stays as a wall while both sides are cleared, and when it finally goes, its neighbours are exactly the walls i and j, so its coins v[i]·v[k]·v[j] are known.

3. In Cut a Stick, what are dp[i][i + 1] and the k range, and why?

dp[i][i + 1] = 0: there is no cut point strictly between two neighbouring points, so there is nothing to do. The range is i < k < j, because pts[k] is the first cut made in the piece. It becomes an endpoint of both remaining pieces, which is why the transition is dp[i][k] + dp[k][j] (shared k), not dp[k+1][j].

4. Why does House Robber III fail if each node returns only "the best for my subtree"?

The parent cannot tell whether that best robbed the child. If it did, the parent cannot be robbed on top of it. If it did not, it can. Example: a root of 5 with a single child of 4, whose child is 10. The child's best is 10 (skip 4, rob 10), but whether the root can add itself depends on whether the child's best used the child (it did not, so 5 + 10 = 15). Returning (rob, skip) gives the parent exactly that information.

5. In Binary Tree Cameras, why does the empty subtree return (∞, 0, ∞), and why is unc not allowed at the root?

An empty subtree cannot hold a camera (cam = ∞). It needs no coverage (cov = 0, and that value makes a leaf's unc = 0 + 0 work). It must never force its parent to place a camera (unc = ∞). At the root, unc means "my parent will cover me", but the root has no parent, so the answer is min(cam, cov).

6. Tree knapsack looks like O(n · k²). Why is it O(n · k)?

The merge at v costs (size of what is merged so far) × (size of the child's array), and every array is only as long as its subtree, capped at k + 1. Without the cap, the product counts the pairs of nodes whose lowest common ancestor is v, so the total over all nodes is the number of pairs, O(n²). With the cap, a standard refinement of the same counting gives O(n·k). Pre-allocating full k + 1 arrays everywhere breaks the argument and really does cost O(n·k²).

7. When rerooting a max (farthest node), why keep the top two child heights?

When the root moves from p down to v, v needs "the best route out of p that does not go back into v". If v's branch gave p its best height, that best is useless to v, and you need the second best. A max cannot be "un-added" the way a sum can be subtracted, so you keep the top two (or prefix and suffix maxima over the children).

8. Merge Stones with K = 3 and 4 piles: what is the answer, and why?

−1. Each merge turns 3 piles into 1, removing 2 piles, so the pile count goes 4 → 2 and can never reach 1. In general one pile is reachable only if (n − 1) % (K − 1) == 0.
