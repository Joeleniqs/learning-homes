Bitmask & Digit DP

Subsets as integers: TSP, assignment and partition problems; digit DP for counting numbers with constraints.

Advanced → Expert~60 min studyBuilds on: The DP Framework, Bit ManipulationUpdated 2026-11-03

Where this page fits

The DP Framework gave you the five-step recipe (state, transition, base cases, order, answer). Up to now the state was always an index or two: a prefix, a capacity, a pair of prefixes, a piece i..j (Interval & Tree DP), or a subtree. This page covers two kinds of state that are not positions in the input at all:

  • Bitmask DP. The state is a set: which people already have a task, which cities have been visited, which items are already in a bucket. With n ≤ 20 or so, a set fits in one integer, with one bit per item. Then dp[mask] (or dp[mask][last]) is an ordinary array, and "add item i" is mask | 1 << i. This turns n! orderings into 2ⁿ sets.
  • Digit DP. The question is "how many integers in [0, N] have property P?", with N up to 10¹⁸, so you cannot look at them one by one. Instead, you build the number one digit at a time, and the state is (position, tight, …whatever P needs to remember). At most a few thousand states replace 10¹⁸ numbers.

Bitmask DP: when the answer depends on which items have been used but not on the order they were used in, make the set itself the state. Digit DP: when you must count numbers up to N, build them left to right and keep one flag that says "my prefix still equals N's prefix". Everything that is not tight is free and can be memoised.

You will use the bit operations from Bit Manipulation constantly. The next section recaps the five you need, so you can start here.

Bitmask DP: a set is a number

Number the items 0 … n−1. A set of items is a binary number with bit i = 1 exactly when item i is in the set. With n = 5, the set {1, 2, 4} is 0b10110 = 22. Bits are printed with the highest bit on the left, so item 0 is the rightmost bit. That trips up everyone the first time.

The five moves you need

You want to… Write Example with mask = 0b10110
test whether item i is in the set mask >> i & 1 i = 2 → 1 (yes), i = 0 → 0 (no)
add item i mask \| 1 << i i = 0 → 0b10111
remove item i mask & ~(1 << i) (or mask ^ 1 << i if you know it is there) i = 4 → 0b00110
the lowest item in the set low = mask & -mask, index low.bit_length() − 1 low = 0b10, item 1
the size of the set mask.bit_count() (C#: BitOperations.PopCount((uint)mask)) 3
the full set of n items (1 << n) − 1 0b11111 = 31
"is sub a subset of mask?" sub & mask == sub 0b00110 → yes

Precedence bites. In Python, 1 << i binds tighter than & and | but looser than + and -, so mask & 1 << i is fine, but 1 << i + 1 is 1 << (i + 1). In C# and Java, == binds tighter than &, so mask & 1 << i == 0 does not do what you mean: write (mask >> i & 1) == 0. When in doubt, add parentheses.

Every mask reuses a smaller mask

The single fact that makes bitmask DP work: removing any item from a set gives a smaller number (you clear a 1 bit). So if you loop for mask in range(1 << n), every subset of mask with one item fewer has already been processed. That is the fill order for almost every problem on this page, and you get it for free.

The visualizer computes the sum of every subset of the items this way. Each mask peels off its lowest item (low = mask & -mask) and adds it to the sum of the smaller mask. The masks are drawn as a lattice: one column per set size, so the arrow always goes from a column to the one on its right.

def subset_sums(a: list[int]) -> list[int]:
    n = len(a)
    s = [0] * (1 << n)                     # s[mask] = total of the chosen items
    for mask in range(1, 1 << n):          # smaller numbers first
        low = mask & -mask                 # lowest set bit, as a number
        b = low.bit_length() - 1           # ... and as an item index
        s[mask] = s[mask ^ low] + a[b]     # drop item b: a smaller mask, already done
    return s

public int[] SubsetSums(int[] a) {
    int n = a.Length;
    var s = new int[1 << n];                         // s[mask] = total of the chosen items
    for (int mask = 1; mask < 1 << n; mask++) {
        int low = mask & -mask;                      // lowest set bit
        int b = BitOperations.TrailingZeroCount(low);
        s[mask] = s[mask ^ low] + a[b];              // a smaller mask, already done
    }
    return s;
}

Complexity: O(2ⁿ) time and memory: one addition per subset. The naive way (sum the items of every subset from scratch) is O(n·2ⁿ).

How big can n be?

Bitmask DP is exponential, so the constraint tells you immediately whether it is intended. Here is the rough budget for about 10⁸ simple steps per second:

State Transition Work Comfortable n
dp[mask] add one item O(n·2ⁿ) n ≤ 20–22
dp[mask][last] try the next item O(n²·2ⁿ) n ≤ 16–18
dp[mask] enumerate submasks O(3ⁿ) n ≤ 15–16
dp[i][mask], mask over a row all pairs of row masks O(rows·4ʷ) width w ≤ 8–10
SOS DP one bit per pass O(n·2ⁿ) n ≤ 20–22

Smells like bitmask DP: n ≤ 12, n ≤ 16 or n ≤ 20 in the constraints, especially when the rest of the input is large. Phrases like "each person exactly one task", "visit every city", "every skill must be covered", "use each element once", "partition into groups". If the brute force is n! orderings, ask whether the order really matters, or only the set of things used so far.

Assignment: the person is popcount(mask)

The textbook bitmask problem: n people, n tasks, cost[p][t] for person p doing task t. Each person gets exactly one task. Minimise the total cost. Trying every assignment is n! (20! ≈ 2.4·10¹⁸).

The trick is to hand out the tasks to the people in order: person 0 first, then person 1, and so on. Then the state does not need to say which person is next, because if the mask has k tasks taken, persons 0 … k−1 have been served and person k is next. The state is just the set of taken tasks.

1 · STATEdp[mask]

The cheapest way to give the tasks in mask to persons 0 … popcount(mask) − 1.

2 · TRANSITIONNext person takes a free task

p = popcount(mask). For every task t not in mask: dp[mask | 1<<t] = min(…, dp[mask] + cost[p][t]).

3 · BASEdp[0] = 0

Nobody has a task, nothing is spent. Everything else starts at ∞.

4 · ORDERIncreasing mask

Every push goes to a larger number, so a mask is final before it is expanded.

5 · ANSWERdp[2ⁿ − 1]

Every task taken. O(n·2ⁿ) time, O(2ⁿ) memory.

This is written push-style: each finished state pushes its value forward into the states it can reach. Pull-style (dp[mask] = min over t in mask of dp[mask ^ 1<<t] + cost[popcount(mask)−1][t]) is equally correct; push is often easier when the transition is "add one thing". In the visualizer, the cost grid shows which row (person) is being served, and the lattice shows the arrows from the current mask.

def min_cost_assignment(cost: list[list[int]]) -> int:
    n = len(cost)                          # cost[p][t]: person p does task t
    dp = [inf] * (1 << n)                  # dp[mask]: tasks in mask are taken
    dp[0] = 0
    for mask in range(1 << n):
        if dp[mask] == inf:
            continue
        p = mask.bit_count()               # persons 0..p-1 are already placed
        if p == n:
            continue
        for t in range(n):
            if not mask >> t & 1:          # task t still free: give it to person p
                nxt = mask | 1 << t
                dp[nxt] = min(dp[nxt], dp[mask] + cost[p][t])
    return dp[(1 << n) - 1]

public int MinCostAssignment(int[][] cost) {
    int n = cost.Length;
    var dp = new int[1 << n];                        // dp[mask]: tasks in mask are taken
    Array.Fill(dp, int.MaxValue);
    dp[0] = 0;
    for (int mask = 0; mask < 1 << n; mask++) {
        if (dp[mask] == int.MaxValue) continue;
        int p = BitOperations.PopCount((uint)mask);  // persons 0..p-1 are placed
        if (p == n) continue;
        for (int t = 0; t < n; t++)
            if ((mask >> t & 1) == 0) {              // task t free: give it to person p
                int nxt = mask | 1 << t;
                dp[nxt] = Math.Min(dp[nxt], dp[mask] + cost[p][t]);
            }
    }
    return dp[(1 << n) - 1];
}

Complexity: O(n·2ⁿ) time, O(2ⁿ) memory. For n = 20 that is about 2·10⁷ steps, against 2.4·10¹⁸ orderings. The same skeleton solves Minimum XOR Sum of Two Arrays (cost = a[p] ^ b[t]) and Maximum AND Sum of Array (each slot holds two numbers, so use two bits per slot).

Why order of people is free but order of tasks is not. Fixing the order of the people costs nothing: every assignment can be listed person by person. What you cannot fix is which tasks those people took, so that is what the mask stores. Whenever a problem has two groups to match, put one group in a fixed order (the loop) and the other in the mask, and put the smaller group in the mask. Number of Ways to Wear Different Hats takes this to its extreme.

TSP and Hamiltonian paths: dp[mask][last]

The travelling salesman: n cities, a distance w[i][j] between every pair. Start at city 0, visit every city exactly once, come back, and minimise the total distance. Brute force tries (n−1)! routes. With n = 16 that is 1.3·10¹².

Look at two partial routes that both start at 0, visit {0, 1, 2, 3}, and stand at city 3: 0 → 1 → 2 → 3 and 0 → 2 → 1 → 3. Whatever happens next is the same for both: the cities still to visit are the same, and so is the current city. So only the cheaper of the two can be part of the best tour. That is the whole idea: the state is (the set visited, the city you are at), and the order inside the set is forgotten.

1 · STATEdp[mask][j]

Shortest route that starts at 0, visits exactly the cities in mask, and ends at j (j ∈ mask).

2 · TRANSITIONWalk on to an unvisited k

dp[mask | 1<<k][k] = min(…, dp[mask][j] + w[j][k]) for every k not in mask.

3 · BASEdp[{0}][0] = 0

Standing at the start, nothing travelled. Everything else ∞.

4 · ORDERIncreasing mask

mask | 1<<k is bigger than mask, so it is filled after mask is final.

5 · ANSWERmin over j of dp[FULL][j] + w[j][0]

Come home from the last city. O(n²·2ⁿ) time, O(n·2ⁿ) memory.

The visualizer shows the table with one row per mask (only the masks that contain city 0, since every route does) and one column per last city. For each new cell it lists every predecessor i in the smaller mask, with the cost dp[prev][i] + w[i][j], and keeps the best one. At the end it follows the stored predecessors back to draw the tour. Switch to Hamiltonian path to drop the "start at 0 and come back" rule: then every city is a possible start (dp[{j}][j] = 0) and every city a possible end.

def tsp(w: list[list[int]]) -> int:
    n = len(w)
    FULL = (1 << n) - 1
    dp = [[inf] * n for _ in range(1 << n)]   # dp[mask][j]: start at 0, visited mask, now at j
    dp[1][0] = 0
    for mask in range(1, 1 << n):
        if not mask & 1:                       # every route contains city 0
            continue
        for j in range(n):
            if dp[mask][j] == inf:
                continue
            for k in range(n):                 # push: walk on to an unvisited city k
                if not mask >> k & 1:
                    nxt = mask | 1 << k
                    dp[nxt][k] = min(dp[nxt][k], dp[mask][j] + w[j][k])
    return min(dp[FULL][j] + w[j][0] for j in range(1, n)) if n > 1 else 0

def shortest_hamiltonian_path(w: list[list[int]]) -> int:
    n = len(w)
    dp = [[inf] * n for _ in range(1 << n)]
    for j in range(n):
        dp[1 << j][j] = 0                      # any city can be the start
    for mask in range(1, 1 << n):
        for j in range(n):
            if dp[mask][j] == inf:
                continue
            for k in range(n):
                if not mask >> k & 1:
                    nxt = mask | 1 << k
                    dp[nxt][k] = min(dp[nxt][k], dp[mask][j] + w[j][k])
    return min(dp[(1 << n) - 1])               # any city can be the end

public int Tsp(int[][] w) {
    int n = w.Length, FULL = (1 << n) - 1, INF = int.MaxValue / 2;
    var dp = new int[1 << n, n];                     // dp[mask, j]: from 0, visited mask, at j
    for (int m = 0; m <= FULL; m++) for (int j = 0; j < n; j++) dp[m, j] = INF;
    dp[1, 0] = 0;
    for (int mask = 1; mask <= FULL; mask++) {
        if ((mask & 1) == 0) continue;               // every route contains city 0
        for (int j = 0; j < n; j++) {
            if (dp[mask, j] == INF) continue;
            for (int k = 0; k < n; k++)              // push: walk on to unvisited k
                if ((mask >> k & 1) == 0) {
                    int nxt = mask | 1 << k;
                    dp[nxt, k] = Math.Min(dp[nxt, k], dp[mask, j] + w[j][k]);
                }
        }
    }
    if (n == 1) return 0;
    int best = INF;
    for (int j = 1; j < n; j++) best = Math.Min(best, dp[FULL, j] + w[j][0]);
    return best;
}

public int ShortestHamiltonianPath(int[][] w) {
    int n = w.Length, FULL = (1 << n) - 1, INF = int.MaxValue / 2;
    var dp = new int[1 << n, n];
    for (int m = 0; m <= FULL; m++) for (int j = 0; j < n; j++) dp[m, j] = INF;
    for (int j = 0; j < n; j++) dp[1 << j, j] = 0;   // any city can be the start
    for (int mask = 1; mask <= FULL; mask++)
        for (int j = 0; j < n; j++) {
            if (dp[mask, j] == INF) continue;
            for (int k = 0; k < n; k++)
                if ((mask >> k & 1) == 0) {
                    int nxt = mask | 1 << k;
                    dp[nxt, k] = Math.Min(dp[nxt, k], dp[mask, j] + w[j][k]);
                }
        }
    int best = INF;
    for (int j = 0; j < n; j++) best = Math.Min(best, dp[FULL, j]);   // any end
    return best;
}

Complexity: O(n²·2ⁿ) time, O(n·2ⁿ) memory. For n = 16 that is about 1.7·10⁷ steps (versus 1.3·10¹² routes). tsp on the visualizer's default matrix [[0,2,9,10],[2,0,6,4],[9,6,0,8],[10,4,8,0]] gives 23 (0 → 1 → 3 → 2 → 0: 2 + 4 + 8 + 9). To print the route, store the best predecessor par[mask][k] = j and walk back from the best final city.

Unweighted edges? Use BFS over (node, mask). In Shortest Path Visiting All Nodes every edge has length 1 and you may revisit nodes, so a plain BFS over the n·2ⁿ states (node, visited) finds the answer directly, with no relaxation order to worry about. Advanced Graphs explains why the Hamiltonian path problem has no polynomial algorithm, which is why 2ⁿ is the best you can hope for. Find the Shortest Superstring is TSP in disguise: cities are words and w[i][j] is how many letters word j adds after word i.

Partition into k equal subsets

Partition to K Equal Sum Subsets: can nums (n ≤ 16) be split into k groups with equal sums? Backtracking solves it by filling buckets, and its section Switch to bitmask DP explains why the same states keep coming back. Here is that DP in full.

The key observation: fill the buckets one at a time. If the set of used items is mask, their total is sum(mask), so the number of full buckets is sum(mask) // target and the open bucket holds sum(mask) % target. The mask alone decides everything, so a mask is either reachable or it is not, and it only needs to be explored once.

  • State: fill[mask] = how full the open bucket is after using exactly the items in mask, or −1 if mask cannot be reached by filling buckets one at a time without overflowing.
  • Transition: add an unused item i if fill[mask] + nums[i] ≤ target. When the bucket hits target exactly, it closes and the next bucket starts at 0 (the % target).
  • Answer: fill[FULL] == 0.

In the visualizer, the bars show the buckets for the current mask (closed buckets are full, the open one is partly filled), and the dot map shows every one of the 2ⁿ masks: grey ones were never reached. That grey area is the work that the DP skips.

def can_partition_k_subsets(nums: list[int], k: int) -> bool:
    total, n = sum(nums), len(nums)
    if total % k:
        return False
    target = total // k
    nums.sort()
    fill = [-1] * (1 << n)                     # fill[mask]: level of the open bucket
    fill[0] = 0
    for mask in range(1 << n):
        if fill[mask] < 0:
            continue
        for i in range(n):
            if mask >> i & 1:
                continue
            if fill[mask] + nums[i] > target:  # sorted: bigger items won't fit either
                break
            fill[mask | 1 << i] = (fill[mask] + nums[i]) % target   # full bucket -> 0
    return fill[(1 << n) - 1] == 0

public bool CanPartitionKSubsets(int[] nums, int k) {
    int total = nums.Sum(), n = nums.Length;
    if (total % k != 0) return false;
    int target = total / k;
    Array.Sort(nums);
    var fill = new int[1 << n];                      // fill[mask]: level of the open bucket
    Array.Fill(fill, -1);
    fill[0] = 0;
    for (int mask = 0; mask < 1 << n; mask++) {
        if (fill[mask] < 0) continue;
        for (int i = 0; i < n; i++) {
            if ((mask >> i & 1) == 1) continue;
            if (fill[mask] + nums[i] > target) break; // sorted: bigger ones won't fit
            fill[mask | 1 << i] = (fill[mask] + nums[i]) % target;
        }
    }
    return fill[(1 << n) - 1] == 0;
}

Complexity: O(n·2ⁿ) time, O(2ⁿ) memory. Sorting lets the inner loop break as soon as an item does not fit. [4, 3, 2, 3, 5, 2, 1] with k = 4 is true (5, 1+4, 2+3, 2+3); [1, 2, 3, 4] with k = 3 is false.

Memoising backtracking gives you bitmask DP. The backtracking version fills bucket after bucket; it is exponential because the same set of used items is reached in many different orders. Caching on that set (@cache def can(mask)) is the same algorithm as the table above. Whenever a backtracking search's future depends only on which choices were made, not their order, a memo keyed by the mask turns it into a DP.

Submask enumeration: sub = (sub − 1) & mask

Many bitmask DPs split a set into one group plus the rest. "Give child number c some of the remaining bags", "take this semester's courses from the available ones", "the last team covers which people?". The transition loops over every submask sub ⊆ mask, and you want to visit exactly those, not all 2ⁿ numbers.

The loop is three lines long and worth memorising:

sub = mask
while sub:                      # visits every non-empty submask, largest first
    ...                         # use sub (and mask ^ sub, the rest)
    sub = (sub - 1) & mask
# handle sub = 0 here if the empty group is allowed

Why it works: sub − 1 turns the lowest 1 of sub into 0 and every bit below it into 1 (a borrow). & mask then throws away the bits that are not in mask. The result is the next smaller number whose bits all lie inside mask. It is a counter that only "sees" the bits of mask: if you squeeze the mask's bits together, sub counts down from all ones to zero in plain binary. Step through it and watch the borrow:

Why all masks together cost 3ⁿ, not 4ⁿ

If you enumerate the submasks of every mask, the total number of pairs (mask, sub) with sub ⊆ mask is 3ⁿ: for each item independently there are exactly three options, "in neither", "in mask only", or "in both". There is no fourth option, because "in sub but not in mask" is impossible. For n = 15 that is 1.4·10⁷ pairs, against 4¹⁵ ≈ 10⁹ for two independent loops.

The empty submask. while sub: stops before sub = 0. If the empty group is a legal choice, handle it after the loop (or use the while True: … if sub == 0: break form, as in the valid-words code below). Also, don't write for sub in range(mask + 1): if sub & mask == sub "to be safe": over all masks that is 4ⁿ work, and for n = 15 it times out.

Distributing bags to k children

Fair Distribution of Cookies (n ≤ 8 bags, k children): minimise the largest total any child gets. Add the children one at a time:

  • total[mask] = cookies in the bags of mask (the subset-sum table from above).
  • dp[mask] with c children = the best possible "largest share" when those c children split exactly the bags in mask.
  • Adding child c + 1: it takes some sub ⊆ mask, and the earlier children take mask ^ sub. So new[mask] = min over sub of max(total[sub], dp[mask ^ sub]).
def distribute_cookies(cookies: list[int], k: int) -> int:
    n = len(cookies)
    full = (1 << n) - 1
    total = [0] * (1 << n)                     # total[mask]: cookies in that bag set
    for mask in range(1, 1 << n):
        low = mask & -mask
        total[mask] = total[mask ^ low] + cookies[low.bit_length() - 1]
    dp = total[:]                              # dp[mask]: best unfairness, 1 child
    for _ in range(k - 1):                     # add one more child at a time
        new = dp[:]
        for mask in range(1, full + 1):
            sub = mask
            while sub:                         # the new child takes the bags in sub
                new[mask] = min(new[mask], max(total[sub], dp[mask ^ sub]))
                sub = (sub - 1) & mask
        dp = new
    return dp[full]

public int DistributeCookies(int[] cookies, int k) {
    int n = cookies.Length, full = (1 << n) - 1;
    var total = new int[1 << n];                     // total[mask]: cookies in those bags
    for (int mask = 1; mask <= full; mask++) {
        int low = mask & -mask;
        total[mask] = total[mask ^ low] + cookies[BitOperations.TrailingZeroCount(low)];
    }
    var dp = (int[])total.Clone();                   // one child takes everything
    for (int child = 1; child < k; child++) {
        var nw = (int[])dp.Clone();
        for (int mask = 1; mask <= full; mask++)
            for (int sub = mask; sub > 0; sub = (sub - 1) & mask)   // new child takes sub
                nw[mask] = Math.Min(nw[mask], Math.Max(total[sub], dp[mask ^ sub]));
        dp = nw;
    }
    return dp[full];
}

Complexity: O(k·3ⁿ) time, O(2ⁿ) memory. [8, 15, 10, 20, 8] with k = 2 gives 31 ({8, 15, 8} and {10, 20}). The same "one more group takes a submask" loop solves Minimum Incompatibility and Distribute Repeating Integers.

Counting words that fit a puzzle

Number of Valid Words for Each Puzzle: a word is valid for a puzzle if it contains the puzzle's first letter and uses only letters of the puzzle. Up to 10⁵ words and 10⁴ puzzles, so comparing every pair is too slow. But a puzzle has only 7 letters, so it has only 2⁶ = 64 subsets that include its first letter.

So turn each word into its letter mask and count how many words have each mask. For a puzzle, enumerate the submasks of its other 6 letters, add the first letter, and look each one up. That is 64 dictionary lookups per puzzle.

def find_num_of_valid_words(words: list[str], puzzles: list[str]) -> list[int]:
    bits = lambda s: sum(1 << (ord(c) - 97) for c in set(s))
    freq = defaultdict(int)
    for w in words:
        m = bits(w)
        if m.bit_count() <= 7:                 # a puzzle has 7 letters
            freq[m] += 1
    out = []
    for p in puzzles:
        first, rest = bits(p[0]), bits(p[1:]) & ~bits(p[0])
        cnt, sub = 0, rest
        while True:                            # every subset of the other letters
            cnt += freq.get(sub | first, 0)    # ... plus the required first letter
            if sub == 0:
                break
            sub = (sub - 1) & rest
        out.append(cnt)
    return out

public IList<int> FindNumOfValidWords(string[] words, string[] puzzles) {
    static int Bits(string s) { int m = 0; foreach (char c in s) m |= 1 << (c - 'a'); return m; }
    var freq = new Dictionary<int, int>();
    foreach (var w in words) {
        int m = Bits(w);
        if (BitOperations.PopCount((uint)m) <= 7) freq[m] = freq.GetValueOrDefault(m) + 1;
    }
    var res = new List<int>();
    foreach (var p in puzzles) {
        int first = 1 << (p[0] - 'a'), rest = Bits(p[1..]) & ~first, cnt = 0;
        for (int sub = rest; ; sub = (sub - 1) & rest) {   // every subset of the others
            cnt += freq.GetValueOrDefault(sub | first);     // plus the first letter
            if (sub == 0) break;
        }
        res.Add(cnt);
    }
    return res;
}

Complexity: O(W·L + P·2⁶) time, where W·L is the total length of the words. words = ["aaaa","asas","able","ability","actt","actor","access"] with puzzles ["aboveyz","abrodyz","abslute","absoryz","actresz","gaswxyz"] gives [1,1,3,2,4,0].

SOS DP: sum over subsets at a glance

Some problems need, for every mask at once, the sum (or count, max, OR, …) of A[sub] over all sub ⊆ mask. Submask enumeration does this in 3ⁿ. Sum over subsets (SOS) DP does it in n·2ⁿ: for n = 20, that is 2·10⁷ steps instead of 3.5·10⁹.

The idea is to grow the "allowed difference" one bit at a time. After pass b, F[mask] holds the sum of A[sub] over every sub ⊆ mask that agrees with mask on all bits above b. In pass b, every mask that has bit b set picks up its twin mask ^ (1 << b). That twin already covers every way to differ in the lower bits, so adding it extends the coverage to bit b too. After the last pass, every bit is allowed to differ, and F[mask] is the full subset sum.

Each pass touches every mask once, so there are n passes of 2ⁿ steps. In the visualizer, each cell lists which A[sub] it currently contains, so you can watch the coverage double with every pass:

def sum_over_subsets(A: list[int]) -> list[int]:
    n = (len(A) - 1).bit_length()              # len(A) == 2**n
    F = A[:]
    for b in range(n):                         # free up one bit per pass
        for mask in range(1 << n):
            if mask >> b & 1:
                F[mask] += F[mask ^ (1 << b)]
    return F                                   # F[mask] = sum of A[sub], sub ⊆ mask

public long[] SumOverSubsets(long[] A) {
    int n = BitOperations.Log2((uint)A.Length);      // A.Length == 2^n
    var F = (long[])A.Clone();
    for (int b = 0; b < n; b++)                      // free up one bit per pass
        for (int mask = 0; mask < 1 << n; mask++)
            if ((mask >> b & 1) == 1) F[mask] += F[mask ^ (1 << b)];
    return F;                                        // F[mask] = sum of A[sub], sub ⊆ mask
}

Complexity: O(n·2ⁿ) time, O(2ⁿ) memory, in place. Reversed, the same loop (F[mask ^ bit] += F[mask] when the bit is set) gives sums over supersets. Replacing += with -= undoes the transform (inclusion-exclusion, the Möbius inverse). Typical uses: "for every mask, how many array values are submasks of it?" (count of x with x & m == x), Compatible Numbers (for each x, find some y with x & y = 0: look up any value that is a submask of ~x), and the "pairs whose OR / AND / XOR is a given set" problems on Codeforces. LeetCode rarely needs it, but when the constraint is 2²⁰ values and "subset" appears in the statement, this is the tool.

Bit order trick. The passes can run over the bits in any order, but the inner loop must complete one bit before the next starts. Swapping the loops (for mask: for b:) is wrong: then a mask can collect a submask's contribution twice. The bit is the outer loop.

Broken profile DP: tiling a grid

How many ways can you tile an R × C board with 1×2 dominoes? For R ≤ 10 or so, scan the cells one at a time, column by column and top to bottom. The only thing the future needs to know is the frontier: for each row, is the next undecided cell already covered by a horizontal domino that poked in from the left? That is one bit per row, R bits in total. This is called the profile, and since the frontier has a step in it (rows above the current cell are already in the next column), it is a broken profile.

At cell (r, c), for each profile:

  • Bit r is 1: a horizontal domino from the left already covers this cell. Clear the bit and move on.
  • Bit r is 0, and the cell is empty, so place a domino:
  • horizontal: it covers (r, c) and (r, c + 1). Set bit r, so the cell in the next column is marked as covered. Only if c + 1 < C.
  • vertical: it covers (r, c) and (r + 1, c). Set bit r + 1: the next cell visited is (r + 1, c), and it must find itself covered. Only if r + 1 < R and that bit is 0.

A real tiling ends with nothing poking out of the board: profile 0. Each state is a dictionary entry profile → number of ways. The visualizer shows the board with the current cell, and the profile table before and after that cell:

def domino_tilings(R: int, C: int) -> int:
    ways = {0: 1}                              # profile -> count; bit r = (r, c) pre-filled
    for c in range(C):
        for r in range(R):                     # cell (r, c), column by column
            nxt = defaultdict(int)
            for mask, w in ways.items():
                if mask >> r & 1:              # covered by a domino from the left
                    nxt[mask & ~(1 << r)] += w
                    continue
                if c + 1 < C:                  # horizontal: pokes into column c+1
                    nxt[mask | 1 << r] += w
                if r + 1 < R and not mask >> (r + 1) & 1:
                    nxt[mask | 1 << (r + 1)] += w   # vertical: covers (r+1, c) too
            ways = nxt
    return ways.get(0, 0)

public long DominoTilings(int R, int C) {
    var ways = new long[1 << R];                     // ways[profile]; bit r = (r, c) pre-filled
    ways[0] = 1;
    for (int c = 0; c < C; c++)
        for (int r = 0; r < R; r++) {                // cell (r, c), column by column
            var nxt = new long[1 << R];
            for (int mask = 0; mask < 1 << R; mask++) {
                long w = ways[mask];
                if (w == 0) continue;
                if ((mask >> r & 1) == 1) { nxt[mask & ~(1 << r)] += w; continue; }
                if (c + 1 < C) nxt[mask | 1 << r] += w;          // horizontal
                if (r + 1 < R && (mask >> (r + 1) & 1) == 0)
                    nxt[mask | 1 << (r + 1)] += w;               // vertical
            }
            ways = nxt;
        }
    return ways[0];
}

Complexity: O(R·C·2ᴿ) time, O(2ᴿ) memory. Put the smaller dimension in the profile. 2×3 gives 3, 3×4 gives 11, 4×4 gives 36, and the 8×8 chessboard has 12,988,816 tilings. Domino and Tromino Tiling is the 2-row case, small enough to write as a linear recurrence.

Row-by-row masks: seats, colours, cells

A simpler version of the same idea: process the grid one full row at a time, and let the state be the mask of the previous row. It works whenever a row only interacts with the row directly above it.

  • Maximum Students Taking Exam (worked below): a student may not sit next to another or diagonally in front of one. Valid row masks are the good-seat submasks with no two adjacent bits (sub & sub << 1 == 0), and a pair of rows is compatible if neither row's student sits diagonally from the other's (sub & prev << 1 == 0 and sub & prev >> 1 == 0).
  • Painting a Grid With Three Different Colors: the "mask" of a column is a base-3 colouring (at most 3⁵ = 243 of them, only 48 of which are valid). Precompute which pairs of columns are compatible, then it is a walk of length n on that compatibility graph.
  • Number of Ways to Paint N × 3 Grid: the same with width 3, where only two kinds of rows exist (ABA and ABC), so the DP collapses to two numbers.

Precompute the valid row masks. In a row of width 10, only 144 of the 1024 masks have no two adjacent bits. Listing them once and listing the compatible pairs once turns the inner loops into a few thousand checks per row.

Digit DP: count numbers without listing them

"How many integers in [1, N] have all different digits?" With N = 10¹⁸ you cannot check them one by one. But every such question has the same structure: write the numbers with the same number of digits as N (pad with leading zeros), and build them one digit at a time from the left.

Warm-up: counting by hand

Count Numbers with Unique Digits asks the question for 0 ≤ x < 10ⁿ, which is every number with at most n digits. No upper bound gets in the way, so plain counting works. A k-digit number with distinct digits has 9 choices for the first digit (not 0), then 9, 8, 7, … for the rest.

def count_numbers_with_unique_digits(n: int) -> int:
    total, ways = 1, 9                         # "0", then the 9 one-digit numbers 1..9
    for length in range(1, n + 1):
        total += ways                          # numbers with exactly `length` digits
        ways *= 10 - length                    # next place: 9, 8, 7, … choices left
    return total

public int CountNumbersWithUniqueDigits(int n) {
    int total = 1, ways = 9;                         // "0", then 9 one-digit numbers
    for (int len = 1; len <= n; len++) {
        total += ways;                               // exactly len digits
        ways *= 10 - len;                            // 9, 8, 7, ... choices left
    }
    return total;
}

Complexity: O(n). For n = 8 it gives 2,345,851. This is easy because every digit position is unconstrained. Now make the bound arbitrary, say N = 2731. The first digit can be 0, 1 or 2; but if it is 2, the second digit can only go up to 7, and if that is 7, the third can only go up to 3. The bound is what needs a DP.

Tight and free

Compare a prefix of x with the prefix of N of the same length. There are only two situations:

  • Tight: the prefix of x equals the prefix of N (for example 27 when N = 2731). The next digit can only go up to N's next digit, or x would exceed N. There is exactly one tight prefix of each length: N's own.
  • Free: the prefix of x is already smaller than N's prefix (for example 26, or 1). Then x < N no matter what comes next, so every remaining digit can be anything from 0 to 9.

A free prefix stays free forever. A tight prefix becomes free as soon as it takes a digit smaller than N's digit, and stays tight only by copying N's digit. So the numbers ≤ N form a tree: one tight path running down N's digits, with free subtrees hanging off it to the left.

Now the key insight: two free prefixes of the same length behave identically, as long as they agree on whatever the property needs to remember (the digits used, the digit sum, the remainder, …). Their futures are the same set of suffixes. So the count for a free subtree depends only on (position, state), and can be memoised. That is why digit DP is fast: there are only len(N) × (number of states) free subproblems, and the tight path adds just one more state per position.

1 · STATEf(pos, state, tight, started)

How many ways to finish the number from position pos, given what the prefix needs to remember.

2 · TRANSITIONTry every digit d ≤ hi

hi = N[pos] if tight else 9. Tight stays tight only if d == hi. Skip digits the rule forbids.

3 · BASEpos == len(N)

The number is complete: return 1 if it has the property (and is not "empty"), else 0.

4 · ORDERMemoised recursion

Each call only needs pos + 1. Or iterate forward position by position (the table view below).

5 · ANSWERf(0, initial, True, False)

O(len(N) · states · 10) time. For N ≤ 10¹⁸ the length is at most 19.

Watch the walk: count special integers

Count Special Integers: how many x in [1, N] have all distinct digits? The state needs the set of digits used so far, a 10-bit mask. This is bitmask DP inside digit DP.

The visualizer walks down N's digits. At each position it lists every digit choice: the ones smaller than N's digit open a free subtree (it shows how many numbers that subtree holds), the digit equal to N's digit continues the tight path, and the ones that break the rule are crossed out. Then the counts return up the tight path. Switch to digits from a set for Numbers At Most N Given Digit Set (worked below).

def count_special(n: int) -> int:
    s = str(n)
    @cache
    def f(pos: int, mask: int, tight: bool, started: bool) -> int:
        if pos == len(s):
            return int(started)                # 0 is not a positive integer
        hi = int(s[pos]) if tight else 9       # tight: stay at or below n's digit
        total = 0
        for d in range(hi + 1):
            if not started and d == 0:         # still a leading zero: no digit used
                total += f(pos + 1, mask, tight and d == hi, False)
            elif not mask >> d & 1:            # d not used yet
                total += f(pos + 1, mask | 1 << d, tight and d == hi, True)
        return total
    return f(0, 0, True, False)

def num_dup_digits_at_most_n(n: int) -> int:
    return n - count_special(n)                # LeetCode 1012: the complement

public int CountSpecialNumbers(int n) {
    string s = n.ToString();
    var memo = new Dictionary<(int, int, bool), int>();   // free states only
    int F(int pos, int mask, bool tight, bool started) {
        if (pos == s.Length) return started ? 1 : 0;
        if (!tight && memo.TryGetValue((pos, mask, started), out int v)) return v;
        int hi = tight ? s[pos] - '0' : 9, total = 0;
        for (int d = 0; d <= hi; d++) {
            if (!started && d == 0) total += F(pos + 1, mask, tight && d == hi, false);
            else if ((mask >> d & 1) == 0) total += F(pos + 1, mask | 1 << d, tight && d == hi, true);
        }
        if (!tight) memo[(pos, mask, started)] = total;
        return total;
    }
    return F(0, 0, true, false);
}

public int NumDupDigitsAtMostN(int n) => n - CountSpecialNumbers(n);   // LeetCode 1012

Complexity: O(L · 2¹⁰ · 10) time with L = len(str(N)), though only a small fraction of the masks is reachable. count_special(135) = 110. Numbers With Repeated Digits is the complement, N − count_special(N): for N = 1000, 262.

Only free states are worth caching. There is exactly one tight state per position, so it is visited once anyway. Python's @cache stores it too, which is harmless. The C# version memoises only the free states (if (!tight && memo.TryGetValue(…))), so its memo key does not need the tight flag at all, and the memo stays small.

The leading-zero flag

started says whether a non-zero digit has been placed yet. You need it whenever a leading zero would change the answer:

  • Distinct digits: 0012 has two zeros, but it really is 12, which is fine. While started is false, a 0 is padding and must not go into the mask.
  • Digits from a set without 0: padding zeros are "empty places", not the digit 0.
  • Counting [1, N]: the all-zero number 000 is not a positive integer, so the base case returns int(started).
  • Digit sum, count of 1s, remainder: leading zeros add 0, so they don't change anything, and you can drop the flag.

Forgetting the flag is the most common digit-DP bug. It usually shows up as an off-by-one (counting 0), or as an undercount when a rule like "distinct digits" sees the padding zeros as real zeros. When in doubt, check f for N = 9, N = 10 and N = 100 against a loop.

The table view: free counts move forward

The recursion is the usual way to write digit DP, but it helps to see the same computation forward. Keep free[state] = how many free prefixes of the current length have that state, plus the one tight prefix. For each digit of N:

  1. free → free: every free prefix takes every digit 0..9.
  2. tight → free: the tight prefix takes every digit smaller than N's digit; those prefixes become free.
  3. tight → tight: it takes N's digit and stays tight (or dies, if that digit is not allowed).

At the end, the answer is the sum of free[s] over the good states s, plus 1 if the tight prefix (N itself) is good. The visualizer does this for three problems: digit sum equal to S, the number of times digit d appears in 0..N (Number of Digit One), and binary numbers without two adjacent 1s.

Binary digits: non-negative integers without consecutive ones

Non-negative Integers without Consecutive Ones: count x in [0, n] whose binary form has no 11. Same machinery, base 2, and the state is the previous bit. No started flag is needed: leading zeros never create 11, and 0 counts.

def find_integers(n: int) -> int:
    s = bin(n)[2:]
    @cache
    def f(pos: int, last: int, tight: bool) -> int:
        if pos == len(s):
            return 1                           # 0 counts too: [0, n]
        hi = int(s[pos]) if tight else 1
        total = 0
        for b in range(hi + 1):
            if b == 1 and last == 1:           # would create "11"
                continue
            total += f(pos + 1, b, tight and b == hi)
        return total
    return f(0, 0, True)

public int FindIntegers(int n) {
    string s = Convert.ToString(n, 2);
    var memo = new Dictionary<(int, int), int>();
    int F(int pos, int last, bool tight) {
        if (pos == s.Length) return 1;               // 0 counts too: [0, n]
        if (!tight && memo.TryGetValue((pos, last), out int v)) return v;
        int hi = tight ? s[pos] - '0' : 1, total = 0;
        for (int b = 0; b <= hi; b++) {
            if (b == 1 && last == 1) continue;       // would create "11"
            total += F(pos + 1, b, tight && b == hi);
        }
        if (!tight) memo[(pos, last)] = total;
        return total;
    }
    return F(0, 0, true);
}

Complexity: O(log n) states, 2 digits each. find_integers(5) = 5 (0, 1, 2, 4, 5). The free count with k bits left is a Fibonacci number, which is the famous closed-form solution; the DP finds it without needing to see that.

Ranges: f(R) − f(L − 1)

Most digit-DP problems ask about a range [L, R]. Count [0, R] and subtract [0, L − 1]. When L is given as a long string (up to 10²² in Count of Integers), subtracting 1 is fiddly, so compute f(R) − f(L) and add 1 back if L itself qualifies.

What goes in the state?

The state is "whatever the rule needs to know about the prefix". Spotting it is the whole problem:

Property of x Extra state Size
all digits distinct mask of digits used 2¹⁰
digit sum = S, ≤ S, in a range sum so far (prune once it is too big) 9·L + 1
divisible by k x mod k so far: (r·10 + d) % k k
no two equal adjacent digits, "stepping" numbers the last digit 10
counts of each parity, "beautiful" numbers (even − odd) and the remainder L · k
how many times digit d appears (sum over all x) the count so far, returned at the end L
digits never decrease the last digit 10
no 11 in binary the last bit 2

"Count of something over all x" is still a count. In Number of Digit One you don't count numbers, you count ones across all numbers. Carry the number of ones so far in the state and return it at the base case, so each finished number contributes its own count. The alternative is to return a pair (numbers, total) from each call, which avoids the extra state.

Recognize it, cost it, avoid the traps

Reach for bitmask DP when:

  • one dimension of the input is tiny (n ≤ 20, often ≤ 16 or ≤ 12) while the others may be large;
  • the brute force tries orderings or subsets of those few items, and the future depends only on which items are used, not their order;
  • the statement says "each … exactly once", "visit all", "cover every skill / requirement", "assign", "split into groups";
  • a grid is narrow (width ≤ 10) and each row only interacts with the row above (row masks, broken profile).

Reach for digit DP when:

  • you must count integers in [L, R] (or sum something over them), and R is up to 10⁹, 10¹⁸ or given as a string;
  • the property is about the digits (sum, distinct, adjacent digits, a digit's count, divisibility, binary pattern);
  • an answer "mod 10⁹+7" over a huge numeric range appears.

The traps that cost the most time:

  • Operator precedence. mask & 1 << i == 0 means mask & ((1 << i) == 0) in C#, Java and C++. Write (mask >> i & 1) == 0.
  • Item 0 is the rightmost bit. When you draw a mask, read it right to left.
  • A mask over the wrong side. Put the smaller group in the mask (40 hats vs 10 people: the people go in the mask).
  • 0/1 vs unbounded. When the items are the outer loop and you update dp in place, iterate masks from high to low (or loop over a snapshot), or the same item gets used twice.
  • 4ⁿ instead of 3ⁿ. Enumerate submasks with (sub − 1) & mask, never by testing every number.
  • Digit DP without started. Leading zeros are padding: they must not count as digit 0 for "distinct digits" or "digits from a set", and the all-zero number may need excluding.
  • Caching across different N. In Python, a @cache defined inside the function is fresh for each call; a global one would reuse answers computed for a different N and return garbage.
  • Range arithmetic. [L, R] = f(R) − f(L − 1). With string bounds, use f(R) − f(L) + [L is good], and take the result mod 10⁹+7 after the subtraction (add MOD before % in C#).

1. Smallest Sufficient Team: the skills are the mask

LeetCode 1125 Hard. There are up to 16 required skills and up to 60 people, each with some of the skills. Return a smallest team whose skills together cover every required skill.

Key insight. 60 people is far too many for a mask, but 16 skills is perfect. Map each skill to a bit, so each person becomes a skills mask have[i]. Then it is a 0/1 knapsack over people where the "weight" is a set union: team[mask | have[i]] can be reached from team[mask] by adding person i. Keep, for each covered set, the smallest team found. Loop over a snapshot of the current entries, so each person is added at most once per round.

Solution: dp over the covered-skills mask, O(people · 2ᵐ)

def smallest_sufficient_team(req_skills: list[str], people: list[list[str]]) -> list[int]:
    idx = {s: i for i, s in enumerate(req_skills)}
    m = len(req_skills)
    have = [sum(1 << idx[s] for s in p) for p in people]
    team = {0: []}                             # skills mask -> smallest team found
    for i, h in enumerate(have):
        if h == 0:
            continue
        for mask, t in list(team.items()):     # snapshot: person i used at most once
            nxt = mask | h
            if nxt not in team or len(team[nxt]) > len(t) + 1:
                team[nxt] = t + [i]
    return team[(1 << m) - 1]

public int[] SmallestSufficientTeam(string[] req_skills, IList<IList<string>> people) {
    var idx = new Dictionary<string, int>();
    for (int i = 0; i < req_skills.Length; i++) idx[req_skills[i]] = i;
    var team = new Dictionary<int, List<int>> { [0] = new() };   // skills mask -> team
    for (int i = 0; i < people.Count; i++) {
        int h = 0;
        foreach (var s in people[i]) h |= 1 << idx[s];
        if (h == 0) continue;
        foreach (var (mask, t) in team.ToList()) {   // snapshot: person i used once
            int nxt = mask | h;
            if (!team.TryGetValue(nxt, out var cur) || cur.Count > t.Count + 1)
                team[nxt] = new List<int>(t) { i };
        }
    }
    return team[(1 << req_skills.Length) - 1].ToArray();
}

Complexity: O(P · 2ᵐ) time and O(2ᵐ · m) memory with m skills, P people. Storing a whole list per mask is fine for m ≤ 16; to save memory, store only the size and the last person and the previous mask, then walk back. Pruning helps a lot: drop people whose skills are a subset of someone else's.

2. Parallel Courses II: pick exactly k from the available courses

LeetCode 1494 Hard. n ≤ 15 courses with prerequisites, and at most k courses per semester. Find the minimum number of semesters to take them all.

Key insight. The state is the set of courses already taken. From it, the available courses (not taken, all prerequisites taken) are fixed. If at most k are available, take them all: taking more never hurts. If more than k are available, greedy choices fail (which courses unlock the most later is not a local question), so try every submask of the available courses with exactly k bits. Submask enumeration keeps the whole DP within 3ⁿ.

Solution: dp[taken] with k-sized submasks of the available set, O(3ⁿ)

def min_number_of_semesters(n: int, relations: list[list[int]], k: int) -> int:
    pre = [0] * n
    for a, b in relations:
        pre[b - 1] |= 1 << (a - 1)             # course b needs course a
    FULL = (1 << n) - 1
    dp = [inf] * (1 << n)                      # dp[taken]: fewest semesters
    dp[0] = 0
    for taken in range(1 << n):
        if dp[taken] == inf:
            continue
        avail = 0
        for c in range(n):                     # not taken yet, prerequisites done
            if not taken >> c & 1 and pre[c] & taken == pre[c]:
                avail |= 1 << c
        if avail.bit_count() <= k:             # take them all: never worse
            dp[taken | avail] = min(dp[taken | avail], dp[taken] + 1)
            continue
        sub = avail
        while sub:                             # choose exactly k of them
            if sub.bit_count() == k:
                dp[taken | sub] = min(dp[taken | sub], dp[taken] + 1)
            sub = (sub - 1) & avail
    return dp[FULL]

public int MinNumberOfSemesters(int n, int[][] relations, int k) {
    var pre = new int[n];
    foreach (var r in relations) pre[r[1] - 1] |= 1 << (r[0] - 1);
    int FULL = (1 << n) - 1;
    var dp = new int[1 << n];
    Array.Fill(dp, int.MaxValue);
    dp[0] = 0;
    for (int taken = 0; taken <= FULL; taken++) {
        if (dp[taken] == int.MaxValue) continue;
        int avail = 0;
        for (int c = 0; c < n; c++)
            if ((taken >> c & 1) == 0 && (pre[c] & taken) == pre[c]) avail |= 1 << c;
        if (BitOperations.PopCount((uint)avail) <= k) {   // take them all
            dp[taken | avail] = Math.Min(dp[taken | avail], dp[taken] + 1);
            continue;
        }
        for (int sub = avail; sub > 0; sub = (sub - 1) & avail)   // exactly k of them
            if (BitOperations.PopCount((uint)sub) == k)
                dp[taken | sub] = Math.Min(dp[taken | sub], dp[taken] + 1);
    }
    return dp[FULL];
}

Complexity: O(3ⁿ + n·2ⁿ) time, O(2ⁿ) memory. For n = 4, relations = [[2,1],[3,1],[1,4]], k = 2, the answer is 3 ({2, 3}, then {1}, then {4}). A popular wrong answer picks the k available courses with the most dependants (or the longest chain behind them). Such greedy rules fail on some inputs, which is why the DP tries every k-subset.

3. Number of Ways to Wear Different Hats: flip which side is the mask

LeetCode 1434 Hard. n ≤ 10 people and 40 kinds of hats. Each person likes some hats. Count the ways to give every person a hat they like, with no two people wearing the same hat (mod 10⁹+7).

Key insight. The obvious state, "which hats are used", needs 2⁴⁰ masks. But there are only 10 people. So loop over the hats (the items, one at a time) and keep a mask of the people who already have a hat. For hat h, either nobody takes it, or one person who likes it and has no hat yet takes it. Iterate masks from high to low so that hat h is given at most once within its own round (the 0/1 knapsack trick). The visualizer shows each hat's round:

Solution: hats as items, mask over people, O(40 · n · 2ⁿ)

def number_ways(hats: list[list[int]]) -> int:
    n = len(hats)
    likes = defaultdict(list)                  # hat -> people who like it
    for p, hs in enumerate(hats):
        for h in hs:
            likes[h].append(p)
    dp = [0] * (1 << n)                        # dp[mask]: people in mask have a hat
    dp[0] = 1
    for h in range(1, 41):                     # hats are the items, one by one
        for mask in range((1 << n) - 1, -1, -1):   # high to low: hat h used once
            if not dp[mask]:
                continue
            for p in likes[h]:
                if not mask >> p & 1:
                    nxt = mask | 1 << p
                    dp[nxt] = (dp[nxt] + dp[mask]) % MOD
    return dp[(1 << n) - 1]

public int NumberWays(IList<IList<int>> hats) {
    int n = hats.Count;
    var likes = new List<int>[41];                   // hat -> people who like it
    for (int h = 0; h <= 40; h++) likes[h] = new();
    for (int p = 0; p < n; p++) foreach (int h in hats[p]) likes[h].Add(p);
    var dp = new long[1 << n];                       // dp[mask]: these people have hats
    dp[0] = 1;
    for (int h = 1; h <= 40; h++)                    // hats are the items
        for (int mask = (1 << n) - 1; mask >= 0; mask--) {   // high to low: hat h once
            if (dp[mask] == 0) continue;
            foreach (int p in likes[h])
                if ((mask >> p & 1) == 0) {
                    int nxt = mask | 1 << p;
                    dp[nxt] = (dp[nxt] + dp[mask]) % MOD;
                }
        }
    return (int)dp[(1 << n) - 1];
}

Complexity: O(40 · n · 2ⁿ) time, O(2ⁿ) memory: about 4·10⁵ steps for n = 10. [[3,5,1],[3,5]] gives 4, and [[3,4],[4,5],[5]] gives 1. Rule of thumb: when the two sides of a matching have very different sizes, the small side is the mask and the large side is the loop.

4. Minimum Cost to Connect Two Groups of Points: one partner each, then patch the rest

LeetCode 1595 Hard. Group 1 has size1 points and group 2 has size2 ≤ size1 ≤ 12 points. Connecting i and j costs cost[i][j]. Every point of both groups must have at least one connection. Minimise the total cost.

Key insight. In an optimal solution, look at each group-1 point. It needs at least one edge. Any extra edges it has only exist to cover some group-2 point, and that point could instead use its own cheapest edge at no greater cost. So, without loss: every group-1 point picks exactly one partner (a row-by-row assignment with a mask over group 2, like the assignment DP but partners may repeat), and at the end every group-2 point still uncovered adds its cheapest edge.

Solution: rows pick one partner, mask over group 2, then patch, O(size1 · size2 · 2^size2)

def connect_two_groups(cost: list[list[int]]) -> int:
    n1, n2 = len(cost), len(cost[0])           # mask over the smaller group 2
    cheapest = [min(cost[i][j] for i in range(n1)) for j in range(n2)]
    dp = [inf] * (1 << n2)                     # dp[mask]: group-1 rows so far, mask touched
    dp[0] = 0
    for i in range(n1):                        # each group-1 point picks one partner
        new = [inf] * (1 << n2)
        for mask in range(1 << n2):
            if dp[mask] == inf:
                continue
            for j in range(n2):
                nxt = mask | 1 << j
                new[nxt] = min(new[nxt], dp[mask] + cost[i][j])
        dp = new
    best = inf
    for mask in range(1 << n2):                # leftover group-2 points: cheapest edge
        extra = sum(cheapest[j] for j in range(n2) if not mask >> j & 1)
        best = min(best, dp[mask] + extra)
    return best

public int ConnectTwoGroups(IList<IList<int>> cost) {
    int n1 = cost.Count, n2 = cost[0].Count, INF = int.MaxValue / 2;
    var cheapest = new int[n2];
    for (int j = 0; j < n2; j++) { cheapest[j] = INF; for (int i = 0; i < n1; i++) cheapest[j] = Math.Min(cheapest[j], cost[i][j]); }
    var dp = new int[1 << n2];                       // dp[mask]: group-2 points touched
    Array.Fill(dp, INF);
    dp[0] = 0;
    for (int i = 0; i < n1; i++) {                   // each group-1 point picks a partner
        var nw = new int[1 << n2];
        Array.Fill(nw, INF);
        for (int mask = 0; mask < 1 << n2; mask++) {
            if (dp[mask] == INF) continue;
            for (int j = 0; j < n2; j++)
                nw[mask | 1 << j] = Math.Min(nw[mask | 1 << j], dp[mask] + cost[i][j]);
        }
        dp = nw;
    }
    int best = INF;
    for (int mask = 0; mask < 1 << n2; mask++) {     // leftovers take their cheapest edge
        int extra = 0;
        for (int j = 0; j < n2; j++) if ((mask >> j & 1) == 0) extra += cheapest[j];
        best = Math.Min(best, dp[mask] + extra);
    }
    return best;
}

Complexity: O(n₁ · n₂ · 2ⁿ²) time, O(2ⁿ²) memory. The official examples give 17, 4 and 10. The mask goes over the smaller group, which keeps it at 2¹² = 4096 states.

5. Maximum Students Taking Exam: the previous row is the state

LeetCode 1349 Hard. A classroom of m × n ≤ 8 × 8 seats, some broken (#). A student can see the answers of anyone to the left, right, upper left and upper right. Seat as many students as possible so that nobody can cheat.

Key insight. Process the rows top to bottom. The only thing row i needs to know about the past is which seats of row i − 1 are taken, so dp[mask] = the best total with the previous row seated as mask. A row mask is valid if it uses only good seats and has no two neighbours (sub & sub << 1 == 0). Two consecutive rows are compatible if no student is diagonally in front of another: sub & prev << 1 == 0 and sub & prev >> 1 == 0. Enumerate only the submasks of the row's good seats.

Solution: row-by-row mask DP, O(m · 4ⁿ)

def max_students(seats: list[list[str]]) -> int:
    m, n = len(seats), len(seats[0])
    good = [sum(1 << j for j in range(n) if row[j] == ".") for row in seats]
    dp = {0: 0}                                # previous row's mask -> best total
    for i in range(m):
        new = {}
        sub = good[i]
        while True:                            # every subset of this row's good seats
            if not sub & (sub << 1):           # no two neighbours side by side
                best = -1
                for prev, val in dp.items():   # nobody diagonally in front
                    if not sub & (prev << 1) and not sub & (prev >> 1):
                        best = max(best, val)
                if best >= 0:
                    new[sub] = best + sub.bit_count()
            if sub == 0:
                break
            sub = (sub - 1) & good[i]
        dp = new
    return max(dp.values())

public int MaxStudents(char[][] seats) {
    int m = seats.Length, n = seats[0].Length;
    var dp = new Dictionary<int, int> { [0] = 0 };   // previous row's mask -> best
    for (int i = 0; i < m; i++) {
        int good = 0;
        for (int j = 0; j < n; j++) if (seats[i][j] == '.') good |= 1 << j;
        var nw = new Dictionary<int, int>();
        for (int sub = good; ; sub = (sub - 1) & good) {
            if ((sub & (sub << 1)) == 0) {           // no side-by-side neighbours
                int best = -1;
                foreach (var (prev, val) in dp)      // nobody diagonally in front
                    if ((sub & (prev << 1)) == 0 && (sub & (prev >> 1)) == 0) best = Math.Max(best, val);
                if (best >= 0) nw[sub] = best + BitOperations.PopCount((uint)sub);
            }
            if (sub == 0) break;
        }
        dp = nw;
    }
    return dp.Values.Max();
}

Complexity: O(m · 4ⁿ) time in the worst case, much less in practice, since only masks without adjacent bits survive (55 of 256 for width 8). O(2ⁿ) memory. The official examples give 4 and 3. This problem also has a max-flow solution (it is a maximum independent set in a bipartite graph), but the mask DP is the one to write in an interview.

6. Numbers At Most N Given Digit Set: an empty place is not a zero

LeetCode 902 Hard. Given a set of digits from 1–9 (no 0) and N ≤ 10⁹, how many positive integers ≤ N can be written using only those digits (each digit any number of times)?

Key insight. A number shorter than N is written with leading empty places. Since 0 is not in the set, you can't pretend those places are zeros: model them with started = False, where the only option is "leave this place empty too", which is automatically free (a shorter number is always smaller). Once started, only digits from the set are allowed, up to hi. Use the digits from a set mode of the walk visualizer above to watch the empty branch and the set digits.

Solution: digit DP with an "empty place" branch, O(len(N) · |D|)

def at_most_n_given_digit_set(digits: list[str], n: int) -> int:
    s = str(n)
    D = sorted(int(d) for d in digits)
    @cache
    def f(pos: int, tight: bool, started: bool) -> int:
        if pos == len(s):
            return int(started)
        hi = int(s[pos]) if tight else 9
        total = 0
        if not started:                        # leave this place empty (shorter number)
            total += f(pos + 1, False, False)
        for d in D:
            if d > hi:
                break
            total += f(pos + 1, tight and d == hi, True)
        return total
    return f(0, True, False)

public int AtMostNGivenDigitSet(string[] digits, int n) {
    string s = n.ToString();
    var D = digits.Select(int.Parse).OrderBy(x => x).ToArray();
    var memo = new Dictionary<(int, bool), int>();
    int F(int pos, bool tight, bool started) {
        if (pos == s.Length) return started ? 1 : 0;
        if (!tight && memo.TryGetValue((pos, started), out int v)) return v;
        int hi = tight ? s[pos] - '0' : 9, total = 0;
        if (!started) total += F(pos + 1, false, false);  // leave this place empty
        foreach (int d in D) {
            if (d > hi) break;
            total += F(pos + 1, tight && d == hi, true);
        }
        if (!tight) memo[(pos, started)] = total;
        return total;
    }
    return F(0, true, false);
}

Complexity: O(L · |D|) time and O(L) memory. ["1","3","5","7"] with N = 100 gives 20, and ["1","4","9"] with N = 10⁹ gives 29523. The closed form is "all shorter numbers, |D| + |D|² + … + |D|^(L−1), plus the tight walk", which is exactly what the free subtrees of the DP add up to.

7. Number of Digit One: count occurrences, not numbers

LeetCode 233 Hard. Count the total number of digit 1 appearing in all integers from 0 to n ≤ 10⁹.

Key insight. This sums a quantity over all x ≤ n instead of counting the x. Put "how many 1s so far" into the state and return it at the end: every finished number then contributes its own count of 1s. Leading zeros don't add 1s, so no started flag is needed. The count digit d mode of the table visualizer shows the same count, kept forward as "free prefixes with c ones so far".

Solution: digit DP carrying the count of 1s, O(L² · 10)

def count_digit_one(n: int) -> int:
    s = str(n)
    @cache
    def f(pos: int, ones: int, tight: bool) -> int:
        if pos == len(s):
            return ones                        # each finished number adds its 1s
        hi = int(s[pos]) if tight else 9
        return sum(f(pos + 1, ones + (d == 1), tight and d == hi)
                   for d in range(hi + 1))
    return f(0, 0, True)

public int CountDigitOne(int n) {
    string s = n.ToString();
    var memo = new Dictionary<(int, int), int>();
    int F(int pos, int ones, bool tight) {
        if (pos == s.Length) return ones;            // each number adds its 1s
        if (!tight && memo.TryGetValue((pos, ones), out int v)) return v;
        int hi = tight ? s[pos] - '0' : 9, total = 0;
        for (int d = 0; d <= hi; d++) total += F(pos + 1, ones + (d == 1 ? 1 : 0), tight && d == hi);
        if (!tight) memo[(pos, ones)] = total;
        return total;
    }
    return F(0, 0, true);
}

Complexity: O(L² · 10) time (positions × counts × digits), O(L²) memory. n = 13 gives 6 (1, 10, 11 twice, 12, 13), and n = 10⁹ gives 900,000,001. Digit Count in Range (LeetCode 1067, premium) is the same with any digit d and a range: compare d instead of 1, and use f(high) − f(low − 1). Careful with d = 0: then leading zeros would be counted, so you need the started flag again.

8. Count of Integers: two bounds and a pruned sum

LeetCode 2719 Hard. Given two numeric strings num1 ≤ num2 (up to 10²²) and min_sum ≤ max_sum ≤ 400, count the x in [num1, num2] whose digit sum lies in [min_sum, max_sum], mod 10⁹+7.

Key insight. The state is (pos, sum so far, tight), and a sum above max_sum can be cut off at once, because sums only grow. For the range, count [0, num2] and [0, num1], subtract, and add 1 back if num1 itself qualifies. That avoids computing num1 − 1 on a string.

Solution: digit DP on the digit sum, with f(R) − f(L) + [L ok], O(L · S · 10)

def count(num1: str, num2: str, min_sum: int, max_sum: int) -> int:
    def upto(s: str) -> int:                   # x in [0, s] with digit sum in range
        @cache
        def f(pos: int, total: int, tight: bool) -> int:
            if total > max_sum:
                return 0                       # prune: sums only grow
            if pos == len(s):
                return int(total >= min_sum)
            hi = int(s[pos]) if tight else 9
            return sum(f(pos + 1, total + d, tight and d == hi)
                       for d in range(hi + 1)) % MOD
        return f(0, 0, True)
    own = int(min_sum <= sum(map(int, num1)) <= max_sum)
    return (upto(num2) - upto(num1) + own) % MOD   # [num1, num2] = f(num2) - f(num1 - 1)

public int Count(string num1, string num2, int min_sum, int max_sum) {
    long Upto(string s) {                            // x in [0, s], digit sum in range
        var memo = new Dictionary<(int, int), long>();
        long F(int pos, int total, bool tight) {
            if (total > max_sum) return 0;           // prune: sums only grow
            if (pos == s.Length) return total >= min_sum ? 1 : 0;
            if (!tight && memo.TryGetValue((pos, total), out long v)) return v;
            int hi = tight ? s[pos] - '0' : 9;
            long res = 0;
            for (int d = 0; d <= hi; d++) res = (res + F(pos + 1, total + d, tight && d == hi)) % MOD;
            if (!tight) memo[(pos, total)] = res;
            return res;
        }
        return F(0, 0, true);
    }
    int own = num1.Sum(c => c - '0');
    long ans = Upto(num2) - Upto(num1) + (min_sum <= own && own <= max_sum ? 1 : 0);
    return (int)(((ans % MOD) + MOD) % MOD);
}

Complexity: O(L · S · 10) time, with L ≤ 23 digits and S ≤ 400: about 10⁵ steps. count("1", "12", 1, 8) gives 11 (1–8, 10, 11, 12). In C#, (a − b) % MOD can be negative, so the code returns ((ans % MOD) + MOD) % MOD.

Check yourself

1. Why is the TSP state dp[mask][last] and not just dp[mask]?

The cost of the next step, w[last][k], depends on where you are standing. Two routes over the same set that end at different cities have different futures, so they cannot share a state. Two routes over the same set that end at the same city do have the same future, and that is the merge that cuts n! down to n²·2ⁿ.

2. In the assignment DP, the state does not say whose turn it is. Why is that safe?

The people are served in a fixed order: 0, 1, 2, … So if k tasks are taken, persons 0 … k−1 have been served, and it is person k = popcount(mask)'s turn. The state already implies it. Any information that can be computed from the state never needs its own dimension.

3. List the submasks visited by sub = (sub − 1) & mask for mask = 0b1010.

1010 → 1000 → 0010 → 0000. From 1010, minus 1 is 1001, and & 1010 gives 1000. Minus 1 is 0111, & 1010 gives 0010. Minus 1 is 0001, & 1010 gives 0000. That is 2² = 4 submasks, in decreasing order, which is exactly binary counting on the two bits of the mask.

4. Why does enumerating the submasks of every mask of n bits take 3ⁿ steps?

Each step is a pair (mask, sub) with sub ⊆ mask. Look at one item: it can be in neither, in mask only, or in both. It cannot be in sub without being in mask. Three independent choices for each of n items give 3ⁿ pairs.

5. N = 2731. Which prefixes of length 2 are tight and which are free?

Only 27 is tight. The free ones are 00–19 (first digit below 2, any second digit: 20 prefixes) and 20–26 (first digit tight, second digit below 7: 7 prefixes), so 27 free prefixes. Every free prefix can be completed with any two digits, which is why their counts only depend on the state, not on the prefix itself.

6. When do you need the started (leading-zero) flag, and when can you drop it?

You need it whenever a padding zero would be mistaken for a real 0: distinct digits (0 would be marked as used), digit sets without 0, counting the digit 0, or "stepping numbers" where the first real digit has no predecessor. You also need it to exclude 0 when counting positive integers. You can drop it when leading zeros cannot change the property: digit sums, remainders, counting 1s, no 11 in binary.

7. In Number of Ways to Wear Different Hats, why do the masks go from high to low?

Within the round for hat h, dp is updated in place: dp[mask | 1 << p] += dp[mask]. The target is a larger mask. Going from high to low means a mask is read before it can be written in this round, so its value still comes from the previous hats only, and hat h is handed out at most once. Going low to high would let the same hat go to a second person, the same mistake as an unbounded knapsack loop in a 0/1 problem.

8. What is the state for "count x in [1, N] divisible by 7 whose digit sum is also divisible by 7"?

(pos, x mod 7, digit sum mod 7, tight). Appending digit d maps the remainder r to (10·r + d) % 7 and the sum s to (s + d) % 7. Leading zeros change neither, but 0 itself has both equal to 0, so subtract it (or use started). That is L · 7 · 7 · 10 steps.
