Segment Trees, Fenwick Trees & Sparse Tables

Range queries with point and lazy range updates, binary indexed trees decoded bit by bit, and O(1) RMQ with sparse tables.

Advanced → Expert~75 min studyBuilds on: Prefix Sums & Difference Arrays, Tree TraversalsUpdated 2026-11-03

Prefix Sums answer "sum of a[l..r]" in O(1), but only while the array stays frozen: change one element and up to n stored prefixes go stale. This page covers the structures that keep range answers cheap while the array changes. A Fenwick tree (binary indexed tree, BIT) is twelve lines of code built on one bit trick. A segment tree handles any associative combine (sum, min, max, gcd, "best subarray", matrix product). With lazy propagation it also handles range updates. A sparse table gives O(1) range-minimum queries on a static array. Then come the moves that make these structures solve hard problems: coordinate compression, counting with a BIT over value ranks, walking down a tree to find the k-th element, dynamic trees over coordinates up to 10⁹, and sweep lines with a cover-count tree.

The invariant. Precompute answers for a set of blocks chosen so that every query range is a union of O(log n) blocks and every array position lies in O(log n) blocks. A query combines a few blocks; an update repairs a few blocks. Fenwick trees, segment trees and sparse tables differ only in which blocks they choose.

Prerequisites: Prefix Sums (prefix differences, difference arrays, 2D inclusion-exclusion) and Tree Traversals (a segment tree is a binary tree in an array, built in postorder). The doubling idea behind sparse tables also drives binary lifting in Tree Problem Patterns, and rank queries here complement the order statistics of Binary Search Trees. The sweep-line problems (My Calendar, Rectangle Area II) were introduced with simpler tools in Intervals & Sweep Line; here they get their O(n log n) versions.

The problem: queries and updates on the same array

Every structure on this page is a trade between two costs. A plain array updates in O(1) but sums a range in O(n). A prefix array sums in O(1) but an update rewrites O(n) prefixes. When a problem interleaves 10⁵ updates and 10⁵ queries, both are O(n · q) ≈ 10¹⁰: too slow. The structures below make both operations O(log n), which is about 17 steps for n = 10⁵.

Fenwick trees

A Fenwick tree stores n numbers t[1..n] (1-based: index 0 is unused). Each t[i] holds the sum of a block of the array that ends at i. How long is the block? That is decided by the binary form of i, and the whole data structure follows from that one rule.

lowbit: the bit trick behind it

lowbit(i) = i & -i keeps only the lowest set bit of i: 12 = 1100 gives 0100 = 4. It works because negative numbers are stored in two's complement: -i = ~i + 1. Flipping every bit turns the trailing zeros of i into ones; the +1 then carries through them and stops at the first zero of ~i, which is exactly where i had its lowest 1. Every bit above it differs between i and -i, every bit below it is 0 in both, so the AND keeps that one bit.

The block rule: t[i] covers a[i − lowbit(i) + 1 .. i], so its length is lowbit(i). Odd indices own one cell, multiples of 2 (not 4) own two, multiples of 4 (not 8) own four, and so on. Step through the visualizer: the bits on top, the block it implies below.

The picture is the whole data structure. To sum a prefix a[1..i], take block t[i], jump to the index just left of it (i -= lowbit(i), which clears the lowest set bit) and repeat. Each jump removes one 1 bit, so the walk takes at most log₂ n + 1 steps: one block per set bit of i. To update a[i], every block that contains position i must change. They are t[i], then t[i + lowbit(i)] (the smallest block that swallows the current one), and so on up to n. Each step moves the lowest set bit at least one place left, so this is O(log n) too.

Query walks left, update walks up

Pick an operation. In range sum mode the green blocks are added (prefix(r)) and the red ones subtracted (prefix(l − 1)): the red part cancels out. build in O(n) shows why you never need n separate add calls.

Why the O(n) build works Visit i = 1..n in order. When we reach i, every block nested inside t[i] has a smaller index and has already added itself to t[i], so t[i] is final. Its parent block is t[i + lowbit(i)]: pass the total up once. Every index passes exactly once, so the build is n additions. The same idea builds a segment tree bottom-up.

Template

class Fenwick:
    """Positions 1..n. add, prefix and lower_bound are O(log n)."""

    def __init__(self, n):
        self.n = n
        self.t = [0] * (n + 1)          # t[0] is never used

    @classmethod
    def from_list(cls, a):              # O(n) build; a[0] goes to position 1
        fw = cls(len(a))
        fw.t[1:] = a
        for i in range(1, fw.n + 1):
            j = i + (i & -i)            # the block directly above i
            if j <= fw.n:
                fw.t[j] += fw.t[i]
        return fw

    def add(self, i, delta):            # a[i] += delta
        while i <= self.n:
            self.t[i] += delta
            i += i & -i                 # next block that contains i

    def prefix(self, i):                # a[1] + ... + a[i]; prefix(0) == 0
        s = 0
        while i > 0:
            s += self.t[i]
            i -= i & -i                 # drop the lowest set bit
        return s

    def range_sum(self, l, r):          # a[l] + ... + a[r], inclusive
        return self.prefix(r) - self.prefix(l - 1)

    def lower_bound(self, k):           # smallest i with prefix(i) >= k; needs a[i] >= 0
        pos, step = 0, 1 << self.n.bit_length()
        while step:
            nxt = pos + step
            if nxt <= self.n and self.t[nxt] < k:
                pos = nxt               # the whole block is still below k: skip it
                k -= self.t[nxt]
            step >>= 1
        return pos + 1                  # n + 1 when the total is below k

public class Fenwick
{
    private readonly long[] t;          // t[0] is never used
    public int N { get; }

    public Fenwick(int n) { N = n; t = new long[n + 1]; }

    public static Fenwick FromArray(IReadOnlyList<long> a)   // O(n); a[0] goes to position 1
    {
        var fw = new Fenwick(a.Count);
        for (int i = 1; i <= fw.N; i++) fw.t[i] = a[i - 1];
        for (int i = 1; i <= fw.N; i++)
        {
            int j = i + (i & -i);       // the block directly above i
            if (j <= fw.N) fw.t[j] += fw.t[i];
        }
        return fw;
    }

    public void Add(int i, long delta)  // a[i] += delta
    {
        for (; i <= N; i += i & -i) t[i] += delta;
    }

    public long Prefix(int i)           // a[1] + ... + a[i]; Prefix(0) == 0
    {
        long s = 0;
        for (; i > 0; i -= i & -i) s += t[i];
        return s;
    }

    public long RangeSum(int l, int r) => Prefix(r) - Prefix(l - 1);

    public int LowerBound(long k)       // smallest i with Prefix(i) >= k; needs a[i] >= 0
    {
        int pos = 0, step = 1;
        while (step <= N) step <<= 1;
        for (; step > 0; step >>= 1)
        {
            int nxt = pos + step;
            if (nxt <= N && t[nxt] < k) { pos = nxt; k -= t[nxt]; }
        }
        return pos + 1;                 // N + 1 when the total is below k
    }
}

Complexity. add, prefix, range_sum, lower_bound: O(log n). from_list: O(n). Space: n + 1 numbers, no pointers, no 4n array. That compactness is why Fenwick trees are the first choice whenever the combine is a sum.

What a Fenwick tree cannot do directly range_sum works because sums can be subtracted: prefix(r) − prefix(l − 1). Minimum cannot: knowing min(a[1..r]) and min(a[1..l−1]) tells you nothing about min(a[l..r]). A Fenwick tree can still keep a prefix max if values only increase (each update does t[i] = max(t[i], v) up the chain), which is enough for LIS-style DP. For arbitrary range min or max, use a segment tree or a sparse table.

Walking down: the k-th smallest in O(log n)

Keep a Fenwick tree over counts: cnt[v] = how many copies of value v are in a multiset. Then prefix(v) is the number of elements ≤ v, and the k-th smallest is the first v with prefix(v) ≥ k. A binary search over v that calls prefix each time costs O(log² n). lower_bound does it in O(log n) by descending through the blocks themselves, exactly like binary lifting in Tree Problem Patterns: try the biggest jump first, keep it if it does not overshoot.

Why is t[pos + 2^s] exactly the block a[pos + 1 .. pos + 2^s]? Because pos is built only from bigger powers of two than 2^s, so pos + 2^s has lowest set bit 2^s and its block has length 2^s, starting right after pos. Each step decides one bit of the answer, from the top bit down. This turns a Fenwick tree into an order-statistics multiset on a bounded value range: insert, delete, rank (prefix(v − 1)) and k-th, all O(log n). It is a common replacement for a balanced BST when the values are small or can be compressed.

Range updates: put a difference array inside

Prefix Sums showed the difference array: to add x to a[l..r], do d[l] += x and d[r + 1] -= x; then a[i] = d[1] + … + d[i]. Those are two point updates and one prefix sum, which is exactly what a Fenwick tree does well. So a BIT over d gives range add + point query in O(log n), and it works online (queries between updates), which the plain difference array cannot do.

Range add + range sum needs one more step. The sum of a[1..i] counts each d[j] once for every position from j to i, that is (i − j + 1) times:

The term i · Σ d[j] is a prefix sum of d times i. The term Σ d[j]·(j − 1) is a prefix sum of a second array. Keep one Fenwick tree for each. A range add touches two entries of each, so it is four point updates. Step through: the top row is the array you are simulating, which nobody stores.

class RangeFenwick:
    """Range add and range sum on positions 1..n, both O(log n)."""

    def __init__(self, n):
        self.n = n
        self.b1 = [0] * (n + 1)         # Fenwick over d[j]
        self.b2 = [0] * (n + 1)         # Fenwick over d[j] * (j - 1)

    def _add(self, t, i, x):
        while i <= self.n:
            t[i] += x
            i += i & -i

    def _prefix(self, t, i):
        s = 0
        while i > 0:
            s += t[i]
            i -= i & -i
        return s

    def range_add(self, l, r, x):       # a[l..r] += x
        self._add(self.b1, l, x)
        self._add(self.b1, r + 1, -x)   # no-op when r == n
        self._add(self.b2, l, x * (l - 1))
        self._add(self.b2, r + 1, -x * r)

    def prefix_sum(self, i):            # a[1] + ... + a[i]
        return self._prefix(self.b1, i) * i - self._prefix(self.b2, i)

    def range_sum(self, l, r):
        return self.prefix_sum(r) - self.prefix_sum(l - 1)

    def point(self, i):                 # a[i] alone needs only b1
        return self._prefix(self.b1, i)

public class RangeFenwick
{
    private readonly long[] b1, b2;     // Fenwick over d[j] and over d[j] * (j - 1)
    private readonly int n;

    public RangeFenwick(int n) { this.n = n; b1 = new long[n + 1]; b2 = new long[n + 1]; }

    private void Add(long[] t, int i, long x) { for (; i <= n; i += i & -i) t[i] += x; }

    private static long Prefix(long[] t, int i) { long s = 0; for (; i > 0; i -= i & -i) s += t[i]; return s; }

    public void RangeAdd(int l, int r, long x)   // a[l..r] += x
    {
        Add(b1, l, x);
        Add(b1, r + 1, -x);             // no-op when r == n
        Add(b2, l, x * (l - 1));
        Add(b2, r + 1, -x * r);
    }

    public long PrefixSum(int i) => Prefix(b1, i) * i - Prefix(b2, i);

    public long RangeSum(int l, int r) => PrefixSum(r) - PrefixSum(l - 1);

    public long Point(int i) => Prefix(b1, i);
}

2D Fenwick trees

Nest the loops: t[i][j] covers the rectangle of rows i − lowbit(i) + 1 .. i and columns j − lowbit(j) + 1 .. j. A point update walks up in both dimensions, a prefix query walks left in both, and a rectangle sum uses the same inclusion-exclusion as 2D prefix sums. Both operations are O(log R · log C). This is the standard answer to "Range Sum Query 2D - Mutable".

class Fenwick2D:
    def __init__(self, rows, cols):
        self.R, self.C = rows, cols
        self.t = [[0] * (cols + 1) for _ in range(rows + 1)]

    def add(self, r, c, delta):         # cell (r, c), 1-based
        i = r
        while i <= self.R:
            j = c
            while j <= self.C:
                self.t[i][j] += delta
                j += j & -j
            i += i & -i

    def prefix(self, r, c):             # sum of the rectangle (1, 1)..(r, c)
        s, i = 0, r
        while i > 0:
            j = c
            while j > 0:
                s += self.t[i][j]
                j -= j & -j
            i -= i & -i
        return s

    def rect(self, r1, c1, r2, c2):     # inclusive corners
        return (self.prefix(r2, c2) - self.prefix(r1 - 1, c2)
                - self.prefix(r2, c1 - 1) + self.prefix(r1 - 1, c1 - 1))

public class Fenwick2D
{
    private readonly long[,] t;
    private readonly int R, C;

    public Fenwick2D(int rows, int cols) { R = rows; C = cols; t = new long[rows + 1, cols + 1]; }

    public void Add(int r, int c, long delta)    // cell (r, c), 1-based
    {
        for (int i = r; i <= R; i += i & -i)
            for (int j = c; j <= C; j += j & -j)
                t[i, j] += delta;
    }

    public long Prefix(int r, int c)    // sum of the rectangle (1, 1)..(r, c)
    {
        long s = 0;
        for (int i = r; i > 0; i -= i & -i)
            for (int j = c; j > 0; j -= j & -j)
                s += t[i, j];
        return s;
    }

    public long Rect(int r1, int c1, int r2, int c2) =>
        Prefix(r2, c2) - Prefix(r1 - 1, c2) - Prefix(r2, c1 - 1) + Prefix(r1 - 1, c1 - 1);
}

Segment trees

A segment tree is a binary tree over ranges. The root owns [0..n−1]; a node that owns [l..r] splits at m = (l + r) // 2 and gives [l..m] to its left child and [m+1..r] to its right child; leaves own one index. Each node stores f over its range. It is stored like a heap: node k has children 2k and 2k + 1, so no pointers are needed.

Query. Ask each node one question: how does my range relate to [ql..qr]?

  • Disjoint: return the identity (0 for sum, +∞ for min). Do not look inside.
  • Fully inside: return the stored value as one piece. Do not look inside.
  • Partial overlap: ask both children and combine.

Why O(log n)? At any depth, at most two nodes are partial: the ones that contain the query's left edge and its right edge. Everything strictly between them is fully inside, and their parents were already fully inside, so the recursion never reaches them. Two partial nodes per level, each with two children, means at most four visits per level.

Update. Change a leaf, then recompute every ancestor on the way back up: one node per level. Pick f and an operation below; green bars are the pieces the answer is assembled from.

Template: point update, range query, any associative f

class SegTree:
    """Point assign and range query for any associative f with identity ident."""

    def __init__(self, a, f=lambda x, y: x + y, ident=0):
        self.n, self.f, self.ident = len(a), f, ident
        self.tree = [ident] * (4 * max(1, self.n))   # 4n always suffices
        if self.n:
            self._build(a, 1, 0, self.n - 1)

    def _build(self, a, node, l, r):
        if l == r:
            self.tree[node] = a[l]
            return
        m = (l + r) // 2
        self._build(a, 2 * node, l, m)
        self._build(a, 2 * node + 1, m + 1, r)
        self.tree[node] = self.f(self.tree[2 * node], self.tree[2 * node + 1])

    def update(self, i, val, node=1, l=0, r=None):   # a[i] = val
        if r is None:
            r = self.n - 1
        if l == r:
            self.tree[node] = val
            return
        m = (l + r) // 2
        if i <= m:
            self.update(i, val, 2 * node, l, m)
        else:
            self.update(i, val, 2 * node + 1, m + 1, r)
        self.tree[node] = self.f(self.tree[2 * node], self.tree[2 * node + 1])

    def query(self, ql, qr, node=1, l=0, r=None):    # f(a[ql..qr]), inclusive
        if r is None:
            r = self.n - 1
        if qr < l or r < ql:                         # disjoint
            return self.ident
        if ql <= l and r <= qr:                      # fully inside
            return self.tree[node]
        m = (l + r) // 2                             # partial: split
        return self.f(self.query(ql, qr, 2 * node, l, m),
                      self.query(ql, qr, 2 * node + 1, m + 1, r))

public class SegTree
{
    private readonly long[] tree;
    private readonly int n;
    private readonly Func<long, long, long> f;
    private readonly long ident;

    public SegTree(IReadOnlyList<long> a, Func<long, long, long> f, long ident)
    {
        n = a.Count; this.f = f; this.ident = ident;
        tree = new long[4 * Math.Max(1, n)];          // 4n always suffices
        Array.Fill(tree, ident);
        if (n > 0) Build(a, 1, 0, n - 1);
    }

    public int Count => n;
    public long Node(int node) => tree[node];

    private void Build(IReadOnlyList<long> a, int node, int l, int r)
    {
        if (l == r) { tree[node] = a[l]; return; }
        int m = (l + r) / 2;
        Build(a, 2 * node, l, m);
        Build(a, 2 * node + 1, m + 1, r);
        tree[node] = f(tree[2 * node], tree[2 * node + 1]);
    }

    public void Update(int i, long val) => Update(i, val, 1, 0, n - 1);

    private void Update(int i, long val, int node, int l, int r)
    {
        if (l == r) { tree[node] = val; return; }
        int m = (l + r) / 2;
        if (i <= m) Update(i, val, 2 * node, l, m);
        else Update(i, val, 2 * node + 1, m + 1, r);
        tree[node] = f(tree[2 * node], tree[2 * node + 1]);
    }

    public long Query(int ql, int qr) => Query(ql, qr, 1, 0, n - 1);

    private long Query(int ql, int qr, int node, int l, int r)
    {
        if (qr < l || r < ql) return ident;               // disjoint
        if (ql <= l && r <= qr) return tree[node];        // fully inside
        int m = (l + r) / 2;                              // partial: split
        return f(Query(ql, qr, 2 * node, l, m), Query(ql, qr, 2 * node + 1, m + 1, r));
    }
}

Complexity. Build O(n), update O(log n), query O(log n), space 4n. Why 4n: the tree has depth ⌈log₂ n⌉, so heap indices reach 2^(⌈log₂ n⌉ + 1) < 4n. With n = 6 there are only 2n − 1 = 11 nodes, but the heap numbering leaves gaps and the deepest leaf sits at index 13.

What can a node store?

Anything that combines associatively: f(f(x, y), z) = f(x, f(y, z)). The tree regroups the elements freely, but it never reorders them, so f does not need to be commutative. That opens up far more than sums:

Descending the tree: first index with a[i] ≥ x

A segment tree can also search. "Find the leftmost i with a[i] ≥ x" on a max tree: at each node, if the left child's max is ≥ x the answer is on the left, so go left; otherwise go right. Only one path is followed, so it is O(log n), the segment-tree version of the Fenwick descent above. The same walk answers "k-th one in a 0/1 array" on a sum tree and "first position where the prefix sum exceeds k".

def first_at_least(st, x):
    """st is a SegTree built with f = max. Smallest i with a[i] >= x, or -1. O(log n)."""
    def go(node, l, r):
        if st.tree[node] < x:
            return -1                   # nothing in this range is big enough
        if l == r:
            return l
        m = (l + r) // 2
        res = go(2 * node, l, m)        # if the left max is >= x this succeeds
        return res if res != -1 else go(2 * node + 1, m + 1, r)
    return go(1, 0, st.n - 1) if st.n else -1

public static class SegTreeSearch
{
    // st must be built with f = Math.Max. Smallest i with a[i] >= x, or -1. O(log n).
    public static int FirstAtLeast(SegTree st, long x) => st.Count == 0 ? -1 : Go(st, x, 1, 0, st.Count - 1);

    private static int Go(SegTree st, long x, int node, int l, int r)
    {
        if (st.Node(node) < x) return -1;                 // nothing in this range is big enough
        if (l == r) return l;
        int m = (l + r) / 2;
        int res = Go(st, x, 2 * node, l, m);              // if the left max is >= x this succeeds
        return res != -1 ? res : Go(st, x, 2 * node + 1, m + 1, r);
    }
}

Lazy propagation: range updates

"Add 3 to a[2..8]" would touch every leaf in the range, which is O(n). Lazy propagation reuses the query's trick: decompose [2..8] into O(log n) fully covered nodes. Update only those nodes, and write a note on each one, a tag, saying "every element below me still owes +3". The children stay stale until someone needs to walk through this node. That walker first pushes the tag one level down: it applies the tag to both children (updating their values and adding to their tags) and clears it.

Two operations make up the whole technique:

  • apply(node, x): bring the node's value up to date (sum += x · length) and remember x in its tag.
  • push(node): apply the node's tag to both children, then clear the tag. Call it before you descend into the children, in updates and queries.

After recursing, recompute the node from its children as usual. Watch the tags (small amber labels) get written on covered nodes and pushed down only when a later operation needs to pass through:

class LazySegTree:
    """Range add and range sum on a[0..n-1], O(log n) each."""

    def __init__(self, a):
        self.n = len(a)
        size = 4 * max(1, self.n)
        self.sum = [0] * size
        self.tag = [0] * size           # pending add owed by every element of the node's range
        if self.n:
            self._build(a, 1, 0, self.n - 1)

    def _build(self, a, node, l, r):
        if l == r:
            self.sum[node] = a[l]
            return
        m = (l + r) // 2
        self._build(a, 2 * node, l, m)
        self._build(a, 2 * node + 1, m + 1, r)
        self.sum[node] = self.sum[2 * node] + self.sum[2 * node + 1]

    def _apply(self, node, l, r, x):
        self.sum[node] += x * (r - l + 1)
        self.tag[node] += x

    def _push(self, node, l, m, r):
        if self.tag[node]:
            self._apply(2 * node, l, m, self.tag[node])
            self._apply(2 * node + 1, m + 1, r, self.tag[node])
            self.tag[node] = 0

    def add(self, ql, qr, x, node=1, l=0, r=None):   # a[ql..qr] += x
        if r is None:
            r = self.n - 1
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            self._apply(node, l, r, x)              # covered: tag it and stop
            return
        m = (l + r) // 2
        self._push(node, l, m, r)                   # about to descend: settle the debt
        self.add(ql, qr, x, 2 * node, l, m)
        self.add(ql, qr, x, 2 * node + 1, m + 1, r)
        self.sum[node] = self.sum[2 * node] + self.sum[2 * node + 1]

    def query(self, ql, qr, node=1, l=0, r=None):   # a[ql] + ... + a[qr]
        if r is None:
            r = self.n - 1
        if qr < l or r < ql:
            return 0
        if ql <= l and r <= qr:
            return self.sum[node]
        m = (l + r) // 2
        self._push(node, l, m, r)
        return (self.query(ql, qr, 2 * node, l, m)
                + self.query(ql, qr, 2 * node + 1, m + 1, r))

public class LazySegTree
{
    private readonly long[] sum, tag;    // tag: pending add owed by every element of the node's range
    private readonly int n;

    public LazySegTree(IReadOnlyList<long> a)
    {
        n = a.Count;
        sum = new long[4 * Math.Max(1, n)];
        tag = new long[4 * Math.Max(1, n)];
        if (n > 0) Build(a, 1, 0, n - 1);
    }

    private void Build(IReadOnlyList<long> a, int node, int l, int r)
    {
        if (l == r) { sum[node] = a[l]; return; }
        int m = (l + r) / 2;
        Build(a, 2 * node, l, m);
        Build(a, 2 * node + 1, m + 1, r);
        sum[node] = sum[2 * node] + sum[2 * node + 1];
    }

    private void Apply(int node, int l, int r, long x) { sum[node] += x * (r - l + 1); tag[node] += x; }

    private void Push(int node, int l, int m, int r)
    {
        if (tag[node] == 0) return;
        Apply(2 * node, l, m, tag[node]);
        Apply(2 * node + 1, m + 1, r, tag[node]);
        tag[node] = 0;
    }

    public void Add(int ql, int qr, long x) => Add(ql, qr, x, 1, 0, n - 1);

    private void Add(int ql, int qr, long x, int node, int l, int r)
    {
        if (qr < l || r < ql) return;
        if (ql <= l && r <= qr) { Apply(node, l, r, x); return; }   // covered: tag it and stop
        int m = (l + r) / 2;
        Push(node, l, m, r);                                         // about to descend: settle the debt
        Add(ql, qr, x, 2 * node, l, m);
        Add(ql, qr, x, 2 * node + 1, m + 1, r);
        sum[node] = sum[2 * node] + sum[2 * node + 1];
    }

    public long Query(int ql, int qr) => Query(ql, qr, 1, 0, n - 1);

    private long Query(int ql, int qr, int node, int l, int r)
    {
        if (qr < l || r < ql) return 0;
        if (ql <= l && r <= qr) return sum[node];
        int m = (l + r) / 2;
        Push(node, l, m, r);
        return Query(ql, qr, 2 * node, l, m) + Query(ql, qr, 2 * node + 1, m + 1, r);
    }
}

The iterative (bottom-up) segment tree

When f is all you need (no lazy tags), there is a shorter and roughly 2–3× faster version with no recursion and exactly 2n cells. Put the leaves at t[n..2n−1]; node i has children 2i and 2i + 1, so its parent is i // 2. Build every internal node from n − 1 down to 1.

The query uses a half-open range [l, r). Move l and r to their leaves, then climb both together:

  • If l is a right child (odd), its parent also covers l − 1, which is outside the range. So take t[l] now and step l one to the right before climbing.
  • If r is a right child (odd), the cell r − 1 is a left child that belongs inside the range, but its parent also covers r, which is outside. So step r back and take t[r].
  • Climb: l //= 2, r //= 2, until l meets r.

Keep the left and right results separate (resl, resr) so the order of elements is preserved when f is not commutative.

class IterSegTree:
    """Leaves at t[n..2n-1]. Point assign, f over the half-open range [l, r)."""

    def __init__(self, a, f=lambda x, y: x + y, ident=0):
        self.n, self.f, self.ident = len(a), f, ident
        self.t = [ident] * self.n + list(a)
        for i in range(self.n - 1, 0, -1):
            self.t[i] = f(self.t[2 * i], self.t[2 * i + 1])

    def update(self, i, val):
        i += self.n
        self.t[i] = val
        while i > 1:
            i //= 2
            self.t[i] = self.f(self.t[2 * i], self.t[2 * i + 1])

    def query(self, l, r):              # f(a[l..r-1])
        resl = resr = self.ident
        l += self.n
        r += self.n
        while l < r:
            if l & 1:                   # l is a right child: take it, move right
                resl = self.f(resl, self.t[l])
                l += 1
            if r & 1:                   # r is a right child: step back, take r - 1
                r -= 1
                resr = self.f(self.t[r], resr)
            l //= 2
            r //= 2
        return self.f(resl, resr)

public class IterSegTree
{
    private readonly long[] t;
    private readonly int n;
    private readonly Func<long, long, long> f;
    private readonly long ident;

    public IterSegTree(IReadOnlyList<long> a, Func<long, long, long> f, long ident)
    {
        n = a.Count; this.f = f; this.ident = ident;
        t = new long[2 * n];
        for (int i = 0; i < n; i++) t[n + i] = a[i];
        for (int i = n - 1; i > 0; i--) t[i] = f(t[2 * i], t[2 * i + 1]);
    }

    public void Update(int i, long val)
    {
        i += n;
        t[i] = val;
        for (i /= 2; i >= 1; i /= 2) t[i] = f(t[2 * i], t[2 * i + 1]);
    }

    public long Query(int l, int r)     // f(a[l..r-1])
    {
        long resl = ident, resr = ident;
        for (l += n, r += n; l < r; l /= 2, r /= 2)
        {
            if ((l & 1) == 1) resl = f(resl, t[l++]);   // l is a right child: take it, move right
            if ((r & 1) == 1) resr = f(t[--r], resr);   // r is a right child: step back, take r - 1
        }
        return f(resl, resr);
    }
}

When n is not a power of two Some internal nodes then combine leaves that are not next to each other (with n = 10, node 2 in the figure combines a[6..9] with a[0..1]). That is harmless: a query only ever takes nodes whose whole range is inside [l, r), and those are always contiguous. Descents like first_at_least do need contiguous ranges, so use the recursive tree (or pad n to a power of two) for them.

Dynamic segment trees: create nodes only when touched

Sometimes the index range is huge, like [0, 10⁹], and the queries arrive online, so you cannot collect and compress the coordinates first. Then do not allocate the tree up front. Start with only the root, and create a child the first time an operation walks into it. Each operation creates at most one path, so q operations make O(q log C) nodes, where C is the size of the range. A missing child simply means "all zeros (or the identity) below here".

class DynamicSegTree:
    """Point add and range sum over [lo, hi] without allocating the whole range."""

    def __init__(self, lo, hi):
        self.lo, self.hi = lo, hi
        self.left, self.right, self.sum = [0, 0], [0, 0], [0, 0]   # node 0 = null, node 1 = root

    def _new(self):
        self.left.append(0)
        self.right.append(0)
        self.sum.append(0)
        return len(self.sum) - 1

    def add(self, i, x):
        node, l, r = 1, self.lo, self.hi
        while True:
            self.sum[node] += x
            if l == r:
                return
            m = (l + r) // 2
            if i <= m:
                if not self.left[node]:
                    self.left[node] = self._new()
                node, r = self.left[node], m
            else:
                if not self.right[node]:
                    self.right[node] = self._new()
                node, l = self.right[node], m + 1

    def query(self, ql, qr, node=1, l=None, r=None):
        if l is None:
            l, r = self.lo, self.hi
        if node == 0 or qr < l or r < ql:       # missing child = all zeros
            return 0
        if ql <= l and r <= qr:
            return self.sum[node]
        m = (l + r) // 2
        return (self.query(ql, qr, self.left[node], l, m)
                + self.query(ql, qr, self.right[node], m + 1, r))

public class DynamicSegTree
{
    private readonly List<int> left = new() { 0, 0 }, right = new() { 0, 0 };   // node 0 = null, node 1 = root
    private readonly List<long> sum = new() { 0, 0 };
    private readonly long lo, hi;

    public DynamicSegTree(long lo, long hi) { this.lo = lo; this.hi = hi; }

    private int NewNode() { left.Add(0); right.Add(0); sum.Add(0); return sum.Count - 1; }

    public void Add(long i, long x)
    {
        int node = 1;
        long l = lo, r = hi;
        while (true)
        {
            sum[node] += x;
            if (l == r) return;
            long m = l + (r - l) / 2;
            if (i <= m)
            {
                if (left[node] == 0) { int c = NewNode(); left[node] = c; }
                node = left[node]; r = m;
            }
            else
            {
                if (right[node] == 0) { int c = NewNode(); right[node] = c; }
                node = right[node]; l = m + 1;
            }
        }
    }

    public long Query(long ql, long qr) => Query(ql, qr, 1, lo, hi);

    private long Query(long ql, long qr, int node, long l, long r)
    {
        if (node == 0 || qr < l || r < ql) return 0;        // missing child = all zeros
        if (ql <= l && r <= qr) return sum[node];
        long m = l + (r - l) / 2;
        return Query(ql, qr, left[node], l, m) + Query(ql, qr, right[node], m + 1, r);
    }
}

The same idea works with lazy tags: when you push into a missing child, create it first. That is the standard answer for My Calendar III when you do not want to sort the events.

Trees over values: coordinate compression

Many counting problems ask "how many of the elements seen so far are smaller than x?". Index the tree by value instead of position: cnt[v] = how many times v has been seen. Then "how many seen are < x" is prefix(x − 1). Values can be negative or as large as 10⁹, but only their order matters, so replace each value by its rank among the distinct values. That is coordinate compression: sort the distinct values once (Sorting), then look ranks up with binary search (Binary Search) or a dict (Hashing).

def compress(values):
    """Map each value to its 1-based rank among the distinct values (Fenwick-ready)."""
    order = sorted(set(values))
    rank = {v: i + 1 for i, v in enumerate(order)}
    return [rank[v] for v in values], len(order)

public static class Compression
{
    // Map each value to its 1-based rank among the distinct values (Fenwick-ready).
    public static (int[] ranks, int m) Compress(IReadOnlyList<long> values)
    {
        long[] order = values.Distinct().OrderBy(v => v).ToArray();
        var rank = new Dictionary<long, int>();
        for (int i = 0; i < order.Length; i++) rank[order[i]] = i + 1;
        return (values.Select(v => rank[v]).ToArray(), order.Length);
    }
}

Compress everything you will ever look up If a query asks about a value that is not in the array (like x − lower in Count of Range Sum), either add it to the list you compress, or look it up with bisect_left / bisect_right on the sorted list so you get the correct rank boundary without needing the exact value.

Sparse tables: O(1) queries when nothing changes

If the array never changes and f is min, max or gcd, there is something faster than a segment tree. Precompute st[k][i] = f over the block of length 2^k that starts at i. Each level is built from the one below in O(n): st[k][i] = f(st[k−1][i], st[k−1][i + 2^(k−1)]), so the build is O(n log n).

To answer [l..r], let k be the largest power with 2^k ≤ length. Two blocks of that length, one starting at l and one ending at r, together cover the whole range. They usually overlap, and for min that does not matter, because counting an element twice does not change a minimum. Functions with this property, f(x, x) = x, are called idempotent: min, max, gcd, bitwise and/or. Sum is not idempotent: the overlap would be counted twice. Pick "sum (breaks: overlap)" below to see exactly which elements get double-counted.

class SparseTable:
    """Static array, idempotent f (min, max, gcd, and, or). O(n log n) build, O(1) query."""

    def __init__(self, a, f=min):
        self.f = f
        n = len(a)
        self.log = [0] * (n + 1)                 # log[x] = floor(log2(x))
        for x in range(2, n + 1):
            self.log[x] = self.log[x // 2] + 1
        self.st = [list(a)]                      # st[k][i] = f(a[i .. i + 2^k - 1])
        k = 1
        while (1 << k) <= n:
            prev, half = self.st[-1], 1 << (k - 1)
            self.st.append([f(prev[i], prev[i + half]) for i in range(n - (1 << k) + 1)])
            k += 1

    def query(self, l, r):                       # inclusive
        k = self.log[r - l + 1]
        return self.f(self.st[k][l], self.st[k][r - (1 << k) + 1])

public class SparseTable
{
    private readonly long[][] st;       // st[k][i] = f(a[i .. i + 2^k - 1])
    private readonly int[] log;         // log[x] = floor(log2(x))
    private readonly Func<long, long, long> f;

    public SparseTable(IReadOnlyList<long> a, Func<long, long, long> f)
    {
        this.f = f;
        int n = a.Count;
        log = new int[n + 1];
        for (int x = 2; x <= n; x++) log[x] = log[x / 2] + 1;
        int levels = n > 0 ? log[n] + 1 : 1;
        st = new long[levels][];
        st[0] = a.ToArray();
        for (int k = 1; k < levels; k++)
        {
            int half = 1 << (k - 1);
            st[k] = new long[n - (1 << k) + 1];
            for (int i = 0; i < st[k].Length; i++) st[k][i] = f(st[k - 1][i], st[k - 1][i + half]);
        }
    }

    public long Query(int l, int r)     // inclusive
    {
        int k = log[r - l + 1];
        return f(st[k][l], st[k][r - (1 << k) + 1]);
    }
}

Where sparse tables show up Range-minimum queries on a static array, the LCA of two nodes as the minimum depth between their positions in an Euler tour (see Tree Patterns), and the LCP of two suffixes as a range minimum over the LCP array (String Algorithms). For a sum on a static array you do not need any of this: plain prefix sums already answer in O(1). For non-idempotent f on a static array, use a disjoint sparse table or just a segment tree.

Beyond the basics

You will rarely need these in an interview, but knowing that they exist tells you when a problem is in reach.

  • Merge sort tree. Each node keeps its range sorted. "How many values ≤ x in a[l..r]?" becomes O(log n) binary searches over the covered nodes, O(log² n) per query, O(n log n) memory. No updates.
  • Persistent segment tree. An update copies only the O(log n) nodes on its path and shares the rest, so every old version survives. Build one version per prefix of the array over value ranks, and "k-th smallest in a[l..r]" is a descent on version r minus version l − 1.
  • Offline tricks. When all queries are known up front, sort them. "Number of distinct values in a[l..r]": sort queries by r, sweep r, keep a 1 in a Fenwick tree only at the last occurrence of each value, answer = range_sum(l, r). Many "hard" range problems collapse into a sweep plus a BIT this way.
  • Segment tree beats. Supports "a[i] = min(a[i], x) on a range" with sums, in amortized O(log² n), by storing the maximum and the second maximum per node.
  • Sqrt decomposition. Cut the array into √n blocks and keep one summary per block. Every operation is O(√n): crude but very flexible, because a block can store anything, even a sorted copy. Mo's algorithm reorders offline queries so a sliding [l, r] window moves O(n√n) steps in total.
  • Sorted containers. In Python, sortedcontainers.SortedList gives insert, delete and rank in about O(log n); it is often the fastest thing to write for "count smaller than x so far" (where it is available). In C#, SortedSet<T> has ordered insert and delete, but it cannot report ranks: GetViewBetween(...).Count walks the view in O(k). For ranks in C#, use a Fenwick tree over compressed values.

Recognize it when

  • "update … then query a range", interleaved, n and q up to 10⁵: you need O(log n) per operation, so a Fenwick or segment tree. Prefix sums would cost O(n) per update.
  • "count of smaller / greater elements before or after i", "inversions", "pairs with nums[i] > 2·nums[j]": scan in one direction and put a Fenwick tree over compressed values.
  • "number of subarrays whose sum is in [lower, upper]": prefix sums plus a counting BIT (or merge sort, see Prefix Sums).
  • "longest increasing subsequence with a constraint on the step", "best dp[j] over j with value in a window": a max segment tree indexed by value, so dp becomes a range query.
  • "add to every element in a range" together with "sum / max of a range": lazy propagation.
  • "maximum number of overlapping bookings", "highest stack", huge coordinates arriving online: dynamic segment tree, or compress and use a lazy tree.
  • "area / perimeter of a union of rectangles": sweep line plus a segment tree that stores covered length.
  • "range minimum" on a static array, many queries: sparse table.
  • "k-th smallest so far", "median of a stream with deletions": Fenwick tree over values plus a descent.

Pitfalls

Index 0 in a Fenwick tree i & -i is 0 when i = 0, so add(0, x) loops forever and prefix(0) silently returns 0. Fix: a Fenwick tree is 1-based. Shift with i + 1 at the boundary, and give compressed ranks starting at 1.

Sending the new value instead of the delta NumArray.update(i, val) sets a[i] = val, but a Fenwick tree only knows how to add. Passing val adds it on top of the old value. Fix: keep a copy of the array and call add(i, val − a[i]), then store a[i] = val.

An array of size 2n for a recursive segment tree With n = 6 the recursive tree uses node 13, past 2·6 = 12, and some n need indices close to 4n. Fix: allocate 4n for the recursive version. Only the iterative version fits in exactly 2n.

Forgetting to push before descending A query that walks into the children of a tagged node reads stale values. Fix: call push on every path that goes below a node, in queries as well as updates, and recompute the node from its children after an update recurses.

Wrong identity for the disjoint case Returning 0 for a disjoint range in a min tree makes every query answer ≤ 0. Fix: the identity must not change any answer: 0 for sum and xor, +∞ for min, −∞ for max, 0 for gcd.

Mixing up inclusive and half-open ranges The recursive tree on this page uses [l..r] inclusive, the iterative one [l, r) half-open, and Fenwick prefix(i) includes i. Off-by-one errors here produce answers that are wrong by exactly one element. Fix: write the convention in a comment next to every query signature, and test the ranges [i..i] and [0..n−1].

Equal values in counting problems "Smaller than" excludes ties; "at most" includes them. Using prefix(rank) instead of prefix(rank − 1) (or inserting before querying) counts the current element or its equals. Fix: decide strict vs non-strict first, and in a one-pass scan always query, then insert.

Overflow in C# Sums of 10⁵ values up to 10⁹, or lengths times coordinates in rectangle area, exceed int. Fix: store long in the tree, multiply in long, and take the modulus only at the end.

Worked problems

1. Range Sum Query - Mutable (Medium)

Problem. Support update(index, val) (set nums[index] = val) and sumRange(left, right), interleaved, up to 3·10⁴ calls.

Insight. This is the problem that motivates the whole page: prefix sums make updates O(n). A Fenwick tree makes both O(log n). The one trap is that update sets a value, while the tree adds: send the difference.

Solution 
class NumArray:
    def __init__(self, nums):
        self.a = list(nums)
        self.fw = Fenwick.from_list(nums)       # O(n) build

    def update(self, index, val):
        self.fw.add(index + 1, val - self.a[index])   # the tree adds: send the delta
        self.a[index] = val

    def sumRange(self, left, right):
        return self.fw.range_sum(left + 1, right + 1)  # shift to 1-based

public class NumArray
{
    private readonly long[] a;
    private readonly Fenwick fw;

    public NumArray(int[] nums)
    {
        a = nums.Select(x => (long)x).ToArray();
        fw = Fenwick.FromArray(a);                    // O(n) build
    }

    public void Update(int index, int val)
    {
        fw.Add(index + 1, val - a[index]);            // the tree adds: send the delta
        a[index] = val;
    }

    public int SumRange(int left, int right) => (int)fw.RangeSum(left + 1, right + 1);   // shift to 1-based
}

Complexity. O(n) build, O(log n) per call, O(n) space. Check: [1, 3, 5]: sumRange(0, 2) = 9; update(1, 2); sumRange(0, 2) = 8.

2. Count of Smaller Numbers After Self (Hard)

Problem. For each i, count the j > i with nums[j] < nums[i].

Insight. Scan from the right. When you stand at i, the Fenwick tree holds exactly the elements to the right of i, indexed by value rank. "How many of them are smaller" is prefix(rank − 1). Then insert nums[i]. Query before inserting, so an element never counts itself; rank − 1 makes equal values not count. The visualizer below has three modes: this problem, plain inversions (the same scan, summed), and the next problem.

Solution 
def count_smaller(nums):

3. Reverse Pairs (Hard)

Problem. Count pairs i < j with nums[i] > 2 · nums[j].

Insight. Scan left to right. At j, the tree holds nums[0..j−1] by rank. The earlier values that are > 2·nums[j] are all of them (j) minus those ≤ 2·nums[j]. The number 2·nums[j] usually is not in the array, so find its boundary with bisect_right on the sorted distinct values: every rank up to that position is ≤ 2·nums[j].

Solution 
from bisect import bisect_left, bisect_right

def reverse_pairs(nums):
    order = sorted(set(nums))
    fw = Fenwick(len(order))
    count = 0
    for j, v in enumerate(nums):                # j values have been inserted so far
        at_most = fw.prefix(bisect_right(order, 2 * v))   # earlier values <= 2v
        count += j - at_most                    # the rest are > 2v
        fw.add(bisect_left(order, v) + 1, 1)    # rank of v, 1-based
    return count

    }

    public static int UpperBound(long[] a, long x)
    {
        int lo = 0, hi = a.Length;

4. Count of Range Sum (Hard)

Problem. Count the subarrays whose sum lies in [lower, upper].

Insight. With prefix sums P (P[0] = 0), subarray (i, j] has sum P[j] − P[i]. For each j, count earlier i with P[j] − upper ≤ P[i] ≤ P[j] − lower: a range count over values seen so far, so a Fenwick tree over compressed prefix sums. The two boundaries are not prefix values themselves, so locate them with bisect: bisect_left(order, P[j] − upper) ranks are too small, bisect_right(order, P[j] − lower) ranks are small enough, and the answer for j is the difference of the two prefix counts. Prefix Sums solves the same problem with merge sort; compare the two.

Solution 
from bisect import bisect_left, bisect_right

def count_range_sum(nums, lower, upper):
    pre = [0]
    for x in nums:
        pre.append(pre[-1] + x)
    order = sorted(set(pre))
    fw = Fenwick(len(order))
    count = 0
    for p in pre:                               # p plays P[j]; fw holds P[0..j-1]
        too_small = bisect_left(order, p - upper)   # ranks 1..too_small are < p - upper
        small_enough = bisect_right(order, p - lower)   # ranks 1..small_enough are <= p - lower
        count += fw.prefix(small_enough) - fw.prefix(too_small)
        fw.add(bisect_left(order, p) + 1, 1)
    return count

public static class CountRangeSumSolution
{
    public static int CountRangeSum(int[] nums, int lower, int upper)
    {
        var pre = new long[nums.Length + 1];
        for (int i = 0; i < nums.Length; i++) pre[i + 1] = pre[i] + nums[i];
        long[] order = pre.Distinct().OrderBy(x => x).ToArray();
        var fw = new Fenwick(order.Length);
        long count = 0;
        foreach (long p in pre)                                         // p plays P[j]; fw holds P[0..j-1]
        {
            int tooSmall = Bounds.LowerBound(order, p - upper);         // ranks 1..tooSmall are < p - upper
            int smallEnough = Bounds.UpperBound(order, p - lower);      // ranks 1..smallEnough are <= p - lower
            count += fw.Prefix(smallEnough) - fw.Prefix(tooSmall);
            fw.Add(Bounds.LowerBound(order, p) + 1, 1);
        }

    }
}

Complexity. O(n log n) time, O(n) space. Check: nums = [-2, 5, -1], lower = -2, upper = 2 → 3 (the subarrays [−2], [−1] and [−2, 5, −1]). Prefix sums reach 10⁵ · 2³¹, so they need long in C#.

5. Longest Increasing Subsequence II (Hard)

Problem. Find the longest strictly increasing subsequence in which adjacent elements differ by at most k. n and the values go up to 10⁵.

Insight. Let best[v] be the longest valid subsequence that ends with the value v. A new element v can follow any value in [v − k, v − 1], so best[v] = 1 + max(best[v − k .. v − 1]). That is a range max over values, and the O(n²) DP from Sequence DP becomes O(n log V) with a max segment tree indexed by value. The half-open iterative tree is a perfect fit: query [v − k, v).

Solution 
def length_of_lis(nums, k):
    top = max(nums)
    st = IterSegTree([0] * (top + 1), max, 0)   # st[v] = longest subsequence ending in value v
    best = 0
    for v in nums:
        cur = 1 + st.query(max(0, v - k), v)    # values v-k .. v-1
        st.update(v, cur)                       # never smaller than the old st[v]
        best = max(best, cur)
    return best

6. My Calendar III (Hard)

Problem. Each call book(start, end) adds the half-open interval [start, end), with 0 ≤ start < end ≤ 10⁹. After each call, return the largest number of intervals that overlap at one point.

Insight. This is range add +1 on [start, end − 1] followed by "global max". The coordinates are huge and arrive online, so use a dynamic tree keyed by heap id in a dictionary. Because we only ever read the root, tags never need to be pushed: keep them on the node permanently and add them on the way up, mx[node] = tag[node] + max(mx[left], mx[right]). Intervals & Sweep Line solves the same problem with a sorted delta map in O(n) per call; this version is O(log C) per call.

Solution 
class MyCalendarThree:
    def __init__(self):
        self.mx = {}                            # node -> max overlap inside its range
        self.tag = {}                           # node -> bookings covering its whole range

    def book(self, start, end):
        self._add(start, end - 1, 1, 0, 10**9)
        return self.mx[1]

    def _add(self, ql, qr, node, l, r):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:                 # covered: permanent tag, no push ever
            self.tag[node] = self.tag.get(node, 0) + 1
            self.mx[node] = self.mx.get(node, 0) + 1
            return
        m = (l + r) // 2
        self._add(ql, qr, 2 * node, l, m)
        self._add(ql, qr, 2 * node + 1, m + 1, r)
        self.mx[node] = self.tag.get(node, 0) + max(self.mx.get(2 * node, 0),
                                                     self.mx.get(2 * node + 1, 0))

public class MyCalendarThree
{
    private readonly Dictionary<long, int> mx = new();    // node -> max overlap inside its range
    private readonly Dictionary<long, int> tag = new();   // node -> bookings covering its whole range

    public int Book(int start, int end)
    {
        Add(start, end - 1, 1, 0, 1_000_000_000);
        return mx[1];
    }

    private void Add(int ql, int qr, long node, int l, int r)   // heap ids reach 2^31: long keys
    {
        if (qr < l || r < ql) return;
        if (ql <= l && r <= qr)                               // covered: permanent tag, no push ever
        {
            tag[node] = tag.GetValueOrDefault(node) + 1;
            mx[node] = mx.GetValueOrDefault(node) + 1;
            return;
        }
        int m = l + (r - l) / 2;
        Add(ql, qr, 2 * node, l, m);
        Add(ql, qr, 2 * node + 1, m + 1, r);
        mx[node] = tag.GetValueOrDefault(node)
                 + Math.Max(mx.GetValueOrDefault(2 * node), mx.GetValueOrDefault(2 * node + 1));
    }
}

Complexity. O(log C) per booking with C = 10⁹ (about 30 levels, at most four nodes per level), O(q log C) nodes in total. Check: book(10, 20), (50, 60), (10, 40), (5, 15), (5, 10), (25, 55) → 1, 1, 2, 3, 3, 3.

7. Falling Squares (Hard)

Problem. Squares fall one by one; square i has its left edge at left and side side, so it covers [left, left + side) and lands on top of the highest square already below that span. After each drop, report the tallest stack so far.

Insight. Treat the ground as an array of heights. Each drop is "h = max(height over the span) + side" and then "assign h to the whole span": range max + range assign, so a lazy segment tree. Only the 2n endpoints matter, so compress the integer cells left and left + side − 1 (compression keeps overlaps intact, because it keeps the order of all endpoints). The assign tag needs a "nothing pending" marker that is not a height.

Solution 
def falling_squares(positions):
    coords = sorted({x for left, side in positions for x in (left, left + side - 1)})
    idx = {x: i for i, x in enumerate(coords)}
    n = len(coords)
    mx = [0] * (4 * n)
    tag = [None] * (4 * n)                      # None = no assignment pending

    def apply(node, v):
        mx[node] = v
        tag[node] = v

    def push(node):
        if tag[node] is not None:
            apply(2 * node, tag[node])
            apply(2 * node + 1, tag[node])
            tag[node] = None

    def query(ql, qr, node, l, r):
        if qr < l or r < ql:
            return 0
        if ql <= l and r <= qr:
            return mx[node]
        push(node)
        m = (l + r) // 2
        return max(query(ql, qr, 2 * node, l, m), query(ql, qr, 2 * node + 1, m + 1, r))

    def assign(ql, qr, v, node, l, r):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            apply(node, v)
            return
        push(node)
        m = (l + r) // 2
        assign(ql, qr, v, 2 * node, l, m)
        assign(ql, qr, v, 2 * node + 1, m + 1, r)
        mx[node] = max(mx[2 * node], mx[2 * node + 1])

    res, best = [], 0
    for left, side in positions:
        l, r = idx[left], idx[left + side - 1]
        h = query(l, r, 1, 0, n - 1) + side     # land on the highest point below
        assign(l, r, h, 1, 0, n - 1)
        best = max(best, h)
        res.append(best)
    return res

public class FallingSquaresSolution
{
    private long[] mx = Array.Empty<long>(), tag = Array.Empty<long>();
    private bool[] hasTag = Array.Empty<bool>();      // false = no assignment pending

    public IList<int> FallingSquares(int[][] positions)
    {
        long[] coords = positions.SelectMany(p => new long[] { p[0], (long)p[0] + p[1] - 1 })
                                 .Distinct().OrderBy(x => x).ToArray();
        var idx = new Dictionary<long, int>();
        for (int i = 0; i < coords.Length; i++) idx[coords[i]] = i;
        int n = coords.Length;
        mx = new long[4 * n]; tag = new long[4 * n]; hasTag = new bool[4 * n];
        var res = new List<int>();
        long best = 0;
        foreach (var p in positions)
        {
            int l = idx[p[0]], r = idx[(long)p[0] + p[1] - 1];
            long h = Query(l, r, 1, 0, n - 1) + p[1];       // land on the highest point below
            Assign(l, r, h, 1, 0, n - 1);
            best = Math.Max(best, h);
            res.Add((int)best);
        }
        return res;
    }

    private void Apply(int node, long v) { mx[node] = v; tag[node] = v; hasTag[node] = true; }

    private void Push(int node)
    {
        if (!hasTag[node]) return;
        Apply(2 * node, tag[node]);
        Apply(2 * node + 1, tag[node]);
        hasTag[node] = false;
    }

    private long Query(int ql, int qr, int node, int l, int r)
    {
        if (qr < l || r < ql) return 0;
        if (ql <= l && r <= qr) return mx[node];
        Push(node);
        int m = (l + r) / 2;
        return Math.Max(Query(ql, qr, 2 * node, l, m), Query(ql, qr, 2 * node + 1, m + 1, r));
    }

    private void Assign(int ql, int qr, long v, int node, int l, int r)
    {
        if (qr < l || r < ql) return;
        if (ql <= l && r <= qr) { Apply(node, v); return; }
        Push(node);
        int m = (l + r) / 2;
        Assign(ql, qr, v, 2 * node, l, m);
        Assign(ql, qr, v, 2 * node + 1, m + 1, r);
        mx[node] = Math.Max(mx[2 * node], mx[2 * node + 1]);
    }
}

Complexity. O(n log n) time, O(n) space. Check: [[1, 2], [2, 3], [6, 1]] → [2, 5, 5]; [[100, 100], [200, 100]] → [100, 100] (they only touch at x = 200, which is why the right end is left + side − 1).

8. Rectangle Area II (Hard)

Problem. Return the total area covered by a list of axis-aligned rectangles (overlaps counted once), modulo 10⁹ + 7. Coordinates go up to 10⁹.

Insight. Sweep a vertical line from left to right. Between two consecutive event x values, the covered area is (covered length on the line) × (distance moved). A rectangle adds +1 on its y-span when the line reaches x1 and −1 at x2. So the tree needs "range add ±1" and "how much of the line has count > 0". Each node stores cnt (rectangles that cover its whole range, never pushed) and cov (covered length inside its range):

  • cnt > 0: the whole range is covered, so cov = its full length.
  • otherwise: cov = left.cov + right.cov (0 at a leaf).

This works without push-down because every −1 removes exactly the nodes that its matching +1 added. The leaves are the gaps between consecutive compressed y values, so each leaf has a real length. Step through the sweep:

Solution 
def rectangle_area(rectangles):
    MOD = 10**9 + 7
    ys = sorted({y for _, y1, _, y2 in rectangles for y in (y1, y2)})
    yi = {y: i for i, y in enumerate(ys)}
    m = len(ys) - 1                             # leaf i = the gap ys[i] .. ys[i + 1]
    cnt = [0] * (4 * m + 4)                     # rectangles covering the node's whole range
    cov = [0] * (4 * m + 4)                     # covered length inside the node's range

    def update(ql, qr, d, node, l, r):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            cnt[node] += d
        else:
            mid = (l + r) // 2
            update(ql, qr, d, 2 * node, l, mid)
            update(ql, qr, d, 2 * node + 1, mid + 1, r)
        if cnt[node] > 0:
            cov[node] = ys[r + 1] - ys[l]       # fully covered
        elif l == r:
            cov[node] = 0
        else:
            cov[node] = cov[2 * node] + cov[2 * node + 1]

    events = []
    for x1, y1, x2, y2 in rectangles:
        events.append((x1, 1, y1, y2))
        events.append((x2, -1, y1, y2))
    events.sort()
    area, prev_x = 0, events[0][0]
    for x, d, y1, y2 in events:
        area += cov[1] * (x - prev_x)           # the strip since the last event
        prev_x = x
        if yi[y1] < yi[y2]:                     # skip zero-height rectangles
            update(yi[y1], yi[y2] - 1, d, 1, 0, m - 1)
    return area % MOD

{
    private long[] ys = Array.Empty<long>(), cov = Array.Empty<long>();   // cov: covered length inside the node
    private int[] cnt = Array.Empty<int>();                               // rectangles covering the whole node

    public int RectangleArea(int[][] rectangles)
    {
        const long MOD = 1_000_000_007;
        ys = rectangles.SelectMany(r => new long[] { r[1], r[3] }).Distinct().OrderBy(y => y).ToArray();
        var yi = new Dictionary<long, int>();
        for (int i = 0; i < ys.Length; i++) yi[ys[i]] = i;
        int m = ys.Length - 1;                        // leaf i = the gap ys[i] .. ys[i + 1]
        cnt = new int[4 * m + 4];
        cov = new long[4 * m + 4];
        var events = new List<(long x, int d, long y1, long y2)>();
        foreach (var r in rectangles)
        {
            events.Add((r[0], 1, r[1], r[3]));
            events.Add((r[2], -1, r[1], r[3]));
        }
        events.Sort();
        long area = 0, prevX = events[0].x;
        foreach (var (x, d, y1, y2) in events)
        {
            area += cov[1] * (x - prevX);             // the strip since the last event
            prevX = x;
            if (yi[y1] < yi[y2]) Update(yi[y1], yi[y2] - 1, d, 1, 0, m - 1);   // skip zero height
        }
        return (int)(area % MOD);
    }

    private void Update(int ql, int qr, int d, int node, int l, int r)
    {
        if (qr < l || r < ql) return;
        if (ql <= l && r <= qr) cnt[node] += d;
        else
        {
            int mid = (l + r) / 2;
            Update(ql, qr, d, 2 * node, l, mid);
            Update(ql, qr, d, 2 * node + 1, mid + 1, r);
        }
        if (cnt[node] > 0) cov[node] = ys[r + 1] - ys[l];   // fully covered
        else if (l == r) cov[node] = 0;
        else cov[node] = cov[2 * node] + cov[2 * node + 1];
    }

Self-check

In a Fenwick tree, which range does t[12] cover, and which cells does prefix(13) read?

lowbit(12) = 4 (12 = 1100₂), so t[12] covers the 4 positions [9..12]. prefix(13) reads t[13] = [13..13], then drops the lowest bit: t[12] = [9..12], then t[8] = [1..8], then 0 stops. Three disjoint blocks that tile [1..13], one per set bit of 13 = 1101₂.

With n = 16, which cells does add(5, x) change, and why exactly those?

5 → 6 → 8 → 16 (add the lowest set bit each time). Those are precisely the blocks that contain position 5: [5..5], [5..6], [1..8] and [1..16]. Every other block either ends before 5 or starts after it.

Why can a Fenwick tree give range sums but not range minimums, while a segment tree gives both?

A Fenwick tree only stores prefix blocks, so a range [l..r] must be computed as prefix(r) "minus" prefix(l − 1). Subtraction exists for sums (and xor), but there is no way to remove the elements of [1..l−1] from a minimum. A segment tree assembles [l..r] directly from O(log n) disjoint nodes that lie inside the range, so it only needs f to be associative, never invertible.

Why does a segment-tree range query visit at most about 4 nodes per level?

Only nodes that partially overlap the query recurse. A partial node must contain one of the query's two edges (ql or qr) without being inside it, and at any one depth at most two nodes contain an edge. Those two nodes have at most four children between them, and those children are the only nodes visited on the next level. Every other node there is never reached, because its parent was fully inside or disjoint and returned without recursing. So the work is O(4 log n) = O(log n).

A lazy add+sum tree has tag 3 on the node for [0..3] and nothing below it. A query asks for [2..3]. What must happen, and what goes wrong without it?

The query is partial on [0..3], so it must descend. Before it does, push: both children ([0..1] and [2..3]) get sum += 3 · 2 and tag += 3, and the parent's tag becomes 0. The query then reads [2..3] directly. Without the push, [2..3] still holds the old sum, and the answer is short by 6.

A sparse table answers range min with two overlapping blocks. Why does that fail for sum, and what would you use instead?

The elements in the overlap are counted twice. Min does not care (min(x, x) = x, idempotent), but sum does. For a static array, use plain prefix sums (O(1) and simpler); if updates exist, a Fenwick tree.

In Count of Smaller Numbers After Self, what changes if you insert before querying, or query prefix(rank) instead of prefix(rank − 1)?

Insert first: every element counts itself, so every answer is one too large. prefix(rank): elements equal to nums[i] on its right are counted as "smaller". The correct scan is: query strictly smaller ranks, then insert.

Which structure would you pick? (a) static array, 10⁶ range-max queries; (b) point updates and range-gcd queries; (c) "add x to a[l..r]" and "sum of a[l..r]", interleaved; (d) count earlier elements less than x, values up to 10⁹.

(a) Sparse table: O(1) queries and max is idempotent. (b) Segment tree: gcd is not invertible, so no Fenwick. (c) Two Fenwick trees (range add, range sum) or a lazy segment tree. (d) Coordinate compression plus a Fenwick tree over ranks.
