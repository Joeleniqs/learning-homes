Topological Sort & DAGs

Kahn's in-degree queue vs DFS finishing order, cycle detection, course scheduling and DP over DAGs.

Intermediate → Advanced~45 min studyBuilds on: Graph Fundamentals: BFS & DFSUpdated 2026-11-03

What a topological order is

Plenty of problems come with "this before that" rules. A course needs its prerequisites, a build target needs the libraries it links, a spreadsheet cell needs the cells its formula reads, and socks go on before shoes. Draw every rule "a must come before b" as an arrow a → b, and the question becomes a graph question: list all the nodes so that every arrow points forward. That list is a topological order, and a directed graph with no directed cycle is a DAG (directed acyclic graph).

This page builds directly on Graph Fundamentals: BFS & DFS. Kahn's algorithm is a BFS that uses in-degree counts instead of a seen set, and the DFS method is the three-colour DFS from that page plus one extra line.

The topological invariant. An order is valid exactly when every edge u → v has u before v, and a valid order exists if and only if the graph has no directed cycle. Both algorithms on this page build an order in O(V + E), and both notice the cycle when there isn't one.

The picture: straighten the graph into a line

Vocabulary used on this page:

  • In-degree of v: the number of arrows into v, that is, how many things must happen before v. A node with in-degree 0 is a source; nothing has to happen before it.
  • Out-degree of u: the number of arrows leaving u. A node with out-degree 0 is a sink; nothing waits for it.
  • Direction convention: on this page u → v always means "u comes before v" ("u is a prerequisite of v", "v depends on u"). Inputs often state it the other way round; translate them once, when you build the graph.

Why "no cycle" is exactly the condition

Both directions of the "if and only if" are short, and the second one is an algorithm:

  1. A cycle makes an order impossible. On a cycle a → b → c → a, a must come before b, b before c, and c before a, so a comes before itself.
  2. Without a cycle, an order always exists. First, some node has in-degree 0: start anywhere and keep walking backwards along an incoming arrow. Without a cycle the walk never repeats a node, so after at most V steps it reaches a node with no incoming arrow. Put that node first. Deleting it (and its arrows) cannot create a cycle among the rest, so repeat on the smaller graph until nothing is left.

Insight: an order, not the order

A DAG usually has many valid orders; the arrows only forbid some of them. The order is unique only when the graph contains a path through all the nodes, so that each consecutive pair is forced by an arrow. That is why problems either accept "any valid order", or add a tie-break such as "lexicographically smallest" (a heap, below), or ask you to count the orders (a much harder problem, also below).

Kahn's algorithm: repeatedly take what is ready

Kahn's algorithm runs the proof above as code. Keep indeg[v] = the number of v's prerequisites not yet placed. A node is ready when its count reaches 0, and ready nodes wait in a queue. Pop a ready node, append it to the order, and "delete" its outgoing arrows by decrementing each target's count; any target that drops to 0 becomes ready.

Why it is correct: a node is only placed once its count is 0, and the count only drops when a prerequisite is placed, so every prerequisite of v is already in the order when v is appended. Why it is O(V + E): each node's count reaches 0 at most once, so each node is queued at most once, and each arrow is deleted exactly once, when its tail is popped.

Try adding 6>0 to the edge list. It closes the cycle 0 → 2 → 4 → 6 → 0, and you can watch the queue run dry with four nodes still waiting.

from collections import deque

def topo_sort(n, edges):
    """Nodes 0..n-1; (u, v) means u must come before v.
    Returns a topological order, or [] if the graph has a cycle."""
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1
    q = deque(u for u in range(n) if indeg[u] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:              # delete u's outgoing arrows
            indeg[v] -= 1
            if indeg[v] == 0:         # last prerequisite of v just got placed
                q.append(v)
    return order if len(order) == n else []

public static int[] TopoSort(int n, int[][] edges)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    var indeg = new int[n];
    foreach (var e in edges) { adj[e[0]].Add(e[1]); indeg[e[1]]++; }

    var q = new Queue<int>();
    for (int u = 0; u < n; u++) if (indeg[u] == 0) q.Enqueue(u);
    var order = new List<int>(n);
    while (q.Count > 0)
    {
        int u = q.Dequeue();
        order.Add(u);
        foreach (int v in adj[u])             // delete u's outgoing arrows
            if (--indeg[v] == 0) q.Enqueue(v); // last prerequisite of v just got placed
    }
    return order.Count == n ? order.ToArray() : Array.Empty<int>();
}

Complexity: O(V + E) time and O(V + E) memory for the adjacency list. Duplicate edges are harmless as long as adj and indeg see them the same number of times: each copy adds 1 to the count and each copy is deleted once.

Tip: the queue is a choice, and the layers are free

Any ready node may go next, so the queue could be a stack or a heap and the result would still be valid. A FIFO queue gives a useful extra: if you process it one whole layer at a time (for _ in range(len(q)), as in level-order BFS), the layer number of a node is the length of the longest chain of prerequisites ending at it. That is the earliest semester in which a course can be taken, the minimum number of build rounds, or the depth of a task in a parallel schedule.

DFS finishing order: reverse the post-order

The second method needs no counts. Run the three-colour DFS from Graph Fundamentals and record each node at the moment it finishes (turns BLACK), which is the post-order. The key fact is: a node finishes only after everything it can reach has finished. So in post-order every arrow points backwards, and reversing the list makes every arrow point forward.

The figure is the whole proof. Take any edge u → v and look at v's colour at the moment DFS examines that edge from u:

  • WHITE: DFS goes into v now, so v finishes before u does.
  • BLACK: v has finished already, so again before u.
  • GREY: v is an ancestor of u on the current call stack. The edge u → v plus the stack path v → … → u is a cycle, so no order exists, and the DFS reports it.

In the two valid cases f[v] < f[u], so u comes before v once the post-order is reversed. Watch the "post" list fill from the deepest nodes outwards:

Recursion is the clearest way to write it, but a long chain of 10⁵ prerequisites will overflow Python's recursion limit and C#'s stack. The template below keeps an explicit stack of (node, index of the next edge to try) pairs, so it behaves exactly like the recursive version, including the moment each node finishes.

def topo_sort_dfs(n, edges):
    """Reversed DFS post-order. Returns [] if the graph has a cycle."""
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
    WHITE, GREY, BLACK = 0, 1, 2
    state = [WHITE] * n
    post = []
    for s in range(n):
        if state[s] != WHITE:
            continue
        state[s] = GREY
        stack = [(s, 0)]                  # (node, index of the next edge to try)
        while stack:
            u, i = stack[-1]
            if i < len(adj[u]):
                stack[-1] = (u, i + 1)
                v = adj[u][i]
                if state[v] == GREY:      # back edge into the current path
                    return []
                if state[v] == WHITE:
                    state[v] = GREY
                    stack.append((v, 0))
            else:                         # every edge of u is done: u finishes
                stack.pop()
                state[u] = BLACK
                post.append(u)
    return post[::-1]

public static int[] TopoSortDfs(int n, int[][] edges)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    foreach (var e in edges) adj[e[0]].Add(e[1]);

    const int White = 0, Grey = 1, Black = 2;
    var state = new int[n];
    var post = new List<int>(n);
    var stack = new Stack<(int U, int Next)>();
    for (int s = 0; s < n; s++)
    {
        if (state[s] != White) continue;
        state[s] = Grey;
        stack.Push((s, 0));                   // (node, index of the next edge to try)
        while (stack.Count > 0)
        {
            var (u, i) = stack.Pop();
            if (i < adj[u].Count)
            {
                stack.Push((u, i + 1));
                int v = adj[u][i];
                if (state[v] == Grey) return Array.Empty<int>(); // back edge: cycle
                if (state[v] == White) { state[v] = Grey; stack.Push((v, 0)); }
            }
            else                              // every edge of u is done: u finishes
            {
                state[u] = Black;
                post.Add(u);
            }
        }
    }
    post.Reverse();
    return post.ToArray();
}

Complexity: O(V + E) time, O(V + E) memory. Every node is pushed once and every edge is examined once.

Kahn (in-degree queue)

Iterative by nature, so there is no recursion depth to worry about. It reports a cycle by counting (len(order) < n). The queue can be swapped for a heap (smallest order) or processed layer by layer (semesters, rounds), and "the queue held two nodes at once" tells you the order is not unique. Choose it for scheduling questions.

DFS (reversed finishing order)

One traversal with no in-degree array. A cycle shows up as a concrete back edge, and the stack holds the cycle itself. Post-order is exactly the order in which memoised recursion completes, so DP on a DAG written top-down is this algorithm in disguise. The same finishing times drive Kosaraju's strongly connected components in Advanced Graph Algorithms.

Pitfall: pre-order is not a topological order

Recording a node when DFS enters it looks tempting, but it fails as soon as a later DFS root points into an earlier tree. With edges 0 → 1 and 2 → 0, DFS from 0 visits 0, 1, and then a new DFS from 2 visits 2: the pre-order 0, 1, 2 puts 2 after 0, against the arrow 2 → 0. The post-order is 1, 0, 2, and reversed it is 2, 0, 1, which is correct. Reversal is not optional either: the un-reversed post-order has every arrow pointing backwards.

When no order exists

Every way of asking "can all of this be done?" (can I finish all courses, can this be built, is this spreadsheet free of circular references) is the same question: does the directed graph have a cycle? Both algorithms answer it as a by-product.

  • Kahn: the queue runs dry before all nodes are placed. Those leftover nodes are not a random set. Arrows from placed nodes were deleted, so every arrow still counted points from one leftover node to another, and every leftover node has at least one. Start at any leftover node and keep walking backwards along those arrows: the walk can never stop and the set is finite, so it must repeat a node. That repetition is a cycle.
  • DFS: the back edge u → v into a GREY node is the cycle: v → … → u along the call stack, then the edge back to v.

Not every leftover node is on a cycle; some only sit behind one, waiting for a node that waits forever. Here node 4 is behind the cycle 1 → 2 → 3, and node 0 is placed normally:

When a problem asks you to show the cycle (a build tool reporting "circular dependency: a → b → c → a"), run Kahn, then walk backwards through the leftovers:

from collections import deque

def find_cycle(n, edges):
    """One directed cycle as a list [a, b, ..., z] meaning a -> b -> ... -> z -> a,
    or [] if the graph is a DAG."""
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1
    q = deque(u for u in range(n) if indeg[u] == 0)
    while q:
        u = q.popleft()
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    pred = {}                                  # leftover node -> a leftover predecessor
    for u, v in edges:
        if indeg[u] > 0 and indeg[v] > 0:
            pred[v] = u
    if not pred:
        return []
    x, pos, walk = next(iter(pred)), {}, []
    while x not in pos:                        # walk backwards until a node repeats
        pos[x] = len(walk)
        walk.append(x)
        x = pred[x]
    return walk[pos[x]:][::-1]                 # we walked backwards, so reverse

public static List<int> FindCycle(int n, int[][] edges)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    var indeg = new int[n];
    foreach (var e in edges) { adj[e[0]].Add(e[1]); indeg[e[1]]++; }
    var q = new Queue<int>();
    for (int u = 0; u < n; u++) if (indeg[u] == 0) q.Enqueue(u);
    while (q.Count > 0)
        foreach (int v in adj[q.Dequeue()])
            if (--indeg[v] == 0) q.Enqueue(v);

    var pred = new int[n];
    Array.Fill(pred, -1);
    int start = -1;
    foreach (var e in edges)                   // leftover node -> a leftover predecessor
        if (indeg[e[0]] > 0 && indeg[e[1]] > 0) { pred[e[1]] = e[0]; start = e[1]; }
    if (start == -1) return new List<int>();

    var pos = new Dictionary<int, int>();
    var walk = new List<int>();
    int x = start;
    while (!pos.ContainsKey(x))                // walk backwards until a node repeats
    {
        pos[x] = walk.Count;
        walk.Add(x);
        x = pred[x];
    }
    var cycle = walk.GetRange(pos[x], walk.Count - pos[x]);
    cycle.Reverse();                           // we walked backwards, so reverse
    return cycle;
}

Complexity: O(V + E). A node's count is still positive after Kahn exactly when it was never queued, which is why indeg[x] > 0 identifies the leftovers.

Course Schedule I & II: the template, with one trap

Course Schedule asks whether all n courses can be finished, and Course Schedule II asks for an order. They are the two outputs of Kahn's algorithm: len(order) == n, and order itself. The only real difficulty is the input format.

A pair [a, b] means "to take a you must first take b", so b comes before a and the arrow is b → a. If you build a → b instead, Course Schedule I still passes, because reversing every arrow keeps cycles as cycles, so the bug hides. Course Schedule II then returns the order exactly backwards. The full solutions are in Worked problems.

Tip: "is x a prerequisite of y?" for many queries

Course Schedule IV asks many reachability queries. Process the nodes in topological order and give each node the set of its ancestors: anc[v] |= anc[u] | {u} for every arrow u → v. Every predecessor is finished before v is processed, so one pass is enough. Python integers work as bitsets (anc[v] |= anc[u] | (1 << u)), so with n = 100 that is about E big-integer ORs, and each query is a single bit test.

Alien dictionary: building the graph is the problem

A list of words is sorted in an unknown alphabet; recover an alphabet order. The topological sort part is the template. The insight is how to read rules out of the words:

  • Compare adjacent words only. At the first position where they differ, w1[i] < w2[i] in the alien alphabet, which gives one arrow. Nothing after that position tells you anything, just as "apple" < "banana" says nothing about whether p comes before a.
  • Adjacent pairs are enough. If every adjacent pair is in order then the whole list is in order, so the pair (w1, w3) can never add a rule that (w1, w2) and (w2, w3) don't already imply.
  • The prefix case. If w2 is a proper prefix of w1 ("abc" before "ab"), no alphabet can sort them, so the answer is "". Missing this check is the most common wrong answer.
  • Every letter that appears is a node, including letters that appear in no rule. They are sources, and they must be in the output.

The edge from "wrf" to "er" ignores everything after the first letter: w < e. Rules can repeat (two different pairs may both say t < f), so store each rule once in a set, or count it in the in-degree as often as you add it to the adjacency list. Mixing the two leaves a letter waiting forever. Try abc,ab to see the prefix case.

Choosing among valid orders

Smallest order: replace the queue with a heap

When the problem wants the lexicographically smallest valid order (or "if several tasks are ready, do the one with the smallest id first"), keep the ready nodes in a min-heap instead of a FIFO queue. At every step the smallest ready node is placed next.

Why greedy is safe: the first position can hold any source, and the smallest source s is the best possible first element. Placing s never blocks anything: every valid order of the remaining nodes is still available. So the smallest order starts with the smallest ready node, and by the same argument applied to the rest, every later position does too.

Switch the mode to "FIFO queue" to see the difference. Both orders are valid, but FIFO places 6 before 2 simply because 6 became ready earlier, while the heap waits for whichever ready node is smallest.

import heapq

def smallest_topo_order(n, edges):
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1
    heap = [u for u in range(n) if indeg[u] == 0]
    heapq.heapify(heap)
    order = []
    while heap:
        u = heapq.heappop(heap)          # the smallest node that is ready
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                heapq.heappush(heap, v)
    return order if len(order) == n else []

public static int[] SmallestTopoOrder(int n, int[][] edges)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    var indeg = new int[n];
    foreach (var e in edges) { adj[e[0]].Add(e[1]); indeg[e[1]]++; }

    var heap = new PriorityQueue<int, int>();
    for (int u = 0; u < n; u++) if (indeg[u] == 0) heap.Enqueue(u, u);
    var order = new List<int>(n);
    while (heap.Count > 0)
    {
        int u = heap.Dequeue();               // the smallest node that is ready
        order.Add(u);
        foreach (int v in adj[u])
            if (--indeg[v] == 0) heap.Enqueue(v, v);
    }
    return order.Count == n ? order.ToArray() : Array.Empty<int>();
}

Complexity: O(V log V + E): each node is pushed and popped once at O(log V) each. See Heaps & Priority Queues for the heap itself.

Pitfall: "smallest order" is not "small labels as early as possible"

Some problems ask for something different: put node 0 as early as possible, then node 1 as early as possible, and so on. The min-heap greedy gets that wrong. With nodes 0, 1, 2 and the single arrow 2 → 0, the smallest order is 1, 2, 0, but the order that puts 0 earliest is 2, 0, 1. Fix: reverse every arrow, run Kahn with a max-heap, and reverse the result. Building the order from the back and placing the largest label last keeps the small labels free to move forward.

Is the order unique?

Kahn's algorithm gives a precise test: the order is unique exactly when the queue never holds more than one node. If two nodes are ready at once, neither depends on the other, so they can be swapped. If the queue always holds exactly one node, each placed node was the only possible choice. Equivalently, consecutive nodes of the order are joined by arrows, so the order is a path through the whole graph. Sequence Reconstruction is this test.

from collections import deque

def unique_topo_order(n, edges):
    """The topological order if it is unique, else None (several orders, or a cycle)."""
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1
    q = deque(u for u in range(n) if indeg[u] == 0)
    order = []
    while q:
        if len(q) > 1:                # two ready nodes could be swapped
            return None
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == n else None

public static int[]? UniqueTopoOrder(int n, int[][] edges)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    var indeg = new int[n];
    foreach (var e in edges) { adj[e[0]].Add(e[1]); indeg[e[1]]++; }

    var q = new Queue<int>();
    for (int u = 0; u < n; u++) if (indeg[u] == 0) q.Enqueue(u);
    var order = new List<int>(n);
    while (q.Count > 0)
    {
        if (q.Count > 1) return null;         // two ready nodes could be swapped
        int u = q.Dequeue();
        order.Add(u);
        foreach (int v in adj[u])
            if (--indeg[v] == 0) q.Enqueue(v);
    }
    return order.Count == n ? order.ToArray() : null;
}

How many orders are there? (concept)

Finding one order is linear, but counting them is a different kind of problem. For a general DAG it is #P-complete (Brightwell and Winkler, 1991), so no polynomial algorithm is expected. Two things still work in practice:

  • Small n (up to about 20): DP over subsets. Let ways[S] be the number of ways to place exactly the set S first. A node v can be placed next when all its predecessors are in S, so ways[S ∪ {v}] += ways[S]. That is O(2ⁿ · n) with a precomputed predecessor mask per node, the same machinery as bitmask DP.
  • Trees: a closed formula. When the arrows form a rooted tree (each node has one parent that must come first), the count is n! / ∏ size(v) over all subtrees. Each node must come first within its own subtree, which happens in exactly 1/size(v) of all n! arrangements, and for a tree these events are independent.

Count Ways to Build Rooms in an Ant Colony is exactly the tree formula, computed modulo 10⁹ + 7 with modular inverses.

DP on a DAG

A topological order has one property that makes it the backbone of dynamic programming: when you reach v, every node with an arrow into v has already been processed. So any recurrence of the form

best[v] = combine( f(best[u], u → v) for every arrow u → v )

can be evaluated in one pass over the order, each value final the moment it is computed. Longest path, shortest path, number of paths, earliest finish time and "largest colour count along a path" are all this one loop. It is also why DP needs its subproblems to form a DAG (The DP Framework): tabulation fills the table in some topological order of the subproblems, and memoised recursion finishes them in DFS post-order.

The classic example is a project plan. Course v takes time[v] months and can start only when all its prerequisites have finished, with as many courses in parallel as you like. Its earliest finish is finish[v] = time[v] + max(finish[u] for u → v), and the whole project takes max(finish). The chain of arrows that achieves the maximum is the critical path: delaying any task on it delays the project, and the tasks off it have slack.

Switch the measure to "semesters" to get Parallel Courses (LC 1136): every course takes one semester, so the answer is the number of nodes on the longest chain, which is also the number of Kahn layers.

The general template computes the heaviest path when the edges carry weights, which may be negative:

from collections import deque

def longest_path(n, edges):
    """edges: (u, v, w). Heaviest path in a DAG as (weight, [nodes]).
    A single node is a path of weight 0. Raises ValueError on a cycle."""
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v, w in edges:
        adj[u].append((v, w))
        indeg[v] += 1
    best = [0] * n                  # heaviest path that ends at v
    parent = [-1] * n
    q = deque(u for u in range(n) if indeg[u] == 0)
    placed = 0
    while q:
        u = q.popleft()             # best[u] is final: all its predecessors are done
        placed += 1
        for v, w in adj[u]:
            if best[u] + w > best[v]:
                best[v] = best[u] + w
                parent[v] = u
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    if placed < n:
        raise ValueError("not a DAG")
    end = max(range(n), key=best.__getitem__)
    path = []
    while end != -1:
        path.append(end)
        end = parent[end]
    return best[path[0]], path[::-1]

public static (long Weight, List<int> Path) LongestPath(int n, int[][] edges)
{
    var adj = new List<(int V, int W)>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<(int, int)>();
    var indeg = new int[n];
    foreach (var e in edges) { adj[e[0]].Add((e[1], e[2])); indeg[e[1]]++; }

    var best = new long[n];                   // heaviest path that ends at v
    var parent = new int[n];
    Array.Fill(parent, -1);
    var q = new Queue<int>();
    for (int u = 0; u < n; u++) if (indeg[u] == 0) q.Enqueue(u);
    int placed = 0;
    while (q.Count > 0)
    {
        int u = q.Dequeue();                  // best[u] is final: all its predecessors are done
        placed++;
        foreach (var (v, w) in adj[u])
        {
            if (best[u] + w > best[v]) { best[v] = best[u] + w; parent[v] = u; }
            if (--indeg[v] == 0) q.Enqueue(v);
        }
    }
    if (placed < n) throw new InvalidOperationException("not a DAG");

    int end = 0;
    for (int v = 1; v < n; v++) if (best[v] > best[end]) end = v;
    var path = new List<int>();
    for (int x = end; x != -1; x = parent[x]) path.Add(x);
    path.Reverse();
    return (best[end], path);
}

Complexity: O(V + E) time and memory. Change > to < for the shortest path. On a DAG this is correct even with negative weights, where Dijkstra fails, and it is faster than Bellman-Ford's O(V·E). Change the update to count[v] += count[u] to count paths. On a general graph the longest simple path is NP-hard; the absence of cycles is what makes it linear.

Insight: the DAG is often hidden

Many "DP on a grid" or "DP on states" problems are DAG DP where the order is implicit. Strictly increasing values, increasing time, a shrinking set or a growing prefix can only move one way, so they cannot cycle. When that monotone quantity is easy to sort by, you can skip the graph entirely and process the states in sorted order: sort the cells by value, the intervals by end, or the words by length (Longest String Chain).

Longest increasing path in a matrix

In Longest Increasing Path in a Matrix, draw an arrow from each cell to every neighbour with a strictly larger value. Values strictly increase along every arrow, so no arrow sequence can return to its start: the grid is a DAG, and the answer is the number of nodes on its longest path. There are two equally good ways to compute it:

  • Memoised DFS: lip(cell) = 1 + max(lip(bigger neighbour)). This is DP in DFS finishing order.
  • Kahn's peeling: cells with no smaller neighbour are the sources. Peel them layer by layer; the number of layers is the longest chain. No recursion at all.

Peeling from the other end

Kahn's idea, "repeatedly remove whatever has nothing left to wait for", is more general than sorting. Two classic problems run it from the sink end or on an undirected tree:

  • Find Eventual Safe States: a node is safe when every path from it ends at a terminal node (out-degree 0). Terminal nodes are safe; a node becomes safe once all its out-arrows lead to safe nodes. That is Kahn on the reversed graph, counting out-degrees instead of in-degrees. Whatever never peels can reach a cycle.
  • Minimum Height Trees: in an undirected tree, repeatedly strip all current leaves (degree 1). The last one or two nodes standing are the centres of the longest path, and rooting the tree there minimises its height.

When the scheduler has a capacity. Parallel Courses II allows at most k courses per semester. It looks like Kahn with a cap, but no greedy rule for which k ready courses to take is always right: taking the course with the longest chain behind it can still lose. With n ≤ 15 the intended solution is DP over the subset of finished courses (bitmask DP). Recognise the cap as the signal that topological sort alone is no longer enough.

Recognize it when

Recognize a topological sort when

  • The input is a set of "before" / "depends on" / "prerequisite" / "must happen after" relations: courses, build steps, recipes and supplies, task dependencies, or ordering constraints on rows and columns.
  • The question is "is it possible to do all of them?" (a cycle test), "in what order?", or "how long at minimum?" with unlimited parallelism (the longest path).
  • An order is hidden in sorted data: adjacent words in a dictionary, or rankings that must agree.
  • You need a DP whose states have an obvious one-way dependency (strictly increasing values, time, subset growth) but no obvious loop order.
  • Something is peeled from the outside in: leaves of a tree, terminal nodes, nodes that "become safe" once all their neighbours are.

Pitfalls: the actual bug and its fix

  1. Arrow direction reversed. [a, b] means b before a, but the code adds a → b. Cycle tests still pass, and every returned order is backwards. Fix: write the meaning next to the line that builds the graph (# b before a) and test one tiny case by hand.
  2. Rules counted twice in one place and once in the other. The alien dictionary yields "t < f" twice; the adjacency set stores it once while indeg[f] is incremented twice, so f never reaches 0. Fix: only increment the in-degree when the set actually gained the edge.
  3. Missing the prefix case. ["abc", "ab"] has no valid alphabet, but the pair loop finds no differing letter and moves on. Fix: if no position differs and len(w1) > len(w2), return "".
  4. Forgetting isolated nodes. Letters that appear in no rule, or courses with no prerequisites and no dependants, never appear in the edge list. Fix: create a node for every item, and seed the queue from all nodes, not just those seen in edges.
  5. A DFS "visited" set as the cycle test. In a diamond 0 → 1 → 3, 0 → 2 → 3, node 3 is visited twice without any cycle. Fix: three colours, and only an edge into a GREY node is a cycle.
  6. Not reversing the DFS post-order, or using pre-order. Fix: post[::-1]. Check that the first node in the answer has in-degree 0.
  7. Recursive DFS on a 10⁵-long chain. RecursionError in Python, and an uncatchable StackOverflowException in C#. Fix: Kahn, or the explicit (node, next index) stack.
  8. A BFS seen-set instead of in-degrees. Marking a node when it is first reached places it before its other prerequisites. Fix: a node joins the queue when its count reaches 0, not when it is first touched.
  9. Not checking len(order) == n. On a cyclic input the loop simply stops and a partial order is returned as if it were an answer. Fix: always compare against n.

Worked problems

1. Course Schedule II Medium

There are numCourses courses, and [a, b] means b must be taken before a. Return any order that takes all of them, or [] if that is impossible.

Key insight. This is the Kahn template with the arrow drawn as b → a. The impossible case is a cycle, which Kahn reports by placing fewer than n courses.

Solution: Kahn's algorithm 
from collections import deque

def find_order(num_courses, prerequisites):
    adj = [[] for _ in range(num_courses)]
    indeg = [0] * num_courses
    for a, b in prerequisites:            # b before a
        adj[b].append(a)
        indeg[a] += 1
    q = deque(c for c in range(num_courses) if indeg[c] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == num_courses else []

public int[] FindOrder(int numCourses, int[][] prerequisites)
{
    var adj = new List<int>[numCourses];
    for (int i = 0; i < numCourses; i++) adj[i] = new List<int>();
    var indeg = new int[numCourses];
    foreach (var p in prerequisites) { adj[p[1]].Add(p[0]); indeg[p[0]]++; } // p[1] before p[0]

    var q = new Queue<int>();
    for (int c = 0; c < numCourses; c++) if (indeg[c] == 0) q.Enqueue(c);
    var order = new List<int>(numCourses);
    while (q.Count > 0)
    {
        int u = q.Dequeue();
        order.Add(u);
        foreach (int v in adj[u])
            if (--indeg[v] == 0) q.Enqueue(v);
    }
    return order.Count == numCourses ? order.ToArray() : Array.Empty<int>();
}

Complexity: O(V + E) time and memory. Course Schedule I is the same code returning len(order) == num_courses.

2. Alien Dictionary Hard

Words are sorted in an unknown alphabet. Return any alphabet order consistent with them, or "" if none exists.

Key insight. Each adjacent pair of words gives at most one rule, from the first differing letter. A pair where the longer word comes first and the shorter one is its prefix is a contradiction on its own. Every letter is a node, even if no rule mentions it. Then sort topologically; a cycle means "". Step through it in the visualizer above.

Solution: rules from adjacent pairs, then Kahn 
from collections import deque

def alien_order(words):
    adj = {c: set() for w in words for c in w}      # every letter is a node
    indeg = {c: 0 for c in adj}
    for w1, w2 in zip(words, words[1:]):
        for a, b in zip(w1, w2):
            if a != b:                                # the first difference decides
                if b not in adj[a]:                   # count each rule once
                    adj[a].add(b)
                    indeg[b] += 1
                break
        else:
            if len(w1) > len(w2):                     # "abc" before "ab": impossible
                return ""
    q = deque(c for c in indeg if indeg[c] == 0)
    order = []
    while q:
        c = q.popleft()
        order.append(c)
        for d in adj[c]:
            indeg[d] -= 1
            if indeg[d] == 0:
                q.append(d)
    return "".join(order) if len(order) == len(indeg) else ""

public string AlienOrder(string[] words)
{
    var adj = new Dictionary<char, HashSet<char>>();   // every letter is a node
    var indeg = new Dictionary<char, int>();
    foreach (var w in words)
        foreach (char c in w)
            if (!adj.ContainsKey(c)) { adj[c] = new HashSet<char>(); indeg[c] = 0; }

    for (int k = 0; k + 1 < words.Length; k++)
    {
        string w1 = words[k], w2 = words[k + 1];
        int len = Math.Min(w1.Length, w2.Length), i = 0;
        while (i < len && w1[i] == w2[i]) i++;
        if (i < len)                                    // the first difference decides
        {
            if (adj[w1[i]].Add(w2[i])) indeg[w2[i]]++;  // count each rule once
        }
        else if (w1.Length > w2.Length) return "";      // "abc" before "ab": impossible
    }

    var q = new Queue<char>();
    foreach (var (c, d) in indeg) if (d == 0) q.Enqueue(c);
    var sb = new StringBuilder();
    while (q.Count > 0)
    {
        char c = q.Dequeue();
        sb.Append(c);
        foreach (char d in adj[c])
            if (--indeg[d] == 0) q.Enqueue(d);
    }
    return sb.Length == indeg.Count ? sb.ToString() : "";
}

Complexity: O(C) to compare the words, where C is the total number of characters, plus O(Σ + R) for the sort, with Σ ≤ 26 letters and R ≤ Σ² distinct rules.

3. Parallel Courses III Hard

Course i takes time[i] months, [prev, next] relations must be respected, and any number of courses can run at the same time. Return the minimum number of months to finish everything (the graph is a DAG).

Key insight. A course starts when its last prerequisite finishes, so start[v] = max(finish[u]) over its prerequisites and finish[v] = start[v] + time[v]. Kahn guarantees every prerequisite's finish is final before v is popped. The answer is the largest finish time: the length of the critical path in the DP-on-a-DAG visualizer.

Solution: longest path in Kahn order 
from collections import deque

def minimum_time(n, relations, time):
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for prev, nxt in relations:                   # courses are 1-indexed
        adj[prev - 1].append(nxt - 1)
        indeg[nxt - 1] += 1
    start = [0] * n                               # latest finish among prerequisites
    q = deque(i for i in range(n) if indeg[i] == 0)
    ans = 0
    while q:
        u = q.popleft()
        finish = start[u] + time[u]
        ans = max(ans, finish)
        for v in adj[u]:
            start[v] = max(start[v], finish)
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return ans

public int MinimumTime(int n, int[][] relations, int[] time)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    var indeg = new int[n];
    foreach (var r in relations) { adj[r[0] - 1].Add(r[1] - 1); indeg[r[1] - 1]++; } // 1-indexed

    var start = new int[n];                       // latest finish among prerequisites
    var q = new Queue<int>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) q.Enqueue(i);
    int ans = 0;
    while (q.Count > 0)
    {
        int u = q.Dequeue();
        int finish = start[u] + time[u];
        ans = Math.Max(ans, finish);
        foreach (int v in adj[u])
        {
            start[v] = Math.Max(start[v], finish);
            if (--indeg[v] == 0) q.Enqueue(v);
        }
    }
    return ans;
}

Complexity: O(n + E) time and memory.

4. Longest Increasing Path in a Matrix Hard

Return the length of the longest strictly increasing path in a grid, moving up, down, left or right.

Key insight. "Strictly larger neighbour" arrows form a DAG, since values only go up along a path. Give each cell an in-degree equal to its number of strictly smaller neighbours, then peel Kahn layers from the local minima: the number of layers is the longest path. Unlike memoised DFS, this cannot hit the recursion limit on a 200 × 200 snake. See the visualizer above.

Solution: Kahn layers on the implicit DAG 
def longest_increasing_path(matrix):
    R, C = len(matrix), len(matrix[0])
    DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))
    indeg = [[0] * C for _ in range(R)]           # number of strictly smaller neighbours
    for r in range(R):
        for c in range(C):
            for dr, dc in DIRS:
                nr, nc = r + dr, c + dc
                if 0 <= nr < R and 0 <= nc < C and matrix[nr][nc] < matrix[r][c]:
                    indeg[r][c] += 1
    layer = [(r, c) for r in range(R) for c in range(C) if indeg[r][c] == 0]
    length = 0
    while layer:
        length += 1                               # one more cell on the longest chain
        nxt = []
        for r, c in layer:
            for dr, dc in DIRS:
                nr, nc = r + dr, c + dc
                if 0 <= nr < R and 0 <= nc < C and matrix[nr][nc] > matrix[r][c]:
                    indeg[nr][nc] -= 1
                    if indeg[nr][nc] == 0:
                        nxt.append((nr, nc))
        layer = nxt
    return length

public int LongestIncreasingPath(int[][] matrix)
{
    int rows = matrix.Length, cols = matrix[0].Length;
    int[] dr = { 1, -1, 0, 0 }, dc = { 0, 0, 1, -1 };
    var indeg = new int[rows, cols];              // number of strictly smaller neighbours
    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
            for (int k = 0; k < 4; k++)
            {
                int nr = r + dr[k], nc = c + dc[k];
                if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && matrix[nr][nc] < matrix[r][c])
                    indeg[r, c]++;
            }

    var layer = new List<(int, int)>();
    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
            if (indeg[r, c] == 0) layer.Add((r, c));
    int length = 0;
    while (layer.Count > 0)
    {
        length++;                                 // one more cell on the longest chain
        var next = new List<(int, int)>();
        foreach (var (r, c) in layer)
            for (int k = 0; k < 4; k++)
            {
                int nr = r + dr[k], nc = c + dc[k];
                if (nr >= 0 && nr < rows && nc >= 0 && nc < cols
                    && matrix[nr][nc] > matrix[r][c] && --indeg[nr, nc] == 0)
                    next.Add((nr, nc));
            }
        layer = next;
    }
    return length;
}

Complexity: O(R · C) time and memory: each cell has at most four arrows.

5. Find Eventual Safe States Medium

A node is safe if every path starting from it ends at a terminal node (one with no outgoing edges). Return all safe nodes in increasing order.

Key insight. Safety flows backwards: a terminal node is safe, and a node is safe once all of its out-arrows lead to safe nodes. That is Kahn on the reversed graph with out-degrees as the counters. Nodes that never reach 0 can reach a cycle. (The DFS alternative: a node is safe exactly when its three-colour DFS finishes BLACK without meeting a GREY node.)

Solution: reverse Kahn from the terminal nodes 
from collections import deque

def eventual_safe_nodes(graph):
    n = len(graph)
    rev = [[] for _ in range(n)]
    out = [len(graph[u]) for u in range(n)]        # arrows not yet known to be safe
    for u in range(n):
        for v in graph[u]:
            rev[v].append(u)
    q = deque(u for u in range(n) if out[u] == 0)  # terminal nodes
    safe = [False] * n
    while q:
        v = q.popleft()
        safe[v] = True
        for u in rev[v]:                           # u -> v just became a safe arrow
            out[u] -= 1
            if out[u] == 0:
                q.append(u)
    return [u for u in range(n) if safe[u]]

public IList<int> EventualSafeNodes(int[][] graph)
{
    int n = graph.Length;
    var rev = new List<int>[n];
    for (int i = 0; i < n; i++) rev[i] = new List<int>();
    var outdeg = new int[n];                      // arrows not yet known to be safe
    var q = new Queue<int>();
    for (int u = 0; u < n; u++)
    {
        outdeg[u] = graph[u].Length;
        foreach (int v in graph[u]) rev[v].Add(u);
        if (outdeg[u] == 0) q.Enqueue(u);         // terminal nodes
    }
    var safe = new bool[n];
    while (q.Count > 0)
    {
        int v = q.Dequeue();
        safe[v] = true;
        foreach (int u in rev[v])                 // u -> v just became a safe arrow
            if (--outdeg[u] == 0) q.Enqueue(u);
    }
    var result = new List<int>();
    for (int u = 0; u < n; u++) if (safe[u]) result.Add(u);
    return result;
}

Complexity: O(V + E) time and memory.

6. Sort Items by Groups Respecting Dependencies Hard

n items, each in one of m groups or in none (-1). Order the items so that the items of each group are contiguous and every beforeItems[i] comes before i. Return [] if that is impossible.

Key insight. It is two topological sorts, one inside the other. Give each ungrouped item a new group of its own. An item edge u → v whose ends lie in different groups is also a group edge group(u) → group(v). Sort the groups to decide which block goes first, and sort the items to decide the order inside each block. Bucket the items by group in item order, then concatenate the buckets in group order. A cycle in either graph means [].

Solution: a group-level sort and an item-level sort 
from collections import deque

def sort_items(n, m, group, before_items):
    def topo(k, edges):
        adj = [[] for _ in range(k)]
        indeg = [0] * k
        for u, v in edges:
            adj[u].append(v)
            indeg[v] += 1
        q = deque(u for u in range(k) if indeg[u] == 0)
        order = []
        while q:
            u = q.popleft()
            order.append(u)
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)
        return order if len(order) == k else None

    group = group[:]
    for i in range(n):
        if group[i] == -1:                        # an ungrouped item is its own group
            group[i] = m
            m += 1
    item_edges, group_edges = [], []
    for v in range(n):
        for u in before_items[v]:                 # u before v
            item_edges.append((u, v))
            if group[u] != group[v]:
                group_edges.append((group[u], group[v]))
    item_order, group_order = topo(n, item_edges), topo(m, group_edges)
    if item_order is None or group_order is None:
        return []
    members = [[] for _ in range(m)]
    for i in item_order:                          # each bucket keeps the item order
        members[group[i]].append(i)
    return [i for g in group_order for i in members[g]]

public int[] SortItems(int n, int m, int[] group, IList<IList<int>> beforeItems)
{
    var g = (int[])group.Clone();
    for (int i = 0; i < n; i++) if (g[i] == -1) g[i] = m++;  // an ungrouped item is its own group
    var itemEdges = new List<(int, int)>();
    var groupEdges = new List<(int, int)>();
    for (int v = 0; v < n; v++)
        foreach (int u in beforeItems[v])                     // u before v
        {
            itemEdges.Add((u, v));
            if (g[u] != g[v]) groupEdges.Add((g[u], g[v]));
        }
    var itemOrder = Topo(n, itemEdges);
    var groupOrder = Topo(m, groupEdges);
    if (itemOrder == null || groupOrder == null) return Array.Empty<int>();

    var members = new List<int>[m];
    for (int k = 0; k < m; k++) members[k] = new List<int>();
    foreach (int i in itemOrder) members[g[i]].Add(i);         // each bucket keeps the item order
    var result = new List<int>(n);
    foreach (int k in groupOrder) result.AddRange(members[k]);
    return result.ToArray();
}

static List<int>? Topo(int k, List<(int U, int V)> edges)
{
    var adj = new List<int>[k];
    for (int i = 0; i < k; i++) adj[i] = new List<int>();
    var indeg = new int[k];
    foreach (var (u, v) in edges) { adj[u].Add(v); indeg[v]++; }
    var q = new Queue<int>();
    for (int u = 0; u < k; u++) if (indeg[u] == 0) q.Enqueue(u);
    var order = new List<int>(k);
    while (q.Count > 0)
    {
        int u = q.Dequeue();
        order.Add(u);
        foreach (int v in adj[u])
            if (--indeg[v] == 0) q.Enqueue(v);
    }
    return order.Count == k ? order : null;
}

Complexity: O(n + m + E) time and memory, where E is the total length of beforeItems. Why it is correct: inside one bucket the items keep their relative item order, so intra-group edges are respected; an edge between groups is respected because its groups appear in group order.

Self-check

Kahn's queue runs dry with 4 of 9 nodes unplaced. Why must there be a cycle, and is every unplaced node on it?

Every unplaced node still has in-degree ≥ 1, and because the arrows from placed nodes were all deleted, each of those remaining arrows comes from another unplaced node. Walking backwards along them from any unplaced node never stops, and there are only 4 nodes, so the walk repeats a node: that is a cycle. Not every unplaced node is on it, though. A node can sit downstream of the cycle, waiting for a node that waits forever (node 4 in the cycle visualizer).

You build the arrows for Course Schedule backwards (a → b instead of b → a). Which of Course Schedule I and II still pass?

I still passes, II fails. Reversing every arrow turns each cycle into a cycle and each DAG into a DAG, so "can all courses be finished?" has the same answer. But a topological order of the reversed graph is the original order backwards, so every course appears before its prerequisites. This is exactly why the bug survives the first problem and surprises you on the second.

Why does reversed post-order work but pre-order does not?

A node finishes only after everything reachable from it has finished, so for every edge u → v, v finishes first (either inside u's call or before it). Reversing puts u first. Pre-order only tells you when a node was entered, and a node entered early can still have an arrow coming into it from a node in a later DFS tree: with 0 → 1 and 2 → 0, pre-order gives 0, 1, 2, but 2 must come before 0.

How can you tell whether a DAG has exactly one topological order, in O(V + E)?

Run Kahn and check whether the queue ever holds two or more nodes. Two ready nodes don't depend on each other (directly or indirectly), so they could be placed in either order. If the queue always holds exactly one node, every step was forced. Equivalently, each consecutive pair in the order is joined by an arrow, so the order is a path through every node.

A weighted DAG has negative edges. How do you find shortest paths from s, and why not Dijkstra?

Relax the edges in topological order: dist[v] = min(dist[v], dist[u] + w) for each arrow u → v, processing u only after all its predecessors. When u is processed, every path into u has already been considered, so dist[u] is final, whatever the signs of the weights. That is O(V + E). Dijkstra assumes that a popped node can never be improved later, which a negative edge can break. On a DAG you don't need that assumption at all.

For "lexicographically smallest order", why does taking the smallest ready node always work?

The first element must be a source, and the smallest source is the best possible first element. Placing it never removes options: any order of the remaining nodes that was valid before is still valid, because a source has no prerequisites to violate. The same argument repeats on the remaining graph. Note that this is not the right greedy for "put small labels as early as possible", which needs the reversed graph and a max-heap.

Why does Parallel Courses II (at most k courses per semester) not fall to Kahn plus a greedy rule?

With unlimited parallelism the answer is the longest chain, and the Kahn layers achieve it. With a cap of k, you must choose which k ready courses to take, and that choice affects which courses are ready later. Every simple rule (most dependants, longest chain behind it) has counterexamples. With n ≤ 15, the intended solution is DP over the 2ⁿ subsets of finished courses, trying the subsets of size ≤ k of the currently ready courses.
