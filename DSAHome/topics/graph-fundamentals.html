Graph Fundamentals: BFS & DFS

Representations, BFS layers and DFS discovery animated on graphs and grids, components, cycle detection and multi-source BFS.

Beginner → Advanced~70 min studyBuilds on: Stacks & Queues, Recursion & the Call StackUpdated 2026-11-03

What a graph is, and when you need one

A graph is things (nodes, also called vertices) plus relationships between them (edges). The idea matters because most "from here I can go to there" problems are graph problems, even when nobody draws a graph. A maze, an island map, a lock dial, a word that changes one letter at a time, a social network and a build system are all graphs. Two traversals, breadth-first search (BFS) and depth-first search (DFS), solve most of them.

This page assumes Stacks & Queues and Recursion & the Call Stack. The connection is direct: BFS is a queue, and DFS is a stack, either your own or the call stack.

The traversal invariant. Every reachable node is discovered exactly once and every edge is examined at most twice, so BFS and DFS cost O(V + E). That bound only holds if you mark a node the moment you discover it and never process a marked node again.

Everything else on this page is a variation on that one sentence: what you store when you discover a node (a distance, a colour, a component id, a parent) and in which order you discover nodes (a queue gives layers, a stack gives deep paths).

The vocabulary, in one picture

Term Meaning Why you care
Path A sequence of nodes joined by edges BFS finds the one with the fewest edges
Cycle A path that returns to its start Breaks topological order, and causes infinite loops if you forget to mark nodes
Connected component A maximal set of mutually reachable nodes "How many islands / provinces / groups?"
DAG A directed acyclic graph It can be ordered: see Topological Sort & DAGs
Sparse vs dense E ≈ V vs E ≈ V² Decides between an adjacency list and a matrix

Insight Problems usually give you an edge list (edges = [[0,1],[1,2]]) but traversals want an adjacency list. Converting costs O(V + E) once, and it is almost always your first line of code. An undirected edge is stored twice, once in each endpoint's list. Forgetting the second copy is the most common reason a BFS "can't reach" a node.

Build the graph edge by edge and watch all three stored forms grow together. Switch between undirected and directed to see the matrix lose its symmetry and each edge appear in only one list.

from collections import defaultdict

def build_adj(n, edges, directed=False):
    adj = [[] for _ in range(n)]          # node ids 0..n-1
    for u, v in edges:
        adj[u].append(v)
        if not directed:
            adj[v].append(u)              # undirected: store both directions
    return adj

def build_adj_labels(edges):              # arbitrary hashable labels ("JFK", (r, c), ...)
    adj = defaultdict(list)
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    return adj

def build_matrix(n, edges):
    m = [[0] * n for _ in range(n)]
    for u, v in edges:
        m[u][v] = m[v][u] = 1
    return m

static List<int>[] BuildAdj(int n, int[][] edges, bool directed = false)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    foreach (var e in edges)
    {
        adj[e[0]].Add(e[1]);
        if (!directed) adj[e[1]].Add(e[0]);   // undirected: store both directions
    }
    return adj;
}

static Dictionary<string, List<string>> BuildAdjLabels(IEnumerable<(string U, string V)> edges)
{
    var adj = new Dictionary<string, List<string>>();
    foreach (var (u, v) in edges)
    {
        if (!adj.TryGetValue(u, out var lu)) adj[u] = lu = new List<string>();
        if (!adj.TryGetValue(v, out var lv)) adj[v] = lv = new List<string>();
        lu.Add(v);
        lv.Add(u);
    }
    return adj;
}

static bool[,] BuildMatrix(int n, int[][] edges)
{
    var m = new bool[n, n];
    foreach (var e in edges) m[e[0], e[1]] = m[e[1], e[0]] = true;
    return m;
}

Building an adjacency list is O(V + E) time and memory; building a matrix is O(V²) however few edges there are.

BFS: explore in rings

BFS answers "what is the fewest number of edges from s to every node?" It works because a FIFO queue releases nodes in the order they were discovered. Everything at distance 1 is discovered before anything at distance 2, so it also leaves the queue first. When a node is discovered for the first time, it is therefore reached by a shortest path (counted in edges).

Run it. Watch the d= labels appear ring by ring, the queue only ever holding two consecutive distances, and the layer table filling up. Set a target to see the shortest path reconstructed from parent links. Add a disconnected pair (like the default 8-9) to see that BFS from one source never reaches another component.

from collections import deque

def bfs(adj, src):
    n = len(adj)
    dist, parent = [-1] * n, [-1] * n     # -1 doubles as "not seen yet"
    dist[src] = 0
    q = deque([src])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:              # mark on ENQUEUE, not on pop
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)
    return dist, parent

def path_to(dist, parent, t):
    if dist[t] == -1:
        return []                          # unreachable
    path = []
    while t != -1:
        path.append(t)
        t = parent[t]
    return path[::-1]

def bfs_by_level(adj, src):               # when you need "minutes", "steps" or whole layers
    seen = {src}
    q, level = deque([src]), 0
    while q:
        for _ in range(len(q)):            # exactly the nodes of the current layer
            u = q.popleft()
            # ... process u at distance `level` ...
            for v in adj[u]:
                if v not in seen:
                    seen.add(v)
                    q.append(v)
        level += 1

static (int[] Dist, int[] Parent) Bfs(List<int>[] adj, int src)
{
    int n = adj.Length;
    var dist = new int[n];
    var parent = new int[n];
    Array.Fill(dist, -1);                  // -1 doubles as "not seen yet"
    Array.Fill(parent, -1);
    dist[src] = 0;
    var q = new Queue<int>();
    q.Enqueue(src);
    while (q.Count > 0)
    {
        int u = q.Dequeue();
        foreach (int v in adj[u])
        {
            if (dist[v] != -1) continue;
            dist[v] = dist[u] + 1;         // mark on ENQUEUE, not on dequeue
            parent[v] = u;
            q.Enqueue(v);
        }
    }
    return (dist, parent);
}

static List<int> PathTo(int[] dist, int[] parent, int t)
{
    var path = new List<int>();
    if (dist[t] == -1) return path;        // unreachable
    for (int v = t; v != -1; v = parent[v]) path.Add(v);
    path.Reverse();
    return path;
}

static void BfsByLevel(List<int>[] adj, int src)
{
    var seen = new bool[adj.Length];
    seen[src] = true;
    var q = new Queue<int>();
    q.Enqueue(src);
    for (int level = 0; q.Count > 0; level++)
    {
        for (int k = q.Count; k > 0; k--)  // exactly the nodes of the current layer
        {
            int u = q.Dequeue();
            // ... process u at distance `level` ...
            foreach (int v in adj[u])
                if (!seen[v]) { seen[v] = true; q.Enqueue(v); }
        }
    }
}

Time O(V + E) and memory O(V). The for _ in range(len(q)) form tracks the layer number without storing a distance per node. Use it when the answer is "how many rounds" (minutes, moves, steps).

Why mark on enqueue?

Mark when popped

u = q.popleft(); if seen[u]: continue; seen[u] = True. Until v is popped, every neighbour that sees it pushes it again. On a dense graph the queue grows to O(E) entries, and on a grid each cell can be queued up to four times. Code that counts or sums while pushing (island area, number of fresh oranges) counts some cells twice.

Mark when pushed

if not seen[v]: seen[v] = True; q.append(v). Each node enters the queue exactly once, the queue holds at most V entries, and the distance stored at discovery is final. It's the same amount of code, and it is always correct.

Tip BFS gives shortest paths only when every edge costs the same. For weights in {0, 1}, use 0-1 BFS with a deque (push 0-edges to the front). For general non-negative weights, use Dijkstra. Both are in Shortest Paths.

DFS: go deep, then back up

DFS follows one path as far as it can, then backtracks to the most recent node that still has an unexplored edge. The "most recent" is exactly what a stack gives you, and recursion uses the call stack for free. DFS doesn't find shortest paths. What it gives you is structure: the moment each node is entered and left, and whether an edge leads forward, back up the current path or sideways.

Track each node with three colours:

  • WHITE: not discovered yet.
  • GREY: discovered, and still on the current recursion path (its call hasn't returned).
  • BLACK: finished; every node reachable from it has been explored.

Recording a clock tick on entry (d[u]) and on exit (f[u]) turns the run into nested intervals.

Edge u→v, and v's colour when u examines it Name What it tells you
WHITE Tree v is discovered through u (parent[v] = u)
GREY Back v is an ancestor on the current path: a cycle
BLACK and d[u] < d[v] Forward v is a descendant that already finished; harmless
BLACK and d[u] > d[v] Cross v is in another, finished branch; harmless

In an undirected graph only tree and back edges exist, because a "cross" edge would have been taken as a tree edge earlier. That is why undirected cycle detection is simpler: see Cycle detection.

Step through it. Watch the call stack grow and shrink, the colour array go white → grey → black, the d/f times appear above each node, and each edge get classified the moment it is examined. The default graph contains all four edge types.

WHITE, GREY, BLACK = 0, 1, 2

def dfs_all(adj):
    n = len(adj)
    color, d, f = [WHITE] * n, [0] * n, [0] * n
    time = 0

    def dfs(u):
        nonlocal time
        color[u] = GREY; time += 1; d[u] = time      # enter: on the current path
        for v in adj[u]:
            if color[v] == WHITE:
                dfs(v)                                # tree edge
            # GREY v -> back edge (cycle); BLACK v -> forward / cross
        color[u] = BLACK; time += 1; f[u] = time     # leave: fully explored

    for s in range(n):                                # restart in every unvisited part
        if color[s] == WHITE:
            dfs(s)
    return d, f

def dfs_iterative(adj):
    """Same colours and times as the recursive version: no recursion limit."""
    n = len(adj)
    color, d, f = [WHITE] * n, [0] * n, [0] * n
    time = 0
    for s in range(n):
        if color[s] != WHITE:
            continue
        time += 1; d[s] = time; color[s] = GREY
        stack = [(s, 0)]                               # (node, index of next neighbour)
        while stack:
            u, i = stack[-1]
            if i < len(adj[u]):
                stack[-1] = (u, i + 1)                 # resume point, like a saved PC
                v = adj[u][i]
                if color[v] == WHITE:
                    time += 1; d[v] = time; color[v] = GREY
                    stack.append((v, 0))
            else:
                stack.pop()
                time += 1; f[u] = time; color[u] = BLACK
    return d, f

const int White = 0, Grey = 1, Black = 2;

static (int[] D, int[] F) DfsAll(List<int>[] adj)
{
    int n = adj.Length, time = 0;
    var color = new int[n];
    var d = new int[n];
    var f = new int[n];

    void Dfs(int u)
    {
        color[u] = Grey; d[u] = ++time;              // enter: on the current path
        foreach (int v in adj[u])
            if (color[v] == White) Dfs(v);            // tree edge
        color[u] = Black; f[u] = ++time;             // leave: fully explored
    }

    for (int s = 0; s < n; s++)
        if (color[s] == White) Dfs(s);
    return (d, f);
}

static (int[] D, int[] F) DfsIterative(List<int>[] adj)
{
    int n = adj.Length, time = 0;
    var color = new int[n];
    var d = new int[n];
    var f = new int[n];
    var stack = new Stack<(int Node, int Next)>();
    for (int s = 0; s < n; s++)
    {
        if (color[s] != White) continue;
        d[s] = ++time; color[s] = Grey;
        stack.Push((s, 0));
        while (stack.Count > 0)
        {
            var (u, i) = stack.Pop();
            if (i < adj[u].Count)
            {
                stack.Push((u, i + 1));               // resume point, like a saved PC
                int v = adj[u][i];
                if (color[v] == White)
                {
                    d[v] = ++time; color[v] = Grey;
                    stack.Push((v, 0));
                }
            }
            else
            {
                f[u] = ++time; color[u] = Black;
            }
        }
    }
    return (d, f);
}

Time O(V + E), memory O(V) for the colours plus O(depth) for the stack.

Pitfall: recursion depth A path-shaped graph (or a 1000×1000 grid shaped like a snake) makes recursive DFS go V levels deep. Python stops at about 1000 frames by default. C# overflows its 1 MB thread stack somewhere around 10⁴–10⁵ frames, and a StackOverflowException cannot be caught. When V can exceed about 10⁴, use the iterative (node, next-index) version above. Alternatively, when you only need "visit everything" and not finish times, use the simpler "push all neighbours, skip on pop if seen" stack. sys.setrecursionlimit only moves the crash.

Insight: BFS or DFS? For plain reachability (components, flood fill, "can I reach t?") either works; choose whichever is shortest to write. You need BFS for fewest edges or steps, or when the answer is "how many rounds". You need DFS for finish order (topological sort, SCCs), back edges (directed cycles), ancestry, or when the work happens after the children return (subtree sizes, memoised DP on a DAG).

Grids: the most common hidden graph

A 2-D grid is a graph: a node is a cell (r, c), and the edges go to the open cells next to it. No adjacency list is ever built; the neighbours are computed with a direction array and a bounds check. A grid traversal costs O(R·C) time and memory.

Flood fill and Number of Islands

Scan every cell. Each time you find land that has not been visited yet, you have found a new island: count it, then flood it (with BFS or DFS) so that none of its cells is counted again. That is "count the connected components" on an implicit graph. Edit the grid, switch between a BFS queue and a DFS stack (the same island gets claimed, in a different order), and switch to 8-way neighbours to see diagonal islands merge.

from collections import deque

DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))

def num_islands(grid):
    R, C = len(grid), len(grid[0])
    seen = [[False] * C for _ in range(R)]
    count = 0
    for r in range(R):
        for c in range(C):
            if grid[r][c] != "1" or seen[r][c]:
                continue
            count += 1                                 # new component found
            seen[r][c] = True
            q = deque([(r, c)])
            while q:                                   # flood it so it is never counted again
                cr, cc = q.popleft()
                for dr, dc in DIRS:
                    nr, nc = cr + dr, cc + dc
                    if 0 <= nr < R and 0 <= nc < C and grid[nr][nc] == "1" and not seen[nr][nc]:
                        seen[nr][nc] = True
                        q.append((nr, nc))
    return count

static readonly (int Dr, int Dc)[] Dirs = { (1, 0), (-1, 0), (0, 1), (0, -1) };

static int NumIslands(char[][] grid)
{
    int R = grid.Length, C = grid[0].Length, count = 0;
    var seen = new bool[R, C];
    var q = new Queue<(int, int)>();
    for (int r = 0; r < R; r++)
    for (int c = 0; c < C; c++)
    {
        if (grid[r][c] != '1' || seen[r, c]) continue;
        count++;                                        // new component found
        seen[r, c] = true;
        q.Enqueue((r, c));
        while (q.Count > 0)                             // flood it so it is never counted again
        {
            var (cr, cc) = q.Dequeue();
            foreach (var (dr, dc) in Dirs)
            {
                int nr = cr + dr, nc = cc + dc;
                if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
                if (grid[nr][nc] != '1' || seen[nr, nc]) continue;
                seen[nr, nc] = true;
                q.Enqueue((nr, nc));
            }
        }
    }
    return count;
}

Time O(R·C) and memory O(R·C) for seen. If you are allowed to modify the input, overwrite '1' with '0' instead of keeping seen. That saves memory, but it destroys the input, so say so in an interview.

Tip: grid habits that prevent bugs

  • Keep one DIRS constant and one bounds check: 0 <= nr < R and 0 <= nc < C.
  • Encode a cell as r * C + c when you need a 1-D id (for union-find, or a seen set of ints).
  • Check "is it open?" before "have I seen it?". Both orders are correct; this one is just faster to read.
  • For "border-connected" problems (Surrounded Regions, Pacific Atlantic, Number of Enclaves), start from the border and mark what is reachable. Everything left unmarked is the answer.

Multi-source BFS: many starting points, one pass

"Every rotten orange infects its neighbours each minute." "Fill each empty room with the distance to its nearest gate." Running one BFS per source costs k · O(V + E) and still needs a min at the end. Instead, put every source in the queue at distance 0 and run a single BFS. The layers grow outward from all sources at once, and the first wave to reach a cell is the one from the nearest source.

Step through both stories on the same grid. In rotting oranges the answer is the number of layers (minutes), or −1 if a fresh orange is never reached. In walls and gates every reached cell stores its layer number, and unreachable rooms stay at ∞.

from collections import deque

def oranges_rotting(grid):
    R, C = len(grid), len(grid[0])
    q, fresh = deque(), 0
    for r in range(R):
        for c in range(C):
            if grid[r][c] == 2:
                q.append((r, c))                 # ALL sources start at minute 0
            elif grid[r][c] == 1:
                fresh += 1
    minutes = 0
    while q and fresh:
        for _ in range(len(q)):                  # one whole layer = one minute
            r, c = q.popleft()
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < R and 0 <= nc < C and grid[nr][nc] == 1:
                    grid[nr][nc] = 2             # mark on enqueue
                    fresh -= 1
                    q.append((nr, nc))
        minutes += 1
    return -1 if fresh else minutes

static int OrangesRotting(int[][] grid)
{
    int R = grid.Length, C = grid[0].Length, fresh = 0, minutes = 0;
    var q = new Queue<(int, int)>();
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (grid[r][c] == 2) q.Enqueue((r, c));   // ALL sources start at minute 0
            else if (grid[r][c] == 1) fresh++;
    int[] dr = { 1, -1, 0, 0 }, dc = { 0, 0, 1, -1 };
    while (q.Count > 0 && fresh > 0)
    {
        for (int k = q.Count; k > 0; k--)             // one whole layer = one minute
        {
            var (r, c) = q.Dequeue();
            for (int d = 0; d < 4; d++)
            {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nr >= R || nc < 0 || nc >= C || grid[nr][nc] != 1) continue;
                grid[nr][nc] = 2;                     // mark on enqueue
                fresh--;
                q.Enqueue((nr, nc));
            }
        }
        minutes++;
    }
    return fresh > 0 ? -1 : minutes;
}

Time O(R·C) and memory O(R·C). The while q and fresh condition matters: without and fresh, the loop would count one extra minute after the last orange rots.

Recognize multi-source BFS when

  • The question asks for the distance to the nearest of many things: gates, zeros (01 Matrix), land (As Far from Land as Possible), or the nearest exit.
  • Something spreads simultaneously from several places (rot, fire, infection, flooding).
  • A brute force would run a BFS from every source. Reverse it: start from all the targets at once.

Connected components

In an undirected graph, a connected component is a maximal set of nodes that can all reach each other. Counting components uses the same outer loop as islands: for each node not seen yet, start a new traversal and stamp every node it reaches with a new component id. Each node is visited once, so the whole thing is O(V + E) even though there are several traversals.

from collections import deque

def components(n, edges):
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    comp = [-1] * n
    k = 0
    for s in range(n):
        if comp[s] != -1:
            continue
        comp[s] = k                       # s starts component k
        q = deque([s])
        while q:
            u = q.popleft()
            for v in adj[u]:
                if comp[v] == -1:
                    comp[v] = k
                    q.append(v)
        k += 1
    return k, comp                        # number of components, label per node

static (int Count, int[] Comp) Components(int n, int[][] edges)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
    var comp = new int[n];
    Array.Fill(comp, -1);
    int k = 0;
    var q = new Queue<int>();
    for (int s = 0; s < n; s++)
    {
        if (comp[s] != -1) continue;
        comp[s] = k;                       // s starts component k
        q.Enqueue(s);
        while (q.Count > 0)
        {
            int u = q.Dequeue();
            foreach (int v in adj[u])
                if (comp[v] == -1) { comp[v] = k; q.Enqueue(v); }
        }
        k++;
    }
    return (k, comp);
}

Traversal or union-find? Use a traversal when the graph is fixed and you need the components once. When edges arrive over time ("after each new connection, how many groups?") or you only need "are a and b connected?", use Union-Find, which handles each union in near-O(1). In a directed graph, "mutually reachable" means strongly connected components (Tarjan or Kosaraju), covered in Advanced Graph Algorithms.

Cycle detection: two different questions

"Does this graph have a cycle?" has two different correct answers, depending on whether the edges are directed. Copying the undirected trick into a directed graph, or the reverse, is one of the most common graph bugs.

Run all three rules on the same default diamond (0-1, 0-2, 1-3, 2-3, 3-4). Read as undirected edges, the diamond is a cycle (0–1–3–2–0), and the parent check finds it. Read as directed edges it has no cycle: the GREY check correctly says so, while the buggy visited-only rule raises a false alarm at node 3. Then try 0>1,1>2,2>0 for a real directed cycle.

WHITE, GREY, BLACK = 0, 1, 2

def has_cycle_undirected(n, edges):
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    seen = [False] * n
    for s in range(n):
        if seen[s]:
            continue
        seen[s] = True
        stack = [(s, -1)]                     # (node, the parent we came from)
        while stack:
            u, parent = stack.pop()
            for v in adj[u]:
                if v == parent:
                    continue                  # the edge we arrived on, seen from the other end
                if seen[v]:
                    return True               # a second route to v: cycle
                seen[v] = True
                stack.append((v, u))
    return False

def has_cycle_directed(n, edges):
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
    state = [WHITE] * n
    for s in range(n):
        if state[s] != WHITE:
            continue
        state[s] = GREY
        stack = [(s, 0)]
        while stack:
            u, i = stack[-1]
            if i < len(adj[u]):
                stack[-1] = (u, i + 1)
                v = adj[u][i]
                if state[v] == GREY:
                    return True               # back edge into the current path
                if state[v] == WHITE:
                    state[v] = GREY
                    stack.append((v, 0))
                # BLACK: finished earlier, reachable twice but no cycle
            else:
                state[u] = BLACK              # leaving the path
                stack.pop()
    return False

static bool HasCycleUndirected(int n, int[][] edges)
{
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
    var seen = new bool[n];
    var stack = new Stack<(int Node, int Parent)>();
    for (int s = 0; s < n; s++)
    {
        if (seen[s]) continue;
        seen[s] = true;
        stack.Push((s, -1));
        while (stack.Count > 0)
        {
            var (u, parent) = stack.Pop();
            foreach (int v in adj[u])
            {
                if (v == parent) continue;        // the edge we arrived on
                if (seen[v]) return true;         // a second route to v: cycle
                seen[v] = true;
                stack.Push((v, u));
            }
        }
    }
    return false;
}

static bool HasCycleDirected(int n, int[][] edges)
{
    const int White = 0, Grey = 1, Black = 2;
    var adj = new List<int>[n];
    for (int i = 0; i < n; i++) adj[i] = new List<int>();
    foreach (var e in edges) adj[e[0]].Add(e[1]);
    var state = new int[n];
    var stack = new Stack<(int Node, int Next)>();
    for (int s = 0; s < n; s++)
    {
        if (state[s] != White) continue;
        state[s] = Grey;
        stack.Push((s, 0));
        while (stack.Count > 0)
        {
            var (u, i) = stack.Pop();
            if (i < adj[u].Count)
            {
                stack.Push((u, i + 1));
                int v = adj[u][i];
                if (state[v] == Grey) return true;    // back edge into the current path
                if (state[v] == White) { state[v] = Grey; stack.Push((v, 0)); }
            }
            else state[u] = Black;                     // leaving the path
        }
    }
    return false;
}

Both are O(V + E).

Undirected alternatives

Union-find: process the edges one by one; an edge whose endpoints are already connected closes a cycle. Counting: a connected undirected graph is a tree exactly when E = V − 1, so a connected graph with E ≥ V has a cycle.

Directed alternative

Kahn's algorithm: repeatedly remove nodes with in-degree 0. If some nodes can never be removed, they sit on or behind a cycle. See Topological Sort & DAGs.

Multigraph caveat

With parallel edges (u–v listed twice), "skip the parent" also skips the second copy, which is a 2-cycle. Skip the parent edge id, not the parent node, when duplicates are possible.

Bipartite graphs: 2-colouring

Many problems ask whether you can split things into two groups so that every conflict crosses the split: "dislike" pairs, two teams, the two sides of a matching. That is a 2-colouring question. Colour the start node L, colour its neighbours R, their neighbours L, and so on. BFS does exactly this, layer by layer. Because each colour is forced by its neighbour, a conflict means no 2-colouring exists at all. It is not a bad choice you could undo.

The visualizer colours each component with BFS and shows the graph redrawn as two sides (L | uncoloured | R). When it finds an edge with the same colour at both ends, it walks the parent links from both endpoints up to their meeting point and highlights the odd cycle that proves the graph is not bipartite. Add 2-0 to the default input to create one.

from collections import deque

def is_bipartite(graph):                  # graph[u] = list of neighbours
    n = len(graph)
    color = [-1] * n
    for s in range(n):                    # every component needs its own start
        if color[s] != -1:
            continue
        color[s] = 0
        q = deque([s])
        while q:
            u = q.popleft()
            for v in graph[u]:
                if color[v] == -1:
                    color[v] = 1 - color[u]    # forced: the opposite side
                    q.append(v)
                elif color[v] == color[u]:
                    return False               # odd cycle through u and v
    return True

static bool IsBipartite(int[][] graph)
{
    int n = graph.Length;
    var color = new int[n];
    Array.Fill(color, -1);
    var q = new Queue<int>();
    for (int s = 0; s < n; s++)            // every component needs its own start
    {
        if (color[s] != -1) continue;
        color[s] = 0;
        q.Enqueue(s);
        while (q.Count > 0)
        {
            int u = q.Dequeue();
            foreach (int v in graph[u])
            {
                if (color[v] == -1) { color[v] = 1 - color[u]; q.Enqueue(v); }
                else if (color[v] == color[u]) return false;   // odd cycle
            }
        }
    }
    return true;
}

Time O(V + E), memory O(V). Union-find works too: for every node u, union all of u's neighbours together, and fail if u ends up in the same set as one of them.

Insight: why "no odd cycle" is the whole story In a BFS tree, nodes at even depth get colour L and nodes at odd depth get colour R. Every tree edge crosses. A non-tree edge u–v joins two layers that differ by at most 1, so it is either a crossing edge (fine) or an edge within one layer. In the second case u and v have the same depth, and the paths up to their common ancestor plus the edge u–v form a cycle of length 2k + 1, which is odd. So BFS finds a conflict exactly when an odd cycle exists.

Implicit graphs: BFS over states

Many "minimum number of moves" puzzles are BFS on a graph that is never written down. A node is a complete state of the world, and an edge is one legal move. You don't build the graph; you generate a state's neighbours when you pop it, and keep a seen set of states.

Word Ladder, step by step

Word Ladder is the classic case. Each word is a node, and two words are adjacent when they differ in exactly one letter. Comparing every pair of words is O(N²·L). It is much cheaper to generate the candidates: for each position, try all 26 letters and look the result up in a hash set. That is 26·L lookups per word. The visualizer lays words out by BFS layer and draws the implicit edges faintly. Notice that a word is marked (removed from the set) the moment it is discovered, so no other word can claim it later.

from collections import deque

def bfs_states(start, is_goal, neighbours):
    """Generic state-space BFS: fewest moves from start to a goal state, or -1."""
    dist = {start: 0}                      # doubles as the seen set; states must be hashable
    q = deque([start])
    while q:
        s = q.popleft()
        if is_goal(s):
            return dist[s]
        for t in neighbours(s):            # generated on demand, never stored
            if t not in dist:
                dist[t] = dist[s] + 1
                q.append(t)
    return -1

# Open the Lock with the generic helper:
def open_lock(deadends, target):
    dead = set(deadends)
    if "0000" in dead:
        return -1
    def nbrs(s):
        for i in range(4):
            d = int(s[i])
            for nd in ((d + 1) % 10, (d - 1) % 10):
                t = s[:i] + str(nd) + s[i + 1:]
                if t not in dead:
                    yield t
    return bfs_states("0000", lambda s: s == target, nbrs)

static int BfsStates<T>(T start, Func<T, bool> isGoal, Func<T, IEnumerable<T>> neighbours)
    where T : notnull
{
    var dist = new Dictionary<T, int> { [start] = 0 };   // doubles as the seen set
    var q = new Queue<T>();
    q.Enqueue(start);
    while (q.Count > 0)
    {
        T s = q.Dequeue();
        if (isGoal(s)) return dist[s];
        foreach (T t in neighbours(s))                   // generated on demand, never stored
        {
            if (dist.ContainsKey(t)) continue;
            dist[t] = dist[s] + 1;
            q.Enqueue(t);
        }
    }
    return -1;
}

static int OpenLock(string[] deadends, string target)
{
    var dead = new HashSet<string>(deadends);
    if (dead.Contains("0000")) return -1;
    IEnumerable<string> Nbrs(string s)
    {
        var a = s.ToCharArray();
        for (int i = 0; i < 4; i++)
        {
            char orig = a[i];
            foreach (int step in new[] { 1, 9 })            // +1 and -1 (mod 10)
            {
                a[i] = (char)('0' + (orig - '0' + step) % 10);
                var t = new string(a);
                if (!dead.Contains(t)) yield return t;
            }
            a[i] = orig;
        }
    }
    return BfsStates("0000", s => s == target, Nbrs);
}

Time O(states × moves per state × cost of building a state). For the lock that is 10⁴ · 8 · 4. Memory is O(states).

Tip: design the state first The state must contain everything that affects which future moves are possible, and nothing else.

  • Plain maze: (r, c).
  • Maze with keys: (r, c, keys_bitmask), because the same cell with different keys has a different future.
  • Grid with k wall breaks: (r, c, breaks_left).
  • Visit every node: (node, visited_mask).

Too little in the state gives wrong answers, because a cell is marked "seen" while a better version of it is still possible. Too much blows up the state count. Multiply out the state count before you code; it is your complexity.

How to model a problem as a graph

1 · NODESWhat is a state?

A cell, a word, a lock combination, a course, an account, or a (cell, keys) pair.

2 · EDGESWhat is one move?

Adjacent cells, a one-letter change, "a before b", or "shares an email". Directed or not?

3 · COSTDo moves cost the same?

All equal: BFS. 0/1: deque. Arbitrary: Dijkstra. None at all: any traversal.

4 · QUESTIONWhat is asked?

Reachable? Fewest steps? Groups? Cycle? Two sides? An order? Each maps to one pattern.

The problem says… Nodes / edges Use
"minimum number of moves / steps / transformations" states / legal moves BFS (level by level)
"nearest X" for every cell, or "spreads each minute" cells / adjacency, all X as sources Multi-source BFS
"how many groups / islands / provinces" items / "connected" relation Traversal with an outer loop, or union-find
"can you finish all / is there a valid order" tasks / prerequisite arrows Directed cycle check or Topological Sort

Recognize it, cost it, and avoid the classic bugs

Recognize a graph traversal when

  • There are things and connections, even if nobody says "graph": cells, words, accounts, cities, courses, states of a puzzle.
  • The question is about reachability ("can I get from A to B?", "which cells can reach the ocean?"), groups ("how many islands / provinces?") or fewest steps ("minimum moves / transformations / minutes").
  • Something spreads from one or more places, layer by layer.
  • You must check for a cycle, a valid two-way split, or an order that respects dependencies.
  • n is up to about 10⁵–10⁶ nodes and edges: an O(V + E) pass is the expected solution.

Pitfalls: the actual bug and its fix

  1. Undirected edge stored once. adj[u].append(v) alone makes v unable to see u, so half the graph becomes unreachable. Fix: also adj[v].append(u).
  2. Traversing only from node 0. Disconnected graphs are the norm in test cases, and the second component is silently ignored. Fix: an outer for s in range(n): if not seen[s]: traverse(s).
  3. Marking on pop. Nodes are queued many times, areas and counts come out too large, and dense graphs time out. Fix: mark the moment you push.
  4. Python's negative indices. grid[r-1][c] with r = 0 silently reads the last row instead of raising an error. Fix: bounds-check 0 <= nr < R before indexing, every time.
  5. "Visited" as a directed cycle test. The diamond 0→1→3, 0→2→3 is reported as a cycle. Fix: three colours; only an edge into a GREY node is a cycle.
  6. Skipping the parent by node id in a multigraph. A doubled edge u–v is a real 2-cycle that gets skipped. Fix: skip the incoming edge id.
  7. Off-by-one in level counting. Counting a minute for the final empty layer, or counting nodes instead of edges ("ladder length" counts words, so it is edges + 1). Fix: stop when nothing is left to do (while q and fresh), and re-read whether the answer counts nodes or edges.
  8. Recursive DFS on 10⁵ nodes. RecursionError in Python, and an uncatchable StackOverflowException in C#. Fix: use an iterative stack.
  9. BFS on a weighted graph. BFS minimises the number of edges, not their total weight. Fix: use 0-1 BFS or Dijkstra.
  10. State too small in a state-space BFS. Marking (r, c) as seen when the real state is (r, c, keys) discards better routes that arrive later with more keys. Fix: the seen set must hold the whole state.

Worked problems

1. Clone Graph Medium

Given a node of a connected undirected graph, return a deep copy of the whole graph.

Key insight. The old → new map does two jobs. It is the seen set (a node has been discovered when it has a copy), and it is how you wire edges (the neighbours of copy(u) are copy(v) for each neighbour v). Create the copy when you discover a node, and add the edges when you process it. Every original edge is then copied exactly once from each side.

Solution: BFS with an old → new map 
from collections import deque

def clone_graph(node):
    if node is None:
        return None
    copies = {node: Node(node.val)}            # original -> copy; also the seen set
    q = deque([node])
    while q:
        u = q.popleft()
        for v in u.neighbors:
            if v not in copies:
                copies[v] = Node(v.val)        # discover: create the copy now
                q.append(v)
            copies[u].neighbors.append(copies[v])
    return copies[node]

public Node? CloneGraph(Node? node)
{
    if (node == null) return null;
    var copies = new Dictionary<Node, Node> { [node] = new Node(node.val) };
    var q = new Queue<Node>();
    q.Enqueue(node);
    while (q.Count > 0)
    {
        var u = q.Dequeue();
        foreach (var v in u.neighbors)
        {
            if (!copies.ContainsKey(v))
            {
                copies[v] = new Node(v.val);       // discover: create the copy now
                q.Enqueue(v);
            }
            copies[u].neighbors.Add(copies[v]);
        }
    }
    return copies[node];
}

Time O(V + E), memory O(V).

2. Pacific Atlantic Water Flow Medium

Water flows from a cell to a neighbour of equal or lower height. Return every cell from which water can reach both the Pacific (top and left edges) and the Atlantic (bottom and right edges).

Key insight. Simulating the flow from every cell costs O((R·C)²). Reverse it: start at each ocean and climb, moving to a neighbour of equal or greater height. That is a multi-source BFS from the border. The cells reached from both oceans are the answer. The general lesson: when every node asks "can I reach the target set?", search backwards from the target set once.

Solution: two reverse floods, then intersect 
from collections import deque

def pacific_atlantic(heights):
    R, C = len(heights), len(heights[0])

    def flood(starts):
        seen = set(starts)
        q = deque(starts)
        while q:
            r, c = q.popleft()
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if (0 <= nr < R and 0 <= nc < C and (nr, nc) not in seen
                        and heights[nr][nc] >= heights[r][c]):   # climb: water flows down to us
                    seen.add((nr, nc))
                    q.append((nr, nc))
        return seen

    pac = flood([(0, c) for c in range(C)] + [(r, 0) for r in range(1, R)])
    atl = flood([(R - 1, c) for c in range(C)] + [(r, C - 1) for r in range(R - 1)])
    return [[r, c] for r, c in sorted(pac & atl)]

public IList<IList<int>> PacificAtlantic(int[][] h)
{
    int R = h.Length, C = h[0].Length;
    int[] dr = { 1, -1, 0, 0 }, dc = { 0, 0, 1, -1 };

    bool[,] Flood(IEnumerable<(int R, int C)> starts)
    {
        var seen = new bool[R, C];
        var q = new Queue<(int, int)>();
        foreach (var (r, c) in starts)
            if (!seen[r, c]) { seen[r, c] = true; q.Enqueue((r, c)); }
        while (q.Count > 0)
        {
            var (r, c) = q.Dequeue();
            for (int d = 0; d < 4; d++)
            {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nr >= R || nc < 0 || nc >= C || seen[nr, nc]) continue;
                if (h[nr][nc] < h[r][c]) continue;        // climb: water flows down to us
                seen[nr, nc] = true;
                q.Enqueue((nr, nc));
            }
        }
        return seen;
    }

    var pac = Flood(Enumerable.Range(0, C).Select(c => (0, c))
        .Concat(Enumerable.Range(0, R).Select(r => (r, 0))));
    var atl = Flood(Enumerable.Range(0, C).Select(c => (R - 1, c))
        .Concat(Enumerable.Range(0, R).Select(r => (r, C - 1))));
    var res = new List<IList<int>>();
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (pac[r, c] && atl[r, c]) res.Add(new[] { r, c });
    return res;
}

Time O(R·C), memory O(R·C).

3. Shortest Path in Binary Matrix Medium

In an n×n grid of 0s (open) and 1s (blocked), return the length of the shortest 8-directional path of open cells from the top-left to the bottom-right, counting cells, or −1.

Key insight. It's a grid BFS with all 8 directions. The traps are in the details: the path length counts cells, so the start has distance 1; check whether the start or the end is blocked; and a 1×1 grid [[0]] has answer 1. Writing a 1 into each visited cell doubles as the seen mark.

Solution: 8-way BFS, marking in place 
from collections import deque

def shortest_path_binary_matrix(grid):
    n = len(grid)
    if grid[0][0] or grid[n - 1][n - 1]:
        return -1
    grid[0][0] = 1                          # mark visited in place
    q = deque([(0, 0, 1)])                  # distance counts cells, so start at 1
    while q:
        r, c, d = q.popleft()
        if r == n - 1 and c == n - 1:
            return d
        for dr in (-1, 0, 1):
            for dc in (-1, 0, 1):
                nr, nc = r + dr, c + dc
                if 0 <= nr < n and 0 <= nc < n and grid[nr][nc] == 0:
                    grid[nr][nc] = 1
                    q.append((nr, nc, d + 1))
    return -1

public int ShortestPathBinaryMatrix(int[][] grid)
{
    int n = grid.Length;
    if (grid[0][0] == 1 || grid[n - 1][n - 1] == 1) return -1;
    grid[0][0] = 1;                                  // mark visited in place
    var q = new Queue<(int R, int C, int D)>();
    q.Enqueue((0, 0, 1));                            // distance counts cells
    while (q.Count > 0)
    {
        var (r, c, d) = q.Dequeue();
        if (r == n - 1 && c == n - 1) return d;
        for (int dr = -1; dr <= 1; dr++)
        for (int dc = -1; dc <= 1; dc++)
        {
            int nr = r + dr, nc = c + dc;
            if (nr < 0 || nr >= n || nc < 0 || nc >= n || grid[nr][nc] != 0) continue;
            grid[nr][nc] = 1;
            q.Enqueue((nr, nc, d + 1));
        }
    }
    return -1;
}

Time O(n²), memory O(n²).

4. Word Ladder Hard

Return the number of words in the shortest transformation sequence from beginWord to endWord, where each step changes one letter and every intermediate word must be in wordList. Return 0 if no sequence exists.

Key insight. This is BFS on the implicit graph from the visualizer above, with two refinements. First, remove a word from the set when it is discovered, so the set is both the dictionary and the seen mark. Second, use bidirectional BFS: grow a frontier from each end and always expand the smaller one. With branching factor b and answer depth d, a one-sided search explores about b^d states, while two searches meeting in the middle explore about 2·b^(d/2).

Solution: bidirectional BFS 
def ladder_length(begin, end, word_list):
    words = set(word_list)
    if end not in words:
        return 0
    words.discard(begin)
    words.discard(end)                    # both ends are already "seen"
    front, back, steps = {begin}, {end}, 1
    while front and back:
        if len(front) > len(back):
            front, back = back, front    # always expand the smaller side
        nxt = set()
        for w in front:
            for i in range(len(w)):
                for ch in "abcdefghijklmnopqrstuvwxyz":
                    cand = w[:i] + ch + w[i + 1:]
                    if cand in back:
                        return steps + 1  # the two searches meet
                    if cand in words:
                        words.remove(cand)
                        nxt.add(cand)
        front, steps = nxt, steps + 1
    return 0

public int LadderLength(string begin, string end, IList<string> wordList)
{
    var words = new HashSet<string>(wordList);
    if (!words.Contains(end)) return 0;
    words.Remove(begin);
    words.Remove(end);                               // both ends are already "seen"
    var front = new HashSet<string> { begin };
    var back = new HashSet<string> { end };
    for (int steps = 1; front.Count > 0 && back.Count > 0; steps++)
    {
        if (front.Count > back.Count) (front, back) = (back, front);   // expand the smaller side
        var next = new HashSet<string>();
        foreach (var w in front)
        {
            var a = w.ToCharArray();
            for (int i = 0; i < a.Length; i++)
            {
                char orig = a[i];
                for (char ch = 'a'; ch <= 'z'; ch++)
                {
                    a[i] = ch;
                    var cand = new string(a);
                    if (back.Contains(cand)) return steps + 1;          // the two searches meet
                    if (words.Remove(cand)) next.Add(cand);
                }
                a[i] = orig;
            }
        }
        front = next;
    }
    return 0;
}

Time O(N · L² · 26) in the worst case, usually far less with two frontiers. Memory O(N · L).

5. Shortest Path in a Grid with Obstacles Elimination Hard

Move 4-directionally from the top-left to the bottom-right of a 0/1 grid. You may walk through at most k walls (1s). Return the fewest steps, or −1.

Key insight. Position alone is not a state, because reaching a cell with 3 breaks left is better than reaching it with 1 break left. The state is (r, c, breaks_left), and BFS over it is correct. To prune, remember the most breaks left you have ever arrived with at each cell (best[r][c]). Because BFS arrives in non-decreasing step order, a later arrival with no more breaks left is dominated and can be dropped. Shortcut: if k ≥ R + C − 2, you can bulldoze a straight Manhattan path.

Solution: BFS over (cell, breaks left) with dominance pruning 
from collections import deque

def shortest_path(grid, k):
    R, C = len(grid), len(grid[0])
    if k >= R + C - 2:
        return R + C - 2
    best = [[-1] * C for _ in range(R)]    # most breaks left on any arrival so far
    best[0][0] = k
    q = deque([(0, 0, k)])
    steps = 0
    while q:
        for _ in range(len(q)):
            r, c, left = q.popleft()
            if r == R - 1 and c == C - 1:
                return steps
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < R and 0 <= nc < C:
                    nl = left - grid[nr][nc]
                    if nl > best[nr][nc]:  # strictly better than every earlier arrival
                        best[nr][nc] = nl
                        q.append((nr, nc, nl))
        steps += 1
    return -1

public int ShortestPath(int[][] grid, int k)
{
    int R = grid.Length, C = grid[0].Length;
    if (k >= R + C - 2) return R + C - 2;
    var best = new int[R, C];                       // most breaks left on any arrival so far
    for (int r = 0; r < R; r++) for (int c = 0; c < C; c++) best[r, c] = -1;
    best[0, 0] = k;
    var q = new Queue<(int R, int C, int Left)>();
    q.Enqueue((0, 0, k));
    int[] dr = { 1, -1, 0, 0 }, dc = { 0, 0, 1, -1 };
    for (int steps = 0; q.Count > 0; steps++)
    {
        for (int cnt = q.Count; cnt > 0; cnt--)
        {
            var (r, c, left) = q.Dequeue();
            if (r == R - 1 && c == C - 1) return steps;
            for (int d = 0; d < 4; d++)
            {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
                int nl = left - grid[nr][nc];
                if (nl <= best[nr, nc]) continue;   // dominated (or out of breaks: nl = -1)
                best[nr, nc] = nl;
                q.Enqueue((nr, nc, nl));
            }
        }
    }
    return -1;
}

Time O(R · C · k) in the worst case, memory O(R · C · k) for the queue.

6. Shortest Path Visiting All Nodes Expert

Given an undirected connected graph with n ≤ 12 nodes, return the length of the shortest walk that visits every node. You may start and end anywhere, and revisit nodes and edges.

Key insight. Because revisiting is allowed, "where am I" is not enough: the state is (node, set of visited nodes), with the set stored as a bitmask. That gives n · 2ⁿ ≈ 49k states. All moves cost 1, so BFS over states finds the minimum. Since the start is free, use multi-source BFS from every (i, 1 << i) at distance 0. This problem combines three ideas from this page: implicit graphs, state design and multi-source BFS. It also opens the door to bitmask DP (DP: Bitmask & Digit).

Solution: multi-source BFS over (node, mask) 
from collections import deque

def shortest_path_length(graph):
    n = len(graph)
    full = (1 << n) - 1
    q = deque((i, 1 << i) for i in range(n))        # every start at distance 0
    seen = [[False] * (1 << n) for _ in range(n)]
    for i in range(n):
        seen[i][1 << i] = True
    steps = 0
    while q:
        for _ in range(len(q)):
            u, mask = q.popleft()
            if mask == full:
                return steps
            for v in graph[u]:
                nm = mask | (1 << v)
                if not seen[v][nm]:
                    seen[v][nm] = True
                    q.append((v, nm))
        steps += 1
    return -1

public int ShortestPathLength(int[][] graph)
{
    int n = graph.Length, full = (1 << n) - 1;
    var seen = new bool[n, 1 << n];
    var q = new Queue<(int Node, int Mask)>();
    for (int i = 0; i < n; i++) { seen[i, 1 << i] = true; q.Enqueue((i, 1 << i)); }  // every start at distance 0
    for (int steps = 0; q.Count > 0; steps++)
    {
        for (int cnt = q.Count; cnt > 0; cnt--)
        {
            var (u, mask) = q.Dequeue();
            if (mask == full) return steps;
            foreach (int v in graph[u])
            {
                int nm = mask | (1 << v);
                if (seen[v, nm]) continue;
                seen[v, nm] = true;
                q.Enqueue((v, nm));
            }
        }
    }
    return -1;
}

Time O(2ⁿ · n²), since each of the n · 2ⁿ states scans up to n neighbours. Memory O(n · 2ⁿ).

Self-check

Why does BFS find shortest paths (in edges) but DFS does not?

BFS's FIFO queue releases nodes in non-decreasing distance order: every distance-k node is dequeued before any distance-(k+1) node. So the first time a node is discovered, it is discovered from a node at the smallest possible distance, and that label is final. DFS discovers a node along whatever path it happens to be exploring, which may be a long detour. On the cycle 0–1–2–3–0, DFS from 0 can reach 3 through 1 and 2 (distance 3) although the edge 0–3 gives distance 1.

In a directed graph, why is "I reached an already-visited node" not proof of a cycle?

Two different paths can lead to the same node without forming a loop, as in the diamond 0→1→3 and 0→2→3. When the DFS explores 2→3, node 3 is already visited (BLACK, finished), but you cannot get from 3 back to 2. Only an edge into a GREY node, an ancestor that is still on the current recursion path, closes a cycle.

A connected undirected graph has V nodes and exactly V edges. How many cycles does it have?

Exactly one. A connected graph with V − 1 edges is a tree (no cycles). Adding one more edge u–v creates exactly one cycle: the tree path from u to v plus the new edge. This is why "redundant connection" style problems look for the edge that closes the cycle, usually with union-find.

You need the distance from every cell to its nearest gate, with k gates on an R×C grid. What is the cost of the obvious approach, and of the better one?

A BFS from each gate costs k · O(R·C), which is O((R·C)²) when gates are dense. A multi-source BFS seeded with all gates at distance 0 costs a single O(R·C). It is correct because it equals one BFS from a virtual super-source that is joined to every gate by a free edge, so the first wave to reach a cell comes from its nearest gate.

Can DFS on an undirected graph produce a forward or cross edge?

No, only tree and back edges. Suppose u–v were a cross edge, with v finished before u was discovered. While v was GREY, it would have examined the edge v–u and found u WHITE, making u a descendant of v through a tree edge. A forward edge is the same edge seen from the other end, and it was already examined as a back edge. This is why an undirected cycle check only has to ignore the parent edge.

Why is an adjacency matrix a bad idea for V = 10⁵ with E = 2·10⁵?

The matrix needs V² = 10¹⁰ cells (about 10 GB even as bits), and a traversal scans a full row per node, so O(V²) = 10¹⁰ steps. An adjacency list needs O(V + E) ≈ 3·10⁵ entries and the traversal costs the same. Use a matrix only for dense graphs or V up to a few thousand.

In Shortest Path to Get All Keys (up to 6 keys), what is the state, and how many states are there?

(r, c, keys_mask): there are R · C · 2⁶ = 64·R·C states. The same cell with different keys has different futures, since a door may or may not open. So the seen set must be over the full triple. Marking only (r, c) would forbid walking back through a corridor after collecting a key, which is often required.
