State Machines & DP Optimisations

Stock-trading state machines, DP on DAGs, and speed-ups: monotonic deque, convex hull trick, divide & conquer and Knuth.

Advanced → Expert~75 min studyBuilds on: Knapsack Family, Sequence & String DP, Monotonic Stack & QueueUpdated 2026-11-03

Where this page fits

By now you can write a correct DP for almost anything: The DP Framework gives you the recipe (state, transition, base cases, order, answer), Knapsack DP adds budgets, Sequence & String DP adds pairs of indices, and Interval & Tree DP adds ranges and subtrees. This page is about the two things that are still missing on "Hard" and "Expert" problems:

  1. States that are not positions. Sometimes "where am I in the array" is not enough. You also need "what mode am I in": holding a stock or not, swapped or not, on cooldown or not. That is a state machine unrolled over time. When the dependencies form an arbitrary acyclic graph instead of a line, it is DP on a DAG.
  2. Transitions that are too slow. The recurrence is right, but it scans all earlier states, which is O(n²) or O(n³) when the limits need O(n log n). The fix is never a new recurrence. It is a data structure or a structural fact that answers "best earlier state" faster: a monotonic deque, binary search, a segment tree, a set of lines (convex hull trick, Li Chao), or the fact that the optimal split point only moves one way (divide & conquer, Knuth).

Then there are three families that look like DP but need their own tricks: probability and expected value, counting modulo 10⁹+7 (including matrix exponentiation for n up to 10¹⁸), and games (minimax, Nim, Sprague-Grundy).

Optimising a DP never changes what you compute. It changes how fast you find the best earlier state. First write the slow recurrence and check it on small cases. Then look at the shape of the max/min inside it: a sliding window, a prefix over sorted keys, a min over lines, or a monotone split point. Each shape has exactly one standard speed-up.

The optimisation map

Every speed-up on this page starts from a recurrence written in a recognisable shape. Learn to read the shape, and the technique follows. Each row is taught in its own section below, with a visualizer that runs it.

State-machine DP

Many problems have a small set of modes, and the rules say which mode you may move to next. Index the DP by time and mode: dp[day][mode]. Each day you take every allowed edge out of every mode, and keep the best value per mode. That is a state machine "unrolled" into a grid, which people call a trellis.

The stock family is one machine

The six LeetCode stock problems (121, 122, 123, 188, 309, 714) look different, but they are all one machine with three kinds of edge: buy (pay the price), sell (receive the price), and wait. The variants only change which modes exist and what an edge costs:

def max_profit_k(prices, k):              # 188; k = 1 is 121, k = 2 is 123
    hold = [float("-inf")] * (k + 1)      # hold[t]: holding, t-th buy done
    sold = [0] + [float("-inf")] * k      # sold[t]: not holding, t trades done
    for p in prices:
        for t in range(k, 0, -1):         # read yesterday's values: go downward
            sold[t] = max(sold[t], hold[t] + p)
            hold[t] = max(hold[t], sold[t - 1] - p)
    return max(sold)

def max_profit_cooldown(prices):          # 309
    rest, hold, sold = 0, float("-inf"), float("-inf")
    for p in prices:
        rest, hold, sold = max(rest, sold), max(hold, rest - p), hold + p
    return max(rest, sold)

def max_profit_fee(prices, fee):          # 714; fee = 0 is 122
    cash, hold = 0, float("-inf")
    for p in prices:
        cash, hold = max(cash, hold + p - fee), max(hold, cash - p)
    return cash

public static int MaxProfitK(int k, int[] prices)       // 188; k = 1 is 121, k = 2 is 123
{
    const long NEG = long.MinValue / 4;
    var hold = new long[k + 1]; var sold = new long[k + 1];
    Array.Fill(hold, NEG); Array.Fill(sold, NEG); sold[0] = 0;
    foreach (int p in prices)
        for (int t = k; t >= 1; t--)                       // downward: read yesterday's sold[t-1]
        {
            sold[t] = Math.Max(sold[t], hold[t] + p);
            hold[t] = Math.Max(hold[t], sold[t - 1] - p);
        }
    return (int)sold.Max();
}

public static int MaxProfitCooldown(int[] prices)        // 309
{
    int rest = 0, hold = int.MinValue / 2, sold = int.MinValue / 2;
    foreach (int p in prices)
        (rest, hold, sold) = (Math.Max(rest, sold), Math.Max(hold, rest - p), hold + p);
    return Math.Max(rest, sold);
}

public static int MaxProfitFee(int[] prices, int fee)    // 714; fee = 0 is 122
{
    int cash = 0, hold = int.MinValue / 2;
    foreach (int p in prices)
        (cash, hold) = (Math.Max(cash, hold + p - fee), Math.Max(hold, cash - p));
    return cash;
}

All three run in O(n·modes) time and O(modes) space. For 188, when k ≥ n/2 the limit never binds, so you can fall back to the unlimited version and avoid an O(nk) loop with a huge k.

Why the tuple assignment matters. In rest, hold, sold = max(rest, sold), max(hold, rest - p), hold + p, every right-hand side reads yesterday's values. If you update one variable at a time, hold would read today's rest, and you would buy and sell on the same day through the cooldown. In the k-trade version the same goal is reached by looping t downward, exactly like the reverse loop in 0/1 knapsack: hold[t] reads sold[t−1], which has not been updated yet this day.

Recognise a state machine when the statement has phrases like "you may not … on the day after …", "at most k times", "you must … before you can …", "after a swap", or "while holding". Draw the modes as circles and the allowed moves as arrows before writing code. The DP is then one line per arrow.

The same pattern solves problems with no stocks at all. Minimum Swaps To Make Sequences Increasing has two modes per column (kept or swapped), and is worked in full below. Other examples are a string with "no three equal letters in a row" (the mode is the length of the current run) and Student Attendance Record II (the modes are absences used × current late streak, so 2 × 3 = 6 modes).

DP on a DAG

A DP is always a computation on a directed acyclic graph: the states are nodes, and "state u is used to compute state v" is an edge. On a line or a grid the order is obvious. When the dependencies are an arbitrary DAG (courses with prerequisites, tasks with dependencies, cells that may only step to larger values), you need an order in which every node comes after all its inputs. That order is a topological order, and Kahn's algorithm gives it to you while you fill the table.

Parallel Courses III is the cleanest example. Course v can start only when every prerequisite has finished, and courses run in parallel. So start[v] = max(finish[u]) over the prerequisites u, and finish[v] = start[v] + time[v]. The answer is the longest path in the DAG, weighted by node. Longest path is NP-hard in general graphs, but on a DAG it is one pass of DP.

from collections import deque

def minimum_time(n, relations, time):     # 2050
    adj = [[] for _ in range(n + 1)]; indeg = [0] * (n + 1)
    for u, v in relations: adj[u].append(v); indeg[v] += 1
    start = [0] * (n + 1)
    q = deque(v for v in range(1, n + 1) if indeg[v] == 0)
    best = 0
    while q:
        u = q.popleft()                   # every input of u is final now
        fin = start[u] + time[u - 1]; best = max(best, fin)
        for v in adj[u]:
            start[v] = max(start[v], fin) # relax: v cannot start before u ends
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    return best

public static int MinimumTime(int n, int[][] relations, int[] time)   // 2050
{
    var adj = new List<int>[n + 1]; var indeg = new int[n + 1];
    for (int v = 0; v <= n; v++) adj[v] = new List<int>();
    foreach (var r in relations) { adj[r[0]].Add(r[1]); indeg[r[1]]++; }
    var start = new int[n + 1]; var q = new Queue<int>();
    for (int v = 1; v <= n; v++) if (indeg[v] == 0) q.Enqueue(v);
    int best = 0;
    while (q.Count > 0)
    {
        int u = q.Dequeue(), fin = start[u] + time[u - 1];   // every input of u is final now
        best = Math.Max(best, fin);
        foreach (int v in adj[u])
        {
            start[v] = Math.Max(start[v], fin);                // v cannot start before u ends
            if (--indeg[v] == 0) q.Enqueue(v);
        }
    }
    return best;
}

O(V + E) time and space. The same skeleton gives Longest Increasing Path in a Matrix (edges go from smaller to larger cells, so the graph is a DAG for free), counting paths in a DAG (replace max by +), and Largest Color Value in a Directed Graph, where each node carries 26 counters and a leftover node after Kahn's pass means there is a cycle. That last one is worked on Interval & Tree DP.

Memoised DFS or Kahn? Both are fine on a DAG. Memoised DFS ("the answer for v is computed from its predecessors, recursively") is shorter to write but can overflow the recursion stack at 10⁵ nodes in Python. Kahn's queue is iterative, and it also detects cycles: if fewer than n nodes are popped, the input was not a DAG.

DP + monotonic deque

Here is the first speed-up. Suppose your recurrence is

dp[i] = a[i] + max(dp[j]) for j in the window [i − k, i − 1].

The direct loop costs O(k) per cell, so O(nk) in total. With n = k = 10⁵ that is 10¹⁰ operations, which is too slow. But the windows of neighbouring cells overlap in all but one element: going from i to i + 1, one state enters the window and one leaves. That is exactly the sliding window maximum problem from Monotonic Stack & Queue, with the twist that the values in the window are DP values you computed a moment ago.

The dominance argument. If j₁ < j₂ and dp[j₁] ≤ dp[j₂], then j₁ can never be the best choice again: j₂ is at least as good, and it stays in the window longer. So throw j₁ away. The survivors are in increasing order of index and decreasing order of value, which is a monotonic deque. The front is the best state in the window, and states leave from the front only when they get too old.

Two classic problems use this shape. In Jump Game VI you must land on the last index, and your score is the sum of the cells you land on: dp[i] = nums[i] + max(dp[i−k … i−1]). In Constrained Subsequence Sum you choose a non-empty subsequence in which neighbours are at most k apart, so you may also start fresh: dp[i] = nums[i] + max(0, max(dp[i−k … i−1])). Step through both with the selector, and watch the deque under the array.

from collections import deque

def max_result(nums, k):                  # Jump Game VI (1696)
    n = len(nums); dp = [0] * n; dp[0] = nums[0]
    dq = deque([0])                       # indices, dp values decreasing
    for i in range(1, n):
        while dq[0] < i - k: dq.popleft()           # too old to jump from
        dp[i] = nums[i] + dp[dq[0]]
        while dq and dp[dq[-1]] <= dp[i]: dq.pop()  # dominated by i
        dq.append(i)
    return dp[-1]

def constrained_subset_sum(nums, k):      # 1425
    dp, dq = [0] * len(nums), deque()
    for i, x in enumerate(nums):
        while dq and dq[0] < i - k: dq.popleft()
        dp[i] = x + max(0, dp[dq[0]] if dq else 0)  # 0 = start a new subsequence
        while dq and dp[dq[-1]] <= dp[i]: dq.pop()
        dq.append(i)
    return max(dp)

public static int MaxResult(int[] nums, int k)             // Jump Game VI (1696)
{
    int n = nums.Length; var dp = new int[n]; dp[0] = nums[0];
    var dq = new int[n]; int head = 0, tail = 0;           // dq[head..tail): indices, dp decreasing
    dq[tail++] = 0;
    for (int i = 1; i < n; i++)
    {
        while (dq[head] < i - k) head++;                   // too old to jump from
        dp[i] = nums[i] + dp[dq[head]];
        while (tail > head && dp[dq[tail - 1]] <= dp[i]) tail--;   // dominated by i
        dq[tail++] = i;
    }
    return dp[n - 1];
}

public static int ConstrainedSubsetSum(int[] nums, int k)  // 1425
{
    int n = nums.Length; var dp = new int[n];
    var dq = new int[n]; int head = 0, tail = 0;
    int best = int.MinValue;
    for (int i = 0; i < n; i++)
    {
        while (tail > head && dq[head] < i - k) head++;
        dp[i] = nums[i] + Math.Max(0, tail > head ? dp[dq[head]] : 0);   // 0 = start fresh
        while (tail > head && dp[dq[tail - 1]] <= dp[i]) tail--;
        dq[tail++] = i;
        best = Math.Max(best, dp[i]);
    }
    return best;
}

Both are O(n) time and O(n) space (O(k) for the deque). The C# version uses a plain array with two moving ends instead of LinkedList<int>, because each index is pushed at most once.

The general form. The deque works whenever the term inside the max splits into a part that depends only on j and a part that depends only on i, and the window's ends only move right: dp[i] = g(i) + max_{j ∈ [L(i), i−1]} h(j) with L(i) non-decreasing. Examples: Max Value of Equation (yᵢ + xᵢ + max(yⱼ − xⱼ) over xᵢ − xⱼ ≤ k), Delivering Boxes from Storage to Ports, and Shortest Subarray with Sum at Least K, which uses an increasing deque over prefix sums. If the term mixes i and j in a product, you need the convex hull trick instead.

DP + binary search

When the "best earlier state" is restricted by a key (a value smaller than mine, an end time before my start) rather than by a window, sort or bucket by the key and binary search for the boundary.

LIS in O(n log n): patience sorting

The slow LIS is dp[i] = 1 + max(dp[j] for j < i if a[j] < a[i]), which is O(n²). The fast version keeps a different table:

tails[L] = the smallest possible last element of an increasing subsequence of length L + 1 seen so far. A smaller tail is always better, because it can be extended by more future numbers. tails is strictly increasing, so for each new x you binary search the first tail ≥ x and replace it (or append if there is none).

Think of a card game. Each card goes on the leftmost pile whose top card is ≥ it, or starts a new pile on the right. The number of piles is the LIS length. The pile tops are exactly tails. To recover an actual subsequence (not only its length), give every card a back-pointer to the current top of the pile to its left. Following back-pointers from the top of the last pile spells out an LIS in reverse.

tails is not an LIS. After [3, 8, 4, 1] the tails are [1, 4], but 1, 4 is not a subsequence in that order, since 1 comes after 4. Only its length is meaningful. If you need the sequence, keep the back-pointers as in the code below. Also choose the bisect side on purpose: bisect_left for strictly increasing, bisect_right for non-decreasing (for example Minimum Operations to Make the Array K-Increasing).

Russian Doll Envelopes: 2D LIS with one sort

An envelope (w, h) fits in another only if both dimensions are strictly smaller. Sort by width, and the problem becomes an LIS on heights, with one catch: two envelopes with the same width must not both be chosen, yet an LIS on heights would happily take (3, 4) then (3, 5). The fix is one sort key: width ascending, height descending on ties. Within one width the heights then appear in decreasing order, so a strictly increasing subsequence can pick at most one of them. Switch the visualizer above to "Russian Doll Envelopes" to see it.

import bisect

def lis(a):                               # returns one longest strictly increasing subsequence
    tails, top, prev = [], [], [-1] * len(a)
    for i, x in enumerate(a):
        j = bisect.bisect_left(tails, x)      # bisect_right for non-decreasing
        prev[i] = top[j - 1] if j else -1     # back-pointer: top of the pile to the left
        if j == len(tails): tails.append(x); top.append(i)
        else: tails[j] = x; top[j] = i
    out, i = [], top[-1] if top else -1
    while i != -1: out.append(a[i]); i = prev[i]
    return out[::-1]

def max_envelopes(env):                   # 354
    env.sort(key=lambda e: (e[0], -e[1]))     # width up, height DOWN on ties
    tails = []
    for _, h in env:
        j = bisect.bisect_left(tails, h)
        if j == len(tails): tails.append(h)
        else: tails[j] = h
    return len(tails)

static int LowerBound(List<int> xs, int x)                // first index with xs[i] >= x
{
    int lo = 0, hi = xs.Count;
    while (lo < hi) { int mid = (lo + hi) / 2; if (xs[mid] < x) lo = mid + 1; else hi = mid; }
    return lo;
}

public static List<int> Lis(int[] a)
{
    var tails = new List<int>(); var top = new List<int>(); var prev = new int[a.Length];
    for (int i = 0; i < a.Length; i++)
    {
        int j = LowerBound(tails, a[i]);
        prev[i] = j > 0 ? top[j - 1] : -1;                // back-pointer: top of the pile to the left
        if (j == tails.Count) { tails.Add(a[i]); top.Add(i); }
        else { tails[j] = a[i]; top[j] = i; }
    }
    var res = new List<int>();
    for (int i = top.Count > 0 ? top[^1] : -1; i != -1; i = prev[i]) res.Add(a[i]);
    res.Reverse();
    return res;
}

public static int MaxEnvelopes(int[][] env)               // 354
{
    Array.Sort(env, (p, q) => p[0] != q[0] ? p[0].CompareTo(q[0]) : q[1].CompareTo(p[1]));
    var tails = new List<int>();
    foreach (var e in env)
    {
        int j = LowerBound(tails, e[1]);
        if (j == tails.Count) tails.Add(e[1]); else tails[j] = e[1];
    }
    return tails.Count;
}

O(n log n) time, O(n) space. In C#, avoid List<T>.BinarySearch here: with duplicates it returns some matching index, not the first one, so it is not a lower bound.

Weighted interval scheduling: sort by end, bisect for the past

Maximum Profit in Job Scheduling gives jobs (start, end, profit). Choose non-overlapping jobs with maximum total profit (a job may start exactly when another ends). Sort by end time. Then dp[i], the best profit using only the first i jobs, has two choices for job i:

  • skip it: dp[i − 1];
  • take it: profit[i] + dp[k], where k is the number of earlier jobs that end at or before start[i]. Because the jobs are sorted by end, those jobs form a prefix, and k = bisect_right(ends, start[i]).

That is "knapsack where the budget is time", and the binary search replaces a backwards scan. The visualizer draws the jobs as bars on a timeline, highlights the compatible prefix found by bisect, and shows which choice wins.

The full solution is worked problem 2.

DP + segment tree or Fenwick tree

Binary search works when the useful earlier states form a prefix of something sorted. When the query is "best dp among earlier states whose value lies in a range [lo, hi]", index a segment tree by value and let it answer range-max queries in O(log V).

Longest Increasing Subsequence II asks for the longest strictly increasing subsequence in which neighbours differ by at most k. Patience sorting cannot express "at most k", but a DP over values can:

best[x] = 1 + max(best[v] for v in [x − k, x − 1]), processed in array order.

best[v] is "the longest valid subsequence seen so far that ends with value v". The range max is a segment tree query; writing back best[x] is a point update. The visualizer shows the tree over values 1..16, the query range lighting up, and the nodes the query touches.

def length_of_lis_k(nums, k):             # 2407
    size = 1
    while size < max(nums) + 1: size *= 2
    tree = [0] * (2 * size)               # iterative segment tree over values, range max
    def query(lo, hi):                    # max over values [lo, hi]
        res, lo, hi = 0, lo + size, hi + size + 1
        while lo < hi:
            if lo & 1: res = max(res, tree[lo]); lo += 1
            if hi & 1: hi -= 1; res = max(res, tree[hi])
            lo //= 2; hi //= 2
        return res
    def update(i, v):
        i += size; tree[i] = max(tree[i], v)
        while i > 1:
            i //= 2; tree[i] = max(tree[2 * i], tree[2 * i + 1])
    for x in nums:
        update(x, query(max(0, x - k), x - 1) + 1)
    return tree[1]

public static int LengthOfLIS(int[] nums, int k)          // 2407
{
    int size = 1;
    while (size < nums.Max() + 1) size *= 2;
    var tree = new int[2 * size];                         // iterative segment tree over values, range max
    int Query(int lo, int hi)                             // max over values [lo, hi]
    {
        int res = 0;
        for (lo += size, hi += size + 1; lo < hi; lo /= 2, hi /= 2)
        {
            if ((lo & 1) == 1) res = Math.Max(res, tree[lo++]);
            if ((hi & 1) == 1) res = Math.Max(res, tree[--hi]);
        }
        return res;
    }
    void Update(int i, int v)
    {
        i += size; tree[i] = Math.Max(tree[i], v);
        for (i /= 2; i >= 1; i /= 2) tree[i] = Math.Max(tree[2 * i], tree[2 * i + 1]);
    }
    foreach (int x in nums) Update(x, Query(Math.Max(0, x - k), x - 1) + 1);
    return tree[1];
}

O(n log V) time and O(V) space. If the values are large (up to 10⁹), coordinate-compress them first (sort the distinct values and replace each value by its rank). When the query range is always a prefix [0, x − 1], a Fenwick tree with "prefix max" is shorter. When you need counts (for example, the number of longest increasing subsequences), store a (length, count) pair per node and merge pairs instead of taking a max.

Convex hull trick and Li Chao tree

When the term mixes i and j

Now the hard case. Frog 3 from the AtCoder Educational DP contest: stones have strictly increasing heights h. The frog jumps from stone j to any later stone i at a cost of (h[i] − h[j])² + C. Find the minimum cost to reach the last stone.

dp[i] = min over j < i of dp[j] + (h[i] − h[j])² + C

The term (h[i] − h[j])² mixes i and j, so a deque of "best dp[j]" does not help: which j is best depends on h[i]. Expand the square and group by who owns each piece:

dp[i] = h[i]² + C + min over j of ( (−2·h[j]) · h[i] + (dp[j] + h[j]²) )

The part in the min is a line in the variable x = h[i], with slope m_j = −2·h[j] and intercept b_j = dp[j] + h[j]², both known as soon as dp[j] is final. So every finished state j contributes one line, and every new state i asks one question: which line is lowest at x = h[i]? The lowest line at each x forms the lower envelope, a convex chain. A line that is never on the envelope is never the answer and can be thrown away.

The monotone case: a deque of lines

In Frog 3 two things are monotone: lines are added in order of decreasing slope (heights increase, so −2·h[j] decreases), and queries come in increasing x (h[i] increases). Then the envelope can be kept in a deque, just like the sliding-window max, but with two different pop rules:

  • Pop from the front while the second line is at least as low as the first at the current x. Queries only move right, so once the front line loses it loses forever.
  • Pop from the back before adding line ℓ₃ while the last line ℓ₂ is never strictly lowest between ℓ₁ and ℓ₃. That is the case when ℓ₃ overtakes ℓ₁ no later than ℓ₂ does. Compare the two intersection x-coordinates by cross-multiplying, never by dividing (floating point would misjudge near-ties):

(b₃ − b₁)·(m₁ − m₂) ≤ (b₂ − b₁)·(m₁ − m₃) → pop ℓ₂.

Each line is pushed and popped once, so the DP is O(n) after sorting. Step through it: the plot shows the lines, the envelope, the current query, and which lines leave the deque and why.

from collections import deque

def frog3(h, C):                          # AtCoder DP Z; h strictly increasing
    n = len(h); dp = [0] * n
    m = lambda j: -2 * h[j]               # slope of line j
    b = lambda j: dp[j] + h[j] * h[j]     # intercept of line j
    val = lambda j, x: m(j) * x + b(j)
    def bad(j1, j2, j3):                  # j2 never strictly lowest
        return (b(j3) - b(j1)) * (m(j1) - m(j2)) <= (b(j2) - b(j1)) * (m(j1) - m(j3))
    dq = deque([0])
    for i in range(1, n):
        x = h[i]
        while len(dq) >= 2 and val(dq[1], x) <= val(dq[0], x): dq.popleft()
        dp[i] = val(dq[0], x) + x * x + C
        while len(dq) >= 2 and bad(dq[-2], dq[-1], i): dq.pop()
        dq.append(i)
    return dp[-1]

public static long Frog3(long[] h, long C)                // AtCoder DP Z; h strictly increasing
{
    int n = h.Length; var dp = new long[n];
    long M(int j) => -2 * h[j];                           // slope of line j
    long B(int j) => dp[j] + h[j] * h[j];                 // intercept of line j
    long Val(int j, long x) => M(j) * x + B(j);
    bool Bad(int j1, int j2, int j3) =>                   // Int128: the products overflow long
        (Int128)(B(j3) - B(j1)) * (M(j1) - M(j2)) <= (Int128)(B(j2) - B(j1)) * (M(j1) - M(j3));
    var dq = new int[n]; int head = 0, tail = 0; dq[tail++] = 0;
    for (int i = 1; i < n; i++)
    {
        long x = h[i];
        while (tail - head >= 2 && Val(dq[head + 1], x) <= Val(dq[head], x)) head++;
        dp[i] = Val(dq[head], x) + x * x + C;
        while (tail - head >= 2 && Bad(dq[tail - 2], dq[tail - 1], i)) tail--;
        dq[tail++] = i;
    }
    return dp[n - 1];
}

Overflow in the cross-multiplication. With heights up to 10⁶ and C up to 10¹², intercepts reach about 10¹³ and slope differences about 10⁶, so the products are around 10¹⁹, which is past long.MaxValue (≈ 9.2·10¹⁸). Python's integers are unbounded and do not care. In C#, use Int128 (as above), decimal, or compare the intersections with double only when you can prove the values are small. In Java there is no 128-bit type, so people use Math.multiplyHigh or BigInteger.

Li Chao tree: lines and queries in any order

If slopes arrive in arbitrary order, or queries jump around, the deque's pop rules break. A Li Chao tree is a segment tree over the x-range in which each node stores one line: the one that is lowest at the node's midpoint among those that reached it. To insert a new line at a node:

  1. Compare the new line with the stored one at mid. Keep the winner in the node; the loser carries on down.
  2. Two lines cross at most once. So the loser can still win on only one side of mid: the side where it is lower at that side's end. Send it to that child only.

A query walks from the root to the leaf for x and takes the min of the lines it passes. Both operations are O(log X), where X is the size of the x-range. Lines can also be inserted over a sub-range (a "segment"), at O(log² X).

class LiChao:
    """Min of lines y = m*x + b over integer x in [lo, hi]."""
    def __init__(self, lo, hi):
        self.lo, self.hi, self.line = lo, hi, {}      # node id -> (m, b); children 2v, 2v+1
    def add(self, m, b):
        node, l, r, new = 1, self.lo, self.hi, (m, b)
        f = lambda ln, x: ln[0] * x + ln[1]
        while True:
            cur = self.line.get(node)
            if cur is None: self.line[node] = new; return
            mid = (l + r) // 2
            left_better = f(new, l) < f(cur, l)
            mid_better = f(new, mid) < f(cur, mid)
            if mid_better: self.line[node], new = new, cur   # winner at mid stays
            if l == r: return
            if left_better != mid_better: node, r = 2 * node, mid     # loser can win only on the left
            else: node, l = 2 * node + 1, mid + 1                     # ... or only on the right
    def query(self, x):
        node, l, r, best = 1, self.lo, self.hi, float("inf")
        while node in self.line:
            m, b = self.line[node]; best = min(best, m * x + b)
            if l == r: break
            mid = (l + r) // 2
            if x <= mid: node, r = 2 * node, mid
            else: node, l = 2 * node + 1, mid + 1
        return best

public sealed class LiChao                                 // min of lines over integer x in [lo, hi]
{
    readonly long lo, hi;
    readonly Dictionary<long, (long m, long b)> line = new();   // node id -> line; children 2v, 2v+1
    public LiChao(long lo, long hi) { this.lo = lo; this.hi = hi; }
    static long F((long m, long b) ln, long x) => ln.m * x + ln.b;
    public void Add(long m, long b)
    {
        long node = 1, l = lo, r = hi; var nw = (m, b);
        while (true)
        {
            if (!line.TryGetValue(node, out var cur)) { line[node] = nw; return; }
            long mid = (long)Math.Floor((l + r) / 2.0);        // floor, also for negative ranges
            bool leftBetter = F(nw, l) < F(cur, l), midBetter = F(nw, mid) < F(cur, mid);
            if (midBetter) { line[node] = nw; nw = cur; }      // winner at mid stays
            if (l == r) return;
            if (leftBetter != midBetter) { node = 2 * node; r = mid; }
            else { node = 2 * node + 1; l = mid + 1; }
        }
    }
    public long Query(long x)
    {
        long node = 1, l = lo, r = hi, best = long.MaxValue;
        while (line.TryGetValue(node, out var ln))
        {
            best = Math.Min(best, F(ln, x));
            if (l == r) break;
            long mid = (long)Math.Floor((l + r) / 2.0);
            if (x <= mid) { node = 2 * node; r = mid; } else { node = 2 * node + 1; l = mid + 1; }
        }
        return best;
    }
}

For max instead of min, insert (−m, −b) and negate the answer. A dictionary keeps memory proportional to the lines inserted. With a small dense range, use arrays of size 4X instead.

Which one to use? Slopes sorted and queries sorted: the deque, O(n). Slopes sorted, queries arbitrary: keep the envelope in an array and binary search the query, O(log n). Anything else, or lines that are only valid on a segment: Li Chao. Li Chao is also the easiest to get right under time pressure, because there is no intersection formula to get wrong.

Divide & conquer optimisation, and Knuth at a glance

Splitting an array into K groups

Many "partition into K pieces" problems have the layered recurrence

dp[t][i] = min over j < i of dp[t − 1][j] + C(j, i)

where C(j, i) is the cost of making a[j..i−1] one group. Done directly this is O(K·n²). Now suppose the optimal split point is monotone: opt(i) ≤ opt(i + 1) (a longer prefix never wants its last group to start earlier). Then compute the middle i first by scanning all candidate j, and recurse: the left half only needs j up to opt(mid), and the right half only j from opt(mid). Each recursion level scans O(n) candidates in total, and there are O(log n) levels, so each layer costs O(n log n).

The visualizer uses C(j, i) = (sum of the group)² on positive numbers, which rewards balanced groups. Watch the candidate range shrink as the recursion goes deeper, and compare the evaluation count with the n² of the naive scan.

def min_partition_cost(a, K):             # split a into K groups, cost = sum of (group sum)^2
    n = len(a); pre = [0]
    for x in a: pre.append(pre[-1] + x)
    cost = lambda j, i: (pre[i] - pre[j]) ** 2
    INF = float("inf")
    prev = [0] + [INF] * n                # layer t - 1
    for t in range(1, K + 1):
        cur = [INF] * (n + 1)
        def solve(lo, hi, opt_lo, opt_hi):
            if lo > hi: return
            mid = (lo + hi) // 2
            best, opt = INF, opt_lo
            for j in range(opt_lo, min(opt_hi, mid - 1) + 1):
                v = prev[j] + cost(j, mid)
                if v < best: best, opt = v, j
            cur[mid] = best
            solve(lo, mid - 1, opt_lo, opt)   # left half: split points <= opt
            solve(mid + 1, hi, opt, opt_hi)   # right half: split points >= opt
        solve(t, n, t - 1, n - 1)
        prev = cur
    return prev[n]

public static long MinPartitionCost(int[] a, int K)       // split into K groups, cost = sum of (group sum)^2
{
    int n = a.Length; var pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
    long Cost(int j, int i) => (pre[i] - pre[j]) * (pre[i] - pre[j]);
    const long INF = long.MaxValue / 4;
    var prev = new long[n + 1]; Array.Fill(prev, INF); prev[0] = 0;
    for (int t = 1; t <= K; t++)
    {
        var cur = new long[n + 1]; Array.Fill(cur, INF);
        void Solve(int lo, int hi, int optLo, int optHi)
        {
            if (lo > hi) return;
            int mid = (lo + hi) / 2, opt = optLo; long best = INF;
            for (int j = optLo; j <= Math.Min(optHi, mid - 1); j++)
            {
                long v = prev[j] + Cost(j, mid);
                if (v < best) { best = v; opt = j; }
            }
            cur[mid] = best;
            Solve(lo, mid - 1, optLo, opt);               // left half: split points <= opt
            Solve(mid + 1, hi, opt, optHi);               // right half: split points >= opt
        }
        Solve(t, n, t - 1, n - 1);
        prev = cur;
    }
    return prev[n];
}

When is opt monotone? A sufficient condition is the quadrangle inequality on the cost: for a ≤ b ≤ c ≤ d,

C(a, c) + C(b, d) ≤ C(a, d) + C(b, c)

In words: two overlapping ranges cost no more than the outer range plus the inner one. Squared sums of non-negative numbers satisfy it, and so does "distance of houses to their median mailbox" (worked problem 6). In an interview or contest, the practical test is just as good: run the slow DP on random small inputs, record opt, and assert that it never decreases.

Knuth's optimisation (interval DP)

For interval DP of the form dp[i][j] = min over i ≤ k < j of dp[i][k] + dp[k+1][j] + C(i, j) (merge stones, optimal BST, cutting a stick), Knuth's observation is that when C satisfies the quadrangle inequality and is monotone on nested intervals (C(b, c) ≤ C(a, d) for [b, c] ⊆ [a, d]), the best split satisfies

opt[i][j − 1] ≤ opt[i][j] ≤ opt[i + 1][j]

Proof sketch of the speed-up: for a fixed interval length, the scan for (i, j) costs opt[i+1][j] − opt[i][j−1] + 1. Summed over all i, the middle terms cancel (a telescoping sum), leaving at most n plus O(n). So each length costs O(n), and all lengths cost O(n²) instead of O(n³). The monotonicity itself comes from showing that dp inherits the quadrangle inequality from C, by induction on the interval length. Interval & Tree DP has a visualizer that shades the narrowed k range cell by cell. Here is the template for merging adjacent piles, where merging costs the total size:

def merge_piles(a):                       # min cost to merge adjacent piles into one, O(n^2)
    n = len(a); pre = [0]
    for x in a: pre.append(pre[-1] + x)
    dp = [[0] * n for _ in range(n)]
    opt = [[i] * n for i in range(n)]     # opt[i][i] = i
    for d in range(1, n):
        for i in range(n - d):
            j = i + d; best = float("inf")
            for k in range(opt[i][j - 1], min(opt[i + 1][j], j - 1) + 1):   # Knuth's window
                v = dp[i][k] + dp[k + 1][j]
                if v < best: best, opt[i][j] = v, k
            dp[i][j] = best + pre[j + 1] - pre[i]
    return dp[0][n - 1]

public static long MergePiles(int[] a)                    // min cost to merge adjacent piles, O(n^2)
{
    int n = a.Length; var pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
    var dp = new long[n, n]; var opt = new int[n, n];
    for (int i = 0; i < n; i++) opt[i, i] = i;
    for (int d = 1; d < n; d++)
        for (int i = 0; i + d < n; i++)
        {
            int j = i + d; long best = long.MaxValue;
            for (int k = opt[i, j - 1]; k <= Math.Min(opt[i + 1, j], j - 1); k++)   // Knuth's window
            {
                long v = dp[i, k] + dp[k + 1, j];
                if (v < best) { best = v; opt[i, j] = k; }
            }
            dp[i, j] = best + pre[j + 1] - pre[i];
        }
    return dp[0, n - 1];
}

Divide & conquer: O(K·n log n)

  • Layered: dp[t][·] from dp[t−1][·].
  • Needs opt(i) ≤ opt(i+1) within a layer.
  • O(K · n log n). Works even when you can only evaluate C(j, i) in O(1) via prefix sums.
  • Typical: split into K groups, K mailboxes, K servers.

Knuth: O(n²)

  • Interval: dp[i][j] from shorter intervals.
  • Needs opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j].
  • O(n²) instead of O(n³).
  • Typical: merge adjacent piles, optimal BST, cutting a stick at given points.

Probability and expected-value DP

Probability DP has the same skeleton as counting DP, with one change: every transition is weighted by its probability, and the weights out of a state sum to 1. You can run it in two directions:

  • Push (forward): keep a distribution over states, the "probability mass", and move it one step at a time. This is natural when the start is fixed and you want the distribution after k steps.
  • Pull (backward): f(state) = Σ p(move) · f(next state), with terminal states as the base case. This is natural for "probability of eventually …" and for expected values, where E(state) = cost + Σ p · E(next). Linearity of expectation is what makes this work: the expected total is the sum of the expected parts, even when the parts are dependent.

Knight Probability: push the mass forward

Knight Probability in Chessboard: a knight makes k uniformly random moves on an n × n board. What is the probability that it is still on the board? Start with mass 1 on the start cell. At each step every cell sends 1/8 of its mass to each of its 8 targets; mass that lands off the board is lost for good. The answer is the mass left after k steps. The heatmap shows where the mass is, and the bar shows how much has fallen off.

def knight_probability(n, k, row, col):   # 688
    moves = [(1, 2), (2, 1), (2, -1), (1, -2), (-1, -2), (-2, -1), (-2, 1), (-1, 2)]
    cur = [[0.0] * n for _ in range(n)]; cur[row][col] = 1.0
    for _ in range(k):
        nxt = [[0.0] * n for _ in range(n)]
        for x in range(n):
            for y in range(n):
                if cur[x][y]:
                    for dx, dy in moves:
                        a, b = x + dx, y + dy
                        if 0 <= a < n and 0 <= b < n: nxt[a][b] += cur[x][y] / 8
        cur = nxt                         # mass that left the board is simply not copied
    return sum(map(sum, cur))

public static double KnightProbability(int n, int k, int row, int col)   // 688
{
    int[] dx = { 1, 2, 2, 1, -1, -2, -2, -1 }, dy = { 2, 1, -1, -2, -2, -1, 1, 2 };
    var cur = new double[n, n]; cur[row, col] = 1;
    for (int step = 0; step < k; step++)
    {
        var nxt = new double[n, n];
        for (int x = 0; x < n; x++)
            for (int y = 0; y < n; y++)
            {
                if (cur[x, y] == 0) continue;
                for (int d = 0; d < 8; d++)
                {
                    int a = x + dx[d], b = y + dy[d];
                    if (a >= 0 && a < n && b >= 0 && b < n) nxt[a, b] += cur[x, y] / 8;
                }
            }
        cur = nxt;                                         // off-board mass is not copied
    }
    double sum = 0; foreach (double p in cur) sum += p;
    return sum;
}

O(k·n²·8) time and O(n²) space. Note that probabilities, not counts, are stored: the count of surviving paths is up to 8ᵏ, which overflows for k = 100, while probabilities stay in [0, 1].

New 21 Game: an average over a sliding window

New 21 Game: Alice starts at 0 points and draws a uniform number from 1..W while she has fewer than k points. What is the probability that she ends with at most n points? Let dp[x] be the probability that she is ever at exactly x points. She reaches x from any x − w (w = 1..W) at which she was still drawing, that is x − w < k:

dp[x] = (1/W) · Σ dp[x − w] over w = 1..W with 0 ≤ x − w < k

That is the average of a sliding window of the last W values. So keep a running window sum, add dp[x] when x < k (she will draw again from x), and drop dp[x − W] as it leaves the window. That turns O(n·W) into O(n). The answer is the sum of dp[x] for k ≤ x ≤ n. The window is the same idea as the deque section, but for sums you need no deque at all.

def new21_game(n, k, maxPts):             # 837
    if k == 0 or n >= k - 1 + maxPts: return 1.0   # she can never pass n
    dp = [0.0] * (n + 1); dp[0] = 1.0
    window, ans = 1.0, 0.0                # window = sum of dp[x-W .. x-1] restricted to x' < k
    for x in range(1, n + 1):
        dp[x] = window / maxPts
        if x < k: window += dp[x]         # she draws again from x
        else: ans += dp[x]                # she stops at x (k <= x <= n)
        if x - maxPts >= 0: window -= dp[x - maxPts]
    return ans

public static double New21Game(int n, int k, int maxPts)   // 837
{
    if (k == 0 || n >= k - 1 + maxPts) return 1.0;          // she can never pass n
    var dp = new double[n + 1]; dp[0] = 1;
    double window = 1, ans = 0;
    for (int x = 1; x <= n; x++)
    {
        dp[x] = window / maxPts;
        if (x < k) window += dp[x]; else ans += dp[x];     // draw again, or stop here
        if (x - maxPts >= 0) window -= dp[x - maxPts];
    }
    return ans;
}

The subtle bug: adding stopped states to the window. Once she reaches k she stops, so dp[x] for x ≥ k must not feed later cells. If you write window += dp[x] unconditionally, you count paths that keep drawing after stopping, and the answer is too large. The early return also matters: when k = 0 she never draws, and when n ≥ k − 1 + W even the worst final total (k − 1 + W) is within n.

Soup Servings: memoise, then notice the limit

Soup Servings gives you n ml each of soups A and B and four equally likely servings: (100, 0), (75, 25), (50, 50), (25, 75). Return P(A empties first) + ½·P(both empty at the same time). Two observations make it easy:

  1. Every amount is a multiple of 25, so work in units of 25 ml: m = ceil(n / 25) and the servings are (4, 0), (3, 1), (2, 2), (1, 3). The state is (a, b), and the pull recurrence is the average of four memoised states.
  2. On average A loses 2.5 units per serving and B only 1.5, so A almost surely empties first when n is large. The answer goes to 1 quickly: past about n = 4800 it is within 10⁻⁶ of 1, which is the tolerance the problem allows. Return 1 immediately there. Without this cutoff, n = 10⁹ gives a table with 10¹⁴ cells.

The full solution is worked problem 7.

Expected value in one line. "Expected number of rolls to see a 6" is E = 1 + (5/6)·E, so E = 6. Every expected-value DP is a system like this. When the state graph is a DAG (the process always moves forward), solve it in reverse topological order. When a state can loop back to itself, as here, move the self-term to the left: E(s) = (1 + Σ_{t≠s} p_t E(t)) / (1 − p_s). Only general cycles need Gaussian elimination.

Counting DP modulo 10⁹ + 7

When a problem says "return the answer modulo 10⁹ + 7", the true count is astronomically large, and the DP is a counting DP: sums of products instead of max/min. Three rules keep it correct:

  • Reduce after every addition and multiplication. (a + b) % M and (a * b) % M. In C#, long holds a product of two values below M (about 10¹⁸ < 9.2·10¹⁸), but not three: reduce between multiplications.
  • Subtraction needs a fix-up: ((a − b) % M + M) % M in C# and Java, where % can return a negative number. Python's % is already non-negative.
  • Never divide. Division mod p is multiplication by a modular inverse. Why 10⁹ + 7 is prime, and how the inverse works, is on Math, Number Theory & Combinatorics.

Number of Music Playlists: count by "how many distinct so far"

Number of Music Playlists: n songs, a playlist of goal slots, every song played at least once, and a song may be replayed only if k other songs have played since. The state that makes the count work is dp[i][j]: playlists of length i that use exactly j distinct songs. The last slot is either a new song (any of the n − (j−1) unused ones) or a replay (any of the j used songs except the k most recent, which are all distinct). It is worked problem 3.

Count Vowels Permutation: counting walks in a state machine

Count Vowels Permutation defines which vowel may follow which. That is a state machine again, and the number of strings of length n is the number of walks of length n − 1 in this graph:

def count_vowel_permutation(n):           # 1220
    a = e = i = o = u = 1                 # strings of length 1 ending in each vowel
    for _ in range(n - 1):
        a, e, i, o, u = (e + i + u) % MOD, (a + i) % MOD, (e + o) % MOD, i % MOD, (i + o) % MOD

Domino and Tromino Tiling: a second state for "ragged edges"

Domino and Tromino Tiling counts tilings of a 2 × n board with dominoes and L-trominoes. Counting only full boards is not enough, because a tromino leaves a ragged edge with one cell sticking out. So add a second state, the same move as adding a mode to a state machine:

  • full[i]: tilings of a 2 × i board.
  • part[i]: tilings of a 2 × (i − 1) board plus one cell of column i (one orientation; the mirror image has the same count).
def num_tilings(n):                       # 790
    full, part = [1, 1] + [0] * n, [0, 0] + [0] * n
    for i in range(2, n + 1):
        full[i] = (full[i - 1] + full[i - 2] + 2 * part[i - 1]) % MOD
        part[i] = (part[i - 1] + full[i - 2]) % MOD
    return full[n]

public static int NumTilings(int n)                       // 790
{
    var full = new long[n + 2]; var part = new long[n + 2];
    full[0] = full[1] = 1;
    for (int i = 2; i <= n; i++)
    {
        full[i] = (full[i - 1] + full[i - 2] + 2 * part[i - 1]) % MOD;
        part[i] = (part[i - 1] + full[i - 2]) % MOD;
    }
    return (int)full[n];
}

Substituting part away gives the famous one-liner full[i] = 2·full[i−1] + full[i−3]. It is neat, but the two-state version is the one you can derive under pressure. Both are O(n). I checked them against a brute-force column-by-column tiler for n ≤ 10.

Matrix exponentiation

Every recurrence in the last section is linear: the new state vector is a fixed matrix times the old one. Fibonacci is the simplest case:

[F(n+1), F(n)]ᵀ = [[1, 1], [1, 0]] · [F(n), F(n−1)]ᵀ, so [[1, 1], [1, 0]]ⁿ = [[F(n+1), F(n)], [F(n), F(n−1)]].

Applying the matrix n times is O(n). But matrix multiplication is associative, so you can compute Mⁿ by repeated squaring, exactly like fast power for numbers: write n in binary, square M once per bit, and multiply the squares whose bit is 1 into the result.

The visualizer runs it on Fibonacci (exact and mod 10⁹+7 for n up to 10¹⁸) and on Tribonacci with a 3 × 3 matrix. It shows the bits of n, the running square, and the result matrix after each bit.

MOD = 10**9 + 7

def mat_mul(A, B, mod=MOD):
    return [[sum(A[i][t] * B[t][j] for t in range(len(B))) % mod
             for j in range(len(B[0]))] for i in range(len(A))]

def mat_pow(M, e, mod=MOD):
    R = [[int(i == j) for j in range(len(M))] for i in range(len(M))]   # identity
    while e:
        if e & 1: R = mat_mul(R, M, mod)  # this bit is set: use the current square
        M = mat_mul(M, M, mod)            # next square
        e >>= 1
    return R

def fib(n, mod=MOD):
    return mat_pow([[1, 1], [1, 0]], n, mod)[0][1]

public static long[,] MatMul(long[,] A, long[,] B)
{
    int n = A.GetLength(0), m = B.GetLength(1), inner = B.GetLength(0);
    var C = new long[n, m];
    for (int i = 0; i < n; i++)
        for (int t = 0; t < inner; t++)
        {
            if (A[i, t] == 0) continue;
            for (int j = 0; j < m; j++) C[i, j] = (C[i, j] + A[i, t] * B[t, j]) % MOD;   // reduce every product
        }
    return C;
}

public static long[,] MatPow(long[,] M, long e)
{
    int n = M.GetLength(0); var R = new long[n, n];
    for (int i = 0; i < n; i++) R[i, i] = 1;              // identity
    for (; e > 0; e >>= 1)
    {
        if ((e & 1) == 1) R = MatMul(R, M);               // this bit is set: use the current square
        M = MatMul(M, M);                                 // next square
    }
    return R;
}

public static long Fib(long n) => MatPow(new long[,] { { 1, 1 }, { 1, 0 } }, n)[0, 1];

O(k³ log n) for a k × k matrix. Checks: fib(10**18) = 209783453, and the Vowel Permutation count with the 5 × 5 follow matrix matches the loop above for every n up to 30.

Use matrix power when the transition is linear with constant coefficients, the state is small (k ≤ about 100), and n is huge (10⁹ to 10¹⁸). Typical signs: "number of strings/tilings/walks of length n" with n ≥ 10⁹, or "the n-th term of a recurrence". Building the matrix: row r of the matrix lists how many ways each old state contributes to new state r. For counting walks, the matrix is just the adjacency matrix of the state machine, and Mⁿ[u][v] is the number of walks of length n from u to v.

Game theory DP

Two players alternate moves, both play perfectly, and you must predict the result. Three ideas cover almost every interview and contest game.

Minimax as a score difference

The textbook minimax alternates max levels and min levels. For zero-sum games there is a much simpler form: let d(state) be (my score − opponent's score) from now on, for the player about to move. After I move, my opponent is "the player about to move", so their advantage counts against me:

d(state) = max over moves of ( gain(move) − d(next state) )

One function, no turn flag, and no separate tables for the two players. In Predict the Winner players take a number from either end of the array, and the state is the remaining interval [i, j]:

def predict_the_winner(nums):             # 486
    n = len(nums); d = nums[:]            # length-1 intervals: d[i] = nums[i]
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            d[i] = max(nums[i] - d[i + 1], nums[j] - d[i])   # d[i+1] is [i+1, j]; old d[i] is [i, j-1]
    return d[0] >= 0                      # a tie counts as a win for player 1

public static bool PredictTheWinner(int[] nums)           // 486
{
    int n = nums.Length; var d = (int[])nums.Clone();     // length-1 intervals: d[i] = nums[i]
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++)
        {
            int j = i + len - 1;
            d[i] = Math.Max(nums[i] - d[i + 1], nums[j] - d[i]);   // d[i+1] is [i+1, j]; old d[i] is [i, j-1]
        }
    return d[0] >= 0;                                     // a tie counts as a win for player 1
}

O(n²) time, O(n) space, by rolling the interval table into one row ordered by length. Stone Game (877) is the same DP, but with an even number of piles the first player can always win: colour the piles alternately, so that the even-indexed and odd-indexed piles each form one colour. The first player can take every pile of whichever colour has the larger total, so the function can just return True. Prove that to yourself once; it is a classic "think before you code" problem. Linear games, where you take 1 to 3 stones from the front (Stone Game III), use the same difference trick on suffixes. That is worked problem 5.

Win/lose states, Nim, and Sprague-Grundy

When there is no score, only "who makes the last move wins", every state is either winning or losing for the player to move:

  • A state is losing if every move leads to a winning state (including "there is no move").
  • A state is winning if some move leads to a losing state.

That is a boolean DP over states, computed from the terminal states up. With many independent piles, though, the state space is the product of the piles, which is far too big. Nim is the key: with piles p₁, …, pₖ where a move removes any positive amount from one pile, the first player wins if and only if p₁ ⊕ p₂ ⊕ … ⊕ pₖ ≠ 0. Why: from XOR 0, any move changes exactly one pile and so makes the XOR non-zero. From XOR X ≠ 0, pick a pile whose binary form has X's top bit set; replacing it by p ⊕ X (which is smaller) brings the XOR back to 0. So the player facing XOR 0 is stuck there until all piles are empty.

Sprague-Grundy extends this to any impartial game, where both players have the same moves: give every state a number, its Grundy value:

g(state) = mex { g(next) : next reachable in one move }

where mex is the smallest non-negative integer not in the set. A state is losing exactly when g = 0, and a state with Grundy value g behaves exactly like a Nim pile of size g. So a sum of independent games is won by the first player iff the XOR of their Grundy values is non-zero. The visualizer computes g for a subtraction game (you may remove only amounts in S) and judges a multi-pile position.

def grundy_table(N, moves):               # subtraction game: remove s in moves from a pile
    g = [0] * (N + 1)
    for x in range(1, N + 1):
        reach = {g[x - s] for s in moves if s <= x}
        m = 0
        while m in reach: m += 1          # mex
        g[x] = m
    return g

def first_player_wins(piles, moves):      # independent piles: XOR the Grundy values
    g = grundy_table(max(piles), moves)
    x = 0
    for p in piles: x ^= g[p]
    return x != 0

public static int[] GrundyTable(int N, int[] moves)       // subtraction game: remove s in moves from a pile
{
    var g = new int[N + 1];
    for (int x = 1; x <= N; x++)
    {
        var reach = new HashSet<int>();
        foreach (int s in moves) if (s <= x) reach.Add(g[x - s]);
        int mex = 0; while (reach.Contains(mex)) mex++;
        g[x] = mex;
    }
    return g;
}

public static bool FirstPlayerWins(int[] piles, int[] moves)   // independent piles: XOR the Grundy values
{
    var g = GrundyTable(piles.Max(), moves);
    int x = 0; foreach (int p in piles) x ^= g[p];
    return x != 0;
}

Both functions were checked against a brute-force win/lose search over all multi-pile positions, and Nim itself against the same search. Grundy tables of subtraction games are eventually periodic, so when the pile sizes go up to 10⁹, print the first few hundred values, find the period, and index into it. When the game state is a set of used numbers (Can I Win), the win/lose DP runs over bitmasks; see Bitmask & Digit DP.

Choosing the right tool

When a DP is correct but too slow, walk down this list. The first "yes" is almost always the intended solution.

Technique Recurrence shape Before → after Condition to check
State machine dp[t][mode] exponential → O(n · modes) small finite set of modes
DAG DP dp[v] = f(dp[u]) over edges — → O(V + E) no cycles (Kahn pops all nodes)
Monotonic deque g(i) + max h(j), j in window O(nk) → O(n) window ends non-decreasing
Bisect best over sorted prefix O(n²) → O(n log n) candidates are a prefix after sorting
Segment tree / BIT best over a key range O(n²) → O(n log V) keys bounded, or compress them
CHT deque min (m_j x_i + b_j) O(n²) → O(n) slopes and queries monotone
Li Chao same, any order O(n²) → O(n log X) x range known in advance
Divide & conquer dp[t−1][j] + C(j, i) O(Kn²) → O(Kn log n) opt monotone (quadrangle inequality)
Knuth interval split O(n³) → O(n²) quadrangle inequality + monotone on nesting
Matrix power linear, fixed size k O(nk) → O(k³ log n) constant coefficients

Pitfalls that cost hours.

  • Updating states in place in a state machine. hold = max(hold, cash − p) followed by cash = max(cash, hold + p) lets you buy and sell on the same day. Use simultaneous assignment, or copy yesterday's values first.
  • Deque with < instead of <= when popping dominated states. It is still correct, but equal values pile up and the deque can grow, and with the "start fresh" variant people then read dq[0] on an empty deque. Pop on <=, and guard if dq.
  • CHT with floating-point intersections. Two lines that cross at x = 3 might be judged to cross at 2.9999999, and a needed line disappears. Compare by cross-multiplying integers (and use 128-bit when the products can pass 9.2·10¹⁸).
  • Sorting envelopes by (w, h) both ascending. Same-width envelopes then chain. Sort heights descending within a width.
  • Bisect on the wrong side in job scheduling. A job that ends at time 5 is compatible with one that starts at 5: that is bisect_right(ends, start). With bisect_left you silently forbid touching jobs.
  • Probability DP that keeps adding stopped states (New 21 Game), or that counts paths instead of probabilities and overflows.
  • Forgetting % MOD on one term of a sum in C#. One un-reduced product of two longs near 10⁹ + 7 is fine; three are not.
  • Divide & conquer without checking monotonicity. If opt is not monotone the code still runs and returns a plausible but wrong answer. Assert it on random small inputs against the O(Kn²) version.

1. Minimum Swaps To Make Sequences Increasing: two modes per column

LeetCode 801 Hard. Two equal-length arrays A and B. In one operation you may swap A[i] with B[i]. Return the fewest swaps that make both arrays strictly increasing (the input guarantees that it is possible).

Key insight. Whether column i is valid depends only on column i − 1 and on whether each of the two was swapped. So the state is (i, swapped?): two modes per column, the same shape as the stock machine. Between neighbours there are two independent tests: "same orientation is fine" (A[i−1] < A[i] and B[i−1] < B[i]) allows keep→keep and swap→swap. "Flipped orientation is fine" (A[i−1] < B[i] and B[i−1] < A[i]) allows keep→swap and swap→keep. A swap at column i costs 1.

Solution: two rolling values, O(n) time, O(1) space 
def min_swap(a, b):
    keep, swap = 0, 1                     # cost so far if column i is kept / swapped
    for i in range(1, len(a)):
        nk = ns = float("inf")
        if a[i - 1] < a[i] and b[i - 1] < b[i]:     # same orientation stays valid
            nk = min(nk, keep); ns = min(ns, swap + 1)
        if a[i - 1] < b[i] and b[i - 1] < a[i]:     # flipped orientation is valid
            nk = min(nk, swap); ns = min(ns, keep + 1)
        keep, swap = nk, ns
    return min(keep, swap)

public static int MinSwap(int[] a, int[] b)
{
    int keep = 0, swap = 1;                         // cost so far if column i is kept / swapped
    for (int i = 1; i < a.Length; i++)
    {
        int nk = int.MaxValue, ns = int.MaxValue;
        if (a[i - 1] < a[i] && b[i - 1] < b[i]) { nk = Math.Min(nk, keep); ns = Math.Min(ns, swap + 1); }
        if (a[i - 1] < b[i] && b[i - 1] < a[i]) { nk = Math.Min(nk, swap); ns = Math.Min(ns, keep + 1); }
        (keep, swap) = (nk, ns);
    }
    return Math.Min(keep, swap);
}

Both tests can pass at once, which is why the code uses two ifs and not an if/else. Checked against trying all 2ⁿ swap patterns.

2. Maximum Profit in Job Scheduling: DP over sorted ends

LeetCode 1235 Hard. Jobs have a start, an end and a profit. Pick non-overlapping jobs (one may start exactly when another ends) to maximise total profit. n ≤ 5·10⁴, times up to 10⁹.

Key insight. Sort the jobs by end time. Let dp[i] be the best profit using only the first i jobs. Job i is either skipped (dp[i−1]) or taken, and then the previous jobs must end by its start. Because the ends are sorted, the compatible jobs form a prefix, and its length is one bisect_right(ends, start). Step through the job visualizer above to see the bisect land.

Solution: sort by end, bisect, O(n log n) 
import bisect

def job_scheduling(start, end, profit):
    jobs = sorted(zip(end, start, profit))
    ends = [e for e, _, _ in jobs]
    dp = [0] * (len(jobs) + 1)            # dp[i]: best using the first i jobs by end time
    for i, (e, s, p) in enumerate(jobs, 1):
        k = bisect.bisect_right(ends, s, 0, i - 1)   # jobs ending at or before s
        dp[i] = max(dp[i - 1], dp[k] + p)
    return dp[-1]

public static int JobScheduling(int[] start, int[] end, int[] profit)
{
    int n = start.Length;
    var idx = Enumerable.Range(0, n).OrderBy(i => end[i]).ToArray();
    var ends = idx.Select(i => end[i]).ToArray();
    var dp = new int[n + 1];                      // dp[i]: best using the first i jobs by end time
    for (int i = 1; i <= n; i++)
    {
        int s = start[idx[i - 1]];
        int lo = 0, hi = i - 1;                   // first index in ends[0..i-1) with end > s
        while (lo < hi) { int mid = (lo + hi) / 2; if (ends[mid] <= s) lo = mid + 1; else hi = mid; }
        dp[i] = Math.Max(dp[i - 1], dp[lo] + profit[idx[i - 1]]);
    }
    return dp[n];
}

Checked against all 2ⁿ subsets on random small inputs. The same skeleton solves Maximum Number of Events That Can Be Attended II with one more dimension (how many events used), where an event ending at d blocks a start at d, so the search there uses bisect_left.

3. Number of Music Playlists: count by distinct songs so far

LeetCode 920 Hard. There are n songs, the playlist has goal slots, every song must be played at least once, and a song can be replayed only if k other songs have been played since its last play. Count playlists mod 10⁹ + 7.

Key insight. Which songs were played does not matter, only how many different ones. Let dp[i][j] count playlists of length i that use exactly j distinct songs. Slot i is either a new song (there are n − (j − 1) unused songs to choose from) or a replay: of the j songs used so far, the last k slots hold k different songs that are blocked, so j − k are allowed.

Solution: O(goal · n) counting DP 
MOD = 10**9 + 7

def num_music_playlists(n, goal, k):
    dp = [[0] * (n + 1) for _ in range(goal + 1)]
    dp[0][0] = 1
    for i in range(1, goal + 1):
        for j in range(1, n + 1):
            new = dp[i - 1][j - 1] * (n - j + 1)          # a song never played before
            old = dp[i - 1][j] * max(j - k, 0)            # replay one not in the last k
            dp[i][j] = (new + old) % MOD
    return dp[goal][n]

const long MOD = 1_000_000_007;

public static int NumMusicPlaylists(int n, int goal, int k)
{
    var dp = new long[goal + 1, n + 1]; dp[0, 0] = 1;
    for (int i = 1; i <= goal; i++)
        for (int j = 1; j <= n; j++)
        {
            long fresh = dp[i - 1, j - 1] * (n - j + 1);      // a song never played before
            long replay = dp[i - 1, j] * Math.Max(j - k, 0);  // replay one not in the last k
            dp[i, j] = (fresh + replay) % MOD;
        }
    return (int)dp[goal, n];
}

Each product is below 10⁹ · 100, so long is safe before the %. Checked against enumerating every sequence for n ≤ 4, goal ≤ 6.

4. Student Attendance Record II: a 6-state machine, counted

LeetCode 552 Hard. Count the strings of length n over {P, A, L} with fewer than 2 A's in total and never 3 L's in a row, mod 10⁹ + 7. n ≤ 10⁵.

Key insight. To decide whether the next letter is allowed you only need two facts: how many A's so far (0 or 1) and how many L's at the very end (0, 1 or 2). That is 2 × 3 = 6 states, and each day every state moves along at most three arrows. It is the stock machine again, but counting paths instead of maximising. For n up to 10¹⁸ the same 6 × 6 transition matrix goes through matrix power.

Solution: 6 rolling counters, O(n) time, O(1) space 
def check_record(n):
    MOD = 10**9 + 7
    dp = [[0] * 3 for _ in range(2)]      # dp[a][l]: a absences so far, l trailing lates
    dp[0][0] = 1
    for _ in range(n):
        nd = [[0] * 3 for _ in range(2)]
        for a in range(2):
            for l in range(3):
                v = dp[a][l]
                nd[a][0] = (nd[a][0] + v) % MOD                  # P: resets the late streak
                if a == 0: nd[1][0] = (nd[1][0] + v) % MOD       # A: only if no absence yet
                if l < 2: nd[a][l + 1] = (nd[a][l + 1] + v) % MOD  # L: streak grows, max 2
        dp = nd
    return sum(map(sum, dp)) % MOD

public static int CheckRecord(int n)
{
    const long MOD = 1_000_000_007;
    var dp = new long[2, 3]; dp[0, 0] = 1;            // dp[a, l]: a absences so far, l trailing lates
    for (int step = 0; step < n; step++)
    {
        var nd = new long[2, 3];
        for (int a = 0; a < 2; a++)
            for (int l = 0; l < 3; l++)
            {
                long v = dp[a, l];
                nd[a, 0] = (nd[a, 0] + v) % MOD;                      // P: resets the late streak
                if (a == 0) nd[1, 0] = (nd[1, 0] + v) % MOD;          // A: only if no absence yet
                if (l < 2) nd[a, l + 1] = (nd[a, l + 1] + v) % MOD;   // L: streak grows, max 2
            }
        dp = nd;
    }
    long total = 0; foreach (long v in dp) total += v;
    return (int)(total % MOD);
}

5. Stone Game III: minimax as a score difference

LeetCode 1406 Hard. Stones in a row with values (possibly negative). Players alternately take 1, 2 or 3 stones from the front. The higher total wins; return "Alice", "Bob" or "Tie".

Key insight. Use the score-difference minimax from Game theory DP: d[i] = best (mover − other) on the suffix starting at i. Taking x stones gains their sum and then hands the opponent d[i + x], so d[i] = max over x of (v[i] + … + v[i+x−1] − d[i+x]). Fill it from the right. Negative values are why "take 3 always" is wrong, and why d[i] starts at −∞, not 0: you must take at least one stone.

Solution: suffix difference DP, O(n) 
def stone_game_iii(v):
    n = len(v); d = [0] * (n + 3)         # d[i]: best (me - opponent) from i on
    for i in range(n - 1, -1, -1):
        take, d[i] = 0, float("-inf")
        for x in range(3):
            if i + x < n:
                take += v[i + x]
                d[i] = max(d[i], take - d[i + x + 1])
    return "Alice" if d[0] > 0 else "Bob" if d[0] < 0 else "Tie"

public static string StoneGameIII(int[] v)
{
    int n = v.Length; var d = new int[n + 3];             // d[i]: best (me - opponent) from i on
    for (int i = n - 1; i >= 0; i--)
    {
        int take = 0; d[i] = int.MinValue;
        for (int x = 0; x < 3 && i + x < n; x++)
        {
            take += v[i + x];
            d[i] = Math.Max(d[i], take - d[i + x + 1]);
        }
    }
    return d[0] > 0 ? "Alice" : d[0] < 0 ? "Bob" : "Tie";
}

Checked against a memoised full game search. Only d[i+1..i+3] is ever read, so a 4-slot ring buffer gives O(1) space.

6. Allocate Mailboxes: divide & conquer over K layers

LeetCode 1478 Hard. Houses on a line; place k mailboxes to minimise the total distance from each house to its nearest mailbox.

Key insight. Sort the houses. Each mailbox serves a contiguous run of houses, and one mailbox is best placed at the median of its run, so cost(j, i) for houses j..i−1 is O(1) with prefix sums. Then dp[t][i] = min over j of dp[t−1][j] + cost(j, i). The median cost satisfies the quadrangle inequality, so the best j never moves left as i grows, and every layer can use divide & conquer: O(k · n log n) instead of O(k · n²). LeetCode's n ≤ 100 accepts O(k n²) too, but the D&C version is the one that scales to n = 10⁵.

Solution: median cost + D&C per layer, O(k · n log n) 
def min_distance(houses, k):
    houses.sort(); n = len(houses)
    pre = [0]
    for h in houses: pre.append(pre[-1] + h)
    def cost(j, i):                       # one mailbox for houses[j:i], at the median
        m = (j + i - 1) // 2
        return houses[m] * (m - j) - (pre[m] - pre[j]) + (pre[i] - pre[m + 1]) - houses[m] * (i - m - 1)
    INF = float("inf"); prev = [0] + [INF] * n
    for t in range(1, k + 1):
        cur = [INF] * (n + 1)
        def solve(lo, hi, olo, ohi):      # fill cur[lo..hi]; their opt lies in [olo, ohi]
            if lo > hi: return
            mid = (lo + hi) // 2; best, opt = INF, olo
            for j in range(olo, min(ohi, mid - 1) + 1):
                v = prev[j] + cost(j, mid)
                if v < best: best, opt = v, j
            cur[mid] = best
            solve(lo, mid - 1, olo, opt); solve(mid + 1, hi, opt, ohi)
        solve(t, n, t - 1, n - 1)
        prev = cur
    return prev[n]

public static int MinDistance(int[] houses, int k)
{
    Array.Sort(houses); int n = houses.Length;
    var pre = new int[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + houses[i];
    int Cost(int j, int i)                                // one mailbox for houses[j..i), at the median
    {
        int m = (j + i - 1) / 2;
        return houses[m] * (m - j) - (pre[m] - pre[j]) + (pre[i] - pre[m + 1]) - houses[m] * (i - m - 1);
    }
    const int INF = int.MaxValue / 2;
    var prev = new int[n + 1]; Array.Fill(prev, INF); prev[0] = 0;
    for (int t = 1; t <= k; t++)
    {
        var cur = new int[n + 1]; Array.Fill(cur, INF);
        void Solve(int lo, int hi, int optLo, int optHi)  // fill cur[lo..hi]; their opt lies in [optLo, optHi]
        {
            if (lo > hi) return;
            int mid = (lo + hi) / 2, best = INF, opt = optLo;
            for (int j = optLo; j <= Math.Min(optHi, mid - 1); j++)
            {
                int v = prev[j] + Cost(j, mid);
                if (v < best) { best = v; opt = j; }
            }
            cur[mid] = best;
            Solve(lo, mid - 1, optLo, opt);
            Solve(mid + 1, hi, opt, optHi);
        }
        Solve(t, n, t - 1, n - 1);
        prev = cur;
    }
    return prev[n];
}

Checked against trying every set of k mailbox positions. The median fact is worth remembering on its own: the sum of |x − p| is minimised at any median p (move p one step toward the larger side and more houses get closer than farther).

7. Soup Servings: probability DP with a cutoff

LeetCode 808 Medium. Two soups A and B start with n ml each. Each turn, one of four servings (A,B) = (100,0), (75,25), (50,50), (25,75) is chosen with probability ¼. Return P(A empties first) + ½·P(both empty at the same time). n ≤ 10⁹.

Key insight. Divide everything by 25 so the servings become (4,0), (3,1), (2,2), (1,3) and the state is (a, b) in units. That is a pull-style probability DP. The trick is the cutoff: on average A loses 2.5 units per turn and B only 1.5, so as n grows the answer races to 1. It is within 10⁻⁶ of 1 once n > 4800, which LeetCode's tolerance accepts. Without that observation n = 10⁹ is hopeless; with it the table is at most 193 × 193.

Solution: memoised (a, b) in units of 25, O(min(n, 4800)² / 625) 
import functools

def soup_servings(n):
    if n > 4800: return 1.0               # the answer is within 1e-6 of 1 from here on
    m = (n + 24) // 25                    # work in units of 25 ml
    @functools.lru_cache(None)
    def f(a, b):
        if a <= 0 and b <= 0: return 0.5
        if a <= 0: return 1.0
        if b <= 0: return 0.0
        return 0.25 * (f(a - 4, b) + f(a - 3, b - 1) + f(a - 2, b - 2) + f(a - 1, b - 3))
    return f(m, m)

public static double SoupServings(int n)
{
    if (n > 4800) return 1.0;                             // the answer is within 1e-6 of 1 from here on
    int m = (n + 24) / 25;                                // work in units of 25 ml
    var memo = new double?[m + 1, m + 1];
    double F(int a, int b)
    {
        if (a <= 0 && b <= 0) return 0.5;
        if (a <= 0) return 1.0;
        if (b <= 0) return 0.0;
        return memo[a, b] ??= 0.25 * (F(a - 4, b) + F(a - 3, b - 1) + F(a - 2, b - 2) + F(a - 1, b - 3));
    }
    return F(m, m);
}

(n + 24) // 25 rounds up, because a partial 25 ml still counts as a full serving's worth of emptying. Checked against the sample answers (n = 50 → 0.625, n = 100 → 0.71875) and the convergence at 4800. The general lesson: when the input is astronomically large and the answer is a probability, look for the value it converges to.

Self-check

In the cooldown stock machine you write hold = max(hold, cash − p) and then cash = max(cash, hold + p) on the next line. What goes wrong?

The second line reads the new hold, so it can buy and sell on the same day with a profit of 0. That is harmless here, but it breaks fee and cooldown variants in subtle ways, and it is plain wrong for "at most k transactions", where the same-day round trip uses a transaction. Assign all modes from yesterday's values at once: hold, cash = max(hold, cash − p), max(cash, hold + p).

After running patience sorting on [3, 1, 4, 1, 5, 9, 2, 6] the tails array is [1, 2, 5, 6]. Is 1, 2, 5, 6 an increasing subsequence of the input?

No: the 2 comes after the 5 in the input. tails only promises that its length (4) is the LIS length, and that tails[L] is the smallest possible end of an increasing run of length L + 1. To recover a real subsequence, store a parent pointer when each element lands on a pile (here 1, 4, 5, 9 or 1, 4, 5, 6).

dp[i] = min over j < i of dp[j] + (h[i] − h[j])² + C, with h strictly increasing and n = 2·10⁵. Which optimisation, and why?

The convex hull trick. Expanding gives h[i]² + C + min_j (−2h[j] · h[i] + dp[j] + h[j]²): a line with slope −2h[j] and intercept dp[j] + h[j]², evaluated at x = h[i]. The slopes decrease and the queries increase, so the deque version runs in O(n) total. With unsorted h, use a Li Chao tree for O(n log X).

Nim with piles 3, 4, 5. Who wins, and what is a winning first move?

3 ⊕ 4 ⊕ 5 = 2, which is non-zero, so the first player wins. The XOR's top bit is bit 1, and pile 3 = 011 has it set, so replace 3 by 3 ⊕ 2 = 1, that is, take 2 stones from the first pile. Then 1 ⊕ 4 ⊕ 5 = 0 and the opponent faces a losing position.

In a subtraction game where you may remove 1 or 2 stones, what is the Grundy value of a pile of 10?

The Grundy values go 0, 1, 2, 0, 1, 2, …, so g(x) = x mod 3, and g(10) = 1. Piles that are multiples of 3 are losing for the player to move. Set the visualizer's moves to 1,2 to watch the period appear. Periodicity is what lets you handle pile sizes up to 10⁹.

Compute Fibonacci(10¹⁸) mod 10⁹ + 7. How many 2 × 2 matrix multiplications does fast power need, roughly?

About 2 · log₂(10¹⁸) ≈ 120: one squaring per bit (60 bits) plus one multiplication per set bit (at most 60). Each one is 8 multiplications of numbers below 10⁹ + 7, so the products fit in a 64-bit integer before % MOD. The answer is 209783453.

When does the divide & conquer optimisation give a wrong answer without crashing?

When the best split opt(i) is not monotone in i. The recursion only searches [optLo, optHi] for each midpoint, so if the true optimum lies outside, it is silently skipped. Check that the cost satisfies the quadrangle inequality, or test against the O(K n²) version on random small inputs before trusting it.

Cheat sheet

State machineOne DP row per mode (hold / free / rest). Update all modes from yesterday at once. O(n · modes).
DAG DPTopological order (Kahn), relax along edges. Longest path = max finish time. O(V + E).
Deque DPdp[i] = a[i] + max dp[j], j in a sliding window. Pop the back while ≤, pop the front when out of the window. O(n).
Bisect DPLIS tails + bisect_left. Envelopes: w ↑, h ↓. Jobs: sort by end, bisect_right(ends, start). O(n log n).
Tree-backed DPBest over a key range: segment tree or BIT over values (compress them). O(n log V).
CHT / Li ChaoTerm f(j)·g(i): lines m_j x + b_j. Deque if monotone, Li Chao otherwise. Integer comparisons only.
D&C / KnuthMonotone opt. D&C: O(K n log n) per K layers. Knuth: opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j], O(n²).
ProbabilityPush the mass forward or pull the expectation backward. Sliding window sum for "average of the next W". Watch for a limit.
Counting% (10⁹ + 7) after every product; state = what the future needs (counts, not identities).
Matrix powerFixed linear recurrence of size k: Mⁿ by squaring. O(k³ log n). Fibonacci, tilings, walks.
GamesZero-sum: d = max(gain − d(next)). Win/lose: losing iff all moves win. Sum of games: XOR of Grundy values.
RecogniseConstraints: n ≤ 10⁵ with O(n²) DP → deque/bisect/tree/CHT. n ≤ 10¹⁸ → matrix power or a cycle.
