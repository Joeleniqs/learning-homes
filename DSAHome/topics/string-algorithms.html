String Algorithms

KMP failure function, Z-algorithm, Rabin–Karp, Manacher's palindromes and string hashing, each animated character by character.

Intermediate → Expert~75 min studyBuilds on: Hashing PatternsUpdated 2026-11-03

What it is and when you need it

A string is an array of characters with extra structure: the same characters repeat, prefixes match suffixes, and halves mirror each other. String algorithms are tools for using that structure so you never redo work. A naive search compares a pattern of length m against a text of length n in up to n·m steps. KMP, Z, Manacher and the suffix-array builders all get down to about n by remembering what earlier comparisons already proved.

The one idea behind every algorithm on this page. Never re-compare characters that earlier comparisons already proved equal. Store that knowledge in a small table (π for KMP, Z for the Z-algorithm, P for Manacher, the LCP height for Kasai) and let one pointer move only forward.

Naive / brute force: O(n·m)

Try every alignment and forget everything after a mismatch. Fine for a one-off search in short strings, and it is what you write first. Repetitive inputs such as aaaa…ab make it quadratic.

Linear-time automata: KMP, Z, Manacher, Aho–Corasick

These are deterministic O(n + m) with no bad inputs. Each keeps an invariant about the rightmost thing it has proved (a border, a Z-box, a palindrome, a trie state).

Hashing and suffix structures

Hashing turns substring equality into an O(1) number comparison, with a small chance of error that you must manage. Suffix arrays sort every suffix once so that questions about all substrings become scans.

Prerequisite: Hashing (its rolling-hash section is the starting point for the deeper treatment below). The window-of-characters family (anagrams, "at most k distinct", minimum window) lives in Sliding Window, and edit distance, LCS and regex/wildcard DP live in DP: Sequences & Strings. This page covers everything in between.

Foundations: strings are arrays with rules

Immutability: build, don't concatenate

Python str and C# string are immutable. s += c allocates a new string and copies all of s into it, so building an n-character string one character at a time copies 1 + 2 + … + n ≈ n²/2 characters. For n = 10⁵ that is about 5·10⁹ copies. CPython sometimes resizes in place when nothing else references s, but that is an implementation detail you cannot rely on.

Python

Collect pieces in a list and call "".join(parts) once. Turn a string into list(s) to edit it in place, then join it back. Slicing s[a:b] copies b − a characters; it is not a view.

C

Use StringBuilder for loops, string.Join/string.Concat for collections, and ReadOnlySpan<char> (s.AsSpan(a, len)) for zero-copy slices. s[a..b] and Substring copy. string.Create(n, state, (span, st) => …) writes a string's characters exactly once, and stackalloc char[n] gives a scratch buffer with no heap allocation.

def is_rotation(a, b):

Characters are small integers

For lowercase letters, ord(c) - ord('a') (Python) or c - 'a' (C#) maps 'a'..'z' to 0..25. That one subtraction powers most string tricks:

  • Count arrays instead of hash maps: cnt = [0] * 26 is faster than a Counter and gives a canonical form for free. The anagram key is the tuple of 26 counts.
  • Bit masks: mask |= 1 << (c - 'a') records which letters occur in an int. Two words share no letter exactly when m1 & m2 == 0.
  • Case and digits: in ASCII, 'A' is 65 and 'a' is 97, so the case bit is 32 (c ^ 32 swaps case for letters). A digit's value is c - '0'.
  • Hash digits: map 'a' to 1, not 0, when building polynomial hashes. Otherwise "a", "aa" and "aaa" all hash to 0.
def letter_mask(word):
    m = 0
    for ch in word:
        m |= 1 << (ord(ch) - 97)               # bit k set  <=>  letter k occurs
    return m

def anagram_key(word):
    cnt = [0] * 26
    for ch in word:
        cnt[ord(ch) - 97] += 1
    return tuple(cnt)                          # hashable canonical form, O(len)

static int LetterMask(string word)
{
    int m = 0;
    foreach (char ch in word) m |= 1 << (ch - 'a');
    return m;
}

static string AnagramKey(string word)
{
    Span<int> cnt = stackalloc int[26];
    foreach (char ch in word) cnt[ch - 'a']++;
    var sb = new StringBuilder(52);
    for (int k = 0; k < 26; k++) sb.Append(cnt[k]).Append('#');   // '#' keeps 1,11 apart from 11,1
    return sb.ToString();
}

Unicode: length is a lie

Interview strings are almost always ASCII. Production strings are not, and the bugs are quiet. There are four different "lengths" for the same text:

  • C#: s.Length counts UTF-16 units. char.IsSurrogate, s.EnumerateRunes() (code points as Rune), and StringInfo.GetTextElementEnumerator / StringInfo.LengthInTextElements (graphemes) give the other views. Reversing a char[] turns surrogate pairs into invalid text.
  • Python: len(s) counts code points, so emoji are safe, but combining marks and multi-code-point emoji are still several "characters". Grapheme clusters need the third-party regex module (regex.findall(r"\X", s)).
  • Equality: "é" can be one code point (U+00E9) or two (e + U+0301). Normalise with unicodedata.normalize("NFC", s) / s.Normalize() before comparing or hashing.
  • Comparison: C# IndexOf(string), StartsWith(string) and CompareTo are culture-sensitive by default. Pass StringComparison.Ordinal for algorithmic work: it is faster and does exactly what the algorithms on this page assume.
import unicodedata

def utf16_length(s):
    return len(s.encode("utf-16-le")) // 2    # what C# string.Length would report

def same_text(a, b):
    nfc = lambda x: unicodedata.normalize("NFC", x)
    return nfc(a) == nfc(b)                    # "é" == "e\u0301" after NFC

static int CodePointCount(string s) => s.EnumerateRunes().Count();

static string ReverseGraphemes(string s)       // safe for emoji and combining marks
{
    var parts = new List<string>();
    var e = StringInfo.GetTextElementEnumerator(s);
    while (e.MoveNext()) parts.Add(e.GetTextElement());
    parts.Reverse();
    return string.Concat(parts);
}

static bool SameText(string a, string b) =>
    string.Equals(a.Normalize(NormalizationForm.FormC), b.Normalize(NormalizationForm.FormC), StringComparison.Ordinal);

Everyday transforms

Most "easy" string problems are one of a handful of transforms. Knowing them as named moves keeps the code short and correct.

def reverse_words_in_place(chars):          # list of chars, single spaces, no padding
    def rev(i, j):                           # reverse chars[i:j]
        j -= 1
        while i < j:
            chars[i], chars[j] = chars[j], chars[i]
            i, j = i + 1, j - 1
    rev(0, len(chars))                       # "the sky" -> "yks eht"
    i = 0
    while i < len(chars):
        j = i
        while j < len(chars) and chars[j] != " ":
            j += 1
        rev(i, j)                            # "yks" -> "sky"
        i = j + 1

def rotate_right(chars, k):
    n = len(chars)
    if n == 0:
        return
    k %= n
    chars.reverse()                          # whole
    chars[:k] = chars[:k][::-1]              # first k
    chars[k:] = chars[k:][::-1]              # rest

static void ReverseWordsInPlace(Span<char> s)    // single spaces, no padding
{
    s.Reverse();                                 // "the sky" -> "yks eht"
    for (int i = 0, j; i < s.Length; i = j + 1)
    {
        j = i;
        while (j < s.Length && s[j] != ' ') j++;
        s[i..j].Reverse();                       // "yks" -> "sky"
    }
}

static void RotateRight(Span<char> s, int k)
{
    if (s.Length == 0) return;
    k %= s.Length;
    s.Reverse();
    s[..k].Reverse();
    s[k..].Reverse();
}

Palindromes: two pointers and expand around the center

A palindrome reads the same in both directions. Two questions come up constantly:

  1. Is s a palindrome? Two pointers from the ends, moving inwards (see Two Pointers). Valid Palindrome adds "skip non-alphanumerics"; Valid Palindrome II adds "you may delete one character". At the first mismatch, try skipping either side and check the rest.
  2. Which substrings are palindromes? Every palindrome has a center: a character (odd length) or a gap between two characters (even length). There are 2n − 1 centers. Grow outwards from each while the ends match. If s[l..r] is a palindrome, then s[l−1..r+1] is one exactly when s[l−1] = s[r+1], so each successful step finds a new palindrome and the first failure ends that center.
def is_palindrome_alnum(s):                  # Valid Palindrome
    i, j = 0, len(s) - 1
    while i < j:
        if not s[i].isalnum():
            i += 1
        elif not s[j].isalnum():
            j -= 1
        elif s[i].lower() != s[j].lower():
            return False
        else:
            i, j = i + 1, j - 1
    return True

def longest_palindrome(s):                   # O(n²) time, O(1) space
    lo, hi = 0, 0                            # best is s[lo:hi]
    for c in range(2 * len(s) - 1):
        l, r = c // 2, (c + 1) // 2
        while l >= 0 and r < len(s) and s[l] == s[r]:
            l, r = l - 1, r + 1
        if r - l - 1 > hi - lo:
            lo, hi = l + 1, r
    return s[lo:hi]

def count_palindromes(s):                    # Palindromic Substrings
    count = 0
    for c in range(2 * len(s) - 1):
        l, r = c // 2, (c + 1) // 2
        while l >= 0 and r < len(s) and s[l] == s[r]:
            count += 1
            l, r = l - 1, r + 1
    return count

static bool IsPalindromeAlnum(string s)
{
    int i = 0, j = s.Length - 1;
    while (i < j)
    {
        if (!char.IsLetterOrDigit(s[i])) i++;
        else if (!char.IsLetterOrDigit(s[j])) j--;
        else if (char.ToLowerInvariant(s[i]) != char.ToLowerInvariant(s[j])) return false;
        else { i++; j--; }
    }
    return true;
}

static string LongestPalindrome(string s)
{
    int lo = 0, hi = 0;
    for (int c = 0; c < 2 * s.Length - 1; c++)
    {
        int l = c / 2, r = (c + 1) / 2;
        while (l >= 0 && r < s.Length && s[l] == s[r]) { l--; r++; }
        if (r - l - 1 > hi - lo) { lo = l + 1; hi = r; }
    }
    return s[lo..hi];
}

static int CountPalindromes(string s)
{
    int count = 0;
    for (int c = 0; c < 2 * s.Length - 1; c++)
        for (int l = c / 2, r = (c + 1) / 2; l >= 0 && r < s.Length && s[l] == s[r]; l--, r++)
            count++;
    return count;
}

Expand-around-center is the right default up to n ≈ 3,000–5,000. When n reaches 10⁵, or a problem needs the palindrome radius at every center, use Manacher. The O(n²) DP table isPal[i][j] gives the same answers with O(n²) memory, so prefer expansion unless you need the table for a follow-up DP such as palindrome partitioning (see DP: Sequences & Strings).

Exact matching: why naive is slow

The question is: where does pattern p (length m) occur in text t (length n)? The naive algorithm tries each alignment s = 0 … n − m and compares left to right. On random text it is fast, because most alignments fail on the first character. On repetitive text it does about (n − m + 1)·m comparisons, because each new alignment re-reads characters it has already matched.

Built-ins are fine for one-off searches: CPython's str.find combines a Boyer–Moore–Horspool-style skip with, since 3.10, the two-way algorithm for longer needles. .NET's IndexOf(p, StringComparison.Ordinal) is vectorised. In interviews, and whenever you need all occurrences, overlapping matches, or information about prefixes, you need an algorithm whose behaviour you control. The next two sections give you two: KMP and Z.

KMP: the prefix function

Borders, the idea everything rests on

A border of a string is a proper prefix that is also a suffix. "abacaba" has borders "aba" and "a". The prefix function stores, for every prefix of s, the length of its longest border:

π[i] = length of the longest proper prefix of s[0..i] that is also a suffix of s[0..i].

Why it matters for matching: suppose the first j characters of the pattern matched and then a mismatch happened. The text you have just read is p[0..j). The next alignment that can still succeed must start where a prefix of p lines up with a suffix of what you read, which is a border of p[0..j). The longest one is π[j−1], so you keep j = π[j−1] characters matched and carry on. You never move backwards in the text.

Building π in O(m): extend or fall back

To compute π[i], start from the best border of the previous prefix, j = π[i−1]. That border s[0..j) is followed by s[j] at the front and by s[i] at the back:

  • s[i] == s[j]: the border grows by one, so π[i] = j + 1.
  • Mismatch: try the next shorter border, j = π[j−1], which is still a border of s[0..i). Repeat until a match or j = 0.

Why this is linear: j goes up by at most 1 per character and every fallback lowers it by at least 1. So over the whole string there are at most m fallbacks, and the total work is under 2m. Watch the purple fallback chain in the visualizer: step through the default abacabab (at the last character the border "aba" cannot be extended by b, so it falls back to "a" and extends that to "ab"), then try aabaaab and aaaa.

def prefix_function(s):
    pi = [0] * len(s)
    for i in range(1, len(s)):
        j = pi[i - 1]                        # best border of s[0..i-1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]                    # fall back to the next border
        if s[i] == s[j]:
            j += 1                           # extend it by s[i]
        pi[i] = j
    return pi

def kmp_search(text, pat):                   # all start indices, overlaps included
    if not pat:
        return list(range(len(text) + 1))
    pi, res, j = prefix_function(pat), [], 0
    for i, ch in enumerate(text):
        while j > 0 and ch != pat[j]:
            j = pi[j - 1]
        if ch == pat[j]:
            j += 1
        if j == len(pat):                    # full match ending at i
            res.append(i - len(pat) + 1)
            j = pi[j - 1]                    # keep the border, look for overlaps
    return res

static int[] PrefixFunction(string s)
{
    var pi = new int[s.Length];
    for (int i = 1; i < s.Length; i++)
    {
        int j = pi[i - 1];
        while (j > 0 && s[i] != s[j]) j = pi[j - 1];
        if (s[i] == s[j]) j++;
        pi[i] = j;
    }
    return pi;
}

static List<int> KmpSearch(string text, string pat)
{
    var res = new List<int>();
    if (pat.Length == 0) { for (int i = 0; i <= text.Length; i++) res.Add(i); return res; }
    int[] pi = PrefixFunction(pat);
    for (int i = 0, j = 0; i < text.Length; i++)
    {
        while (j > 0 && text[i] != pat[j]) j = pi[j - 1];
        if (text[i] == pat[j]) j++;
        if (j == pat.Length)
        {
            res.Add(i - pat.Length + 1);
            j = pi[j - 1];
        }
    }
    return res;
}

The search phase: the text pointer never goes back

The search loop is the same "extend or fall back" loop run over the text, with j = how many pattern characters currently match. When j reaches m you have a match, and you fall back to π[m−1] so overlapping matches are found too ("aa" occurs 3 times in "aaaa"). The text index i only increases, so KMP also works on a stream: it needs O(m) memory and never re-reads input.

The concatenation trick Run prefix_function(p + "#" + t), with # a character that appears in neither string. Since π can never exceed m (the separator blocks longer borders), every position with π = m is the end of a match. One function then gives search, and the same trick works for the Z-function below. Choose the separator carefully: use "\0" or a character outside the alphabet, never one that could appear in the input.

Repeated Substring Pattern in one line s in (s + s)[1:-1] also works. If s = u^k, then s appears inside s + s at offset |u|, which is not the first or last position. The π version is O(n) guaranteed and tells you which block repeats.

def smallest_period(s):
    return len(s) - prefix_function(s)[-1]

def repeated_substring_pattern(s):           # LeetCode 459
    p = smallest_period(s)
    return p < len(s) and len(s) % p == 0

def shortest_palindrome(s):                  # LeetCode 214: add chars in front
    k = prefix_function(s + "#" + s[::-1])[-1]   # longest palindromic prefix
    return s[k:][::-1] + s

static int SmallestPeriod(string s) => s.Length - PrefixFunction(s)[^1];

static bool RepeatedSubstringPattern(string s)
{
    int p = SmallestPeriod(s);
    return p < s.Length && s.Length % p == 0;
}

static string ShortestPalindrome(string s)
{
    if (s.Length == 0) return s;
    char[] rev = s.ToCharArray();
    Array.Reverse(rev);
    int k = PrefixFunction(s + "#" + new string(rev))[^1];
    char[] add = s[k..].ToCharArray();
    Array.Reverse(add);
    return new string(add) + s;
}

Z-algorithm: matching against the prefix

z[i] is the length of the longest substring starting at i that is also a prefix of s. For s = "aabxaab", z = [–, 1, 0, 0, 3, 1, 0]. It answers the same questions as π (they can be converted into each other), but it is indexed by start position rather than end position, which is often the more natural view: "how much of the pattern matches here?"

The Z-box

Keep the window [l, r) with the largest r found so far such that s[l..r) equals a prefix of s. For any i inside that box, s[i..r) is a copy of s[i−l .. r−l), a stretch near the start whose Z-value you already know. That gives a free head start, and you only compare characters past r:

  • i ≥ r: nothing known; compare from scratch.
  • i < r: start at min(r − i, z[i − l]), then keep comparing. If the mirrored value fits strictly inside the box, the first comparison fails immediately.
  • After extending, if i + z[i] > r, move the box to [i, i + z[i]).

Each successful comparison moves r to the right, and r never decreases, so the total is O(n).

def z_function(s):
    n = len(s)
    z = [0] * n
    l = r = 0                                # Z-box [l, r)
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])      # free part copied from the mirror
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    if n:
        z[0] = n                             # convention: the whole string
    return z

def z_search(text, pat):
    if not pat:
        return list(range(len(text) + 1))
    m = len(pat)
    z = z_function(pat + "\0" + text)        # separator in neither string
    return [i - m - 1 for i in range(m + 1, len(z)) if z[i] >= m]

static int[] ZFunction(string s)
{
    int n = s.Length;
    var z = new int[n];
    for (int i = 1, l = 0, r = 0; i < n; i++)
    {
        if (i < r) z[i] = Math.Min(r - i, z[i - l]);
        while (i + z[i] < n && s[z[i]] == s[i + z[i]]) z[i]++;
        if (i + z[i] > r) { l = i; r = i + z[i]; }
    }
    if (n > 0) z[0] = n;
    return z;
}

static List<int> ZSearch(string text, string pat)
{
    var res = new List<int>();
    if (pat.Length == 0) { for (int i = 0; i <= text.Length; i++) res.Add(i); return res; }
    int m = pat.Length;
    int[] z = ZFunction(pat + "\0" + text);
    for (int i = m + 1; i < z.Length; i++)
        if (z[i] >= m) res.Add(i - m - 1);
    return res;
}

Reach for Z when… the question is "for every position, how long does the string match its own start?" Sum of Scores of Built Strings is literally sum(z) with z[0] = n. Minimum Time to Revert Word asks for the first multiple of k with z[i] ≥ n − i. Find Beautiful Indices needs every occurrence of two patterns, which is two Z (or KMP) passes plus a merge.

Pick KMP (π) when

You process text as a stream, you need borders or periods, or you build a matching automaton (Aho–Corasick generalises π to many patterns).

Pick Z when

You think in start positions: "match length at each i", comparing every suffix with the prefix, or scoring every suffix. The code has no inner fallback chain, so it is slightly easier to get right under pressure.

String hashing in depth

The Hashing page introduces the rolling window hash. Here we go further: hash every prefix once, and then the hash of any substring costs O(1). Substring equality becomes a number comparison, and that one capability solves a large share of hard string problems.

Polynomial prefix hashes

Treat the string as a number in base B, modulo a large prime M, with each character mapped to a digit in 1..σ:

H[0] = 0, H[k+1] = (H[k]·B + v(s[k])) mod M, and P[k] = B^k mod M.

Then hash(s[a..a+L)) = (H[a+L] − H[a]·P[L]) mod M. The figure shows why with ordinary decimal digits: the long prefix minus the short prefix shifted left by L digits leaves exactly the middle part.

Equal substrings always have equal hashes. Unequal ones usually differ, and how usually is the next subsection. With O(1) substring comparison you can binary search the longest common prefix of any two suffixes: the predicate "the first L characters are equal" is true up to the LCP and false after it. That gives LCP in O(log n), and lexicographic comparison of any two substrings in O(log n) as well (compare the character right after the LCP).

Collisions: how likely, and how to make them impossible in practice

For two different strings of length L and a random base B modulo a prime M, the hashes collide with probability at most (L − 1)/M. That is the number of roots of a degree-(L − 1) polynomial divided by M. One comparison with M ≈ 10⁹ is safe. But "binary search over lengths, put n hashes in a set" makes about n² / 2 implicit pairwise comparisons, and n = 10⁵ gives 5·10⁹ pairs: a single 10⁹ modulus will collide.

Hash traps that fail real submissions

  • One small modulus with many substrings: use two independent moduli (10⁹+7 and 10⁹+9, about 10¹⁸ combined) or one 61-bit Mersenne prime 2⁶¹ − 1.
  • Overflow in C#: (h * B) % M with long is safe only if h, B < M ≤ about 3·10⁹. With 2⁶¹ − 1, use UInt128 or Math.BigMul.
  • Modulus 2⁶⁴ (letting ulong overflow): fast but broken by construction. The Thue–Morse strings of length 2¹¹ collide for every odd base, and anti-hash tests on judges include them.
  • A base sharing a factor with M: B = 26 and M = 13 gives B ≡ 0, so every power vanishes and the hash is just the last character. Use a prime M and a base in [σ + 1, M − 1], picked at random at start-up so no fixed input can target it.
  • Mapping 'a' to 0: "a", "aa" and "aaa" then all hash to 0. Map characters to 1..σ.
  • Negative results: (x − y) % M is negative in C# (and C/Java) when x < y. Add M before taking %. Python's % is always non-negative.
import random

class StringHash:
    """Double polynomial hash. get(a, L) identifies s[a:a+L] in O(1)."""
    M1, M2 = 1_000_000_007, 1_000_000_009

    def __init__(self, s):
        self.B = random.randrange(911, 10**6)          # random base: no fixed anti-hash input
        n = len(s)
        self.h1, self.h2 = [0] * (n + 1), [0] * (n + 1)
        self.p1, self.p2 = [1] * (n + 1), [1] * (n + 1)
        for k, ch in enumerate(s):
            v = ord(ch)                                  # >= 1 for real text
            self.h1[k + 1] = (self.h1[k] * self.B + v) % self.M1
            self.h2[k + 1] = (self.h2[k] * self.B + v) % self.M2
            self.p1[k + 1] = self.p1[k] * self.B % self.M1
            self.p2[k + 1] = self.p2[k] * self.B % self.M2

    def get(self, a, L):
        x = (self.h1[a + L] - self.h1[a] * self.p1[L]) % self.M1
        y = (self.h2[a + L] - self.h2[a] * self.p2[L]) % self.M2
        return (x << 32) | y                             # one int key for sets and dicts

    def lcp(self, i, j, limit):                          # longest L <= limit with s[i:i+L] == s[j:j+L]
        lo, hi = 0, limit
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if self.get(i, mid) == self.get(j, mid):
                lo = mid
            else:
                hi = mid - 1
        return lo

Rabin–Karp: one rolling hash over the text

For a single pattern, you don't need all prefix hashes. Keep the hash of the current length-m window and roll it: remove the leftmost character's contribution v·B^(m−1), multiply by B, and add the new character. When the window hash equals the pattern hash you have a candidate. Either verify it character by character (always correct, expected O(n + m)) or trust a double hash (Monte Carlo, guaranteed O(n + m)).

The default input below uses a deliberately weak modulus (M = 11) so you can watch a spurious hit happen at s = 0: "bar" and "cab" have the same hash and verification rejects it. Turn on the second modulus M2 and the false alarm disappears.

def rabin_karp(text, pat, B=257, M=(1 << 61) - 1):
    n, m = len(text), len(pat)
    if m == 0:
        return list(range(n + 1))
    if m > n:
        return []
    top = pow(B, m - 1, M)                    # weight of the leftmost char
    hp = hw = 0
    for k in range(m):
        hp = (hp * B + ord(pat[k])) % M
        hw = (hw * B + ord(text[k])) % M
    res = []
    for s in range(n - m + 1):
        if hw == hp and text[s:s + m] == pat:   # verify: never a false positive
            res.append(s)
        if s + m < n:                           # roll: drop text[s], add text[s+m]
            hw = ((hw - ord(text[s]) * top) * B + ord(text[s + m])) % M
    return res

static List<int> RabinKarp(string text, string pat)
{
    const long M = 1_000_000_007, B = 257;
    int n = text.Length, m = pat.Length;
    var res = new List<int>();
    if (m == 0) { for (int i = 0; i <= n; i++) res.Add(i); return res; }
    if (m > n) return res;
    long top = 1, hp = 0, hw = 0;
    for (int k = 0; k < m - 1; k++) top = top * B % M;
    for (int k = 0; k < m; k++)
    {
        hp = (hp * B + pat[k]) % M;
        hw = (hw * B + text[k]) % M;
    }
    for (int s = 0; s + m <= n; s++)
    {
        if (hw == hp && text.AsSpan(s, m).SequenceEqual(pat)) res.Add(s);
        if (s + m < n)
        {
            hw = (hw - text[s] * top % M + M) % M;
            hw = (hw * B + text[s + m]) % M;
        }
    }
    return res;
}

Manacher: every palindrome in O(n)

Expand-around-center wastes work in the same way naive matching does: inside a long palindrome, the right half mirrors the left half, so palindromes centred on the right are copies of ones you have already measured on the left. Manacher reuses them.

Step 1, remove the odd/even split. Put a separator between every pair of characters and at both ends: "abba" → "#a#b#b#a#". Every palindrome in s now has odd length in t and a single centre. P[i] is the radius around t[i] (number of characters on each side), and it equals the length of the matching palindrome in s. The palindrome starts at (i − P[i]) / 2 in s.

Step 2, keep the rightmost palindrome t[2c − r .. r] found so far (centre c, right end r). For a new centre i < r, its mirror is i' = 2c − i, and three cases follow:

All three collapse into one line, P[i] = min(r − i, P[2c − i]), followed by the usual expansion loop. Only case 3 (and i ≥ r) ever expands, and every successful expansion pushes r to the right. Since r only increases and never passes the end of t, the expansions total O(n).

def manacher(s):
    """P[i] for t = '#a#b#...#': length of the longest palindrome of s centred at t[i]."""
    t = "#" + "#".join(s) + "#"
    N = len(t)
    P = [0] * N
    c = r = 0                                 # rightmost palindrome is t[2c-r .. r]
    for i in range(N):
        if i < r:
            P[i] = min(r - i, P[2 * c - i])   # copy from the mirror
        while i - P[i] - 1 >= 0 and i + P[i] + 1 < N and t[i - P[i] - 1] == t[i + P[i] + 1]:
            P[i] += 1                         # expand only past r
        if i + P[i] > r:
            c, r = i, i + P[i]
    return P

def longest_palindrome_linear(s):
    P = manacher(s)
    i = max(range(len(P)), key=P.__getitem__)
    start = (i - P[i]) // 2
    return s[start:start + P[i]]

def count_palindromes_linear(s):
    return sum((p + 1) // 2 for p in manacher(s))   # radius p gives ceil(p/2) palindromes

static int[] Manacher(string s)
{
    int N = 2 * s.Length + 1;
    var t = new char[N];
    for (int k = 0; k < N; k++) t[k] = (k & 1) == 0 ? '#' : s[k >> 1];
    var P = new int[N];
    for (int i = 0, c = 0, r = 0; i < N; i++)
    {
        if (i < r) P[i] = Math.Min(r - i, P[2 * c - i]);
        while (i - P[i] - 1 >= 0 && i + P[i] + 1 < N && t[i - P[i] - 1] == t[i + P[i] + 1]) P[i]++;
        if (i + P[i] > r) { c = i; r = i + P[i]; }
    }
    return P;
}

Suffix arrays and the LCP array

Many hard string problems ask about all substrings at once: how many distinct ones are there, which is the longest that repeats, what is the longest common substring of two strings, what is the k-th smallest substring. Every substring is a prefix of some suffix. So sort the n suffixes, and substrings that share a prefix end up next to each other.

  • Suffix array sa: the start indices of the suffixes in sorted order. For banana: sa = [5, 3, 1, 0, 4, 2] (a, ana, anana, banana, na, nana).
  • LCP array: lcp[k] = longest common prefix of the suffixes at sa[k−1] and sa[k] (lcp[0] = 0). For banana: [0, 1, 3, 0, 0, 2].

Construction by prefix doubling

Sorting n suffixes with ordinary string comparisons costs O(n² log n). Prefix doubling sorts by the first 1, 2, 4, 8, … characters instead. Each round only needs a pair of integers per suffix: once you know the rank of every suffix by its first k characters, its first 2k characters are described by (rank[i], rank[i + k]), the ranks of its two halves. After about log₂ n rounds all ranks are distinct and the order is final.

Kasai's LCP in O(n)

Comparing every adjacent pair from scratch is O(n²). Kasai processes suffixes in text order (i = 0, 1, 2, …) and uses one fact: if suffix i shares h characters with its predecessor in sorted order, then suffix i + 1 shares at least h − 1 with its predecessor (drop the first character from both). So h only falls by 1 per step and rises at most n times in total.

def suffix_array(s):                         # O(n log² n): fine up to ~2·10⁵ in practice
    n = len(s)
    sa, rank, k = list(range(n)), [ord(c) for c in s], 1
    while n:
        key = lambda i: (rank[i], rank[i + k] if i + k < n else -1)
        sa.sort(key=key)
        new = [0] * n
        for a, b in zip(sa, sa[1:]):
            new[b] = new[a] + (key(a) != key(b))
        rank = new
        if rank[sa[-1]] == n - 1:            # all ranks distinct: sorted
            break
        k *= 2
    return sa

def lcp_array(s, sa):                        # Kasai, O(n)
    n = len(s)
    rank = [0] * n
    for k, i in enumerate(sa):
        rank[i] = k
    lcp, h = [0] * n, 0
    for i in range(n):
        if rank[i] == 0:
            h = 0
            continue
        j = sa[rank[i] - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[rank[i]] = h
        if h:
            h -= 1
    return lcp

def distinct_substrings(s):
    n, lcp = len(s), lcp_array(s, suffix_array(s))
    return n * (n + 1) // 2 - sum(lcp)       # each suffix adds len − (prefix shared with predecessor)

Suffix automaton and suffix tree: when you need them

You rarely need to write these in an interview, but you should know what they buy you:

  • Suffix automaton (SAM): the smallest automaton that accepts exactly the substrings of s, with at most 2n states, built online in O(n). It shines when characters arrive one at a time and you need answers after each one (distinct substrings so far, the longest common substring with a stream, occurrence counts of each substring). Distinct substrings is Σ (len[v] − len[link[v]]) over its states.
  • Suffix tree: a compressed trie of all suffixes (Ukkonen, O(n)). It answers the same questions as SA + LCP + RMQ with a tree you can DFS. It is heavy to write and memory-hungry; in practice SA + LCP is the portable replacement.
  • Rule of thumb: one fixed string, offline queries → SA + LCP. Online or "after each appended character" → SAM. A one-off "does some length-L substring repeat?" → hashing + binary search (shortest code).

Aho–Corasick: many patterns, one pass

Searching for k patterns with KMP costs k passes over the text. Aho–Corasick puts all patterns in a trie and adds a failure link to every node: the node for the longest proper suffix of the current string that is also a path in the trie. That is the prefix function, generalised from one pattern to a tree of patterns. Reading the text then works exactly like KMP: follow the trie edge if it exists, otherwise follow failure links until it does (or you reach the root).

Two details make it correct:

  • Build the failure links in BFS order. A node's link points to a shorter string, so it must already be finished when you process the node.
  • Output links. When you arrive at node v, every pattern that is a suffix of v's string has also matched, not only v's own pattern. In the default example, reaching she also reports he. Merge out[v] += out[fail[v]], or keep a "dictionary link" to the nearest terminal node on the failure chain.
from collections import deque

class AhoCorasick:
    def __init__(self, words):
        self.words = words
        self.go, self.fail, self.out = [{}], [0], [[]]
        for idx, w in enumerate(words):                  # 1. plain trie
            u = 0
            for ch in w:
                if ch not in self.go[u]:
                    self.go[u][ch] = len(self.go)
                    self.go.append({}); self.fail.append(0); self.out.append([])
                u = self.go[u][ch]
            self.out[u].append(idx)
        q = deque(self.go[0].values())                   # 2. failure links, BFS
        while q:
            u = q.popleft()
            for ch, v in self.go[u].items():
                f = self.fail[u]
                while f and ch not in self.go[f]:
                    f = self.fail[f]
                nxt = self.go[f].get(ch, 0)
                self.fail[v] = nxt if nxt != v else 0     # depth-1 nodes link to the root
                self.out[v] = self.out[v] + self.out[self.fail[v]]
                q.append(v)

    def search(self, text):                              # yields (start, word index)
        u = 0
        for i, ch in enumerate(text):
            while u and ch not in self.go[u]:
                u = self.fail[u]
            u = self.go[u].get(ch, 0)
            for idx in self.out[u]:
                yield i - len(self.words[idx]) + 1, idx

            }
        }
    }

Parsing: small state machines

Parsing problems are graded on edge cases, not on algorithms. The reliable approach is to write the accepted language down as a state machine, a table of state × character class → next state, and then the code is a single loop. When a branch-heavy solution keeps failing on a hidden test, the table is usually what fixes it.

String to Integer (atoi)

Four phases in order: skip spaces → optional sign → digits → stop at the first non-digit. The only real trap is overflow, and the fix is to check before you multiply: res * 10 + d > LIMIT is the same as res > (LIMIT − d) / 10 in integers, which cannot overflow.

def my_atoi(s):
    INT_MAX, INT_MIN = 2**31 - 1, -2**31
    i, n = 0, len(s)
    while i < n and s[i] == " ":
        i += 1
    sign = 1
    if i < n and s[i] in "+-":
        sign = -1 if s[i] == "-" else 1
        i += 1
    res = 0
    while i < n and "0" <= s[i] <= "9":      # not isdigit(): that accepts "²" and "٣"
        d = ord(s[i]) - 48
        if res > (INT_MAX - d) // 10:        # res*10 + d would exceed INT_MAX
            return INT_MAX if sign == 1 else INT_MIN
        res = res * 10 + d
        i += 1
    return sign * res

static int MyAtoi(string s)
{
    int i = 0, n = s.Length, sign = 1, res = 0;
    while (i < n && s[i] == ' ') i++;
    if (i < n && (s[i] == '+' || s[i] == '-')) sign = s[i++] == '-' ? -1 : 1;
    while (i < n && char.IsAsciiDigit(s[i]))
    {
        int d = s[i++] - '0';
        if (res > (int.MaxValue - d) / 10) return sign == 1 ? int.MaxValue : int.MinValue;
        res = res * 10 + d;
    }
    return sign * res;
}

Valid Number as a DFA

Valid Number accepts things like 2, -0.1, 4., .5, -90E3 and +6e-1, and rejects e3, 1e, ., --6 and 99e2.5. Classify each character as digit, sign, dot, exp or anything else, then walk this 8-state machine. A missing transition means "invalid". At the end, the string is valid only if you stopped in an accepting state: after digits (2), after digits with a dot (4), or after exponent digits (7).

def is_number(s):
    T = {0: {"sign": 1, "digit": 2, "dot": 3}, 1: {"digit": 2, "dot": 3},
         2: {"digit": 2, "dot": 4, "exp": 5}, 3: {"digit": 4},
         4: {"digit": 4, "exp": 5}, 5: {"sign": 6, "digit": 7},
         6: {"digit": 7}, 7: {"digit": 7}}

    def cls(ch):
        if "0" <= ch <= "9": return "digit"
        if ch in "+-": return "sign"
        if ch == ".": return "dot"
        if ch in "eE": return "exp"
        return None

    state = 0
    for ch in s:
        state = T[state].get(cls(ch))
        if state is None:
            return False
    return state in (2, 4, 7)

static bool IsNumber(string s)
{
    // columns: digit, sign, dot, exp; -1 = dead
    int[,] T =
    {
        { 2, 1, 3, -1 }, { 2, -1, 3, -1 }, { 2, -1, 4, 5 }, { 4, -1, -1, -1 },
        { 4, -1, -1, 5 }, { 7, 6, -1, -1 }, { 7, -1, -1, -1 }, { 7, -1, -1, -1 },

}

Run-length encoding and String Compression

Group runs of equal characters: aaabccdddd → a3bc2d4. LeetCode's String Compression does it in place: a read pointer scans each run while a write pointer writes the character and its count. Writing never overtakes reading, because a run of length L ≥ 2 needs at most L − 1 digits.

def compress(chars):                         # LeetCode 443: returns the new length
    w = i = 0
    while i < len(chars):
        j = i
        while j < len(chars) and chars[j] == chars[i]:
            j += 1
        chars[w] = chars[i]
        w += 1
        if j - i > 1:
            for d in str(j - i):
                chars[w] = d
                w += 1
        i = j
    return w

static int Compress(char[] chars)
{

Rotations and the canonical minimum rotation

The rotations of s are exactly the length-n windows of s + s. A canonical form for a rotation class (necklaces, cyclic strings, "are these two rotations of each other?") is the lexicographically smallest rotation. Comparing all n rotations naively is O(n²). The two-candidate method is O(n): race candidate starts i and j, with k = how many characters agree. On a mismatch at offset k, the larger candidate loses, and so do the next k starts after it. If s[i+k] > s[j+k], then for every 0 ≤ q ≤ k the rotation at i + q is beaten by the one at j + q. A whole block is eliminated at once, so i and j together advance at most 2n.

def min_rotation(s):                         # start index of the smallest rotation
    n = len(s)
    i, j, k = 0, 1, 0
    while i < n and j < n and k < n:
        a, b = s[(i + k) % n], s[(j + k) % n]
        if a == b:
            k += 1
            continue
        if a > b:
            i += k + 1
        else:
            j += k + 1
        if i == j:
            j += 1
        k = 0
    return min(i, j)

def last_substring(s):                       # LeetCode 1163: the largest suffix, same race
    i, j, k, n = 0, 1, 0, len(s)
    while j + k < n:
        if s[i + k] == s[j + k]:
            k += 1
            continue
        if s[i + k] < s[j + k]:
            i = max(i + k + 1, j)            # i..i+k all lose; jump to at least j
            j = i + 1
        else:
            j += k + 1
        k = 0
    return s[i:]

static int MinRotation(string s)
{
    int n = s.Length, i = 0, j = 1, k = 0;
    while (i < n && j < n && k < n)
    {
        char a = s[(i + k) % n], b = s[(j + k) % n];
        if (a == b) { k++; continue; }
        if (a > b) i += k + 1; else j += k + 1;
        if (i == j) j++;
        k = 0;
    }
    return Math.Min(i, j);
}

static string LastSubstring(string s)
{
    int i = 0, j = 1, k = 0, n = s.Length;
    while (j + k < n)
    {
        if (s[i + k] == s[j + k]) { k++; continue; }
        if (s[i + k] < s[j + k]) { i = Math.Max(i + k + 1, j); j = i + 1; }
        else j += k + 1;
        k = 0;
    }
    return s[i..];
}

Orderly Queue is the classic follow-up: with k = 1 you can only rotate, so the answer is the minimum rotation; with k ≥ 2 any two neighbours can be swapped, so the answer is the sorted string.

Recognize it when you see…

  • "find the pattern", "first occurrence", "how many times does p occur (overlaps allowed)" → KMP / Z.
  • "longest prefix that is also a suffix", "smallest repeating unit", "built by repeating" → prefix function.
  • "add characters in front to make a palindrome" → π of s + '#' + reverse(s).
  • "longest palindromic substring" with n ≤ 1000 → expand; n ≥ 10⁵ or "two non-overlapping palindromes" → Manacher.
  • "longest substring that occurs twice", "number of distinct substrings" → suffix array + LCP or binary search + hashing.
  • "a list of forbidden or dictionary words, scan a long text or a stream" → Aho–Corasick.
  • "is t a rotation of s", "lexicographically smallest after rotations" → s + s and minimum rotation.
  • "parse", "valid", "convert to integer" → write the state machine first.

Pitfalls that cost real submissions

  • Quadratic building: res += ch in a loop over 10⁵ characters. Use "".join / StringBuilder.
  • Slicing inside loops: s[i:] == t or s.Substring(i) in a loop is a hidden O(n) per step. Compare with indices, spans, or hashes.
  • KMP after a full match: forgetting j = π[j−1] either misses overlapping matches or reads p[m] out of range.
  • Separator inside the alphabet: p + "#" + t breaks if # can appear in the input; π or Z values then cross the boundary. Use "\0" or a character outside the alphabet.
  • Z-array off by one: the Z-box is half-open [l, r). Mixing it with the closed form [l, r] gives r − i + 1 in one place and r − i in another. Pick one form and keep it everywhere.
  • Manacher index mapping: centre i in t with radius P[i] starts at (i − P[i]) / 2 in s and has length P[i]. Not P[i] / 2, and not 2·P[i] + 1.
  • Hash collisions: one 32-bit modulus with a fixed base, or ulong overflow arithmetic. Use a double mod or 2⁶¹ − 1 with a random base, and verify when the cost is acceptable.
  • Culture-sensitive C# comparisons: "ss".StartsWith("ß") may be true under some cultures. Pass StringComparison.Ordinal.
  • Aho–Corasick outputs: reporting only the node's own word misses patterns that are suffixes of it (he inside she).

1. Repeated String Match Medium

Problem. Return the minimum number of times a must be repeated so that b is a substring of the result, or −1.

Insight. If b occurs at all, its start lies inside the first copy of a (offset < |a|). The copies it touches therefore number either q = ⌈|b| / |a|⌉ or q + 1, and never more. So test exactly two strings, each in linear time with KMP.

Solution: two KMP checks, O(|a| + |b|)

def repeated_string_match(a, b):
    def occurs(text, pat):                   # KMP via pi of pat + sep + text
        s = pat + "\0" + text
        pi = [0] * len(s)
        for i in range(1, len(s)):
            j = pi[i - 1]
            while j > 0 and s[i] != s[j]:
                j = pi[j - 1]
            if s[i] == s[j]:
                j += 1
            pi[i] = j
            if j == len(pat):
                return True
        return False

    q = -(-len(b) // len(a))                 # ceil(|b| / |a|)
    for reps in (q, q + 1):
        if occurs(a * reps, b):
            return reps
    return -1

static int RepeatedStringMatch(string a, string b)
{
    static bool Occurs(string text, string pat)
    {
        string s = pat + "\0" + text;
        var pi = new int[s.Length];
        for (int i = 1; i < s.Length; i++)
        {
            int j = pi[i - 1];
            while (j > 0 && s[i] != s[j]) j = pi[j - 1];
            if (s[i] == s[j]) j++;
            pi[i] = j;
            if (j == pat.Length) return true;
        }
        return false;
    }

    int q = (b.Length + a.Length - 1) / a.Length;
    var sb = new StringBuilder();
    for (int k = 0; k < q; k++) sb.Append(a);
    if (Occurs(sb.ToString(), b)) return q;
    if (Occurs(sb.Append(a).ToString(), b)) return q + 1;
    return -1;
}

Time O(|a| + |b|), because q·|a| < |b| + |a|. Space is the same.

2. Sum of Scores of Built Strings Hard

Problem. The string s is built by prepending one character at a time, so the i-th intermediate string is a suffix of s. The score of a suffix is the length of its longest common prefix with s. Return the sum of all scores.

Insight. "The longest common prefix of the suffix starting at i with s" is the definition of z[i], and the whole string scores n. The answer is n + Σ z[i]. Step through the Z visualizer above with babab: z = [5, 0, 3, 0, 1], sum 9.

Solution: Z-function, O(n)

def sum_scores(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    return n + sum(z)

static long SumScores(string s)
{
    int n = s.Length;
    var z = new int[n];
    long total = n;
    for (int i = 1, l = 0, r = 0; i < n; i++)
    {
        if (i < r) z[i] = Math.Min(r - i, z[i - l]);
        while (i + z[i] < n && s[z[i]] == s[i + z[i]]) z[i]++;
        if (i + z[i] > r) { l = i; r = i + z[i]; }
        total += z[i];
    }
    return total;
}

Time O(n), space O(n). The answer can reach n(n+1)/2 ≈ 5·10⁹ for n = 10⁵, so C# needs long.

3. Longest Duplicate Substring, without hashing Hard

Problem. Return any longest substring that occurs at least twice (occurrences may overlap), or "".

Insight. Two occurrences of a substring are two suffixes sharing a prefix. Among all pairs of suffixes, the longest common prefix is achieved by neighbours in sorted order: a suffix shares more with its neighbour than with anything further away. So the answer is max(lcp). The hashing page solves the same problem with binary search + rolling hash; this version is exact and has no collision risk. Try banana in the LCP visualizer: the maximum is 3, at ana.

Solution: suffix array + Kasai, O(n log² n)

def longest_dup_substring(s):
    sa = suffix_array(s)                     # from the suffix array section
    lcp = lcp_array(s, sa)
    k = max(range(len(s)), key=lcp.__getitem__, default=0)
    return s[sa[k]:sa[k] + lcp[k]] if s else ""

static string LongestDupSubstring(string s)
{
    if (s.Length == 0) return "";
    int[] sa = SuffixArray(s), lcp = LcpArray(s, sa);
    int k = 0;
    for (int t = 1; t < lcp.Length; t++) if (lcp[t] > lcp[k]) k = t;

}

Time O(n log² n) for the sort, O(n) for Kasai. Space O(n). For n = 3·10⁴ the Python version runs in well under a second.

4. Distinct Echo Substrings Hard

Problem. Count distinct non-empty substrings of the form aa, a string concatenated with itself (n ≤ 2000).

Insight. Fix the half-length L and slide i. Keep run = how many consecutive positions ending at i satisfy s[i] = s[i + L]. When run ≥ L, the L characters ending at i equal the next L, so s[i−L+1 .. i+L] is an echo. That check is exact and O(1). Hashing is needed only to deduplicate the echoes in a set without copying them. The total is O(n²).

Solution: run counter + prefix hashes, O(n²)

def distinct_echo_substrings(text):
    n, H, seen = len(text), StringHash(text), set()   # StringHash from the hashing section
    for L in range(1, n // 2 + 1):
        run = 0
        for i in range(n - L):
            run = run + 1 if text[i] == text[i + L] else 0
            if run >= L:                               # text[i-L+1..i] == text[i+1..i+L]
                seen.add((L, H.get(i - L + 1, 2 * L)))
    return len(seen)

static int DistinctEchoSubstrings(string text)
{
    int n = text.Length;
    var h = new StringHash(text);                      // from the hashing section
    var seen = new HashSet<(int, long)>();
    for (int L = 1; 2 * L <= n; L++)
    {
        int run = 0;
        for (int i = 0; i + L < n; i++)
        {
            run = text[i] == text[i + L] ? run + 1 : 0;
            if (run >= L) seen.Add((L, h.Get(i - L + 1, 2 * L)));
        }
    }
    return seen.Count;
}

Time O(n²) with O(1) work per (L, i); space O(n²) in the worst case for the set (bounded by the number of distinct echoes).

5. Maximum Product of the Length of Two Palindromic Substrings Expert

Problem. Choose two non-overlapping odd-length palindromic substrings and maximise the product of their lengths (n ≤ 10⁵).

Insight. Split the string at every boundary: answer = max over i of best_left[i] · best_right[i+1], where best_left[i] is the longest odd palindrome inside s[0..i]. Manacher gives the maximal odd palindrome at every centre in O(n). A maximal palindrome of length 2d − 1 ending at e also gives one of length 2d − 3 ending at e − 1 (peel one character from each end). So a right-to-left sweep end[e] = max(end[e], end[e+1] − 2) finds the longest palindrome ending exactly at each e, and a prefix max turns that into best_left. Mirror everything for the right side.

Solution: odd Manacher + two sweeps, O(n)

def max_product(s):
    n = len(s)
    d1, l, r = [0] * n, 0, -1               # d1[i]: odd radius (1 = just s[i])
    for i in range(n):
        k = 1 if i > r else min(d1[l + r - i], r - i + 1)
        while i - k >= 0 and i + k < n and s[i - k] == s[i + k]:
            k += 1
        d1[i] = k
        if i + k - 1 > r:
            l, r = i - k + 1, i + k - 1
    end, start = [1] * n, [1] * n           # longest odd palindrome ending / starting exactly here
    for i in range(n):
        end[i + d1[i] - 1] = max(end[i + d1[i] - 1], 2 * d1[i] - 1)
        start[i - d1[i] + 1] = max(start[i - d1[i] + 1], 2 * d1[i] - 1)
    for e in range(n - 2, -1, -1):
        end[e] = max(end[e], end[e + 1] - 2)        # peel both ends
    for b in range(1, n):
        start[b] = max(start[b], start[b - 1] - 2)
    for e in range(1, n):
        end[e] = max(end[e], end[e - 1])            # best inside s[0..e]
    for b in range(n - 2, -1, -1):
        start[b] = max(start[b], start[b + 1])      # best inside s[b..]
    return max(end[i] * start[i + 1] for i in range(n - 1))

static long MaxProduct(string s)
{
    int n = s.Length;
    var d1 = new int[n];
    for (int i = 0, l = 0, r = -1; i < n; i++)
    {
        int k = i > r ? 1 : Math.Min(d1[l + r - i], r - i + 1);
        while (i - k >= 0 && i + k < n && s[i - k] == s[i + k]) k++;
        d1[i] = k;
        if (i + k - 1 > r) { l = i - k + 1; r = i + k - 1; }
    }
    var end = new int[n];
    var start = new int[n];
    Array.Fill(end, 1);
    Array.Fill(start, 1);
    for (int i = 0; i < n; i++)
    {
        end[i + d1[i] - 1] = Math.Max(end[i + d1[i] - 1], 2 * d1[i] - 1);
        start[i - d1[i] + 1] = Math.Max(start[i - d1[i] + 1], 2 * d1[i] - 1);
    }
    for (int e = n - 2; e >= 0; e--) end[e] = Math.Max(end[e], end[e + 1] - 2);
    for (int b = 1; b < n; b++) start[b] = Math.Max(start[b], start[b - 1] - 2);
    for (int e = 1; e < n; e++) end[e] = Math.Max(end[e], end[e - 1]);
    for (int b = n - 2; b >= 0; b--) start[b] = Math.Max(start[b], start[b + 1]);

Time O(n), space O(n). The product can exceed 2³¹ (5·10⁴ · 5·10⁴), so use long in C#.

6. Stream of Characters Hard

Problem. Given a word list, after each streamed letter answer "does some suffix of the stream equal a word?"

Insight. This is Aho–Corasick with the text arriving one character at a time. The automaton state after each letter is the longest suffix of the stream that is a path in the trie. A word ends at the current position exactly when the state, or some state on its failure chain, is terminal. Precompute that as a boolean hit[v] = terminal[v] or hit[fail[v]] during the BFS, and each query is amortised O(1). Default example in the visualizer above: after streaming …she, both she and he are suffixes. The tries page solves it with a reversed trie in O(longest word) per query instead.

Solution: Aho–Corasick automaton, O(Σ|w|·σ) build, O(1) per query

from collections import deque

class StreamChecker:
    def __init__(self, words):
        nxt, hit = [[0] * 26], [False]
        for w in words:
            u = 0
            for ch in w:
                c = ord(ch) - 97
                if not nxt[u][c]:
                    nxt[u][c] = len(nxt)
                    nxt.append([0] * 26)
                    hit.append(False)
                u = nxt[u][c]
            hit[u] = True
        fail = [0] * len(nxt)
        q = deque(v for v in nxt[0] if v)
        while q:
            u = q.popleft()
            hit[u] = hit[u] or hit[fail[u]]          # some suffix is a word
            for c in range(26):
                v = nxt[u][c]
                if v:
                    fail[v] = nxt[fail[u]][c] if u else 0
                    q.append(v)
                else:
                    nxt[u][c] = nxt[fail[u]][c]      # goto automaton
        self.nxt, self.hit, self.state = nxt, hit, 0

    def query(self, letter):
        self.state = self.nxt[self.state][ord(letter) - 97]
        return self.hit[self.state]

public class StreamChecker
{
    readonly List<int[]> nxt = new() { new int[26] };
    readonly List<bool> hit = new() { false };
    int state;

    public StreamChecker(string[] words)
    {
        foreach (string w in words)
        {
            int u = 0;
            foreach (char ch in w)
            {
                int c = ch - 'a';
                if (nxt[u][c] == 0) { nxt[u][c] = nxt.Count; nxt.Add(new int[26]); hit.Add(false); }
                u = nxt[u][c];
            }
            hit[u] = true;
        }
        var fail = new int[nxt.Count];
        var q = new Queue<int>();
        for (int c = 0; c < 26; c++) if (nxt[0][c] != 0) q.Enqueue(nxt[0][c]);
        while (q.Count > 0)
        {
            int u = q.Dequeue();
            hit[u] = hit[u] || hit[fail[u]];
            for (int c = 0; c < 26; c++)
            {
                int v = nxt[u][c];
                if (v != 0) { fail[v] = u == 0 ? 0 : nxt[fail[u]][c]; q.Enqueue(v); }
                else nxt[u][c] = nxt[fail[u]][c];
            }
        }
    }

    public bool Query(char letter)
    {
        state = nxt[state][letter - 'a'];
        return hit[state];
    }
}

Build O(Σ|w| · 26) time and space; each query O(1). hit[fail[u]] is final when u is processed, because fail[u] is shallower and BFS finished it first.

7. Longest Common Subpath Expert

Problem. m friends each walk a path (an array of city ids). Return the length of the longest contiguous subpath shared by every path (total length ≤ 10⁵).

Insight. If a common subpath of length L exists, then one of every shorter length exists too (take its prefix), so the answer can be binary searched. For a fixed L, hash every window of length L in each path and intersect the sets. That is O(total) per check, O(total · log) overall. The "characters" are integers up to 10⁵, so the base must exceed the largest id (+1). Collisions are a real risk here (up to 10⁵ hashes per set, about 17 rounds), so use a double modulus.

Solution: binary search on length + double rolling hash, O(total · log(min len))

import random

def longest_common_subpath(n, paths):
    M1, M2 = 1_000_000_007, 1_000_000_009
    B = random.randrange(n + 2, 10**9)

    def window_hashes(p, L):
        p1, p2 = pow(B, L, M1), pow(B, L, M2)
        h1 = h2 = 0
        out = set()
        for k, city in enumerate(p):
            h1 = (h1 * B + city + 1) % M1
            h2 = (h2 * B + city + 1) % M2
            if k >= L:                                   # drop p[k-L]
                h1 = (h1 - (p[k - L] + 1) * p1) % M1
                h2 = (h2 - (p[k - L] + 1) * p2) % M2
            if k >= L - 1:
                out.add((h1 << 32) | h2)
        return out

    def common(L):
        acc = window_hashes(paths[0], L)
        for p in paths[1:]:
            acc &= window_hashes(p, L)
            if not acc:
                return False
        return True

    lo, hi = 0, min(map(len, paths))
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if common(mid):
            lo = mid
        else:
            hi = mid - 1
    return lo

static int LongestCommonSubpath(int n, int[][] paths)
{
    const long M1 = 1_000_000_007, M2 = 1_000_000_009;
    long B = Random.Shared.NextInt64(n + 2, 1_000_000_000);

    HashSet<long> WindowHashes(int[] p, int L)
    {
        long p1 = 1, p2 = 1;
        for (int k = 0; k < L; k++) { p1 = p1 * B % M1; p2 = p2 * B % M2; }
        long h1 = 0, h2 = 0;
        var set = new HashSet<long>();
        for (int k = 0; k < p.Length; k++)
        {
            h1 = (h1 * B + p[k] + 1) % M1;
            h2 = (h2 * B + p[k] + 1) % M2;
            if (k >= L)
            {
                h1 = ((h1 - (p[k - L] + 1) * p1) % M1 + M1) % M1;
                h2 = ((h2 - (p[k - L] + 1) * p2) % M2 + M2) % M2;
            }
            if (k >= L - 1) set.Add((h1 << 32) | h2);
        }
        return set;
    }

    bool Common(int L)
    {
        var acc = WindowHashes(paths[0], L);
        for (int k = 1; k < paths.Length && acc.Count > 0; k++) acc.IntersectWith(WindowHashes(paths[k], L));
        return acc.Count > 0;
    }

    int lo = 0, hi = paths.Min(p => p.Length);
    while (lo < hi)
    {
        int mid = (lo + hi + 1) / 2;
        if (Common(mid)) lo = mid; else hi = mid - 1;
    }
    return lo;
}

Time O(total · log(min length)) expected; space O(max path length). h1 * B is below 10⁹ · 10⁹ = 10¹⁸, which fits in long. (p[k − L] + 1) * p1 is below 10⁵ · 10⁹, also safe.

Self-check

Compute π for aabaaab by hand.

[0, 1, 0, 1, 2, 2, 3]. At i = 5 the border aa cannot be extended by a (the next character after it is b), so it falls back to a and extends that to aa. At i = 6, aa + b matches aab, giving 3. Check it in the prefix-function visualizer.

What is the smallest period of abababa, and is the string a whole repetition of a block?

π[6] = 5 (ababa), so the period is 7 − 5 = 2 (ab). 2 does not divide 7, so it is not a whole repetition; it is ab repeated 3.5 times. Repeated Substring Pattern returns false.

Why does KMP run in O(n) even though it has a while loop inside the for loop?

j increases by at most 1 per text character, so by at most n in total. Each iteration of the while loop lowers j by at least 1, and j never goes below 0, so there are at most n fallbacks across the whole run. Total work ≤ 2n. This amortised argument (a potential that rises slowly and is spent by the inner loop) is the same one behind Z, Manacher and Kasai, each with a different potential: r for Z and Manacher, h for Kasai.

A friend's Rabin–Karp uses B = 26 and M = 13 and reports matches everywhere. Why?

26 ≡ 0 (mod 13), so B^k ≡ 0 for every k ≥ 1 and the hash of any window is just the value of its last character. Every window ending in the same letter "matches". The base must be invertible mod M (gcd(B, M) = 1). Use a large prime M, a random base, and verify candidates.

In Manacher's case 2 (the mirror's palindrome sticks out past L), why is P[i] exactly r − i and not larger?

Let d = r − i = i' − L, and recall the big palindrome stopped because t[L − 1] ≠ t[r + 1]. The mirror's palindrome is longer than d, so the character just outside its radius-d window on the right, t[i' + d + 1], equals t[i' − d − 1] = t[L − 1]. That character lies inside the big palindrome, and its reflection across c is t[i − d − 1], the character just left of i's radius-d window. So t[i − d − 1] = t[L − 1]. For i's palindrome to grow past d, it would need t[i − d − 1] = t[r + 1], which would mean t[L − 1] = t[r + 1]: a contradiction. So P[i] = r − i, with no comparison needed.

How many distinct substrings does banana have? Use sa and lcp.

sa = [5, 3, 1, 0, 4, 2] and lcp = [0, 1, 3, 0, 0, 2], so Σ lcp = 6. Total substrings with repetition is 6·7/2 = 21, giving 21 − 6 = 15 distinct. Each suffix contributes its length minus the prefix it shares with its sorted predecessor.

Why must Aho–Corasick compute failure links in BFS order rather than DFS?

fail[v] is computed from fail[parent] and points to a strictly shorter string, which is a shallower node. BFS processes nodes by depth, so every shallower node, including the target's own failure chain and its full goto row, is finished first. DFS can reach a deep node before the shallower node it needs.

You need the longest substring present in each of 5 strings (total length 2·10⁵). Which tools work?

Two standard options. (1) Binary search on L, intersecting rolling-hash sets for each string (the Longest Common Subpath solution), O(total · log). (2) A generalised suffix array over s1 # s2 $ s3 … with distinct separators, then a sliding window over sa that covers all 5 colours while tracking the window's minimum lcp. Option 1 is far shorter to write; option 2 is exact.
