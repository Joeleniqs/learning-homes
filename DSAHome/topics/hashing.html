Hashing Patterns

How hash tables work inside, then frequency maps, grouping by canonical keys, complement lookups and rolling hashes.

Beginner → Advanced~45 min studyUpdated 2026-11-03

What it is and when you need it

A hash table stores keys (and optionally a value per key) so that "is this key here, and what is attached to it?" costs O(1) on average, no matter how many keys there are. It does that by turning the key itself into an array index. There is no searching, no comparing against the other keys and no ordering. In Python it is dict and set; in C# it is Dictionary<TKey, TValue> and HashSet<T>.

That one capability, constant-time exact lookup, turns a huge number of O(n²) "for each element, look through the others" solutions into O(n) single passes. It is the most common tool in interview problems, and also the one most often used without understanding what it costs.

The rule. Whenever an inner loop exists only to find something by exact value ("is there an earlier x with …", "how many times have I seen …", "where did I last see …"), replace that loop with a hash map lookup. Then ask: what is the key, and what is the value? Getting those two right is the whole skill.

Unsorted array

Lookup by value is a scan: O(n). Fine for 10 items, fatal inside another loop over n items.

Sorted array / balanced tree

Lookup is O(log n), and you also get order: min, max, predecessor, ranges. Use it when the question involves order.

Hash table

Lookup, insert and delete are O(1) on average. No order at all; extra memory; worst case O(n) if hashing goes wrong.

This page builds the data structure from the inside (so you know why it is fast and when it is not), then works through the six patterns that solve nearly every hashing problem, with a visualizer for each. Prerequisites: arrays and Complexity Analysis. Related pages: Prefix Sums (pattern 4 lives on both pages), Sliding Window (windows usually keep a frequency map), Sorting (the main alternative to hashing) and String Algorithms (rolling hashes in depth).

Inside a hash table

Every hash table makes the same three decisions:

  1. Hash function: how a key becomes a number.
  2. Collision strategy: what to do when two keys want the same slot (chaining or open addressing).
  3. Resize policy: when to grow the array, so slots stay mostly free.

Step 1: the hash function

A hash function maps a key to an integer. The table then reduces that integer to a slot with hash % m (or hash & (m − 1) when m is a power of two). Two properties are non-negotiable, and two more make the table fast:

Property Why it matters
Deterministic The same key must give the same hash every time it is asked, or a stored key can never be found again.
Consistent with equality If a == b then hash(a) == hash(b). The table only compares keys that land in the same place, so equal keys with different hashes are treated as different keys.
Spreads keys evenly Each slot should get about n/m keys, whatever the input looks like. Clustering in the hash becomes clustering in the table.
Cheap It runs on every operation. Hashing a string costs O(length); hashing an int is nearly free.

Note what is not required: different keys may share a hash. That is a collision, and it is unavoidable (there are more possible strings than integers). The table handles it; the hash function just keeps it rare.

What the runtimes actually do:

  • Python: hash(n) for an int is n itself (reduced mod 2⁶¹ − 1), except hash(-1) == -2 because −1 is reserved as an error code inside CPython. Strings and bytes use SipHash with a random seed per process (PYTHONHASHSEED), so hash("cat") changes between runs. Tuples combine their elements' hashes; frozenset hashes are order-independent.
  • C#: int.GetHashCode() returns the value itself. string.GetHashCode() is randomized per process (Marvin hash). Records, tuples and anonymous types generate a field-by-field hash for you. Plain classes hash by reference unless you override GetHashCode and Equals.

Step 2a: collisions by separate chaining

The simplest strategy: each slot (a bucket) holds a small list of all keys that hashed there. Insert appends to the bucket's list; lookup walks only that one list. If the hash spreads keys evenly, every list has about α = n/m keys, the load factor, so every operation costs O(1 + α).

Step through it below. Watch how a lookup only ever looks inside one bucket, and how colliding keys share a chain. Then try m = 10 with keys that are all multiples of 10: every key lands in bucket 0 and the table degrades into a linked list.

Here is a complete chaining hash set, including the resize from the next section. Read it once; you will never have to write one in an interview, but every later section assumes you know what it does.

class ChainedSet:
    """A hash set using separate chaining; doubles when the load factor passes 1."""

    def __init__(self, m: int = 8):
        self.m, self.n = m, 0
        self.buckets: list[list] = [[] for _ in range(m)]

    def _bucket(self, key) -> list:
        return self.buckets[hash(key) % self.m]

    def contains(self, key) -> bool:
        return any(k == key for k in self._bucket(key))

    def add(self, key) -> bool:
        b = self._bucket(key)
        if any(k == key for k in b):
            return False
        b.append(key)
        self.n += 1
        if self.n > self.m:              # load factor above 1: grow
            self._resize(2 * self.m)
        return True

    def remove(self, key) -> bool:
        b = self._bucket(key)
        for i, k in enumerate(b):
            if k == key:
                b[i] = b[-1]             # O(1) unordered delete
                b.pop()
                self.n -= 1
                return True
        return False

    def _resize(self, new_m: int) -> None:
        old = self.buckets
        self.m, self.buckets = new_m, [[] for _ in range(new_m)]
        for b in old:
            for k in b:                  # every key must be rehashed:
                self._bucket(k).append(k)  # its bucket depends on m

public class ChainedSet<T>
{
    private List<T>[] buckets;
    private int n;
    private readonly IEqualityComparer<T> eq = EqualityComparer<T>.Default;

    public ChainedSet(int m = 8) { buckets = NewTable(m); }
    public int Count => n;

    private static List<T>[] NewTable(int m)
    {
        var t = new List<T>[m];
        for (int i = 0; i < m; i++) t[i] = new List<T>();
        return t;
    }

    // Mask off the sign bit so a negative hash still gives a valid index.
    private List<T> Bucket(T key, List<T>[] table) =>
        table[(eq.GetHashCode(key) & 0x7FFFFFFF) % table.Length];

    public bool Contains(T key) => Bucket(key, buckets).Exists(k => eq.Equals(k, key));

    public bool Add(T key)
    {
        var b = Bucket(key, buckets);
        if (b.Exists(k => eq.Equals(k, key))) return false;
        b.Add(key);
        if (++n > buckets.Length) Resize(2 * buckets.Length);
        return true;
    }

    public bool Remove(T key)
    {
        var b = Bucket(key, buckets);
        int i = b.FindIndex(k => eq.Equals(k, key));
        if (i < 0) return false;
        b[i] = b[^1];
        b.RemoveAt(b.Count - 1);
        n--;
        return true;
    }

    private void Resize(int newM)
    {
        var table = NewTable(newM);
        foreach (var b in buckets)
            foreach (var k in b)
                Bucket(k, table).Add(k);
        buckets = table;
    }
}

hash % m with a negative hash. In Python % always returns a non-negative result for positive m, so hash(k) % m is safe. In C# (and Java, C++) -7 % 4 == -3, which is not a valid index. Mask the sign bit (h & 0x7FFFFFFF) or normalise with ((h % m) + m) % m. The same trap appears in every "remainder as a key" problem later on.

Step 2b: collisions by open addressing

Open addressing stores the keys in the array itself, one key per slot, no lists. When a key's home slot h(k) is taken, it follows a fixed probe sequence of other slots until it finds a free one. A lookup replays the same sequence and stops at the key, or at an EMPTY slot, which proves the key is absent (if it were present, insertion would have put it there or earlier).

Probe sequence i-th slot tried Strength Weakness
Linear (h + i) mod m Neighbouring slots: very cache friendly Primary clustering: occupied runs grow and merge, and long runs attract more keys
Quadratic (h + i²) mod m Breaks up runs May visit only some slots. With m prime it is guaranteed to find a free slot while the table is at most half full
Double hashing (h + i · h2(k)) mod m Each key gets its own step size; almost no clustering Needs h2(k) ≠ 0 and coprime with m (use m prime)

Try the visualizer with each sequence. Two experiments are worth doing. First, m = 8 with quadratic probing and keys 0, 8, 16, 24, 32, 40: they all start at slot 0, and the sequence 0, 1, 4, 1, 0, 1, … only ever reaches 3 of the 8 slots, so the fourth key is rejected even though five slots are free. Second, delete a key and then look up a key that probed past it.

Deletion is the subtle part of open addressing. You cannot simply empty a slot, because the EMPTY slot would cut every probe path that passed through it:

class OpenSet:
    """Open addressing with linear probing and tombstones; grows at 2/3 full."""
    _EMPTY, _DEL = object(), object()     # unique sentinels, never equal to a key

    def __init__(self, m: int = 8):
        self.t = [self._EMPTY] * m
        self.n = self.used = 0            # used = keys + tombstones

    def _probe(self, key):
        m = len(self.t)
        i = hash(key) % m
        for _ in range(m):
            yield i
            i = (i + 1) % m

    def contains(self, key) -> bool:
        for i in self._probe(key):
            if self.t[i] is self._EMPTY:
                return False
            if self.t[i] is not self._DEL and self.t[i] == key:
                return True
        return False

    def add(self, key) -> bool:
        tomb = None
        for i in self._probe(key):
            s = self.t[i]
            if s is self._EMPTY:
                break
            if s is self._DEL:
                if tomb is None:
                    tomb = i
            elif s == key:
                return False
        else:
            i = None                      # no EMPTY slot on the whole path
        if tomb is not None:
            self.t[tomb] = key            # reuse a tombstone: `used` unchanged
        else:
            self.t[i] = key
            self.used += 1
        self.n += 1
        if 3 * self.used >= 2 * len(self.t):
            self._rebuild()
        return True

    def remove(self, key) -> bool:
        for i in self._probe(key):
            s = self.t[i]
            if s is self._EMPTY:
                return False
            if s is not self._DEL and s == key:
                self.t[i] = self._DEL     # tombstone, NOT empty
                self.n -= 1
                return True
        return False

    def _rebuild(self) -> None:
        keys = [s for s in self.t if s is not self._EMPTY and s is not self._DEL]
        self.t = [self._EMPTY] * max(8, 4 * len(keys))  # drops all tombstones
        self.n = self.used = 0
        for k in keys:
            self.add(k)

public class OpenSet
{
    private enum State : byte { Empty, Full, Deleted }
    private int[] keys = new int[8];
    private State[] state = new State[8];
    private int n, used;                  // used = keys + tombstones
    public int Count => n;

    private int Home(int key, int m) => (key.GetHashCode() & 0x7FFFFFFF) % m;

    public bool Contains(int key)
    {
        int m = keys.Length;
        for (int p = 0, i = Home(key, m); p < m; p++, i = (i + 1) % m)
        {
            if (state[i] == State.Empty) return false;
            if (state[i] == State.Full && keys[i] == key) return true;
        }
        return false;
    }

    public bool Add(int key)
    {
        int m = keys.Length, tomb = -1, slot = -1;
        for (int p = 0, i = Home(key, m); p < m; p++, i = (i + 1) % m)
        {
            if (state[i] == State.Empty) { slot = i; break; }
            if (state[i] == State.Deleted) { if (tomb < 0) tomb = i; }
            else if (keys[i] == key) return false;
        }
        if (tomb >= 0) slot = tomb;       // reuse a tombstone: used unchanged
        else used++;
        keys[slot] = key;
        state[slot] = State.Full;
        n++;
        if (3 * used >= 2 * keys.Length) Rebuild();
        return true;
    }

    public bool Remove(int key)
    {
        int m = keys.Length;
        for (int p = 0, i = Home(key, m); p < m; p++, i = (i + 1) % m)
        {
            if (state[i] == State.Empty) return false;
            if (state[i] == State.Full && keys[i] == key)
            {
                state[i] = State.Deleted;  // tombstone, NOT empty
                n--;
                return true;
            }
        }
        return false;
    }

    private void Rebuild()
    {
        var live = new List<int>();
        for (int i = 0; i < keys.Length; i++)
            if (state[i] == State.Full) live.Add(keys[i]);
        int m = Math.Max(8, 4 * live.Count);
        keys = new int[m];
        state = new State[m];
        n = used = 0;
        foreach (int k in live) Add(k);
    }
}

Why the rebuild counts tombstones. Tombstones are never EMPTY, so a lookup for a missing key walks over them. A table that sees many inserts and deletes can end up with almost no EMPTY slots, and then every miss scans the whole array. That is why the trigger above uses used (keys + tombstones), and why the rebuild re-inserts only live keys. CPython's dict does the same: deleted entries count toward the resize threshold.

Step 3: load factor and resizing

Whatever the collision strategy, performance depends on the load factor α = n/m. With chaining, the expected chain length is α. With linear probing, an unsuccessful search costs about ½(1 + 1/(1 − α)²) probes: 2.5 at α = ½, 8.5 at α = ¾, 50.5 at α = 0.9. So every table keeps α below a threshold and resizes when an insert would cross it: allocate a bigger array, then re-insert every key, because each key's slot depends on m.

A resize costs O(n). The question is whether that ruins the O(1) promise. Step through the visualizer with "double", then switch growth to "add 4" and compare the "work / n" stat.

The argument in words: after a resize to capacity 2c, at least c more cheap inserts happen before the next resize, which then copies about 2c keys. Charge each cheap insert 3 units instead of 1 and the extra 2 per insert pays in advance for its own future copy plus one older key's copy. The bank never goes negative, so n inserts cost at most 3n: amortized O(1) per insert. Individual inserts can still be slow (a resize of a million keys is a visible pause), which matters for latency-sensitive code but never for algorithm analysis.

Runtime Strategy Resizes when Grows to
CPython dict Open addressing, perturbed probing, separate compact entries array used slots reach 2/3 of the index table next power of two ≥ 3 × live keys
CPython set Open addressing, short linear runs then perturbation fill reaches 60% about 4× (small) or 2× (large)
.NET Dictionary / HashSet Chaining through int links inside one entries array count reaches capacity (α = 1) next prime ≥ 2 × count
Java HashMap Chaining; a chain of 8+ becomes a red-black tree size > 0.75 × capacity 2 × capacity (power of two)

Pre-size when you know n. new Dictionary<int, int>(n) and new HashSet<int>(n) allocate once instead of resizing log₂ n times. Python has no capacity argument, but dict.fromkeys(keys) and building with a comprehension are faster than repeated d[k] = v in a loop. On LeetCode this rarely changes the verdict; in production hot loops it can halve the time.

How production tables are actually built

Two details from real implementations explain behaviour you will see:

  • Cached hashes. Both CPython and .NET store each key's full hash code next to it. A lookup first compares the stored hash with the probe's hash and only calls __eq__ / Equals when they match. That is why a slow Equals rarely matters, and why a bad GetHashCode (many equal hashes) hurts so much: every collision becomes a real Equals call.
  • Ordering. Python dicts iterate in insertion order (a language guarantee since 3.7) because iteration walks the dense entries array. set has no order guarantee. .NET Dictionary usually iterates in insertion order until the first Remove, after which freed slots are reused and the order breaks: treat it as unordered.

What "O(1)" really means

Operation Average Worst case When the worst case happens
lookup / contains O(1) O(n) all keys share a bucket (bad hash or adversarial input)
insert O(1) amortized O(n) a resize, or the same bad-hash case
delete O(1) O(n) bad hash
iterate all keys O(n + m) O(n + m) always: empty slots are visited too
hash a key of length L O(L) O(L) always: strings and tuples are not free to hash

The last row is the one people forget: a dict keyed by strings of length L costs O(L) per operation, so "O(n) with a hash map" over n strings of length L is really O(n · L). Likewise, a key like tuple(sorted(word)) costs O(L log L) to build before the dict even sees it.

Adversarial collisions are real. Because integer hashes are the identity, an attacker who knows the table size can choose keys that all collide. On Codeforces, "anti-hash" tests routinely push C++ unordered_map and Java HashMap<Long, …> solutions to O(n²) (Java's tree bins soften the blow). Python's perturbed probing mixes in the high bits, which helps, and string hashing is randomized per process in both Python and .NET. Mitigations when you face hostile input: randomize the hash (XOR with a random salt, or a splitmix64 mixer), or switch to a sorted structure with a guaranteed O(log n). LeetCode does not do this, so plain dicts are fine there.

Modifying while iterating. Python raises RuntimeError: dictionary changed size during iteration; C# throws InvalidOperationException when you add during a foreach (removing is allowed since .NET Core 3.0, but do not rely on it for clarity). Iterate over a snapshot instead: for k in list(d): or foreach (var k in d.Keys.ToList()).

defaultdict and Counter reads. defaultdict inserts on any d[k] read, which silently grows the dict and changes len(d). Counter returns 0 for a missing key without inserting, but Counter entries can be zero or negative after c[k] -= 1, and len(c) still counts them. When "number of distinct elements in the window" matters (sliding window problems), delete the key when its count reaches 0.

Custom keys: equality and hash must agree

A key type needs two things that agree with each other: equality (__eq__ / Equals) and a hash (__hash__ / GetHashCode) such that equal objects have equal hashes. Break that and lookups silently fail.

from dataclasses import dataclass

@dataclass(frozen=True)        # frozen: generates __eq__ AND __hash__ from the fields
class Point:
    x: int
    y: int

pts = {Point(1, 2), Point(1, 2), Point(3, 4)}
assert len(pts) == 2

class Bad:
    def __init__(self, v): self.v = v
    def __eq__(self, other): return self.v == other.v
    # Defining __eq__ without __hash__ sets __hash__ = None: Bad(1) is unhashable.

class Manual:
    def __init__(self, x, y): self._x, self._y = x, y
    def __eq__(self, o): return isinstance(o, Manual) and (self._x, self._y) == (o._x, o._y)
    def __hash__(self): return hash((self._x, self._y))   # hash the same fields as __eq__

// A record (class or struct) generates Equals and GetHashCode from its fields.
public readonly record struct Point(int X, int Y);

// A hand-written key: override BOTH, over the SAME fields, and keep them immutable.
public sealed class Cell : IEquatable<Cell>
{
    public int R { get; }
    public int C { get; }
    public Cell(int r, int c) { R = r; C = c; }
    public bool Equals(Cell other) => other is not null && R == other.R && C == other.C;
    public override bool Equals(object obj) => Equals(obj as Cell);
    public override int GetHashCode() => HashCode.Combine(R, C);
}

Struct keys without overrides are slow in C#. A plain struct used as a key falls back to ValueType.GetHashCode, which may use reflection and may hash only the first field, so (r, 0), (r, 1), (r, 2), … can all collide. Use a record struct, a value tuple (int, int), or pack two ints into one long: ((long)r << 32) | (uint)c.

Arrays are compared by reference in C#. new HashSet<int[]>() treats two arrays with the same contents as different keys, and Python refuses lists outright (TypeError: unhashable type: 'list'). Convert to an immutable value first: a tuple in Python; a string (string.Join(",", arr)), a value tuple, or a custom IEqualityComparer<int[]> in C#.

Six patterns that cover most hashing problems

The rest of the page takes the patterns one at a time. Each section has a visualizer, the template in both languages, and the variations you will meet.

Pattern 1: frequency map

Store: value → number of occurrences. Use it when the problem talks about "how many times", "same characters", "anagram", "majority", "most frequent", "can be rearranged", or "at most k distinct". The map turns a multiset into something you can compare, update and query in O(1).

Two classic shapes:

  • Compare two multisets: Valid Anagram, Ransom Note, Find All Anagrams in a String. Count one side up and the other side down; everything must end at zero (or ≥ 0 for Ransom Note).
  • Rank by frequency: Top K Frequent Elements, Sort Characters by Frequency. Count, then order by count. Because a count is an integer between 1 and n, you can bucket by count instead of sorting, for O(n) total.
from collections import Counter

def is_anagram(s: str, t: str) -> bool:
    if len(s) != len(t):
        return False
    cnt: dict[str, int] = {}
    for a, b in zip(s, t):
        cnt[a] = cnt.get(a, 0) + 1
        cnt[b] = cnt.get(b, 0) - 1
    return all(v == 0 for v in cnt.values())

def top_k_frequent(nums: list[int], k: int) -> list[int]:
    cnt = Counter(nums)
    bucket: list[list[int]] = [[] for _ in range(len(nums) + 1)]
    for x, c in cnt.items():
        bucket[c].append(x)           # index = frequency, at most n
    out: list[int] = []
    for c in range(len(nums), 0, -1): # highest frequency first
        for x in bucket[c]:
            out.append(x)
            if len(out) == k:
                return out
    return out

{

public static int[] TopKFrequent(int[] nums, int k)
{
    var cnt = new Dictionary<int, int>();
    foreach (int x in nums) cnt[x] = cnt.GetValueOrDefault(x) + 1;
    var bucket = new List<int>[nums.Length + 1];
    foreach (var (x, c) in cnt) (bucket[c] ??= new List<int>()).Add(x);
    var output = new List<int>(k);
    for (int c = nums.Length; c > 0 && output.Count < k; c--)
        if (bucket[c] != null)
            foreach (int x in bucket[c])
            {
                output.Add(x);
                if (output.Count == k) break;
            }
    return output.ToArray();
}

When the alphabet is small, use an array. For lowercase letters, cnt = [0] * 26 indexed by ord(c) - ord('a') (C#: new int[26], c - 'a') is a perfect hash with no collisions: faster than any dict, and two count arrays compare with == (C#: SequenceEqual). Switch to a dict when the alphabet is large or unknown (Unicode, arbitrary integers).

Pattern 2: complement lookup

Store: value → index (or count) of everything seen so far. Use it when you need a pair (i, j) whose values satisfy an equation, like a[i] + a[j] = target, a[j] − a[i] = k, or (a[i] + a[j]) mod k = 0. Solve the equation for the partner: for each x, the partner must be exactly target − x. Then "is my partner on my left?" is a single lookup, and one left-to-right pass checks every pair once.

def two_sum(nums: list[int], target: int) -> list[int]:
    seen: dict[int, int] = {}         # value -> index
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i                   # store AFTER the lookup: x cannot pair with itself
    return []

def count_pairs_with_diff(nums: list[int], k: int) -> int:
    """Number of pairs i < j with |nums[i] - nums[j]| == k (k >= 1)."""
    cnt: dict[int, int] = {}
    total = 0
    for x in nums:
        total += cnt.get(x - k, 0) + cnt.get(x + k, 0)   # partners on the left
        cnt[x] = cnt.get(x, 0) + 1
    return total

public static int[] TwoSum(int[] nums, int target)
{
    var seen = new Dictionary<int, int>();   // value -> index
    for (int i = 0; i < nums.Length; i++)
    {
        int need = target - nums[i];
        if (seen.TryGetValue(need, out int j)) return new[] { j, i };
        seen[nums[i]] = i;
    }
    return Array.Empty<int>();
}

public static long CountPairsWithDiff(int[] nums, int k)
{
    var cnt = new Dictionary<int, int>();
    long total = 0;
    foreach (int x in nums)
    {
        total += cnt.GetValueOrDefault(x - k) + cnt.GetValueOrDefault(x + k);
        cnt[x] = cnt.GetValueOrDefault(x) + 1;
    }
    return total;
}

The same idea generalises in three directions:

  • Count instead of find: store value → count and add the partner's count (above). The answer can be O(n²) in size, so use a 64-bit counter.
  • Change the equation: pairs with sum divisible by k need (x mod k) + (y mod k) ≡ 0, so the partner key is (k − x mod k) mod k. Pairs of "nice" numbers (x − rev(x) = y − rev(y)) need the key x − rev(x): rewrite the condition so each side depends on one element, then hash that.
  • Meet in the middle: 4Sum II asks for a + b + c + d = 0 over four arrays. Store every a + b with its count (n² entries), then look up −(c + d) for every pair of the other two: O(n²) instead of O(n⁴). See worked problem 2.

Hash or two pointers? Two Sum on an unsorted array wants indices back, so sorting would lose them: use the map, O(n) time and O(n) space. On a sorted array (Two Sum II), two pointers give O(n) time with O(1) space. 3Sum is usually sort + two pointers, because it needs deduplication of triples that a map makes awkward.

Pattern 3: grouping by a canonical key

Store: canonical key → list (or count) of items. Use it when items should be grouped by an equivalence: "anagrams", "same pattern", "shifted strings", "isomorphic", "duplicate files", "points on the same line". Design a function key(x) that is equal for equivalent items and different otherwise; then one dict pass groups everything.

from collections import defaultdict

def group_anagrams(words: list[str]) -> list[list[str]]:
    groups: dict[tuple[int, ...], list[str]] = defaultdict(list)
    for w in words:
        count = [0] * 26
        for ch in w:
            count[ord(ch) - 97] += 1
        groups[tuple(count)].append(w)   # lists are unhashable: freeze to a tuple
    return list(groups.values())

public static IList<IList<string>> GroupAnagrams(string[] words)
{
    var groups = new Dictionary<string, IList<string>>();
    foreach (var w in words)
    {
        var count = new int[26];
        foreach (char ch in w) count[ch - 'a']++;
        var key = string.Join(",", count);   // int[] compares by reference: build a string
        if (!groups.TryGetValue(key, out var list)) groups[key] = list = new List<string>();
        list.Add(w);
    }
    return groups.Values.ToList();
}

Pattern 4: prefix sum + hash map

Store: prefix value → how many times it has occurred (or the first index where it occurred). Use it when the problem asks about contiguous subarrays whose sum (or count, xor, balance, remainder) hits an exact target, and the array may contain negative numbers. With only non-negative numbers a sliding window works; negatives break the window because extending it can make the sum go down. The prefix map handles everything.

The algebra is one line. Let P[i] be the sum of the first i elements, with P[0] = 0. The subarray a[i..j-1] has sum P[j] − P[i]. So

sum(a[i..j-1]) = k ⇔ P[i] = P[j] − k

At each position j the question "how many subarrays end here with sum k?" becomes "how many earlier prefixes equal P[j] − k?", which is a single lookup. It is the complement lookup of pattern 2, applied to prefix sums instead of values.

def subarray_sum(nums: list[int], k: int) -> int:
    seen = {0: 1}                     # the empty prefix P[0] = 0, seen once
    run = total = 0
    for x in nums:
        run += x                      # run = P[j]
        total += seen.get(run - k, 0) # earlier prefixes P[i] = P[j] - k
        seen[run] = seen.get(run, 0) + 1
    return total

public static int SubarraySum(int[] nums, int k)
{
    var seen = new Dictionary<long, int> { [0] = 1 };
    long run = 0;
    int total = 0;
    foreach (int x in nums)
    {
        run += x;
        total += seen.GetValueOrDefault(run - k);
        seen[run] = seen.GetValueOrDefault(run) + 1;
    }
    return total;
}

Longest instead of count: store the first index where each prefix value appears. The longest subarray ending at i with sum k starts right after the earliest index j whose running sum was run − k. Never overwrite an existing entry, because a later index can only give a shorter subarray.

def longest_subarray_sum_k(nums: list[int], k: int) -> int:
    first = {0: -1}                   # prefix value -> earliest index where it ended
    run = best = 0
    for i, x in enumerate(nums):      # run = sum(nums[0..i])
        run += x
        j = first.get(run - k)
        if j is not None:
            best = max(best, i - j)   # the subarray nums[j+1..i]
        first.setdefault(run, i)      # keep the earliest, never overwrite
    return best

public static int LongestSubarraySumK(int[] nums, int k)
{
    var first = new Dictionary<long, int> { [0] = -1 };
    long run = 0;
    int best = 0;
    for (int i = 0; i < nums.Length; i++)
    {
        run += nums[i];
        if (first.TryGetValue(run - k, out int j)) best = Math.Max(best, i - j);
        first.TryAdd(run, i);
    }
    return best;
}

The pattern works for anything that "adds up" along the array, as long as you can solve for the earlier prefix:

Problem shape Prefix value Partner key Store
Count subarrays with sum k running sum run − k count
Longest subarray with sum k running sum run − k first index
Equal 0s and 1s (Contiguous Array) +1 for 1, −1 for 0 run (sum 0) first index

Forgetting the empty prefix. Without seen = {0: 1} (or first = {0: -1} in the longest variant: the empty prefix "ends" just before index 0) you miss every subarray that starts at index 0. It is the single most common bug in this pattern.

Negative remainders. In C#, Java and C++, -7 % 5 == -2, so the same residue class shows up under two keys (-2 and 3). Normalise with ((run % k) + k) % k. Python's % already returns a value in [0, k) for positive k. The same applies to the prefix sums page in general: overflow is the other trap, so accumulate in long in C#.

Pattern 5: sets for membership, dedupe and sequences

Store: just the keys. Use it when the only question is "have I seen this?": detecting duplicates, intersecting lists, visited states in a BFS (see graph fundamentals), or "is x + 1 present?".

The showcase is Longest Consecutive Sequence in O(n) without sorting. Put every number in a set. A number x is the start of a run exactly when x − 1 is not in the set. Only from starts do you walk x + 1, x + 2, …. Each number is walked at most once (as part of its own run, from that run's unique start), so the total work is O(n) even though there is a loop inside a loop.

def longest_consecutive(nums: list[int]) -> int:
    s = set(nums)
    best = 0
    for x in s:                       # iterate the SET: duplicates would re-walk runs
        if x - 1 in s:
            continue                  # not a start: its run is counted from the start
        y = x
        while y + 1 in s:
            y += 1
        best = max(best, y - x + 1)
    return best

def contains_nearby_duplicate(nums: list[int], k: int) -> bool:
    window: set[int] = set()          # the last k values
    for i, x in enumerate(nums):
        if x in window:
            return True
        window.add(x)
        if len(window) > k:
            window.remove(nums[i - k])
    return False

public static int LongestConsecutive(int[] nums)
{
    var s = new HashSet<int>(nums);
    int best = 0;
    foreach (int x in s)
    {
        if (s.Contains(x - 1)) continue;
        int y = x;
        while (s.Contains(y + 1)) y++;
        best = Math.Max(best, y - x + 1);
    }
    return best;
}

public static bool ContainsNearbyDuplicate(int[] nums, int k)
{
    var window = new HashSet<int>();
    for (int i = 0; i < nums.Length; i++)
    {
        if (!window.Add(nums[i])) return true;
        if (window.Count > k) window.Remove(nums[i - k]);
    }
    return false;
}

Why iterate the set, not the array? With input [1, 1, 1, …, 1, 2, 3, …, n], iterating the array visits the start 1 once per duplicate and walks the whole run each time: O(n²). Iterating the set visits each distinct value once. This exact case is in LeetCode's tests and causes time limit exceeded.

Other set tricks worth knowing:

  • Two-set dedupe of pairs: to count distinct pairs with difference k, add min(x, y) of each found pair to a result set.
  • Set of seen states for cycle detection: Happy Number stores each digit-square sum and stops when one repeats (or use Floyd's cycle detection from two pointers for O(1) space).
  • Hash set of strings in a sliding window: Repeated DNA Sequences (worked problem 6).
  • Bitmask instead of a set when the universe is ≤ 64 values: mask |= 1 << c is a set of letters in one integer, and two words share no letter iff m1 & m2 == 0 (Maximum Product of Word Lengths).

Pattern 6: index maps for O(1) delete and random access

A hash table alone cannot return a random element in O(1), and an array alone cannot delete an arbitrary value in O(1). Together they can: keep the values in an array, and a map value → index into that array. To delete, swap the victim with the last element, fix the moved element's index in the map, and pop the end. This "map points into a dense array" trick is how Insert Delete GetRandom O(1) works, and the same idea (map → node of a doubly linked list) is the heart of an LRU cache.

import random

class RandomizedSet:
    def __init__(self) -> None:
        self.vals: list[int] = []
        self.pos: dict[int, int] = {}     # value -> index in vals

    def insert(self, x: int) -> bool:
        if x in self.pos:
            return False
        self.pos[x] = len(self.vals)
        self.vals.append(x)
        return True

    def remove(self, x: int) -> bool:
        i = self.pos.get(x)
        if i is None:
            return False
        last = self.vals[-1]
        self.vals[i] = last               # move the last value into the hole
        self.pos[last] = i
        self.vals.pop()
        del self.pos[x]                   # delete AFTER the move (x may equal last)
        return True

    def get_random(self) -> int:
        return random.choice(self.vals)

public class RandomizedSet
{
    private readonly List<int> vals = new();
    private readonly Dictionary<int, int> pos = new();
    private readonly Random rng = new();

    public bool Insert(int x)
    {
        if (!pos.TryAdd(x, vals.Count)) return false;
        vals.Add(x);
        return true;
    }

    public bool Remove(int x)
    {
        if (!pos.TryGetValue(x, out int i)) return false;
        int last = vals[^1];
        vals[i] = last;
        pos[last] = i;
        vals.RemoveAt(vals.Count - 1);
        pos.Remove(x);
        return true;
    }

    public int GetRandom() => vals[rng.Next(vals.Count)];

    public int Count => vals.Count;
}

Order of the two map updates in remove. If x is itself the last element, "set pos[last] = i" and then "delete pos[x]" leaves the map correct. Doing the delete first and then writing pos[last] = i would resurrect x in the map. Step through it in the visualizer with the remove of the last value.

Rolling hash: hashing every window in O(1)

To find a pattern of length m in a text of length n, comparing every window costs O(n·m). A rolling hash gives every window a number, computed from the previous window's number in O(1): drop the leftmost character's contribution, shift, add the new character. Equal windows always have equal hashes, so only windows whose hash matches the pattern's need a real comparison (Rabin–Karp). Unequal windows can occasionally collide, which is exactly why the comparison is kept.

Treat the window as a number in base B, modulo a prime M:

H(s[i..i+m-1]) = s[i]·B^(m-1) + s[i+1]·B^(m-2) + … + s[i+m-1] (mod M)

H(next) = (H(cur) − s[i]·B^(m-1)) · B + s[i+m] (mod M)

The visualizer uses a deliberately tiny modulus (M = 101) so you can watch a spurious hit: a window with the same hash as the pattern but different letters. Real code uses M around 10⁹ or 2⁶¹ − 1, or two independent moduli, to make that astronomically unlikely.

def rabin_karp(text: str, pat: str, base: int = 256, mod: int = 1_000_000_007) -> list[int]:
    n, m = len(text), len(pat)
    if m == 0 or m > n:
        return []
    high = pow(base, m - 1, mod)      # weight of the leftmost character
    hp = hw = 0
    for i in range(m):
        hp = (hp * base + ord(pat[i])) % mod
        hw = (hw * base + ord(text[i])) % mod
    out = []
    for i in range(n - m + 1):
        if hw == hp and text[i:i + m] == pat:   # verify: hashes can collide
            out.append(i)
        if i + m < n:
            hw = ((hw - ord(text[i]) * high) * base + ord(text[i + m])) % mod
    return out

public static List<int> RabinKarp(string text, string pat, long b = 256, long mod = 1_000_000_007)
{
    int n = text.Length, m = pat.Length;
    var output = new List<int>();
    if (m == 0 || m > n) return output;
    long high = 1;
    for (int i = 0; i < m - 1; i++) high = high * b % mod;
    long hp = 0, hw = 0;
    for (int i = 0; i < m; i++)
    {
        hp = (hp * b + pat[i]) % mod;
        hw = (hw * b + text[i]) % mod;
    }
    for (int i = 0; i + m <= n; i++)
    {
        if (hw == hp && string.CompareOrdinal(text, i, pat, 0, m) == 0) output.Add(i);
        if (i + m < n)
        {
            hw = (hw - text[i] * high % mod + mod) % mod;   // keep it non-negative
            hw = (hw * b + text[i + m]) % mod;
        }
    }
    return output;
}

Where rolling hashes shine. Single-pattern search has better tools (KMP, Z-function; see string algorithms). Rolling hashes win when you must compare many substrings with each other: "is there a repeated substring of length L?" (combine with binary search on L, worked problem 7), counting distinct substrings, longest common substring of two strings, or palindrome checks with forward and backward hashes. In C#, keep products under 2⁶³ by using a modulus below about 3·10⁹ with long, or use UInt128/Math.BigMul for 2⁶¹ − 1.

Coordinate compression

Some structures want small dense indices: a Fenwick or segment tree over values, a counting array, a grid. When the values are huge or sparse (like [1000000000, -7, 42, 42]) but there are only n of them, compress: sort the distinct values and map each to its rank. The order is preserved (x < y ⇔ rank(x) < rank(y)), so any question that only depends on comparisons gives the same answer on ranks.

def compress(nums: list[int]) -> list[int]:
    rank = {v: i for i, v in enumerate(sorted(set(nums)))}   # value -> 0-based rank
    return [rank[x] for x in nums]

public static int[] Compress(int[] nums)
{
    var sorted = nums.Distinct().OrderBy(v => v).ToArray();
    var rank = new Dictionary<int, int>(sorted.Length);
    for (int i = 0; i < sorted.Length; i++) rank[sorted[i]] = i;
    return nums.Select(x => rank[x]).ToArray();
}

Typical uses: Count of Smaller Numbers After Self and Reverse Pairs (Fenwick tree over ranks), Rank Transform of an Array (the answer is the compression, 1-based), sweep lines over interval endpoints, and 2-D grids where only the given coordinates matter. Instead of the dict you can also binary-search the sorted distinct array (bisect_left / Array.BinarySearch), trading O(1) lookups for no extra map.

Choosing the right structure

Two questions settle most cases: do I need order? (smallest, next larger, range queries: use a sorted structure or a heap) and are the keys small integers? (use an array, which is a perfect hash). Otherwise a hash map or set is the default.

Templates at a glance

Pattern Store At each element Time · Space
Frequency map value → count cnt[x] += 1; compare or rank counts O(n) · O(distinct)
Complement lookup value → index / count (left side) look up partner(x), then insert x O(n) · O(n)
Canonical key key(x) → list / count append x under key(x) O(n · cost of key) · O(n)
Prefix + map prefix → count / first index look up run − k; seed {0: 1} or {0: −1} O(n) · O(n)
Set membership the keys if x in s; start runs only where x − 1 ∉ s O(n) · O(n)
Index map value → position in an array swap with last on delete, fix the moved index O(1) per op · O(n)
Rolling hash window hash → position h = (h − out·B^(m−1))·B + in O(n) expected · O(n)
Compression value → rank sort distinct, then map O(n log n) · O(n)

Recognize it when

  • A brute force has a nested loop where the inner loop searches for something (a partner, an earlier prefix, a duplicate): replace the inner loop with a lookup.
  • The words "count", "frequency", "anagram", "duplicate", "distinct", "seen before", "first unique" appear.
  • You need pairs or subarrays with an exact sum, difference, xor or remainder, and the input is unsorted or has negatives.
  • Items must be grouped by an equivalence (same letters, same pattern, same slope, same remainder).
  • You must remember visited states (BFS, cycle detection, memoization of a DP with sparse or tuple-shaped states; see the DP framework).
  • You need O(1) insert, delete and lookup together, possibly with random access or recency order (design problems).

When it does not work

  • You need order. Hash tables cannot answer "smallest key ≥ x", "k-th smallest", or "all keys in [l, r]". Use sorting plus binary search, a heap (heaps), a balanced BST (SortedDictionary / SortedList in C#, sortedcontainers in Python), or a Fenwick tree.
  • "At most / at least" a sum with non-negative numbers. A sliding window uses O(1) space and handles inequalities, which an exact-match lookup cannot.
  • O(1) extra space is required. Look for sorting + two pointers, cyclic sort (values in 1..n, see sorting), bit tricks (bit manipulation), or Floyd's cycle detection.
  • Keys are small integers. An array of size k is faster, simpler and collision-free.
  • Worst-case guarantees matter (adversarial input, real-time systems): hash tables are O(1) only on average. Prefer a sorted structure with O(log n) worst case, or randomise the hash.

Worked problems

1. Contiguous Array

Find the longest subarray with an equal number of 0s and 1s. Insight: replace every 0 by −1. "Equal counts" becomes "sum 0", and a subarray has sum 0 exactly when the prefix sum at its end equals the prefix sum just before its start. Store the first index of each prefix value; the empty prefix sits at index −1.

Solution: O(n) time, O(n) space 
def find_max_length(nums: list[int]) -> int:
    first = {0: -1}                   # balance -> earliest index where it occurred
    bal = best = 0
    for i, x in enumerate(nums):
        bal += 1 if x == 1 else -1
        if bal in first:
            best = max(best, i - first[bal])
        else:
            first[bal] = i
    return best

public static int FindMaxLength(int[] nums)
{
    var first = new Dictionary<int, int> { [0] = -1 };
    int bal = 0, best = 0;
    for (int i = 0; i < nums.Length; i++)
    {
        bal += nums[i] == 1 ? 1 : -1;
        if (first.TryGetValue(bal, out int j)) best = Math.Max(best, i - j);
        else first[bal] = i;
    }
    return best;
}

Balance can live in an array. The balance stays within [−n, n], so first can be an array of size 2n + 1 indexed by bal + n. Use that trick whenever the prefix value has a small known range (also for the vowel bitmask problem, where the mask has 32 values).

2. 4Sum II

Count tuples (i, j, k, l) with A[i] + B[j] + C[k] + D[l] = 0, all four arrays of length n ≤ 200. Insight: meet in the middle. Split the equation into two halves, A[i] + B[j] = −(C[k] + D[l]). Count every A + B sum in a map (n² entries), then for every C + D pair add the count of its negation. O(n²) instead of O(n⁴).

Solution: O(n²) time, O(n²) space 
from collections import Counter

def four_sum_count(a: list[int], b: list[int], c: list[int], d: list[int]) -> int:
    ab = Counter(x + y for x in a for y in b)
    return sum(ab[-(x + y)] for x in c for y in d)   # Counter reads do not insert

public static int FourSumCount(int[] a, int[] b, int[] c, int[] d)
{
    var ab = new Dictionary<int, int>();
    foreach (int x in a)
        foreach (int y in b)
            CollectionsMarshal.GetValueRefOrAddDefault(ab, x + y, out _)++;
    int total = 0;
    foreach (int x in c)
        foreach (int y in d)
            total += ab.GetValueOrDefault(-(x + y));
    return total;
}

3. Subarray Sums Divisible by K

Count subarrays whose sum is divisible by k. Insight: sum(i..j) is divisible by k exactly when P[j+1] and P[i] have the same remainder mod k. Count remainders; each new prefix pairs with every earlier prefix of the same remainder. Seed remainder 0 with count 1 (the empty prefix), and normalise negative remainders in C#.

Solution: O(n) time, O(k) space 
def subarrays_div_by_k(nums: list[int], k: int) -> int:
    cnt = [0] * k
    cnt[0] = 1                        # empty prefix
    run = total = 0
    for x in nums:
        run = (run + x) % k           # Python: always in [0, k)
        total += cnt[run]
        cnt[run] += 1
    return total

public static int SubarraysDivByK(int[] nums, int k)
{
    var cnt = new int[k];
    cnt[0] = 1;
    int run = 0, total = 0;
    foreach (int x in nums)
    {
        run = ((run + x) % k + k) % k;   // C#: % can be negative
        total += cnt[run];
        cnt[run]++;
    }
    return total;
}

The remainder lives in [0, k), so an array replaces the map. That is the "small keys → array" rule from the toolkit section.

4. Brick Wall

A wall is given as rows of brick widths. Draw one vertical line from top to bottom that crosses the fewest bricks (passing along an edge does not cross). Insight: a line crosses every row except the rows that have an edge at that x. So count, over all rows, how often each inner edge position occurs (the running width, excluding the final wall edge). The best line sits at the most common edge: answer = rows − max count.

Solution: O(total bricks) time 
def least_bricks(wall: list[list[int]]) -> int:
    edges: dict[int, int] = {}        # x position -> rows with an edge there
    for row in wall:
        x = 0
        for w in row[:-1]:            # the last edge is the wall's border
            x += w
            edges[x] = edges.get(x, 0) + 1
    return len(wall) - max(edges.values(), default=0)

public static int LeastBricks(IList<IList<int>> wall)
{
    var edges = new Dictionary<long, int>();
    int most = 0;
    foreach (var row in wall)
    {
        long x = 0;
        for (int i = 0; i < row.Count - 1; i++)
        {
            x += row[i];
            int c = edges.GetValueOrDefault(x) + 1;
            edges[x] = c;
            most = Math.Max(most, c);
        }
    }
    return wall.Count - most;
}

5. Max Points on a Line

Given up to 300 distinct points, find the most that lie on one straight line. Insight: fix an anchor point p. Every other point q lies on exactly one line through p, identified by the direction q − p. Group by direction with a canonical key: divide (dx, dy) by their gcd, then fix the sign so that (2, −4) and (−1, 2) give the same key. The largest group plus the anchor is the best line through p. Floats are wrong here: 1/3 and 2/6 may not compare equal after rounding, and vertical lines divide by zero.

Solution: O(n²) time, O(n) space 
from math import gcd

def max_points(points: list[list[int]]) -> int:
    n = len(points)
    best = min(n, 1)
    for i in range(n):
        slopes: dict[tuple[int, int], int] = {}
        x1, y1 = points[i]
        for j in range(i + 1, n):
            dx, dy = points[j][0] - x1, points[j][1] - y1
            g = gcd(dx, dy)           # never 0: the points are distinct
            dx, dy = dx // g, dy // g
            if dx < 0 or (dx == 0 and dy < 0):
                dx, dy = -dx, -dy     # one sign convention per direction
            slopes[(dx, dy)] = slopes.get((dx, dy), 0) + 1
            best = max(best, slopes[(dx, dy)] + 1)
    return best

public static int MaxPoints(int[][] points)
{
    int n = points.Length, best = Math.Min(n, 1);
    for (int i = 0; i < n; i++)
    {
        var slopes = new Dictionary<(int, int), int>();
        for (int j = i + 1; j < n; j++)
        {
            int dx = points[j][0] - points[i][0], dy = points[j][1] - points[i][1];
            int g = GcdInt(Math.Abs(dx), Math.Abs(dy));
            dx /= g; dy /= g;
            if (dx < 0 || (dx == 0 && dy < 0)) { dx = -dx; dy = -dy; }
            int c = slopes.GetValueOrDefault((dx, dy)) + 1;
            slopes[(dx, dy)] = c;
            best = Math.Max(best, c + 1);
        }
    }
    return best;
}

static int GcdInt(int a, int b) => b == 0 ? a : GcdInt(b, a % b);

6. Repeated DNA Sequences

Return every 10-letter substring that occurs more than once in a DNA string (letters A C G T). Insight: a set of seen windows plus a set of answers. Storing 10-character strings works, but there is a neater perfect rolling hash: with only four letters, each needs 2 bits, so a window of 10 letters fits exactly in 20 bits. Slide by shifting left 2, adding the new letter, and masking to 20 bits. Different windows always get different integers, so no verification is needed.

Solution: O(n) time, O(n) space 
def find_repeated_dna(s: str) -> list[str]:
    code = {"A": 0, "C": 1, "G": 2, "T": 3}
    mask = (1 << 20) - 1              # keep the last 10 letters = 20 bits
    seen: set[int] = set()
    added: set[int] = set()
    out: list[str] = []
    h = 0
    for i, ch in enumerate(s):
        h = ((h << 2) | code[ch]) & mask
        if i >= 9:
            if h in seen and h not in added:
                added.add(h)
                out.append(s[i - 9:i + 1])
            seen.add(h)
    return out

public static IList<string> FindRepeatedDnaSequences(string s)
{
    var seen = new HashSet<int>();
    var added = new HashSet<int>();
    var output = new List<string>();
    int h = 0, mask = (1 << 20) - 1;
    for (int i = 0; i < s.Length; i++)
    {
        int code = s[i] switch { 'A' => 0, 'C' => 1, 'G' => 2, _ => 3 };
        h = ((h << 2) | code) & mask;
        if (i >= 9 && !seen.Add(h) && added.Add(h))
            output.Add(s.Substring(i - 9, 10));
    }
    return output;
}

7. Longest Duplicate Substring

Find the longest substring that occurs at least twice (occurrences may overlap), with n up to 3·10⁴. Insight: two ideas stack. First, the answer is monotone in the length: if some substring of length L repeats, so does its prefix of length L − 1. So binary search on L. Second, "does any length-L substring repeat?" is a rolling-hash pass that puts every window's hash into a map: O(n) per check. Total O(n log n). Use two moduli (a pair of hashes) and confirm a hit with a real comparison, so a collision can never produce a wrong answer.

Solution: O(n log n) expected time, O(n) space 
def longest_dup_substring(s: str) -> str:
    n = len(s)
    a = [ord(c) for c in s]
    m1, m2, base = 1_000_000_007, 998_244_353, 131

    def repeat_start(length: int) -> int:
        """Start of some length-`length` substring seen earlier, or -1."""
        p1, p2 = pow(base, length, m1), pow(base, length, m2)
        h1 = h2 = 0
        first: dict[tuple[int, int], int] = {}
        for i in range(n):
            h1 = (h1 * base + a[i]) % m1
            h2 = (h2 * base + a[i]) % m2
            if i >= length:           # drop the character that left the window
                h1 = (h1 - a[i - length] * p1) % m1
                h2 = (h2 - a[i - length] * p2) % m2
            if i >= length - 1:
                start = i - length + 1
                j = first.setdefault((h1, h2), start)
                if j != start and s[j:j + length] == s[start:start + length]:
                    return start
        return -1

    lo, hi, best_start, best_len = 1, n - 1, 0, 0
    while lo <= hi:
        mid = (lo + hi) // 2
        st = repeat_start(mid)
        if st >= 0:
            best_start, best_len, lo = st, mid, mid + 1
        else:
            hi = mid - 1
    return s[best_start:best_start + best_len]

public static string LongestDupSubstring(string s)
{
    int lo = 1, hi = s.Length - 1, bestStart = 0, bestLen = 0;
    while (lo <= hi)
    {
        int mid = (lo + hi) / 2;
        int st = RepeatStart(s, mid);
        if (st >= 0) { bestStart = st; bestLen = mid; lo = mid + 1; }
        else hi = mid - 1;
    }
    return s.Substring(bestStart, bestLen);
}

static int RepeatStart(string s, int len)
{
    const long M1 = 1_000_000_007, M2 = 998_244_353, B = 131;
    long p1 = 1, p2 = 1;
    for (int i = 0; i < len; i++) { p1 = p1 * B % M1; p2 = p2 * B % M2; }
    long h1 = 0, h2 = 0;
    var first = new Dictionary<long, int>();
    for (int i = 0; i < s.Length; i++)
    {
        h1 = (h1 * B + s[i]) % M1;
        h2 = (h2 * B + s[i]) % M2;
        if (i >= len)
        {
            h1 = ((h1 - s[i - len] * p1) % M1 + M1) % M1;
            h2 = ((h2 - s[i - len] * p2) % M2 + M2) % M2;
        }
        if (i < len - 1) continue;
        int start = i - len + 1;
        long key = h1 * M2 + h2;              // the pair packed into one long
        if (!first.TryAdd(key, start)
            && string.CompareOrdinal(s, first[key], s, start, len) == 0)
            return start;
    }
    return -1;
}

Why confirm hits? Without the comparison, a single collision makes the check say "yes" for a length that does not repeat, and the binary search then returns garbage. With it, a collision can at worst hide a real repeat whose slot was taken by a different string, which two 30-bit moduli make vanishingly unlikely. A suffix array solves the same problem deterministically in O(n log n); the hashing version is shorter to write under pressure.

8. Number of Submatrices That Sum to Target

Count the non-empty submatrices of an r × c matrix (up to 100 × 100) whose sum equals target. Insight: reduce 2-D to 1-D. Fix a top row and a bottom row; collapse the rows between them into one array of column sums. Every submatrix with exactly those rows is a contiguous subarray of that array, so "Subarray Sum Equals K" (pattern 4) counts them in O(c). There are O(r²) row pairs, and extending the bottom row by one updates the column sums in O(c), for O(r² · c) total.

Solution: O(r² · c) time, O(c) space 
def num_submatrix_sum_target(matrix: list[list[int]], target: int) -> int:
    rows, cols = len(matrix), len(matrix[0])
    total = 0
    for top in range(rows):
        col = [0] * cols              # column sums for rows top..bottom
        for bottom in range(top, rows):
            for j in range(cols):
                col[j] += matrix[bottom][j]
            seen = {0: 1}             # pattern 4 over the collapsed row
            run = 0
            for v in col:
                run += v
                total += seen.get(run - target, 0)
                seen[run] = seen.get(run, 0) + 1
    return total

public static int NumSubmatrixSumTarget(int[][] matrix, int target)
{
    int rows = matrix.Length, cols = matrix[0].Length, total = 0;
    for (int top = 0; top < rows; top++)
    {
        var col = new int[cols];
        for (int bottom = top; bottom < rows; bottom++)
        {
            for (int j = 0; j < cols; j++) col[j] += matrix[bottom][j];
            var seen = new Dictionary<int, int> { [0] = 1 };
            int run = 0;
            foreach (int v in col)
            {
                run += v;
                total += seen.GetValueOrDefault(run - target);
                seen[run] = seen.GetValueOrDefault(run) + 1;
            }
        }
    }
    return total;
}

If rows outnumber columns, transpose first (or loop over column pairs instead) so the squared factor is the smaller dimension.

Self-check

A chained table has 8 buckets and holds 6 keys. What is the load factor, and what is the expected cost of an unsuccessful lookup?

α = 6 / 8 = 0.75. With a good hash, an unsuccessful lookup computes the hash and scans one whole chain, whose expected length is α: about 1 + 0.75 steps. That is why tables resize when α crosses a constant: the cost depends on α, not on n.

In open addressing, why can't remove just empty the slot?

Lookups stop at the first empty slot. If you empty a slot in the middle of a probe run, every key that was placed after it in that run becomes unreachable. A tombstone says "deleted, keep probing" to lookups and "free, you may reuse me" to inserts. Too many tombstones slow every lookup, so the table rebuilds when live + tombstones gets too high.

Doubling the capacity makes one insert cost O(n). Why is insert still O(1)?

Amortised: after a resize to capacity 2c, the next resize happens only after about c more inserts. The O(c) rehash is paid for by those c cheap inserts, a constant amount each. Summed over n inserts the copying is at most n + n/2 + n/4 + … < 2n. Growing by a constant (+100 slots) instead would make the total O(n²).

Subarray Sum Equals K with nums = [1, -1, 0], k = 0. How many subarrays, and what breaks if you forget seen = {0: 1}?

Prefix sums are 0 (empty), 1, 0, 0. Pairs of equal prefixes: the three zeros give 3 pairs, so the answer is 3: [1, -1], [0] and [1, -1, 0]. Without the seed, the empty prefix is missing, and the two subarrays that start at index 0 ([1, -1] and [1, -1, 0]) are not counted: you get 1.

Why is Longest Consecutive Sequence O(n) despite the while loop inside the for?

The inner loop only runs from a start (a value whose x − 1 is absent), and it walks exactly the values of that one run. Runs are disjoint, so across all starts the inner loop advances at most n times in total. Every other value does O(1) work and continues.

You put a Python list into a set and get TypeError: unhashable type: 'list'. Why does Python refuse, and what do you do?

A list is mutable. If it changed after insertion its hash would change, and it would sit in the wrong bucket forever, unfindable (the mutable-key figure above). Convert to an immutable equivalent: tuple(lst), or frozenset(s) for sets. C# does not refuse: HashSet<int[]> compares arrays by reference, which compiles fine and silently treats equal contents as different keys.

Rabin–Karp finds a window whose hash equals the pattern's hash. Is it a match?

Not necessarily. Equal strings always have equal hashes, but different strings can share a hash (a collision, the "spurious hit" in the visualizer). Confirm with a character comparison. With a modulus near 10⁹ collisions are rare, so the expected time stays O(n + m); the worst case is O(n·m) if every window collides.

Two Sum: what goes wrong if you insert x into the map before looking up target − x?

When x = target / 2 (say x = 3, target 6) the lookup finds x itself and returns [i, i], pairing an element with itself. Looking up first, then inserting, guarantees the partner has a strictly smaller index. With duplicates like [3, 3] it still works: the second 3 finds the first.
