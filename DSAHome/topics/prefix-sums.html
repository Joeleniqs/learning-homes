Prefix Sums & Difference Arrays

1D/2D prefix sums, prefix + hash map for subarray targets, difference arrays for range updates, and prefix XOR.

Beginner → Advanced~50 min studyUpdated 2026-11-03

What prefix sums are

You have an array and you will be asked, many times, “what is the sum of nums[l…r]?”. Adding the numbers each time costs O(length) per question. Prefix sums pay O(n) once so that every later question costs O(1). Then the same idea, viewed from different angles, solves a surprising range of problems: counting subarrays with a target sum, rectangle sums in a matrix, thousands of range updates, range XOR, and “product of everything except me”.

The invariant. Let P[k] be the sum of the first k elements (P[0] = 0). Then the sum of any range l…r is P[r+1] − P[l]: two prefixes that share the same head, subtracted so the head cancels. Every technique on this page is that one subtraction, read forwards (range queries), backwards (difference arrays) or as a lookup (prefix + hash map).

Three facts carry through the whole topic:

  1. The extra slot. P has n + 1 entries and P[0] = 0 is the sum of nothing. Without it, a range starting at index 0 would need a special case. With it, P[r+1] − P[l] works for every 0 ≤ l ≤ r < n.
  2. Subtraction is the only thing you need. Any operation with an inverse works the same way: +/− for sums, ^/^ for XOR, counts of a property (“how many vowels in s[l…r]”), even bitmasks of parities.
  3. Prefix and difference are inverses. Taking the prefix sum of the difference array gives the original array back. That is what turns O(length) range updates into O(1) each (see difference arrays).

Intuition: running totals and fences

Think of P as the odometer of a car driving along the array: P[k] is the distance driven when the car passes fence k. The distance driven between two fences is the later reading minus the earlier one. Nobody re-measures the road.

Watch P being built and queried

Build P one cell at a time (each new value reuses the previous one), then answer a few queries. Notice that a query over 1 element and a query over the whole array cost exactly the same: one subtraction.

Half-open ranges make the indices disappear

The cleanest way to remember the formula is to think in half-open ranges [l, r): “from index l up to, but not including, r”. Then sum[l, r) = P[r] − P[l], with no +1 anywhere, and the empty range [l, l) gives 0 for free. The inclusive version nums[l…r] is the half-open range [l, r+1), which is where P[r+1] comes from.

You want Formula Notes
sum of nums[l…r] (inclusive) P[r+1] − P[l] The common LeetCode form
sum of [l, r) (half-open) P[r] − P[l] Length is r − l
sum of the first k elements P[k] P[0] = 0, P[n] = total
sum of the last k elements P[n] − P[n−k]
sum of everything except l…r P[n] − (P[r+1] − P[l])
average of nums[l…r] (P[r+1] − P[l]) / (r − l + 1) Combine with binary search on the answer for “max average” problems

The templates

1D prefix sums

from itertools import accumulate

def build_prefix(nums: list[int]) -> list[int]:
    P = [0] * (len(nums) + 1)              # P[0] = 0: the empty prefix
    for i, x in enumerate(nums):
        P[i + 1] = P[i] + x                # sum of nums[0..i]
    return P
    # one-liner: list(accumulate(nums, initial=0))   (Python 3.8+)

def range_sum(P: list[int], l: int, r: int) -> int:
    return P[r + 1] - P[l]                 # inclusive l..r

public static long[] BuildPrefix(int[] nums)
{
    var P = new long[nums.Length + 1];     // P[0] = 0: the empty prefix
    for (int i = 0; i < nums.Length; i++)
        P[i + 1] = P[i] + nums[i];         // sum of nums[0..i]
    return P;
}

public static long RangeSum(long[] P, int l, int r) => P[r + 1] - P[l];   // inclusive l..r

O(n) to build, O(1) per query, O(n) extra space. In C# use long for the prefix array: 10⁵ values of 10⁹ overflow int long before they look suspicious. Python integers do not overflow.

2D prefix sums

In a matrix, let P[r][c] be the sum of the block of rows 0…r−1 and columns 0…c−1 (again one row and one column of zero padding). Two ideas, both pure inclusion–exclusion:

  • Build: the block ending at (r, c) is the cell itself, plus the block above, plus the block to the left. Those two blocks overlap in the block up-and-left, which was therefore added twice: subtract it once.
  • Query: a rectangle is the big block to its bottom-right corner, minus the strip above, minus the strip to the left. The corner where the strips overlap was subtracted twice: add it back once.
class NumMatrix:                                     # LC 304
    def __init__(self, matrix: list[list[int]]):
        m, n = len(matrix), len(matrix[0])
        P = [[0] * (n + 1) for _ in range(m + 1)]    # zero row and column
        for r in range(m):
            for c in range(n):
                P[r + 1][c + 1] = matrix[r][c] + P[r][c + 1] + P[r + 1][c] - P[r][c]
        self.P = P

    def sum_region(self, r1: int, c1: int, r2: int, c2: int) -> int:
        P = self.P
        return P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]

public class NumMatrix                               // LC 304
{
    private readonly int[,] P;

    public NumMatrix(int[][] matrix)
    {
        int m = matrix.Length, n = matrix[0].Length;
        P = new int[m + 1, n + 1];                   // zero row and column
        for (int r = 0; r < m; r++)
            for (int c = 0; c < n; c++)
                P[r + 1, c + 1] = matrix[r][c] + P[r, c + 1] + P[r + 1, c] - P[r, c];
    }

    public int SumRegion(int r1, int c1, int r2, int c2) =>
        P[r2 + 1, c2 + 1] - P[r1, c2 + 1] - P[r2 + 1, c1] + P[r1, c1];
}

O(mn) to build, O(1) per rectangle. The signs follow a pattern worth memorising: the two corners on the main diagonal of the query ((r2+1, c2+1) and (r1, c1)) are added, the two on the anti-diagonal are subtracted. The same pattern appears in the 2D difference array below.

Prefix + hash map: subarrays with a target

“Count (or find the longest) subarray whose sum is k” looks like it needs all O(n²) pairs (j, i). Rewrite the condition with prefixes:

sum(nums[j…i]) = k ⇔ P[i+1] − P[j] = k ⇔ P[j] = P[i+1] − k.

So as you sweep i left to right, the question “how many subarrays ending at i sum to k?” becomes “how many earlier prefixes equal run − k?”, which a hash map answers in O(1). One pass, O(n).

from collections import defaultdict

def subarray_sum(nums: list[int], k: int) -> int:   # LC 560
    count, run = 0, 0
    seen = defaultdict(int)
    seen[0] = 1                        # the empty prefix: lets a subarray start at 0
    for x in nums:
        run += x                       # run = P[i + 1]
        count += seen[run - k]         # earlier prefixes we can subtract
        seen[run] += 1                 # only now make this prefix available
    return count

public static int SubarraySum(int[] nums, int k)    // LC 560
{
    var seen = new Dictionary<int, int> { [0] = 1 };  // the empty prefix
    int count = 0, run = 0;
    foreach (int x in nums)
    {
        run += x;                                      // run = P[i + 1]
        count += seen.GetValueOrDefault(run - k);      // earlier prefixes we can subtract
        seen[run] = seen.GetValueOrDefault(run) + 1;   // only now make this prefix available
    }
    return count;
}

O(n) time, O(n) space. Two details decide correctness, and the visualizer shows both:

  • seen = {0: 1} stands for P[0]. Without it every subarray that starts at index 0 is missed.
  • Look up before you insert. Inserting first would let the current prefix pair with itself, which is the empty subarray. With k = 0 that silently adds one to the count per element.

Why not a sliding window? A sliding window needs “growing the window never decreases the sum”, which holds only for non-negative numbers. With negatives, a window that is too big can become right again after adding more, so no pointer move is ever safe. Prefix + hash map does not care about signs: it never moves a left edge, it looks every candidate left edge up at once.

What to store in the map

The key is always the prefix value (or something derived from it). The value depends on the question:

Question Map value Update rule Example
How many subarrays sum to k? count of each prefix seen[run] += 1 every time LC 560, 930, 1248
Longest subarray with sum k? first index of each prefix insert only if absent LC 525, 325
Shortest subarray with sum k? last index of each prefix overwrite every time LC 1590
Does any subarray qualify? a set of prefixes add after the check LC 523
Sum of lengths / indices sum of indices per prefix add i “sum of distances” problems

For the longest subarray you want the earliest matching left fence, so you keep the first index at which each prefix value appears and never overwrite it. Seed the map with {0: −1}: prefix 0 “happens” just before index 0.

The same reduction (“map the property to ±1 or to a bitmask, then look for equal prefixes”) solves vowel-parity substrings (LC 1371), “more 1s than 0s” counts, and many string problems. The counting version even walks down trees: LC 437 (Path Sum III) keeps the map of root-to-node prefix sums during a DFS and removes each prefix on the way back up.

Prefix sums with modulo

“Count subarrays whose sum is divisible by k” is the same lookup with the condition rewritten modulo k:

(P[i+1] − P[j]) mod k = 0 ⇔ P[i+1] mod k = P[j] mod k.

Only the remainder of each prefix matters. There are just k possible remainders, so the “map” can be an array of k buckets, and every pair of prefixes that land in the same bucket is one divisible subarray.

Negative remainders in C#, Java, C++ and Go -7 % 5 is 3 in Python but -2 in C#, Java, C++ and Go, so −2 and 3 land in different buckets although they are the same remainder. Fix: normalise with ((x % k) + k) % k. Python’s % already returns a value in 0…k−1 for positive k.

Two classics use this, and they differ in what the map stores:

  • LC 974 (count divisible subarrays): counts per remainder, exactly like LC 560.
  • LC 523 (is there a subarray of length ≥ 2 with a sum that is a multiple of k?): store the first index of each remainder (seeded with {0: −1}), and answer yes as soon as a remainder repeats at distance ≥ 2. Keeping the first index maximises the distance, so a valid pair is never hidden by a later one.

Both appear as worked problem 3 below.

Prefix XOR

XOR has the two properties subtraction gives sums: it has an identity (x ^ 0 = x) and every value is its own inverse (x ^ x = 0). So with X[k] = a[0] ^ … ^ a[k−1], the XOR of any range is X[r+1] ^ X[l]: the shared head appears twice and cancels.

def xor_queries(arr: list[int], queries: list[list[int]]) -> list[int]:   # LC 1310
    X = [0]                                   # X[k] = arr[0] ^ ... ^ arr[k-1]
    for x in arr:
        X.append(X[-1] ^ x)
    return [X[r + 1] ^ X[l] for l, r in queries]

public static int[] XorQueries(int[] arr, int[][] queries)   // LC 1310
{
    var X = new int[arr.Length + 1];          // X[k] = arr[0] ^ ... ^ arr[k-1]
    for (int i = 0; i < arr.Length; i++) X[i + 1] = X[i] ^ arr[i];
    return queries.Select(q => X[q[1] + 1] ^ X[q[0]]).ToArray();
}

The hash-map trick carries over unchanged, with “equal prefixes” now meaning “range XOR is 0”:

  • LC 1442 (triplets with equal XOR): a == b for the split i < j ≤ k means X[i] == X[k+1], and then every j between them works, so each equal pair contributes k − i triplets.
  • Parity masks (LC 1371, 1915): keep one bit per letter, flipped on each occurrence. Two equal masks bracket a substring where every letter appears an even number of times. “At most one odd letter” means masks that differ in at most one bit: look up the mask itself and the 26 masks with one bit flipped.

Prefix and suffix products

Products have no safe inverse: division fails as soon as a zero appears, and LC 238 forbids it anyway. The fix is to stop subtracting. Keep a prefix (everything to the left) and a suffix (everything to the right) and combine them instead.

def product_except_self(nums: list[int]) -> list[int]:    # LC 238
    n = len(nums)
    out = [1] * n
    for i in range(1, n):                     # pass 1: out[i] = product of nums[0..i-1]
        out[i] = out[i - 1] * nums[i - 1]
    suffix = 1                                # product of nums[i+1..n-1]
    for i in range(n - 1, -1, -1):            # pass 2: multiply the right part in
        out[i] *= suffix
        suffix *= nums[i]
    return out

public static int[] ProductExceptSelf(int[] nums)         // LC 238
{
    int n = nums.Length;
    var output = new int[n];
    output[0] = 1;
    for (int i = 1; i < n; i++)               // pass 1: product of nums[0..i-1]
        output[i] = output[i - 1] * nums[i - 1];
    int suffix = 1;                           // product of nums[i+1..n-1]
    for (int i = n - 1; i >= 0; i--)          // pass 2: multiply the right part in
    {
        output[i] *= suffix;
        suffix *= nums[i];
    }
    return output;
}

O(n) time and O(1) extra space (the output array does not count). The pattern generalises to any associative operation, inverse or not: prefix max/min arrays answer “best value to my left” (LC 42 Trapping Rain Water stores max_left[i] and max_right[i]), and a prefix gcd plus a suffix gcd gives “gcd of everything except i”. What you lose without an inverse is arbitrary ranges l…r: only ranges that touch an end are O(1). For arbitrary range min/max/gcd, use a sparse table or a segment tree.

Difference arrays: range updates in O(1)

Now flip the problem. Instead of many range queries on a fixed array, you get many range updates (“add v to every element in l…r”) and need the final array once at the end. Doing each update cell by cell costs O(length).

Define the difference array D[i] = a[i] − a[i−1]. Prefix-summing D rebuilds a. Now look at what “add v to a[l…r]” does to D: inside the range, neighbours both moved by v, so their differences did not change. Only two differences change: D[l] += v (the step up into the range) and D[r+1] −= v (the step back down after it).

from itertools import accumulate

def corp_flight_bookings(bookings: list[list[int]], n: int) -> list[int]:   # LC 1109
    D = [0] * (n + 1)                         # one spare slot for r + 1 == n
    for first, last, seats in bookings:       # 1-indexed, inclusive
        D[first - 1] += seats                 # step up where the range starts
        D[last] -= seats                      # step down just after it ends
    return list(accumulate(D[:n]))            # prefix sum materialises the array

public static int[] CorpFlightBookings(int[][] bookings, int n)   // LC 1109
{
    var D = new int[n + 1];                   // one spare slot for r + 1 == n
    foreach (var b in bookings)               // 1-indexed, inclusive
    {
        D[b[0] - 1] += b[2];                  // step up where the range starts
        D[b[1]] -= b[2];                      // step down just after it ends
    }
    var answer = new int[n];
    int run = 0;
    for (int i = 0; i < n; i++)
        answer[i] = run += D[i];              // prefix sum materialises the array
    return answer;
}

O(1) per update plus one O(n) pass: O(n + q) instead of O(n · q). The same idea in different clothes:

  • Car Pooling (LC 1094): +passengers at pickup and −passengers at drop-off. A running total that ever exceeds capacity means “no”.
  • Coordinates too large for an array? Keep the marks in a sorted map (or a sorted list of events) and sweep them in order. That is exactly the sweep line technique, and “max overlapping intervals” is the maximum of the running sum.
  • Updates and queries interleaved? A difference array only materialises at the end. If you must read values between updates, put the difference array inside a Fenwick tree: a range update becomes two point updates and a point read becomes a prefix sum, both O(log n).

Prefix and difference are inverses diff(prefix(a)) = a and prefix(diff(a)) = a. When a problem mixes “update ranges” and “query ranges”, ask which side of this pair each operation is cheap on. Range update + point query: store differences. Point update + range query: store values and read prefixes. Both at once: a Fenwick tree over differences, or a segment tree with lazy propagation.

2D difference arrays

The 2D version marks four corners. +v at (r1, c1) would spread to every cell below and to the right once you take the 2D prefix sum. Two −v marks stop the spread to the right of c2 and below r2. The corner (r2+1, c2+1) is now cancelled twice, so it gets +v back. The signs match the 2D query formula, for the same inclusion–exclusion reason.

def range_add_queries(n: int, queries: list[list[int]]) -> list[list[int]]:   # LC 2536
    D = [[0] * (n + 1) for _ in range(n + 1)]    # spare row and column
    for r1, c1, r2, c2 in queries:
        D[r1][c1] += 1
        D[r1][c2 + 1] -= 1
        D[r2 + 1][c1] -= 1
        D[r2 + 1][c2 + 1] += 1
    out = [[0] * n for _ in range(n)]
    for r in range(n):                           # 2D prefix sum of D
        for c in range(n):
            up = out[r - 1][c] if r else 0
            left = out[r][c - 1] if c else 0
            diag = out[r - 1][c - 1] if r and c else 0
            out[r][c] = D[r][c] + up + left - diag
    return out

public static int[][] RangeAddQueries(int n, int[][] queries)   // LC 2536
{
    var D = new int[n + 1, n + 1];                   // spare row and column
    foreach (var q in queries)
    {
        int r1 = q[0], c1 = q[1], r2 = q[2], c2 = q[3];
        D[r1, c1]++;
        D[r1, c2 + 1]--;
        D[r2 + 1, c1]--;
        D[r2 + 1, c2 + 1]++;
    }
    var output = new int[n][];
    for (int r = 0; r < n; r++)                      // 2D prefix sum of D
    {
        output[r] = new int[n];
        for (int c = 0; c < n; c++)
        {
            int up = r > 0 ? output[r - 1][c] : 0;
            int left = c > 0 ? output[r][c - 1] : 0;
            int diag = r > 0 && c > 0 ? output[r - 1][c - 1] : 0;
            output[r][c] = D[r, c] + up + left - diag;
        }
    }
    return output;
}

O(1) per rectangle and O(n²) at the end, instead of O(n²) per rectangle. Stamping Grid (LC 2132) uses both 2D tools: a 2D prefix sum to test in O(1) whether a stamp fits at each position, then a 2D difference array to mark every cell some stamp covers.

Recognize it when

Recognize it when

  • Many range-sum queries on an array or matrix that does not change between queries.
  • “Number of subarrays with sum = k”, “longest subarray with sum k”, or “sum divisible by k”, especially when the values can be negative (which rules out a sliding window).
  • A property that can be counted or toggled per element: equal counts of two things (map them to ±1), even counts of letters (parity bitmask), XOR of a range.
  • Many range updates (“add v to all of l…r”, bookings, passengers, overlapping intervals) and the final values are needed once.
  • “Product / max / min of everything except i”, or “best value to the left and to the right of i”.
  • A matrix problem about sub-rectangles: fix two rows (or columns), collapse, and solve a 1D prefix problem.

Prefix mod k none O(1) per element O(k) or O(n) Array of k buckets when k is small

Pitfalls

Off by one between P[r] and P[r+1] With P[0] = 0, the inclusive range l…r is P[r+1] − P[l]. Writing P[r] − P[l] drops nums[r], and writing P[r] − P[l−1] reads P[−1] (in Python, silently the last element) when l = 0. Pick the half-open convention once and test with l = 0 and r = n − 1.

Forgetting seen[0] = 1 (or first[0] = −1) The map must contain the empty prefix before the loop. Without it, every subarray that starts at index 0 is invisible, and the bug only shows up when the answer includes such a subarray.

Inserting before looking up Adding the current prefix to the map and then asking for run − k lets the prefix pair with itself: the empty subarray. For k = 0 it adds one false match per element. Always: look up, then insert.

Overflow and negative remainders In C#, prefix sums of int overflow quietly: use long (10⁵ values of 10⁹ reach 10¹⁴). Remainders of negative prefixes are negative in C#, Java and C++: use ((x % k) + k) % k. In LC 523, k can be close to 2³¹, so even run + nums[i] must be computed in long.

Using a sliding window on values that can be negative “Shrink when the sum is too big” is only correct when every element is ≥ 0. With negatives, use prefix + hash map (exact target) or a monotonic deque over prefix sums (LC 862, shortest subarray with sum at least k).

First index vs last index For the longest subarray keep the first index of each prefix (insert only if absent). Overwriting it with later indices shortens every answer. For the shortest subarray you want the latest index, so overwrite.

2D signs and the difference array’s spare slot The 2D formula is + big − top − left + corner. Getting one sign wrong still passes 1-row and 1-column tests. A 1D difference array needs n + 1 slots (2D: one spare row and column), or updates that end at the last index crash.

Worked problems

Every solution follows the same three steps: write the condition as an equation between two prefixes, decide what to remember about earlier prefixes, and sweep once.

1. Subarray Sum Equals K Medium

Count the contiguous subarrays of nums (values may be negative) whose sum is k.

Insight. sum(j…i) = k ⇔ P[j] = P[i+1] − k. Count earlier prefixes equal to run − k with a hash map, seeded with {0: 1}. This is the prefix + hash map template itself; the visualizer there steps through it.

Solution: prefix + counts map 
from collections import defaultdict

def subarray_sum(nums: list[int], k: int) -> int:
    count, run = 0, 0
    seen = defaultdict(int)
    seen[0] = 1                        # the empty prefix
    for x in nums:
        run += x
        count += seen[run - k]         # look up first ...
        seen[run] += 1                 # ... then insert
    return count

public static int SubarraySum(int[] nums, int k)
{
    var seen = new Dictionary<int, int> { [0] = 1 };  // the empty prefix
    int count = 0, run = 0;
    foreach (int x in nums)
    {
        run += x;
        count += seen.GetValueOrDefault(run - k);      // look up first ...
        seen[run] = seen.GetValueOrDefault(run) + 1;   // ... then insert
    }
    return count;
}

O(n) time, O(n) space.

2. Contiguous Array Medium

Given a binary array, return the length of the longest contiguous subarray with as many 0s as 1s.

Insight. Map 0 → −1 and 1 → +1. A balanced subarray has sum 0, so its two fences have equal prefix values. For the longest one, remember the first index where each prefix value occurs (see the balanced picture).

Solution: first index of each prefix value 
def find_max_length(nums: list[int]) -> int:
    first = {0: -1}                    # prefix 0 happens just before index 0
    best = run = 0
    for i, x in enumerate(nums):
        run += 1 if x == 1 else -1
        if run in first:
            best = max(best, i - first[run])
        else:
            first[run] = i             # keep the earliest index only
    return best

public static int FindMaxLength(int[] nums)
{
    var first = new Dictionary<int, int> { [0] = -1 };  // prefix 0 just before index 0
    int best = 0, run = 0;
    for (int i = 0; i < nums.Length; i++)
    {
        run += nums[i] == 1 ? 1 : -1;
        if (first.TryGetValue(run, out int j))
            best = Math.Max(best, i - j);
        else
            first[run] = i;                              // keep the earliest index only
    }
    return best;
}

O(n) time, O(n) space. The prefix values lie in −n…n, so an array of size 2n + 1 can replace the map.

3. Subarray Sums Divisible by K and Continuous Subarray Sum Medium

LC 974: count subarrays whose sum is divisible by k. LC 523: is there a subarray of length at least 2 whose sum is a multiple of k (values are non-negative, k up to 2³¹ − 1)?

Insight. Both reduce to “two prefixes with the same remainder”. Counting uses k buckets of counts. Existence with a minimum length keeps the first index of each remainder and checks the distance.

Solution: remainder buckets / first index of each remainder 
def subarrays_div_by_k(nums: list[int], k: int) -> int:     # LC 974
    count, run = 0, 0
    buckets = [0] * k
    buckets[0] = 1                     # the empty prefix has remainder 0
    for x in nums:
        run = (run + x) % k            # Python: always 0..k-1
        count += buckets[run]
        buckets[run] += 1
    return count

def check_subarray_sum(nums: list[int], k: int) -> bool:    # LC 523
    first = {0: -1}
    run = 0
    for i, x in enumerate(nums):
        run = (run + x) % k
        if run in first:
            if i - first[run] >= 2:    # length i - first[run] >= 2
                return True
        else:
            first[run] = i             # earliest index maximises the length
    return False

public static int SubarraysDivByK(int[] nums, int k)        // LC 974
{
    var buckets = new int[k];
    buckets[0] = 1;                                // the empty prefix has remainder 0
    int count = 0, run = 0;
    foreach (int x in nums)
    {
        run = ((run + x) % k + k) % k;             // normalise negative remainders
        count += buckets[run];
        buckets[run]++;
    }
    return count;
}

public static bool CheckSubarraySum(int[] nums, int k)      // LC 523
{
    var first = new Dictionary<long, int> { [0] = -1 };
    long run = 0;                                  // k can be near 2^31: avoid overflow
    for (int i = 0; i < nums.Length; i++)
    {
        run = (run + nums[i]) % k;
        if (first.TryGetValue(run, out int j))
        {
            if (i - j >= 2) return true;           // length i - j >= 2
        }
        else first[run] = i;                       // earliest index maximises the length
    }
    return false;
}

Both O(n) time. Space O(k) for 974 (k ≤ 10⁴) and O(min(n, k)) for 523.

4. Corporate Flight Bookings Medium

bookings[i] = [first, last, seats] reserves seats on every flight first…last (1-indexed). Return the total seats on each of the n flights.

Insight. A textbook difference array: two marks per booking, one prefix pass at the end. The code is the difference array template above.

Solution: difference array 
from itertools import accumulate

def corp_flight_bookings(bookings: list[list[int]], n: int) -> list[int]:
    D = [0] * (n + 1)
    for first, last, seats in bookings:
        D[first - 1] += seats
        D[last] -= seats               # index last = (last - 1) + 1 in 0-based terms
    return list(accumulate(D[:n]))

public static int[] CorpFlightBookings(int[][] bookings, int n)
{
    var D = new int[n + 1];
    foreach (var b in bookings)
    {
        D[b[0] - 1] += b[2];
        D[b[1]] -= b[2];               // index last = (last - 1) + 1 in 0-based terms
    }
    var answer = new int[n];
    int run = 0;
    for (int i = 0; i < n; i++)
        answer[i] = run += D[i];
    return answer;
}

O(n + b) time, O(n) space.

5. Product of Array Except Self Medium

Return answer[i] = product of all elements except nums[i], in O(n), without division.

Insight. answer[i] = (product of nums[0…i−1]) × (product of nums[i+1…n−1]). The left products fill the output array in one forward pass; a running suffix product multiplies the right part in on the way back. Zeros need no special case because nothing is ever divided.

Solution: prefix pass, then suffix pass 
def product_except_self(nums: list[int]) -> list[int]:
    n = len(nums)
    out = [1] * n
    for i in range(1, n):
        out[i] = out[i - 1] * nums[i - 1]      # left product
    suffix = 1
    for i in range(n - 1, -1, -1):
        out[i] *= suffix                       # times right product
        suffix *= nums[i]
    return out

public static int[] ProductExceptSelf(int[] nums)
{
    int n = nums.Length;
    var output = new int[n];
    output[0] = 1;
    for (int i = 1; i < n; i++)
        output[i] = output[i - 1] * nums[i - 1];   // left product
    int suffix = 1;
    for (int i = n - 1; i >= 0; i--)
    {
        output[i] *= suffix;                       // times right product
        suffix *= nums[i];
    }
    return output;
}

O(n) time, O(1) extra space.

6. Number of Submatrices That Sum to Target Hard

Count the non-empty sub-rectangles of a matrix (values may be negative) whose sum equals target.

Insight. A rectangle is a band of rows top…bottom and a range of columns. Fix the band: the sum over the band of each column turns the band into a 1D array, and the question becomes LC 560 on that array. Grow bottom one row at a time so the column sums update in O(n).

Solution: fix two rows, run LC 560 on column sums 
from collections import defaultdict

def num_submatrix_sum_target(matrix: list[list[int]], target: int) -> int:
    m, n = len(matrix), len(matrix[0])
    total = 0
    for top in range(m):
        col = [0] * n                          # column sums of rows top..bottom
        for bottom in range(top, m):
            for c in range(n):
                col[c] += matrix[bottom][c]
            seen = defaultdict(int)            # LC 560 on col
            seen[0] = 1
            run = 0
            for v in col:
                run += v
                total += seen[run - target]
                seen[run] += 1
    return total

public static int NumSubmatrixSumTarget(int[][] matrix, int target)
{
    int m = matrix.Length, n = matrix[0].Length, total = 0;
    for (int top = 0; top < m; top++)
    {
        var col = new int[n];                              // column sums of rows top..bottom
        for (int bottom = top; bottom < m; bottom++)
        {
            for (int c = 0; c < n; c++) col[c] += matrix[bottom][c];
            var seen = new Dictionary<int, int> { [0] = 1 };  // LC 560 on col
            int run = 0;
            foreach (int v in col)
            {
                run += v;
                total += seen.GetValueOrDefault(run - target);
                seen[run] = seen.GetValueOrDefault(run) + 1;
            }
        }
    }
    return total;
}

O(m² · n) time, O(n) space. If m > n, transpose first (or fix columns instead) so the squared factor is the smaller side.

7. Count of Range Sum Hard

Count the pairs l ≤ r with lower ≤ sum(nums[l…r]) ≤ upper.

Insight. In prefix terms: count pairs j < i of prefixes with lower ≤ P[i] − P[j] ≤ upper. A hash map only answers equality. For a range of differences you need order, so count pairs during a merge sort of P: when both halves are sorted, the left prefixes that match one right prefix form a contiguous window, and that window only slides right as the right prefix grows (see Sorting for the inversion-count version of this idea).

Solution: merge sort over prefix sums 
def count_range_sum(nums: list[int], lower: int, upper: int) -> int:
    P = [0]
    for x in nums:
        P.append(P[-1] + x)

    def sort_count(lo: int, hi: int) -> int:     # pairs inside P[lo:hi], then sort it
        if hi - lo <= 1:
            return 0
        mid = (lo + hi) // 2
        count = sort_count(lo, mid) + sort_count(mid, hi)
        i = j = lo
        for r in range(mid, hi):                 # right half is sorted ascending
            while i < mid and P[r] - P[i] > upper:
                i += 1                           # P[i] too small: difference too big
            while j < mid and P[r] - P[j] >= lower:
                j += 1                           # first P[j] with difference < lower
            count += j - i
        P[lo:hi] = sorted(P[lo:hi])              # or a linear merge
        return count

    return sort_count(0, len(P))

public static int CountRangeSum(int[] nums, int lower, int upper)
{
    var P = new long[nums.Length + 1];
    for (int i = 0; i < nums.Length; i++) P[i + 1] = P[i] + nums[i];
    return SortCount(P, 0, P.Length, lower, upper);
}

static int SortCount(long[] P, int lo, int hi, int lower, int upper)   // pairs inside [lo, hi)
{
    if (hi - lo <= 1) return 0;
    int mid = (lo + hi) / 2;
    int count = SortCount(P, lo, mid, lower, upper) + SortCount(P, mid, hi, lower, upper);
    int i = lo, j = lo;
    for (int r = mid; r < hi; r++)                     // right half is sorted ascending
    {
        while (i < mid && P[r] - P[i] > upper) i++;    // difference too big
        while (j < mid && P[r] - P[j] >= lower) j++;   // first difference < lower
        count += j - i;
    }
    Array.Sort(P, lo, hi - lo);                        // or a linear merge
    return count;
}

O(n log² n) with the library sort shown, O(n log n) with a hand-written linear merge; O(n) space. Sorting the right half does not break anything because pairs are counted only across the halves, and every right index is after every left index. Alternatives: a Fenwick tree over coordinate-compressed prefix values, or a sorted container with bisect.

8. Max Sum of Rectangle No Larger Than K Expert

Return the largest sum of a sub-rectangle that is at most k.

Insight. Two layers of reduction. Fix two columns and collapse the band into row sums (as in problem 6). In 1D, for the current prefix run, the best start is the smallest earlier prefix ≥ run − k: a ceiling lookup in a sorted set (bisect in Python, SortedSet.GetViewBetween in C#). Kadane does not work because the constraint is “at most k”, not “as large as possible”.

Solution: fix two columns, sorted set of prefixes 
import bisect

def max_sum_submatrix(matrix: list[list[int]], k: int) -> int:
    m, n = len(matrix), len(matrix[0])
    best = float("-inf")
    for left in range(n):
        row = [0] * m                            # row sums of columns left..right
        for right in range(left, n):
            for r in range(m):
                row[r] += matrix[r][right]
            seen = [0]                           # sorted earlier prefixes
            run = 0
            for v in row:
                run += v
                i = bisect.bisect_left(seen, run - k)   # smallest prefix >= run - k
                if i < len(seen):
                    best = max(best, run - seen[i])
                bisect.insort(seen, run)
    return best

public static int MaxSumSubmatrix(int[][] matrix, int k)
{
    int m = matrix.Length, n = matrix[0].Length, best = int.MinValue;
    for (int left = 0; left < n; left++)
    {
        var row = new int[m];                                // row sums of columns left..right
        for (int right = left; right < n; right++)
        {
            for (int r = 0; r < m; r++) row[r] += matrix[r][right];
            var seen = new SortedSet<int> { 0 };             // earlier prefixes
            int run = 0;
            foreach (int v in row)
            {
                run += v;
                var view = seen.GetViewBetween(run - k, int.MaxValue);   // prefixes >= run - k
                if (view.Count > 0) best = Math.Max(best, run - view.Min);
                seen.Add(run);
            }
        }
    }
    return best;
}

O(n² · m log m) time with a balanced tree (C#). Python’s insort is O(m) per insert, so O(n² · m²) in the worst case, which is still fine at LeetCode’s 100 × 100; use sortedcontainers.SortedList for a true O(log m). Collapse along the larger dimension so that the squared factor is the smaller one. Prefix sums fit in int here; use long otherwise.

Self-check

Why does P have n + 1 entries instead of n?

P[0] = 0 is the sum of the empty prefix. It makes P[r+1] − P[l] correct for l = 0 without a special case, and in the hash-map pattern it is the seen[0] = 1 seed that lets a subarray start at index 0.

In LC 560, what goes wrong if you insert run into the map before looking up run − k?

When k = 0, run − k = run is found immediately: the current prefix pairs with itself, which is the empty subarray. Every element adds a false match. For k ≠ 0 it happens to work, which is why the bug survives casual tests.

Why can a sliding window not solve “count subarrays with sum k” when values can be negative?

The window technique needs monotonicity: extending the window must never decrease the sum, so “too big” safely means “move the left edge”. A negative value breaks that, so a window that is too big now may be exactly right after a few more elements. Prefix + hash map checks every left edge at once instead of moving one.

For the longest subarray with sum k, do you store the first or the last index of each prefix? Why?

The first. The length is i − index, which is largest when index is smallest. Insert a prefix only if it is not yet in the map and seed the map with {0: −1}.

Write the 2D query for rows r1…r2, columns c1…c2, and explain the last term.

P[r2+1][c2+1] − P[r1][c2+1] − P[r2+1][c1] + P[r1][c1]. The two subtracted strips (above and to the left) overlap in the block above-left of the query, which was therefore removed twice. Adding P[r1][c1] puts it back once.

You must add v to a[l…r] 10⁵ times and print the array once. What do you store, and why does it work?

A difference array D with n + 1 slots: D[l] += v, D[r+1] −= v, then one prefix-sum pass. Inside the range all neighbours move together, so only the two boundary differences change; the prefix sum turns differences back into values. O(n + q) instead of O(n · q).

Why does LC 974 count pairs of prefixes with equal remainders, and what changes in C#?

(P[i] − P[j]) mod k = 0 exactly when P[i] mod k = P[j] mod k. In C#, % of a negative number is negative, so −2 and 3 would land in different buckets although both mean “3 mod 5”. Normalise with ((x % k) + k) % k.
