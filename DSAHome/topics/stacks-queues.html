LINKED LISTS, STACKS, QUEUES & HEAPS

Stacks & Queues

Balanced brackets, expression evaluation, min-stack, queues from stacks, deques and BFS queues.

Beginner → Intermediate~40 min studyUpdated 2026-11-03

Two containers, two orders

A stack and a queue both hold items you will come back to later. The only difference is which item you get back. A stack returns the newest item (last in, first out: LIFO). A queue returns the oldest (first in, first out: FIFO). Both support their core operations in O(1), and that is the point: they are not clever data structures. The skill is recognising which order the problem needs.

The one rule. Use a stack when the thing you must deal with next is the most recent unfinished thing (an open bracket, an operator waiting for its right operand, an outer context you paused). Use a queue when you must deal with things in the order they arrived (BFS layers, a buffer, a scheduler).

Push the same items into both and pop them all. Watch the order flip:

Two traps in the libraries. In Python, list.pop(0) and list.insert(0, x) shift every element: O(n). A BFS written with them is O(n²) and times out on big inputs. Use deque. In C#, enumerating a Stack<T> (with foreach, ToArray, ToList or LINQ) goes top to bottom, the reverse of push order. new Stack<int>(list) pushes the list in order, so its top is the last element. When you want "bottom to top", call Reverse() first.

A stack holds the most recent unmatched thing

Many problems have nesting: brackets inside brackets, a sub-expression inside a parenthesis, a function call inside a function call, 3[a2[c]]. Nesting has one property that makes a stack the right tool: whatever opened last must close first. When you meet a closer, the only candidate partner is the most recent opener that is still unmatched, which is exactly the top of a stack.

The same shape shows up all over the place:

  • Recursion is a stack. Every call pushes a frame; returning pops it. Any recursive algorithm can be rewritten with an explicit stack, which is how you avoid Python's recursion limit (see Recursion).
  • DFS uses a stack (implicitly through recursion, or explicitly); BFS uses a queue. Swapping the container swaps the traversal order.
  • Undo and the browser back button are stacks: the most recent action is undone first.
  • "Next greater element" and similar "who is the nearest bigger thing" questions use a stack that stays sorted. That has its own page: Monotonic Stack & Queue.

Balanced brackets

The classic first problem: is s (made of ()[]{}, possibly with other characters mixed in) properly nested? Push every opener. On a closer, the top of the stack must be the matching opener; pop it. At the end the stack must be empty. That gives three distinct ways to fail, and the visualizer reaches all of them: a closer with an empty stack, a closer of the wrong type, and openers left over at the end.

def is_valid(s: str) -> bool:
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in '([{':
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False          # nothing open, or the wrong kind
    return not stack                  # leftovers were never closed

public static bool IsValid(string s)
{
    var pairs = new Dictionary<char, char> { [')'] = '(', [']'] = '[', ['}'] = '{' };
    var stack = new Stack<char>();
    foreach (char ch in s)
    {
        if (ch == '(' || ch == '[' || ch == '{') stack.Push(ch);
        else if (pairs.TryGetValue(ch, out char open))
        {
            if (stack.Count == 0 || stack.Pop() != open) return false;
        }
    }
    return stack.Count == 0;
}

Only one kind of bracket? Then you don't need a stack at all, only its height: a counter depth. ( adds one, ) subtracts one, the string is invalid the moment depth goes negative, and valid if it ends at 0. With several kinds you need the stack because you must know which kind is on top.

Minimum removals to make it valid

LC 1249: remove as few ( and ) as possible so the rest is valid (letters stay). The stack tells you exactly which characters can never be matched. Push the index of every (. A ) that finds the stack empty has no partner anywhere to its left: mark it for removal. When the scan ends, whatever is still on the stack is a ( with no partner to its right: mark those too. Removing precisely those characters is optimal, because each one is provably unmatchable and everything else got paired.

def min_remove_to_make_valid(s: str) -> str:
    stack, remove = [], set()
    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
        elif ch == ')':
            if stack:
                stack.pop()
            else:
                remove.add(i)          # no '(' to its left is free
    remove.update(stack)               # no ')' to their right is free
    return ''.join(ch for i, ch in enumerate(s) if i not in remove)

public static string MinRemoveToMakeValid(string s)
{
    var stack = new Stack<int>();
    var remove = new HashSet<int>();
    for (int i = 0; i < s.Length; i++)
    {
        if (s[i] == '(') stack.Push(i);
        else if (s[i] == ')')
        {
            if (stack.Count > 0) stack.Pop();
            else remove.Add(i);
        }
    }
    remove.UnionWith(stack);
    var sb = new StringBuilder();
    for (int i = 0; i < s.Length; i++)
        if (!remove.Contains(i)) sb.Append(s[i]);
    return sb.ToString();
}

Longest valid substring: keep a "wall" at the bottom

LC 32 (Hard) asks for the length of the longest valid substring of a (/) string. Push indices again, and add one trick: the bottom of the stack always holds the index just before the current valid run (start with -1). When a ) matches, the run that just closed reaches back to whatever index is now on top, so its length is i - stack[-1]. When a ) has nothing to match it pops the wall itself; no valid substring can cross this ), so its own index becomes the new wall.

The full code is worked problem 5 below. There is also an O(1)-space two-pass counter solution, shown there as an alternative.

Evaluating expressions

Expressions are nesting too: 3 + 4 * (2 - 1) contains the sub-expression 2 - 1 inside a parenthesis, and 4 * … inside the + because * binds tighter. Every expression is secretly a tree. Operators are internal nodes, numbers are leaves, and precedence and parentheses decide the shape. The three classic notations are three traversal orders of that tree.

Reverse Polish Notation: one stack, no rules

Read tokens left to right. A number is pushed. An operator pops its two operands (the first pop is the right operand b), computes a op b and pushes the result. Each value on the stack stands for a whole finished sub-tree; the visualizer shows the sub-expression each value represents.

def eval_rpn(tokens: list[str]) -> int:
    stack = []
    for t in tokens:
        if t in {'+', '-', '*', '/'}:
            b = stack.pop()            # right operand comes off first
            a = stack.pop()
            if t == '+': stack.append(a + b)
            elif t == '-': stack.append(a - b)
            elif t == '*': stack.append(a * b)
            else: stack.append(int(a / b))   # truncate toward zero, not //
        else:
            stack.append(int(t))
    return stack.pop()

public static int EvalRPN(string[] tokens)
{
    var stack = new Stack<int>();
    foreach (var t in tokens)
    {
        if (t is "+" or "-" or "*" or "/")
        {
            int b = stack.Pop(), a = stack.Pop();
            stack.Push(t switch { "+" => a + b, "-" => a - b, "*" => a * b, _ => a / b }); // C# '/' truncates
        }
        else stack.Push(int.Parse(t));
    }
    return stack.Pop();
}

Division rounds differently. LeetCode-style problems want division that truncates toward zero: -7 / 2 = -3. C#'s / on ints does exactly that. Python's // floors: -7 // 2 = -4. Use int(a / b) (fine for 32-bit values) or -(-a // b) when the signs differ. Also pop b first: a - b and a / b are not symmetric.

Shunting-yard: infix to postfix

Dijkstra's shunting-yard algorithm converts infix to postfix with one operator stack. Numbers go straight to the output because their relative order never changes. An operator has to wait, because something stronger might follow (3 + 4 * 2: the * must run before the +). So before pushing an operator, pop every waiting operator that binds at least as tightly: those are complete and can go out. ( is a wall that nothing pops past, and ) flushes everything back to its (.

The one subtle rule is associativity. 8 - 3 - 2 means (8 - 3) - 2, so on equal precedence the earlier operator goes first (pop it). 2 ^ 3 ^ 2 means 2 ^ (3 ^ 2), so on equal precedence a right-associative operator must not pop the earlier one. Try both in the visualizer.

def to_postfix(tokens: list[str]) -> list[str]:
    prec = {'+': 1, '-': 1, '*': 2, '/': 2, '^': 3}
    out, ops = [], []
    for t in tokens:
        if t.isdigit():
            out.append(t)
        elif t == '(':
            ops.append(t)
        elif t == ')':
            while ops[-1] != '(':
                out.append(ops.pop())
            ops.pop()                                  # drop the '('
        else:
            while (ops and ops[-1] != '(' and
                   (prec[ops[-1]] > prec[t] or
                    prec[ops[-1]] == prec[t] and t != '^')):
                out.append(ops.pop())
            ops.append(t)
    while ops:
        out.append(ops.pop())
    return out

public static List<string> ToPostfix(IEnumerable<string> tokens)
{
    var prec = new Dictionary<string, int> { ["+"] = 1, ["-"] = 1, ["*"] = 2, ["/"] = 2, ["^"] = 3 };
    var output = new List<string>();
    var ops = new Stack<string>();
    foreach (var t in tokens)
    {
        if (char.IsDigit(t[0])) output.Add(t);
        else if (t == "(") ops.Push(t);
        else if (t == ")")
        {
            while (ops.Peek() != "(") output.Add(ops.Pop());
            ops.Pop();
        }
        else
        {
            while (ops.Count > 0 && ops.Peek() != "(" &&
                   (prec[ops.Peek()] > prec[t] || prec[ops.Peek()] == prec[t] && t != "^"))
                output.Add(ops.Pop());
            ops.Push(t);
        }
    }
    while (ops.Count > 0) output.Add(ops.Pop());
    return output;
}

Evaluate without building the postfix. Replace "append the operator to the output" with "pop two values from a value stack, apply the operator, push the result". You now have two stacks (values and operators) and a one-pass evaluator for any infix expression. This is the general tool behind every calculator problem; the special cases below are just leaner versions of it.

Basic Calculator II: one stack of terms

LC 227 has + - * / but no parentheses. A leaner idea than shunting-yard: an expression without parentheses is a sum of terms, where each term is a product/quotient chain. 3 + 2*2 - 8/3*3 is 3 + (4) + (-6). Keep a stack of terms. Track op, the operator in front of the number you are reading. When the number ends, act on op: + pushes the number, - pushes its negative, and * or / combine it with the top term immediately, because they bind tighter than anything that could come later. The answer is the sum of the stack. A sentinel + at the end flushes the last number.

def calculate_ii(s: str) -> int:
    stack, num, op = [], 0, '+'
    for ch in s + '+':
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch in '+-*/':
            if op == '+': stack.append(num)
            elif op == '-': stack.append(-num)
            elif op == '*': stack.append(stack.pop() * num)
            else: stack.append(int(stack.pop() / num))
            op, num = ch, 0
        # spaces fall through
    return sum(stack)

public static int CalculateII(string s)
{
    var stack = new Stack<int>();
    int num = 0;
    char op = '+';
    foreach (char ch in s + "+")
    {
        if (char.IsDigit(ch)) num = num * 10 + (ch - '0');
        else if (ch is '+' or '-' or '*' or '/')
        {
            if (op == '+') stack.Push(num);
            else if (op == '-') stack.Push(-num);
            else if (op == '*') stack.Push(stack.Pop() * num);
            else stack.Push(stack.Pop() / num);
            op = ch;
            num = 0;
        }
    }
    return stack.Sum();
}

You can drop the stack entirely: keep total (sum of finished terms) and last (the current term). * and / rewrite last; + and - add last to total and start a new one. Same O(n) time, O(1) space. The stack version is easier to extend, which matters for the next one.

Basic Calculator: parentheses save and restore state

LC 224 (Hard) has only + -, but with parentheses and unary minus (-(2 + 3)). With only + and - the answer is a running sum res, and sign is the sign in front of the number being read. A ( starts a fresh sub-sum, so push the outer state (res, sign) and reset. A ) finishes the sub-sum: pop the saved state and fold the inner result into it: res = saved_res + saved_sign * res. Unary minus needs no special case: - before ( simply sets sign = -1 and that sign is saved with the outer state.

This is the general recipe for nested problems: a stack frame is whatever you need to resume the outer level. Here it is (res, sign); in Decode String below it is (text so far, repeat count); in recursion it is the local variables. The full code, plus the version that also handles * and / with parentheses (Basic Calculator III), is in worked problems 6 and 7.

Stacks that carry extra state

A stack entry does not have to be a single value. Store whatever you will need when that entry becomes the top again. Two classic designs show the idea.

Min stack: remember the minimum at every height

LC 155: a stack with push, pop, top and getMin, all O(1). A single min variable fails as soon as you pop the minimum, because the previous minimum is gone. The fix: next to every value, store the minimum of everything at or below it. A stack only changes at the top, so what lies below an entry never changes while that entry exists, and its stored minimum stays correct. Popping restores the previous minimum for free.

class MinStack:
    def __init__(self):
        self.st = []                   # (value, min of this and everything below)

    def push(self, x: int) -> None:
        m = min(x, self.st[-1][1]) if self.st else x
        self.st.append((x, m))

    def pop(self) -> None:
        self.st.pop()

    def top(self) -> int:
        return self.st[-1][0]

    def getMin(self) -> int:
        return self.st[-1][1]

public class MinStack
{
    private readonly Stack<(int Val, int Min)> st = new();

    public void Push(int x) => st.Push((x, st.Count == 0 ? x : Math.Min(x, st.Peek().Min)));
    public void Pop() => st.Pop();
    public int Top() => st.Peek().Val;
    public int GetMin() => st.Peek().Min;
}

The same trick answers "max so far", "sum so far" or "how many evens so far" for a stack. It does not work for a queue directly, because a queue changes at the bottom too. The way around that is a queue built from two stacks (below), each a min-stack, or the monotonic deque from Monotonic Stack & Queue.

Decode String: a frame per bracket level

LC 394: 3[a2[c]] decodes to accaccacc. Brackets nest, so use a stack. While reading, keep cur (text decoded at the current level) and k (the repeat count being read; it can have several digits). On [, the outer level is paused: push (cur, k) and start an empty cur. On ], pop (prev, n) and set cur = prev + cur * n. The inner level has been folded into the outer one.

The code is worked problem 2.

Collisions: when the newcomer fights the top

LC 735, Asteroid Collision: positive numbers move right, negative move left, equal speed. When two meet, the smaller explodes (both, if equal). Scan left to right with a stack of survivors. The only possible collision is a left-mover arriving while the top is a right-mover. Everything below the top is shielded by it. The newcomer either destroys the top and keeps fighting the next one, dies with it, or dies against it. If it survives every fight it is pushed.

"Keep popping while the newcomer beats the top" is the heart of the monotonic stack. Here the comparison is a collision. In "next greater element" it is "is the new value bigger than the top?". In "largest rectangle in histogram" it is a height. Each element is pushed once and popped at most once, so the nested while is O(n) in total, not O(n²). This is the most common amortized argument in interviews. The Monotonic Stack & Queue page builds a whole family of problems on it.

Other "the newcomer cancels the top" problems: Remove All Adjacent Duplicates in String (abbaca → ca, with a stack of characters), Backspace String Compare (# pops), Baseball Game (C pops, D doubles the top), and Remove K Digits.

Queues

A queue built from two stacks

LC 232: implement a queue using only stack operations. One stack reverses order, so two reversals restore it. Push into in. To pop, take from out; if out is empty, first pour all of in into out, which reverses them and leaves the oldest element on top.

class MyQueue:
    def __init__(self):
        self.inb, self.out = [], []

    def push(self, x: int) -> None:
        self.inb.append(x)

    def _move(self) -> None:
        if not self.out:                       # only refill when out is empty
            while self.inb:
                self.out.append(self.inb.pop())

    def pop(self) -> int:
        self._move()
        return self.out.pop()

    def peek(self) -> int:
        self._move()
        return self.out[-1]

    def empty(self) -> bool:
        return not self.inb and not self.out

public class MyQueue
{
    private readonly Stack<int> inb = new(), outb = new();

    public void Push(int x) => inb.Push(x);

    private void Move()
    {
        if (outb.Count == 0)
            while (inb.Count > 0) outb.Push(inb.Pop());
    }

    public int Pop() { Move(); return outb.Pop(); }
    public int Peek() { Move(); return outb.Peek(); }
    public bool Empty() => inb.Count == 0 && outb.Count == 0;
}

Why is that O(1)? A single pop can move n elements, so the worst case of one call is O(n). But follow one element through its life instead of one call through its work:

Refilling too eagerly breaks it. If you move in into out on every pop even when out is not empty, the order gets mixed (new items land on top of older ones in out), and the cost becomes O(n) per call. The rule is: refill only when out is empty, and then move everything.

The reverse (LC 225, a stack from one queue) is the cheap trick: after each push(x), rotate the queue len - 1 times (popleft and append) so that x comes to the front. Push is O(n), pop is O(1). It is mostly an exercise; nobody needs it in practice.

Circular buffers and deques

How do deque and Queue<T> get O(1) at the front without shifting? They use a ring buffer: a fixed array, an index head for the front, and a size. The live elements are a[head], a[head+1], …, a[head+size-1], every index taken mod capacity. Popping the front just moves head forward; pushing at the front moves head back (wrapping from 0 to the last slot). Nothing ever shifts. (Queue<T> grows by copying into an array twice as big when full; CPython's deque actually links fixed-size blocks, but the idea is the same.)

Design Circular Queue (LC 622) and Design Circular Deque (LC 641) are exactly this. The full deque is worked problem 4. Keeping size (instead of a separate tail index) avoids the classic ambiguity where head == tail could mean either empty or full.

BFS preview: the queue that measures distance

The most important use of a queue in algorithms is breadth-first search. Start from the source, and repeatedly take the oldest discovered cell and discover its unseen neighbours. Because the queue is FIFO, every cell at distance d leaves the queue before any cell at distance d + 1 arrives at the front. Cells are therefore processed in order of distance, and the first time BFS reaches a cell is along a shortest path (in an unweighted graph).

from collections import deque

def shortest_path(grid: list[str]) -> int:
    rows, cols = len(grid), len(grid[0])
    start = next((r, c) for r in range(rows) for c in range(cols) if grid[r][c] == 'S')
    q = deque([start])
    dist = {start: 0}
    while q:
        r, c = q.popleft()
        if grid[r][c] == 'T':
            return dist[(r, c)]
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] != '#' and (nr, nc) not in dist:
                dist[(nr, nc)] = dist[(r, c)] + 1    # mark when enqueued
                q.append((nr, nc))
    return -1

public static int ShortestPath(string[] grid)
{
    int rows = grid.Length, cols = grid[0].Length;
    var dist = new int[rows, cols];
    var q = new Queue<(int R, int C)>();
    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
        {
            dist[r, c] = -1;
            if (grid[r][c] == 'S') { q.Enqueue((r, c)); }
        }
    var (sr, sc) = q.Peek();
    dist[sr, sc] = 0;
    int[] dr = { 1, -1, 0, 0 }, dc = { 0, 0, 1, -1 };
    while (q.Count > 0)
    {
        var (r, c) = q.Dequeue();
        if (grid[r][c] == 'T') return dist[r, c];
        for (int k = 0; k < 4; k++)
        {
            int nr = r + dr[k], nc = c + dc[k];
            if (nr < 0 || nc < 0 || nr >= rows || nc >= cols || grid[nr][nc] == '#' || dist[nr, nc] >= 0) continue;
            dist[nr, nc] = dist[r, c] + 1;
            q.Enqueue((nr, nc));
        }
    }
    return -1;
}

Mark when you enqueue, not when you dequeue. If you only mark a cell as seen when it is popped, two neighbours can both enqueue the same cell before it is popped. The queue can then grow to many times the number of cells: same answer, but much slower, and it often hits the time limit on large grids.

BFS on general graphs, multi-source BFS, BFS by levels and 0-1 BFS (a deque: weight-0 edges go to the front) are covered in Graph Fundamentals and Shortest Paths.

One more way to see it. A stack turns recursion inside out: every recursive solution can be rewritten with an explicit stack of frames, and every problem above that pushes "the state to resume later" (Decode String, Basic Calculator, iterative DFS) is exactly that rewrite. A queue does the same for "breadth": it is the to-do list of a process that must finish everything at distance d before anything at distance d + 1.

Pitfalls and a debugging checklist

Popping an empty stack. stack.pop() on an empty list raises IndexError; Stack<T>.Pop() throws InvalidOperationException. In bracket problems an empty stack at a closer is not a crash, it is an answer ("invalid", or "unmatched, remove it"). Check if stack first, or use TryPop / TryPeek in C#.

Losing the last number. A calculator loop acts on a number when it sees the next operator, so the final number is never processed. Either append a sentinel (s + '+'), or repeat the "flush" step after the loop. Also build multi-digit numbers with num = num * 10 + digit; reading one character as one number breaks on 12.

Pushing the wrong thing. Push indices when you need positions later (lengths, removals, distances); you can always look up s[i] from an index, but not the other way round. Push tuples when you need to restore several variables ((res, sign), (cur, k)).

Recursion that is too deep. A recursive parser on ((((…)))) with 10⁵ levels overflows Python's default limit of 1000 frames and can overflow the C# call stack too. The explicit-stack versions on this page have no such limit, which is one reason they are the preferred answers.

Debugging checklist

  1. Write down what one stack entry means: "an unmatched ( at index i", "a finished term", "the outer state to resume". Every push and pop must respect that meaning.
  2. When does an entry leave? Each element should be pushed once and popped at most once; if not, your complexity argument is gone.
  3. What happens at the end of the input? Flush pending numbers, check that the stack is empty, or treat the leftovers as the answer.
  4. Run the edge cases: empty input, a single token, everything nested (((((), nothing nested, a closer first, numbers with several digits, negative results.

Recognize it when

  • The input has nesting: brackets, parentheses in an expression, k[...], tags, directories in a path (.. pops). Stack.
  • You must match each item with the most recent compatible item before it: closers with openers, a left-mover with a right-mover. Stack.
  • "Undo", "backspace", "cancel the previous one", "remove adjacent pairs". Stack.
  • A process must resume an outer level after finishing an inner one: push the outer state. Any recursion can be turned into this.
  • "Next greater / smaller", "how far until a bigger one", "largest rectangle": a monotonic stack (Monotonic Stack & Queue).
  • Things must be processed in arrival order, or level by level, or you need the fewest steps in an unweighted graph or grid. Queue / BFS.
  • A fixed-size window of recent events ("calls in the last 3000 ms"): a queue that drops from the front as time moves.
  • Fast access to both ends: deque. Fast access to the best element: not a queue at all, use a heap.

Worked problems

1. Asteroid Collision Medium

Positive = moving right, negative = moving left; when two meet, the smaller explodes (both if equal). Return the survivors. Insight: only "top moves right, newcomer moves left" collides. Fight in a while loop; Python's while … else runs the else only when the loop ended without break, which is exactly "the newcomer survived". The visualizer in the Collisions section runs this code.

Solution: O(n) time, O(n) space 
def asteroid_collision(asteroids: list[int]) -> list[int]:
    stack = []
    for a in asteroids:
        while stack and a < 0 < stack[-1]:
            if stack[-1] < -a:
                stack.pop()            # top explodes; a keeps flying
                continue
            if stack[-1] == -a:
                stack.pop()            # both explode
            break                      # a explodes
        else:
            stack.append(a)            # no break: a survived
    return stack

public static int[] AsteroidCollision(int[] asteroids)
{
    var stack = new List<int>();               // a List used as a stack keeps the output order
    foreach (int a in asteroids)
    {
        bool alive = true;
        while (alive && a < 0 && stack.Count > 0 && stack[^1] > 0)
        {
            int top = stack[^1];
            if (top < -a) { stack.RemoveAt(stack.Count - 1); continue; }
            if (top == -a) stack.RemoveAt(stack.Count - 1);
            alive = false;
        }
        if (alive) stack.Add(a);
    }
    return stack.ToArray();
}

2. Decode String Medium

Decode k[encoded] recursively nested strings: 3[a2[c]] → accaccacc. Insight: each [ opens a level, so push the state needed to resume the outer level, (text so far, k). Build text as a list of pieces (or a StringBuilder): repeated cur += ch on immutable strings is quadratic in the worst case.

Solution: O(output length) time 
def decode_string(s: str) -> str:
    stack, cur, k = [], [], 0
    for ch in s:
        if ch.isdigit():
            k = k * 10 + int(ch)
        elif ch == '[':
            stack.append((cur, k))     # pause the outer level
            cur, k = [], 0
        elif ch == ']':
            prev, n = stack.pop()
            prev.append(''.join(cur) * n)
            cur = prev                 # resume the outer level
        else:
            cur.append(ch)
    return ''.join(cur)

public static string DecodeString(string s)
{
    var stack = new Stack<(StringBuilder Prev, int K)>();
    var cur = new StringBuilder();
    int k = 0;
    foreach (char ch in s)
    {
        if (char.IsDigit(ch)) k = k * 10 + (ch - '0');
        else if (ch == '[')
        {
            stack.Push((cur, k));
            cur = new StringBuilder();
            k = 0;
        }
        else if (ch == ']')
        {
            var (prev, n) = stack.Pop();
            string inner = cur.ToString();
            for (int i = 0; i < n; i++) prev.Append(inner);
            cur = prev;
        }
        else cur.Append(ch);
    }
    return cur.ToString();
}

3. Simplify Path Medium

Turn a Unix path such as /a/./b/../../c/ into its canonical form /c. Insight: split on /. The directories you are currently inside form a stack: a name pushes, .. pops (if possible), and . or an empty piece does nothing. The answer is the stack from bottom to top, joined with /. (In C#, that is exactly where Stack<T>'s top-first enumeration bites; a List<string> used as a stack avoids it.)

Solution: O(n) time, O(n) space 
def simplify_path(path: str) -> str:
    stack = []
    for part in path.split('/'):
        if part == '..':
            if stack:
                stack.pop()
        elif part and part != '.':
            stack.append(part)
    return '/' + '/'.join(stack)

public static string SimplifyPath(string path)
{
    var stack = new List<string>();
    foreach (var part in path.Split('/'))
    {
        if (part == "..") { if (stack.Count > 0) stack.RemoveAt(stack.Count - 1); }
        else if (part != "" && part != ".") stack.Add(part);
    }
    return "/" + string.Join("/", stack);
}

4. Design Circular Deque Medium

Implement a fixed-capacity deque: insertFront, insertLast, deleteFront, deleteLast, getFront, getRear (−1 when empty), isEmpty, isFull. Inserts return False when full; deletes return False when empty. Insight: the ring buffer from the visualizer above: an array, head, size, and indices mod k. Python's % already returns a non-negative result for -1 % k; C#'s % does not, so add k before taking the remainder.

Solution: O(1) per operation, O(k) space 
class MyCircularDeque:
    def __init__(self, k: int):
        self.a = [0] * k
        self.head = 0
        self.size = 0

    def insertFront(self, value: int) -> bool:
        if self.isFull():
            return False
        self.head = (self.head - 1) % len(self.a)
        self.a[self.head] = value
        self.size += 1
        return True

    def insertLast(self, value: int) -> bool:
        if self.isFull():
            return False
        self.a[(self.head + self.size) % len(self.a)] = value
        self.size += 1
        return True

    def deleteFront(self) -> bool:
        if self.isEmpty():
            return False
        self.head = (self.head + 1) % len(self.a)
        self.size -= 1
        return True

    def deleteLast(self) -> bool:
        if self.isEmpty():
            return False
        self.size -= 1
        return True

    def getFront(self) -> int:
        return -1 if self.isEmpty() else self.a[self.head]

    def getRear(self) -> int:
        return -1 if self.isEmpty() else self.a[(self.head + self.size - 1) % len(self.a)]

    def isEmpty(self) -> bool:
        return self.size == 0

    def isFull(self) -> bool:
        return self.size == len(self.a)

public class MyCircularDeque
{
    private readonly int[] a;
    private int head, size;

    public MyCircularDeque(int k) => a = new int[k];

    public bool InsertFront(int value)
    {
        if (IsFull()) return false;
        head = (head - 1 + a.Length) % a.Length;    // C# % can be negative
        a[head] = value;
        size++;
        return true;
    }

    public bool InsertLast(int value)
    {
        if (IsFull()) return false;
        a[(head + size) % a.Length] = value;
        size++;
        return true;
    }

    public bool DeleteFront()
    {
        if (IsEmpty()) return false;
        head = (head + 1) % a.Length;
        size--;
        return true;
    }

    public bool DeleteLast()
    {
        if (IsEmpty()) return false;
        size--;
        return true;
    }

    public int GetFront() => IsEmpty() ? -1 : a[head];
    public int GetRear() => IsEmpty() ? -1 : a[(head + size - 1) % a.Length];
    public bool IsEmpty() => size == 0;
    public bool IsFull() => size == a.Length;
}

5. Longest Valid Parentheses Hard

Given a string of ( and ), return the length of the longest valid (well-formed) substring. Insight: keep the index just before the current valid run at the bottom of the stack (initially -1). Every ) pops. If the stack becomes empty, this ) is unmatched and is the new wall. Otherwise the run ending here starts right after the new top, so its length is i - stack[-1]. The visualizer in the Balanced brackets section steps through it.

Alternative with O(1) space: scan left to right counting open and close. When they are equal you have a valid run of 2 · close; when close > open the run is broken, so reset both. That misses runs with surplus ( such as ((), so scan again right to left with the roles swapped.

Solution: O(n) time, O(n) space (stack) or O(1) space (two passes) 
def longest_valid_parentheses(s: str) -> int:
    stack, best = [-1], 0
    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
        else:
            stack.pop()
            if not stack:
                stack.append(i)                # unmatched ')': new wall
            else:
                best = max(best, i - stack[-1])
    return best


def longest_valid_two_pass(s: str) -> int:
    best = 0
    for seq, opener in ((s, '('), (reversed(s), ')')):
        opened = closed = 0
        for ch in seq:
            if ch == opener:
                opened += 1
            else:
                closed += 1
            if opened == closed:
                best = max(best, 2 * closed)
            elif closed > opened:
                opened = closed = 0
    return best

public static int LongestValidParentheses(string s)
{
    var stack = new Stack<int>();
    stack.Push(-1);
    int best = 0;
    for (int i = 0; i < s.Length; i++)
    {
        if (s[i] == '(') { stack.Push(i); continue; }
        stack.Pop();
        if (stack.Count == 0) stack.Push(i);
        else best = Math.Max(best, i - stack.Peek());
    }
    return best;
}

public static int LongestValidTwoPass(string s)
{
    int best = 0;
    for (int pass = 0; pass < 2; pass++)
    {
        int opened = 0, closed = 0;
        char opener = pass == 0 ? '(' : ')';
        for (int k = 0; k < s.Length; k++)
        {
            char ch = pass == 0 ? s[k] : s[s.Length - 1 - k];
            if (ch == opener) opened++; else closed++;
            if (opened == closed) best = Math.Max(best, 2 * closed);
            else if (closed > opened) opened = closed = 0;
        }
    }
    return best;
}

6. Basic Calculator Hard

Evaluate a string with non-negative integers, +, -, parentheses, spaces, and unary minus (-(2+3), 1-(-2)). No eval. Insight: with only + and -, the value is a signed running sum. ( pushes the outer (res, sign) and starts a fresh sum; ) folds the inner sum into the saved one. A unary minus is just the sign in front of the next number or (; since res is still 0 at that point, res += sign * num with num = 0 changes nothing. Watch it in the Basic Calculator visualizer above.

Solution: O(n) time, O(nesting depth) space 
def calculate(s: str) -> int:
    res, num, sign, stack = 0, 0, 1, []
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch in '+-':
            res += sign * num
            num, sign = 0, (1 if ch == '+' else -1)
        elif ch == '(':
            stack.append((res, sign))          # save the outer state
            res, sign = 0, 1
        elif ch == ')':
            res += sign * num
            prev_res, prev_sign = stack.pop()
            res, num = prev_res + prev_sign * res, 0
    return res + sign * num

public static int Calculate(string s)
{
    int res = 0, num = 0, sign = 1;
    var stack = new Stack<(int Res, int Sign)>();
    foreach (char ch in s)
    {
        if (char.IsDigit(ch)) num = num * 10 + (ch - '0');
        else if (ch == '+' || ch == '-')
        {
            res += sign * num;
            num = 0;
            sign = ch == '+' ? 1 : -1;
        }
        else if (ch == '(')
        {
            stack.Push((res, sign));
            res = 0;
            sign = 1;
        }
        else if (ch == ')')
        {
            res += sign * num;
            var (prevRes, prevSign) = stack.Pop();
            res = prevRes + prevSign * res;
            num = 0;
        }
    }
    return res + sign * num;
}

7. Basic Calculator III Hard

Now + - * / and parentheses (non-negative integers, division truncates toward zero): 2*(5+5*2)/3+(6/2+8) = 21. Insight: combine the two previous ideas. Inside one level of parentheses, run Calculator II: a list of terms and a pending op. On (, push the current level's (terms, op) and start a fresh level. On ), flush the last number, collapse the inner level to one number (sum(terms)), restore the outer level, and carry on as if that number had just been read. The pending outer op then applies to it, so 2*( … ) multiplies correctly.

Solution: O(n) time, O(n) space 
def calculate_iii(s: str) -> int:
    frames = []                                # saved (terms, op) of the outer levels
    terms, num, op = [], 0, '+'
    for ch in s + '+':
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch == '(':
            frames.append((terms, op))
            terms, op = [], '+'
        elif ch in '+-*/)':
            if op == '+': terms.append(num)
            elif op == '-': terms.append(-num)
            elif op == '*': terms.append(terms.pop() * num)
            else: terms.append(int(terms.pop() / num))
            if ch == ')':
                num = sum(terms)               # the whole group acts as one number
                terms, op = frames.pop()
            else:
                op, num = ch, 0
    return sum(terms)

public static int CalculateIII(string s)
{
    var frames = new Stack<(List<int> Terms, char Op)>();
    var terms = new List<int>();
    int num = 0;
    char op = '+';
    foreach (char ch in s + "+")
    {
        if (char.IsDigit(ch)) num = num * 10 + (ch - '0');
        else if (ch == '(')
        {
            frames.Push((terms, op));
            terms = new List<int>();
            op = '+';
        }
        else if (ch is '+' or '-' or '*' or '/' or ')')
        {
            if (op == '+') terms.Add(num);
            else if (op == '-') terms.Add(-num);
            else if (op == '*') terms[^1] *= num;
            else terms[^1] /= num;
            if (ch == ')')
            {
                num = terms.Sum();
                (terms, op) = frames.Pop();
            }
            else
            {
                op = ch;
                num = 0;
            }
        }
    }
    return terms.Sum();
}

The recursive version is the same algorithm. Write evaluate(i) that runs Calculator II from index i, calls itself on (, and returns (value, index after the ')') on ). The call stack then holds the (terms, op) frames for you. It is shorter to write, but it is limited by recursion depth; the explicit stack is not.

Self-check

A string has only ( and ). Why is a counter enough, and why does ([)] need a real stack?

With one kind of bracket every closer can pair with any unmatched opener, so all you need is how many are unmatched: the stack's height. The string is valid when the counter never goes below 0 and ends at 0. With several kinds, a closer must match the type of the most recent unmatched opener. In ([)] the counter goes 1, 2, 1, 0 and would say "valid", but at ) the top is [, so the pairs would cross. Only the stack remembers which kind is on top.

Evaluating RPN 8 2 -: what goes wrong if you pop a first and then b?

The stack is [8, 2] with 2 on top. The top is the right operand. Popping into a first gives a = 2, b = 8 and computes 2 − 8 = −6 instead of 8 − 2 = 6. + and * hide the bug; - and / expose it. Always pop b (right) first.

In shunting-yard, why do - and ^ behave differently on equal precedence?

- is left-associative: 8 - 3 - 2 = (8 - 3) - 2, so the earlier - must be applied first. It is popped to the output before the new - is pushed. ^ is right-associative: 2 ^ 3 ^ 2 = 2 ^ (3 ^ 2) = 512, so the earlier ^ must wait for the later one. It stays on the stack, and the new ^ goes on top of it.

Queue from two stacks: one pop can move n elements. Why is it still called O(1)?

Amortized cost counts the total work over a whole sequence. Each element is pushed onto in once, moved to out at most once (a refill only happens when out is empty, and nothing ever goes back) and popped once: at most 4 stack operations per element in its life. So m operations do at most about 4m units of work, O(1) per operation on average, even though an individual call can be O(n).

Asteroid Collision has a while inside a for. Why is it O(n) and not O(n²)?

Every iteration of the inner while either pops an asteroid or ends the loop. An asteroid is pushed at most once and so can be popped at most once, so all while loops together pop at most n times. Total work: n pushes + n pops + n loop exits = O(n).

In BFS, what goes wrong if you mark a cell as visited when you pop it instead of when you push it?

A cell can be discovered from several neighbours before it is popped. With late marking each of them enqueues it again, so the queue holds duplicates (up to 4 copies of a cell in a grid, far more in dense graphs). The distances stay correct because the first copy popped is still the shortest, but the time and memory blow up. Mark on enqueue, and every cell enters the queue exactly once.

Your C# solution builds the answer with string.Join("/", stack) where stack is a Stack<string>, and the path comes out backwards. Why?

Enumerating a Stack<T> yields items from the top down, i.e. in reverse push order. string.Join enumerates it, so /a/b/c becomes /c/b/a. Either call .Reverse() first, or use a List<T> as the stack (Add / RemoveAt(Count - 1) / [^1]), which enumerates bottom to top.
