BITS & MATH

Bit Manipulation

Bits drawn as switches: masks, XOR tricks, counting bits, subset enumeration and Gray codes.

Beginner → Advanced~45 min studyUpdated 2026-11-03

Where this page fits

This page has no prerequisites. It is still one of the most reused pages on the site, because bit manipulation shows up in two disguises:

  1. A number is a row of switches. A 32-bit int is 32 independent on/off cells. The operators &, |, ^, ~, << and >> act on all of them at once, in one CPU instruction. Tricks like x & (x − 1) look like magic until you watch what they do to each column.
  2. A number is a set. Bit i on means "item i is in". Then a subset of up to 64 items is a single integer: you can store it, hash it, compare it, and loop over all subsets with for mask in range(1 << n). That is the whole foundation of Bitmask & Digit DP.

Other pages lean on this one: the Fenwick tree in Segment Trees, Fenwick Trees & Sparse Tables walks with i & −i; the binary trie in Tries answers maximum-XOR queries; Nim in Advanced DP is decided by an XOR; and rolling hashes in Hashing live in fixed-width arithmetic.

&, |, ^ and ~ work on every column independently, so reason about one column at a time. Only shifts and arithmetic (+, −) move information between columns. The carry (or borrow) of +1 / −1 is the one cross-column effect, and it powers almost every famous trick: x & (x − 1), x & −x, Gosper's hack and adding without +.

Bits are switches

Write a number in base 2 and each digit is a switch with a place value: bit i is worth 2i. Bit 0 (the rightmost) is the least significant bit; the leftmost bit of a fixed width is the most significant bit. Every value has exactly one pattern, because each place value is larger than all smaller ones together: 2i > 2i−1 + … + 2 + 1 = 2i − 1. That one inequality is also why greedy "decide the top bit first" algorithms work (see Maximum XOR below).

Three readings of the same switches will come up again and again:

  • As a number: 0b00101101 is 45.
  • As a set: bits {0, 2, 3, 5} are on, so with items a b c d e f (item i ↔ bit i), it is the set {a, c, d, f}.
  • As a row of flags: "is position i used / visited / odd?" for up to 64 positions, in one word.

Negative numbers: two's complement

With a fixed width w, there are 2w patterns. Unsigned types read them as 0 … 2w − 1. Signed types use two's complement: the top bit is worth −2w−1 instead of +2w−1. Nothing else changes. So 11111111 as a signed byte is −128 + 127 = −1, and 10000000 is −128.

The picture to keep in mind is a wheel. Adding 1 moves one step clockwise, and the hardware never "notices" the sign: signed and unsigned addition are the same circuit. Only the reading of the bits differs.

Two identities fall straight out of the wheel, and you will use them constantly:

  • ~x = −x − 1. Flipping every bit of x gives the pattern that adds to x to make all ones, and all ones is −1. So x + ~x = −1.
  • −x = ~x + 1. Rearrange the first one. This is how CPUs negate, and it is why x & −x isolates the lowest set bit (shown below).

There is one more asymmetry: the signed range is −2w−1 … 2w−1 − 1, so the most negative value has no positive partner. −(−128) as a byte is −128 again. In 32 bits, −int.MinValue == int.MinValue.

The consequence for Python: ~5 is −6 (correct), but bin(−6) prints '-0b110', not a bit pattern. To simulate a 32-bit machine, mask with 0xFFFFFFFF and convert back to signed at the end.

MASK32 = 0xFFFFFFFF

def to_signed32(u):
    """Read the low 32 bits of u as a C# int."""
    u &= MASK32
    return u - (1 << 32) if u >> 31 else u

Five bugs that only exist in fixed width.

  1. 1 << 31 in C# is int.MinValue (negative), and 1 << 32 is 1, not 0, because the count is taken mod 32. Use 1L << k or 1UL << k when k can reach 31 or more.
  2. x >> 1 is not x / 2 for negative x in C#: −5 >> 1 = −3 but −5 / 2 = −2.
  3. Math.Abs(int.MinValue) throws OverflowException, and −int.MinValue silently stays negative. Widen to long first.
  4. a * b of two ints overflows before you store it in a long. Write (long)a * b.
  5. In Python, loops that shift a negative number right until it reaches 0 never stop. Mask with & 0xFFFFFFFF first, or loop over a fixed number of bits.

The six operators, column by column

&, |, ^ and ~ are column-wise: bit i of the result depends only on bit i of the inputs. Shifts slide the whole row. Learn each operator by the one sentence in the right-hand column; every trick on this page is a combination of these sentences.

Single-bit operations and the lowest set bit

Four one-liners read or change a single bit i. Each one builds a mask with a 1 only at position i (1 << i) or a 0 only there (~(1 << i)), then uses the operator sentence from the table above:

  • test: (x >> i) & 1. Slide bit i to position 0 and keep only it.
  • set: x | (1 << i). OR with 1 turns on; OR with 0 keeps.
  • clear: x & ~(1 << i). AND with 0 turns off; AND with 1 keeps.
  • toggle: x ^ (1 << i). XOR with 1 flips; XOR with 0 keeps.

The more surprising tricks use the carry. Subtracting 1 borrows from the lowest 1 bit: that bit becomes 0 and every 0 below it becomes 1. Negating is ~x + 1: the flip inverts everything, and the +1 carries back up through the flipped trailing zeros (now 1s) until it reaches the lowest 1 of x. Either way, only the bits at or below the lowest 1 change. So:

  • x & (x − 1) drops the lowest 1 (the bits above it survive the AND, the bits at or below it do not).
  • x & −x keeps only the lowest 1 (above it, x and −x are complements, so the AND is 0; at it, both have a 1).
  • x | (x + 1) sets the lowest 0 (the carry of +1 stops at the lowest 0).

Step through each trick and watch the borrow or carry ripple. Set x to a power of two with x & (x − 1) selected: the result is 0, which is the power-of-two test.

i & −i is the Fenwick tree. The value of the lowest set bit of i is exactly the length of the range that Fenwick node i covers. Adding it (i += i & −i) climbs to the next node that covers i; subtracting it (i −= i & −i) jumps to the previous disjoint range. See Segment Trees, Fenwick Trees & Sparse Tables.

Template: the single-bit toolbox

def test(x, i):       return (x >> i) & 1
def set_bit(x, i):    return x | (1 << i)
def clear_bit(x, i):  return x & ~(1 << i)
def toggle(x, i):     return x ^ (1 << i)
def low_bit(x):       return x & -x               # value of the lowest 1, e.g. 44 -> 4
def drop_low(x):      return x & (x - 1)          # 44 -> 40
def low_index(x):     return (x & -x).bit_length() - 1   # 44 -> 2 (x > 0)
def high_index(x):    return x.bit_length() - 1   # floor(log2 x), 44 -> 5 (x > 0)
def low_mask(k):      return (1 << k) - 1         # k ones: 3 -> 0b111
def is_subset(b, a):  return a & b == b           # every bit of b is in a

print(low_bit(44), drop_low(44), low_index(44), high_index(44))   # 4 40 2 5

All of these are O(1). In C#, keep i ≤ 30 for int masks (1 << 31 is negative and 1 << 32 is 1); switch to 1L << i for 64-bit masks.

Counting bits

Popcount with Kernighan's loop

The population count (popcount, Hamming weight) is the number of 1 bits. Checking all 32 positions works, but Kernighan's loop is better and teaches the key trick: x &= x − 1 deletes one 1 bit per iteration, so the loop runs once per 1 bit, not once per bit. On sparse numbers that is a big difference.

def popcount(x):
    """Number of 1 bits of a non-negative x (mask negatives first)."""
    count = 0
    while x:
        x &= x - 1        # drop the lowest 1
        count += 1
    return count

def popcount_swar(x):
    """The same for 32-bit x, with no loop: add neighbouring fields in parallel."""
    x &= 0xFFFFFFFF
    x = x - ((x >> 1) & 0x55555555)                    # 16 two-bit counts
    x = (x & 0x33333333) + ((x >> 2) & 0x33333333)     # 8 four-bit counts
    x = (x + (x >> 4)) & 0x0F0F0F0F                    # 4 byte counts
    return ((x * 0x01010101) & 0xFFFFFFFF) >> 24       # sum of the 4 bytes

print(popcount(0b1011000010100000), (-1 & 0xFFFFFFFF).bit_count(), popcount_swar(-1))   # 5 32 32

public static int Popcount(uint x)
{
    int count = 0;
    while (x != 0)
    {
        x &= x - 1;       // drop the lowest 1
        count++;
    }
    return count;
}

public static int PopcountSwar(uint x)
{
    x -= (x >> 1) & 0x55555555;                       // 16 two-bit counts
    x = (x & 0x33333333) + ((x >> 2) & 0x33333333);   // 8 four-bit counts
    x = (x + (x >> 4)) & 0x0F0F0F0F;                  // 4 byte counts
    return (int)((x * 0x01010101) >> 24);             // uint multiply wraps: sum of bytes
}

Kernighan's loop is O(number of 1s). The SWAR version ("SIMD within a register") is O(log w) with no branches, and it is the same divide-and-conquer as reversing bits below: combine neighbouring 1-bit fields into 2-bit counts, then 4-bit, then 8-bit. In real code, call the built-in; it compiles to the single POPCNT instruction.

Python's bit_count() ignores the sign. (−5).bit_count() is 2, the popcount of 5, not the 31 ones of the 32-bit pattern of −5. For C#-style answers on negative inputs, mask first: (x & 0xFFFFFFFF).bit_count(). Kernighan's loop on a negative Python int never ends, for the same reason.

Counting bits for every number from 0 to n

Counting Bits asks for the popcount of every i in 0 … n in O(n). Calling popcount n times is O(n log n). The DP view: every i is a smaller number plus one bit, and that smaller number's answer is already in the table. There are three natural ways to split i, and all three give a correct O(n) DP:

  • dp[i >> 1] + (i & 1): i is i >> 1 with one more bit appended at the bottom.
  • dp[i & (i − 1)] + 1: i is i without its lowest 1, plus that 1.
  • dp[i − msb] + 1: i is i without its top bit, plus that bit. Each power of two starts a new "block" that copies the previous block plus one.
def count_bits(n):
    dp = [0] * (n + 1)
    for i in range(1, n + 1):
        dp[i] = dp[i >> 1] + (i & 1)     # or dp[i & (i - 1)] + 1
    return dp

print(count_bits(5))   # [0, 1, 1, 2, 1, 2]

public static int[] CountBits(int n)
{
    var dp = new int[n + 1];
    for (int i = 1; i <= n; i++)
        dp[i] = dp[i >> 1] + (i & 1);    // or dp[i & (i - 1)] + 1
    return dp;
}

O(n) time and space. The same "a smaller number is already solved" idea drives subset DP: dp[mask] built from dp[mask & (mask − 1)] (see Bitmask & Digit DP).

Powers of two and four

A power of two has exactly one 1 bit. So x & (x − 1) (drop the lowest 1) must leave 0, and x > 0 rules out zero and, in C#, int.MinValue (a single 1 bit, but negative).

A power of four is a power of two whose single 1 sits at an even position (1, 4, 16, 64 … are bits 0, 2, 4, 6). The mask 0x55555555 is 0101…0101, a 1 at every even position, so AND with it keeps the bit only if it is in the right place. An algebraic alternative: 4ᵏ = (3 + 1)ᵏ leaves remainder 1 when divided by 3, while 2 · 4ᵏ leaves 2.

def is_power_of_two(x):
    return x > 0 and x & (x - 1) == 0

def is_power_of_four(x):
    return is_power_of_two(x) and x & 0x55555555 != 0    # the 1 is at an even position

def is_power_of_three(x):
    return x > 0 and 1162261467 % x == 0    # 3^19, the largest power of 3 in an int

print([v for v in range(70) if is_power_of_four(v)])   # [1, 4, 16, 64]

public static bool IsPowerOfTwo(int x) => x > 0 && (x & (x - 1)) == 0;

public static bool IsPowerOfFour(int x) => IsPowerOfTwo(x) && (x & 0x55555555) != 0;

public static bool IsPowerOfThree(int x) => x > 0 && 1162261467 % x == 0;   // 3^19

The power-of-three check is not a bit trick (3 is not a power of 2), but it uses the same idea: the largest power of three that fits divides exactly the powers of three, because 3 is prime.

XOR: the operator that cancels

XOR is "add each column mod 2, with no carry". Every useful XOR trick comes from five facts:

  1. a ^ a = 0 and a ^ 0 = a. A value XORed with itself vanishes.
  2. Order does not matter (commutative and associative). So the XOR of a list depends only on which values appear an odd number of times: pairs cancel no matter where they sit.
  3. XOR is its own inverse. If a ^ b = c then a = b ^ c and b = a ^ c. You can "subtract" with XOR, which is why prefix XORs work like prefix sums: xor(nums[l..r]) = P[r + 1] ^ P[l].
  4. a ^ b marks the bits where a and b differ. So a ^ b == 0 means a == b, and popcount(a ^ b) is the Hamming distance.
  5. a + b = (a ^ b) + 2 · (a & b). XOR is the sum without carries, AND marks where the carries are. This is the adder below.

A handy consequence of fact 2: the XOR of 0, 1, …, n has a period-4 pattern, because every aligned block of four numbers 4k, 4k+1, 4k+2, 4k+3 XORs to 0 (the low two bits cover 00, 01, 10, 11 once each, and the high bits appear four times).

n mod 4 0 ^ 1 ^ … ^ n Example
0 n n = 8 → 8
1 1 n = 9 → 1
2 n + 1 n = 10 → 11
3 0 n = 11 → 0

Single Number I, II, III

The classic trio: every value appears twice (or three times) except one or two, and you must find the odd ones out in O(n) time and O(1) extra space. Step through all three. In II, watch each column count its 1s mod 3: three copies of a value add 3 to each of its columns, which is 0 mod 3, so only the single value's bits survive.

  • I (pairs): XOR everything. Pairs cancel (fact 2), the single value remains.
  • II (triples): XOR cannot cancel triples (a ^ a ^ a = a). Count the 1s in each of the 32 columns and keep the columns whose count is not a multiple of 3.
  • III (two singles, a and b): XOR everything to get x = a ^ b ≠ 0. Any 1 bit of x is a column where a and b differ; take the lowest, d = x & −x. Splitting all numbers by that bit puts a and b in different groups, and every pair in the same group. Now each group is a Single Number I.

The column counter of II can be done for all 32 columns at once with two words, ones and twos, that hold each column's count mod 3 in binary. Each column is a tiny 3-state machine:

def single_number(nums):              # I: every other value twice
    acc = 0
    for x in nums:
        acc ^= x
    return acc

def single_number_ii(nums):           # II: every other value three times
    ones = twos = 0
    for x in nums:
        ones = (ones ^ x) & ~twos     # count 0 -> 1, and 2 -> 0 (twos was set)
        twos = (twos ^ x) & ~ones     # count 1 -> 2, and 2 -> 0
    return ones                       # works for negatives too: Python ints are two's complement

def single_number_iii(nums):          # III: two singles, every other value twice
    x = 0
    for v in nums:
        x ^= v                        # x = a ^ b, non-zero
    d = x & -x                        # a column where a and b differ
    a = 0
    for v in nums:
        if v & d:
            a ^= v                    # the group with that bit holds exactly one single
    return sorted([a, x ^ a])         # the other single is x ^ a

print(single_number([4, 1, 2, 1, 2]), single_number_ii([0, 1, 0, 1, 0, 1, -99]), single_number_iii([1, 2, 1, 3, 2, 5]))   # 4 -99 [3, 5]

public static int SingleNumber(int[] nums)
{
    int acc = 0;
    foreach (int x in nums) acc ^= x;
    return acc;
}

public static int SingleNumberII(int[] nums)
{
    int ones = 0, twos = 0;
    foreach (int x in nums)
    {
        ones = (ones ^ x) & ~twos;    // count 0 -> 1, and 2 -> 0
        twos = (twos ^ x) & ~ones;    // count 1 -> 2, and 2 -> 0
    }
    return ones;
}

public static int[] SingleNumberIII(int[] nums)
{
    int x = 0;
    foreach (int v in nums) x ^= v;   // x = a ^ b
    int d = x & -x;                   // lowest differing column (fine even for int.MinValue)
    int a = 0;
    foreach (int v in nums)
        if ((v & d) != 0) a ^= v;
    int b = x ^ a;
    return a < b ? new[] { a, b } : new[] { b, a };
}

All three are O(n) time and O(1) space. The ones/twos update order matters: ones is computed first and then used to compute twos. Trace one column through 1, 1, 1 to convince yourself: (0,0) → (0,1) → (1,0) → (0,0).

Missing number and the XOR swap

Missing Number: nums holds n distinct values from 0 … n, one is missing. XOR all indices 0 … n with all values: every present value meets its index and cancels, and the missing one is left. It is a sum-based solution in disguise, but XOR cannot overflow.

def missing_number(nums):
    acc = len(nums)                   # index n has no slot in the loop
    for i, v in enumerate(nums):
        acc ^= i ^ v
    return acc

print(missing_number([3, 0, 1]), missing_number([9, 6, 4, 2, 3, 5, 7, 0, 1]))   # 2 8

public static int MissingNumber(int[] nums)
{
    int acc = nums.Length;
    for (int i = 0; i < nums.Length; i++) acc ^= i ^ nums[i];
    return acc;
}

The XOR swap a ^= b; b ^= a; a ^= b exchanges two variables without a temporary (after line 1, a holds a ^ b; line 2 gives b ^ (a ^ b) = a; line 3 gives (a ^ b) ^ a = b). It is a nice proof of fact 3 and a bad idea in real code: it is slower than a tuple swap on modern CPUs, and if both names refer to the same location (swap(arr[i], arr[j]) with i == j) the first line zeroes it. Use a, b = b, a or (a, b) = (b, a).

Reversing bits

Reverse Bits mirrors a 32-bit word: bit 0 goes to bit 31, bit 1 to bit 30, and so on. The direct loop pops bits off the bottom of n and pushes them onto the bottom of res, like reversing a stack: w steps.

The divide-and-conquer version needs only log₂ w steps: swap the two halves, then swap neighbouring quarters inside each half, then eighths, down to single bits. Each step is two masks, two shifts and an OR, and it moves all blocks at once. Each bit is moved by every step, and the moves add up to exactly its mirror position. (The order of the steps does not matter.)

def reverse_bits(n):                  # loop: 32 steps
    res = 0
    for _ in range(32):
        res = (res << 1) | (n & 1)
        n >>= 1
    return res

def reverse_bits_dc(n):               # divide and conquer: 5 steps
    M = 0xFFFFFFFF
    n = ((n >> 1) & 0x55555555) | ((n & 0x55555555) << 1)      # swap single bits
    n = ((n >> 2) & 0x33333333) | ((n & 0x33333333) << 2)      # swap pairs
    n = ((n >> 4) & 0x0F0F0F0F) | ((n & 0x0F0F0F0F) << 4)      # swap nibbles
    n = ((n >> 8) & 0x00FF00FF) | ((n & 0x00FF00FF) << 8)      # swap bytes
    return ((n >> 16) | (n << 16)) & M                         # swap halves

print(reverse_bits(43261596), reverse_bits_dc(43261596))   # 964176192 964176192

public static uint ReverseBits(uint n)
{
    uint res = 0;
    for (int i = 0; i < 32; i++)
    {
        res = (res << 1) | (n & 1);
        n >>= 1;
    }
    return res;
}

public static uint ReverseBitsDc(uint n)
{
    n = ((n >> 1) & 0x55555555) | ((n & 0x55555555) << 1);
    n = ((n >> 2) & 0x33333333) | ((n & 0x33333333) << 2);
    n = ((n >> 4) & 0x0F0F0F0F) | ((n & 0x0F0F0F0F) << 4);
    n = ((n >> 8) & 0x00FF00FF) | ((n & 0x00FF00FF) << 8);
    return (n >> 16) | (n << 16);     // uint shifts drop the overflow for us
}

The same masks (0x55…, 0x33…, 0x0F…) appear in the SWAR popcount: "work on neighbouring fields of size 1, 2, 4, 8, 16" is a general pattern. If the function is called many times, a 256-entry table of reversed bytes is faster still: reverse each byte by lookup and reverse the byte order.

Adding without +

Sum of Two Integers forbids + and −. Fact 5 says a + b = (a ^ b) + ((a & b) << 1): XOR adds every column and ignores carries, and a & b marks the columns that produce a carry into the next column. That is a new addition problem, so repeat until there are no carries. Each round, the lowest carry moves at least one column left, so a w-bit addition ends within w rounds. In fixed width, the carry out of the top bit falls off, which is exactly two's complement wrap-around, so negative numbers work for free.

def get_sum(a, b):
    M = 0xFFFFFFFF                    # simulate 32-bit registers
    a, b = a & M, b & M
    while b:
        a, b = (a ^ b) & M, ((a & b) << 1) & M
    return a - (1 << 32) if a >> 31 else a   # back to a signed value

print(get_sum(23, -9), get_sum(-2, -3), get_sum(2147483647, 1))   # 14 -5 -2147483648

public static int GetSum(int a, int b)
{
    while (b != 0)
    {
        int carry = (a & b) << 1;     // the top carry falls off: two's complement wrap
        a ^= b;                       // add every column, ignoring carries
        b = carry;
    }
    return a;
}

The Python version needs the mask: with unbounded ints, adding a negative number would push the carry left forever (a negative number has infinitely many 1s on the left). Subtraction is a + (~b + 1), using −b = ~b + 1.

Gray code

A Gray code lists all 2ⁿ patterns of n bits so that neighbours differ in exactly one bit. Mechanical encoders use it so that a sensor between two positions can only be off by one step, and puzzles use it to visit every state with single moves (Towers of Hanoi and the Chinese rings puzzle are Gray codes in disguise).

Two constructions give the same list (Gray Code):

  • Reflect and prefix. Take the list for n − 1 bits, then append it in reverse with the new top bit set. Inside each half, neighbours already differ in one bit. At the seam the two codes are equal except for the new bit, because the reversed copy starts with the same code the first copy ended with.
  • g = i ^ (i >> 1). Bit j of g says "bits j and j + 1 of i differ". Counting from i to i + 1 flips a block of trailing bits, but only one neighbouring pair changes whether it differs, so exactly one bit of g flips.

Geometrically, the n-bit patterns are the corners of an n-dimensional cube, and flipping one bit walks along one edge. A Gray code is a path that visits every corner once (a Hamiltonian path). Step through it and watch the walk:

def gray_code(n):
    return [i ^ (i >> 1) for i in range(1 << n)]

def gray_code_reflect(n):
    codes = [0]
    for k in range(n):
        codes += [c | (1 << k) for c in reversed(codes)]
    return codes

def gray_to_index(g):                 # inverse: i = g ^ (g >> 1) ^ (g >> 2) ^ ...
    i = 0
    while g:
        i ^= g
        g >>= 1
    return i

print(gray_code(3), gray_code_reflect(3) == gray_code(3), gray_to_index(0b110))   # [0, 1, 3, 2, 6, 7, 5, 4] True 4

public static List<int> GrayCode(int n)
{
    var codes = new List<int>(1 << n);
    for (int i = 0; i < 1 << n; i++) codes.Add(i ^ (i >> 1));
    return codes;
}

public static int GrayToIndex(int g)
{
    int i = 0;
    for (; g != 0; g >>= 1) i ^= g;
    return i;
}

O(2ⁿ) to list them, O(1) per code. Because the list is also cyclic (the last code differs from the first in the top bit only), XORing every code with a fixed start gives a Gray cycle that begins at start: that is all of Circular Permutation in Binary Representation.

Subsets as integers

With n ≤ ~20 items, a subset is an n-bit mask, and "loop over all subsets" is just "count from 0 to 2ⁿ − 1". Three loops cover almost every use:

  1. All subsets: for mask in range(1 << n). In this order, every proper subset of a mask is a smaller number, so a DP over masks can be filled left to right.
  2. All submasks of a given mask: sub = (sub − 1) & mask. Subtracting 1 is counting down, and & mask throws away the positions outside the mask, so you count down inside the mask. It visits 2popcount(mask) values. Over all masks the total is 3ⁿ, because each item is either outside the mask, in the mask but not the submask, or in both.
  3. All subsets of size exactly k: Gosper's hack jumps straight to the next larger mask with the same popcount, without visiting the others.

How Gosper's hack works, on x = 0b0110 (n = 4, k = 2): c = x & −x = 0b0010 is the lowest 1. r = x + c = 0b1000: the carry ripples through the lowest block of 1s and moves one bit up past it (the "next larger" step). r ^ x = 0b1110 marks every changed bit, which is the old block plus the new bit. Shifting right by 2 and dividing by c (both remove positions) leaves exactly the 1s that must be refilled at the bottom, as few and as low as possible: 0b0001. The OR gives 0b1001, the next 2-subset after 0b0110 in increasing order.

def subsets(items):                   # all 2^n subsets
    n = len(items)
    return [[items[i] for i in range(n) if mask >> i & 1] for mask in range(1 << n)]

def submasks(mask):                   # all submasks, from mask down to 0
    out, sub = [], mask
    while True:
        out.append(sub)
        if sub == 0:
            break
        sub = (sub - 1) & mask
    return out

def k_subsets(n, k):                  # Gosper's hack: n-bit masks with exactly k ones, ascending
    if k == 0:
        return [0]
    out, x = [], (1 << k) - 1
    while x < 1 << n:
        out.append(x)
        c = x & -x
        r = x + c
        x = (((r ^ x) >> 2) // c) | r
    return out

def bits_of(mask):                    # positions of the 1 bits, lowest first
    while mask:
        low = mask & -mask
        yield low.bit_length() - 1
        mask ^= low

print(submasks(0b1101), k_subsets(4, 2), list(bits_of(0b101100)))   # [13, 12, 9, 8, 5, 4, 1, 0] [3, 5, 6, 9, 10, 12] [2, 3, 5]

public static List<IList<int>> Subsets(int[] items)
{
    int n = items.Length;
    var all = new List<IList<int>>();
    for (int mask = 0; mask < 1 << n; mask++)
    {
        var s = new List<int>();
        for (int i = 0; i < n; i++)

        all.Add(s);
    }

}

public static List<int> Submasks(int mask)
{
    var outList = new List<int>();
    for (int sub = mask; ; sub = (sub - 1) & mask)
    {
        outList.Add(sub);
        if (sub == 0) break;
    }
    return outList;
}

public static List<int> KSubsets(int n, int k)
{
    if (k == 0) return new List<int> { 0 };
    var outList = new List<int>();
    for (int x = (1 << k) - 1; x < 1 << n; )
    {
        outList.Add(x);
        int c = x & -x, r = x + c;
        x = (((r ^ x) >> 2) / c) | r;
    }
    return outList;
}

All subsets cost O(2ⁿ · n) to materialise; submask loops cost O(3ⁿ) in total over all masks; Gosper is O(1) per subset. The while sub form of the submask loop skips the empty set, so use the if sub == 0: break form when 0 matters. For DP over these masks (TSP, assignment, SOS / "sum over subsets"), continue in Bitmask & Digit DP.

Maximum XOR of two numbers

Maximum XOR of Two Numbers in an Array: pick two numbers whose XOR is as large as possible, in O(n · W) instead of O(n²).

The greedy idea comes from the place-value fact: bit b is worth more than all lower bits together, so the answer should win the highest bit it can, and only then worry about lower bits. Build the answer from the top. Before deciding bit b, you know the higher bits ans. Ask: is there a pair whose top bits XOR to ans with a 1 appended (cand)? Keep only each number's top bits (x & mask) in a set. Two prefixes p and q XOR to cand exactly when q = p ^ cand (XOR is its own inverse), so one set lookup per prefix answers the question.

def find_maximum_xor(nums):
    ans = mask = 0
    for b in range(max(nums).bit_length() - 1, -1, -1):
        mask |= 1 << b
        prefixes = {x & mask for x in nums}
        cand = ans | (1 << b)
        if any(p ^ cand in prefixes for p in prefixes):
            ans = cand
    return ans

print(find_maximum_xor([3, 10, 5, 25, 2, 8]))   # 28 (5 ^ 25)

public static int FindMaximumXOR(int[] nums)
{
    int ans = 0, mask = 0;
    for (int b = 30; b >= 0; b--)
    {
        mask |= 1 << b;
        var prefixes = new HashSet<int>();
        foreach (int x in nums) prefixes.Add(x & mask);
        int cand = ans | (1 << b);
        foreach (int p in prefixes)
            if (prefixes.Contains(p ^ cand)) { ans = cand; break; }
    }
    return ans;
}

O(n · W) time with W = 31 bits, O(n) space. The binary trie is the same greedy, stored differently: insert every number bit by bit, then for each number walk down choosing the opposite bit whenever that child exists. The trie wins when numbers arrive online, or when queries come with limits (Maximum XOR With an Element From Array sorts queries offline and inserts numbers as the limit grows).

Bitsets as a speed-up

A bitset is a long row of bits packed into 64-bit words. One |, & or shift on a word updates 64 cells at once, so a DP whose rows are booleans can run 64 times faster without changing the algorithm.

Subset sum is the standard example. The boolean DP says "sum s is reachable after item x if it was reachable before, or s − x was". With a bitset reach (bit s = "s is reachable"), "s − x was reachable" for every s at once is reach << x. So one item is one shift and one OR:

def can_partition(nums):              # Partition Equal Subset Sum
    total = sum(nums)
    if total % 2:
        return False
    reach = 1                         # Python ints are bitsets of any length
    for x in nums:
        reach |= reach << x
    return reach >> (total // 2) & 1 == 1

print(can_partition([1, 5, 11, 5]), can_partition([1, 2, 3, 5]))   # True False

using System.Collections;

public static bool CanPartition(int[] nums)
{
    int total = nums.Sum();
    if (total % 2 == 1) return false;
    int target = total / 2;
    var reach = new BitArray(target + 1);       // bits past target are never needed
    reach[0] = true;
    foreach (int x in nums)
    {
        var shifted = new BitArray(reach).LeftShift(x);   // bit s moves to s + x; overflow drops off
        reach.Or(shifted);
    }
    return reach[target];
}

O(n · S / 64) word operations for n items and total S, against O(n · S) for the plain DP. The same trick speeds up other boolean DPs and closures:

  • Reachability in a dense graph: row i of the transitive closure is a bitset; if reach[i] >> k & 1: reach[i] |= reach[k] gives Floyd–Warshall closure in O(n³ / 64).
  • Counting triangles or common neighbours: popcount(adj[u] & adj[v]).
  • Many small sets: an int or long as a set of up to 64 flags (visited cells in a word search, used letters in Maximum Product of Word Lengths).

Recognize it

Reach for bits when you see:

  • "every element appears twice (or k times) except …", with O(1) extra space → XOR, or count each bit column mod k.
  • n ≤ 20 (or ≤ 15 with an extra factor) and "choose a subset / visit all" → the state is a mask: Bitmask & Digit DP.
  • "XOR of a subarray" → prefix XOR, with P[r + 1] ^ P[l] exactly like prefix sums.
  • "maximum XOR of a pair / with a query" → decide the answer bit by bit from the top: prefix set or binary trie.
  • "AND / OR over all subarrays" → for each end, at most ~32 distinct values; or, for a range, the common prefix.
  • "sum over all pairs of some bitwise quantity" → each column is independent: count the ones in each column and combine counts.
  • "even number of each vowel / character", "all characters with even counts" → a parity mask of the counts, plus first occurrence per mask.
  • "without +, *, /" or "power of two / four" → carries and x & (x − 1).
  • a boolean DP row of size up to ~10⁵ … 10⁶ that is too slow → a bitset.

Pitfalls

Operator precedence differs between languages. In C#, == binds tighter than &, so x & 1 == 0 means x & (1 == 0) and does not compile (in C, C++ and Java the same mistake compiles and is wrong). Python puts & above ==, so the same text works there, which makes the bug easy to port. Shifts bind looser than + in both languages: 1 << n - 1 is 1 << (n − 1), and a + b >> 1 is (a + b) >> 1. Parenthesise every bit expression.

^ is XOR, not power. 2 ^ 10 is 8, not 1024. Use 2 ** 10 or 1 << 10 in Python and 1 << 10 or Math.Pow in C#.

Masks wider than the type. 1 << i with i ≥ 31 breaks in C# (int masks wrap and the shift count is taken mod 32). Use 1L << i, 1UL << i, or BigInteger. In Python, nothing breaks, but ~mask is negative, so x & ~mask is fine while ~mask printed or used as a count is not. Use full ^ mask with full = (1 << n) − 1 for "complement within n items".

Negative numbers in Python bit loops. while x: x >>= 1 never ends for negative x; bin(−5) is '-0b101'; (−5).bit_count() is 2. When a problem means "the 32-bit pattern", convert once with x & 0xFFFFFFFF and convert back at the end with x − (1 << 32) if x >> 31 else x. Column counting (Single Number II with a 32-bit loop) needs that final sign fix.

Worked problems

1. Bitwise AND of Numbers Range: keep the common prefix

LeetCode 201 Medium. Return the AND of every integer in [left, right], with right up to 2³¹ − 1 (so looping over the range is too slow).

Key insight. Look at the highest bit where left and right differ. In the range, that bit goes from 0 (in left) to 1 (in right), so somewhere it rolls over from …0111…1 to …1000…0: every bit at or below it is 0 in at least one number. The bits above it are the same in every number of the range. So the answer is the common binary prefix followed by zeros.

Solution: drop low bits of right until it is at most left, O(log right) 
def range_bitwise_and(left, right):
    while right > left:
        right &= right - 1      # drop right's lowest 1: it cannot be in the common prefix
    return right

print(range_bitwise_and(26, 30), range_bitwise_and(5, 7), range_bitwise_and(1, 2147483647))   # 24 4 0

public static int RangeBitwiseAnd(int left, int right)
{
    while (right > left)
        right &= right - 1;     // drop right's lowest 1
    return right;
}

Each step clears one 1 bit of right, and it stops as soon as right is no longer above left. At that point right is the common prefix with zeros below. At most 31 steps. Checked against a direct loop on random ranges.

2. Total Hamming Distance: count each column once

LeetCode 477 Medium. Sum the Hamming distance over all pairs of nums (n up to 10⁴, so the O(n²) pair loop is too slow).

Key insight. The Hamming distance is a sum over columns, and columns are independent. In one column with c ones and n − c zeros, a pair differs exactly when it takes one of each: c · (n − c) pairs. This "contribution per bit" technique works for any pairwise sum of XOR, AND or OR.

Solution: per-column counts, O(32 · n) 
def total_hamming_distance(nums):
    n, total = len(nums), 0
    for b in range(32):
        c = sum((x >> b) & 1 for x in nums)
        total += c * (n - c)
    return total

print(total_hamming_distance([4, 14, 2]), total_hamming_distance([4, 14, 4]))   # 6 4

public static int TotalHammingDistance(int[] nums)
{
    int n = nums.Length, total = 0;
    for (int b = 0; b < 32; b++)
    {
        int c = 0;
        foreach (int x in nums) c += (x >> b) & 1;
        total += c * (n - c);
    }
    return total;
}

O(32 · n) time, O(1) space. The same counting gives the sum of XOR over all pairs (Σ c · (n − c) · 2ᵇ), which is a common follow-up. Checked against the pair loop.

3. Longest Substring with Even Vowel Counts: a parity mask

LeetCode 1371 Medium. Return the length of the longest substring in which each of a, e, i, o, u appears an even number of times.

Key insight. Only the parity of each count matters, and five parities fit in a 5-bit mask: bit k flips each time vowel k appears. A substring s[l..r] has all-even counts exactly when the prefix masks before l and after r are equal (their XOR, the substring's parity, is 0). So for each mask, remember the first index where it appeared; the answer is the widest gap between two equal masks. It is "longest subarray with sum 0" from Hashing, with XOR in place of +.

Solution: prefix parity mask + first occurrence, O(n) 
def find_the_longest_substring(s):
    first = [-2] * 32           # first index where each mask appeared; -2 = never
    first[0] = -1               # the empty prefix
    mask = best = 0
    for i, ch in enumerate(s):
        k = "aeiou".find(ch)
        if k >= 0:
            mask ^= 1 << k
        if first[mask] == -2:
            first[mask] = i
        else:
            best = max(best, i - first[mask])
    return best

print(find_the_longest_substring("eleetminicoworoep"), find_the_longest_substring("bcbcbc"))   # 13 6

public static int FindTheLongestSubstring(string s)
{
    var first = new int[32];
    Array.Fill(first, -2);      // -2 = never seen
    first[0] = -1;              // the empty prefix
    int mask = 0, best = 0;
    for (int i = 0; i < s.Length; i++)
    {
        int k = "aeiou".IndexOf(s[i]);
        if (k >= 0) mask ^= 1 << k;
        if (first[mask] == -2) first[mask] = i;
        else best = Math.Max(best, i - first[mask]);
    }
    return best;
}

O(n) time and O(2⁵) space: an array of 32 slots replaces the hash map. The same trick solves "longest substring where every character appears an even number of times" with a 26-bit mask, and Number of Wonderful Substrings (at most one odd count: also look up the 10 masks one bit away). Checked against all O(n²) substrings.

4. Bitwise ORs of Subarrays: at most 32 values per end

LeetCode 898 Medium. Count the distinct values of OR(arr[l..r]) over all subarrays, with n up to 5 · 10⁴.

Key insight. Fix the right end r and grow the subarray to the left. OR can only turn bits on, so the values form a chain where each new distinct value has at least one more bit. With 30-bit numbers there are at most 31 distinct values per end. Keep the set cur of ORs of subarrays ending at r − 1; the ones ending at r are {v | arr[r] for v in cur} ∪ {arr[r]}.

Solution: roll the set of ORs ending here, O(n · 30) 
def subarray_bitwise_ors(arr):
    seen, cur = set(), set()
    for x in arr:
        cur = {v | x for v in cur} | {x}     # ORs of subarrays ending at x
        seen |= cur
    return len(seen)

print(subarray_bitwise_ors([1, 1, 2]), subarray_bitwise_ors([1, 2, 4]))   # 3 6

public static int SubarrayBitwiseORs(int[] arr)
{
    var seen = new HashSet<int>();
    var cur = new HashSet<int>();
    foreach (int x in arr)
    {
        var next = new HashSet<int> { x };
        foreach (int v in cur) next.Add(v | x);
        cur = next;
        seen.UnionWith(cur);
    }
    return seen.Count;
}

O(n · 30) set operations. The same "few distinct values per end" fact solves AND (bits only turn off) and GCD (each new value at least halves): Find a Value of a Mysterious Function Closest to Target and Smallest Subarrays With Maximum Bitwise OR. Checked against all O(n²) subarrays.

5. Decode XORed Permutation: XOR is its own inverse

LeetCode 1734 Medium. perm is a permutation of 1 … n with n odd. You get only encoded[i] = perm[i] ^ perm[i + 1]. Recover perm.

Key insight. If you knew perm[0], fact 3 would give the rest: perm[i + 1] = perm[i] ^ encoded[i]. To get perm[0], XOR two things you can compute. The XOR of the whole permutation is 1 ^ 2 ^ … ^ n. The encoded values at odd indices pair up perm[1] ^ perm[2], perm[3] ^ perm[4], …, which covers every element except perm[0] (this is why n must be odd). XOR the two, and everything but perm[0] cancels.

Solution: total XOR, odd-index XOR, then unroll, O(n) 
def decode(encoded):
    n = len(encoded) + 1
    total = 0
    for v in range(1, n + 1):
        total ^= v                       # p0 ^ p1 ^ ... ^ p(n-1)
    rest = 0
    for i in range(1, n - 1, 2):
        rest ^= encoded[i]               # p1 ^ p2 ^ ... ^ p(n-1)
    perm = [total ^ rest]
    for e in encoded:
        perm.append(perm[-1] ^ e)
    return perm

print(decode([6, 5, 4, 6]), decode([3, 1]))   # [2, 4, 1, 5, 3] [1, 2, 3]

public static int[] Decode(int[] encoded)
{
    int n = encoded.Length + 1, total = 0, rest = 0;
    for (int v = 1; v <= n; v++) total ^= v;
    for (int i = 1; i < n - 1; i += 2) rest ^= encoded[i];
    var perm = new int[n];
    perm[0] = total ^ rest;
    for (int i = 0; i < n - 1; i++) perm[i + 1] = perm[i] ^ encoded[i];
    return perm;
}

O(n) time. Checked against random odd-length permutations.

6. Find XOR Sum of All Pairs Bitwise AND: AND distributes over XOR

LeetCode 1835 Hard. Return the XOR of arr1[i] & arr2[j] over all pairs, with both arrays up to 10⁵ long (10¹⁰ pairs).

Key insight. Look at one column. With c₁ ones in that column of arr1 and c₂ in arr2, exactly c₁ · c₂ pairs have a 1 after the AND. XOR keeps the parity of that count, and c₁ · c₂ is odd exactly when both are odd. "Parity of the ones in a column of arr1" is that column of xor(arr1). So the answer is xor(arr1) & xor(arr2). In algebra: AND is multiplication and XOR is addition mod 2, so (a₁ ^ a₂) & b = (a₁ & b) ^ (a₂ & b), just like (a₁ + a₂) · b.

For example, arr1 = [1, 2, 3] and arr2 = [6, 5]: the six ANDs are 0, 1, 2, 0, 2, 1, which XOR to 0, and (1 ^ 2 ^ 3) & (6 ^ 5) = 0 & 3 = 0.

Solution: two XORs and one AND, O(n + m) 
from functools import reduce
from operator import xor

def get_xor_sum(arr1, arr2):
    return reduce(xor, arr1) & reduce(xor, arr2)

print(get_xor_sum([1, 2, 3], [6, 5]), get_xor_sum([12], [4]))   # 0 4

public static int GetXORSum(int[] arr1, int[] arr2)
{
    int x1 = 0, x2 = 0;
    foreach (int v in arr1) x1 ^= v;
    foreach (int v in arr2) x2 ^= v;
    return x1 & x2;
}

O(n + m) time, O(1) space. The column argument is the general tool: whenever an answer is "XOR / sum over pairs of a bitwise expression", reduce it to counts per column. Checked against the double loop.

7. Minimum One Bit Operations to Make Integers Zero: Gray code in disguise

LeetCode 1611 Expert. Turn n into 0. You may (1) flip bit 0, or (2) flip bit i if bit i − 1 is 1 and all bits below it are 0. Return the minimum number of operations.

Key insight. Operation 2 flips "the bit just left of the lowest 1". Those are exactly the two kinds of step in the reflected Gray code: from g(i) to g(i + 1), an even i flips bit 0, and an odd i flips the bit just left of the lowest 1. Every state has at most these two moves, one forward and one backward along the Gray sequence, so the state graph is a single path 0 = g(0), g(1), g(2), …. The minimum number of operations from n to 0 is the position of n in the Gray sequence: the inverse Gray code n ^ (n >> 1) ^ (n >> 2) ^ ….

Solution: inverse Gray code, O(log n) 
def minimum_one_bit_operations(n):
    ans = 0
    while n:
        ans ^= n               # ans = n ^ (n >> 1) ^ (n >> 2) ^ ...
        n >>= 1
    return ans

print(minimum_one_bit_operations(3), minimum_one_bit_operations(6), minimum_one_bit_operations(333))   # 2 4 393

public static int MinimumOneBitOperations(int n)
{
    int ans = 0;
    for (; n != 0; n >>= 1) ans ^= n;
    return ans;
}

O(log n). Without spotting the Gray code, you can still derive a recurrence: clearing the top bit k of a value that is exactly 2ᵏ takes 2ᵏ⁺¹ − 1 moves, so f(n) = (2ᵏ⁺¹ − 1) − f(n − 2ᵏ). It gives the same numbers. Checked against a BFS over all states up to 2¹².

Self-check

x & (x − 1) == 0 is the power-of-two test. Which inputs does it get wrong without the extra x > 0 check?

0, because 0 & −1 = 0, and in C# int.MinValue: its pattern 1000…0 has a single 1, so x & (x − 1) is 0, but the value is negative. Hence x > 0 && (x & (x − 1)) == 0.

In C#, what are 1 << 32, 1 << 31 and 1L << 32?

1 << 32 is 1: for int the shift count is taken mod 32, so it is 1 << 0. 1 << 31 is −2147483648 (int.MinValue): the 1 lands in the sign bit. 1L << 32 is 4294967296: for long the count is taken mod 64. Use 1L (or 1UL) for masks of 32 or more bits.

Your Python Single Number II counts the 1s of each of 32 columns mod 3 and rebuilds res. It returns 4294967293 for [−3, 5, 5, 5]. Why, and what is the fix?

(x >> b) & 1 reads the two's complement bits of −3 correctly, so res holds the 32-bit pattern 0xFFFFFFFD, but Python reads that as the positive number 4294967293. Convert at the end: res − (1 << 32) if res >> 31 else res gives −3. The ones/twos version does not need the fix, because it never builds the value from 32 separate columns.

How many times does the body of the submask loop run, in total, if you run it for every mask of n = 10 items? Why?

3¹⁰ = 59049 (counting the visit of 0 for every mask). Each of the 10 items is in one of three situations: not in the mask, in the mask but not the submask, or in both. A (mask, submask) pair is one choice of situation per item, so there are 3ⁿ pairs, against 4ⁿ ≈ 10⁶ for a naive double loop with a subset test.

What is the Gray code with index 10, and which index has Gray code 1111?

g(10) = 10 ^ 5 = 1010 ^ 0101 = 1111 = 15. Conversely, the inverse of 1111 is 1111 ^ 0111 ^ 0011 ^ 0001 = 1010 = 10. They are the same fact read in both directions.

Why does the maximum XOR greedy decide bits from the top down? Would bottom-up work?

Top-down works because bit b is worth 2b, more than all lower bits together (2b − 1). So any pair that wins bit b beats every pair that loses it, regardless of the lower bits: committing to the 1 is always safe. Bottom-up gives no such guarantee: winning bit 0 says nothing about the higher bits, and a pair with a 0 in bit 0 may still be the best.

Cheat sheet

Single bitsTest (x >> i) & 1, set x | 1 << i, clear x & ~(1 << i), toggle x ^ 1 << i. O(1).
Lowest 1x & −x keeps it; x & (x − 1) drops it; x | (x + 1) sets the lowest 0. Fenwick walks with i & −i.
Two's complement−x = ~x + 1, ~x = −x − 1. Range −2ʷ⁻¹ … 2ʷ⁻¹ − 1; −MIN == MIN.
Python vs C#Python: unbounded, mask with 0xFFFFFFFF, sign-fix at the end. C#: wraps, >>> is logical, shift count mod 32/64, use 1L << k.
Popcountx.bit_count(), BitOperations.PopCount. Kernighan O(ones). Counting bits: dp[i >> 1] + (i & 1).
XORa ^ a = 0; order-free; self-inverse; a + b = (a ^ b) + 2(a & b). XOR 0…n by n mod 4: n, 1, n+1, 0.
Single NumberI: XOR all. II: columns mod 3 or ones/twos. III: split by (a ^ b) & −(a ^ b).
SubsetsAll: range(1 << n). Submasks: sub = (sub − 1) & mask, 3ⁿ total. k-subsets: Gosper.
Gray codeg = i ^ (i >> 1); inverse: XOR of all right shifts. One bit per step; a Hamiltonian cycle on the cube.
Max XORTop bit first. Prefix set: is p ^ cand present? Or a binary trie. O(n · W).
Per-column countingPairwise sums of XOR/AND/OR: count ones per column, c · (n − c) pairs differ. O(n · W).
Bitsetsreach |= reach << x for subset sum; rows of closures; O(n · S / 64). Python int or C# BitArray / ulong[].
