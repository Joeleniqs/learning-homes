What this page is and when you need it

Graph Fundamentals gave you BFS and DFS. Topological Sort showed that a DFS finish order carries information. This page is the "very hard" end of graphs. Almost every technique here is a BFS or a DFS you already know, plus one extra array that answers a sharper question:

The question The extra bookkeeping Technique
Which single edge or node, if it fails, splits the network? tin[u], low[u] timestamps Bridges and articulation points (Tarjan)
Who can reach whom and get back? low[u] plus a stack of unfinished nodes Strongly connected components (Tarjan, Kosaraju)
Can these yes/no rules all hold at once? an implication graph, then SCC ids 2-SAT
Can I use every edge exactly once? in/out degree counts, then post-order Euler path (Hierholzer)
How many pairs can I make? How much can flow through? a residual graph you search again and again Matching, max flow, min cut
What is the shortest path when the "node" is really a situation? a state tuple, a deque, or two frontiers State BFS, 0-1 BFS, bidirectional BFS
Which root gives the smallest tree height? degrees, peeling leaves Tree centres and diameter

The one idea. Each advanced graph algorithm is an ordinary traversal plus one invariant you maintain along the way: a timestamp (low), a stack of unfinished nodes, a degree balance, or a residual capacity. Learn the invariant and the code writes itself.

Prerequisites: Graph Fundamentals (BFS, DFS, the iterative DFS stack, grids, bipartite 2-colouring, BFS over states) and Topological Sort (DFS finish order, DAGs). Related pages, which this one does not re-teach: Union-Find (dynamic connectivity), Shortest Paths (Dijkstra, Bellman-Ford) and Minimum Spanning Trees (Kruskal, Prim).

Bridges and articulation points

A bridge is an edge whose removal disconnects the graph. An articulation point (cut vertex) is a node whose removal does the same. Typical uses are single points of failure in a network ("critical connections"), roads whose closure strands a town, and the islands-and-days problems on grids.

The brute force removes each edge, re-runs a BFS and counts components: O(E · (V + E)). Tarjan's idea finds all of them in one DFS.

Two numbers per node: tin and low

Run a DFS and stamp each node with the time you first reach it: tin[u] = 0, 1, 2, .... The DFS splits the edges into tree edges (they discovered a new node) and back edges (they point to a node that is already on the current DFS path, an ancestor). In an undirected DFS there are no other kinds of edge.

Now define

low[u] = the smallest tin reachable from u's subtree by going down any number of tree edges and then up at most one back edge.

low[u] answers one question: "How high up the DFS tree can my subtree climb without using the edge to my parent?"

The two tests follow directly from that sentence. Take a tree edge u → v:

  • If low[v] > tin[u], the subtree of v cannot reach u or anything above u without this edge. Cut the edge and the subtree is stranded, so u–v is a bridge.
  • If low[v] >= tin[u], the subtree of v can at best climb back to u itself. Delete u and the subtree is stranded, so u is an articulation point. The one exception is the DFS root, which has nothing above it. The root is a cut vertex exactly when it has two or more DFS children: the children cannot reach each other except through the root, because an undirected DFS has no cross edges.

Bridge: strict >

low[v] == tin[u] means v's subtree has a back edge to u. That back edge plus the tree path is a cycle through u–v, so removing u–v leaves the cycle's other route. Not a bridge.

Cut vertex: >=

low[v] == tin[u] means the subtree's best escape lands on u. If u itself is deleted, that escape disappears too. u is a cut vertex. Equality counts.

Watch it run

The animation numbers the nodes in DFS order, fills the tin/low table as the DFS goes down, and updates low as each call returns. The bridge and cut-vertex tests fire at the moment a child finishes, which is exactly where they sit in the code. The default graph is three triangles chained by single edges, so you should see two bridges and four cut vertices.

Things to notice while stepping:

  • low only ever decreases, and it changes in two places: when a back edge is seen (min(low[u], tin[v])) and when a child returns (min(low[u], low[v])).
  • A whole cycle ends up sharing the low of its highest node. Triangle 0-1-2 settles at low = 0, triangle 2-3-4 at low = 2. That shared value is what "cannot escape" means.
  • Edges inside a cycle are never bridges. Every bridge is a tree edge, because a back edge always closes a cycle.

Template

import sys
sys.setrecursionlimit(1 << 20)   # the search below is recursive

def bridges_and_cut_vertices(n, edges):
    adj = [[] for _ in range(n)]
    for i, (u, v) in enumerate(edges):
        adj[u].append((v, i))
        adj[v].append((u, i))
    tin, low = [-1] * n, [0] * n
    timer = 0
    bridges, cut = [], set()

    def dfs(u, parent_edge):
        nonlocal timer
        tin[u] = low[u] = timer
        timer += 1
        children = 0
        for v, eid in adj[u]:
            if eid == parent_edge:          # skip the edge we came in on, not the parent node
                continue
            if tin[v] != -1:                # back edge: v is an ancestor
                low[u] = min(low[u], tin[v])
            else:                           # tree edge
                dfs(v, eid)
                low[u] = min(low[u], low[v])
                children += 1
                if low[v] > tin[u]:
                    bridges.append((u, v))
                if parent_edge != -1 and low[v] >= tin[u]:
                    cut.add(u)
        if parent_edge == -1 and children >= 2:
            cut.add(u)

    for s in range(n):
        if tin[s] == -1:
            dfs(s, -1)
    return bridges, sorted(cut)

public static class LowLink
{
    public static (List<(int, int)> Bridges, SortedSet<int> Cut) BridgesAndCutVertices(int n, int[][] edges)
    {
        var adj = new List<(int To, int Id)>[n];
        for (int i = 0; i < n; i++) adj[i] = new();
        for (int i = 0; i < edges.Length; i++)
        {
            adj[edges[i][0]].Add((edges[i][1], i));
            adj[edges[i][1]].Add((edges[i][0], i));
        }
        int[] tin = Enumerable.Repeat(-1, n).ToArray(), low = new int[n];
        int timer = 0;
        var bridges = new List<(int, int)>();
        var cut = new SortedSet<int>();

        void Dfs(int u, int parentEdge)
        {
            tin[u] = low[u] = timer++;
            int children = 0;
            foreach (var (v, id) in adj[u])
            {
                if (id == parentEdge) continue;              // skip the edge, not the parent node
                if (tin[v] != -1) { low[u] = Math.Min(low[u], tin[v]); continue; }   // back edge
                Dfs(v, id);
                low[u] = Math.Min(low[u], low[v]);
                children++;
                if (low[v] > tin[u]) bridges.Add((u, v));
                if (parentEdge != -1 && low[v] >= tin[u]) cut.Add(u);
            }
            if (parentEdge == -1 && children >= 2) cut.Add(u);
        }

        for (int s = 0; s < n; s++) if (tin[s] == -1) Dfs(s, -1);
        return (bridges, cut);
    }
}

Complexity: O(V + E) time and O(V + E) memory. Every edge is looked at twice, once from each end.

Pitfall: skipping the parent node instead of the parent edge

The tempting code is if v == parent: continue. It breaks as soon as there are parallel edges: two cables between the same pair of routers. The second cable is a genuine back edge, but "skip the parent" throws it away, so the algorithm reports a bridge that is not one. Pass the edge id you came in on and skip only that one edge. If the problem guarantees a simple graph, both versions work, but the edge-id version costs nothing extra.

Pitfall: recursion depth

A path of 10⁵ nodes makes the recursive DFS 10⁵ frames deep. Python's default limit is about 1000, and raising it with sys.setrecursionlimit can still crash the interpreter's C stack. C# overflows its 1 MB stack and a StackOverflowException cannot be caught. For large inputs use the iterative version from worked problem 1. It keeps (node, parent edge, next neighbour index) on an explicit stack and does the "child returned" update when it pops a node.

Strongly connected components

In a directed graph, u and v are strongly connected when u can reach v and v can reach u. The relation splits the nodes into strongly connected components (SCCs): maximal groups where everyone reaches everyone. A single node with no cycle through it is an SCC on its own.

The picture on the right is the most useful fact about SCCs. If you collapse each SCC into one node, the result is always a DAG, called the condensation. If two SCCs could reach each other, they would be one SCC. So every directed graph is "a DAG of cycle clusters", and you can run any DAG technique on the condensation: topological order, longest path, DP. That is how SCCs turn a hard cyclic problem into an easy acyclic one.

Tarjan's SCC: low-link plus a stack

Tarjan's SCC algorithm is the same tin/low DFS as above, run on directed edges, with one addition: a stack of nodes whose SCC is not decided yet.

  1. On entering u, push it on the stack and mark it on_stack.
  2. For each edge u → v:
    • if v is unvisited, recurse, then low[u] = min(low[u], low[v]);
    • if v is visited and still on the stack, then v belongs to an SCC that is still open, so low[u] = min(low[u], tin[v]);
    • if v is visited and off the stack, v's SCC is already finished and cannot contain u (v cannot reach back). Ignore the edge.
  3. When u finishes with low[u] == tin[u], nothing below u can climb above u, so u is the root of an SCC. Pop the stack down to u; everything popped is one SCC.

Why the "on stack" check is the whole trick

In a directed DFS there are cross edges to nodes in other, already finished branches. Such a node may have a small tin, but it lives in a different SCC that has already been popped. If you let it lower low[u], u would wrongly believe it can climb, and two SCCs would merge. "Still on the stack" means exactly "in an SCC that is still being built along the current path". Compare this with bridges: undirected graphs have no cross edges, so that code needs no stack.

In the animation, the stack panel shows the nodes waiting for their SCC. Watch the edge 6 → 5 near the end: node 5 is visited but its SCC {3, 4, 5} was already popped, so it is no longer on the stack, and the note tells you the edge is ignored. Right after, node 8 finishes with low == tin and is popped alone as its own SCC.

A useful by-product: Tarjan completes SCCs in reverse topological order. The first SCC popped is a sink of the condensation (nothing leaves it), and the last one popped is a source. 2-SAT below relies on this.

Kosaraju: two passes and a reversed graph

Kosaraju's algorithm needs no low at all. It runs two plain DFS passes:

  1. Pass 1 on G: record nodes in finish order (post-order), as in topological sort.
  2. Pass 2 on Gᵀ (every edge reversed): take nodes in decreasing finish time. Each DFS started from an unassigned node collects exactly one SCC.

Why does pass 2 never leak into a second SCC? The node that finishes last lies in a source SCC of the condensation: if some other SCC B had an edge into its SCC A, a DFS that entered B would have explored A and come back, so something in B would finish later. In Gᵀ every edge is reversed, so that source SCC becomes a sink: the DFS from it cannot leave. Label it, conceptually delete it, and the next-latest finisher is again in a source of what remains. Repeat.

Template: both algorithms

import sys
sys.setrecursionlimit(1 << 20)   # the search below is recursive

def tarjan_scc(n, adj):
    tin, low = [-1] * n, [0] * n
    on_stack, stack = [False] * n, []
    comp, timer, count = [-1] * n, 0, 0

    def dfs(u):
        nonlocal timer, count
        tin[u] = low[u] = timer
        timer += 1
        stack.append(u)
        on_stack[u] = True
        for v in adj[u]:
            if tin[v] == -1:
                dfs(v)
                low[u] = min(low[u], low[v])
            elif on_stack[v]:               # only nodes of an unfinished SCC
                low[u] = min(low[u], tin[v])
        if low[u] == tin[u]:                # u is the root of an SCC: pop it
            while True:
                w = stack.pop()
                on_stack[w] = False
                comp[w] = count
                if w == u:
                    break
            count += 1

    for s in range(n):
        if tin[s] == -1:
            dfs(s)
    return comp, count          # comp ids are in REVERSE topological order

def kosaraju_scc(n, adj):
    radj = [[] for _ in range(n)]
    for u in range(n):
        for v in adj[u]:
            radj[v].append(u)
    seen, order = [False] * n, []
    for s in range(n):                      # pass 1: finish order on G
        if seen[s]:
            continue
        seen[s] = True
        stack = [(s, 0)]
        while stack:
            u, i = stack.pop()
            if i < len(adj[u]):
                stack.append((u, i + 1))
                v = adj[u][i]
                if not seen[v]:
                    seen[v] = True
                    stack.append((v, 0))
            else:
                order.append(u)             # u finished
    comp, count = [-1] * n, 0
    for s in reversed(order):               # pass 2: latest finisher first, on G reversed
        if comp[s] != -1:
            continue
        comp[s] = count
        stack = [s]
        while stack:
            u = stack.pop()
            for v in radj[u]:
                if comp[v] == -1:
                    comp[v] = count
                    stack.append(v)
        count += 1
    return comp, count          # comp ids are in topological order

public static class Scc
{
    // Tarjan: component ids come out in REVERSE topological order.
    public static (int[] Comp, int Count) Tarjan(int n, List<int>[] adj)
    {
        int[] tin = Enumerable.Repeat(-1, n).ToArray(), low = new int[n], comp = Enumerable.Repeat(-1, n).ToArray();
        var onStack = new bool[n];
        var stack = new Stack<int>();
        int timer = 0, count = 0;

        void Dfs(int u)
        {
            tin[u] = low[u] = timer++;
            stack.Push(u); onStack[u] = true;
            foreach (int v in adj[u])
            {
                if (tin[v] == -1) { Dfs(v); low[u] = Math.Min(low[u], low[v]); }
                else if (onStack[v]) low[u] = Math.Min(low[u], tin[v]);   // unfinished SCC only
            }
            if (low[u] == tin[u])                    // u is the root of its SCC
            {
                int w;
                do { w = stack.Pop(); onStack[w] = false; comp[w] = count; } while (w != u);
                count++;
            }
        }

        for (int s = 0; s < n; s++) if (tin[s] == -1) Dfs(s);
        return (comp, count);
    }

    // Kosaraju: component ids come out in topological order.
    public static (int[] Comp, int Count) Kosaraju(int n, List<int>[] adj)
    {
        var radj = new List<int>[n];
        for (int i = 0; i < n; i++) radj[i] = new();
        for (int u = 0; u < n; u++) foreach (int v in adj[u]) radj[v].Add(u);

        var seen = new bool[n];
        var order = new List<int>();
        for (int s = 0; s < n; s++)                  // pass 1: finish order on G
        {
            if (seen[s]) continue;
            seen[s] = true;
            var st = new Stack<(int U, int I)>();
            st.Push((s, 0));
            while (st.Count > 0)
            {
                var (u, i) = st.Pop();
                if (i < adj[u].Count)
                {
                    st.Push((u, i + 1));
                    int v = adj[u][i];
                    if (!seen[v]) { seen[v] = true; st.Push((v, 0)); }
                }
                else order.Add(u);                   // u finished
            }
        }

        var comp = Enumerable.Repeat(-1, n).ToArray();
        int count = 0;
        for (int k = order.Count - 1; k >= 0; k--)   // pass 2: on the reversed graph
        {
            int s = order[k];
            if (comp[s] != -1) continue;
            comp[s] = count;
            var st = new Stack<int>();
            st.Push(s);
            while (st.Count > 0)
            {
                int u = st.Pop();
                foreach (int v in radj[u])
                    if (comp[v] == -1) { comp[v] = count; st.Push(v); }
            }
            count++;
        }
        return (comp, count);
    }
}

Complexity: both are O(V + E). Kosaraju also stores the reversed graph, which is O(V + E) extra memory.

Passes one DFS two DFS, the second on the reversed graph

Which one to write in an interview?

If you have just written bridges, Tarjan is the same code with a stack, so write Tarjan. If you are nervous about low-link, Kosaraju is two DFS calls you cannot get wrong. Both give the same components. Only the numbering of the components differs (reverse topological versus topological), and that matters for 2-SAT.

The condensation DAG

Once every node has a component id, build the condensation: one node per SCC, and an edge comp[u] → comp[v] for every original edge whose ends are in different components (skip duplicates if you care). It is a DAG, so you can:

  • topologically sort it (Tarjan's ids already give you the reverse of that order);
  • run DP along it: "collect the most coins when every room in a cycle can be revisited" becomes "sum the coins inside each SCC, then find the longest path in the DAG";
  • count sources and sinks to answer reachability questions.

The classic question: what is the minimum number of edges to add to make the whole graph strongly connected? The answer is max(#sources, #sinks) of the condensation, and 0 if there is only one SCC. Every source needs a new incoming edge and every sink a new outgoing one, and one added edge can fix one sink and one source at once by linking a sink to a source. The visualizer finds the SCCs, draws the condensation, colours the sources and sinks, and suggests the edges to add.

Pitfall: the single-SCC case

When the graph is already strongly connected, the condensation is one node that is both a source and a sink, so the formula would say 1. The answer is 0. Special-case count == 1.

2-SAT: yes/no rules as an implication graph

You have n boolean variables and a list of clauses, each an OR of two literals: (a ∨ b), (¬a ∨ c), .... Can all clauses hold at once? With three literals per clause (3-SAT) this is NP-complete. With two it is linear, thanks to SCCs.

The key rewrite: (a ∨ b) says "if a is false, b must be true, and if b is false, a must be true":

(a ∨ b) ≡ (¬a → b) ∧ (¬b → a)

Make a graph with two nodes per variable, x and ¬x, and add both implications as directed edges for every clause.

  • If x and ¬x are in the same SCC, then x forces ¬x and ¬x forces x. That is a contradiction: unsatisfiable.
  • Otherwise a valid assignment exists. Set each x to the literal that comes later in topological order of the condensation. Implications point "forward", so choosing the later literal never forces something earlier that contradicts it. With Tarjan's reverse-topological ids, "later in topological order" means a smaller component id: x = comp[x] < comp[¬x]. With Kosaraju's ids the comparison flips.

Step through the default formula. Each clause adds two edges, then the SCCs are found and each variable is assigned. Then replace the formula with a|b, a|!b, !a|b, !a|!b, which no assignment satisfies, and watch a and ¬a land in the same SCC.

Turning constraints into clauses

Most of the work in a 2-SAT problem is translation. Every rule below becomes one or two clauses:

Constraint Clauses
a or b (a ∨ b)
a implies b (¬a ∨ b)
not both a and b (¬a ∨ ¬b)
exactly one of a, b (a xor b) (a ∨ b), (¬a ∨ ¬b)
a equals b (¬a ∨ b), (a ∨ ¬b)
a must be true (a ∨ a), which adds the edge ¬a → a

Template

def two_sat(n, clauses):
    """clauses: list of (a, b) literals; literal x>=0 means var x, ~x (negative) means NOT x."""
    node = lambda lit: 2 * lit if lit >= 0 else 2 * ~lit + 1
    adj = [[] for _ in range(2 * n)]
    for a, b in clauses:                    # (a or b)  ==  (!a -> b) and (!b -> a)
        adj[node(a) ^ 1].append(node(b))
        adj[node(b) ^ 1].append(node(a))
    comp, _ = tarjan_scc(2 * n, adj)
    value = []
    for x in range(n):
        if comp[2 * x] == comp[2 * x + 1]:
            return None                     # x and !x imply each other
        value.append(comp[2 * x] < comp[2 * x + 1])   # pick the literal later in topo order
    return value

public static class TwoSat
{
    // Literal x >= 0 means variable x; ~x means NOT x. Returns null when unsatisfiable.
    public static bool[]? Solve(int n, (int A, int B)[] clauses)
    {
        static int Node(int lit) => lit >= 0 ? 2 * lit : 2 * ~lit + 1;
        var adj = new List<int>[2 * n];
        for (int i = 0; i < 2 * n; i++) adj[i] = new();
        foreach (var (a, b) in clauses)              // (a or b) == (!a -> b) and (!b -> a)
        {
            adj[Node(a) ^ 1].Add(Node(b));
            adj[Node(b) ^ 1].Add(Node(a));
        }
        var (comp, _) = Scc.Tarjan(2 * n, adj);
        var value = new bool[n];
        for (int x = 0; x < n; x++)
        {
            if (comp[2 * x] == comp[2 * x + 1]) return null;
            value[x] = comp[2 * x] < comp[2 * x + 1];   // the literal later in topological order wins
        }
        return value;
    }
}

Complexity: O(n + m) for n variables and m clauses (2n nodes, 2m edges).

Recognise 2-SAT when

Every item makes one binary choice (on/off, left/right, team A/B, pizza topping yes/no), and every rule mentions at most two of those choices. If a rule mentions three choices, it is not 2-SAT.

Equality is not 2-SAT. Satisfiability of Equality Equations (a==b, b!=c) looks similar, but the variables take many values, not two. Merge all the == pairs with union-find, then check that no != pair ended up in the same set.

Euler paths and circuits

An Euler path uses every edge exactly once. An Euler circuit is an Euler path that ends where it started. These are the "draw the house without lifting your pen" puzzles, and they hide inside interview problems that talk about tickets, dominoes, pairs that must chain, or strings that must contain every code.

When does one exist? Count degrees

Every time the walk passes through a node, it uses one edge in and one edge out. So in the middle of the walk degrees come in pairs, and only the two ends can be unbalanced.

Plus, in every case, all edges must lie in one connected piece (isolated nodes with no edges do not matter). The cheap way to check connectivity is to run the algorithm and verify that the path it returns has E + 1 nodes.

Hierholzer's algorithm: walk, get stuck, back up

Here is the problem with a naive walk. Start anywhere and keep following unused edges: you will get stuck, and you may get stuck too early, with edges still unused somewhere behind you. Hierholzer's fix is beautifully small:

  1. Keep a stack holding the current walk.
  2. If the top node still has an unused edge, take it and push the neighbour.
  3. If the top node has no unused edges, pop it and append it to the answer.
  4. Reverse the answer at the end.

Why "write it down when stuck" works

A node is written to the answer only when it has no edges left. That means it is genuinely final from that point of the tour on. A dead end found early, which was the "too early" problem, is written first and therefore ends up last after the reversal. Meanwhile, the stack backs up to a node that still has unused edges and walks a detour from there. That detour is spliced into the tour before the dead end. It is post-order DFS on edges, exactly the same trick as topological sort's "add on finish".

The animation shows the stack, the circuit being written in post-order, and the used edges. With the default graph, the walk A → B → C → A → D gets stuck at D while the loop B → E → F → B is still unused. D is written first, so it ends up last. The stack then backs up to B, which still has an edge, and the loop is spliced in there.

Template: directed and undirected

The undirected version needs one extra detail. Each edge appears in two adjacency lists, so mark edges used by id, and advance a per-node pointer past edges already used from the other end. That keeps it O(V + E).

from collections import defaultdict

def euler_path_directed(edges):
    adj, indeg, outdeg = defaultdict(list), defaultdict(int), defaultdict(int)
    for u, v in edges:
        adj[u].append(v)
        outdeg[u] += 1
        indeg[v] += 1
    nodes = set(indeg) | set(outdeg)
    start = next(iter(nodes)) if nodes else None
    plus = minus = 0
    for x in nodes:
        d = outdeg[x] - indeg[x]
        if d == 1:
            plus += 1; start = x
        elif d == -1:
            minus += 1
        elif d != 0:
            return None
    if (plus, minus) not in ((0, 0), (1, 1)):
        return None
    if (plus, minus) == (0, 0):
        start = min(x for x in nodes if outdeg[x] > 0) if edges else start
    stack, out = [start], []
    while stack:
        u = stack[-1]
        if adj[u]:
            stack.append(adj[u].pop())      # walk an unused edge
        else:
            out.append(stack.pop())         # stuck: u is final in the circuit
    out.reverse()
    return out if len(out) == len(edges) + 1 else None   # disconnected edges

def euler_path_undirected(n, edges):
    adj = [[] for _ in range(n)]
    for i, (u, v) in enumerate(edges):
        adj[u].append((v, i))
        adj[v].append((u, i))
    odd = [x for x in range(n) if len(adj[x]) % 2]
    if len(odd) not in (0, 2):
        return None
    start = odd[0] if odd else next((x for x in range(n) if adj[x]), 0)
    used, ptr = [False] * len(edges), [0] * n
    stack, out = [start], []
    while stack:
        u = stack[-1]
        while ptr[u] < len(adj[u]) and used[adj[u][ptr[u]][1]]:
            ptr[u] += 1                     # skip edges already used from the other end
        if ptr[u] == len(adj[u]):
            out.append(stack.pop())
        else:
            v, i = adj[u][ptr[u]]
            used[i] = True
            stack.append(v)
    return out[::-1] if len(out) == len(edges) + 1 else None

        foreach (var (u, v) in edges)
        {
            if (!adj.ContainsKey(u)) adj[u] = new();
            if (!adj.ContainsKey(v)) adj[v] = new();
            adj[u].Push(v);
            bal[u] = bal.GetValueOrDefault(u) + 1;
            bal[v] = bal.GetValueOrDefault(v) - 1;

        if (edges.Count == 0) return new List<T>();
        T start = edges[0].U;
        int plus = 0, minus = 0;
        foreach (var (x, d) in bal)
        {
            if (d == 1) { plus++; start = x; }
            else if (d == -1) minus++;
            else if (d != 0) return null;
        }
        if (!((plus == 0 && minus == 0) || (plus == 1 && minus == 1))) return null;

        var outList = new List<T>();
        stack.Push(start);
        while (stack.Count > 0)
        {
            T u = stack.Peek();
            if (adj[u].Count > 0) stack.Push(adj[u].Pop());   // walk an unused edge
            else outList.Add(stack.Pop());                     // stuck: u is final
        }
        outList.Reverse();
        return outList.Count == edges.Count + 1 ? outList : null;
    }

        var stack = new Stack<int>();

        stack.Push(start);

            if (ptr[u] == adj[u].Count) { outList.Add(stack.Pop()); continue; }
            var (v, id) = adj[u][ptr[u]];

        }
        outList.Reverse();

Bipartite matching

A graph is bipartite when its nodes split into two sides with every edge going across. Graph Fundamentals shows how to test that with 2-colouring. This section is about what you do once you have the two sides: workers and jobs, students and seats, people and invitations. A matching is a set of edges with no shared endpoint, so each person gets at most one job and each job at most one person. We want the maximum matching.

Greedy fails: "match each worker to the first free job" can block a later worker whose only job you just took. The fix is the augmenting path.

Augmenting paths: free, matched, free, ..., free

An alternating path switches between edges that are not in the matching and edges that are. If it starts and ends at free (unmatched) vertices, it is an augmenting path. It has one more free edge than matched edge, so flipping every edge on it (matched becomes free, free becomes matched) grows the matching by exactly one, and every vertex on it stays matched once.

Berge's theorem: a matching is maximum if and only if no augmenting path exists. So the algorithm is: find an augmenting path, flip it, repeat until none exists.

Kuhn's algorithm: one DFS per left vertex

Kuhn's algorithm (the "Hungarian DFS" for unweighted matching) tries each left vertex u in turn:

  • For each right neighbour r of u that is not yet seen in this attempt, mark it seen.
  • If r is free, take it.
  • If r belongs to some left vertex w, ask w recursively to move to a different right vertex. If w succeeds, r is now free for u.
  • A success unwinds the recursion and flips every edge on the path, because each level re-assigns match_r[r] = u.

The seen array is reset for every new left vertex and shared during one attempt. That stops one attempt from asking the same right vertex twice (an infinite loop), but lets the next attempt try everything again.

In the default graph, a, b and c are matched without conflict. Then d's only option, 1, is taken by a. Watch the chain reaction: a moves to 2, which forces b to 3, which forces c to 4. That single DFS is the augmenting path d–1–a–2–b–3–c–4.

Hopcroft-Karp at a glance

Kuhn is O(V · E): up to V attempts, each a DFS over all edges. Hopcroft-Karp batches the work. Each phase first runs one BFS from all free left vertices at once to label layers, then finds a maximal set of vertex-disjoint shortest augmenting paths with DFS restricted to "layer + 1" edges.

The length of the shortest augmenting path strictly increases from phase to phase, and there are only O(√V) phases, so the total is O(E · √V). The structure is the same as Dinic's max-flow algorithm below: BFS levels, then DFS along levels. On a unit-capacity bipartite network, Dinic is Hopcroft-Karp.

import sys
sys.setrecursionlimit(1 << 20)   # the search below is recursive
from collections import deque

def max_matching_kuhn(n_left, n_right, adj):
    match_r = [-1] * n_right                # match_r[r] = left node matched to r

    def try_kuhn(u, seen):
        for r in adj[u]:
            if seen[r]:
                continue
            seen[r] = True
            if match_r[r] == -1 or try_kuhn(match_r[r], seen):
                match_r[r] = u              # flip the alternating path
                return True
        return False

    return sum(try_kuhn(u, [False] * n_right) for u in range(n_left))

def hopcroft_karp(n_left, n_right, adj):
    INF = float("inf")
    match_l, match_r = [-1] * n_left, [-1] * n_right
    dist = [0] * n_left

    def bfs():
        q = deque()
        for u in range(n_left):
            dist[u] = 0 if match_l[u] == -1 else INF
            if match_l[u] == -1:
                q.append(u)
        found = False
        while q:
            u = q.popleft()
            for r in adj[u]:
                w = match_r[r]
                if w == -1:
                    found = True             # a free right node ends a shortest path
                elif dist[w] == INF:
                    dist[w] = dist[u] + 1
                    q.append(w)
        return found

    def dfs(u):
        for r in adj[u]:
            w = match_r[r]
            if w == -1 or (dist[w] == dist[u] + 1 and dfs(w)):
                match_l[u], match_r[r] = r, u
                return True
        dist[u] = INF                        # dead end: never revisit in this phase
        return False

    matching = 0
    while bfs():
        for u in range(n_left):
            if match_l[u] == -1 and dfs(u):
                matching += 1
    return matching

public static class Matching
{
    public static int Kuhn(int nLeft, int nRight, List<int>[] adj)
    {
        var matchR = Enumerable.Repeat(-1, nRight).ToArray();

        bool Try(int u, bool[] seen)
        {
            foreach (int r in adj[u])
            {
                if (seen[r]) continue;
                seen[r] = true;
                if (matchR[r] == -1 || Try(matchR[r], seen)) { matchR[r] = u; return true; }
            }
            return false;
        }

        int result = 0;
        for (int u = 0; u < nLeft; u++) if (Try(u, new bool[nRight])) result++;
        return result;
    }

    public static int HopcroftKarp(int nLeft, int nRight, List<int>[] adj)
    {
        const int Inf = int.MaxValue;
        var matchL = Enumerable.Repeat(-1, nLeft).ToArray();
        var matchR = Enumerable.Repeat(-1, nRight).ToArray();
        var dist = new int[nLeft];

        bool Bfs()
        {
            var q = new Queue<int>();
            for (int u = 0; u < nLeft; u++)
            {
                dist[u] = matchL[u] == -1 ? 0 : Inf;
                if (matchL[u] == -1) q.Enqueue(u);
            }
            bool found = false;
            while (q.Count > 0)
            {
                int u = q.Dequeue();
                foreach (int r in adj[u])
                {
                    int w = matchR[r];
                    if (w == -1) found = true;               // a free right node ends a shortest path
                    else if (dist[w] == Inf) { dist[w] = dist[u] + 1; q.Enqueue(w); }
                }
            }
            return found;
        }

        bool Dfs(int u)
        {
            foreach (int r in adj[u])
            {
                int w = matchR[r];
                if (w == -1 || (dist[w] == dist[u] + 1 && Dfs(w)))
                {
                    matchL[u] = r; matchR[r] = u;
                    return true;
                }
            }
            dist[u] = Inf;                                   // dead end for this phase
            return false;
        }

        int matching = 0;
        while (Bfs())
            for (int u = 0; u < nLeft; u++)
                if (matchL[u] == -1 && Dfs(u)) matching++;
        return matching;
    }
}

Maximum flow and minimum cut

A flow network is a directed graph with a capacity on each edge, a source s and a sink t. A flow assigns each edge an amount 0 ≤ f ≤ cap, such that every node except s and t sends out exactly what it receives. Max flow asks: how much can get from s to t?

It models pipes and bandwidth, but its real power in problem solving is as a universal matching and cut engine. Matching, edge-disjoint paths, "fewest roads to close" and assignment with quotas are all max flow with a clever network.

The residual graph: room to push, room to undo

Pushing flow greedily along any s → t path and stopping when none is left gives a wrong (too small) answer: an early path can block better ones. The fix is to let later paths undo earlier choices. For an edge u → v carrying flow f of capacity c, the residual graph has:

  • a forward arc u → v with residual capacity c − f (room left), and
  • a backward arc v → u with residual capacity f (flow you could cancel).

An augmenting path is any s → t path in the residual graph. Pushing its bottleneck capacity along it increases the flow. When it uses a backward arc, it reroutes flow that an earlier path sent the wrong way. This is exactly the "flip" of bipartite matching, generalised to capacities.

Ford-Fulkerson and Edmonds-Karp

  • Ford-Fulkerson is the method: while some augmenting path exists, push its bottleneck. With integer capacities it terminates, but a bad choice of paths can take O(E · maxflow) time.
  • Edmonds-Karp picks the shortest augmenting path (fewest edges) with BFS. That bounds the number of augmentations by O(V · E), so the total is O(V · E²) regardless of the capacities.

Max-flow = min-cut: the certificate

An s-t cut splits the nodes into S (containing s) and T (containing t). Its capacity is the total capacity of edges going from S to T. Every unit of flow must cross the cut, so any flow ≤ any cut. The theorem says the two meet:

max flow = min cut, and the cut is easy to read off. After the last BFS fails, S = every node the BFS could still reach in the residual graph.

Why is the BFS-reachable set a minimum cut? Every S → T edge must be saturated, otherwise BFS could cross it. Every T → S edge must carry zero flow, otherwise its backward arc would let BFS cross. So the net flow across the cut equals the cut's capacity, and since flow ≤ cut always holds, both are optimal.

Use the min cut, not just the number

"What is the cheapest set of edges to remove so that s cannot reach t?" is a min-cut question. Solve max flow, run one more BFS on the residual graph, and output the edges from reached to unreached nodes. For "fewest nodes to remove", split each node into in → out with capacity 1 first (see the modelling tricks below).

Dinic at a glance

Dinic's algorithm speeds this up the same way Hopcroft-Karp speeds up Kuhn:

  1. BFS from s on the residual graph assigns each node a level (its distance).
  2. A DFS pushes flow only along edges that go from level ℓ to ℓ + 1 (the level graph) until no s → t path is left in it: a blocking flow. A per-node edge pointer (it[u]) skips edges that are already dead, so each edge is abandoned at most once per phase.
  3. Repeat until BFS cannot reach t.

There are at most V phases, each O(V · E), so O(V² · E) in general. On unit-capacity networks such as matching it drops to O(E · √V). On the default network, Dinic needs only 2 phases where Edmonds-Karp needed 4 augmentations. Phase 1 saturates every route of length 3 at once, and phase 2 finds the single remaining route of length 4.

from collections import deque

def max_flow_edmonds_karp(n, edges, s, t):
    cap = [[0] * n for _ in range(n)]
    adj = [set() for _ in range(n)]
    for u, v, c in edges:
        cap[u][v] += c
        adj[u].add(v); adj[v].add(u)        # reverse edge for the residual graph
    flow = 0

        parent[s] = s

Dinic with an edge list, where each edge stores the index of its reverse edge, is the one to keep for real sizes.

from collections import deque

class Dinic:
    def __init__(self, n):
        self.n, self.g = n, [[] for _ in range(n)]   # edge = [to, cap, index of reverse]

    def add_edge(self, u, v, c):
        self.g[u].append([v, c, len(self.g[v])])
        self.g[v].append([u, 0, len(self.g[u]) - 1])

    def max_flow(self, s, t):
        flow = 0
        while True:
            level = [-1] * self.n
            level[s] = 0
            q = deque([s])
            while q:
                u = q.popleft()
                for v, c, _ in self.g[u]:
                    if c > 0 and level[v] == -1:
                        level[v] = level[u] + 1
                        q.append(v)
            if level[t] == -1:
                return flow
            it = [0] * self.n

            def dfs(u, pushed):
                if u == t:
                    return pushed
                while it[u] < len(self.g[u]):
                    e = self.g[u][it[u]]
                    v, c, rev = e
                    if c > 0 and level[v] == level[u] + 1:
                        d = dfs(v, min(pushed, c))
                        if d:
                            e[1] -= d
                            self.g[v][rev][1] += d
                            return d
                    it[u] += 1
                return 0

            while (f := dfs(s, float("inf"))) > 0:
                flow += f

public sealed class Dinic
{
    private sealed class Edge { public int To, Cap, Rev; }
    private readonly List<Edge>[] g;
    private int[] level = Array.Empty<int>(), it = Array.Empty<int>();

    public Dinic(int n) { g = new List<Edge>[n]; for (int i = 0; i < n; i++) g[i] = new(); }

    public void AddEdge(int u, int v, int c)
    {
        g[u].Add(new Edge { To = v, Cap = c, Rev = g[v].Count });
        g[v].Add(new Edge { To = u, Cap = 0, Rev = g[u].Count - 1 });
    }

    public long MaxFlow(int s, int t)
    {
        long flow = 0;
        while (Bfs(s, t))
        {
            it = new int[g.Length];
            int f;
            while ((f = Dfs(s, t, int.MaxValue)) > 0) flow += f;
        }
        return flow;
    }

    private bool Bfs(int s, int t)
    {
        level = Enumerable.Repeat(-1, g.Length).ToArray();
        level[s] = 0;
        var q = new Queue<int>();
        q.Enqueue(s);
        while (q.Count > 0)
        {
            int u = q.Dequeue();
            foreach (var e in g[u])
                if (e.Cap > 0 && level[e.To] == -1) { level[e.To] = level[u] + 1; q.Enqueue(e.To); }
        }
        return level[t] != -1;
    }

    private int Dfs(int u, int t, int pushed)
    {
        if (u == t) return pushed;
        for (; it[u] < g[u].Count; it[u]++)              // current-arc pointer
        {
            var e = g[u][it[u]];
            if (e.Cap <= 0 || level[e.To] != level[u] + 1) continue;
            int d = Dfs(e.To, t, Math.Min(pushed, e.Cap));
            if (d > 0) { e.Cap -= d; g[e.To][e.Rev].Cap += d; return d; }
        }
        return 0;
    }

Pitfall: forgetting the reverse edge, or sharing it wrongly

Every edge must have a reverse edge of capacity 0, created at the same time, and pushing d units does cap -= d on the edge and += d on its reverse. Without reverse edges you get greedy flow, which is wrong. With an adjacency matrix, two opposite input edges u→v and v→u share cells, which is fine, because cap[u][v] and cap[v][u] are each other's reverses. With an edge list, store the reverse's index (rev) so the update is O(1). Searching for the reverse edge is slow, and with parallel edges it can pick the wrong one.

Flow modelling tricks

How often does flow show up in interviews?

Rarely by name, and very few LeetCode problems need it. The ideas matter more: augmenting paths (matching), the residual "undo" arc, and min cut as a certificate. Write Kuhn for matching problems. Reach for flow when a problem has capacities or quotas on both sides, or asks for the minimum number of things to cut.

Implicit graphs: when the node is a situation

The hardest "graph" problems often do not give you a graph. They describe a puzzle, a grid with keys, a lock with wheels or a bus network, and you must decide what a node is. Graph Fundamentals introduced the idea in BFS over states and Word Ladder. This section is the advanced toolkit.

The state rule. A node must contain everything that affects the future, and nothing else. If two situations at the same cell can lead to different futures (different keys held, different obstacles left to break), they are different nodes. If they cannot, merging them is what keeps the search small.

State-space BFS: (cell, keys)

Shortest Path to Get All Keys: walls #, keys a–f, locks A–F, and you start at @. Standing on a cell with no keys is not the same situation as standing there holding key a, because lock A is open only in the second. So the node is (row, col, keys_bitmask). Picture one copy of the grid per key set. Picking up a key moves you to another copy.

0-1 BFS: edge weights 0 and 1 with a deque

When every edge costs 0 or 1, plain BFS is wrong (it treats all edges as cost 1) and Dijkstra is overkill. 0-1 BFS uses a deque:

  • a 0-cost edge: the neighbour has the same distance, so push it to the front;
  • a 1-cost edge: the neighbour is one further, so push it to the back.

The deque always holds distances d, d, ..., d+1, d+1, sorted, so the front is always a minimum. That is the same guarantee Dijkstra's heap gives, at O(1) per operation. Like Dijkstra, a node can be pushed more than once, so check dist[u] + w < dist[v] before pushing. For general weights see Shortest Paths.

Minimum Cost to Make at Least One Valid Path in a Grid is the textbook case. Each cell has an arrow. Following it is free, and changing it (moving any other way) costs 1. In the input, R/L/D/U are the arrows. The animation draws them as glyphs, fills the dist grid beside them, and shows the deque with its front (the next cell to pop) on the left.

from collections import deque

def zero_one_bfs(n, adj, src):
    dist = [float("inf")] * n
    dist[src] = 0
    dq = deque([src])
    while dq:
        u = dq.popleft()
        for v, w in adj[u]:                 # w is 0 or 1
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                if w == 0:
                    dq.appendleft(v)
                else:
                    dq.append(v)
    return dist

public static class ZeroOne
{
    public static int[] Bfs(int n, List<(int V, int W)>[] adj, int src)
    {
        var dist = Enumerable.Repeat(int.MaxValue, n).ToArray();
        dist[src] = 0;
        var dq = new LinkedList<int>();
        dq.AddFirst(src);
        while (dq.Count > 0)
        {
            int u = dq.First!.Value; dq.RemoveFirst();
            foreach (var (v, w) in adj[u])                // w is 0 or 1
            {
                if (dist[u] + w >= dist[v]) continue;
                dist[v] = dist[u] + w;
                if (w == 0) dq.AddFirst(v); else dq.AddLast(v);
            }
        }
        return dist;
    }
}

Complexity: O(V + E). Nodes leave the deque in non-decreasing distance order, so a node's distance can improve at most once after it is first set, and each node is pushed at most twice.

Recognise 0-1 BFS when

The moves are "free" versus "cost one": following an arrow versus changing it, walking on empty cells versus breaking an obstacle (Minimum Obstacle Removal to Reach Corner), staying on the same line versus switching. If there are three or more distinct weights, use Dijkstra.

Multi-source BFS: many starts, one pass

When the question is "distance to the nearest of many sources" (nearest gate, rotten orange, land cell), put all the sources in the queue at distance 0 and run one BFS. It is the BFS version of the super source from max flow: an imaginary node joined to every source by a 0-cost edge. Graph Fundamentals covers it with a visualizer in Multi-source BFS.

Bidirectional BFS: two small balls instead of one big one

When you know both the start and the target, and the graph branches heavily (word ladders, lock combinations, puzzle states), search from both ends at once and stop when the frontiers meet.

With branching factor b and distance d, one BFS explores about bᵈ states; two half-depth searches explore about 2 · b^(d/2). For b = 10 and d = 6 that is a million versus two thousand. Three rules make it correct:

  1. Expand one whole layer at a time, always the smaller frontier.
  2. Check for a meeting when generating a neighbour: if it is in the other side's visited set, the distance is dist_this(u) + 1 + dist_other(v).
  3. Because you finish the whole layer, the first meeting found gives the shortest distance.

The animation runs plain BFS and bidirectional BFS on the same maze and counts the cells each one touches.

Pitfall: stopping at the first meeting cell mid-layer

If you stop the moment any node is seen by both sides, you can return a path one step too long when an even shorter meeting exists elsewhere in the same layer. Finish the layer and take the minimum, or check meetings as you generate (rule 2), which is safe because you expand layer by layer.

The other modelling moves

  • Change what a node is. In Bus Routes the question counts buses, not stops, so make the buses the nodes. Two buses are adjacent if they share a stop. Go through a stop → buses index rather than building all bus–bus edges.
  • Collapse equivalent states. In Word Ladder II, BFS by layers, removing each whole layer from the dictionary only after the layer is done. Record every parent from the previous layer, then backtrack over that parent DAG. This lists all shortest paths without exploring longer ones.
  • Add a dimension for "time" or "parity". If you may wait, or the graph changes over time, the node becomes (cell, t mod period).

Tree diameter and centres

The Tree Patterns page computes the diameter with a post-order DP ("the longest path through each node"). Graph thinking gives two other views that are often simpler when the tree arrives as an edge list.

Diameter by BFS twice. BFS from any node and take the farthest node u. BFS from u, and the farthest node v gives the diameter u … v. This works because in a tree the farthest node from any node is always an endpoint of some diameter. If a deeper endpoint existed, the paths would combine into a longer path, a contradiction. It holds for non-negative edge weights too, using a DFS that sums the weights. It does not hold in general graphs.

Centres by peeling leaves. Repeatedly remove all current leaves (degree 1), round by round, like a topological sort from the outside in. The last one or two nodes standing are the centres. They sit in the middle of every diameter, and rooting the tree there gives the minimum height, ⌈diameter / 2⌉. That is exactly Minimum Height Trees.

The default tree has diameter 5, an odd number of edges, so it has two centres. Switch the mode to "two BFS (diameter)" to see the other method on the same tree.

from collections import deque

def find_min_height_trees(n, edges):
    if n <= 2:
        return list(range(n))
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v); adj[v].append(u)
    deg = [len(a) for a in adj]
    leaves = [u for u in range(n) if deg[u] == 1]
    remaining = n
    while remaining > 2:
        remaining -= len(leaves)
        nxt = []
        for u in leaves:
            for v in adj[u]:
                deg[v] -= 1
                if deg[v] == 1:
                    nxt.append(v)
        leaves = nxt
    return leaves

def tree_diameter(n, edges):
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v); adj[v].append(u)
    def bfs(s):
        dist = [-1] * n; dist[s] = 0; q = deque([s])
        while q:
            u = q.popleft()
            for v in adj[u]:
                if dist[v] < 0:
                    dist[v] = dist[u] + 1; q.append(v)
        far = max(range(n), key=dist.__getitem__)
        return far, dist[far]
    a, _ = bfs(0)
    _, d = bfs(a)
    return d

{
    public static IList<int> FindMinHeightTrees(int n, int[][] edges)

        {

            var next = new List<int>();
            foreach (int u in leaves)
                foreach (int v in adj[u])
                    if (--deg[v] == 1) next.Add(v);
            leaves = next;

    {
        var adj = new List<int>[n];
        for (int i = 0; i < n; i++) adj[i] = new();
        foreach (var e in edges) { adj[e[0]].Add(e[1]); adj[e[1]].Add(e[0]); }
        (int Far, int Dist) Bfs(int s)
        {
            var dist = Enumerable.Repeat(-1, n).ToArray();
            dist[s] = 0;
            var q = new Queue<int>(); q.Enqueue(s);
            int far = s;
            while (q.Count > 0)
            {
                int u = q.Dequeue();
                if (dist[u] > dist[far]) far = u;
                foreach (int v in adj[u]) if (dist[v] < 0) { dist[v] = dist[u] + 1; q.Enqueue(v); }
            }
            return (far, dist[far]);
        }
        var (a, _) = Bfs(0);
        return Bfs(a).Dist;
    }
}

Complexity: O(n) for both. Peeling handles n ≤ 2 as a special case, because the loop stops when 1 or 2 nodes remain.

Pitfall: updating low from a finished SCC (Tarjan SCC)

Bug: elif tin[v] != -1: low[u] = min(low[u], tin[v]). A cross edge to a node in an already-popped SCC lowers low[u], and two SCCs merge. Fix: update from visited nodes only if they are still on the stack (elif on_stack[v]).

Pitfall: greedy instead of Hierholzer

Bug: "always take the smallest next airport and append it to the route". It walks into dead ends with tickets left over. Fix: append on pop (when stuck), then reverse. Also sort each adjacency list descending if you pop() from the end, so the smallest comes out first.

Pitfall: Kuhn's seen shared across left vertices

Bug: allocating seen once outside the loop. The second left vertex then cannot revisit right vertices touched by the first attempt, and augmenting paths are missed. Fix: a fresh seen per left vertex. (The opposite bug, a fresh seen per recursive call, loops forever.)

Pitfall: 2-SAT literal encoding off by one

Bug: mixing "variable x is node x, NOT x is node x + n" with "NOT is id ^ 1". Pick one. With 2x / 2x + 1, negation is id ^ 1, and the clause (a ∨ b) adds node(a) ^ 1 → node(b) and node(b) ^ 1 → node(a). Forgetting the second edge silently drops half of each clause.

Pitfall: state BFS with a 2-D seen

Bug: seen[r][c] in the keys problem. After you pick up a key you must be allowed to re-walk cells you have already visited. Fix: seen over the full state (r, c, keys). The same bug in k-eliminations: seen[r][c] blocks a path that arrives later but with more breaks left.

1. Critical Connections in a Network Hard

n servers and undirected connections. Return every connection whose removal disconnects some servers from others. n is up to 10⁵.

Key insight. "Critical connection" is a bridge: the test is low[child] > tin[parent]. The only real difficulty is size. 10⁵ nodes in a path make recursion overflow in both Python and C#, so write the DFS iteratively. The stack holds (node, edge id we came by, next neighbour index). When a node runs out of neighbours, pop it and do the "child returned" update on its parent: low[p] = min(low[p], low[u]), then test for a bridge.

Run the LeetCode example (0-1, 1-2, 2-0, 1-3): the triangle gets low = 0 everywhere, and only 1–3 is a bridge.

Solution: iterative Tarjan bridges 
def critical_connections(n, connections):
    adj = [[] for _ in range(n)]
    for i, (u, v) in enumerate(connections):
        adj[u].append((v, i))
        adj[v].append((u, i))
    tin, low = [-1] * n, [0] * n
    timer, res = 0, []
    for root in range(n):
        if tin[root] != -1:
            continue
        tin[root] = low[root] = timer; timer += 1
        stack = [(root, -1, 0)]                 # (node, edge id we came by, next adj index)
        while stack:
            u, pe, i = stack[-1]
            if i < len(adj[u]):
                stack[-1] = (u, pe, i + 1)
                v, eid = adj[u][i]
                if eid == pe:
                    continue
                if tin[v] == -1:                # tree edge: descend
                    tin[v] = low[v] = timer; timer += 1
                    stack.append((v, eid, 0))
                else:                           # back edge
                    low[u] = min(low[u], tin[v])
            else:                               # u finished: report to its parent
                stack.pop()
                if stack:
                    p = stack[-1][0]
                    low[p] = min(low[p], low[u])
                    if low[u] > tin[p]:
                        res.append([p, u])
    return res

public static IList<IList<int>> CriticalConnections(int n, IList<IList<int>> connections)
{
    var adj = new List<(int To, int Id)>[n];
    for (int i = 0; i < n; i++) adj[i] = new();
    for (int i = 0; i < connections.Count; i++)
    {
        adj[connections[i][0]].Add((connections[i][1], i));
        adj[connections[i][1]].Add((connections[i][0], i));
    }
    int[] tin = Enumerable.Repeat(-1, n).ToArray(), low = new int[n];
    int timer = 0;
    var res = new List<IList<int>>();
    var stack = new Stack<(int U, int ParentEdge, int I)>();
    for (int root = 0; root < n; root++)
    {
        if (tin[root] != -1) continue;
        tin[root] = low[root] = timer++;
        stack.Push((root, -1, 0));
        while (stack.Count > 0)
        {
            var (u, pe, i) = stack.Pop();
            if (i < adj[u].Count)
            {
                stack.Push((u, pe, i + 1));
                var (v, id) = adj[u][i];
                if (id == pe) continue;
                if (tin[v] == -1) { tin[v] = low[v] = timer++; stack.Push((v, id, 0)); }
                else low[u] = Math.Min(low[u], tin[v]);
            }
            else if (stack.Count > 0)                // u finished: report to its parent
            {
                int p = stack.Peek().U;
                low[p] = Math.Min(low[p], low[u]);
                if (low[u] > tin[p]) res.Add(new List<int> { p, u });
            }
        }
    }
    return res;
}

Time O(V + E), memory O(V + E). No recursion, so 10⁵-node paths are fine.

2. Reconstruct Itinerary Hard

Given airline tickets [from, to], use every ticket exactly once starting at JFK, and return the lexicographically smallest valid itinerary. A valid one is guaranteed.

Key insight. Tickets are edges that must each be used once, so this is an Euler path from JFK. Hierholzer visits neighbours smallest-first (adjacency sorted in reverse, then pop()) and writes an airport only when it is stuck. Any dead end is then pushed to the end of the route, which is the only place it can be. Here is LeetCode's second example; the answer is JFK ATL JFK SFO ATL SFO.

Solution: Hierholzer with sorted adjacency 
from collections import defaultdict

def find_itinerary(tickets):
    adj = defaultdict(list)
    for a, b in sorted(tickets, reverse=True):
        adj[a].append(b)                        # reverse-sorted: pop() gives the smallest
    stack, route = ["JFK"], []
    while stack:
        while adj[stack[-1]]:
            stack.append(adj[stack[-1]].pop())
        route.append(stack.pop())
    return route[::-1]

public static IList<string> FindItinerary(IList<IList<string>> tickets)
{
    var adj = new Dictionary<string, PriorityQueue<string, string>>();
    foreach (var t in tickets)
    {
        if (!adj.TryGetValue(t[0], out var pq)) adj[t[0]] = pq = new PriorityQueue<string, string>(StringComparer.Ordinal);
        pq.Enqueue(t[1], t[1]);
    }
    var stack = new Stack<string>();
    var route = new List<string>();
    stack.Push("JFK");
    while (stack.Count > 0)
    {
        string u = stack.Peek();
        if (adj.TryGetValue(u, out var pq) && pq.Count > 0) stack.Push(pq.Dequeue());
        else route.Add(stack.Pop());
    }
    route.Reverse();
    return route;
}

Time O(E log E) for the sort, plus O(E) for the walk. Memory O(E).

3. Cracking the Safe Hard

The password is n digits from 0..k−1, and the safe checks the last n digits typed. Return any shortest string that is guaranteed to open it.

Key insight. De Bruijn graph: nodes are the (n−1)-digit suffixes, and edges are the passwords. Every node has in = out = k, so an Euler circuit exists, and it uses each of the kⁿ passwords once. Start at 0…0 (n−1 zeros), run Hierholzer, and record the digit of each edge in post-order. The answer is the start node plus the reversed digits, of length kⁿ + n − 1. The visualizer below shows n = 2, k = 3, where every node also has a self-loop (00, 11, 22).

Solution: Hierholzer on the de Bruijn graph 
from collections import defaultdict

def crack_safe(n, k):
    if n == 1:
        return "".join(map(str, range(k)))
    start = "0" * (n - 1)
    nxt = defaultdict(int)                      # node -> next digit to try
    stack, out = [(start, "")], []              # (node, digit of the edge that led here)
    while stack:
        node, d = stack[-1]
        if nxt[node] < k:                       # an unused outgoing edge exists
            digit = str(nxt[node])
            nxt[node] += 1
            stack.append(((node + digit)[1:], digit))
        else:                                   # stuck: this edge is final (post-order)
            stack.pop()
            out.append(d)
    return start + "".join(reversed(out))

public static string CrackSafe(int n, int k)
{
    if (n == 1) return string.Concat(Enumerable.Range(0, k));
    string start = new string('0', n - 1);
    var next = new Dictionary<string, int>();
    var stack = new Stack<(string Node, char Digit)>();
    var outDigits = new StringBuilder();
    stack.Push((start, ' '));
    while (stack.Count > 0)
    {
        var (node, d) = stack.Peek();
        int tried = next.GetValueOrDefault(node);
        if (tried < k)
        {
            next[node] = tried + 1;
            char digit = (char)('0' + tried);
            stack.Push(((node + digit).Substring(1), digit));
        }
        else
        {
            stack.Pop();
            if (stack.Count > 0) outDigits.Append(d);
        }
    }
    var arr = outDigits.ToString().ToCharArray();
    Array.Reverse(arr);
    return start + new string(arr);
}

Time O(kⁿ · n) (string slicing per edge), memory O(kⁿ). n = 1 is special-cased: every single digit, once.

4. Valid Arrangement of Pairs Hard

Rearrange pairs [start, end] so that each pair's end equals the next pair's start. A valid arrangement is guaranteed.

Key insight. Each pair is a directed edge start → end, and "chain them all" is an Euler path. Compute out − in for every number. If some number has out − in = 1, the path must start there; otherwise it is a circuit and any start works. Run Hierholzer, then turn the node path back into consecutive pairs. The values go up to 10⁹, so use a hash map for adjacency, not an array.

Solution: degree balance + Hierholzer 
from collections import defaultdict

def valid_arrangement(pairs):
    adj, bal = defaultdict(list), defaultdict(int)
    for a, b in pairs:
        adj[a].append(b)
        bal[a] += 1
        bal[b] -= 1
    start = pairs[0][0]
    for x, d in bal.items():
        if d == 1:                              # out - in = 1: the path must start here
            start = x
            break
    stack, path = [start], []
    while stack:
        u = stack[-1]
        if adj[u]:
            stack.append(adj[u].pop())
        else:
            path.append(stack.pop())
    path.reverse()
    return [[path[i], path[i + 1]] for i in range(len(path) - 1)]

public static int[][] ValidArrangement(int[][] pairs)
{
    var adj = new Dictionary<int, Stack<int>>();
    var bal = new Dictionary<int, int>();
    foreach (var p in pairs)
    {
        if (!adj.TryGetValue(p[0], out var s)) adj[p[0]] = s = new Stack<int>();
        s.Push(p[1]);
        bal[p[0]] = bal.GetValueOrDefault(p[0]) + 1;
        bal[p[1]] = bal.GetValueOrDefault(p[1]) - 1;
    }
    int start = pairs[0][0];
    foreach (var (x, d) in bal) if (d == 1) { start = x; break; }
    var stack = new Stack<int>();
    var path = new List<int>();
    stack.Push(start);
    while (stack.Count > 0)
    {
        int u = stack.Peek();
        if (adj.TryGetValue(u, out var s) && s.Count > 0) stack.Push(s.Pop());
        else path.Add(stack.Pop());
    }
    path.Reverse();
    var res = new int[path.Count - 1][];
    for (int i = 0; i + 1 < path.Count; i++) res[i] = new[] { path[i], path[i + 1] };
    return res;
}

Time O(E), memory O(E). Iterative, because E is up to 10⁵.

5. Minimum Cost to Make at Least One Valid Path in a Grid Hard

Each cell holds an arrow (1 right, 2 left, 3 down, 4 up). Changing a cell's arrow costs 1. Find the minimum cost so that following arrows from the top-left reaches the bottom-right.

Key insight. Moving in the arrow's direction is a 0-cost edge, and moving any other way is a 1-cost edge (you changed that arrow). That is a 0-1 BFS on R · C nodes. Each cell is changed at most once on a shortest path, so counting 1 per non-arrow move is exact. Here is LeetCode's second example, whose arrows already lead to the corner (cost 0):

Solution: 0-1 BFS 
from collections import deque

def min_cost(grid):
    R, C = len(grid), len(grid[0])
    dirs = [(0, 1), (0, -1), (1, 0), (-1, 0)]   # sign 1..4 = right, left, down, up
    dist = [[float("inf")] * C for _ in range(R)]
    dist[0][0] = 0
    dq = deque([(0, 0)])
    while dq:
        r, c = dq.popleft()
        for k, (dr, dc) in enumerate(dirs):
            nr, nc = r + dr, c + dc
            if 0 <= nr < R and 0 <= nc < C:
                w = 0 if grid[r][c] == k + 1 else 1
                if dist[r][c] + w < dist[nr][nc]:
                    dist[nr][nc] = dist[r][c] + w
                    if w == 0:
                        dq.appendleft((nr, nc))
                    else:
                        dq.append((nr, nc))
    return dist[R - 1][C - 1]

public static int MinCost(int[][] grid)
{
    int R = grid.Length, C = grid[0].Length;
    int[] dr = { 0, 0, 1, -1 }, dc = { 1, -1, 0, 0 };   // sign 1..4 = right, left, down, up
    var dist = new int[R, C];
    for (int r = 0; r < R; r++) for (int c = 0; c < C; c++) dist[r, c] = int.MaxValue;
    dist[0, 0] = 0;
    var dq = new LinkedList<(int R, int C)>();
    dq.AddFirst((0, 0));
    while (dq.Count > 0)
    {
        var (r, c) = dq.First!.Value; dq.RemoveFirst();
        for (int k = 0; k < 4; k++)
        {
            int nr = r + dr[k], nc = c + dc[k];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
            int w = grid[r][c] == k + 1 ? 0 : 1;
            if (dist[r, c] + w >= dist[nr, nc]) continue;
            dist[nr, nc] = dist[r, c] + w;
            if (w == 0) dq.AddFirst((nr, nc)); else dq.AddLast((nr, nc));
        }
    }
    return dist[R - 1, C - 1];
}

Time O(R · C), memory O(R · C).

6. Shortest Path to Get All Keys Hard

A grid with walls, up to 6 keys a–f and their locks A–F. Starting at @, find the fewest moves to collect all keys, or −1.

Key insight. The node is (r, c, keys). Lock X is passable only when bit X is in keys, and stepping on a key ORs its bit in. BFS by layers and return the first time keys == all_keys. There are at most 30 · 30 · 64 = 57,600 states. Here is LeetCode's second example (answer 6). Notice the BFS must pick up a before it can pass lock A.

Solution: BFS over (cell, key mask) 
from collections import deque

def shortest_path_all_keys(grid):
    R, C = len(grid), len(grid[0])
    all_keys = 0
    for r in range(R):
        for c in range(C):
            ch = grid[r][c]
            if ch == "@":
                sr, sc = r, c
            elif ch.islower():
                all_keys |= 1 << (ord(ch) - 97)
    q = deque([(sr, sc, 0)])
    seen = {(sr, sc, 0)}
    steps = 0
    while q:
        for _ in range(len(q)):
            r, c, keys = q.popleft()
            if keys == all_keys:
                return steps
            for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                if not (0 <= nr < R and 0 <= nc < C):
                    continue
                ch = grid[nr][nc]
                if ch == "#" or (ch.isupper() and not keys >> (ord(ch) - 65) & 1):
                    continue
                nk = keys | (1 << (ord(ch) - 97)) if ch.islower() else keys
                if (nr, nc, nk) not in seen:
                    seen.add((nr, nc, nk))
                    q.append((nr, nc, nk))
        steps += 1
    return -1

public static int ShortestPathAllKeys(string[] grid)
{
    int R = grid.Length, C = grid[0].Length, sr = 0, sc = 0, all = 0;
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
        {
            char ch = grid[r][c];
            if (ch == '@') { sr = r; sc = c; }
            else if (char.IsLower(ch)) all |= 1 << (ch - 'a');
        }
    var seen = new bool[R, C, 1 << 6];
    var q = new Queue<(int R, int C, int Keys)>();
    q.Enqueue((sr, sc, 0));
    seen[sr, sc, 0] = true;
    int[] dr = { 1, -1, 0, 0 }, dc = { 0, 0, 1, -1 };
    for (int steps = 0; q.Count > 0; steps++)
    {
        for (int size = q.Count; size > 0; size--)
        {
            var (r, c, keys) = q.Dequeue();
            if (keys == all) return steps;
            for (int k = 0; k < 4; k++)
            {
                int nr = r + dr[k], nc = c + dc[k];
                if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
                char ch = grid[nr][nc];
                if (ch == '#' || (char.IsUpper(ch) && (keys >> (ch - 'A') & 1) == 0)) continue;
                int nk = char.IsLower(ch) ? keys | 1 << (ch - 'a') : keys;
                if (seen[nr, nc, nk]) continue;
                seen[nr, nc, nk] = true;
                q.Enqueue((nr, nc, nk));
            }
        }
    }
    return -1;
}

Time O(R · C · 2^K), memory O(R · C · 2^K).

7. Bus Routes Hard

routes[i] is the loop of stops that bus i visits. Find the fewest buses you must take to get from source to target, or −1.

Key insight. The cost is per bus, not per stop, so BFS over buses. Build stop → buses. Start with every bus through source at 1 ride. When you process a bus, look at each of its stops. If a stop is target, you are done. Otherwise, every unused bus through that stop goes in the next layer. Mark stops as used too, so that a stop shared by 500 buses is expanded only once. Building explicit bus–bus edges can be O(B²) and time out.

Solution: BFS with buses as nodes 
from collections import defaultdict, deque

def num_buses_to_destination(routes, source, target):
    if source == target:
        return 0
    buses_at = defaultdict(list)
    for b, route in enumerate(routes):
        for stop in route:
            buses_at[stop].append(b)
    q = deque(buses_at[source])
    used_bus = set(q)
    used_stop = {source}
    rides = 1
    while q:
        for _ in range(len(q)):
            b = q.popleft()
            for stop in routes[b]:
                if stop == target:
                    return rides
                if stop in used_stop:
                    continue
                used_stop.add(stop)
                for nb in buses_at[stop]:
                    if nb not in used_bus:
                        used_bus.add(nb)
                        q.append(nb)
        rides += 1
    return -1

public static int NumBusesToDestination(int[][] routes, int source, int target)
{
    if (source == target) return 0;
    var busesAt = new Dictionary<int, List<int>>();
    for (int b = 0; b < routes.Length; b++)
        foreach (int stop in routes[b])
        {
            if (!busesAt.TryGetValue(stop, out var l)) busesAt[stop] = l = new List<int>();
            l.Add(b);
        }
    if (!busesAt.ContainsKey(source)) return -1;
    var usedBus = new HashSet<int>(busesAt[source]);
    var usedStop = new HashSet<int> { source };
    var q = new Queue<int>(busesAt[source]);
    for (int rides = 1; q.Count > 0; rides++)
    {
        for (int size = q.Count; size > 0; size--)
        {
            int b = q.Dequeue();
            foreach (int stop in routes[b])
            {
                if (stop == target) return rides;
                if (!usedStop.Add(stop)) continue;
                foreach (int nb in busesAt[stop])
                    if (usedBus.Add(nb)) q.Enqueue(nb);
            }
        }
    }
    return -1;
}

Time O(Σ |routes[i]|): every (bus, stop) pair is touched once. Memory the same.

8. Word Ladder II Expert

Return all shortest transformation sequences from beginWord to endWord, changing one letter at a time, with every intermediate word in the dictionary.

Key insight. Two phases. (1) BFS by whole layers, deleting the entire layer from the dictionary after the layer is expanded, and recording every parent from the previous layer. Deleting word by word would lose equally short alternative parents. Stop after the layer that contains endWord. (2) DFS backwards from endWord through the parent lists. Every route back to beginWord is a shortest path, and no time is wasted on dead branches, because every recorded parent lies on some shortest path from the start. The BFS part is the Word Ladder walkthrough in Graph Fundamentals.

Solution: layered BFS + backtrack over the parent DAG 
import sys
sys.setrecursionlimit(1 << 20)   # the search below is recursive
from collections import defaultdict

def find_ladders(begin, end, word_list):
    words = set(word_list)
    if end not in words:
        return []
    parents = defaultdict(list)                 # child -> parents one layer up
    layer, found = {begin}, False
    words.discard(begin)
    while layer and not found:
        words -= layer                          # remove the whole layer at once
        nxt = set()
        for w in layer:
            for i in range(len(w)):
                for ch in "abcdefghijklmnopqrstuvwxyz":
                    cand = w[:i] + ch + w[i + 1:]
                    if cand in words:
                        if cand == end:
                            found = True
                        nxt.add(cand)
                        parents[cand].append(w)
        layer = nxt
    if not found:
        return []
    res, path = [], [end]
    def back(w):                                # walk the parent DAG from end to begin
        if w == begin:
            res.append(path[::-1])
            return
        for p in parents[w]:
            path.append(p)
            back(p)
            path.pop()
    back(end)
    return res

public static IList<IList<string>> FindLadders(string begin, string end, IList<string> wordList)
{
    var words = new HashSet<string>(wordList);
    var res = new List<IList<string>>();
    if (!words.Contains(end)) return res;
    var parents = new Dictionary<string, List<string>>();
    var layer = new HashSet<string> { begin };
    words.Remove(begin);
    bool found = false;
    while (layer.Count > 0 && !found)
    {
        words.ExceptWith(layer);                     // remove the whole layer at once
        var next = new HashSet<string>();
        foreach (string w in layer)
        {
            var chars = w.ToCharArray();
            for (int i = 0; i < chars.Length; i++)
            {
                char orig = chars[i];
                for (char ch = 'a'; ch <= 'z'; ch++)
                {
                    chars[i] = ch;
                    string cand = new string(chars);
                    if (!words.Contains(cand)) continue;
                    if (cand == end) found = true;
                    next.Add(cand);
                    if (!parents.TryGetValue(cand, out var ps)) parents[cand] = ps = new List<string>();
                    ps.Add(w);
                }
                chars[i] = orig;
            }
        }
        layer = next;
    }
    if (!found) return res;
    var path = new List<string> { end };
    void Back(string w)
    {
        if (w == begin)
        {
            var copy = new List<string>(path);
            copy.Reverse();
            res.Add(copy);
            return;
        }
        foreach (string p in parents[w]) { path.Add(p); Back(p); path.RemoveAt(path.Count - 1); }
    }
    Back(end);
    return res;
}

Time O(N · L · 26) for the BFS (N words of length L), plus the size of the output for the backtracking. Memory O(N · L) plus the parent lists.

Self-check

Why is the bridge test `low[v] > tin[u]` but the cut-vertex test `low[v] >= tin[u]`?

low[v] == tin[u] means v's subtree has a back edge that lands exactly on u. For the edge u–v that back edge forms a cycle through u–v, so removing the edge leaves another route: not a bridge. For the node u, that escape route lands on u itself, so deleting u removes it, and v's subtree is cut off: u is a cut vertex. Equality is an escape for an edge but not for a node.

In Tarjan's SCC algorithm, what goes wrong if you update `low[u]` from every visited neighbour, not just those on the stack?

A cross edge u → v into an SCC that was already completed and popped would lower low[u] to tin[v]. Then u's SCC root would not satisfy low == tin at the right moment, and u's SCC would be merged with nodes that cannot reach back to it. For example, in 0 → 1, 1 → 0, 2 → 0, if node 2 is visited after {0, 1} is done, low[2] would become 0 and node 2 would never be popped as its own component. "On the stack" means "still in an open SCC".

In Kosaraju, why must the second pass run on the reversed graph, in decreasing finish time?

The node with the latest finish time is in a source SCC of the condensation. On the original graph, a DFS from it would flow out into every SCC below it. Reversing the edges turns that source into a sink, so the DFS from it is trapped inside its own SCC and collects exactly that SCC. Removing it leaves a graph whose latest remaining finisher is again in a source SCC, and so on.

A directed graph has out − in = +1 at A, −1 at D and 0 everywhere else, but Hierholzer from A returns only 5 nodes for 6 edges. What happened?

The degree test passed, but the edges are not all in one connected piece. Some cycle sits in a part of the graph the walk from A never reaches, so its edges are never used. The len(path) == E + 1 check catches exactly this. The degree conditions are necessary, and they are sufficient only together with connectivity of the edges.

After Edmonds-Karp finishes, how do you list the edges of a minimum cut, and why are they all saturated?

Run one more BFS from s in the residual graph. S is every node it reaches, and the cut edges are the original edges from S to the rest. Each such edge must have residual capacity 0, which means it is saturated: otherwise BFS would have crossed it. Each edge from the rest back into S must carry 0 flow, otherwise its backward residual arc would have let BFS cross. So the flow across the cut equals the cut's capacity, which proves both are optimal.

Why can 0-1 BFS use a deque where Dijkstra needs a heap?

With weights only 0 and 1, the nodes waiting to be processed never have more than two distinct distances, d and d + 1. Pushing a 0-edge neighbour (distance d) to the front and a 1-edge neighbour (distance d + 1) to the back keeps the deque sorted, so the front is always a minimum, which is the only thing Dijkstra's heap is for. Every operation is O(1), so the total is O(V + E) instead of O(E log V).
