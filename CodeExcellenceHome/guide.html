How this home works

This site is generated. Edit Markdown, never the HTML.

1 · PLANcurriculum.json

Tracks, topics, levels, prerequisites. A topic is “Planned” until its Markdown exists.

2 · WRITEcontent/<slug>.md

Prose, callouts, inline SVG, code tabs, quizzes and .viz mounts.

3 · ANIMATEassets/viz/<slug>.js

Registers step-through visualizers with the shared Viz engine.

4 · BUILDpython build.py

Regenerates index.html, topics/*.html and this guide. Fully offline.

File Purpose
curriculum.json Home branding, tracks and topics (slug, title, summary, level, minutes, prereqs, keywords).
content/<slug>.md Topic body. Starts at ## headings (the page hero supplies the H1).
assets/viz/<slug>.js Optional. Auto-included on the topic page when present.
assets/topics/<slug>.css Optional topic-only styles. Prefer the shared vocabulary below.
assets/site.css, site.js, viz-core.js, build.py Shared engine. Keep identical across DSA Home and Code Excellence Home.

Build: .venv\Scripts\python.exe build.py (or any Python with Markdown==3.7).

Callouts

Rule / invariant. The one sentence you must remember. Use once or twice per topic.

Recognize it when

  • The input is sorted, or you can sort it.
  • You need a pair / triple with a target relationship.

Tip A practical trick, shortcut or interview move.

Pitfall The bug everyone writes once: off-by-one, overflow, stale state.

Neutral note. Plain amber callout for context.

Compare and cheat sheets

Brute force — O(n²)

Check every pair. Simple, too slow beyond ~10⁴ items.

Two pointers — O(n)

Sorted input lets each step discard a whole row of pairs.

Hash map — O(n) time, O(n) space

Works unsorted, costs memory.

n ≤ 20Bitmask / backtracking, O(2ⁿ)
n ≤ 10³O(n²) DP or pairs
n ≤ 10⁵O(n log n): sort, heap, binary search
n ≤ 10⁷O(n): linear scan, two pointers

Difficulty chips for problem ladders: Easy Medium Hard Expert · keys: ← → Space

Code tabs

Consecutive fenced blocks inside .code-tabs become synchronised tabs. Your language choice is remembered across pages.

def two_sum_sorted(a, target):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        s = a[lo] + a[hi]
        if s == target:
            return lo, hi
        if s < target:
            lo += 1          # need bigger: discard a[lo]
        else:
            hi -= 1          # need smaller: discard a[hi]
    return None

public static (int, int)? TwoSumSorted(int[] a, int target)
{
    int lo = 0, hi = a.Length - 1;
    while (lo < hi)
    {
        int s = a[lo] + a[hi];
        if (s == target) return (lo, hi);
        if (s < target) lo++; else hi--;
    }
    return null;
}

Quizzes and solutions

Why can two pointers skip pairs safely on a sorted array?

If a[lo] + a[hi] < target, then a[lo] plus any element left of hi is even smaller — so no pair involving a[lo] can work. Discarding it loses nothing.

Viz.register("my-viz", (host, opts) => Viz.player(host, {
  title: "Binary search", tag: "STEP THROUGH",
  legend: [["active", "mid"], ["dim", "discarded"], ["done", "answer"]],
  code: ["lo, hi = 0, n - 1", "while lo <= hi:", "  mid = (lo + hi) // 2"], codeLang: "python",
  inputs: [{ key: "nums", label: "nums", value: "1,3,5,7,9" }, { key: "t", label: "target", value: "7" }],
  random: () => ({ nums: Viz.randInts(8, 1, 40).sort((a, b) => a - b).join(","), t: String(Viz.rand(1, 40)) }),
  build: ({ nums, t }) => {
    const a = Viz.parse.ints(nums), frames = [];
    frames.push({ a, lo: 0, hi: a.length - 1, line: 0, note: "Start with the whole range.", vars: { lo: 0, hi: a.length - 1 } });
    return frames;                             // throw new Error("msg") for bad input
  },
  render: (f) => Viz.row(
    Viz.array(f.a, { ptrs: { lo: f.lo, hi: f.hi }, cls: (i) => (i < f.lo || i > f.hi ? "dim" : "") }),
  ),
}));
